真实原生伤害与攻击提供者仅扩展有限来源、嘲讽绕过和本体免疫条件，数值/目标/生命周期仍交原执行器。当前种族、占位和未实现克洛玛图斯来源边界见[契约](m3-native-health-attack-providers.md)，不能从登记数量认证正式标准支持。

真实条件消费者继续使用既有属性、攻击、施法和物理库存事实；跨冻结反应的原邻位组仅增加有限法术续接，冻结/死亡仍由公共执行器负责。保存、末次武器奖励及初始资格的边界见[契约](m3-conditional-consumers.md)，当前执行版本以原两份台账为准。

真实卡牌应组合已有公共效果，敌方随从持续嘲讽仅增加有限声明范围；生命设值、连击复制、武器死亡、随机额外效果与牌库逆序继续共用原执行器。新增范围及待国服边界见[配方契约](m3-public-effect-consumers.md)，下文历史初始范围不覆盖此后新增形状。

原延系检索按第一次实际抽牌的完整类型连接第二次物理检索；原生手牌额外效果只替换两个印刷关键词槽，独立授予继续保留。有限表达及未实现来源边界见[契约](m3-kindred-hand-bonus.md)。

真实抽牌条件只读原两次物理抽牌，来源奖励绑定原连续驻留；按实际消灭奖励保存原目标与死亡原因，继续委托普通死亡、抽牌和法力执行器。有限请求及待国服边界见[五费随从契约](m3-five-cost-native.md)。

真实原生法术参数绑定原亡语执行与物理材料，当前费用/亡语抽取连接原手牌奖励；首回合和后续正常抽牌共用可移除来源门禁。有限字段、公共执行及未覆盖继承边界见[亡灵资源契约](m3-undead-resource-native.md)。

真实英雄本回合生命变化目标读取原提交账本，随机随从增益仅抽选后交给原属性层；受伤召唤、不能攻击和实际过量治疗继续组合公共执行器，表达与待校准边界见[亡灵原生效果契约](m3-undead-native.md)。

上一张使用的印刷符文用原冻结历史查询；固定召唤组从完整原交付连接原目标强制攻击，保存、容量与时序边界见[符文与召唤组战斗契约](m3-blood-rune-native.md)。

真实英雄救援复用原英雄致死屏障、实际残骸支出与原身份恢复，公开一次性标记按原接受时钟退役；具体表达、替换及校准边界见[哈斯克契约](m3-hero-corpse-rescue.md)。

原生残骸获得倍率保留可移除来源和固有死亡基数；物理消费者检索、原目标支付及真实任务/地标/第二技能依赖见[残骸消费者契约](m3-corpse-consumer-native.md)。已有第二技能槽安装仍明确未支持，不能以首次安装认证整卡。

原随从残骸门禁在执行时重核实际来源、空位/复生/召唤对象，再沿原完整支付分支；原目标伤害与三个真实选项保持引用和信息边界，见[残骸触发与选择契约](m3-corpse-trigger-choices.md)。

真实回手禁止须绑定成功到达的原物理对象；控制归还和“下个本人回合结束”按实际原玩家区间计时，普通/对方/结束反应安装分别接受。有限入口和仍未支持的控制层叠边界见[时间效果契约](m3-temporal-spell-effects.md)。

真实首次复制的目标要求通过有限原生声明共用选择管线；召唤后的全法力奖励绑定原请求、实际交付和原支出，见[数值资源法术契约](m3-numeric-resource-spells.md)。

下一次延系必须只重复真实成立部分，原准备/替代分支、原付款及原接收对象分别表达；原生入口、紧凑计划与恢复边界见[延系部分契约](m3-kindred-components.md)。

实际置顶/增益必须共用原物理对象，真实成功召唤奖励必须保留原事实与连续驻留；不为接口缺失缩成当前名字判断。有限能力与依赖接入见[原接收对象契约](m3-original-imp-recipients.md)。

固定衍生物依赖先核官网child及完整原行，再复用公共语义洗牌、原实体抽牌/召唤与实际回合费用流程；具体接入方式见[固定洗入契约](m3-fixed-shuffle-followups.md)。

种族候选前审须调用公共matches_metadata，完整元数据的字面成员检查仍会漏掉all种族。下一次价格与关键词奖励须共享原实际付款材料，真实下一回合沿原owner开始事件，见[费用卡契约](m3-paid-minion-price-keywords.md)。

实际牌库施放和历史重施共享自动目标资格；真实“优先自身”需保留原驻留并在CAST窗口处理合法回退，不能用手动出牌目标预检近似。限定消费者、存储费用和严格保存边界见[原随从优先施法契约](m3-original-minion-spell-targets.md)。

完整随机/发现池的实际依赖可按共同效果先接入，入口保持未支持直到候选和可达内容闭合；种族候选必须使用完整元数据而非只看主种族。延系普通出牌、固定跨系列衍生物及其与战吼入口的区分见[配方契约](m3-kindred-murloc-effects.md)。

真实卡的成长/抽牌关联须保存可复制且可被沉默移除的原附件材料，并在反应通知前绑定实际获取；冻结复制材料也要验证原引用，不能用无界来源历史查询替代。具体最小能力及国服待校准边界见[契约](m3-native-deathrattle-memory.md)。

遇到真实持续条件缺口，先在原生命周期补最小声明和接受窗，复用既有执行器；面板容量必须计入所有实际占位并采用当前规则容量。灰烬虫的必要能力与待CN边界见[契约](m3-full-board-dormancy.md)。

出牌后奖励须绑定原使用事实与连续实体驻留，按需在真实执行窗重读，不重绑离场再入场；未知接收形态明确报错，不能把登记数当完整支持数，见[真实出牌奖励契约](m3-played-minion-keywords.md)。

基础英雄、默认技能及其指定衍生物须作为实际对局依赖一起接通；规范角色用真实30张实验套牌核对开局流程，并与正式标准池认证区分。完整基本图腾和源引用装配方式见[角色契约](m3-basic-hero-roles.md)。

发现基础英雄、技能或其指定衍生物未接通时，将其作为真实对局前置补齐；不以其他头像的显式Scenario认证该职业默认开局。持续来源资格优先限定原提供者，保持原付款接受和伤害包窗口，不能以轮询附魔替代，见[原生条件契约](m3-native-conditional-sources.md)。

真实卡需要连续追随公开出牌时，必须区分原生来源和当前卡面，验证获取同步、复制/转手及离手退役；不能用回合开始或单次变形充当完整实现。最小独立表示与待国服继承政策见[原生手牌镜像契约](m3-native-hand-mirrors.md)。

真实卡牌的官方修复记录如果要求抽到时施放也受奖励，不能把只覆盖最终手牌的组后回调当完整实现；先在原抽牌管线补最小真实窗口，仍保留未知衍生物的显式不支持。原生复生与FIRE抽牌的具体表达见[契约](m3-native-reborn-fire-draw.md)。

原随从奖励需跨反应保留原引用时，使用已有属性层外的最小身份守卫；单卡明确覆盖手牌/牌库时，声明有限原生scope，不能据接口扩成组合矩阵。原攻击者和三区域成长的边界见[契约](m3-stored-growth-cards.md)，实际进度仍仅在原两台账。

随机生成源依赖按真实效果分批补齐时，源仍保留显式不支持，直到完整候选和实际可达内容接通；候选定义数量不代替正式生成资格。多目标效果需要延后接受时，应保存原物理引用，在每个真实执行窗口调用公共机制，而非提前伪造共同接受事实；相关[复制驻留契约](m3-six-cost-native-cards.md)提供具体边界。

用户于2026-10-14授权建立并推进补卡目标，并最新明确先补齐标准环境，狂野暂缓。本文件维护范围、顺序和验收约定；实际完成数量、批次证据、差异和下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)登记。长期范围仍以[roadmap](roadmap.md)为准。

本轮目标：完整支持固定国服正式补丁的标准对战，补齐全部标准合法根卡及实际可达内容、正式构筑和生成池，按效果分类分批实现并验证；复用公共机制，只为真实卡需求补最小缺口。保持完整对局、支付、生命周期、选择恢复、回放及玩家信息边界正确；增量只运行专项与明确影响测试，阶段集中全量。狂野专属卡牌、机制和验收后置，不计本轮完成条件。内部交付与国服官方支持分别记录，以标准范围完整性、实际验证和对应M0/M6证据判断完成。

## 范围与版本

- 冻结一个国服正式构筑补丁，本轮仅标准；狂野作为后续目标另行安排，不用历史数值代替目标补丁的有效卡面。
- 核查日2026-10-14的[国服37.0公告](https://hs.blizzard.cn/news/24301454/)说明补丁于北京时间10月14日上线；“黑暗帝国的统治”10月21日正式上线。抢先体验乱斗/竞技池不等于正式标准池，预加载新卡单独列为待上线；已提前可用的赠送卡需逐张核实。
- 本地安装版本另行读取，安装信息不代替服务器规则。原M0清单和固定代表包保留为历史，不改成最新完整支持。
- 收齐全部标准合法根卡以及实际可达的衍生物、形态、英雄技能、附魔、奖励、组合配方；标准效果实际能生成或调用的跨系列内容仍是必要依赖，不能按系列删除。狂野专属根卡不计标准覆盖分母；数据、合法性、效果实现、内部验证、官方校准分别记录。
- 当前候选政策由目标清单指针选择。经来源审核的根卡排除使用显式`excluded_ids`，只改变候选根资格，保留完整原始记录及可达依赖审查；不按未实现状态删候选。排除必须解析到真实可收藏根，不能同时声明提前可用；旧政策未列此字段时保持原结果。官网标准目录可能包含预览数据，仍须分别核查上线日期、提前开放、标准资格及禁限。

## 开发顺序

1. 建立全部源记录与正式目标清单，标记目标内/目标外/待核实；导入目录不自动注册可执行效果。
2. 纯数值随从、普通关键词随从、普通装备：显式审核数据及能力声明，用已有内核执行。
3. 伤害/治疗、抽牌/资源、增益、召唤、消灭/移除/沉默：按主体效果分批复用；战吼、亡语、法术等是独立触发入口，不作为复杂度分母。
4. 条件、发现/随机生成、复制/变形、区域操作、持续效果与历史查询：按已有模块依赖排序，每张根卡和其必要衍生物一起接通。
5. 特殊卡及真实组合：先尝试组合已有原语，确实不能表达才补最小公共能力；不从接口缺失或自造组合扩大需求。
6. 每一阶段按系列核对标准漏项、可达内容和已知差异；标准完整交付为本轮终点，狂野保留为后续目标。

同一批优先接入可复用同一效果的卡，再处理真实条件差异。代码中的数据可以按系列分文件，公共行为按机制共享；不把所有卡堆进历史代表包，不为每张牌重写支付、死亡或时序。

## 批次验收与效率

- 2026-10-16用户授权持续并行：本会话继续复杂卡与必要公共能力，同一独立工作树会话每批只接明确能复用公共机制的简单卡。本会话审查、专项与实际影响验证、合并通过后继续派下一批，不等待子会话停止主线。派工具体卡牌ID与必要依赖唯一分配；子会话遇真实公共缺口整张暂缓并转交，不在卡牌层造执行器。共享注册、内容身份和两份进度台账由本会话维护；按真实依赖同步基线，不因每次合并触发全量。实际开发、测试、协调和合并耗时分开记录，没有串行对照不宣称并行提速倍数。

- 只有数据审核/有效映射、完整效果及必要依赖、关键正反例、实际受影响的恢复/回放/玩家边界验证都通过，才登记该批完成。普通数值和关键词卡共享参数化执行验证；不同卡的数据映射仍逐条核对。
- 每批先说明影响关系，只运行专项和明确受影响测试。公共内核没变时不因新增卡数量扩大到所有机制测试；不为每张简单牌重复跑整局或完整回放。
- 公共语义确实变化时补覆盖实际影响的支付、生命周期、选择恢复、回滚、随机/回放及隐藏信息。旧结果仅在依赖不变、完整成功时保留，失败批次如实留存。
- 全量只在阶段整体或发布验收集中执行，同一时间一个批次；不得把每个小增量变成全量。记录实际耗时后再优化，未执行项明确登记。
- 卡牌未实现必须明确报错，不能作为白板、不能从应有发现/生成池偷偷删去。候选合法池未完整时公开受限状态，不能认证正式池。
- 本轮标准以零未处理合法根卡/实际可达内容、必要验证和阶段回归实际完成作为内部交付门槛；正式标准完整支持还要求对应M0版本/热修/合法池闭合及M6国服官方证据校准。狂野池未闭合或狂野专属内容未实现不阻塞本轮；标准实际依赖不能据此豁免。
