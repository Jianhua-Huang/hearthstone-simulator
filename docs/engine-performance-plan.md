## 固定基准

统一入口：`tools/engine_performance_baseline.py`，完整宿主子工作负载为 `tools/engine_performance_standard.py`。

```powershell
python -B -X utf8 tools/engine_performance_baseline.py --registry constructed --samples 5 --standard --output outputs/新的优化前目录
python -B -X utf8 tools/engine_performance_baseline.py --registry constructed --samples 5 --standard --compare outputs/优化前目录/report.json --output outputs/新的优化后目录
```

每次目录必须新建。基准冻结源代码、测试、工具、数据及数据显式引用的本地证据，核对源复制前/后与副本SHA。所有对局从该副本导入，源码守卫检查整个运行期间保持。阶段微测可以用重复的 `--case attack --case legal_actions_dense`，省略整局；完整阶段收尾仍执行上面的同一套基准。

固定同一版本卡池、目标、Python、机器、种子和牌组。基础11类操作预热一次、轮流测5次；正常30张牌库场景测火球/符文宝珠/操控时间，另跑确定策略的整场双方30张牌对局。动作计时不含初始化、克隆准备、断言、策略选择、剖析和回放；完整宿主构建/建局单独计时。保留原始wall/CPU时间、中位数与范围；小样本不报p95，不以剖析绝对秒数作为正常延迟，不将不同版本旧报告称为受控加速。

若单项出现异常退步，先保留整批原结果并重测；混合核心CPU或其他系统负载可能影响测量，但不能据此直接免除回归。必要时用相同外部启动器将两个冻结版本都固定同一逻辑CPU，顺序执行原定时工具，记录掩码、工具SHA、来源及完整语义比较。不同亲和性结果分别报告，不拼接成一组样本，不改定时函数来消除慢样本。

## 行为相等是硬门槛

性能改动不改变效果、声明、生命周期、版本身份或快照schema。若实际发现必须改变语义，应退出本性能增量、另行处理，不能靠归一化隐藏差异。

基础工作负载比较完整状态与结果摘要；历史压力比较每次选择后的完整快照。整局每一步比较原动作、完整快照摘要、全部保留事件/随机状态/支付/待选帧、合法操作与公开修订、操作返回及另一玩家视图。原始摘要不删除字段、不忽略RNG/事件顺序、不仅比较最终胜负。任何差异都失败。独立注册表恢复、clone、回放、双方观察、非法选择回滚和一次支付继续检查。

同工具、同夹具和同身份下比较优化前后。工具或输入不同应明确失败并建立新基线，不能将语义变化忽略为性能差异。保留每阶段的全部原失败、测试清单和源守卫；已变化依赖的测试结果不能继承。

正常对局与强化学习共用唯一规则执行器。只在一次同步拼装生成、选择结算前的工作计算、等待边界审计或抽样计算内部复用固定模板、派生卡定义和拼装配方；候选列表、当前职业、来源、查询、权重、动态状态及RNG仍逐次计算。上下文在同步计算返回后关闭，在后续效果执行前释放，不将缓存的派生对象交给对局或玩家。

入口及出口检查完整冻结注册库存；可变注册表、子类或未知扩展结构走原路径。每个缓存结果使用完整原生结构守卫，嵌套修改或类型/schema变化不得命中。最多保存4个注册表、每个512项；库存身份变化不复用旧材料，失败不入缓存。任意未实现内容继续显式报错，完整候选与恢复证明校验保持。外部独立定义查询仍走原解析与校验。

固定典型卡对照必须核对完整快照、返回、RNG、候选、事件、支付、双方视图、独立恢复/clone/回放及连续原生动作。保存提交前版本、原基准、剖析和失败记录；按实际变化选择专项与明确相关回归，不频繁全量。实际执行、差异、耗时和下一项仍仅在两份原台账维护。


## Release / Debug 运行模式（2026-11-01）

正常对战和强化学习默认使用 `RuntimeMode.RELEASE`（`release`），保留原生内存帧与缓存路径；`RuntimeMode.DEBUG`（`debug`）开启逐动作状态、历史和结算边界审计。成功日志只记动作、对局标识、前后位置、分段耗时、结算/事件总数、队列峰值及已有状态摘要；失败再附最近32项结算类型、异常原因链和堆栈。不扫描事件分类、不写成功动作的完整步骤列表、不为日志额外复制状态或计算摘要。两种模式共用原结算器、支付/目标/候选与随机处理；合法操作、事务回滚、信息隔离和外部读档校验始终保留。模式本身不是稳定版本认证，发布稳定性仍由对应版本的验收决定。

模式是宿主运行配置，不进入快照、回放身份、状态摘要或玩家DTO。`Game.from_scenario`、`Game.from_decks`、`Game.from_snapshot` 及 `replay` / `load_replay` 接受关键字 `mode='debug'`；默认都是 `release`。已有对局只在动作边界设置 `game.runtime_mode`；`game.runtime_audits` 保留为兼容布尔别名。clone继承模式但使用独立空诊断缓冲区；从快照恢复需由宿主明确传入模式。`game.audit()` 仍可在release中按需检查独立副本。

Python调用示例：

```python
from hs_sim.engine import Game, RuntimeMode

game = Game.from_scenario(scenario, registry, mode=RuntimeMode.DEBUG)
game.apply(action)
records = game.debug_records  # 宿主最近128次动作的独立记录副本
```

命令行的 `demo` / `simulate` / `match` / `replay` 和测试服务统一使用 `--mode release` 或 `--mode debug`。debug默认写入 `outputs/engine-debug/cli-进程号.jsonl` 或 `server-端口-进程号.jsonl`，可用 `--debug-log 路径` 指定文件；release不接受此调试日志参数。每文件5MiB轮转，保留两个旧文件。库调用默认只保留内存记录，可使用 `hs_sim.engine.runtime.debug_log(path)` 上下文启用JSONL。独立训练进程使用各自日志文件。

```powershell
python -B -X utf8 -m hs_sim demo --mode debug --max-actions 3 --debug-log outputs/engine-debug/demo.jsonl
python -B -X utf8 -m web_ui.server --port 8770 --mode release
python -B -X utf8 -m web_ui.server --port 8770 --mode debug
```

详细记录覆盖 `Game.apply` 的成功与失败，包括非法原生动作和审计失败；保留异常原因链以及已丢弃事务的位置和结算步骤，不逐步复制全知快照。记录为宿主调试材料，可能包含原生命令实体ID和异常消息，不通过玩家/HTTP数据接口导出。日志写入失败不改变已完成动作或原异常。release不构造调试记录、不做分段计时、不输出引擎详细日志；既有HTTP/浏览器耗时日志保持其独立用途。测试加牌/法力调整、实验卡场景和新会话继承服务启动时的模式，不让读档操作悄悄切换模式。已启动进程不自动改模式。


## 第八轮：压缩内部证明检查及诊断成本（2026-11-01）

用户明确继续优化release，同时要求debug也控制性能成本。release不再为每个取出的结算项重审原手牌/法术支付证明，结束时仍检查真实完成状态、活跃窗口和剩余队列；支付、效果、候选与随机照常执行。显式调用的证明验证器仍执行原检查，外部恢复和回放校验不减。

固定拼装材料继续有界缓存，release内部作用域信任已冻结注册表和内部只读材料，不反复遍历全部库存及每份派生结构，也不重审刚生成的完整候选证明。缓存仍绑定注册表实例及其冻结身份，未知扩展不命中；当前职业、查询、候选顺序和实际随机抽样没有缓存。debug及默认独立材料查询保留完整守卫。release不保证检测手工改写私有冻结库存或缓存对象；应通过正常注册流程构建新注册表，不在运行期篡改内部材料。

两模式均直接复制原生待选帧。debug在最终稳定边界遍历原生类型、状态不变量和机制证明，避免先编码再还原整帧；同次遍历的同一对象只审计一次。扩展类型和含特殊规范化约束的结束计划保持原codec路径，专用随机状态保留原高斯缓存。显式`game.audit()`和外部存档恢复继续完整wire/schema校验。诊断日志仍限制最近128次动作及5MiB文件/两个备份；对局标识仅首次debug动作生成，clone的诊断历史与标识独立，不改变引擎RNG。

验收继续保存优化前后冻结源码、同工具完整摘要和典型卡原始样本；release和debug分别测速，慢项保留并针对性复测。事务副本、回滚、玩家信息边界及快照schema保持。实际结果、已知差异和下一项只记原两份台账。
