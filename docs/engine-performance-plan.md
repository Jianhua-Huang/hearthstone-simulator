## 固定基准

统一入口：`tools/engine_performance_baseline.py`，完整宿主子工作负载为 `tools/engine_performance_standard.py`。

```powershell
python -B -X utf8 tools/engine_performance_baseline.py --registry constructed --samples 5 --standard --output outputs/新的优化前目录
python -B -X utf8 tools/engine_performance_baseline.py --registry constructed --samples 5 --standard --compare outputs/优化前目录/report.json --output outputs/新的优化后目录
```

每次目录必须新建。基准冻结源代码、测试、工具、数据及数据显式引用的本地证据，核对源复制前/后与副本SHA。所有对局从该副本导入，源码守卫检查整个运行期间保持。阶段微测可以用重复的 `--case attack --case legal_actions_dense`，省略整局；完整阶段收尾仍执行上面的同一套基准。

固定同一版本卡池、目标、Python、机器、种子和牌组。基础11类操作预热一次、轮流测5次；正常30张牌库场景测火球/符文宝珠/操控时间，另跑确定策略的整场双方30张牌对局。动作计时不含初始化、克隆准备、断言、策略选择、剖析和回放；完整宿主构建/建局单独计时。保留原始wall/CPU时间、中位数与范围；小样本不报p95，不以剖析绝对秒数作为正常延迟，不将不同版本旧报告称为受控加速。

若单项出现异常退步，先保留整批原结果并重测；混合核心CPU或其他系统负载可能影响测量，但不能据此直接免除回归。必要时用相同外部启动器将两个冻结版本都固定同一逻辑CPU，顺序执行原定时工具，记录掩码、工具SHA、来源及完整语义比较。不同亲和性结果分别报告，不拼接成一组样本，不改定时函数来消除慢样本。

## 行为相等是硬门槛

性能改动不改变效果、声明、生命周期、版本身份或快照schema。若实际发现必须改变语义，应退出本性能增量、另行处理，不能靠归一化隐藏差异。

基础工作负载比较完整状态与结果摘要；历史压力比较每次选择后的完整快照。整局每一步比较原动作、完整快照摘要、全部保留事件/随机状态/支付/待选帧、合法操作与公开修订、操作返回及另一玩家视图。原始摘要不删除字段、不忽略RNG/事件顺序、不仅比较最终胜负。任何差异都失败。独立注册表恢复、clone、回放、双方观察、非法选择回滚和一次支付继续检查。

同工具、同夹具和同身份下比较优化前后。工具或输入不同应明确失败并建立新基线，不能将语义变化忽略为性能差异。保留每阶段的全部原失败、测试清单和源守卫；已变化依赖的测试结果不能继承。

## 相关回归与验收

- A：原裂变与真实组合来源、注册表身份，并覆盖基础选择/玩家接口隔离；新检查聚焦冻结后不再全目录扫描、构建期新增族不陈旧及返回值隔离。
- B：目标域、玩家输入、声明式目标谓词、原生出牌目标预检、自动目标及实际受影响的英雄技能/战斗路径；新增恶意可变回调与builtin域一致性检查。
- C：固有费用与历史前缀、compact费用证明、生成成本保留、支付接受和生命周期、恢复/回放/回溯及篡改负例；按真实调用链选择完整相关模块，不以新微测替代旧用例。
- D：原选择、支付等待边界、帧codec和严格恢复负例、信息边界及真实发现来源。

运行原 `tools/run_tests.py`，检查成功、源码守卫、准确方法清单和恰一次执行。阶段收尾汇总全部明确影响回归；既有发布/阶段全量义务保持，不在每个小改动触发全库全量。每项须同时具有行为相等、相关测试正常和实际提速证据；无收益或无法保持语义的改动撤回。其他基准出现超过通常波动的退步时重复测量并解释，不能只摘取加速项。

禁止以关闭验证、跳过付款/生命周期/隐藏信息检查、删去回滚快照、裁剪候选池、改变随机权重/顺序或按对象ID跨状态缓存来换取速度。
