# 引擎性能优化与行为保全契约

## 公共卡池查询及自动施法完成审计（2026-11-04）

`resolve_candidates` 在遍历候选前验证一次完整不可变 PoolQuery（含所有 OR 子句），循环内只逐张匹配当前元数据；直接调用 `matches_metadata` 仍先验证输入。候选顺序、权重、排除政策、未知事实报错、完整可执行定义检查和随机抽样均保持。复用范围只有一次同步查询，不缓存候选结果或对局状态；debug 也不按卡牌数量反复验证同一查询声明。

自动施法完成时，release 直接沿原接受目标、原 CAST 与后续主体队列完成，不再复制原始局面重新验证目标证明；debug 仍执行 `validate_target_finish`，失败整步回滚并记录必要诊断。已完成/中断/主体未开始、额外主体游标等实际结算条件保持。显式证明验证、完整审计和外部快照恢复继续检查原始目标接受证明；release 不承诺检测对私有完成工作或证明的手工改写。该机制不按具体卡牌 ID 特判。

## Release 按需摘要与回放 v2（2026-11-03）

按用户明确的 release/debug 分工，release 的普通 `Game.apply` 不再自动遍历/编码完整局面计算逐步状态摘要，也不计算该步事件摘要。`ActionResult.state_hash` 及 `game.history` 对应的两项摘要在 release 为 `None`；事件与接受动作仍保留。需要当前局面摘要的宿主显式调用 `game.state_hash()`。debug 沿原路径计算逐步摘要、必要审计及有界诊断；不增加另一种训练模式。卡牌规则所读的出牌/施法/死亡等历史、支付、待选续接、事务回滚、RNG及玩家信息边界保持。

显式 `snapshot()`、`state_hash()`、`audit()` 仍执行其原职责，快照 schema 与内容不变。待选支付边界目前仍保存严格恢复所用的证明和摘要，不能将本增量描述为已去掉所有证明成本。

新导出的回放为 schema 2：原 origin 与动作记录之外，在导出时计算 `final_state_hash` 和 `final_events_hash`；每条动作保留原字段，release 的两项逐步摘要均为空，debug 的均为真实执行时摘要。导出不重演对局、不补造过去状态证明、不持有逐步完整局面。读取仍校验 origin、版本、合法动作，重演后核对完整最终状态（含RNG）及全部事件。存在逐步摘要时额外核对原步骤；缺少摘要时无法指出中间状态首次分歧，也不认证中间状态未曾分歧后收敛。schema 1 仍按原强制逐步校验读取，不能把缺失摘要当作旧格式有效。

边界切换模式只影响后续动作是否收集摘要；读取者选择的模式不伪装或改写源记录的审计覆盖。旧外部程序若要求每次 `ActionResult.state_hash` 都是字符串，需显式调用当前 `game.state_hash()` 或使用 debug；只识别回放 v1 的旧读取器需升级。玩家DTO/命令接口和旧快照读取不受此接口调整影响。

用户于2026-10-31要求先全局定位，再逐项修复，并以固定基准比较优化前后、执行相关原有测试。本文件只定义方案与验收方式；执行进度、实际结果、失败及下一项仍仅维护在原两份台账。当前范围为引擎，不包含HTML或新的卡牌效果。

## 固定基准

统一入口：`tools/engine_performance_baseline.py`，完整宿主子工作负载为 `tools/engine_performance_standard.py`。

```powershell

python -B -X utf8 tools/engine_performance_baseline.py --registry constructed --samples 5 --standard --compare outputs/优化前目录/report.json --output outputs/新的优化后目录
```

每次目录必须新建。基准冻结源代码、测试、工具、数据及数据显式引用的本地证据，核对源复制前/后与副本SHA。所有对局从该副本导入，源码守卫检查整个运行期间保持。阶段微测可以用重复的 `--case attack --case legal_actions_dense`，省略整局；完整阶段收尾仍执行上面的同一套基准。

固定同一版本卡池、目标、Python、机器、种子和牌组。基础11类操作预热一次、轮流测5次；正常30张牌库场景测火球/符文宝珠/操控时间，另跑确定策略的整场双方30张牌对局。动作计时不含初始化、克隆准备、断言、策略选择、剖析和回放；完整宿主构建/建局单独计时。保留原始wall/CPU时间、中位数与范围；小样本不报p95，不以剖析绝对秒数作为正常延迟，不将不同版本旧报告称为受控加速。

## 行为相等是硬门槛

性能改动不改变效果、声明、生命周期、版本身份或快照schema。若实际发现必须改变语义，应退出本性能增量、另行处理，不能靠归一化隐藏差异。

基础工作负载比较完整状态与结果摘要；历史压力比较每次选择后的完整快照。整局每一步比较原动作、完整快照摘要、全部保留事件/随机状态/支付/待选帧、合法操作与公开修订、操作返回及另一玩家视图。原始摘要不删除字段、不忽略RNG/事件顺序、不仅比较最终胜负。任何差异都失败。独立注册表恢复、clone、回放、双方观察、非法选择回滚和一次支付继续检查。

同工具、同夹具和同身份下比较优化前后。工具或输入不同应明确失败并建立新基线，不能将语义变化忽略为性能差异。保留每阶段的全部原失败、测试清单和源守卫；已变化依赖的测试结果不能继承。

## 第六轮：单次动作内合并重复状态检查（2026-11-01）

用户最新允许压缩无意义的重复操作，优先维持模拟器正确执行与强化学习用途。本轮不再延续前几轮“验证次数必须不变”的局部限制：同一份已验证、完整结构未变化的原生状态可复用结果；真实规则、动态上下文、支付、生命周期、随机/候选与玩家信息检查保持。

复用只存在于Game.apply的事务副本内，覆盖本次原生动作、受控回合自动步骤和最后摘要，提交前释放。作用域先休眠，只有实际发起新选择时才开启；普通动作或结束既有选择且不产生新选择时，不为这层复用构建材料或扫描库存。首见状态走原完整校验和编码；后续必须通过全部原生字段、容器顺序/引用、标量类型和构造/schema守卫。仅由同作用域编码产生、仍未修改的wire允许复用解码材料；首次解码仍走原严格构造及检查，后续返回独立副本。复制与新副本的守卫构建合并，避免额外遍历；候选分支之间不共享可变状态。

## 第七轮：正常执行、诊断审计与存档处理分离（2026-11-01）

## Release / Debug 运行模式（2026-11-01）

正常对战和强化学习默认使用 `RuntimeMode.RELEASE`（`release`），保留原生内存帧与缓存路径；`RuntimeMode.DEBUG`（`debug`）开启逐动作状态、历史和结算边界审计。成功日志只记动作、对局标识、前后位置、分段耗时、结算/事件总数、队列峰值及已有状态摘要；失败再附最近32项结算类型、异常原因链和堆栈。不扫描事件分类、不写成功动作的完整步骤列表、不为日志额外复制状态或计算摘要。两种模式共用原结算器、支付/目标/候选与随机处理；合法操作、事务回滚、信息隔离和外部读档校验始终保留。模式本身不是稳定版本认证，发布稳定性仍由对应版本的验收决定。

模式是宿主运行配置，不进入快照、回放身份、状态摘要或玩家DTO。`Game.from_scenario`、`Game.from_decks`、`Game.from_snapshot` 及 `replay` / `load_replay` 接受关键字 `mode='debug'`；默认都是 `release`。已有对局只在动作边界设置 `game.runtime_mode`；`game.runtime_audits` 保留为兼容布尔别名。clone继承模式但使用独立空诊断缓冲区；从快照恢复需由宿主明确传入模式。`game.audit()` 仍可在release中按需检查独立副本。

Python调用示例：

```python
from hs_sim.engine import Game, RuntimeMode

game = Game.from_scenario(scenario, registry, mode=RuntimeMode.DEBUG)
game.apply(action)
records = game.debug_records  # 宿主最近128次动作的独立记录副本
```

命令行的 `demo` / `simulate` / `match` / `replay` 和测试服务统一使用 `--mode release` 或 `--mode debug`。debug默认写入 `outputs/engine-debug/cli-进程号.jsonl` 或 `server-端口-进程号.jsonl`，可用 `--debug-log 路径` 指定文件；release不接受此调试日志参数。每文件5MiB轮转，保留两个旧文件。库调用默认只保留内存记录，可使用 `hs_sim.engine.runtime.debug_log(path)` 上下文启用JSONL。独立训练进程使用各自日志文件。

```powershell
python -B -X utf8 -m hs_sim demo --mode debug --max-actions 3 --debug-log outputs/engine-debug/demo.jsonl
python -B -X utf8 -m web_ui.server --port 8770 --mode release
python -B -X utf8 -m web_ui.server --port 8770 --mode debug
```

详细记录覆盖 `Game.apply` 的成功与失败，包括非法原生动作和审计失败；保留异常原因链以及已丢弃事务的位置和结算步骤，不逐步复制全知快照。记录为宿主调试材料，可能包含原生命令实体ID和异常消息，不通过玩家/HTTP数据接口导出。日志写入失败不改变已完成动作或原异常。release不构造调试记录、不做分段计时、不输出引擎详细日志；既有HTTP/浏览器耗时日志保持其独立用途。测试加牌/法力调整、实验卡场景和新会话继承服务启动时的模式，不让读档操作悄悄切换模式。已启动进程不自动改模式。


## 第八轮：压缩内部证明检查及诊断成本（2026-11-01）

用户明确继续优化release，同时要求debug也控制性能成本。release不再为每个取出的结算项重审原手牌/法术支付证明，结束时仍检查真实完成状态、活跃窗口和剩余队列；支付、效果、候选与随机照常执行。显式调用的证明验证器仍执行原检查，外部恢复和回放校验不减。

## 第十轮：公共候选预览的局部副本（2026-11-02）

## 第十一轮：同一选择边界复用状态编码（2026-11-02）

原生选择先捕获完整支付边界证明，再保存等待执行的选择帧；两者会重复引用相同的历史状态。仅在这一次原生选择准备期间复用这些状态的编码，沿用最多64个状态的限制，到保存帧时立即丢弃暂存引用。此窗口不执行等待队列中的效果，不跨选择、动作或对局缓存可变状态。外部效果处理器不使用跨两次编码的暂存，编码遇到外部载荷仍清空暂存并执行原完整路径。

私有摘要及帧缓存可以只读共享已经生成的JSON状态树，避免为计算摘要再复制每个分支；默认codec导出和公开snapshot仍为每次出现创建独立可变树。实际运行的GameState、回调上下文及各个选择分支继续完整分离，原copy_runtime的逐出现复制不变。原始JSON字段、排序、全部证明字符串、候选/权重/RNG及摘要字节保持，未压缩或删减证明内容。信息输出、连击接受和回溯效果的必要副本复用现有runtime_copy，扩展复制协议及事务隔离保持。

## 第十二轮：直接生成公共状态字典及原生容器复制（2026-11-02）

原生状态和实体直接生成独立JSON值树，同时完成dataclass字段展开、元组转列表、枚举值及字典键归一化，不再先递归asdict、再生成整棵JSON字符串并解析回来。所有字段、键顺序、关键词排序、数值和摘要字节保持；整卡回放账本与特殊事件仍调用原专用编码器。每次转换单独缓存类型字段，不保留可变状态或跨动作转换结果。

原生快速路径不执行扩展复制钩子。遇到未知对象、容器子类、特殊复制协议或不能直接表达的值时，丢弃临时结果并从头调用完整旧编码器，保留扩展执行顺序、晚发生的修改及原错误行为；公开输出的可变分支继续分别分配。普通关键词set跳过随后被替换的无用副本，有注册reducer或特殊成员时仍回退。此处与上一轮仅替换JSON归一化的实验不同，同时合并了dataclass转换和JSON值构建。

runtime_copy使用精确原生类型集合，list与tuple中的原子值不再逐项递归；全为原子值的tuple按Python deepcopy既有语义保留自身，且先尊重本次memo。包含可变成员、循环、扩展或特殊协议的值仍保持原独立副本、别名及钩子语义。不分享可变GameState，不改变逐分支捕获次数，也不关闭GC、诊断、支付或恢复检查。

验证除四个真实后期慢动作外，还覆盖普通动作、选择、公开快照、环境分支复制、24次结束回合和固定40步真实动作的重新开局/连续执行。注册表复用的reset与进程冷启动明确区分；有限轨迹不代表包含策略推理和多进程训练的完整吞吐。优化中间样本、未采用方案、最终冻结源及专项/相关测试分别留存；实际结果与下一项仍仅登记原两份台账。

## 第十三轮：内部证明所有权与不可变记录复用（2026-11-02）

原生证明工厂已从实时局面捕获独立状态，等待帧和内部事务可以沿用这些只读证明；普通回调的每个状态出现仍分别复制。仅声明的手牌、连击、战吼、法术、技能完成尾及支付选择边界允许转交自己的证明字段，选择边界中的可执行工作继续递归区分。替换成外部mechanics处理器时回退原完整复制。公开clone、state、snapshot、事件和回放起点保持独立副本；内部事务仅复制只追加日志的容器，原历史项和回放起点只读复用。

release通过公共capture_state捕获伤害批次及手牌/法术/技能证明时，可以复用同次结算已判定为深层不可变的原生frozen记录。包含可变子项、扩展对象或复制协议的记录不参与共享；GameState、实体、玩家及list/dict/set始终独立复制。缓存最多8192对象，持有原对象防止ID复用，遇循环保守判为不可共享，随Resolution结束释放。执行回调和公开复制保留原完整复制，debug及外部mechanics不启用记录复用。此内部只读契约不支持运行期用object.__setattr__或私有字典篡改frozen记录。

公共复制器、原生帧编码器和读档字典复制器在返回或抛出异常时断开自己的递归闭包引用，及时释放本次memo；否则闭包循环会把复制前后对象图留到循环GC。该修复不关闭GC，也不改变源对象中的真实循环、别名、扩展memo和复制协议。通过临时关闭循环GC的弱引用专项确认普通源记录和捕获状态在操作结束后即可释放，正常性能测量仍启用GC。

内部刚产生的技能收据、可用法术候选键和英雄致死工作摘要共用encode_produced：release使用原生快速编码，debug保留原完整审计；外部FrameCodec.encode/decode不变。原生手牌/连击/战吼/技能完成尾不重复重算自己的捕获证明，debug仍执行这些检查；实际支付、完成身份、未决队列和玩法条件保持。玩家信息树只在同步摘要过程中只读借用，公开快照仍完整复制。两种模式的schema、规则、候选、随机状态、事件和摘要格式均不变。

后续候选按相同真实输入和release冷缓存动作成组比较，结合连续40步对局评估；小样本和后台负载限制必须明确。当前卡组的后续候选未达到10%稳定收益时不继续堆复杂缓存，提交验证版本给既有HTML会话做独立对战和其他卡组测试。功能缺口单独记录，跳过受影响局面不等于修复或全卡支持。

## 第十四轮：普通执行和查询复用静态材料（2026-11-03）

公共原生结算、动作校验、合法动作枚举和玩家观察在同步作用域内复用已有拼装材料缓存。缓存仍只保存冻结注册表的模板、配方身份和派生牌面，最多4个注册表、每个512项；不缓存实时费用、目标、卡牌可用性或对局结果。已有完整输入候选资格缓存的键、上限、候选顺序、权重和随机抽样不变。mutable注册表及未知注册表类型保留原路径。

release内部费用查询不再反复审计整段回合/出牌历史、所有实体和死亡记录的费用来源声明；实际本征条件、修正来源、支付方式、费用下限和可消费来源仍按当前局面计算。独立调用的费用查询、显式历史/来源验证器、存档恢复及debug仍保留原检查。同步作用域不能降低外层debug的检查等级，异常时恢复上下文；debug的缓存退出审计发生在事务采用新状态之前，失败仍可回滚。release不承诺发现对私有冻结记录或实时状态的任意手工篡改。

可用临时法术生成复用已有公共capture_state和encode_produced，私有信息仅在立即生成摘要字符串时只读借用；不改变证明内容、公开格式、schema、候选枚举或RNG。目标枚举在单次同步查询中计算一次当前目标范围，每个候选继续执行完整存活、区域、阵营、保护规则和目标谓词；下一次查询重新计算，扩展谓词和玩家回调继续使用独立状态/可见DTO。自动目标和手动选择的保护差异保持。

验收同时覆盖原卡组和独立HTML环境产生的法术过牌、铺场亡语、发现生成卡组。短局和长局造假者均使用真实schema680完整输入，每个冷样本显式清空静态材料及候选资格缓存。查询、提交和固定40步连续工作负载分开记录；同一次测量不混入profiler时间，不以三五个样本声称P95。功能缺口、旧测试夹具问题、失败批次及未采用实验保留，实际结果和下一项仅登记两份原台账。
## 第十五轮：真实异职业长尾的公共复制、查询与编码（2026-11-03）

新的真实长尾继续按同 core/schema 的完整局面对照。release 原生结束回合不逐结算项重审已经接受的全局证明，结束时仍核对批次身份、全部主体完成/跳过状态和嵌套完成栈；debug、显式验证与外部 mechanics 保持完整审计。只用于枚举已接受引用的比较窗口，独立扩展两个目录列表，其他字段只读借用，不执行回调或游戏效果。

公共捕获复用深层不可变的原生记录，纯原子元组不再占满8192项记录预算；普通复制器在单次复制中复用原子元组判定。已加载原生模块定义的回调可以复用这些只读记录，其 GameState、实体、玩家及可变容器仍独立；外部回调、debug 和公开 clone 保持完整副本。仅声明的结束回合证明和拼装 offer 的 before 字段可沿原私有证明所有权转交。内部事务的整个实时状态仍按原方式复制，不采用本轮实验过的跨事务冻结历史共享。

同一原生 release 操作内，严格伤害载荷解码按实际不可变输入身份复用，最多1024项。第一次仍完整解码，异常、可变输入和扩展对象不缓存；不以相等值混淆 bool/int，不跨动作保存，不缓存活跃游戏条件或随机结果。debug 和独立调用保持原解码。普通、无本征公式的价格查询直接计算本地/外部修正、支付方式、下限与可消费来源，实际支付仍产生完整费用证明；特殊公式继续原管线。原生手牌主体能力查询合并重复遍历，debug/独立查询保留原检查范围。

原生私有只读帧编码在单次调用内有界复用深层不可变记录的 JSON 树，最多8192条编码；单独 GameState/RuleContext 根不启用此缓存，避免为单一捕获做额外扫描。专用事件字段写入独立父行，不污染通用记录编码。未知扩展或完整回退会清空材料，编码结束断开递归闭包，及时释放原记录；公开转换和 snapshot 的每个可变分支仍独立。字段、顺序、证明字符串、摘要字节和 schema 均保持，不压缩或裁掉对局事实。

可用法术生成在一次纯预览和紧接的抽选收据之间复用自己独立捕获状态的编码，事件仍导出独立树。资格缓存键直接规范化完整结构，不再把已规范化的整局 JSON 字符串重复包进另一层 JSON；仍包括原状态/上下文、完整私有信息、全部有序权重及规则，注册表和 mechanics 身份及64项上限保持。仅内存键的编码方式变化，卡池、资格判断、候选顺序、权重、实际抽样、事件和恢复格式不变。

两模式沿用既有有界诊断，不增加逐步快照或额外摘要。保存全部候选源、失败与不利样本；固定场景的冷/热普通样本与 profiler 分开，连续真实动作另记。达到用户的后续收益不足10%条件后停止追加候选，仍须完成本地提交与既有 HTML 会话的独立环境复核。具体执行、实际结果与下一项仅在原两份台账记录。

## R16：回溯捕获、原生编码窗口与拼装审计继承

回溯起点、手牌法术回溯锚点及重试恢复共用 Resolution 的私有状态捕获；允许指定原有检查点作为复制来源。可变状态、实体、玩家和容器始终独立，只在 release 原生结算内复用深层不可变记录。手牌进度条件复用同一原生回调归属判断，外部条件和 debug 保持完整隔离；不改变实际进度条件、回溯资源、历史、身份及随机推进。

只读编码窗口中，原生记录转换后的 JSON 可按对象身份复用，无需再次递归确认记录的深层不可变性：该窗口不执行游戏工作，未知扩展进入原转换前后清空缓存。缓存只覆盖原生记录，最多8192项；不跨动作缓存实时状态，不给普通容器建立大量条目。状态摘要可使用同样的局部窗口，公开 state_to_dict、快照及可变导出仍独立。完整字段、JSON、摘要与外部恢复格式保持原样。

拼装的同步纯查询默认继承同一注册表外层作用域的审计模式，避免 release 在 draw/candidates 内重新升级成完整目录扫描。独立调用仍审计，显式 validate_offer/validate_boundary 强制审计，debug 不降级；卡池、顺序、权重、查询、抽样及实际结果不缓存。每次局部关键词刷新只扫描一次活跃附件，条件攻击及关键词没有适用声明时直接返回原空结果，保持真正条件、区域、休眠及消费政策。

功能修复改变 core、宿主目标或实际轨迹时，重建同版本的真实基线；旧版本证据保留，绝不修改旧快照版本头。普通计时保留 GC 与调度影响，诊断记录 GC 暂停以解释波动，不通过关闭 GC 或删去不利样本取得收益。具体场景、成组门槛、运行结果与交接继续只记原两份台账。

同类公共模块的普通深复制统一复用既有 runtime_copy，默认仍完整分离可变与不可变记录，并保留扩展复制协议、循环及别名语义。随机分段伤害/治疗的接受与每点窗口、自动法术重复/选目标和制作候选的私有证明使用同一 Resolution 捕获器；仍为每个实际结算点建立独立局面、重新计算当前候选并推进原 RNG。只有深层不可变的原生记录在 release 私有证明中复用，绝不缓存候选结果或合并实际伤害/治疗点。奥秘、有限触发与持有法术条件沿用原生回调归属判断，debug 和外部条件完整复制。证明验证、恢复和公开输出的原边界保持。
