# M1：附魔、动态能力与生命周期契约

本文记录 M1 引入的生命周期语义，当前 `prototype-v75` / `core-effects-v75` 继续使用这些约定；新增伤害与目标接口见 [M2 契约](m2-damage-targeting.md)，供后续扩展和回归测试使用。它是原型契约，**不表示已完成官方时序校准**。阶段顺序见 [长期计划](roadmap.md)，实际验收与下一项见 [项目状态](project-status.md)，模块边界见 [架构](architecture.md)。

目标验收地区已选择国服；精确热修生效时间和完整合法卡池仍需核实。地区选择、数据快照、机制实现和官方一致性是不同维度，不能互相替代。当前代表包也不声明国服标准或狂野完整支持。

## 1. 三种身份与状态来源

| 对象 | 身份与用途 |
| --- | --- |
| `CardDefinition` | 共享的卡牌定义；基础属性及印刷能力模板，不保存某一局的伤害、增益或能力消耗 |
| `Entity` | 对局中的独立实体；唯一 `id`，保存 owner、controller、区域、伤害、攻击次数、附件与来源关系 |
| `Enchantment` / `AbilityInstance` | 实体上的独立状态记录；使用全局唯一附件 ID，带来源、到期时间及沉默移除条件 |

创建或重置实体时，印刷关键词、战吼、亡语、触发和光环安装成 `origin='printed'` 的能力实例。后续授予能力使用 `origin='granted'`；结算读取实体当前能力，不能重新读取静态定义来恢复已经被沉默或消耗的能力。

`Enchantment` 保存 `attack/health/cost` 加法量及 `set_attack/set_health` 设值操作数，按获得顺序重算；同一属性的加法与设值互斥，详见 [属性运算契约](m2-stats.md)；`AbilityInstance.kind` 为 `keyword/trigger/deathrattle/aura/battlecry/on_play/on_use/spell_damage`，不同种类字段严格互斥。公共效果目前支持数值增益以及关键词/亡语/触发/攻击光环授予；印刷战吼使用独立 `battlecry` 实例，普通出牌主体仍为 `on_play`；尚无通用授予战吼接口。费用加法字段只是状态基础，不代表完整费用修改体系已完成。

实体的 `attack_bonus`、`health_bonus`、`cost_modifier`、`keywords` 为派生缓存。攻击力光环也每次从活跃来源重新计算，不写入永久增益。当前生命是最大生命减去累计伤害。

附件记录不可变；消费能力通过替换实例改变 `consumed`。多个亡语/触发按实例保存顺序分别执行。圣盾和复生是旗标：一次事件消费全部当前有效的同名实例；重复授予不会形成多层圣盾或一次死亡中的多次复生。

## 2. 增益、沉默与到期

`Buff` 创建单独的附魔记录，带来源 ID；当前场上接口的攻击和生命增量均可正可负。历史M1阶段的非负生命限制已由后续有符号增量实现扩展，负生命不冒充伤害、治疗或设值；原死亡检查点负责致命结果。存储卡`BuffStoredCard`仍遵循自己的明确限制，不能据场上接口外推。`RemoveEnchantment`按ID移除一条记录，不删除其他增益。

`Silence` 作用于场上随从，移除其 `remove_on_silence=True` 的附魔和能力，包括印刷能力、额外能力及已经消费的可移除记录。实体标记为 `silenced=True`。此标记不阻止以后获得新能力，也不阻止其他来源的光环继续影响它。

降低最大生命的移除采用以下原型契约：保留原有剩余生命，但不能高于新的最大生命。例如一个基础 4 血随从获得 +4 生命后受到 6 点伤害，剩余 2 血；移除增益后为 4 点生命上限、2 点剩余生命。该逻辑用于沉默、手动移除和到期，生命设值/交换/翻倍及光环交互另见 M2 属性和战斗状态契约。

`expires_turn` 是全局回合编号；`None` 不自动到期，当前回合编号表示本回合结束时移除。到期阶段按以下顺序执行：

1. 发出 `turn_ended`，先完成该事件引发的反应。
2. 收集并删除所有实体本阶段到期的附件，重新派生属性和光环，再发出 `attachments_expired`。已到期的触发能力不再监听同批到期事件。
3. 结算反应；若反应又产生本回合到期的附件，继续清理。循环受统一结算预算约束。
4. 切换全局回合，清零双方在场角色的本回合攻击次数，恢复行动方法力，执行回合开始事件及抽牌。

这不是“控制者下回合结束”或任意事件持续时间系统。稳定快照不得保留 `expires_turn < 当前回合` 的当前附件；历史死亡记录可以保留当时尚未失效的附件。

## 3. 区域与实体变化表

所有条目均为当前实现约定。未知官方边界留待 M6 核对，不根据这张表宣称完整官方行为。

| 操作 | 实体与区域 | 保留/重置规则 |
| --- | --- | --- |
| 抽牌、正常出牌 | 原实体从牌库到手牌、从手牌到战场或墓地 | 保留当前实体状态；出牌随从设置入场顺序及召唤回合，主动出牌才调度普通 `on_play` 主体与明确 `battlecry` 能力 |
| 新召唤 | 新实体进入指定玩家战场 | 安装印刷属性与能力；不执行战吼；满场只记录失败 |
| 正常死亡 | 原实体从战场到墓地 | 离场前保存 `DeathRecord`；实体不删除；死亡不等于普通区域迁移 |
| 回手 | 原实体进入当前 controller 的手牌 | 重置为当前 card_id 的印刷属性/能力，移除附魔、伤害、沉默、冻结和能力消耗；owner 不变 |
| 满手牌回手 | 原场上实体保持原控制者并经普通死亡进入墓地 | 记录 `card_burned`，原死亡协调器产生死亡记录及适用亡语/残骸/复生；不执行成功回手重置，见[修正契约](m2-full-hand-return-death.md) |
| 洗入牌库 | 原手牌/战场实体进入指定玩家牌库 | 重置为当前印刷定义，owner 不变、controller 改为牌库所属玩家；引擎 RNG 随机选择插入空隙，不重新打乱其他牌的相对顺序 |
| 变形 | 场上原实体保持 ID、owner、controller 和位置 | 替换 card_id 和基础属性、重建印刷能力，清伤害/附魔/沉默/消耗/冻结；保留当回合攻击次数、召唤回合与入场顺序 |
| `CopyMinion(mode='current')` | 为指定玩家创建新实体及新附件 ID | 复制当前基础属性、伤害、附魔、能力消耗和沉默状态；冻结状态按新控制者重新安排期限；光环重新计算，攻击次数及召唤状态按新召唤处理 |
| `CopyMinion(mode='base')` | 为指定玩家创建新实体 | 只使用当前 card_id 的印刷定义，不复制伤害/附魔/沉默/能力消耗 |
| 控制权转移 | 原实体移到目标玩家战场最右侧 | owner 不变，保留伤害/附件/当回合攻击次数；更新 controller、入场顺序和召唤回合；目标满场则失败 |
| 复生 | 原实体留墓地，创建新实体进入死亡时 controller 的战场 | 使用死亡时 card_id 的印刷定义，剩余生命设为 1，消费复生；不复制额外附魔/能力、冻结或伤害 |

复制和复生设置 `origin_entity_id` 指向来源实体。`current` 复制为附件分配新 ID，但保留附件的 `source_id`，仅作为历史来源追踪；它不会把能力的执行主体改回来源随从。行为执行时的 `ctx.source_id` 始终是持有该能力的实体。

控制权转移保留同一全局回合已经使用的攻击次数，上一回合的次数在切换回合时已清零。转控设置本回合召唤限制，冲锋/突袭按当前攻击规则处理。若攻击宣告后的反应令攻击双方成为友方，待执行的伤害阶段取消攻击并记录 `combatants_became_friendly`；宣告时已消耗的攻击次数不会返还。这只是当前攻击中断规则的一部分。

## 4. 死亡记录与复生阶段

死亡检查先保存每个将死亡随从的最后状态：实体/card_id、owner/controller、位置、回合、最终攻击/生命上限/伤害、基础属性、当前关键词、能力与附魔，以及唯一记录 ID 和死亡批次 ID。它们为不可变记录，之后光环消失、能力被消费、实体被变形或转控不会改变历史。

同批死亡时，先保存全部记录，再移出全部死亡随从，重新计算光环，发出死亡事件。亡语回调得到 `ctx.death`；要读取死亡位置、控制者或最后属性，应使用它，而非墓地实体当前字段。场上随从回到满手的失败路径写入普通死亡历史；普通存储卡溢出、变形和非死亡区域迁移不写入场上死亡历史。

当前死亡检查点的反应顺序为：

```text
捕获的普通事件触发
→ 收集的亡语（同一实体按能力保存顺序）
→ 收集的复生
→ 调用者原本的后续效果
```

跨实体顺序为当前行动方优先，再按入场顺序、实体 ID。每条反应产生的效果仍进入统一队列并具有自己的死亡检查点；不是把全部亡语代码一次执行完后才检查其后果。

带有效复生的随从死亡时，记录保留死亡时仍有效的复生能力，墓地实体相应能力被标记已消费，随后排入复生反应。执行时若有位置，新实体在原位置索引插入；索引按当时场面长度截断。印刷圣盾等能力重新安装，复生被消费，剩余生命为 1。额外授予的亡语、属性增益等不会复制到新实体。

亡语可以先占满空位，从而导致后续复生失败；失败发出 `reborn_failed`。如果检查点已经判定英雄死亡，后续反应队列停止，复生也不会继续。这些顺序及满场、终局边界均属于待官方校准的契约。

## 5. 快照、回放与失败回滚

当前快照 schema 74 包含附件 ID 分配器、死亡记录及批次计数、来源链、能力消耗、到期时间、派生缓存、RNG 和事件。嵌套字段严格校验，未知字段和缺失字段拒绝；来源实体/行为 ID 必须存在，当前附件 ID 全局唯一，计数器必须超过当前与历史已使用 ID。

稳定边界还会重算派生缓存，防止只改 `keywords` 或增益总数造成状态不一致。克隆、读取状态和导入/导出快照均不共享可变容器。

schema 1～73 快照明确拒绝，需要对应原引擎读取；当前没有自动迁移器。动作回放外层仍是 schema 1，其 `origin` 使用 schema 74 快照。回放要求规则版本、效果签名和注册表指纹匹配，每次成功操作重算状态与事件摘要。

单个外部操作中途失败时，实体变化、附件序号、死亡历史、事件和 RNG 一起回滚。M3 已支持结算中的选择挂起、保存恢复及继续执行，后续机制复用该流程。

## 6. 代表卡与可运行示例

`representative-m5-v38` 提供 269 个真实卡牌/衍生物 ID，另有一个用于场景的测试英雄。来源来自锁定的本地 build `36.6.0.251952` 数据记录；加载器校验每张记录的哈希，行为显式手写。原 16 条样本及 M2/M3 新增的 42 条记录都有实验适配；血法师在 M2 加入法伤与亡语抽牌。

```powershell
# 查看目标、覆盖状态和仍待确认的内容
python -m hs_sim target

# 卡塔图防御者被击杀并复生，随后被沉默并再次击杀
python -m hs_sim simulate examples/scenarios/reborn.json --actions examples/actions/reborn.json --card-set representative --events --replay-out outputs/reborn-replay.json
python -m hs_sim replay outputs/reborn-replay.json --card-set representative
```

示例文件：[场景](../examples/scenarios/reborn.json)、[操作](../examples/actions/reborn.json)。复生新实体的 ID 可预测是因为这个场景及操作序列固定；业务调用应读取当前状态，而不是给所有对局硬编码实体 ID。

真实代表卡仍有明确限制：职业、法术派系、构筑合法性、完整生成池均未接入。M2 已补目标战吼无候选时的出牌和火球的加法法伤。这些卡用于公共机制验证，不构成任何正式补丁的完整卡池。

本回合临时控制复用原永久转控和生命周期，独立纯标记在到期/沉默/手动移除归还，变形/跨区取消且当前复制不带物理归还，见[临时控制契约](m2-temporary-control.md)。精确CN政策待校准。
