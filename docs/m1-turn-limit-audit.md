# 回合上限与逻辑平局的现有表达

现有基础入口是 `Ruleset.draw_after_turn`，不需要再增加平局模块。指定 `draw_after_turn=N` 后，当前全局回合到达 N，在自然结束主体、反应、待选及到期处理完毕后关闭当前本人回合区间，并产生 `status='draw'`、`winner=None` 的终局；不制造下一个回合开始、抽牌或疲劳。若结束反应已造成别的终局，原解释器不会再开始这个自然交接。

`Ruleset.max_turns=200` 是工程预算。耗尽它会抛出 `ResolutionLimitExceeded` 并回滚当前动作，保留对局可继续的原边界。它不是官方对局回合上限；与明确的 `draw_after_turn` 同时到达时，现有玩法平局先处理。参见 [原资源契约](m2-resources.md) 和 [原回合调度契约](m3-turn-scheduling.md)。

该历史样例实际运行指定 `draw_after_turn=89`，通过公共 `EndTurn` 完整走到第 89 回合，再确认逻辑平局：本人开始区间数量为先手 45、后手 44；当前全局时钟保留 89，第 90 回合不开始，英雄保持存活，没有把平局伪装成双方受到伤害。此数值是测试中的显式配置，不是本轮新增的正式默认值。89 回合样例使用有限 2000 生命的实验英雄，以便原疲劳不提前结束测试，没有增加免疫或跨机制组合。

另一个有界样例在自然结束待选期间仍保留 `playing` 和未关闭区间；失败选择恢复原等待边界，成功选择后才关闭并平局。两个样例使用原保存、clone、独立注册表 replay 和玩家接口，未改变运行源、解释器、状态、协议或卡牌适配。

数值依据的强度须分开：2015 年 Hearthstone Science 发布的 [89 回合实验说明](https://www.youtube.com/watch?v=Uc392c5SfwY)描述了第 89 回合结束、未开始第 90 回合的历史行为；本轮读到搜索返回的发布者说明，视频直接读取失败，未审查视频像素或原始日志。2026 年 [玩家自己的对局报告](https://us.forums.blizzard.com/en/hearthstone/t/why-this-happened/165269)报告过长期对局平局，但没有给出精确计数，其他回复不能充当官方数值规范。未找到锁定补丁下国服正式默认值的强证据。

`draw_after_turn` 默认仍为 `None`；本项引入批次为 `prototype-v251` / `core-effects-v245`、schema 221、观察 76、命令 12、replay 1。本轮证明现有公共能力能表达该已知需求；正式目标 profile 的默认数值、准确国服时序，以及额外/跳过回合对官方计数的影响，仍属于 M0/M6 待核实范围，不能据此宣称最新国服回合规则已完成校准。未签名快照也不提供外部来源认证。

实际验证结果、当前执行位置和下一项只在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md) 维护。
