# 攻击期间免疫

`Keyword.IMMUNE_WHILE_ATTACKING` 表达“攻击时免疫”这一真实战斗属性。它不是永久 `IMMUNE`，也不是只预防反击伤害的 COMBAT 修正。实际进度、验证结果与下一项只在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md) 维护。

## 真实来源与原表达缺口

[官方长弓卡文](https://hearthstone.blizzard.com/en-gb/cards/311-gladiators-longbow)说明英雄在攻击期间免疫；[官方 30.2.2 公告](https://hearthstone.blizzard.com/en-us/news/24134638)中的猛禽狂怒说明带攻击期间免疫的愤怒的小鸟，并将其身材调整为 3/3。本地完整记录分别为 `DS1_188` 和 `VAC_410t`。这两个独立代表验证英雄有效装备与随从本体两个必要路径；不实现猛禽狂怒的主体或穷举来源。

原攻击宣告有 `ActionWindow`，宣告反应结束后关闭窗口，再交付 `CombatDamage` 和同一 `CombatExchange`。原永久免疫会错误地保护平时/被动受击的角色；只有 COMBAT 防护又无法保护宣告反应中的普通伤害。原健康数值规则没有“该角色是正在攻击的来源”这一条件，无法直接复用该规则来完整表达。

因此在 [原战斗模块](../hs_sim/engine/combat.py)增加纯 `is_immune(state, entity, combat=None)` 查询，原伤害执行器、主动目标检查及嘲讽资格共同读取；不安装/撤销临时永久免疫，不另开攻击流程、状态账户或伤害执行器。

## 原窗口与伤害交换中的角色

- 普通 `Keyword.IMMUNE` 保持旧行为。
- 新属性只有当前有效角色进入原攻击者角色时才提供免疫：宣告反应阶段读取现有攻击窗口；交付后的同批伤害读取已验证的 `CombatExchange.attacker_id`。仅作为防守者不获得免疫。
- 当前有效本体/装备属性在原实际结算点读取。攻击宣告后沉默随从、摧毁/替换武器会失去旧保护，伤害交换使用原当前武器；不会永久记住宣告时的旧武器。
- 原健康批次传入冻结局面与已验证交换，原 `immune` 防护原因、结果、护甲/圣盾/剧毒/吸血和数值管线保持。不是零伤害或豁免死亡的替代规则；普通消灭仍由原死亡管线负责。
- 原窗口关闭/取消后，未带该交换上下文的新伤害不获得保护；`attack_finished` 反应属于已结束攻击的原后续。最终一点耐久仍在原已接受交换完成后消耗，不取消该批已经报价的保护。
- 普通支付/攻击次数、强制随从攻击、重定向、终局、自然回合与工程预算继续由旧模块负责。没有新次数、时钟、回合或控制尾。

“宣告开始到原交换结束”的边界是当前内部执行契约，尚未经国服实际对局校准。官方卡文不单独证明所有窗口细节。

## 随从的原入场身份

攻击作用于原随从的这一段物理入场，不能只认实体 ID。原 `ActionWindow` 末尾追加 `attack_source_presence: BoardPresenceReference | None`，沿用已有 [场上来源模块](../hs_sim/engine/board_presence.py)；随从攻击宣告捕获原入场引用，英雄仍为 None 并沿用原英雄攻击历史。

纯免疫查询要求随从仍处于原入场；控制变化和原位置/卡面变化沿用既有物理驻留政策。离场停止保护；同一个 ID 离场再进场得到新 `board_presence_id`，不能获得旧窗口免疫。原交付检查也取消对新入场执行旧攻击：当前仍在场但原引用失效时，记录 `attacker_left_original_board_residence`；普通仍未回场的取消继续使用原处理路径及原因。

这只是一个已有窗口上的身份引用，没有新场上身份计数器、独立持久攻击账本或触发器。它进入原状态/上下文/帧序列化，恢复后读取原身份，不能重捕获为新入场。空引用的随从攻击窗口、其他实体冒用、未分配/布尔引用和未知字段严格拒绝；合法 unsigned 存档仍不提供来源真实性认证。

## 本体、装备和生命周期

新值进入原 `Keyword` 枚举和已有战斗属性许可。印刷随从本体沿用原附件、沉默、复制、转控和变形；有效装备通过原 `WEAPON_KEYWORDS` 缓存给当前回合英雄，但这个值只是条件属性，平时不等于免疫。武器离场、换装、被动受击与最后耐久沿原装备/磨损边界。

原关键词光环和计时声明许可识别该战斗属性，没有新增授予效果、光环目标、计时方式或组合机制。本批不接其他光环/授予/临时来源的真实主体；后续按具体真实卡复用原能力，确有缺口再补。

选择前的已支付动作、宣告反应、原入场和窗口保存在原帧中。选择失败回滚到原等待边界，动作失败沿原事务回滚；恢复、clone 与独立注册表 replay 沿用原解释器。公开属性可以出现在角色关键词中，内部窗口/入场引用/全知帧和对手隐藏身份不交给玩家。
