# 原生顺劈的基础战斗契约

普通随从与武器可声明 `CardDefinition.cleave=True`，默认 False。不另建伤害执行器，也不将顺劈发明为正式关键词。原生声明安装一个纯 `AbilityInstance(kind='cleave', origin='printed')`；沉默、变形、回手重放、当前/基础复制与转控沿原生命周期。授予、附魔存储、磁力/星舰等复合载体按后续真实卡需求处理，当前明确拒绝，不能当作普通原生声明接入。

引入时规则 `prototype-v202`、效果 `core-effects-v196`、schema190 拒绝旧1～189。只有 CardDefinition 末尾新增一个默认 False 字段；AbilityInstance 复用现有字段。全知 Entity/Player/GameState、事件、动作与玩家协议不新增字段。完整注册表及捕获卡面包含新声明，旧默认定义指纹因此改变；旧卡面其余内容保持。实际执行及验收结果见[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。

## 一次攻击的结算

原攻击窗口完成替换和反应后，`CombatDamage` 读取当前攻击者、最终受击者、当前攻击力与原生顺劈来源。随从从自身有效附件读取；英雄从本人当前有效装备武器读取，复用 `equipped_weapon`，不将能力缓存到英雄关键词上。受击方的顺劈来源不会在反击时再次顺劈。

最终目标是场上随从时，按其所在控制者的物理战场顺序，捕获左一格、右一格的当前有效随从。英雄没有战场邻居。非随从、休眠、非活跃、非正生命、将死格不受击，也不越过该格寻找更远对象；不会把攻击者自己纳入额外受击对象。这些边界是当前内部政策，待 M6 国服校准。

原 `DamageBatch` 保存主目标伤害、主目标对攻击者的反击，再保存左邻/右邻的额外伤害。额外包继承攻击者的完整当前攻击力、来源 ID 和 COMBAT 分类；所有包由原批次完成准备、伤害预防、伤害提交、吸血、事件和死亡检查。原 `CombatExchange` 仅保留一次，正常攻击次数、真实英雄攻击历史和武器磨损复用原管线。攻击者在反击中死亡不会提前截断已准备的额外包。

批次结构只允许两份原互伤包以及最多两份同源、同攻击量、互异且不重复主目标/攻击者的额外包。执行时另重算完整有序相邻对象，拒绝删去一侧、加入远处对象或伪造额外包。普通无顺劈攻击保持原两包顺序。未改变法术及非战斗批次的任意包数量接口。

等待期间的目标替换、邻居移除、攻击力变化、沉默或装备替换会影响最终捕获；移除攻击者沿原攻击取消。捕获仍是原批次内的瞬时步骤，没有新增等待窗或随机调用。恢复、克隆、回放与事务沿原解释器；当前实体、死亡记录及捕获状态校验纯附件及唯一原生声明，拒绝冒充卡面或任意授予。

## 必要来源与证据边界

[本地完整原始证据](../data/support/cleave-combat-basics.json)仅固定 GVG_113 死神4000型（8费6/9机械）和 BT_271 斩炎（7费5攻3耐久恶魔猎手武器）；后者本地 HEALTH=3 按武器耐久解释。实验注册表在专项中独立构建，生产代表卡包保持。完整文件 pin 为 `83c5d189d414f1eaf6bd837e0154fcffdd32104aca19f6787cd738e6834a6d13`，每条完整 raw 另有独立哈希。

[暴雪2017年站位说明](https://hearthstone.blizzard.com/en-us/news/21295165)列出武器与随从的相邻伤害来源，并说明选取目标可减少反伤。这支持广义独立需求，不证明当前国服准确包顺序、战场资格、免疫/休眠边界、反应窗口或合法卡池。M6 待校准；本地11条文字线索和两个必要适配也不是全部顺劈来源的完成分母。真实 DAL_062 授予线索保留，按卡后置，不新增特殊授予或机制组合。
