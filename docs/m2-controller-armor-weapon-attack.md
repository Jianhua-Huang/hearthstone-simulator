# 按当前控制者护甲持续计算武器攻击力

B226 的独立属性规则扩展原 `StatRelationSpec`，复用属性、装备、护甲账户、攻击政策及解释器。实际进度、验收证据和下一项仅维护在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md)。

## 有限声明

```python
StatRelationSpec(operand=StatRelationOperand.CONTROLLER_ARMOR)
```

目标仍为 Attack，层为 `FINAL_ATTACK`，amount 必须为整数零，阈值与比较符必须为 None。仅允许普通武器上的一个原生印刷声明；随从、英雄、复合载体、混入另一关系、动态授予、期限、消费或重复附件均拒绝。原普通随从资格函数保持原语义，其他机制不能因此将武器当作随从。

纯查询读取武器当前 controller 的当前英雄 armor，写入原 `Entity.conditional_attack` 派生缓存。这里复用已有数值槽作为状态依赖操作数；武器的最终攻击直接取该值，不能将其再加到印刷攻击或永久附魔上。普通数值修改仍保存在原层中，刷新不会累加、清除或重施附魔。此最终层优先级是明确的本地政策，尚未获得国服校准证据。

没有新增 State、Player、Entity、CardDefinition 或私有保存字段，没有新的资源账户、攻击执行器或任意表达式图。只新增有限枚举值；旧引擎无法解释该值，当前 `core-effects-v295` 指纹拒绝旧机制包。prototype-v295、schema259、观察84、命令12、replay1保持。

## 刷新与生命周期

原光环刷新和事件前规范化均更新缓存；若该武器当前装备在行动玩家身上，同步更新原英雄 `weapon_attack` 贡献，然后才捕获监听上下文。非行动玩家仍可查询武器攻击，但不获得本回合英雄攻击贡献。护甲获得、直接失去、伤害吸收和英雄替换均使用原账户与事件，不增加第二条记账路径。

武器转移保留原物理实体和附件，立即读取新控制者护甲。替换、损坏、销毁、死亡记录、耐久磨损与英雄攻击次数继续由原装备和战斗管线负责。历史死亡记录保存原窗口攻击；之后护甲变化不重新计算这份冻结记录。自身生命最终关系的死亡校验仍只针对该关系，不将武器关系错误地解释为生命值。

攻击声明后的待选仍由旧窗口恢复；伤害准备前读取当时攻击。已经准备的伤害保持原冻结数值，即使反击消耗护甲，亦不回改该次攻击量。这沿用现有战斗契约，精确国服时序仍待校准。

## 必要代表与信息边界

只安装 LOOT_044 铁刃护手的实验定义；CORE_LOOT_044 保留完整原始证据，不额外接第二张代表。武器2费、原始攻击0、耐久2及战士史诗元信息来自原始卡库。`cannot_attack_heroes` 直接复用现有武器到英雄攻击政策，不建立新的关键词继承矩阵。

[官方卡库](https://hearthstone.blizzard.com/en-gb/cards/129222-bladed-gauntlet/)支持“攻击力等同护甲”及“无法攻击英雄”的卡文和类型、职业、稀有度，不能单靠卡文证明数值层、所有区域显示或准确国服窗口。原始证据完整保存于 [隔离支持文件](../data/support/armor-weapon-attack-basics.json)。

模型、JSON 和 FrameCodec 在各自状态域检查派生缓存与原生声明；历史上下文读取其自己的英雄护甲。选择恢复、clone、独立注册表回放和异常回滚共用原管线。玩家接口只给公开攻击值与合法操作，不返回关系、缓存、附件或全知工作帧。恢复校验不承担未签名存档来源认证。
