# 独立亡语禁止契约

死亡守望者（YOP_012）的完整原文是“亡语不会触发”。本基础能力复用现有亡语调度、真实死亡、目标规则与解释器。仅接入死亡守望者、装死（ICC_052）及血法师萨尔诺斯（EX1_012）三个完整隔离代表；静逝无声（YOP_012e）仅保留原始证据，不另外制作可授予附魔。

## 当前资格与结构身份

`Keyword.DEATHRATTLE_SUPPRESSOR`是内核的原生来源属性，不是新增官方命名关键词。当前活跃、存活且未被标记消灭的场上随从来源，使`deathrattles_can_trigger`返回假；双方来源使用同一判断，手牌、牌库、离场和休眠来源不生效。只接受随从的印刷声明；普通关键词授予、连续关键词光环和组合载体不扩展该属性。当前复制沿原附件生命周期保留；基础复制恢复印刷声明，沉默清除来源本体声明。

`triggerable_deathrattles`将上述门禁与原`active_abilities`结合。原印刷声明、当前物理附件、能力来源和历史死亡材料仍保留；被禁止不等于沉默或从结构上删除亡语。按印刷能力、历史亡语材料筛选的消费者继续使用原有结构查询，不一律改为执行资格。

引擎拥有的`triggerable_deathrattle`目标谓词只读取当前活跃场上随从及公开场上禁用来源。装死还声明友方、场上随从域，操作枚举、玩家命令和实际验证共用该目标判断。目标非法时沿原事务拒绝，费用、实体、历史及RNG不改变。这个谓词不读取隐藏手牌、牌库或隐藏统计，不增加玩家DTO字段。

官方[20.0补丁修复](https://hearthstone.blizzard.com/en-us/news/23642550/opisanie-obnovleniya-20-0)明确处理了死亡守望者在场时，装死等仍能选取亡语随从的问题。这支持目标资格需要受禁用影响；它没有证明当前国服全部时序。

## 原接受窗口与自然收据

自然死亡仍按原内核完整移除、刷新后接受亡语。各自然死亡先完成`DeathRecord.deathrattles_blocked`布尔收据，再发布本批死亡、尸体和普通反应；替换武器在原销毁发布前完成收据，英雄死亡沿原致死协调器处理。收据只有保留未消费结构亡语的死亡才可为真，不能用于普通无亡语死亡。死亡编号沿原单调分配，不假定回溯后的编号等于数组位置。

被禁止的自然死亡不创建`DeathrattleBatch`或激活历史，也不消费亡语编号；真实死亡、归因、尸体以及原材料继续存在。原队列覆盖校验对明确禁止的死亡要求零接受主体，对其他死亡仍要求完整主体覆盖；禁止收据与实际接受组不能并存。后续来源离场不追补这次死亡的亡语。

主动`TriggerDeathrattles`在自身原执行窗口经过同一门禁，不制造自然死亡、尸体或禁止死亡收据。门禁只控制新的接受。已经接受的主体继续使用原窗口、批次、开始/结束控制标记及完整证明，后续来源进场不重新裁剪该计划；后续新的触发另按新局面判断。没有另造亡语执行流程、重复机制或新检查点。

英雄第一次致死且所有可救援亡语被禁止时，使用原无可执行亡语的终局路径；原已接受协调器中的新致死仍保留其独立死亡事实及禁止收据。既有英雄控制、消费和终局队列校验复用这一明确缺席证明。

## 生命周期、保存与边界

沉默、回手、变形、转控、当前/基础复制及休眠/唤醒使用原实体管线。来源被沉默后门禁消失；沉默另一个随从不会清除外部禁用来源。来源同时死亡时，当前实现按既有移除后接受窗口判断，不冻结“死亡前仍在场”的来源。将死状态的资格、同时死亡与武器/英雄精确发布窗口均为待国服校准政策。

收据进入完整宿主快照和回放；schema225拒绝旧1～224，prototype-v255/core-effects-v249。当前原生属性和历史载体均须符合声明，未开始主体的捕获窗口不得含有效禁用来源，禁止死亡不能冒充已接受亡语。完整未签名历史仍不提供外部来源认证。观察76/命令12/replay1保持，收据和完整激活历史不进入玩家观察。

不批量接卡，不扩展特殊授予、固定重复、跨族组合或其他模式。实际运行结果、已知差异和下一项只维护在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)，原始数据及限定验证见[本批证据](../outputs/deathrattle-prohibition-basics-20261012/verification.json)。完整来源、正式池及国服校准仍开放。
