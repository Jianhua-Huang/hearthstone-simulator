# 每回合首张指定类型牌的费用光环

穆格的真实被动技能在解锁后成为原首随从报价的装备来源；完整原生载体、实际本人回合及同一FirstPlayCostFact复用见[契约](m3-mugzee-passive-powers.md)。下文原普通随从来源批次保留其范围。

持续费用光环可以按付款者当前实际回合的出牌历史判断“首张”。实际执行、验证和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。本契约是内部规则表达，尚未完成国服时序校准。

## 声明与适用范围

```python
CostAuraSpec(
    CostSpec(delta=-1, card_types=(CardType.MINION,)),
    first_per_turn=True,
)
```

`first_per_turn` 默认 `False`，保留既有光环行为。启用时支持友方、单一随从或法术类型的减费或设置费用。原生普通随从提供光环；声明和附件按原卡面、数量及来源核对。真实纳拉雷克斯现按[首张当前种族契约](m2-first-tribe-turn-cost-aura.md)扩展随从种族筛选；任意授予、融合载体和其他额外筛选继续明确拒绝。

这是对现有 `CostAuraSpec` 和费用报价管线的扩展，没有新增费用模块、玩家账户、实体缓存或全局状态字段。一次性玩家费用修正有独立用途时钟，不能代替依附存活来源的持续光环。

## 历史、报价与付款

条件读取付款者当前实际回合已经提交的付费手牌出牌记录，按提交时冻结的卡牌类型匹配。来源本回合何时进入、是否已贡献过减费，不改变玩家的历史。已先使用同类牌，再召唤这个来源，后续牌不能重新享受首张减费；直接使用来源自身也会成为一次随从出牌。普通召唤、英雄技能和报价查询不会产生手牌出牌记录。不同玩家、不同类型分别判断；新实际回合自然读取新回合历史，不维护可漂移的用途缓存。

反制的已提交付费手牌根仍由原出牌历史保留，条件不以完成主体为门槛。自动施法及其他间接来源的正式计数政策仍需证据，不能从这里的付费手牌政策推定全部来源完成。特别是卡雷苟斯的自动施法边界尚未校准。

物理报价、生成报价、合法操作枚举和付款复用原管线。每个有效物理来源各贡献一次；已有本地费用层、外部附件顺序、最低零及支付收据保持。生成报价只查询假设新牌，不分配实体、不增加历史、不耗 RNG 或用途。实际付款冻结原报价；之后来源离场或历史推进不改写已经支付的金额。动作失败回滚付款和未提交的出牌历史；等待选择期间已经提交的根仍占据首张位置。

## 生命周期与保存

光环沿原来源生命周期：未进入场面的来源不贡献；沉默、死亡、回手、变形和休眠停止贡献；唤醒和转控按现时来源及受益玩家历史重新报价。复制得到新的物理来源，并不复制玩家的“首张”资格。

`FirstPlayCostFact` 保存完整有序付费手牌前缀，复用既有 `PlayerPlayedClassCostRow` 和冻结卡面，不嵌套整份旧支付证明。它记录付款者、卡牌类型、实际回合、动作、分配边界和前缀长度；`CostContribution.first_play` 只供启用条件的光环使用。前缀顺序、类型、原报价时钟和付款者必须一致，紧凑事实重新检查条件；恢复时再与实际保留历史前缀绑定，允许后续合法推进。原操作窗口的完整状态继续承担接受证明，不能把这些检查当成未签名存档的来源认证。

原快照和帧编解码保存完整材料；玩家只取得有权限的最终手牌费用与公开信息，不获得贡献、前缀、分配身份或全知状态。观察/命令/replay 接口版本保持 76/12/1。结构变为 prototype-v268 / core-effects-v262 / schema235，旧 schema1～234 必须使用其原引擎；默认未启用条件的生产注册表指纹保持。

## 必要来源与限制

仅隔离适配 EX1_076 小个子召唤师，完整本地卡面为 2 费 2/2，其本人每回合首张随从减费 1 点。[官方卡牌库](https://hearthstone.blizzard.com/en-gb/cards/37)支持这一基本卡牌需求，未证明国服精确时序。完整原行及 pin 见[本地来源](../data/support/first-play-turn-cost-basics.json)。同文件保留 DAL_609 / CORE_DAL_609 原行；它们证明首张法术设置为零的需求，完整发现战吼未适配。设置为零的管线用诊断载体验证，不把诊断载体当作真实卡牌。

正式候选池、完整卡牌来源、间接起源、其他计数或类别及国服校准继续开放；本项不能用于宣称整套费用机制或全部基础机制完成。
