# 持续冻结防护与不可沉默来源审查

执行、验证结果和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。本页描述独立冻结防护如何接入既有关键词光环、冻结状态和生命周期，不声明全部来源或准确国服校准完成。

## 标签先按载体解释

[不可沉默原始来源](../data/support/silence-source-audit.json)对本地完整卡库同时检查标签和去除格式后的中英文文本，共100候选：92附魔、4武器、4个TB/CRED随从，没有可收藏候选。最初98行标签/字面搜索遗漏两个只有格式化卡文的CRED随从；完整匹配保留它们，不能把标签枚举当成完整机制分母。

这些随从没有在当前构筑主线适配。武器不属于原 `Silence` 的场上随从作用域；附魔必须继续区分实体附件、持续光环、玩家效果及其他模式来源。原 `remove_on_silence`、外部光环重算和独立玩家效果可表达相应基础边界，单凭附魔的 `CANT_BE_SILENCED` 不证明其随从本体免疫沉默。本批没有新增全局免沉默关键词，也没有宣布92附魔的完整载体映射已经结束。

例如团队领袖的CS2_122e是持续攻击光环证据，伺机待发EX1_145o是玩家未来费用证据；两者不意味着普通随从本体无法沉默。活化龙息的DRG_068e也标记该标签，但它描述受保护者的持续“无法冻结”贡献：沉默受保护者不会删除其他活跃来源，沉默活化龙息会删除该来源。原完整行均保留，未执行的内容不能当白板，也不能从未来正式池静默删去。

## 真实冻结防护缺口

原 `Freeze` 只检查目标存活/区域和已有冻结，原连续关键词中没有冻结防护；普通 `Immune` 是伤害与主动目标规则，无法表达活化龙息的效果。[官方22.2补丁](https://hearthstone.blizzard.com/en-gb/news/23765270/opisanie-obnovleniya-22-2)明确记载活化龙息阻止冻结的情况。[2019年原回复](https://www.reddit.com/r/hearthstone/comments/e64k7m/comment/f9oavti/)由puffinplays表示会解除已有冻结，官方论坛当时将其引用为开发者回复；这是历史语义证据，不是当前国服实测或开发者身份的独立认证。

新增 `Keyword.CANT_BE_FROZEN` 复用原实体关键词集合。活化龙息使用：

```python
KeywordAuraSpec(
    Keyword.CANT_BE_FROZEN,
    target="friendly_minions",
    include_self=True,
)
```

只有原普通友方场上随从光环范围获准：不添加英雄/手牌、相邻、种族筛选、动态条件等新声明范围。自身包含在“你的随从”中。来源活跃资格、存活/将死处理、休眠、控制权、变形和沉默继续沿原光环选择与检查点政策，不新增专用光环执行器。

## 新增冻结与已有冻结

`combat.can_be_frozen` 读取已派生的当前关键词，原 `Freeze` 在计算自身回合截止前检查它。受保护时沿用 `freeze_unchanged` 事件并记录内核 reason，不写入 `frozen_until_owner_turn`，不发出成功 `frozen`。主动目标仍合法，寒冰箭的伤害照常结算；冻结防护不等于伤害免疫，普通伤害免疫也不会单独阻止冻结。

原 `Resolution.refresh_auras` 在全部光环、条件和装备贡献稳定后，清除受保护角色已有的冻结截止。先清除所有受保护者，再逐个发布既有 `unfrozen`，反应不会看到半批冻结状态。精确刷新检查点、原来源将死边界和此处事件顺序是内部政策，留待国服校准。普通自然到期和显式 `Unfreeze` 继续使用同一字段；光环离场不恢复已清除的旧截止，之后真正的新 `Freeze` 才重新计算截止。

解除冻结不归还已用攻击次数，不撤销召唤限制。原 `CopyMinion(current)`在新位置/控制者光环派生后，也用相同资格判断是否继承来源冻结；不会在已经受保护的新实体上重新写入截止。复制、召唤、沉默、回手、变形、转控、休眠/唤醒和来源死亡均复用原生命周期。

共享 `CopyEntryMaterial` 的场上当前复制也遵守这一资格检查。它先恢复材料并派生新实体的当前贡献，仅在 `can_be_frozen` 允许时重算冻结期限。不能先写入不合法的冻结再靠后续刷新解除，否则会给从未合法冻结的新实体产生虚假的 `unfrozen` 事件和监听效果。来源的冻结材料仍保留；没有防护的接收者按新控制者和召唤机会正常继承冻结，基础复制继续不继承该状态。

此修正改变原事件语义，默认效果身份为 `core-effects-v285`；规则 `prototype-v290`、schema254及玩家接口布局保持。旧效果版本的存档须由匹配的旧引擎读取，不能默默用新事件序列恢复。版本断言与显式测试工厂读取结算器的 `CORE_EFFECTS_VERSION`，不重复维护散落的当前版本字面量。准确国服窗口仍按原校准范围登记，执行证据见两份台账。

## 保存、等待与玩家信息

稳定状态拒绝活跃受保护角色仍持有冻结截止。原快照重算校验把截止纳入比较，验证时不发布清除冻结事件；不能仅去掉缓存关键词后让恢复静默修正不一致的原字段。待选帧、clone、独立注册表回放与失败回滚继续由公共解释器承担，没有新的状态账户或时间记录。

既有 `freeze_unchanged`/`unfrozen`事件类别和公开字段保持；玩家可见在场关键词和布尔冻结状态，不能取得冻结截止、完整来源证明、全知状态或对方隐藏卡。存档的重算一致性不提供未签名外部来源认证。
