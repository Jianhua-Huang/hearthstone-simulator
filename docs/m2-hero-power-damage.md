# 英雄技能伤害加成的独立基础

原 `HealthRule` 已能表达原生随从对英雄技能伤害的加成，无需新增模块、关键词、伤害管线或账户。此页记录实现契约；实际执行、验收和下一项只在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md) 维护。

## 真实来源和最小表达

[官方 Fallen Hero 卡牌页面](https://hearthstone.blizzard.com/en-us/cards/2545-fallen-hero/)说明它令己方英雄技能额外造成 1 点伤害。本地完整 `AT_003` 中文名为“英雄之魂”：法师、稀有、亡灵、2 费 3/2，没有自身战吼或亡语。原生定义直接安装一个打印的公共规则：

```python
HealthRule(HealthFlow.DAMAGE, HealthOp.ADD, 1,
           source_relation='friendly',
           damage_kinds=(DamageKind.HERO_POWER,))
```

唯一必要英雄技能为本地完整 `HERO_08bp` 火焰冲击：2 费、对一个合法角色造成 1 点伤害，普通 `on_use` 返回 `Damage(target_id, 1, source_id, DamageKind.HERO_POWER)`。目标、费用、次数、主体接受和完成证明沿原英雄技能路径。

[完整原始证据包](../data/support/hero-power-damage-basics.json)保留同标签的四行 `AT_003`、`CORE_AT_003`、`YOD_008`、`PVPDR_SCH_Maget3`，加上火焰冲击完整原行；只有 `AT_003` 和 `HERO_08bp` 注册在 [隔离专项](../tests/test_hero_power_damage_basics.py)。其余三行不注册执行适配；武器的使用后耐久行为没有借此验证。包 canonical PIN 为 `1d14d5280d78f2aa61da774cc775a54fb6f92abacb66be2c9140988825c33cf6`。原始 36022 行卡库 SHA256 为 `fd0a3412afa031504f0553210670d6c14ce02ca952819f7524514a8003b86c08`；固定本地 36.6.0.251952/zhCN 数据不是当前国服正式池认证。

## 共享报价和来源生命周期

[health_rules.py](../hs_sim/engine/health_rules.py)在普通伤害包实际准备时读取有效场上来源，随后沿 SOURCE ADD 层执行。来源必须存活、活跃、非将死；手牌、牌库、离场或休眠的实体不参与。`friendly` 比较伤害来源与提供者的当前控制者，因此转控后加成随新的控制者解释。每个有效物理来源有自己的既有能力身份；一份来源令火焰冲击从 1 变为 2，两份令其变为 3。

加成限定 `HealthFlow.DAMAGE` 与 `DamageKind.HERO_POWER`，不作用于法术、战斗、疲劳、普通效果、随从能力或英雄技能治疗。伤害包声明的基础值保留 1，匹配的规则附件 ID 进入原报价和事件。原普通批次读取同一份局面，之后的独立包重新读取当前有效来源；没有新接受窗或死亡检查点。

沉默移除来源的原健康规则；死亡、回手和变形沿公共生命周期失去加成。current 复制保留沉默结果，base 复制重建原打印规则；休眠不销毁规则，醒来后原有效规则重新参与报价。上述都是单个来源的生命周期边界，不建立组合族或特殊授予契约。

## 等待、存档、支付和玩家接口

英雄技能已接受的普通主体仍只声明基础伤害。若原 `hero_power_started` 反应等待后来源被沉默，尚未执行的伤害按其实际报价局面成为 1；若原 `health_resolved` 已结算 2 点伤害后等待，之后沉默不会重伤或改写已结算数值。两种等待均沿原解释器保存、独立注册表恢复、clone 和 replay；失败选择回滚保留原 pending 状态，不重复付款或伤害。

玩家从原公开合法动作提交带 revision 的英雄技能命令，只支付一次 2 费并消耗一次使用。已用技能拒绝再次使用，事务状态保持。全知规则、帧与对方隐藏身份不进入玩家观察；存档增加未知规则字段时，即使重算外层 hash 仍由原 typed 校验拒绝。未签名存档不认证外部来源。

没有运行代码或协议迁移：`prototype-v255` / `core-effects-v249`、schema 225 拒旧 1～224、Keyword 46、观察 76、命令 12、replay 1、生产代表包 64 与合成包 3 保持。

## 证据限度

官方卡文支持来源的数值定义；精确国服接受、将死、同时批次及发布时序仍未校准。永久本局加成、完整真实来源及正式池尚未由本契约覆盖。其他规则和具体来源消费者按各自真实需求处理，不增加任意伤害分类、条件授予或组合。M0、M6、M7 和完整基础目标继续开放。
