# 场上原生来源的英雄技能禁用

ICC_902 摧心者要求双方英雄技能均无法使用。此前逐技能 `use_rule` 只约束手动入口，不能代表当前公共禁用规则；效果激活与被动监听的绕过已实际诊断。执行结果、差异与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 原生来源与生命周期

```python
CardDefinition(
    'ICC_902', '摧心者', CardType.MINION,
    cost=3, attack=2, health=5,
    keywords=(Keyword.HERO_POWER_SUPPRESSOR,),
    metadata=metadata_from_record(raw),
)
```

`HERO_POWER_SUPPRESSOR` 是内核原生标记，不是新增对外正式关键词，也不能把枚举成员数当作机制完成度。它复用现有印刷关键词附件、派生缓存、复制、沉默和离区处理，没有新状态字段或运行模块。

注册只接受普通随从来源；禁止动态授予、关键词光环或复合载体扩展。保存时检查标记原生出处、数量、可移除政策和载体类型，不能伪造为授予或其他牌型。死亡材料继续保留原印刷附件，用于既有复制和生命周期验证。

`hero_powers_can_activate(state)` 为纯查询：任一方当前场上存在活跃、存活、未待销毁且拥有有效标记的随从，双方英雄技能均被禁用。手牌、离区、死亡和休眠不提供禁用；沉默移除贡献，唤醒、正常印刷重置或基础复制恢复印刷贡献。控制转移不改变双方禁用；多个来源须全部退役才解除。

## 手动与效果激活

手动 `use_error` 在费用、次数和逐技能条件之前判断公共门禁。因此原合法操作、玩家权限与实际动作共用同一个结果；被拒绝动作不支付、不消耗次数、不建立成功激活记录。

`TriggerHeroPower` 先保持原安装身份和引用守卫，再判断门禁；被禁用时保存完整的失败激活记录，`failure='disabled'`、已完成、没有主体或重复贡献。此尝试不支付、不消费使用次数，也不进行自动目标或抉择抽样。没有把技能删掉或替换为白板。

原实际激活与本局次数费用投影均识别这个失败种类。选择未被接受的禁用根不消费合并选择用途；失败根不能伪造主体或重复来源。安装、替换、额外技能槽和固有技能数据继续沿原管线，之后仍按当前场上门禁判断是否可用。

## 被动主体与维护操作

原被动监听守卫 `CheckHeroPowerTrigger` 按其完整捕获状态判断门禁。原窗有禁用来源时，主体不接受；后来移除来源不能借机放行。原窗已允许时，后续来源出现不能撤销该已接受窗口，但技能安装身份仍须通过既有守卫。

已经接受的普通技能主体、等待选择与整次计划继续执行；主体中出现禁用来源不会中途取消自己的后续效果。公共结束主体复用原跳过、计划与解释器，没有另建事件执行器。

普通主动技能的维护监听继续执行，不把技能实体的全部事件关闭。替换、奖励、升级和技能卡面更新仍能发生；更新完成的技能继续受公共门禁约束。当前构筑被动来源依原监听主体实现；没有借此泛化尚无真实需求的连续技能光环或其他模式规则。

上述接受时点与效果/被动门禁是明确的本地政策，精确国服窗口尚待M6校准。结构维护继续是已获官方历史证据支持的要求，而非允许在禁用期间执行技能主体。
