# 原生英雄技能有限与无限次数贡献

AT_080 要塞指挥官允许每回合使用两次英雄技能，AT_008 考达拉幼龙允许任意次数。它们是当前场上来源的许可，不是技能本体的永久次数修改。执行结果、差异和下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 声明与实例

```python
HeroPowerUseAuraSpec(limit=2)     # 要塞指挥官
HeroPowerUseAuraSpec(limit=None)  # 考达拉幼龙，真正没有次数上限

CardDefinition(..., hero_power_use_aura=HeroPowerUseAuraSpec(limit=2))
```

有限上限必须是正整数，排除布尔值；`None` 是显式无限，不使用大整数或工程结算预算作为替代。单一声明只包含次数许可，不扩展条件、减费、动态授予或跨机制组合。

仅普通原生随从提供。原 `AbilityInstance` 增加可空的完整声明字段，印刷安装产生 `hero_power_use_aura` 附件；来源、顺序、沉默移除、复制、控制转移、休眠和离区继续使用已有生命周期。保存时验证来源普通类型、唯一原生实例、完整声明、不可伪造授予及静态配置匹配。

## 有效上限与实际使用

`effective_use_limit(state, power)` 是纯查询，使用技能自己的原 `use_limit` 基准与当前控制者场上活跃、存活、未待销毁的来源贡献。有限值取最大值；任一无限来源使结果为 `None`。多个有限来源不会各产生独立用途，也不会简单加成三次或四次。

这项最大值与多槽政策是明确的内部原型契约，精确国服叠加和全部来源窗口仍待校准。保留现有各安装技能独立的 `uses_this_turn`，不合并技能槽，也不引入新的玩家次数账本。技能本身的较高次数或显式 `SetHeroPowerUses` 修改继续保留；来源贡献不改写这个基准。

手动公共资格以有效上限检查实际已用次数；合法动作和付款继续复用原入口。无限仍须满足费用、目标、当前可用性及其他既有资格。每次实际手动使用继续独立支付和登记使用事实；来源进入不重置旧使用，来源退役不退款费用或次数。

真正的新回合沿原管线重置技能已用量；替换与额外安装保持原安装策略，再读取当前贡献，不另外造替换或回合时钟。自动效果激活维持原“不支付、不消耗手动次数”的独立契约，本项不重新定义自动技能重复。

## 来源与恢复

来源只在场上活跃且存活时贡献。沉默、死亡、回手、变形和休眠撤回；唤醒或基础复制恢复印刷声明。当前复制保持来源当前有效材料，沉默来源的当前复制不会恢复许可。转控后贡献由新控制者取得，双方既有技能的已用次数仍各自保留。

技能主体一旦接受，支付和已用事实冻结；选择等待、来源变化与后续回合不会把这次使用改成未使用。错误动作沿原事务回滚，失败的后续选择保留之前已提交的使用。JSON状态与typed帧均保存新声明，选择恢复、clone和动作回放复用原解释器。

## 玩家信息与版本

安装技能的玩家可见 `use_limit` 显示同一个有效上限；`None` 表示无限。它与合法操作查询一致，技能自身基准仍只在私有引擎状态中维护。来源附件、实例身份及全知证明不提供给玩家。

公开观察值域新增空上限，因此观察版本升为 `player-view-v77`；命令12与replay1保持。结构/语义为 prototype-v275 / core-effects-v269 / schema241，旧1～240必须使用原引擎。一个持久能力字段，没有新全局状态、次数缓存、运行模块或账户。
