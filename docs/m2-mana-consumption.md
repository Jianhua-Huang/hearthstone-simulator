# 效果中的直接法力消耗

禁忌烈焰等真实卡文要求在主体中消耗剩余法力。这与原卡牌费用、水晶移除、过载和恢复分别建模，底层扣款投影继续复用。实际执行、差异与下一项仅在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 公共指令与账户

```python
SpendMana(player_id=1, amount=5, source_id=source)
SpendMana(player_id=1, amount=None, source_id=source)  # 耗尽当时可用量
SpendMana(player_id=1, source_id=source, on_result='consumer')
```

数量只接受非负整数，排除布尔值；`None` 显式表示当前全部可用量。固定数量实际消耗 `min(请求量, 当前可用法力)`。它不检查或伪造一份卡牌费用报价，不消耗费用修正用途；零价打出后可用法力仍可由主体消耗。

原 `project_mana_spend` 和 `spend_mana` 处理唯一账户写入：先消耗临时法力，再增加永久已用量，重新得到有效可用量。原永久水晶数量、增长上限、待过载与已锁定量保持。临时量超过水晶上限或永久余额为负时也使用原方程，不通过删水晶或负数恢复冒充消费。后续恢复、回合重置与新消费继续使用原账户。

来源可空；回调必须有已知物理来源，未知来源或行为在扣款前拒绝。来源实体的当前控制者提供普通原始归属；存在对应已接受、未完成的物理施法时，取该次施法的原来源卡面和行动玩家，保留 `cast_id`。没有施法的来源不会伪造 CAST 或付费手牌根。

## 原始事实、结果与顺序

`GameState.mana_consumption_history` 保存有序不可变 `ManaConsumptionRecord`，包括零量消费。连续 ID 由原完整长度分配，无额外全局计数缓存。记录保存请求与实际量、回合/动作、永久/临时/锁定账户两端、原来源类型/卡面/行动玩家及可空的物理施法身份。

结果满足原法力方程、临时优先消耗和实际量关系；不根据后来的余额倒推。每次发布内部 `mana_consumption_resolved`，正量紧接发布 `mana_consumed`，随后发布原 `mana_changed` 账户变更。普通已捕获反应先执行，回调通过 `RuleContext.mana_result` 读取扣除时的不可变事实及原上下文；反应后来补充法力不会改写本次实际量。零量仍可回调，不产生正量消费事件。

上述事件顺序、原类型归属和间接消费计入政策是明确的本地契约，尚未做精确国服校准。一般卡牌代码只返回指令，不直接修改余额或维护闭包中的消耗计数。

## 既有法术法力查询的一致性

原[实际法术法力费用输入](m3-player-spell-mana-costs.md)继续读取原付费手牌 `PlayRecord`，并读取独立消费的完整前缀。仅实际消耗玩家与原来源行动玩家相同、来源类型为 SPELL 的直接单位计入该玩家的法术投入量；普通随从、地标、技能、无来源或另一玩家消耗不误算为本人的法术投入。

手牌付款金额与主体消费量分别登记，各只贡献一次。例如零基础费禁忌烈焰消耗8点，原卡牌费用仍0、主体事实为8；2费诊断法术打出后消费剩余6点，则原付款2与消费6相加为8。无需提高印刷费用，也不把自动施法冒充手牌付款。这里补齐已有数量读取的资源事实，不新增费用公式或卡牌组合机制。

`PlayerSpellManaCostFact` 追加 `consumption_rows` 和 `consumption_history_length` 两个冻结操作数，保留付款与消费的全部行，包含未计入行。报价纯查询，不从事件日志取数；原窗口验证完整前缀和账户/来源身份，后续新增行或恢复法力不改写旧报价。紧凑前缀不认证未签名外部存档的来源。

## 恢复与玩家信息

State、原费用事实和必要行为帧通过共同类型化解码恢复；事件与持久记录绑定，正量配对及账户变更须完整，未知/缺失字段、变化的数值投影、未来施法和不一致来源拒绝。动作异常回滚整个未提交动作；后续选择异常保留原等待边界及已提交消费。克隆和回放共用原规则解释器。

玩家观察仍读取原当前法力；新增公开 `mana_consumed` 只提供普通数量和既有观察引用，不包含原始消费行、付款前缀或全知来源证明。内部结果不公开。观察版本为 `player-view-v79`，命令12/replay1保持；语义为 `prototype-v277 / core-effects-v271 / schema243`，旧1～242须用原引擎。

只新增一个持久历史字段和两个冻结费用字段，没有新运行模块或法力账户，默认生产注册表指纹保持。

## 来源与限度

[十二完整来源与 pin](../data/support/mana-consumption-basics.json)保留11条耗尽法力主体及既有 TSC_829 数量需求；仅 OG_086 禁忌烈焰是必要完整隔离适配，其他主体按接卡后置。[官方2016介绍](https://hearthstone.blizzard.com/en-us/news/20056288)支持使用当时全部可用法力及烈焰0基础费，不证明当前国服临时顺序、事件时点、间接归属或正式卡池。原本地 cost 为 null 的记录完整保留，实验定义的0基础费单独说明依据，不改写原数据。
