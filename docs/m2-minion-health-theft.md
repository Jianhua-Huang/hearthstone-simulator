# 原随从之间的生命偷取与逐次选取

CATA_699恐怖海兽的固定原行和双语官方卡面是9费8/8野兽、嘲讽，战吼选择敌方随从偷取3点生命，触发三次。36.4.2的[国服补丁](https://hs.blizzard.cn/news/24296231/index.html)确认身材改为8/8。[35.0.2官方修正](https://us.forums.blizzard.com/en/hearthstone/t/3502-hotfix-patch/158856)及[35.4国服修正](https://hs.blizzard.cn/news/24266874/index.html)确认曾修复它处理受伤随从生命量/生命上限的问题；这些公告没有完整定义正确数值公式或每次选择的精确窗口。

`StealHealthToMinion(beneficiary, donor, amount, source_id)`只接受两个不同阵营的原`MinionReference`。本地实现取请求量与提供者当前剩余生命的较小值，双方保留已受伤害；减少量和增加量是同一次原子修改。公共Buff附件安装器分别安装两端普通属性附件，首个属性事件发布前两方已提交并刷新光环。仍由原死亡检查处理生命归零，不制造伤害、治疗、吸血或生命支付包，不消耗圣盾，也不调用原英雄上限转移入口。每次请求重新检查区域、卡面、控制者、驻留、存活及来源；原对象失效时整次转移跳过，不绑到后来同名随从或同ID的新驻留。

`ChooseHealthForMinion(beneficiary, amount, count, source_id)`保留原受益者引用，每次实际选取前重查当前敌方随从，选中后交上述转移。前次完整转移、死亡和反应结束后才开始下一次选择，因此新生成的敌方随从可以进入后次候选。无合格目标、没有原存活受益者或零量时不造选择、附件或额外随机；工程次数预算仍明确报错。卡牌只声明原受益者、3点和3次，公共模块不依赖卡名。

玩家选取使用普通随从能力的目标规则：敌方潜行/免疫不能手选，扰魔不禁止随从能力；直接属性转移本身不被伤害保护拦截。间接战吼沿已有`choices=random`选择政策，自动目标资格和原随机/回放管线共享。重复战吼各自执行三次选择，不重复支付；原受益者回手重入、死亡或易主不把剩余效果转给新驻留。旧`StealHealthToHero`和`RandomStealHealthToHero`继续原有最大生命预算/英雄受益者契约，未据新卡推改旧来源。

等待分支保存原引用、选中对象与剩余次数，复用已有Choice、Battlecry、事务、恢复和玩家信息边界；没有新增GameState、Entity或能力字段。新增两个Effect类型，原MinionReference载荷复用，内核及保存身份的具体版本、实际验证与剩余事项仅在原两份台账登记。

当前公式、三个在战吼主体内逐次选取的窗口、无目标终止、双方事件先后、普通可沉默附件和自动目标细节均为明确内部政策。官方修正和旧玩家多次点击报告支持排查方向，但不足以认证这些细节；仍须M6国服对局校准。非随从作为间接受益者的来源明确未支持，不能以本卡内部通过认证全部历史/跨载体来源、完整正式池或标准可达内容。
