# 按场上其他同种族随从数量持续增加自身攻击力

B227 的独立基础规则扩展原连续属性关系，复用当前种族查询、物理场上区域、数值缓存、生命周期与解释器。实际进度、验收和下一项仅维护在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md)。

## 有限声明与计算

```python
StatRelationSpec(
    operand=StatRelationOperand.OTHER_BATTLEFIELD_TRIBE_COUNT,
    layer=StatRelationLayer.CONDITIONAL_ATTACK,
    amount=1,
    count_tribe='murloc',
)
```

唯一新字段 `count_tribe` 是非空种族字符串。该操作数要求 Attack 目标、条件攻击层、严格正整数系数和无牌库阈值。旧操作数必须保持该字段 None；原默认自身生命关系不变。声明只允许原可沉默、普通非融合随从，原生印刷附件与原声明完整匹配，不允许动态授予、期限、消费或额外重复附件。武器护甲关系保持自己的唯一武器资格。

纯查询遍历双方物理 BOARD，按实体本身 ID 排除载体。只计其他随从，排除位置和惰性交互物；每个物理随从至多贡献一次，重复卡面是不同实体。查询使用当前种族，包含已有动态种族修改及全集标记的排除项，不读原始职业或卡名。所有物理卡面仍由注册表验证；待匹配随从的种族未知时明确报错，不能当作无种族或删掉它。

贡献为匹配数量乘以系数，存入原 `conditional_attack`，在普通有序数值附魔及外部光环后加入攻击并执行零下限。基础攻击、附魔和伤害均保持原值；反复刷新不累加永久 Buff。没有新的计数状态、表达式语言、资源账户或攻击执行器。

本地 presence 政策计入仍在物理 BOARD 的休眠及将死其他随从，直到原区域移除；载体自身只有原活跃能力才生效。区域显示、死亡窗口和休眠计数的精确国服规则仍待校准。本实现不声明所有阵营、子集合或卡名分类的连续计数都已完成。

## 刷新、支付及恢复

原完整属性刷新和事件前规范化重新计算当前贡献。召唤、移除、变形、转控及种族变化沿原事件和检查点处理；监听上下文保存当时自己的完整场上与当前种族。双方范围不随载体转控改变，复制的载体按新物理 ID 排除自己，不读取旧来源实体的当前状态。

沉默撤销关系；沉默后的当前复制保持移除，基础复制、回手重装和变形沿用既有声明安装。攻击机会、冲锋、伤害准备与死亡磨损继续由原内核处理。攻击声明待选之后、伤害准备之前读当前值；已经准备的伤害和冻结死亡记录不随之后的场上变化重新计算。

当前种族需要固定注册表，因此 `conditional_attack`、缓存刷新及事件规范化接受该注册表。原真实结算、支付投影与付款提交证明、回溯恢复均传入同一注册表；既有不依赖种族的直接查询仍可省略。遇到新关系而缺少注册表时明确报错，不能沿用陈旧缓存。没有第二套支付或重试路径。

`count_tribe` 进入原 typed 声明、附件、工作帧及死亡记录的严格保存格式。schema260 拒绝旧1～259，规则/核心分别为 prototype-v296/core-effects-v296；观察84、命令12及replay1保持。JSON、模型和 FrameCodec 在各自状态域检查完整原声明与派生缓存。缺字段、篡改种族、非法来源、重复附件及陈旧值均拒绝；这些一致性检查不认证未签名存档的来源。

玩家只看到公开攻击和合法操作，不获得种族计数字段、附件、派生缓存或全知工作帧。等待恢复、clone、独立注册表回放及异常回滚复用公共管线。
