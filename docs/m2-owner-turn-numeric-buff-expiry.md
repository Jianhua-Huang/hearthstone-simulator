# 数值附魔在指定玩家下次真实回合开始时到期

B229 扩展原 Buff 与数值附件的期限，复用实际自身回合时钟和原子附件清理。执行结果和下一项仅维护在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md)。

## 声明和保存

```python
Buff(target_id, attack=1, source_id=source_id,
     until_owner_turn_start=player_id)
```

新增字段是严格的玩家1或2，表示该指定玩家下一次真正开始的回合。它不能与旧 `expires_turn` 同用；旧全局回合结束规则保持。执行时依据实际 `owner_turn_history` 计算期限，跳过的机会不增加自身序号，额外回合则增加。

原 Enchantment 增加可空 `owner_turn_expiry`，包含绑定玩家、创建全局回合、目标自身开始序号和创建区间ID。`OwnerTurnExpiry` 是原 `KeywordExpiry` 的中性公开别名，保留已有私有类型身份和字段。没有第二个时钟、Player/GameState计数或单独的数值结算器。字段只适用于普通可沉默、加法攻击/生命 Buff，不能给费用、种族、控制归还、仪式或其他附件偷偷添加新期限。

指定玩家在施加时绑定，转控不改期限。当前复制沿原附件复制保留期限，基础复制、沉默、回手和换形依原重置处理。休眠不暂停数值期限；非场上实体也清理到期附件。冻结死亡记录和过去上下文保留原时钟及原数值，不用今天的局面重建。

## 原子到期与恢复

原下一回合入口先记录真正的新自身区间，再一次清理该玩家到期的关键词和数值附件。所有实体先移除，刷新原属性/光环后才捕获 `attachments_expired` 监听。不会让第一个监听看到另一实体仍保留到期加成。攻击/生命移除沿用既有有序数值层与剩余生命钳制规则。

到期反应可以暂停选择；普通回合开始事件和自然抽牌继续由原 BeginTurnEvents 延续点处理。到期反应重新给予同类期限时，当前真实开始已经发生，新期限指向再下一次开始。异常、clone、JSON恢复、独立注册表回放及玩家接口均复用原管线。

模型和 FrameCodec 在各自状态域验证创建区间与期限计算，Game稳定边界拒绝当前实体仍持有已到期的数值附件。历史死亡字段只检验原创建及死亡窗口，不要求其期限晚于今天。缺字段、错误类型、未来创建、改变序号、混用期限及非法数值附件形状明确拒绝。这不提供未签名存档来源认证。

Buff和Enchantment的新字段改变保存结构，当前采用 prototype-v297/core-effects-v297/schema261，旧1～260需原引擎。观察84、命令12及replay1保持；玩家不获得创建区间、附件时钟或全知工作帧。
