# 每回合每第 N 张随从的费用光环

本文保留B130随从契约及当时拒绝周期法术的历史边界；法术独立计数与费用规则另见[周期法术契约](m2-periodic-spell-cost-auras.md)。实际执行与下一项仅在两台账。

真实来源 REV_021 / CORE_REV_021 要求每回合每第三张随从为零费。现有首张费用历史能够提供原前缀，但原光环只能判断首张；现在扩展同一费用声明的序号条件。实际执行、验收和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。

## 声明

```python
CostAuraSpec(
    CostSpec(set_to=0, card_types=(CardType.MINION,)),
    every_nth_per_turn=3,
)
```

`every_nth_per_turn` 默认 `None`，启用值必须为整数且至少为 2；排除布尔值。当前支持友方普通随从来源、单一随从受益类型的减费或设置费用。它与 `first_per_turn`、种族、卡牌 ID、能力筛选和特殊支付账户不组合，任意授予及融合载体明确拒绝。已有首张、普通和种族光环保持各自行为。

法术周期条件目前明确拒绝。BT_255 的“施放”计数涉及付费手牌、自动来源和反制政策；现有施法账本与手牌出牌账本不同，不能把付费手牌数量静默当作全部施法数量。该真实公共需求继续开放，没有注册法术周期适配。

## 序号与共同报价

复用 [首张费用契约](m2-first-play-turn-cost-auras.md) 的 `FirstPlayCostFact` 和原冻结卡面行，不新增账本、次数缓存或模块。`ordinal` 为原报价窗口中本方当前实际回合已有同类付费手牌根数加 1；`is_first` 仍等价于序号 1。当前候选尚未成为历史根，第三张和第六张分别以原前缀 2 和 5 计算。

序号能被 N 整除时，该来源进入原外部费用层。多个同类物理来源各贡献一次，不能把相邻随从变成下一份免费用途。付款、最低零、本地与外部费用顺序、合法操作、生成报价继续共用原管线。普通召唤和无关类型不增加随从出牌数量；来源何时进入不重置玩家序号。直接使用来源本身沿原付费手牌历史计数。新实际回合重新读取其历史；双方玩家各自判断。

本契约的计数对象为已提交付费手牌根，保留反制根，不依赖主体完成。其他间接“使用随从”起源和精确国服窗口仍需实际证据，不宣称全部起源完成。

## 来源、付款与恢复

来源活跃、控制者、存活、沉默、死亡、回手、变形、休眠、唤醒、复制和转控继续由原生命周期决定，序号没有依附来源的独立用途预算。实际支付冻结完整原报价；之后来源变化和新出牌不改写旧价格。

每个有效周期贡献必须保存原完整历史前缀；序号从前缀重算，不接受外部填写的数量。前缀、原付款者、类型、实际回合、动作及原报价边界必须一致；恢复时与实际保留历史前缀绑定，并校验原生声明与周期值。保存、独立注册表恢复、clone、选择中断、回放和异常回滚沿原解释器。玩家仅取得有权限的最终费用，不获得完整贡献或历史证明。

结构为 prototype-v269 / core-effects-v263 / schema236，旧 schema1～235 必须使用原引擎。默认 `None` 从注册表指纹的静态声明中省略，旧默认生产身份保持；启用周期的值参与身份。没有新运行时模块、全局状态字段、玩家账户、动作或事件；观察/命令/replay 版本保持 76/12/1。

仅隔离适配 REV_021 逐罪者凯尔萨斯；本地完整原行为 8 费 4/7 和每第三张随从零费。CORE_REV_021 同效果身份及 BT_255 原行保留于[完整来源与 pin](../data/support/periodic-play-turn-cost-basics.json)，不自动批量适配。[官方24.2.2公告](https://hearthstone.blizzard.com/en-us/news/23852686)证明历史费用从 6 调至 8，未证明当前国服精确序号窗口；本次官方卡牌库页面提取未返回渲染效果正文，不把它作为计数时序证据。
