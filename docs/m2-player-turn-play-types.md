# 玩家本回合的手动出牌类型权限

BE_EVENT_100 古神降临与 BE_EVENT_101 泰坦降临分别要求“在本回合的剩余时间内，你只能使用随从牌/法术牌”。这是当前玩家的出牌资格，不能用高费用、目标限制、静态禁止出牌或付款后取消代替。执行结果与下一项仅维护在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。

```python
PlayerEffectSpec(
    'turn.only.minions', 'BE_EVENT_100',
    kind='turn_rule', allowed_card_types=(CardType.MINION,),
)
```

复用原玩家效果实例、AddPlayerEffect、来源记录、created_turn 及统一结束清理，没有新增玩家账户、时钟、运行时模块或状态账本。声明必须是不可变、去重的可手动使用牌型元组：MINION、SPELL、WEAPON、HERO、LOCATION。空元组仅是旧定义的默认值，不能单独充当策略；未知类型、重复类型和 HERO_POWER 明确报错。

同一个 turn_rule 定义只声明手动出牌类型或原法术目标策略中的一项，不混入触发、光环、倒计时等其他文本。不同实际类型限制共同取交集；同类实例移除一个不会移除剩余限制。来源死亡、沉默、移区或转控不撤销已建立的玩家规则。

## 接受与到期

原 player_effects.manual_play_allowed 是纯查询。Game.validate 在报价和付款前检查它；合法动作枚举先排除被禁止的 PlayCard；解释器 PlayFromHand 的真实入口再次检查，不能从内部效果绕过。资格读取当前实体牌面类型，存储升级后的类型按新牌面判断。静态 manual_playable 仍独立生效。

完整付款证明校验原 payment_state 中的类型资格。以后安装的规则不取消已经接受的出牌，也不在历史恢复时重判当前局面。原付款、选择、反制与执行完成流程继续拥有其已有收据和窗口。

限制只约束新的手动 PlayCard。自动施法、英雄技能、攻击和替代手牌操作仍走各自原入口。纯费用查询可以返回一张被禁止出牌的牌的价格，它不承诺该牌可使用；目标查询也不代替整体合法动作检查。不同来源若有更广限制，需真实卡文和政策依据，不由本机制推断。

原 expire_turn_rules 在真实回合结束清理双方当回合规则，包括结束反应中建立的实例。额外实际回合不会延长上一回合限制，活跃旧回合实例在状态恢复时拒绝。显式移除、等待恢复、异常回滚、clone 与动作回放沿已有解释器。
