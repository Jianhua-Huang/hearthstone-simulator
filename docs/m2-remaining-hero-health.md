# 英雄当前生命值直接赋值

阿莱克丝塔萨的卡文设置的是英雄剩余生命，而非生命上限。[前审来源](../data/support/remaining-hero-health-audit.json)和既有处理器的实际反证支持单独的公共操作。执行位置、验证及下一项仅在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 指令与物理目标

```python
SetHeroHealth(target_id=hero_id, health=15, source_id=source)
```

目标是原物理英雄实体，不是玩家账户别名。数量为非负整数，排除布尔值；来源可空，非空来源必须已知。目标必须是当前安装、存活、未待销毁的 HERO；已被替换或离场、死亡及待销毁目标按原失效效果路径跳过。它不能替代 `RecoverHero` 在英雄致死窗口中的恢复。

执行时保留最大生命、护甲、关键词和既有附魔，只调整原累计伤害表示，使剩余生命达到指定值。新数值不借用 `Heal`、`Damage` 或 `LoseHealth`，不受这些流程的倍率、伤害防护或生命损失替换影响，不制造治疗、伤害、支付或普通生命损失事实。卡牌出牌的目标资格仍沿既有规则，操作没有放宽真实卡牌的选目标限制。

当前本地政策将请求钳制到目标的当前最大生命。最大生命低于15时的官方行为尚无本批证据，明确保留到M6；不能将这个政策宣称国服已认证。未修改原 `SetStats` 设置局部最大生命并清伤害的契约。

## 实际变化与死亡

每次成功赋值发布 `hero_health_set`，保存请求量、当前量前后和原最大生命，公开数量为实际有符号变化。原 `HeroHealthChangeRecord` 与九字段过渡封套复用：只有当前生命确实变化才追加事实，不变仍有赋值事件而没有新的变化次数。原本人回合数量、费用读取及回合区间继续消费同一原始历史。

剩余生命设为0沿原死亡检查、英雄致死协调和终局处理；致死原因是 `health_state / remaining_health_assignment`，保存物理来源，不冒充伤害或荣誉消灭。后续等待、反应和终局依已有解释器顺序，不新建检查点或另一套死亡流程。精确国服赋值通知与反应窗口仍待校准。

## 验证、恢复和信息

事件读取检查完整原始字段、请求与实际数值、最大生命不变、原物理身份、来源和有符号变化。变化事实绑定原事件类型；独立赋值不能改写上限或借用别的原始事件。保留的完整过渡与历史共用原边界校验。未签名外部快照不提供来源认证。

待选前后的赋值指令及尚未执行的捕获事件通过原 FrameCodec 恢复；捕获状态中的原英雄事实与事件必须一致。动作失败回滚整个未提交动作，后续选择失败保留已提交的等待边界。克隆、JSON恢复、回放与普通解释器共享，不以闭包保存状态。

玩家看到原当前/最大生命和普通赋值数量，原九字段过渡、历史、请求及内部实体编号不输出。新增公开事件域使观察版本为 `player-view-v80`，命令12/replay1保持。语义版本 `prototype-v278 / core-effects-v272 / schema244`，旧1～243须用原引擎。

没有新持久字段、生命账户或运行模块；仅新增效果和原实际变化的事件种类。默认生产注册表不新增卡牌，指纹保持。

## 来源与限度

[七条完整 raw 与 pin](../data/support/remaining-hero-health-basics.json)保持原始记录。仅 EX1_561 是必要完整隔离适配；VAN/CORE、MIS/CATA主体未新增接入，CATA后续满血伤害和两条剩余生命复制的入场材料/时序按接卡后置，不建立组合任务。[官方卡牌索引](https://hearthstone.blizzard.com/en-us/cards/581-alexstrasza?textFilter=alexstrasza)支持剩余生命到15，不证明当前国服全部窗口或低上限例外。
