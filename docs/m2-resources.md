# M2：费用、法力与玩家资源

效果中的直接法力消耗用SpendMana，复用原扣款投影并保存独立实际单位和来源；与普通卡牌费用、法力恢复、水晶和过载分开。见[直接消耗契约](m2-mana-consumption.md)，不将主体消耗伪装成卡牌费用。

印刷支付账户由原CardDefinition.cost_payment不可变声明，物理、生成和冻结费用校验共用；默认法力、局部/外部覆盖及原Health/Corpses/Armor账户执行保持。创建、抽取、复制与重置依据固定卡面，不靠可移除费用附魔冒充固有币种。见[印刷账户契约](m2-native-cost-payment.md)；正式来源、优先级与精确CN仍待校准，实际执行与下一项只在两台账。

本局尸体消耗费用直接消费[原成功实际单位事实](m3-corpse-spend-history.md)与spent_corpses纯查询，资源/上限/付款执行保持；完整原前缀和金额由[费用消费者契约](m3-player-corpse-spend-costs.md)定义。不能按当前余额、请求上限或次数推导已消耗单位；新消费者没有增加资源状态或执行器。


对应 M2-05。当前版本以[项目状态](project-status.md)为准；v78扩展见[身份条件与双方费用光环](m5-battlecry-costs.md)。本页描述已实现、通过内部测试的契约，复杂边界尚未完成国服官方校准。总体进度见 [项目状态](project-status.md)，后续开发遵循 [长期计划](roadmap.md)。

## 模块与真值

[costs.py](../hs_sim/engine/costs.py) 负责无副作用报价、支付资格、支付及费用附件；[resources.py](../hs_sim/engine/resources.py) 负责玩家账目与资源效果。卡牌行为组合公共指令，不能直接改 `player.mana` 或在回调闭包保存折扣次数。

`Game.quote_cost(entity_id)` 返回不可变的 `CostQuote`：实体、付款玩家、金额、支付账户、已匹配修正和待消耗修正 ID。出牌、技能合法性检查、合法操作枚举和实际支付共用报价。报价本身不保证目标、位置和使用次数合法。

`Entity.cost` 只表示本实体基础费用与本地附魔的结果。场上费用光环和玩家下一张牌效果属于报价层；界面和策略不能用 `Entity.cost <= player.mana` 代替合法性查询。

## 费用层与支付

| 类型 | 当前契约 |
| --- | --- |
| `CostSpec` | 有符号 `delta` 或 `set_to` 二选一、`minimum`、适用 `card_types`、`card_ids`、可选结构性 `ability` 条件，以及可选 `payment` |
| `ModifyCost(target_id, spec)` | 在指定实体上添加有 ID 的费用附魔；支持来源、到期；回手重置、复制保留按生命周期契约执行 |
| `CardDefinition.cost_auras` / `GrantCostAura` | 使用 `CostAuraSpec(CostSpec(...), relation)`；随从、地标或武器有效时依友方/敌方/双方关系修改报价；生命周期共用实体能力机制 |
| `AddCostModifier(player_id, spec, uses_remaining=...)` | 玩家持有的持续或下 N 次匹配出牌/技能修正；来源离场后仍有效，可指定本回合到期 |
| 消耗 | 所有匹配的有限次修正各消耗一次，包含最终零费的匹配牌；不匹配类型不消耗；非法操作和结算失败整体回滚 |

原型顺序为：基础费用 → 按附件顺序应用实体附魔 → 按附件 ID 混合应用当前光环和玩家修正。每个操作应用自己的下限；减费下限不会抬高已经低于下限的费用。例如巫师学徒的“不能少于 1”不会把零费幸运币变成一费。复制产生新附件 ID，因此可能改变混合修正的先后。这些排序是明确的待校准契约，不代表已覆盖所有设费、光环、巨人式动态费用和特殊卡例外。

支付账户目前有 `MANA / HEALTH / ARMOR / CORPSES`。法力支付优先消耗临时法力。生命支付在本原型中先扣护甲，再结算生命损失；没有合格替换效果时，不允许付掉最后一点有效生命。奥妮克希亚等 [生命损失替换](m5-health-loss.md) 生效时，共享资格查询允许超过剩余生命的费用，并将最终扣血替换为上限增长。护甲支付只扣护甲，尸体支付只扣对应资源。支付不产生 `Damage`，不触发吸血、不消耗圣盾，也不因免疫而免单。[官方 26.0 更新](https://hearthstone.blizzard.com/en-us/news/23934449/26-0-patch-notes) 支持“生命/护甲费用不算伤害且免疫/圣盾不免除支付”，不据此宣称护甲顺序、濒死资格或特殊卡例外已校准。

每次费用只发出一个对应的 `mana_spent / health_spent / armor_spent / corpses_spent` 事件，记录报价及消耗的修正 ID。生命支付造成的生命变化不产生普通伤害事件。

M4 已追加 `CostScope.CARD / STARSHIP_LAUNCH`，费用附件、快照和公共消费逻辑共用，报价按作用域隔离。星舰基础五费经专属修正后支付，普通牌/技能修正不会改变它。具体边界见 [星舰费用契约](m4-starships.md)。

## 法力账目

| 玩家字段 | 含义 |
| --- | --- |
| `max_mana` / `mana_cap` | 拥有的永久水晶数 / 当前增长上限，二者不同 |
| `mana_spent` | 永久水晶已使用量 |
| `temporary_mana` | 尚未消耗或到期的临时法力量 |
| `overload_owed` | 下个自己回合需要锁定的量 |
| `overload_locked` | 当前回合已经锁定的量，允许超过已有水晶数 |
| `mana` | 派生缓存：`max(0, max_mana - mana_spent - overload_locked + temporary_mana)` |

稳定边界严格核对缓存、非负整数及永久水晶上限；可用法力可以超过水晶成长上限，不接受自行改 `mana` 的快照。`PlayerSetup` 可设置上限、临时法力、待锁/已锁过载和起始尸体；原有只指定法力的场景仍可运行。

- `GainTemporaryMana` 不增加永久水晶，临时账户与可用法力可超过基本或修改后的水晶成长上限；未消耗部分在回合交接时清除。结束事件及其反应仍能看到结束前资源。
- `RefreshMana` 只恢复已使用的永久法力，不重建已经花掉的临时法力，不解除过载。
- `ChangeManaCrystals(amount, filled=False)` 区分空水晶与已充能水晶；减少时先移除空水晶，再调整永久已用量。`SetManaCap` 支持扩容及缩容，只约束永久水晶；改变水晶、上限、恢复或解锁保留未消费临时法力。
- 自己回合开始时增长一个永久水晶，已使用量及临时量清零，把待锁量移入当前锁定量，最后重算法力。旧锁定不会自动再次顺延。
- `Overload` 累加待锁量；`UnlockOverload` 解除已锁量，默认也清除待锁量，可显式保留待锁。

**待校准边界：**超量过载不丢失，在报价中形成负余额。例如 10 水晶锁 11 时，第一个临时法力仍使可用量为 0，第二个才得到 1。该场景、减水晶选择及恢复/解锁的精确交互仍是原型约定；旧临时法力裁剪已依公开29.0规则修正，见[临时法力与水晶上限](m2-temporary-mana-over-cap.md)。默认上限 10 是可配置起点，不能直接当作国服当前版本的完整法力规则常量。

## 尸体与其他资源

`PlayerState.resources` 使用严格的 `Resource` 枚举，目前只有 `CORPSES`。未知账户明确报错。`GainResource` 增加资源；`SpendResource` 在实际执行时检查余额，成功后扣除并执行 `on_success`，不足则执行 `on_failure`，不会部分扣款。`required=True` 的不足会抛错并回滚整个动作。

可选增效必须用执行时分支，不能在生成指令的早期快照中先判断资源。例如吸血鬼之血先加 5 生命，再尝试支付 3 份尸体，成功才额外加 5 并抽一张；资源不足不妨碍基础施放。分支继续使用原来的受限队列与死亡检查，没有绕开公共结算。

每个死亡随从按死亡时控制者入账，整批移出战场后先累计整批尸体，再发资源/死亡事件和捕获亡语。所有玩家均有账户，不依赖英雄职业。[官方 25.4 更新](https://hearthstone.blizzard.com/en-us/news/23913671) 确认所有职业整局记录尸体；[死亡骑士介绍](https://hearthstone.blizzard.com/en-us/news/23852696) 说明友方随从死亡提供资源、召唤物及复生也可贡献。上述公告不证明本引擎的批内触发顺序。

普通随从默认 `corpse_value=1`，明示不留尸体的定义可以为 0；实体和不可变 `DeathRecord` 保存这一值。该固有特性不被沉默移除；当前复制保留、变形及重置读取新定义。复生后的新随从再次死亡会再次按其定义入账。武器毁坏、回手、变形及英雄替换不产生尸体。玩家账户跨英雄替换保留。

符文属于构筑限制，留在 M3 构筑校验；没有把 `COST_BLOOD` 等数据误当作战斗中可消耗的资源。更多资源类型、条件支付与特殊覆盖按 M5 的目标机制清单扩展。

## 成功残骸消耗共同事实

原固定SpendResource、上限SpendUpToResource和CORPSES付款共用完整私有corpse_spend_history；实际扣款单位及原身份一次登记，原资源执行、反应和付款证明共享。corpse_spends/spent_corpses只读原状态；零成功保留零行，增益/略过/失败不计量，退款不抹原成功单位。上限typed结果及operation_id沿用，完成pending移除不清历史；原待选、事务回滚、回溯和终局保持。完整事件包与有效原前缀匹配，玩家不接收私有记录，见[公共契约](m3-corpse-spend-history.md)。该层提供事实，不自动安装残骸费用消费者或真实卡适配。
