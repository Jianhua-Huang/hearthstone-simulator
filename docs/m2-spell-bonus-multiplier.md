# 法术伤害加成系数

`Damage` 在既有字段末尾增加 `spell_bonus_multiplier: int = 1`。只在原健康结算的法强报价步骤使用，表示本包取得的**法术伤害加成**的系数；不改变声明伤害，也不乘整个结果。没有新增伤害执行器、法强账户、事件或卡牌定义字段。实际验证与下一项只在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md) 维护。

## 真实需求与表达缺口

[官方奥术冲击页面](https://hearthstone.blizzard.com/en-us/cards/2572)及本地完整 `AT_004` 原始记录说明：基础伤害为 2，获得双倍法术伤害加成。若当前适用法强之和为 S，算式是 `2 + 2*S`。S 为 0、1、3 时分别是 2、4、8；原有针对总数值的 SCALE 会把 S=1 算成 `(2+1)*2=6`，不能替代这个规则。

在卡牌行为规划时提前查询 S，再把差值写进普通 `Damage.amount`，也不等价：规划之后、伤害包之前的合法效果可能增加、沉默或移除法强来源；同时伤害需要冻结同一个批次开始局面。系数必须随未执行的普通伤害包保存，在原实际报价窗口应用。

必要隔离代表只有 `AT_004`：法师、史诗、1 费、奥术法术，目标为任意一侧的场上随从。其普通主体声明：

```python
Damage(ctx.target_id, 2, ctx.source_id, DamageKind.SPELL,
       spell_bonus_multiplier=2)
```

[完整原始证据包](../data/support/spell-bonus-multiplier-basics.json)保留本地同标签全部四行：`AT_004`、`AT_004_Puzzle`、`LETL_1073_01`、`LT24_822P2`；后三行只作证据，不注册构筑执行适配。完整包 canonical PIN 为 `f2d6a4b45d443a5b4cfcd1539527218c20cc37668d761a423259921de717aa82`，原始 36022 行卡库 SHA256 为 `fd0a3412afa031504f0553210670d6c14ce02ca952819f7524514a8003b86c08`。本地来源仍是 36.6.0.251952/zhCN，不证明当前国服正式池已经冻结。

## 原伤害管线的边界

- 系数必须是严格正整数，拒绝布尔、0、负数与其他类型；仅 `DamageKind.SPELL` 可以声明非 1 系数。来源、类型、回调和目标继续沿用旧验证。
- 转换与重定向后，只有最终是普通法术伤害的包进入法强步骤。原 `spell_damage_sources` 按实际来源控制者和实际学派取得同一份适用加成之和，然后乘系数。来源类型仍须是法术。
- 报价公式是 `base_amount + spell_bonus_multiplier*S`；随后才进入原 SOURCE/TARGET 的 ADD、SCALE、SET、CAP、PREVENT 和生命下限步骤。默认 1 保留旧行为；治疗转法术伤害仍取得默认 1，不要求 `Heal` 拥有新字段。
- `PreparedHealth.base_amount` 和 `HealthResult.base_amount` 保留原声明值；原 `spell_bonus` 保存本次实际加成。例如奥术冲击加 S=1 保存 base=2、bonus=2。结果续接消费原捕获结果，不重新查询当前法强。
- 独立伤害包按各自实际窗口报价；`DamageBatch` 沿用原同批冻结。吸血包沿用原不重复取得法强的守卫。随机分配预算继续使用原一次报价和单位包，内部单位包必须保持默认系数 1；本项没有扩展随机分配或 `RandomDamage` 的请求形状。

## 存档、事务和玩家边界

新操作数进入原 `FrameCodec` 的完整 typed 字段校验。等待之前未执行的包保存系数，恢复后从原当前位置继续；已经结算的结果与回调等待保存原 base/bonus/实际结果，不重新伤害。未知字段、布尔系数和不合法值在重算外层 hash 后仍须拒绝。有效 unsigned 存档不提供来源真实性认证。

原支付、死亡检查点、选择失败回滚、动作事务、clone 和独立注册表 replay 复用；没有新选择系统或控制时钟。全知帧、内部系数和对手隐藏身份不进入玩家观察 DTO。

运行身份为 `prototype-v252` / `core-effects-v246`，snapshot schema 222 拒绝旧 1～221；观察 76、玩家命令 12、replay 1 保持。历史存档须使用对应旧引擎，旧完整证据保留。生产代表包 64 和合成包 3 保持，本项代表在 [专项测试](../tests/test_spell_bonus_multiplier_basics.py) 的独立注册表中。

## 证据限度

官方卡文支持加成翻倍的定义；应用窗口、护盾、死亡、等待及结果政策仍按既有内部管线验证，未经国服实际对局校准。不展开任意系数来源、授予或关键词组合，也不以四条标签记录宣称完整构筑范围已确定。M0 正式池、M6 国服校准、M7 批量接卡与完整目标继续开放。
