# 本回合临时控制权

真实回手禁止须绑定成功到达的原物理对象；控制归还和“下个本人回合结束”按实际原玩家区间计时，普通/对方/结束反应安装分别接受。有限入口和仍未支持的控制层叠边界见[时间效果契约](m3-temporal-spell-effects.md)。

独立基础机制复用原转控、附件及回合末清理，不设置第二控制者缓存或另一套死亡执行器。实际进度、验证与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 公共入口

`ChangeControl(target_id, player_id)` 保持永久转控的原用法。
`ChangeControl(target_id, player_id, until_end_of_turn=True, source_id=source_id)` 表示直到当前全局回合结束的临时转控。标志必须为严格布尔值，临时来源必须是已知实体；不提供任意回合数、条件或授予矩阵。

实际转控成功后才在同一物理随从追加独立 `Enchantment`，以 `control_return_player_id` 保存实际前一控制者。它不使用原始 owner 代替前一控制者，来源可已在墓地。标记必须有来源和期限、可沉默，且无数值、费用、磁力、种族或仪式载荷。当前位置与实际控制者仍由原实体和战场列表表示。

共享 `transfer_control` 保持原移动政策：追加到目的方战场右端，更新入场顺序与本回合召唤限制，保留实体、owner、驻留身份及已用攻击次数；满场失败不追加标记。回合末归还、沉默及手动移除该标记共用 `restore_removed_control`，并复用原光环刷新和事件发布。

## 生命周期和期限

| 情况 | 当前基础政策 |
| --- | --- |
| 正常结束回合 | 先执行原结束反应，待其选择完成后清理到期附件，再归还；原下一回合开始流程继续执行 |
| 沉默 | 移除可沉默附件并立即归还；永久转控没有归还标记 |
| 手动移除 | 仅移除控制标记触发归还；移除无关附魔不会归还 |
| 变形 | 原重置删除旧标记，保持当前控制者；不归还旧卡面 |
| 回手或洗入牌库 | 原区域重置取消标记，归当前控制者；不取回已离场对象 |
| 死亡 | 由实际控制者的原死亡检查点处理，历史冻结仍保留原标记；不会复活或重新取回 |
| 当前复制 | 不复制原物理随从的归还标记；普通数值和能力仍按原复制政策处理 |
| 基础复制 | 使用原印刷定义，没有临时控制或授予能力 |
| 休眠驻留 | 正常有空位时仍可归还，不通过主动目标选择重新获取 |
| 归还方满场 | 标记原随从为消灭，由原死亡检查点结算；死亡归属仍为归还失败时的当前控制者 |

清理到期附件使用原全局当前回合的 `expires_turn`，不新增时钟。按原实体遍历顺序清理附件并归还，全部清理后发布转控/消灭与附件到期事件；选择和异常回滚仍使用原解释器。休眠且归还方满场的死亡政策明确不支持，报错回滚；重叠临时控制来源也明确拒绝，后续具体真实卡需要时再定义。

仍冻结的随从在实际归还后使用新控制者的本人回合截止，不能保留借用方的结束序号。原 `Resolution.refresh_auras` 接收本次真实控制迁移的实体集合，在所有当前贡献及真正解冻完成后、事件上下文捕获前重新绑定期限；普通刷新不重新计时。手动移除与自然到期共享此路径，同控无操作和归还失败保持原状态。冻结期限和来源材料继续使用原字段，不增加跨选择的临时队列或归还账户；具体能力授予后的冻结窗口仍按原 M6 范围核实。

## 必要代表与证据

仅隔离适配 `EX1_334` 暗影狂乱：3 费牧师稀有暗影法术，选择当前攻击力不超过 3 的敌方场上随从，己方满场时不能施放。目标条件复用原 `TargetSpec` 和 `PlayerTargetRuleSpec` 的公开 DTO；原完整付款接受证明保存该输入。

成功转控后的冲锋使用原 `GrantKeyword`，到本回合末到期；转控失败不会授予。完整[原始证据](../data/support/temporary-control-basics.json)包括 `EX1_334e`，该附魔只作证据，不注册第二可执行卡。原始附魔没有 CHARGE 标签，不能把该标签缺失当作冲锋行为的官方证明。

[官方卡库](https://hearthstone.blizzard.com/en-gb/cards/220-shadow-madness/)索引支持卡面基本要求，直接打开只提供动态外壳。[来源记录](../outputs/temporary-control-basics-20261010/official-evidence.json)将冲锋、沉默/变形差异、结束反应顺序和满场归还列为社区线索及本地暂定政策，等待 M6 国服校准；未证明当前标准/狂野合法身份或所有来源。

## 保存和信息边界

引入时 `prototype-v201` / `core-effects-v195` / schema 189 拒绝旧 1～188。新 `Enchantment.control_return_player_id` 以及 `ChangeControl` 两个默认参数均进入原严格完整字段编码，原 FrameCodec 和完整状态验证共享。控制标记只能在场上或墓地的随从中保留，期限不能指向未来回合。死亡冻结只允许随从载体。

观察 74、命令 11、replay 1 保持。玩家接口展示当前公开控制和战场变化，不提供内部附件、归还字段、全知状态或随机状态。没有新增行动、事件种类、实体/玩家状态字段、机制模块或生产卡包适配。


## 2026-10-25：已观察的两次原控制者结束期限

原“重叠临时来源全部拒绝”的历史范围由本节作有限更新。[实测资料](../data/support/overlapping-control-observation-v1.json)保存好友标准对局的749个有序窗口事件及完整原卡材料；用户原目标为栉龙而非操作单中的森金。A原有随从，B先夺取，A再夺回；A结束时第一份退役且实体仍在A侧，B结束时第二份退役并转至B侧。附件85/87及创建者10/35独立保留，没有第二次使用时覆盖第一份。原构建254477、模式GT_VS_FRIEND/FT_STANDARD；不是冻结255026或完整国服校准，不把另一个栉龙16的攻击归给目标39，也没有A再次结束或整局完成证据。

ChangeControl现有限允许两个不同物理来源的until_previous_controller_turn_end标记：已有且仅有一份owner-end期限，其返回玩家必须等于本次转入玩家，来源身份必须不同。新标记仍保存这次实际前控制者和独立原玩家结束期限，不改旧标记；全局回合结束期限的重叠、两份尚存时再加第三份，以及复用同一来源的重叠仍明确拒绝。入口按已有期限材料表达，不在内核按卡牌ID特判，不据一次观察认证任意控制历史或所有来源。

原到期移除器只清本次到期附件。已处于该标记的返回玩家一侧时，退役而不重新转移、排位或发布虚假的control_changed；另一份保持到自己的原边界。实际归还继续使用原物理转移、光环/冻结刷新、容量/死亡路径及事件。复制、回手/变形/沉默、死亡、满血保留附魔复生仍沿原公共生命周期；相应检查是内部兼容验证，不新增这些特殊组合的实服观察。原永久插入、同时批量移除、休眠满场等未观测服务器语义继续单独标注，不能借本节宣称全部控制交互完成。

没有新Effect、模型字段或schema；core-effects-v732拒绝旧core731机制签名，结构587保持。原攻击及主动技能禁令仍按既有本回合政策，本次连续CANT_ATTACK聚合标签不足以修改跨回合攻击规则。实际验证、差异与下一项仅在两份原台账维护。
