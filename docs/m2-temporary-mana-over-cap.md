# M2：临时法力与永久水晶上限

本契约修正原[法力账户](m2-resources.md)，执行进度与实际验证只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。正式卡池与国服校准仍按[长期计划](roadmap.md)处理。

## 规则依据与范围

[官方 29.0 更新说明（2024-03-11）](https://hearthstone.blizzard.com/en-us/news/24064735/29-0-patch-notes)明确临时法力可以超过基本或修改后的最大法力，例如硬币与激活。旧实现将获取、恢复和解锁后的可用法力裁到水晶成长上限，因而在 10/20 水晶处使用硬币没有获得法力；这是已有基础资源规则的差异。

本项修改既有账户，不新增组合机制、付款器、状态字段或执行队列。使用原有完整且已固定数据版本的 `GAME_005` 代表，其他合成行为仅检查本项账户和必要恢复边界。公告证明“可以超过上限”，不单独证明当前国服的全部过载、移除水晶或回合窗口；这些精确行为仍待 M6。

## 公共账户

| 字段或操作 | 契约 |
| --- | --- |
| `max_mana` | 当前永久水晶数，仍满足 `0 <= max_mana <= mana_cap` |
| `mana_cap` | 永久水晶成长上限，不限制临时账户或派生可用法力 |
| `temporary_mana` | 尚未消费或到期的独立临时账户；获取时直接增加非负请求量 |
| `mana` | 保持原缓存公式 `max(0, max_mana - mana_spent - overload_locked + temporary_mana)`，可以大于 `mana_cap` |
| 获取 | 不增长永久水晶、不消耗 RNG；零量保持账户 |
| 消费 | 原 `project_mana_spend` 与 `spend_mana` 优先消费临时量，余额再记入永久已用量 |
| 恢复/解锁 | 原操作仅恢复永久已用量或解除锁定，保留未消费临时量；不会重建已消费临时量 |
| 增减水晶/改变上限 | 原永久账户规则保持，完成后复用 `refresh_mana`；不因水晶成长上限而丢弃临时量 |

删除旧 `trim_temporary` 裁剪 helper，两个原调用点直接复用既有 `refresh_mana`。法力操作仍发原 `mana_changed`；付款仍发原 `mana_spent`，完整报价、消费收据、实际法力历史和原付款证明共用原管线。可用量即使超过成长上限，仍必须足够支付费用，非法操作及结算失败照常回滚。

超量过载仍遵循已有负余额原型政策，本项没有替它增加另一种解释。永久水晶上限、永久已用量范围、所有账户的非负整数与缓存一致性校验保持；放开的是可用法力相对于水晶成长上限的限制。

## 生命周期、恢复与玩家边界

临时账户属于玩家。牌进入墓地、来源离场或后续其他实体的复制、沉默、变形、转控不撤销已经取得的法力；这些实体操作也不建立新的临时账户。本项不为每种实体操作另造组合测试。

沿用原时序：结束事件与其反应仍可消费或观察结束前资源，实际回合交接清除结束方临时量，真实本人开始重置永久已用量、临时量并处理过载和水晶成长。工程预算和结束失败回滚保持原语义；此具体窗口为内部契约，待国服校准。

原初始场景和存档可以保存余额正确的超过上限状态。获取后等待、付款后等待、失败恢复、克隆和逐动作回放仍由原解释器及完整付款证明处理，不以清掉临时量“修复”合法状态。校验拒绝旧规则上下文、错误派生缓存、非整数/负账户、超成长上限永久水晶，以及与原付款证明不一致的改写。该校验不是未签名存档的外部来源认证。

玩家视图沿用已有公开 `mana / max_mana / mana_cap / temporary_mana` 字段，合法动作与实际提交共用原报价和付款入口；公开 `mana_spent` 事件名保留。内部永久已用字段、RNG、解释帧和完整付款状态不交给玩家。
