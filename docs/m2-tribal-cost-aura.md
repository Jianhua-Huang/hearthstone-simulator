# 指定当前种族的持续费用光环

本契约在原费用光环上增加受益卡的种族筛选。实际执行、验证与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。身份、来源与支付窗口为内部政策，尚未国服校准。

## 声明与保存

```python
CostAuraSpec(
    CostSpec(delta=-1, card_types=(CardType.MINION,)),
    tribes_any=('mech',),
)
```

`CostAuraSpec.tribes_any` 为唯一、不可变的非空字符串元组，默认空元组保持原费用光环的类型、卡牌ID、能力和付款者关系。不为空时仅支持友方随从的纯负数减费：无设置费用、特殊下限、付款账户替换、卡牌ID或能力条件。旧位置参数保持；`CostSpec` 不新增种族参数。

必要新增声明仅限印刷普通非融合随从，附件必须有来源、可沉默、未消费、无期限、非磁力。载体按注册卡面核对完整原声明和数量，拒绝删空或修改选择器、借用另一卡面和重复附件。原 `GrantCostAura` 的空选择器范围保持，非空选择器明确拒绝。

当前 prototype-v201 / core-effects-v195 / schema189，拒绝旧 schema1～188、缺字段、错误类型及非法原生生命周期。已有非空费用光环声明新增默认空选择器，对应注册表指纹和嵌套保存字段变化；空声明保持。没有新 GameState/Entity/Player/Ability 字段、报价状态、缓存、事件、动作或机制模块。

## 报价、身份和原费用层

`costs.py` 的原 `_external_quote` 保留物理来源筛选、当前控制者与付款者关系。新的 `matches_cost_contribution` 先匹配原类型/卡牌/能力条件，再对种族光环读取受益卡的完整当前种族。它与紧凑物理、生成费用事实验证共用，不能在恢复时遗漏这个条件。

物理报价使用既有 `CostQuoteInput` 中完整原始有序附魔，以 `tribe_state_for(..., basis='current')` 重算当时的种族；不读取今天的同名卡，不再新增身份快照。双种族、`all` 与排除复用[当前种族契约](m5-dynamic-tribes.md)。需要种族筛选的未知随从明确报错；没有活跃筛选或已因卡牌类型排除时不把未知误当空种族。

生成报价是假设新创建的基础卡面，没有物理实体或种族修改，采用该卡面初始身份。不会借用同名手牌的动态种族，也不创建实体、推进获取历史、消耗 RNG 或有限用途。真正加入手牌后沿普通物理报价执行。

减费继续进入原外部层：固有报价、本地有序费用修改之后，和玩家费用修正统一按附件ID排序。两物理来源各自贡献一次，最低零，已经为零的卡不会因减费涨价。有限玩家修正仍只在实际支付时消费。`Entity.cost` 是本地费用，玩家价格、合法操作与支付使用原 `Game.quote_cost`。

## 生命周期、接受和信息

来源出牌或召唤安装同一印刷声明；沉默、死亡、回手、变形、转控、休眠与唤醒由原生命周期决定是否贡献。当前控制者获得收益，原附件来源ID继续用于追踪。当前和基础复制使用原新物理实体/附件身份政策，不把外部减费复制成永久本地修正。来源自己的种族不作为提供光环的额外条件。

实际支付先冻结完整报价和原接受域。之后来源沉默或离场、受益卡离开手牌，不改写已经支付的金额或补扣费用。紧凑事实在自己的原操作数上复核种族条件；原付款状态、捕获上下文和死亡载体通过共同不变量核对原生声明，不借当前场面重算旧价格。未签名存档的外部来源真实性仍不属于这些检查的承诺。

挂起选择、恢复、clone、回放和失败回滚复用公共执行器。玩家只获得其授权手牌的最终费用和公开信息，不能读取选择器、完整贡献、付款证明或全知帧；查询保持纯读取。宿主内部查询另一方卡牌不能绕过玩家接口的信息边界。
