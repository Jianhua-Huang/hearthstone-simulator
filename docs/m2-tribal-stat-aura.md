# 指定当前种族的持续属性光环

本契约复用原属性光环和种族查询，只补连续属性的受益者筛选。实际执行、验证与下一项只维护在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。当前为内部政策，尚未国服校准。

## 声明与保存

```python
AuraSpec(attack=1, health=1, tribes_any=('pirate',))
```

新增 `tribes_any` 是唯一、不可变的非空字符串元组，默认空元组保持原随从/相邻/受伤武器声明。不为空时仅普通场上友方随从、`condition='always'`、非相邻范围；攻击为严格整数，生命为非负整数，来源是否参加仍由原 `include_self` 决定。原有位置参数保持。

新声明仅印刷普通非融合随从、可沉默、有来源、未消费、无期限、非磁力。附件按原扁平格式保存 `aura_tribes_any`，`aura_spec` 由数值/位置/范围/选择器重建，没有重复保存整份数值声明。完整原生声明和数量校验拒绝改变或删空选择器；其他能力类型不能携带该字段。`GrantAura` 保持原 API，不新增种族或条件授予。

当前 prototype-v201 / core-effects-v195 / schema189，拒绝旧 schema1～188、缺字段、非法类型、重复选择器及非法原生生命周期。旧非空属性声明新增默认空选择器，注册表指纹和保存格式相应变化；空声明保持。没有新 GameState/Entity/Player 字段、派生缓存、事件、动作或模块。

## 当前身份与原数值层

原光环重算先按旧已结算生命选择物理来源，不先清除生命贡献。每个来源在当前控制者场面、原 include_self 与 active 范围中，使用 `has_any_tribe(..., basis='current')` 筛选受益者，再加入原 Attack/Health 总贡献。双种族任一、`all` 和排除复用现有查询；未知完整种族明确报错，不按空集合处理。来源自己的种族不是其持续提供光环的条件。

贡献进入原 `aura_attack` / `aura_health`，位于本地有序数值层之后，攻击沿用原零下限。重复刷新不叠加永久增益，不分配附件或消耗 RNG。两物理来源各自贡献，来源之间符合筛选时也可相互受益；不按卡牌名合并。

原生命撤销政策保持：降低最大生命时钳制剩余生命，不能把撤销另作伤害；改变当前种族而失去贡献也走同一政策。后来重新获得生命贡献不重置已存在伤害。这里保留既有内部政策，精确官方生命和死亡窗口留待 M6，不据内部测试认证国服规则。

## 生命周期和战斗

来源沉默、离场、变形、转控、休眠与唤醒重算贡献。受益者沉默保留外部属性光环，但恢复印刷种族后可能失去资格。当前复制保留本地修改、保留旧来源追踪并分配新附件身份，外部数值不复制成永久增益；基础复制/回手/重置沿原身份政策。地标、休眠与建造中星舰按原 active 政策排除。

死亡记录冻结最后有效属性，整批移出后撤销贡献，不新增死亡检查点。普通出牌与召唤安装同一声明；真实战斗沿原读取、次数和主要伤害包政策。攻击宣告等待中来源失效时，原交付窗读取当前攻击，已准备的伤害包保持原语义。

选择恢复、clone、回放、异常回滚和玩家观察共用原管线。根稳定边界拒绝陈旧光环缓存；捕获上下文在其原状态中校验原生声明，不新增所有历史外部光环缓存的认证。玩家只见当前公开数值和种族，不获得选择器、附件、完整注册表或全知帧；查询保持纯读取。
