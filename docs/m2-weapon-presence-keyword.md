# 装备武器时持续拥有冲锋

独立基础契约 B35/U22。扩展[现有关键词模块](../hs_sim/engine/keyword_auras.py)，从[装备模块](../hs_sim/engine/equipment.py)读取当前控制者的武器。冲锋、召唤限制、攻击次数、战斗与生命周期继续使用原内核。实际验证及下一项只维护在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。

## 声明与武器条件

```python
from hs_sim.engine import Keyword, KeywordAuraSpec

while_equipped = KeywordAuraSpec(
    Keyword.CHARGE,
    target='self',
    condition='controller_has_weapon',
)
# 普通随从 CardDefinition(..., keyword_auras=(while_equipped,))
```

新增形状只允许本体、冲锋和上述武器条件，不接受位置选项。原 `always` 外部/手牌光环和[受伤风怒](m2-self-damaged-keyword.md)保持。仅普通非融合随从的可沉默印刷附件：必须有来源、未消费、无期限、无磁力归属，注册和恢复核对完整原生声明及数量。新条件 `GrantKeywordAura` 继续拒绝；没有任意条件表达式或额外授予入口。

`equipped_weapon(state, player)` 抽取原装备谓词：读取当前玩家武器槽，实体耐久大于零且未标记销毁。零攻击武器仍满足条件，敌方武器不满足。该查询不依赖当前行动玩家；原英雄只在控制者回合获得武器贡献的政策保持。稳定状态的武器类型、区域和槽归属由原状态校验保证。来源 ID 只记录身份，转控或复制后按载体当前控制者的当前装备判断。

## 派生关键词与事件

新增 `Entity.conditional_keywords` 派生集合，单独保存需要 GameState 的自身贡献；实体本地的受伤风怒仍沿用原计算。有效关键词由本体、永久、武器、外部场面、手牌和自身条件贡献合并。同一关键词的其他来源不会在武器损坏时被清除；不创建永久关键词附件，也不写入旧 `aura_keywords`。

普通关键词刷新与原事件前规范化重算该集合。装备、损坏、替换、转控、沉默、复制和换形的结果上下文因此能读到当时的冲锋；没有新增事件、随机消耗或分配。事件前仅规范化自身条件，不提前重选旧外部光环来源。

自身贡献沿用原 `active_abilities` 活跃政策：休眠和非活跃建造状态不生效。手牌、牌库和墓地的本体显示沿用既有区域/活跃政策，并按当前武器更新；这不是已校准的国服显示规则。死亡记录冻结当时的有效关键词和原生附件。

## 攻击与生命周期

新打出或召唤的随从有有效冲锋时，原合法攻击管线允许立即攻击；失去武器后恢复原召唤限制。已经度过召唤限制的随从无需冲锋仍可正常攻击，不能把这个条件解释为“没有武器永远不能攻击”。

失去、替换或重新装备武器不会重置 `attacks_this_turn`，不会返还已用机会。实际新本人回合沿用原重置。攻击声明已被接受、随后在待选反应中失去条件时，原接受与交付政策继续执行；不会以新条件追改已准备的伤害包。本项不修改攻击执行器或武器磨损。

沉默移除原生声明并清除该贡献；回手和变形复用重置。当前复制保留原印刷来源身份，分配新附件 ID，并读取目标控制者装备；沉默的当前复制不恢复能力。基础复制重新安装普通印刷声明。休眠抑制、唤醒重算，转控立即改读新控制者武器。手动出牌与普通召唤安装同一声明。

## 保存与信息边界

派生集合进入实体、快照及冻结工作上下文的严格完整格式。缺失字段、错误类型、重复或未知关键词、非原生声明和陈旧缓存明确拒绝。原 Game 边界检查有效关键词；模型校验还在每个捕获状态自己的武器域中重算条件贡献，不能拿当前装备覆盖历史上下文。该检查验证内部一致性，不认证未签名存档的历史来源。

当前 `prototype-v201 / core-effects-v195 / schema189` 拒绝旧 schema1～188；观察74、命令11、回放1保持。没有新 GameState/Player 字段、事件或外部动作。原普通47个完整定义及指纹保持；新增 condition 值不增加 `CardDefinition` 或 `KeywordAuraSpec` 字段。

玩家只看到当前关键词和合法操作；`conditional_keywords`、条件公式、内部附件及全知工作帧不进入玩家接口。异常回滚、待选恢复、clone 和独立注册表回放复用共享管线。
