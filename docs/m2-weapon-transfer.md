# 已装备武器的物理转控

黏指狗头人要求偷取对手的武器。实际装备是独立实体，不能通过销毁并按印刷卡面重新创建来代替。[前审](../data/support/weapon-transfer-audit.json)已保存材料丢失、错误死亡与亡语的实际反证。执行、验证与下一项仅在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 指令与安装引用

```python
reference = EquippedWeaponReference.capture(current_weapon)
TransferWeapon(reference, player_id=1, source_id=source)
```

引用保存原物理实体、当前控制者、卡面、区域 epoch 和安装顺序。它只能从活跃、未待销毁、有耐久的已装备武器捕获；目标卡面必须是已知 WEAPON。执行时重查这份完整引用和原玩家槽，失效则跳过，不把旧请求别名到当前新武器。同一控制者的请求不重复安装。来源可空；非空必须已知，未知来源/定义或不合类型明确拒绝。

此入口只处理已装备武器的永久控制变化。随从的 `ChangeControl` 保持原 BOARD 契约；不会自动扩展临时武器控制、隐藏区域或其他对象类型。

## 原实体和共同装备流程

保留实体 ID、原 owner、当前攻击/耐久、附魔、能力 ID、来源与适用期限；更新 controller 和双方 `weapon_id`。共同 `equip_entity` 接受这项明确的目标控制者，目的方原武器仍通过原替换归因、死亡记录和移区退休。原 `Resolver.move` 只增加具体 WEAPON 到 WEAPON 的槽位控制迁移，原 PLAY 到 BOARD 的初始随从控制分支保持。

被取武器离开原槽不是销毁，不登记它的死亡或执行它的亡语。新安装增加原区域 epoch 和入场顺序，使旧安装引用失效，不分配新实体或重新复制附件。原护甲/英雄生命、原英雄实际已用攻击次数不重置。

装备和光环按双方完整的新槽位刷新，原武器关键词贡献由当前控制者及实际行动方决定；后续攻击耐久、最后一点耐久效果、到期和自然死亡继续使用原模块。被取武器之后真正死亡时，亡语按当时控制者执行，原 owner 不被当作当前控制者。

## 接受和事件

源移交及目的替换在同一个效果中完成，原装备事件与转移事件捕获时看到完整双方槽位。当前本地顺序为 `weapon_equipped` 后 `weapon_transferred`，目的旧武器亡语仍由原检查点队列安排。转移按一次新的实际装备发布，是待国服校准的明确政策，不能据本地事件推出所有官方计数卡的精确归属。

转移事件保存原完整引用、原 owner 与新安装身份，校验来源、原物理对象、控制变化、epoch 连续性、新顺序和同动作的装备依据。原回溯退休的事件不被拿来核对今天的状态；其余保留事件允许后续合法移区、转控或死亡。不提供未签名外部存档的来源认证，也没有新增全局武器转移历史账户。

## 恢复、事务与信息

引用是 model 中的不可变类型，沿原 FrameCodec 与公共效果保存；捕获的转移事件校验原字段与已知武器定义。待选前的引用、转移后旧武器亡语的等待及尚未执行的事件回调共用解释器。直接失败回滚整个动作，后续选择失败保留已经完成的转控等待边界。JSON恢复、克隆和回放沿同一规则执行。

玩家继续看到当前装备和原公开实体句柄，新增公开转移事件仅提供普通数量和既有观察引用。原安装字段、owner 证明、区域 epoch 和完整捕获引用不输出；没有向玩家交付全知快照。观察版本为 `player-view-v81`，命令12/replay1保持。

语义版本 `prototype-v279 / core-effects-v273 / schema245`，旧1～244须用原引擎。没有新持久字段、运行模块或武器账户，默认生产注册表指纹保持。

## 来源与限度

[两条完整 raw 与 pin](../data/support/weapon-transfer-basics.json)保留 DRG_082 和 DEEP_012。仅 DRG_082 是必要完整隔离适配；其本地 CARDRACE=23 解码为已有海盗种族，未忽略未知标签。DEEP_012 的取走、存储、返还等特殊主体按接卡后置，不建立机制组合任务。官方检索未取得语义或当前合法性证明，本批需求依据明确为固定本地原文；精准国服装备计数、事件顺序及正式池仍开放。
