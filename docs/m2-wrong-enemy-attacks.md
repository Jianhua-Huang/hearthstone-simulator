# 随机改打错误敌人的独立表达

本项确认现有抽样、自动回调和目标替换能表达真实的50%错误敌人规则，无需新增随机或战斗执行器。实际执行、验收结果及下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 原接口与表达步骤

`RequestChoice(sample_size=1, min_count=0, max_count=0, on_select=...)` 先由引擎对完整选项无放回抽样，再自动完成零项选择。回调从 `ctx.choice.choice.options` 读取抽到的一个选项；`selected_ids` 为空。分支效果不会自动执行，回调显式返回后续普通效果。这是[原选择接口](m3-choices.md)的已有行为，抽样不在卡牌回调中直接调用宿主 RNG。

必要食人魔步兵配方采用三个自动回调步骤：

1. `attack_declared` 的本体监听保存原 `window_id` 到一个选项 ID，零项回调取得执行时的新状态。重新检查原窗口、攻击者卡面、沉默/存活及错误敌人池，避免捕获后攻击者离场仍抽样。
2. 将 `keep` 与 `redirect` 两个等权选项抽一个，保持原目标或继续抽样。前者不抽目标。
3. 从实际当前敌方英雄/战场中，排除当前原受击者及非活跃/休眠/将死对象，对唯一物理候选按 ID 排序抽一个。每个目标一个权重；将原窗口 ID 和实际实体引用保留在选项中，回调返回 `RedirectAttack(window_id, target_id)`。

完整可执行配方见[必要代表夹具](../tests/test_wrong_enemy_attack_basics.py)。没有新 Effect、条件表达式、保存字段或模块；引入时核心为 `prototype-v201 / core-effects-v195 / schema189`，拒绝旧1～188，观察74/命令11/replay1保持。生产代表包与合成包没有扩张。

这些自动请求不建立 `pending_choice`，不发布玩家选择请求，不要求 `SelectChoice`，也不属于德鲁伊抉择机制。原引擎的选择计数及内部 `choice_skipped` 仍推进；它们不进入玩家事件。只有测试中显式加入的攻击窗口等待夹具才产生真正的玩家待选。不能称内部计数或事件完全没有变化。

## 攻击和生命周期

错误目标池为空时不抽概率或目标，仍允许原正常攻击；自动刷新请求自身不消耗 RNG。保持目标只抽一次概率，改打目标再抽一次目标。英雄可以作为错误受击者；普通攻击先通过原合法性检查，改打依原 `RedirectAttack` 的结构/存活检查，不再套一次玩家普通嘲讽或潜行限制。

原攻击窗口 ID、攻击者、是否强制、攻击机会和结算路径保持。只有一次原攻击声明与完成，不创建额外攻击；相邻目标规则也不能用这一配方模拟。伤害、反击、护甲、死亡和终局继续由原战斗管线负责。

监听复用普通原生触发附件，沉默/变形移除，回手重放重新安装，当前/基础复制获得独立身份，转控按实际新控制者选择敌人，休眠阻止普通攻击。没有物理卡外的次数状态或一次消费声明；每次合法攻击独立抽样。

原窗口在抽样前或改打后等待时，保存、独立注册表恢复、clone和动作回放继续使用原帧。已经抽到的引用和 RNG 不会因恢复重抽；选中英雄替换后，原交付取消，不自动攻击新英雄。即时错误与失败待选沿原事务回滚状态、事件、正常攻击计数、伤害与随机状态。玩家观察和操作查询保持只读，不提供内部选项、窗口、完整帧、附件或 RNG。

## 规则证据与保留边界

仅隔离验证 `GVG_065` 食人魔步兵，完整[本地 raw/pin](../data/support/wrong-enemy-attack-basics.json)为3费4/4中立普通，FORGETFUL=1是存在标签。[2014年官方食人魔说明](https://hearthstone.blizzard.com/en-us/news/16893475)给出50%错误敌人及可能绕过嘲讽和潜行的历史需求；[来源分级](../outputs/wrong-enemy-attack-basics-20261010/official-evidence.json)不把这段历史文案当作当前国服规则认证。

排除哪个接受窗口的目标、免疫目标资格、空池/随机推进、自动内部计数/事件及其它反应顺序均为 M6 待校准。更广的原生/武器来源、正式合法池和可达卡面仍需 M0/M7 调查与适配，不宣称完整 FORGETFUL 或 U44。原后续顺劈已接入同一战斗批次的相邻伤害能力；当前执行位置见两份主台账，完整基础目标保持开放。
