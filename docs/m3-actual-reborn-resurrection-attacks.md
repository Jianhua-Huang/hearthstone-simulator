# 实际复生历史的整批复活与原返回者攻击

CAP_806雷斯·范盖斯特使用原`successful_reborns`中的实际成功发生，保存精确原死亡ID。死亡时带复生、普通复活、复制或当前场上关键词均不能替代实际复生。固定来源、内部验收与正式国服校准分别登记；具体执行结果仅见原两份台账。

## 有限表达与执行

`Resurrect.death_ids`默认为`None`，沿原完整死亡查询；显式tuple表示精确死亡子集，空tuple表示空集合，未知死亡拒绝，需要实际查询时不符合原查询的死亡也不得静默跳过。满场或零次请求保留既有不捕获查询/不抽选政策。精确子集及`attack_after_all=True`要求原`SummonCause`，不能落到旧无归因执行路径。完整死亡库存、原查询及抽选仍由既有`ResurrectionBatch`捕获；不按实体编号排除多个不同死亡发生。

精确材料通过既有复活入场器检查及交付，未选中的其他死亡材料不阻塞精确子集。普通默认查询的既有材料政策保持。返场顺序沿原随机不重复死亡抽选，容量在每个实际原入场前重核；数量附件的额外体、入场反应及逐体后续全部结束后，才关闭复活阶段。

关闭时从每次原抽选已绑定的`entry_root_id`及其完整实际交付构建有序攻击组。不会猜未来分配编号、扫描同来源历史或把每体`on_summon`误作整批完成。未成功交付的体没有攻击义务；同批数量额外成功体各有自己的原驻留。原复生历史和本批死亡子集均不会因为后续战斗新发生复生而扩展。

每步委托原`AttackRandomEnemyMinion`选择当时仍存在的敌方随从，再委托普通`ForceAttack`及其返回的实际`ResolveAttack.window_id`。随机事件反应先于攻击声明，攻击声明反应先于战斗，前一步全部反应结束后才开始下一步。敌方英雄、休眠及非普通可交互物不进入该原生随机池；空池或失效的原攻击者不抽随机数。未重新定义既有强制攻击、伤害、死亡和复生规则。

原返回者死亡、转控、休眠或离场重入后跳过，不能用之后的同编号驻留、复生新体或其他随从顶替；原连续驻留内变形保留原义务，战斗读取实际当前属性。随机选择反应中转控的攻击者也不能替另一位玩家发动本次攻击；原已选敌人离场后不另找替代对象。

## 保存与边界

`ResurrectionBatch.attacks`保存原完整交付分配事实、下一个下标、选择/应用阶段、普通强制攻击及实际原攻击窗口。三个有限控制分别负责下一步、应用普通攻击及确认原战斗完成；完整原成员不可缩减或重排，排队义务不可删除、复制或越过原战斗。私有进度收据约束原阶段的单调变化，复用原选择、异常回滚、终局中断、回溯与回放机制。

新schema371要求显式新增请求/记录字段并拒旧370及更早；core454保护执行身份。没有新的GameState、Entity或Player字段。观察92、命令12及replay1布局保持，完整材料、原随机状态及内部队列不进入玩家DTO。存档哈希和私有收据验证内部一致性，不认证未签名存档的外部来源。

## 待国服校准

原成功复生发生的计数、复活抽选及放置顺序、数量额外体是否属于“使其攻击”、整批返场与原生战斗的具体窗口、连续驻留内变形及随机事件反应政策均为内部执行契约，仍须M6正式国服证据确认。完整正式卡池和其他尚未实现内容仍按M0/M7登记，不能由单卡内部通过推断整池支持。
