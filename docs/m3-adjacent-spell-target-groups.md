# 电流导联与原双箭头的本地执行策略

真实消费者为BE_302烈焰震击，原资料、两个不同敌人、普通手动/自动目标接受见
[既有双箭头契约](m3-spell-target-groups.md)。本扩展不改变该卡的原定义、一次付款、
原目标输入和完整实际目标收据，也不添加新卡或生成池成员。

## 证据范围

[官方29.2更新](https://news.blizzard.com/en-gb/article/24077473/29-2-patch-notes)
要求被迫重复的法术遵守目标合法性。
[玩家实际对局记录](https://www.reddit.com/r/hearthstone/comments/1xcmytr/conductivity_flame_shock_interaction/)
报告电流导联配合烈焰震击会累计三点过载，支持完整主体重复；
该记录没有证明第二条箭头的去向、重合目标规则或第二箭头是否扩展邻位。

以下是明确采用的本地近似，不冒称国服服务器的精确双箭头规则。
精确版本、热修和边界校准按用户要求继续暂缓，不等待实测。

## 不可变输入与派生执行子集

原CAST实际标量target_id仍是完整已接受组的第一个非空实际位置。
只由这个实际主箭头在接受时捕获原邻位，第二条箭头不另扩邻位。
额外主体把原主箭头位置替换为自己的原相邻目标，保留其他原已接受箭头位置。
这是一份从原CAST/实际组收据和原相邻槽导出的执行子集，不是新的双目标输入，
不重新抽样、付款、分配CAST、重开玩家选择或修改原实际组。

相邻主目标沿既有严格原连续驻留和普通法术合法性门禁；无效时整项主体不执行。
其他箭头沿原显式场上驻留查询当前对象，再核当前普通目标合法性。
离场、当前无法被法术选中、转为友方或其他不合法的副目标不补选、不过桥、不重绑定。
若派生执行中两个位置指向同一物理对象，只保留第一次，仍不改写原两个不同输入。
这些分配、去重和主箭头优先级是本地策略，均保留为未校准差异。

原主体仍使用原完整组执行；只有已接受的相邻主体进入新派生分支。
整个有效主体继续执行原DamageBatch和一次Overload，副目标失效不会单独取消过载。
主体伤害、免疫、法伤、终局截断和过载锁定继续由原执行器负责。

## 保存与范围

`target_ids(context, registry)`要求原CAST仍属于捕获状态、原实际目标阶段已关闭，
额外分支还校验真实注册的两箭头profile、运行中相邻槽、原来源/玩家、实际邻位箭头
及其当前合法性。原本可空的其他箭头和完整原目标收据保持，派生向量不成为可伪造的新输入。
等待伤害/过载反应时保存的普通效果和原续接沿原FrameCodec恢复；失败按原事务回滚。
原输入/候选/实际组、相邻计划和RNG不进入玩家DTO。

不增加GameState字段、Effect或载荷类型，core826/schema646拒旧1～645。
资料v3保留v2原三个行及角色/响应，新增完整BE_302兼容依赖和两个官网主面证据，
旧v1/v2文件均保留。原数据源及71萨满成员不按执行覆盖率裁剪。
动态药水的成分主体支持继续保留，实际原双箭头入口限制由这一明确本地策略解除。
相邻目标与选中监听/法术记忆的关系仍另行核对，YOG_522不提前宣称国服完整校准，
萨满71来源也不由注册数自动绑定；实际进展及下一项只在两份原台账维护。
