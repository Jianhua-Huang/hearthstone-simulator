# 破碎的巨龙之魂与原手牌接邻施法

本文维护有限实现契约；执行进度、实际证据和下一项仍只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。

## 原始套件与开局

`data/cards/dragon-soul-essences-v1.json`保存八条完整原行及16份完整双语官网响应：可收藏根CATA_EVENT_110、六种6费中立精华和绿色精华召唤的8费8/8龙。该龙已在旧注册表存在，本批核完整旧定义指纹并直接复用，不重复注册。

原根只有对战开始时主体。真正before_deal钩子核原开局来源及仍在牌库的物理根，先RemoveFromGame移到SETASIDE，再用原ShuffleDeckCards和六次AddToDeck随机洗入六种精华。原始构筑牌表及原实体库存保留，运行时牌库净增5，之后走普通发牌、换牌及首回合。对局内获得的根不重新触发开局，普通使用没有额外文本效果。特殊开局来源的精确排序、复制及牌库容量政策继续由原公共管线和M6核定。

根的原DONT_PICK_FROM_SUBSETS标记用于显式普通生成禁入。register_generation_exclusion复用历史名为fabled_generation_exclusions的已审核排除库存；不改变旧排除和身份键，也不将该根登记为奇闻。原牌仍有完整数据、定义和池元数据，不能为了避开实现而删除候选。ETC侧板与完整正式生成域仍待M0核定。

## 六个原主体

红色对一个敌方角色造成8点法术伤害，蓝色随机抽三张实际法术牌，无匹配跳过；青铜复原8法力，黑色获得12护甲，绿色普通召唤原8/8龙，风暴对全部敌方活跃普通随从造成4点同批法术伤害。实际伤害、法伤、抽牌/满手、费用资源、容量、召唤数量和死亡继续使用原执行器。

完整原行没有法术学派，不能按颜色猜填。35.4.2[官方补丁](https://hearthstone.blizzard.com/en-us/news/24276662)可证风暴4伤及青铜复原8的数值更新；36.2[官方补丁](https://hearthstone.blizzard.com/en-us/news/24290432/36-2-patch-notes)记载希奈丝特拉误重复精华的修复。现有other-class谓词已经排除中立法术，本批使用真实CATA_154验证，不额外发明精华的通用禁止重复标记。

## 原物理手牌组

AdjoiningSpellProfile只声明六个真实精华卡面。真实手牌付款时从原报价状态冻结完整有序手牌；自动施放保存移区前真实来源与原区域。组保存实际施放者与原手牌持有者两个身份，外方手牌/牌库沿已有CastStoredSpell控制转换，不能把源持有者当作施放者，也不能借当前施放者的另一手牌。

当前本地政策为：从原来源向左右扩展，接受同一连续精华块；先执行选中来源，再按原手牌从左到右执行其余成员。非精华阻断；后续抽牌不会扩充原组。每个成员用CardReference保留原实体、持有者、卡面及驻留，轮到它时再核原物理引用；移区或换驻留则跳过，不按同名补造副本。

只有第一张手动使用记录进入原PlayRecord并支付；其余通过普通CastStoredSpell自动施放原实体，具有自己的CAST和原随机/目标/选择政策，不增加使用牌数或额外支付。自动从手牌施放同样接受它当时的连续块；新生成或从牌库施放的来源没有手牌接邻组。成员附带原父CAST与位置绑定，主体不再递归扩充另一个组。

原来源需要指定目标时按正常手动准入；隐式成员需要目标时沿普通自动随机选择。这一目标政策、连续块接受时机、成员顺序、成员移动和逐主体反应窗口仍为本地政策，须以国服证据校准，不能只凭“同时施放”文字宣称精确时序已完成。

## 恢复、终局与信息边界

五种私有记录分别保存原付款/自动来源、实际组接受、每个有序成员的实际CAST或失效处理和完整结束。保存核原实体分配前缀、完整连续块、原出牌/CAST来源、玩家、唯一接受与顺序覆盖；不能裁整个组或替换另一个CAST。CastAdjoiningSpells是唯一新增Effect，只保存原根CAST及下一位置，普通帧沿原解释器恢复。等待时必须恰有原下一义务；正常完成须覆盖全部成员，提前终局须有实际game_ended及原CAST中断。

失败选择/反应沿原事务回滚，克隆和回放不重抽原组或多付费用。没有新增GameState账户、模型字段/类或明确payload类型；完整原手牌保存在私有证据，不进入玩家DTO，不提供未签名存档的外部来源认证。观察仍为player-view-v109。

M0正式版本/热修/合法与生成池、M6国服精确规则、完整实际可达及阶段发布验收仍独立开放。
