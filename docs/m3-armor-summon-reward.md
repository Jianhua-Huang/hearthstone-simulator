# 原固定召唤组与护甲奖励

实际进度、验证和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。本契约服务于BE_561起源熔炉及BE_561t钢铁魔像，不表示正式国服规则或完整生成域已认证。

## 原地标与完整交付

3费2耐久地标沿原放置/UseLocation管线，放置不执行主体。使用返回一个带原SummonCause的固定3/3嘲讽魔像请求和SpendArmorForSummonedGroup。普通满场门禁及最后耐久释放位置沿原R-037，召唤、死亡、数量倍率及位置仍由旧内核负责。

original_summon_groups按完整原状态前缀、Cause及固定材料连接唯一完成请求与全部成功交付。奖励不按卡名、当前位置或同类随从重找；数量额外交付共享一份固定支付。本地政策为至少一份原交付仍是存活、活动、友方连续在场时才接受支付；无原受益者则不消耗护甲。该数量/存活政策仍待M6。

## 非牌费护甲消费

SpendArmor(player_id, amount, source_id)只接受正整数完整门槛，执行时读取当前安装英雄账户：足额扣全额，不足扣零。使用原PaymentWrite应用器，不产生牌价报价、费用用途或一次性牌费修正消费，也不伪装成LoseArmor、伤害或增甲。

原结果保存英雄/发行者、本人回合区间、turn/action/root_action、原余额、请求量、实际量、余额和事件位置。私有armor_consumption_resolved保留完整结果；正支出发布独立armor_consumed，牌费armor_spent及直接损失armor_lost保持各自含义。原数值与普通反应检查点不另写执行器。

## 支付后的原奖励

奖励先保存完整有序交付ID、原接受状态、费用/属性及私有接受证明，再交普通SpendArmor。支付反应结束后，FinishArmorSummonReward核对精确下一份原支出、原英雄和余额，并沿原在场引用及Buff执行器一次应用已接受奖励。

原友方连续在场变形可以继续接收；死亡、休眠、控制不再友方或离场重进使原引用跳过，支付不倒退，也不补给新同名随从。后来获得护甲、独立消费、召唤或英雄变化不重新定价或扩张原受益者。该反应/控制/继承窗口为本地契约，仍待国服校准。

## 保存与边界

完整原请求/上下文、交付与费用证明进入原FrameCodec；私有结果和正公开通知配对，挂起续接重算原完整组并绑定原支出。正常JSON恢复、克隆、回放及整动作/待选失败回滚共用旧事务；不增加State、Entity或Player字段。出现的原续接须通过语义核验，完整存档仍不提供未签名来源认证或所有入口的完整主体计划认证。
