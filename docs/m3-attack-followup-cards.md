# 原生攻击后的奖励、击杀与跟随攻击

ForceAttack新增默认false的excess_to_hero选项，只为真实幼龙结束主体启用；原前两个操作数、第三个战斗关系及其默认行为保持。该政策沿原窗口保存，普通跟随攻击继续无分流，见[战斗分流契约](m2-forced-combat-excess.md)。

真实条件消费者继续使用既有属性、攻击、施法和物理库存事实；跨冻结反应的原邻位组仅增加有限法术续接，冻结/死亡仍由公共执行器负责。保存、末次武器奖励及初始资格的边界见[契约](m3-conditional-consumers.md)，当前执行版本以原两份台账为准。

真实卡牌应组合已有公共效果，敌方随从持续嘲讽仅增加有限声明范围；生命设值、连击复制、武器死亡、随机额外效果与牌库逆序继续共用原执行器。新增范围及待国服边界见[配方契约](m3-public-effect-consumers.md)，下文历史初始范围不覆盖此后新增形状。

上一张使用的印刷符文用原冻结历史查询；固定召唤组从完整原交付连接原目标强制攻击，保存、容量与时序边界见[符文与召唤组战斗契约](m3-blood-rune-native.md)。

后续怒袭甲龙使用原驻留随机攻击入口：先真实增益及其反应，再取当前敌随从，并将原攻击者/选中目标驻留传回既有ForceAttack。格里什掘洞虫继续本页的原完成事实和存活截面政策；没有替换原战斗执行器，见[后续契约](m3-beast-trigger-cards.md)。

本契约覆盖雷加尔·大地之怒、飞火流星·芬杰和伊利达雷审判官。完整固定37.0原行及审核配方在[卡牌数据](../data/cards/attack-followup-effects-v1.json)，行为在`hs_sim/cards/attack_followup_cards.py`。实际进度、验证、差异和下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。

## 原接受窗口

三张卡订阅既有`attack_finished`，通过事件位置寻找唯一已完成的`CharacterAttackRecord`，核对原来源、实际交付目标和战斗接受。兼容的裸`CombatDamage`不具备声明攻击信用，不触发这些主体；取消或未完成攻击也不算完成。

现有攻击完成事实在同批健康结算之后、死亡清理及排队反应执行之前捕获。卡牌明确要求来源在这一截面仍活跃、存活、未标记消灭。已经接受的普通奖励/招募主体不会因后来来源死亡而撤销。该截面与精确国服先后仍需M6校准，不将内部策略写成官方结论。

雷加尔读取原截面的本方场上顺序，只有自己或相邻的实际攻击随从合格；普通英雄攻击和敌方攻击不合格。相邻攻击者本次互伤将死时仍保持其原位置，本牌自己将死则不授予奖励。生成卡由明确的`COLLECTION_RELATED_CARD_DATABASE_ID=69625`绑定已有完整`CORE_EX1_238`闪电箭，交付、满手烧牌、伤害、支付及过载仍走公共模块。

芬杰要求本体是原攻击者并存活，最终受击随从的首个致死原因来自本次COMBAT伤害/剧毒包；核对原源epoch、入场顺序及原战斗事件区间。不会用后来死亡列表、任意法术击杀或防守反击冒充攻击击杀。满足后返回`SummonFromZone(count=2, query=PoolQuery(tribes_any=('murloc',)), cause=SummonCause.capture(ctx))`，两次实际招募的随机、当前牌库、数量、容量和入场均沿既有执行器；不触发战吼、不按卡名生成替代品，不从未知候选中删牌。当前政策针对原最终受击者，不据此认证所有改道伤害、额外波及及延迟击杀例外。

审判官要求本方英雄完成攻击，捕获原实际交付敌人。已死亡或失效的敌人不借后来复生体续打。它返回原`ForceAttack`，普通次数、冻结、入场等待、双方关系、战斗和终局继续由既有强制攻击政策负责；不会提交玩家的普通攻击来伪造跟随。

## 绑定原场上驻留的强制攻击

原`ForceAttack(attacker_id, defender_id, combat_relation='opponent')`保持三个字段及整数用法。两项角色操作数现在也接受已有的`BoardPresenceReference`：

```python
ForceAttack(
    BoardPresenceReference.capture(ctx.state, ctx.source_id),
    BoardPresenceReference.capture(ctx.state, original_minion_target_id),
)
```

英雄受击者仍使用原物理英雄ID。随从的原驻留引用在返回效果时从接受截面捕获，执行时沿`resolve_board_presence`解析。回手、死亡或离场再入场即失效，即使物理实体ID复用也不会重绑；旧引用过期属于跳过。未分配实体或未来驻留编号属于错误，在执行和带`origin_state`的`FrameCodec`编码/解码时拒绝。

驻留保持期间的变形、沉默和控制变化不自行创建新驻留；执行仍检查当前活跃、存活和请求的战斗关系。已接受的审判官主体不因后来沉默而取消，但不能让后来重入场的载体替它攻击。旧整数请求继续按既有当前ID策略运行，不为它们偷偷补捕获政策。

## 保存、版本及边界

没有新Effect类型、内核模块、状态账本或持久字段。原BoardPresenceReference已在typed codec白名单中；ID通用整数校验只对ForceAttack的这两种明确操作数作有限扩展，其他字段保持原严格校验。原私有接受状态、引用、历史和队列不提供给玩家，公开攻击事件与命令协议保持。

原schema270布局保持，core-effects-v334及内容包preview-v35的签名保护新的执行语义和操作数类型；布局相同不代表可将旧语义存档当作当前存档恢复。默认历史代表包不追加这三张根卡或实验夹具。芬杰的构筑身份由具名DECK_RULE引用40803对应CFM_344明确核对，不从未知数字标签猜测；历史完整原行只作身份依据。

`python -B -X utf8 -m examples.card_attack_followups`使用玩家投影命令展示原相邻奖励、闪电箭、物理招募及普通/跟随攻击。示例的显式法力、短牌库和旧武器用于内部实验，不认证正式标准套牌。正式池、全部实际可达内容、精确国服时序和强制资格仍按M0/M6/M7要求闭合。
