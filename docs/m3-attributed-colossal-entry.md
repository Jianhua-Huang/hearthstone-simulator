# 原生带归因召唤的巨型入场

2026-10-19增量：带归因的`CopyEntryMaterial.profile=board_copy`巨型资格也已接通，继续复用原材料安装及`colossal.enter_minion`；其他存储复制/招募profile的旧限制保持。实际缺口与验证边界见[克洛玛图斯契约](m3-colossal-keyword-loss.md)，下文保留本批原始范围。

真实依赖来自两个已经登记的六费随机池消费者：阿梅达希尔FIR_907的使用进度到6时，及欧斯克TLC_452t20的六费随从召唤，都能选中CATA_139柳牙。后者还要求把嘲讽、吸血安装到原主体。不能从完整池删掉这张合格巨型，也不能改用手牌/牌库存储移动来代替新建召唤。完整卡面和来源保持原P68与K141证据，本增量不增加卡牌定义。

`summon_quantities.validate_material(..., allow_colossal=False)`保留旧的限制性默认。只有原生`SummonByCard`的`SummonEntryMaterial`、池候选与有限候选召唤明确启用巨型资格；原复制、招募、复活池和有序组的委托检查仍走原默认。已有直接死亡材料复活及整牌重放各自保持独立契约，不由本项新增或撤销支持。新的资格只接受印刷普通材料，及既有池所需的空、单独TAUNT、有序TAUNT/LIFESTEAL声明；额外属性、亡语、其他关键词、强制休眠或具名交付回调仍明确拒绝，不顺带认证其他材料配置。

实际交付继续使用原`DeliverCardSummon`创建主体并安装入场附件，再调用既有`colossal.enter_minion`；没有第二套附肢循环、实体分配、容量规则或战吼执行器。每条附肢保留真实独立实体与入场反应，随后才通知主体，再继续同一原数量计划中的下一个主体。主体离场或易主取消剩余附肢，已经生成的附肢保留；导致召唤的原卡离场不会取代巨型主体的身份。数量额外体使用已接受材料和原次数，每个实际主体各自展开、各自重核场位。

随机、发现的完整候选、原选中结果、付款/施法事实、父子请求和完成收据仍由原公共模块保存。空池及满场不隐去未知合格内容；生成批次原已抽定的结果保留失败交付。等待、异常回滚、回放及玩家信息继续沿已有原召唤与巨型两套账本，不给玩家内部记录。保存布局、Effect/payload类型和玩家协议不变，仅内核语义版本更新；具体内部验证、实际版本与剩余事项只在两份原台账维护。

这仍是本地内部契约。完整正式池、准确国服隐式资格、巨型各通知窗口及数量/授予细节需要M0/M6证据；不能以实验池中的两个真实消费者通过宣称所有巨型来源或完整标准可达内容已支持。
