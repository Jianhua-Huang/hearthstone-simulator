# 艾萨拉的奇闻地标与原实体强化

真实家族包含TIME_211艾萨拉女士、辛艾萨莉和永恒之井的基础/强化面、两个仅选择界面分支。完整原行和官方双语主面固定在`data/cards/azshara-fabled-locations-v1.json`；两附魔仅作源证据。实际进度、验收与下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。

## 选择与原实体

卡牌使用原`ChooseOneSpec`及`FabledSpec(ROOT,(WELL,ZIN))`，普通起始构筑、出牌付款和分支处理保持。选择界面的法术定义不可从手牌使用，不独立加入生成池；运行中创建艾萨拉不会补入两张地标。

每个真实分支在原主体窗口捕获本人当前场上、手牌和牌库中匹配的地标：先强化该侧基础面，再摧毁另一侧基础/强化面。保留完整有序物理引用，后续反应不追加新目标，也不借用已换面或离场重入的对象。当前实施范围为全部匹配副本，墓地、对方和未来生成物不在本次计划内；该精确范围仍待国服校准。

- 场上强化使用既有`AdvanceLocationFace`，保留原实体、入场顺序、耐久、冷却、使用次数及有效动态附件，只更新印刷材料和epoch。
- 手牌/牌库强化使用有限`AdvanceStoredLocationFace(CardReference,card_id,source_id)`，共用同一印刷替换；保留原动态成本、耐久和物理对象，并沿原存储换面通知隐藏旧手牌身份。
- 场上摧毁使用`DestroyCapturedLocation(LocationFaceReference,source_id)`，先核原物理驻留再交原地标摧毁和死亡检查点；存储目标沿既有`DestroyStoredCard`处理。
- “兼得”按两段原分支执行，第二段重新读取第一段实际结果，最终两个地标都会被摧毁。没有额外组合执行器。

两个新地标请求复用原字段验证与frame遍历。等待时保存原引用；目的面、种类、来源和未来epoch仍须验证，类型注解也必须能由原付费/续接codec解析。失败选择、事务回滚、玩家投影与回放继续使用原解释器，没有新状态账本。

## 真实地标主体

辛艾萨莉按既有友方随从目标规则执行普通当前`CopyMinion`；强化面通过原`SummonStats`在入场前设置为当前攻击及剩余生命的两倍。复制材料、伤害、附件、容量、最后耐久腾位及原接受窗口沿既有管线，未增加提前锁定目标材料的窗口。

永恒之井使用`FillHandFromPool(GenerateFromPool(...))`，接受当前实际手牌空位，完整抽选后逐张交付。只为本真实来源允许临时法术的填手；原随从配方、成本配置和发现限制保持。普通井不授予重复，强化井使用原`CardSpellRepeatGrant`。

`CreateTemporaryCard`的可选`spell_repeat`只接受法术材料，共用原创建安装器，在首次`card_created`、获取及烧毁通知前同时提交临时期限和重复附件。正常出牌仍仅付一次费用，重复施法、到期和跨区处理沿原规则；不把相邻回合或任意期限组合推广为新入口。

卡包依赖宿主提供明确的生成上下文和`constructed.cards`池，包含未实现内容也不能裁去；全部合格候选在抽样前验证，满手的零交付也保留池检查。实验候选目录不等于正式合法或生成池，后续实际可达内容仍须闭合。

## 证据及待校准边界

[官方卡面](https://hearthstone.blizzard.com/en-us/cards/119928/)及同批子卡主面支持两种强化/摧毁、临时法术、双重施放和双倍复制。[ClayByte在原发布帖的答复](https://www.reddit.com/r/hearthstone/comments/1o3576y/comment/niuoiks/)明确兼得会摧毁两张地标，原观察另存于本批证据；该答复没有逐项证明通知窗口、全部副本范围或国服37.0行为。

精确多副本范围、存储动态材料留存、摧毁公开程度、分支通知次序、剩余生命翻倍和原临时生命周期政策仍待M6。宿主正式版本/卡池及全部随机结果的实际可达内容另行验收；内部登记不能认证这些边界已完成。
