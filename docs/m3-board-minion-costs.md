# 按场上随从数量持续减费

本契约补齐原费用管线的一个独立基础输入：按当前场上的随从数量，每个减一费，最低零费。实际结果和下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。它不是任意费用表达式，也不建立跨机制组合清单。

## 依据与声明

[三条完整原始记录](../data/support/board-minion-cost-basics.json)保存计数模块`TOY_330t98`、海巨人`EX1_586`及核心海巨人`CORE_EX1_586`，canonical pin为`8a50f2bdb060ca5115582ec6a6603ba6e4913bb5ea72c3c4bd982b5add0f40bd`。本地计数模块明确按友方随从减费，海巨人按整个战场的随从减费。计数模块原名称是“计数模块”，较早前审文字称“计时模块”是名称笔误，旧证据保留。固定本地数值和文本不是最新正式合法池认证。

`CardDefinition.board_minion_cost`可为`BoardMinionCostSpec(scope='friendly')`或`BoardMinionCostSpec(scope='all')`，政策固定`cost.board-minions-v1`。默认`None`；其他scope/政策、任意表达式及非普通随从载体明确拒绝。注册表仍负责普通定义校验；模块化构筑的必要功能模板可以保留这个真实随从声明，由编译卡面承担实际物理行为。

```python
CardDefinition(
    'EX1_586', '海巨人', CardType.MINION,
    cost=10, attack=8, health=8,
    board_minion_cost=BoardMinionCostSpec('all'),
    # 另需审核过的正常构筑元信息。
)
```

声明只表达每个合格随从减一费、最低零费；没有任意倍率、设置金额、隐藏条件或历史公式扩展。

## 数量对象与公共报价

每次报价读取两个玩家完整有序BOARD驻留目录，并保存物理ID和当时卡面。按原卡面定义计入普通随从，排除惰性投牌物。休眠随从仍是场上随从；本地政策以区域驻留为准，直到真正离开BOARD，不因活跃、受伤或将死标记另减数量。手牌、牌库、虚空、场外星舰建造槽等不是BOARD驻留对象。所有行均检查已支持定义，包括friendly未选择的另一侧；零费不短路、不跳过未知内容。

friendly按实际报价玩家的当前控制方场面计数；all统计双方。转控改变friendly数量但不改变all总数，召唤、移除、回手与再进入后自然按新局面重算。规则不写Entity基础费用、费用附魔或持续缓存，也不分配实体/附件ID、不消费RNG或有限用途。

沿原`capture_intrinsic_stage`插入这一个纯数量输入。顺序为原当前base→场面计数减费→已有上一自身回合条件阶段→原本地附魔→外部费用来源→调用方最低费用。旧定义的场面阶段为明确`None`，既有条件顺序和支付账户保持。现有合法动作枚举、玩家显示、手牌校验、实际付款、实际接受报价及无实体的生成报价共用原公共入口，没有第二套定价公式。

## 冻结付款依据

`BoardMinionCostFact`保存原声明、payer、原实体分配上界、双方完整有序目录、实际数量和before/after。它进入`IntrinsicCostStageFact.board_minions`，从固定定义及全部行重算数量与金额。物理报价的来源必须已在原分配上界内，不能借更新实体；手牌提交收据拒绝将尚未打出的自身计入原场面。

实际手牌先按付款前场面接受报价，再付款、进入战场、执行后续。例如原有两个随从时海巨人支付8费，自己进入后不会把原付款重写成7费。完整原付款/接受证明沿既有解释器重查原状态；card_played后的真实选择保持原收据，选择后的合法场面变化不重新扣款。

历史紧凑校验检查原时间线和物理分配前缀，重算保存的数量操作数；不能用今天的场面替换旧目录。它不认证未签名存档的外部来源或协同重写后的完整历史真实性。原支付证明与恢复/回放沿原框架，失败事务恢复实体、原收据、分配上界、RNG和玩家观察。

## 印刷身份与必要生命周期

基础费用保持印刷/当前base身份，连续减费不变成永久本地减费。印刷复制保留声明，沉默与回手的普通生命周期保持；再获取为手牌后按当前场面重新报价。没有新增战斗、死亡或复制处理器。当前定义读取政策覆盖必要普通来源，特殊复制到手牌时保留沉默/费用等精确官方行为仍待M6及具体真实来源审核。

只在隔离专项适配一张海巨人，并验证计数模块的必要原生构筑卡面。计数模块＋完美模块的印刷值为9费4/5，只有一名友方随从时支付8费，两个敌方随从不会额外影响friendly报价。构筑规则与关键词继续复用已完成的[模块化构筑](m3-modular-deck-basics.md)，不新增无依据配置。核心海巨人仅保留原始证据；生产代表64、合成包3保持。

## 保存与玩家边界

首次落地为`prototype-v182`、`core-effects-v176`、schema171，明确拒绝旧1～170。当前共享规则`prototype-v190`、效果`core-effects-v184`、schema179拒旧1～178；观察74、命令11和replay1保持。所有卡牌定义增加默认`board_minion_cost=None`，注册表指纹因此变化；所有固有阶段保存显式`board_minions`，包括旧定义的`None`，严格解码不补旧字段。后续[手牌数量费用](m3-hand-count-costs.md)增加独立默认hand_cards=None叶，场面事实及原语义保持；当前指纹/费用格式相应变化。没有新实体/玩家字段、玩法事件或外部动作。

双方场面本来公开；本人手牌显示共用计算后的报价，对手隐藏手牌仍不提供当前价格。观察不输出数量原目录、实体分配上界、费用证明或全知付款状态；宿主快照和定义目录不能给玩家。

## 剩余范围

场面对象资格、休眠/将死驻留政策、固有费用顺序与特殊复制来源目前是内部政策，未国服校准。不同数量公式、伤害/治疗/弃牌/支付等历史条件，以及完整真实来源、正式池与导入继续U53/M0/M6/M7；本项不宣称任意费用公式或整个模拟器完成。具体卡牌能用现有固定效果表达时不另造公共机制。

当前共享费用API为prototype-v190/core-effects-v184/schema179，拒旧1～178。新增[本局实际法术法力费用](m3-player-spell-mana-costs.md)复用原物理出牌/付款，不改变本契约自身资格；精确CN仍待校准。
