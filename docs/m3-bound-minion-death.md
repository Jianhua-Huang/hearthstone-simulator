# 原随从的延迟死亡表达

回合开始或回合结束时消灭原随从，可以由已有 `GrantLimitedTrigger`、`LimitedTriggerSpec`、原附件身份及 `Destroy` 表达。真实的单次死亡用途使用有限次数规格；这个路径已提供具体的已消费附件和原施加来源，不需要为普通触发器的 `trigger=None` 分支增加新状态或计时器。

实际进度与下一项只在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md) 维护。本次表达的 [完整原始证据](../data/support/bound-minion-death-basics.json) 固定 `CS2_063`、`CS2_063e`、`EX1_316`、`EX1_316e` 全部行，PIN 为 `5196f99a86328c4fbc5978b3f118f579b8da464c741a43bf044696e5c03c8aed`。两个法术只接入隔离实验注册表，两个附魔只有原始证据。生产代表包、正式池与协议保持。

## 原施放者的开始边界

腐蚀术 `CS2_063` 是 1 费术士暗影法术，只能选择敌方随从。正文与附魔明确指向施放腐蚀术的玩家的回合开始。

实验行为向原目标安装一次 `turn_started` 有限触发。两个预注册的固定条件分别判断事件玩家为 1 或 2；效果按原施放者选择条件，原来源保存在附件的 `source_id`。没有可变闭包、每牌全局计数或新玩家时钟。

对手开始不消费该附件。原施放者的下一个真实开始触发；额外回合产生的实际开始有效，被跳过的调度槽不产生开始。目标在接受边界前转控时，固定条件仍指向原施放者，不能改成随从当前控制者的开始。

消费后的行为读取 `context.trigger.source_id`，执行 `Destroy(context.source_id, original_source_id)`。死亡走既有公共死亡检查与死因归属；法术已进入墓地不丢失来源实体或卡面。相同卡面的另一个随从不代替原目标。

## 当前回合的结束边界

力量的代价 `EX1_316` 是 1 费术士暗影法术，只能选择友方随从。实验完整行为先执行原 `Buff` 的 +4/+4，指定当前回合到期，再安装一次分类结束触发 `LimitedTriggerSpec(..., end_turn=EndTurnSpec('either'))`，附件同样在当前回合到期。

`either` 指当前自然结束事件，不把死亡改成随从转控后的控制者回合。结束主体执行时仍有增益，由明确的 `Destroy` 制造死亡；不能把之后的增益消失导致的属性变化当作这个法术的消灭原因。支付、施法历史和来源归属沿用原手动出牌流程。

这里验证的是普通手动出牌所需的独立基础。结束后安装、额外主动结束调用、复杂授予与全部施放来源必须按真实卡需求另行核对，本次没有扩展这些组合。

## 身份与生命周期

原 [有限次触发契约](m5-limited-triggers.md) 负责原载体、附件 ID、控制者与入场顺序的执行前守卫。目标早死、沉默、回手或变形后，原未消费附件失效；回手再打不会重新安装原授予。同一目标上的多个独立声明各有身份，实际死亡只发生一次，后续失效候选不消灭另一实体。

这些守卫也区分消费前与消费后：执行前失去原附件的候选不消费；已经消费并捕获的主体沿用已有保留窗口。主体中的普通效果继续使用其原目标检查，不增加自定义取消政策。精确转控、休眠、复制、消费后变形、嵌套来源与国服先后顺序仍需校准，不能从本次基本场景推导整个交互族已完成。

## 待选、回滚与玩家信息

安装后待选保存完整原出牌和附件来源；回合开始前的待选保留原未消费候选；消费事件反应引起的待选保留已消费状态、具体附件及原死亡主体。分类结束待选继续原结束根。独立注册表恢复、克隆与回放使用已有帧，不增加执行器。

后续异常复用原事务回滚。选择失败保留同一个待选状态和后续死亡，合法选择可继续一次。原来源和次数的单字段篡改不能通过既有捕获上下文一致性检查；整体一致的未签名存档仍没有来源认证。

玩家视图只显示已有有限触发的公开剩余次数，不显示附件 ID、条件/行为名称、原来源卡面、入场顺序或原候选队列。对手未知手牌保持不透明。查看观察、事件和合法动作不消费附件，也不推进回合。
