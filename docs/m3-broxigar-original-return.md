# 布洛克斯加：原实体消失与返回

真实来源为TIME_020、塞纳留斯之斧、四道阿古斯传送门和四个对应恶魔，共十张定义。完整原行和二十份双语官网响应固定在[数据包](../data/cards/broxigar-v1.json)。实际执行、验收和下一项仍只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)登记。

## 构筑和普通效果

官网奇闻成员只有第一道传送门和武器。主卡加两伴生与二十七张自选牌组成普通三十张完整套牌，不把四个恶魔加入套牌，也不另设容量规则。四道传送门原记录没有COST字段；完整官网面确认均为零费邪能法术，数据包保留原缺省值并显式登记数值归一化。

主卡原始开局钩子在发牌前调用共享移除操作，将同一物理卡移到SETASIDE，不死亡、不弃牌、不计入换牌候选。四道法术沿共享召唤为对手生成对应1/1、2/1、3/1、4/1恶魔。前三个亡语先令当前亡语玩家的对手实际抽一张，再洗入下一道传送门；后续抽牌、反应、选择及洗牌由原解释器处理。满场不会生成恶魔或虚构后续亡语。

武器保持3费3攻2耐久及吸血。完成的真实英雄攻击必须绑定原实际武器、原受击随从及其致死战斗伤害包，才从本人牌库抽取一道原物理传送门。非致死攻击、法术消灭和无匹配牌不奖励；最后一点耐久的攻击沿原捕获的攻击完成监听结算。

## 原卡托管

`DisappearOriginalCard`记录真实开局来源及移除前后完整物理分配事实。`ReappearOriginalCard`只接受正在执行的对应亡语身份，使用现有`MoveCard`将同一实体交给当前亡语控制者的对手，不生成另一张布洛克斯加。单次领取后再次复制或触发最终传送门，不复制、复活或拉回已返回的卡。满手仍沿共享容量管线烧毁该原卡，并消耗本次托管。

新增`SetAsideCardReference`仅供明确的非抽牌返回手牌。普通`CardReference`仍只接受手牌和牌库；普通查询、复制、移入牌库、抽牌和reset不因此开放SETASIDE。原所有者保持，实际接收者成为控制者；共享进手、溢出、观察和事务回滚保持。

完整私有消失、领取和交付收据进入可选快照承诺及状态哈希，恢复时重核原开局、完整候选、唯一交付和原亡语。回溯沿原有效事件前缀恢复托管，不把已放弃尝试的领取重复计入；原追加日志仍保留。监听进入待选时，物理交付已经原子完成，继续使用普通保存、clone和回放。玩家投影不开放这些收据或内部实体分配。

## 已知边界

[官方历史34.0.3热修讨论](https://us.forums.blizzard.com/en/hearthstone/t/3403-hotfix-patch/154571)说明复制/窃取最终传送门可以取得原卡，也记录冰霜陷阱及滑翔相关修复。[重复最终传送门的本人报告](https://us.forums.blizzard.com/en/hearthstone/t/copying-final-portal-to-argus/158689)支持原卡只返回一次；这些都不是当前国服完整校准。

本地`broxigar-single-original-v1`只在存在一个未领取原实体时执行返回，没有原托管时不生成奖励。双方都有尚未领取的原卡、或真实开局复制导致多个原身份时，当前明确报未支持来源选择，不能凭实体顺序或FIFO猜测。没有凭卡牌描述另造“四个不同恶魔死亡”计数器；实际普通链条自然抵达最终亡语，复制最终传送门仍沿已知单原卡规则。镜像选择、复制继承及精确国服窗口仍待M6。

内核605、快照499；观察114、命令12和回放schema1保持。十张定义接入不认证正式标准池、完整实际可达或当前国服规则闭合。
