# 攻击规则授予的原目标保护

飞行助翼 CATA_564 的实际战吼为原友方随从授予超级风怒和不能攻击英雄。朴素的“原引用关键词，再按裸 ID 加规则”已复现错误：关键词反应中原物理牌回手并重入后，关键词正常清除，后续规则却加到了新驻留。已有无穷永动机 TIME_043 的设值/临时规则组合也复现同样问题。

## 有限参数

`GrantAttackPolicy` 在末尾增加 `recipient: MinionReference | None = None`。它与原 `source_binding` 分开：后者约束授予来源，前者只在安装时约束原接收对象。不能把 `source_id` 改成目标来伪装来源保护。

有 recipient 时目标 ID 必须一致，引用须为已知、非未来的分配及随从定义。实际安装前沿现有 `live_minion` 核对原定义、控制者、区域驻留和入场身份；失效就跳过，不能附到同 ID 的后续驻留。保存/恢复通过原 FrameCodec 结构白名单与新增状态核对。默认 None 保留原英雄、武器和其他既有授予入口。

保护只属于请求，不写入永久能力。成功安装后继续使用原攻击规则、四次攻击预算、复制/沉默/重置、期限及来源归属。没有新规则执行器、效果或 payload 类型，没有新模型字段。可序列化参数变化采用 core387/schema310，旧 schema309 存档使用原引擎。

## 实际消费者

飞行助翼的两个效果捕获同一原 MinionReference，顺序为超级风怒后永久不能攻击英雄。原来源离场不撤回接收者的独立能力。普通手牌出牌使用付款前目标域，已在场的真实触发战吼不额外排除自身。当前定义、控制变更导致引用失效等细节沿既有契约，准确国服顺序和资格仍待 M6 校准。

TIME_043 改用已有 `SetCapturedMinionStats` 与带相同 recipient 的规则请求，保持原 8/8 设值和本回合到期；完整原定义和原数据 pin 保持。变更的是实际回调实现，不能把“原定义保持”误说成所有既有行为完全不变。

[固定包](../data/cards/captured-attack-grants-v1.json)保留新根完整原记录/两份中英文官网全脸，以及已有消费者完整原记录和定义摘要。[专项](../tests/test_captured_attack_grant_cards.py)覆盖实际付款、攻击预算/英雄禁止、普通与触发战吼、目标重入/变形、来源离场、两段失败回滚、复制/沉默/转控、保存恢复/clone/回放、坏引用与玩家合法动作。实际结果和下一项仅在 [项目状态](project-status.md)、[机制执行清单](mechanism-backlog.md) 维护；正式池、完整可达和国服校准独立验收。


## K490：真实原驻留来源与扩大交付

ETC_109吵吵歌迷复用GrantAttackPolicy及原AttackSourceBinding，不增加攻击规则或在卡牌回调中直接修改状态。目标声明采用IF_AVAILABLE；手牌没有合格随从可选时正常入场，有候选时必须选一个。已在场的真实间接战吼允许选自身。安装时原MinionReference保护接收对象，之后的限制绑定原物理来源的一段连续战场驻留；来源离场后同ID再进场不能复活旧链接。

来源沿既有AttackSourcePolicy(live,preserve,ignore)内部政策：存活检查与活动状态分开，转控、沉默、同驻留变形或休眠不改成另一来源；死亡和离场关闭链接。目标的沉默、变形、正常回手及当前/基础复制继续走普通附件生命周期。[官方26.0.3补丁记录](https://us.forums.blizzard.com/en/hearthstone/t/2603-patch-notes/106272)曾明确修复受影响目标变形后仍受影响的问题；这不证明国服37.0的全部来源沉默、变形、休眠与精确窗口政策，仍待M6校准。

MIS_307水宝宝鱼人、MIS_307t模塑鱼人宝宝和MIS_307t1大型形态使用完整独立原行及双语官网面，母面childIds与两个DBF身份对应。战吼以当前冻结上下文攻击和非负剩余生命生成SummonEntryMaterial，原SummonByCard负责归因、入场、数量及普通死亡；鱼人宝宝的突袭来自自身真实印刷定义，不复制母体的其他能力。扩大只声明原HandDerivativeSpec，沿原手牌出牌完成生成一张全新印刷8费8/8大型牌；母体附魔不传给该手牌，大型自身不再生成另一大型。满手、满场、重复主体、选择恢复与回滚继续委托原管线。当前属性/光环和生成精确窗口仍待国服校准。

本批只增加薄卡牌适配，没有公共内核、模型、schema或新效果变化；实际结果和下一项只在原两份台账维护。
