# 原角色攻击历史与阶段查询

`character_attacks(state, player_id, *, phase='completed', turn=None, forced=None, before_window_id=None)`及`character_attack_count`读取完整原角色攻击记录。默认查询整局已完成攻击；支持声明、战斗接受、完成、取消、终局中断五种明确阶段。全局回合和排他窗口ID须为正整数，player须为1或2，forced仅bool或None。返回冻结行元组，查询不读动作日志来猜次数、不推进随机或写当前实体缓存。

## 原窗口和归属

普通英雄/随从攻击和现有强制随从攻击，均复用原 `ActionWindow.id`及原解释器。新增一个 `GameState.character_attack_history`列表，没有新攻击ID分配器、伤害器、支付账户、动作或玩法事件。原手动英雄详细记录、武器损耗和当前攻击机会计数保持；新列表补齐全部角色的统一查询。

`CharacterAttackRecord`保存原声明窗口、原来源卡面/类型/物理epoch/入场顺序、原全局回合/实际区间/根动作和声明时钟，随后独立追加原窗口交付、实际战斗接受与终态。声明目标和最终交付目标分别保留，不能把改道目标倒填到原声明。

查询的玩家归属固定为原声明控制者，后来变形、控制转移、死亡、回手或英雄替换不重新归属。接受点另存实际攻击者/防御者控制者、卡面、原武器和时钟，以保留各阶段差异，不把这些点偷换成一个“攻击次数”。强制攻击是否贡献具体卡文、声明/接受/完成中的准确口径仍待CN校准。

原强制攻击仍只允许随从，不消耗手动攻击机会，存活和关系资格由既有流程决定。无有效配对或未实际打开窗口不造记录。被取消的攻击保留声明和取消，不能伪作完成；已进入战斗并完成交换的攻击只计一次，零伤害、圣盾或多个伤害包不增加攻击次数。原终局排队中断保留到达的阶段，不执行未完成战斗。

原裸随从 `CombatDamage`仍是兼容的直接战斗伤害操作，没有原窗口就不制造声明信用；裸英雄战斗沿旧契约拒绝。没有据此补专用组合或扩展强制英雄范围。

## 稳定边界、保存和信息

交付后的 `CombatDamage`及`CombatExchange`携带原 `attack_window_id`。英雄既有引用中的窗口ID可复用，两者并存时必须一致；外来、重复、关闭的引用不能冒充原攻击。原战斗状态/武器/死亡仍由公共执行器处理，记录不会改变这些结果。

原记录严格校验时间线、窗口顺序、卡牌类型、物理分配/epoch和阶段。稳定待选边界要求每个未完成声明或交付恰有一个原控制尾和对应窗口生命周期；不能裁掉、复制或塞入选项/嵌套效果。同步伤害处理中捕获的规则状态可保留实际接受事实，不被误当作稳定控制队列。

Game边界沿既有有效事件政策逐条核对全部原声明、原强制标记、动作时钟及终态事件，拒绝裁掉已完成记录。真正回溯沿原状态/有效时间线退役尝试，选择恢复、克隆、回放和失败回滚共享原解释器。原登记卡面在Game/快照边界查验；只读State查询沿已捕获类型和结构验证，不提供未签名存档外部来源认证。

JSON明确保存新列表、三种冻结类型和原窗口载体；typed-frame使用同一字段及类型。完整历史、时钟和控制引用不提供给玩家；原公开声明/伤害/完成事件域保持，因此观察84、命令12、replay1不变。

[CATA_568完整本地原行](../data/support/character-attack-history-basics.json)只提供整局友方角色攻击计费的需求证据。此增量补历史与查询前置，尚未注册穆拉丁的奋战或其费用消费者，也没有白板适配或生产代表扩张。

新State列表和控制载体字段改变保存结构，引入 `prototype-v294` / `core-effects-v293` / schema258，旧1～257需原引擎。准确CN阶段/来源/转换窗口、完整正式池及其他基础机制仍开放。实际验证与下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。
