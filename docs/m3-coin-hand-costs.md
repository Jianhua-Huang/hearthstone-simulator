# 手中幸运币筛选减费

真实来源是`JAIL_503`黑掌的链镖：3费3攻2耐久武器，手中每有一张幸运币便少一费，亡语抽一张牌。完整原行、两种已接幸运币依赖及六个严格双语官网主面保存在[固定来源](../data/cards/native-coin-hand-cost-v1.json)。实际验收与下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。

## 有限声明和分类

`CardDefinition.hand_count_cost`在原`HandCountCostSpec`之外接受`CoinHandCountCostSpec`。新声明只用于普通可从手牌使用的武器，保存非空、唯一、有序的完整卡面ID元组及固定`cost.coin-hand-count-v1`政策。它不能与其他固有费用公式叠用，不能据此放开任意类型、名称或文本表达式。旧声明、旧事实字段和随从/法术资格保持。

固定源有69条`COIN_CARD=1`记录，其中68条是SPELL身份，另一条`GAME_005e`是ENCHANTMENT证据。只有68条SPELL进入手中幸运币分类；不能按译名、获得法力效果或仅`GAME_005`来识别。68条分类不表示68条行为已实现。当前直接复用完整已登记的`GAME_005`和`JAIL_504t2`，任何其他未知实际手牌仍明确报错。原始包核对所有完整源行和包hash，排除的附魔原行仍保留。

## 纯报价与原付款

每次报价复用原`hand_count_costs.capture`，先遍历双方完整有序HAND，核对真实区域、控制方及已支持当前卡面。按payer当前手中属于固定分类的物理实体计数，每张减一费、最低零；其他区域、另一方幸运币和同名非分类牌不计。实体变形后的当前卡面决定下一次报价，不依赖原印刷名称。报价不安装附件、不写基础费用、不消费用途、实体ID或RNG。

物理与纯生成报价共享同一数量阶段。新生成武器不会额外产生幸运币，满手查询也不分配实体或绕过普通烧牌。数量阶段仍在原base之后、本地设值/附魔及外部减费之前。本人观察价格、合法操作、支付验证和实际付款都复用原管线；亡语直接调用普通`Draw`，武器攻击损耗、替换死亡、抽牌通知和选择继续由既有执行器负责。

`CoinHandCountCostFact`保留原spec、payer、分配上界、双方有序物理ID、subject、数量和金额，并记录每行完整原`CardReference`卡面/控制方/手牌驻留。两套目录必须一一对应，重算原分类数量及零下限。真实手牌收据要求原subject确实存在于本人手牌，完整付款证明从原付款前状态重新查询；不能删subject、改为同数量另一幸运币或借后来目录替换旧原料。

后来的合法弃牌、变形或同ID离手重入不改写旧价格，也不重复付款。紧凑历史校验使用冻结卡面并核对原分配前缀及非未来驻留；不会拿今天的卡面去否定原来合法的事实。它不认证未经签名存档的外部来源真实性。

## 保存与边界

新事实通过原`IntrinsicCostStageFact.hand_cards`的严格分支保存，不增加另一个费用字段。旧`HandCountCostSpec/Fact`和旧完整卡牌定义形状保持；新增两个model dataclass由原FrameCodec注册。schema366拒绝旧1～365，core449；旧快照及旧mechanics签名须原引擎。没有新GameState/Entity字段、Effect、对外命令或玩法事件。

完整两方卡面、subject、分配上界及付款证明只属于宿主私有状态。玩家只得到自己可见的价格和普通武器/抽牌事件，对手隐藏卡面与当前费用不因分类查询暴露。waiting恢复、独立reader、clone、回放及异常事务回滚均使用公共框架。

固定数据分类、当前卡面计数、层顺序、特殊复制与准确国服接受/通知窗属于本地内部政策，仍待M6。完整标准合法/生成池、全部实际可达幸运币来源、M0正式补丁/热修及阶段发布不由本卡认证。
