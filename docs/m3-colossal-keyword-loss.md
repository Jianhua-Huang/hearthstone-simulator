# 克洛玛图斯的原生关键词移除

真实来源为CATA_432及CATA_432t1～t4五个独立卡面，完整原始记录和十份严格双语官网主面固定在`data/cards/colossal-keyword-loss-v1.json`。主身体印刷具有嘲讽、吸血、扰魔、圣盾；四个2/3巨龙头各有一个对应关键词，亡语移除身体的相应关键词。主体并非依靠存活头颅的光环获得关键词，因此没有空间生成头颅、头颅被沉默或非死亡离场，都不会自动移除主体关键词。

官方[版本介绍](https://news.blizzard.com/en-us/article/24245219/deathwing-strikes-back-in-cataclysm-hearthstones-next-expansion)确认巨型和四头设计；官网主面确认四个不同childIds及各亡语。[原始实测帖](https://www.reddit.com/r/hearthstone/comments/1s21ez2/til_chromatus_will_have_permanent_taunt_if_you/)明确绿色嘲讽头最后召唤、三个已有随从时缺少该头。该观察没有证明其余三头的完整次序或多身体作用范围。

当前内部声明按铜、蓝、红、绿展开，前两左、后两右；绿头最后有上述原始观察，其余次序和落点属于待国服校准的本地政策，不能用官网childIds列表顺序冒充执行顺序。展开、占位、容量失败、身体离场取消、附肢独立生命周期和等待继续全部使用既有`colossal`模块，不新建巨型执行器或父子状态。

亡语内部政策选择当前执行玩家战场上存活、激活、当前卡面为CATA_432的全部身体；不按原所有者、印刷名称或最新同名身体查找，也不凭文案创建一条原父体绑定。实际亡语上下文决定玩家，移除目标在该次主体执行时捕获。多身体、控制变化、变形和精确接受窗仍需M6核实，该项是明确的内部实现政策，不能当作已校准规则。

## 最小公共能力

`sacrifice.RemoveCapturedKeyword(beneficiary, keyword, source_id)`仅接受这张真实卡需要的四个普通关键词。目标为既有`MinionReference`，执行时重核卡面、控制者、区域epoch及入场顺序；前一个目标的反应令后一个目标移区重入或易主时，旧请求失效，不追到新驻留。来源只需为原存在实体，头颅正常死亡不会使已经接受的亡语失效。

处理器复用`lifecycle.consume_keyword`，将当前印刷或授予的同一关键词附件标为已消费，再沿原刷新和通知路径。不会沉默目标、清除属性增益或删除其他关键词/战吼/亡语等附件；独立持续光环贡献继续由原光环层计算，后续实际授予仍可重新获得关键词。没有合格附件时是无效果，不产生移除通知。一次实际移除发出不含附件ID的`keyword_removed`事件。

移除状态沿既有附件保存；当前复制保留已移除状态，基础复制和回手后正常重置恢复印刷内容。专项发现带归因`CopyEntryMaterial.profile=board_copy`原被普通材料资格误拒，现仅允许这一原复制profile的巨型资格；存储复制/招募等其他profile仍走旧限制。原材料接受、数量、属性安装、附肢展开、通知及继续调用原复制和召唤执行器，没有另造复制路径。

普通恢复、异常回滚、回放、巨型待继续和玩家信息投影复用现有管线，没有新增Entity、PlayerState、GameState或保存布局字段，没有建立第二份历史账本。接口增量只增加有限Effect注册和内核语义版本。

逐批实际验证、当前身份和下一项仍仅在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。M0正式合法/生成池、M6精确国服规则、全部可达依赖和发布验收继续开放；不得由五个卡面数据、候选登记或内部通过宣称标准完整支持。
