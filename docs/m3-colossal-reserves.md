# 有限巨型余量与空位补充

熔喉`CATA_550`是7费2/12野兽/机械，巨型+99，并在有空位时继续召唤剩余肢节。六种肢节及随机友方随从+2攻击力的亡语已由原P50/P51适配；本体直接复用其完整定义，不重新注册或复制亡语。完整本体、六肢节和提示附魔在`data/cards/magmaw-v1.json`，十四个严格中英官方主面保留两段完整本体文字，只省略原始分隔符和运行时余量槽。

`ColossalReserveProfile`声明一个真实有限、右侧展开的原生巨型。完整99项仍在`CardDefinition.colossal`，普通巨型不受此profile影响。原生附件`colossal_reserve`只保存声明身份及`colossal_remaining`，初值为完整展开长度；没有新增GameState账户。每个成功物理肢节只扣一次，满场、取消及未接受的身体不扣余量。每个来源独立，转控后的补位使用当前控制者的容量及新肢节owner。

原巨型入口仍负责主体先占位、附肢召唤、主体通知、战吼与完整入场历史。本体的初始展开每次只排下一个附肢，满场即关闭这次入场，避免预排99个失败身体。原`ColossalRecord.attempted=99`表示这次初始展开窗口已处理完，成功实体仍逐项记录；未落地项不是成功召唤，也不消耗原生附件保存的余量。普通巨型满场失败的原行为保持。

后续补位是`RefillColossalAppendage`普通效果，捕获原物理驻留、附件ID和当时余量，执行时重核存活、活跃、沉默、控制者、原引用和真实容量。共用`colossal.create_appendage`创建物理随从、刷新光环及通知，不重放战吼，不构造替代死亡或第二份巨型历史。成功补位后由下一检查点重新判断容量；旧来源、过期引用和已消耗余量不追踪后来新周期。

当前补位等已有亡语执行完成后再检查空位。这与一份[上线后玩家实战记录](https://www.reddit.com/r/hearthstone/comments/1s12fy7/magmaw_hunter_from_plat_10_to_legend_and_no_star/)所述“清掉肢节后增益集中本体”一致；这是有限实现政策，不是开发者对当前国服37.0精确窗口的认证。初始附肢反应仍走原巨型流程。普通死亡、亡语、额外属性、恢复、支付、回滚和终局保留既有执行器。

2026-11-03修复：`FinishDeathrattleBatch`完成原整批接受证明后，显式调用原补位调度器。它是透明控制项，不产生普通效果检查点；一次攻击若以该控制项结束，过去会留下仍欠补位的空场位，release可导出无法通过严格恢复校验的存档。新续接仍等全部待执行亡语结束，并重核原死亡延迟、主体驻留、活跃/沉默、容量和已排补位；不新增完整检查点、不重放亡语、不修改旧存档或放松恢复校验。亡语填满场位、移除主体或结束游戏时沿原政策不补位。

沉默移除持续余量附件，既有独立肢节保留；原已接受的初始附肢不因沉默被裁掉。休眠暂停持续补位，唤醒后可继续；离场及变形离开本体不继续供给。新的巨型入场当前按完整99项重新建立余量，包括新召唤、基础复制、当前复制的有效巨型及变形进入；沉默后的当前复制没有巨型或持续余量。回手重建印刷状态。当前复制/恢复是否应保留旧余量、磁力材料、休眠及转控窗口仍需M6逐情形校准，不从内部通过推定官方一致。

六个等效果图像卡面当前按完整原行的`t,t2,…,t6`顺序循环，全部落在主体及其仍属当前来源的肢节右侧。原始记录没有执行顺序脚本；具体图像顺序和后续落点是明确保留的国服校准项。

原生余量重建和每次成功扣除有私有一致性收据，校验有序余量、真实物理交付及当前附件；等待中不得修改接受余量或裁掉仍欠的补位。它们不能认证未签名存档来源。玩家只能看到自己手牌及公开场上本体的`colossal_remaining`，看不到私有收据或对手手牌参数。
