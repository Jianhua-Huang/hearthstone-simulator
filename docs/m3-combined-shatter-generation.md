# 原生已重组创建与裂变生成

能量窃取CATA_202是3费潜行者暗影法术，从其他职业获得一张已重组的裂变卡。[完整来源包](../data/cards/combined-shatter-generation-v1.json)固定37.0原行、两完整官方卡面和已有五族定义摘要；原始数据中的五个SHATTER标记根是内容调查结果，不等于正式生成资格。实际进度、验证和下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。

## 格式池依赖

通用构筑生成统一使用`constructed.cards`池ID，目标版本和模式由宿主提供的`GenerationContext`定位。能量窃取使用既有`GenerateFromPool`和`PoolQuery`筛选可收藏法术、印刷SHATTER及其他当前英雄职业，不能按卡牌本身的潜行者职业筛选，也不按已实现卡动态拼池。

宿主须绑定与目标/模式匹配的`PoolDefinition`，正式格式要求完整资格声明。共享查询负责显式排除、特殊生成限制、生成身份去重及全部合资格内容校验；缺少可执行定义时抽样前报错，不能把它从池里删除。没有上下文或对应池时明确失败且事务回滚，不借用原型池或具名有限名单。宿主显式提供实验上下文时仍仅是实验；正式标准池仍属M0未完成工作，本批没有注册生产标准池，实验夹具不能证明标准模式生成已可用。

## 创建时机

`AddToHand.combined_shatter`与`GenerateFromPool.combined_shatter`是有限布尔创建声明，默认False，仅支持手牌交付。所有合资格候选都须为有原生ShatterSpec及印刷SHATTER的完整法术；错误载体、片段、非布尔值或其他区域声明明确拒绝。

沿原`create_hand_card`物化和创建附加流程，在第一次`card_created`和`card_added_to_hand`通知前消费原生印刷SHATTER能力。没有额外GameState/Entity标记，不制造裂变或实际合并事件。满手仍生成完整材料并沿原爆牌路径处理；原生当前复制保留消费，基础复制恢复印刷裂变。普通未声明的创建继续正常裂变。

后续支付、完整卡的两个主体、容量、费用、随机、创建归因、反应及玩家投影仍使用公共执行器。批次先冻结抽样，再按原顺序交付；空合资格池不消耗随机数，存在未知合资格成员时即使手牌已满也不抽样。延迟入手声明、观察者等待、克隆、恢复、回放及错误选择回滚使用原解释器与严格布尔解码。
