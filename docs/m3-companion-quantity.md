# 塔雅与动物伙伴的逻辑数量

MEND_304（塔雅·陆行）的完整原记录和严格中英文主面固定在`data/cards/native-companion-quantity-v1.json`。战吼通过普通`AddPlayerEffect`安装独立永久玩家实例，声明`ProducerQuantitySpec`的动物伙伴单位增加1；重复战吼分别叠加，来源死亡、沉默、回手或控制变更不移走原玩家的程序。创建或普通召唤塔雅不会自行执行战吼。

`fixed_companion_cards.companion_effects`是已有动物伙伴消费者的共同配方入口。动物伙伴、兽群呼唤、MEND_301与EDR_853保留原行为ID和完整物理定义，分别在实际主体接受时，用原`SummonCause`、实际来源种类和完整有序玩家程序清单调用既有`producer_amounts.decisions`。三个注册profile区分随机单体、原有序组与选择主体，共享同一逻辑单位，只接受卡牌来源或实际施法来源；英雄技能不借用此卡所述“卡牌”的数量。没有匹配贡献时，原请求、三伙伴顺序、选择ID、支付、随机策略和检查点保持。

本地执行政策：随机主体原先召唤1个，额外单位分别再随机召唤；兽群呼唤保留霍弗、雷欧克、米莎三个原顺序请求，随后召唤额外随机伙伴；选择主体保留一次原菜单和原选中伙伴，随后召唤额外随机伙伴。额外单位不重复施法、支付或战吼。主体一次报价并保留整条尾部，等待或前次入场反应中新加的程序不改变已报价数量，后来的新主体重新报价。

每个逻辑单位仍是普通`SummonByCard`请求。选择在该单位实际接受时发生，因此前一次入场反应可以消耗RNG、改变空位和当前召唤倍率；不提前抽完后续单位。现有满场不抽样、每个选中材料的普通召唤倍率、属性、光环、入场、死亡和容量执行器均保持。普通倍率可以复制该次已选择的伙伴；塔雅增加的独立逻辑单位仍分别选择，不能混为同一种倍率。

数量本身继续使用普通请求和完整选项配方，未增加状态或另一套解释器。未来伙伴的[家族扩展](m3-future-companion-families.md)另行保存私有修订，并接回同一数量入口。永久程序的公开显示复用原玩家效果投影；原物理来源、内部召唤记录、完整等待帧与RNG不交给玩家。数量声明自身的版本兼容性由构筑内容身份和注册表指纹处理，家族扩展的内核和快照结构由其独立契约规定。

官网[职业系列介绍](https://hearthstone.blizzard.com/en-us/news/24267730)说明伙伴随升级成长；卡面本身没有认证额外单位与选择、来源时钟和所有跨卡交互的精确国服窗口。上述额外随机策略、组内先后与报价窗口是待M6国服校准的本地政策，不冒充官方时序证据。正式标准池和所有实际可达来源另行验收；配方读取对应玩家的原三伙伴或已替换家族，不把其他尚未注册的来源静默当作已支持。
