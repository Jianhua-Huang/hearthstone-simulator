# 合成药水的原施法与相邻主体证明

这是电流导联K678之后的有限扩展，对应`hs_sim/engine/composed_spells.py`。
实际来源是艾雅暗金幸运币生成的一费药水，保留原模板JAIL_504t3p、九个真实成分、
两个不同成分的规范身份及原生成随机证明；不接入狂野卡扎库斯主卡或额外药水等级。
原资料见[一费药水契约](m3-kazakus-potion-forms.md)。

## 原进度的分区

药水仍只有一个物理CAST。原来每CAST只允许一组两个成分及一个完成事件，
在电流导联额外执行整张药水时，会把新主体误判为重复原成分。
现在`ResolveComposedSpell`增加可空的`body_index`，明确区分原主体与实际相邻主体。
空值仍表示原物理主体，原STEP/END事件形状保持；相邻主体保存原下一法术主体槽号，
事件仅对这一类加入私有`spell_body_index`。

每个实际主体分别执行原两个有序成分并结束，不能借另一主体的成分、完成或后续游标。
所有成分/完成事件必须落在自己原主体的接受/完成窗口中；原主体还必须早于第一个
额外主体开始。即使交换两个已完成主体的所有成分标签并重算外部哈希，也不能通过恢复。
该证明是内部一致性约束，不提供未签名存档的外部来源认证。

## 公共执行与恢复

原配方、生成候选、抽样、复制、实体交付和玩家可见配方保持不变。
`begin`从真实CAST及其当前相邻槽构造续接；当前成分用`body_target_id`取得自己的箭头，
原CAST历史继续保留原主箭头，不伪造额外支付、物理出牌或组件CAST。
伤害、法伤、护甲、召唤、复活、冻结、抽牌、属性和随机恶魔生成继续调用原公共效果。
失效相邻目标仍沿原目标合法性门禁，整项不执行，不能只保留护甲或召唤部分。

FrameCodec和Game恢复分别校验原未完成CAST、当前相邻槽、完整成分组和唯一后续请求。
主主体、左右额外主体或成分中的自动抽到时施法均可正式等待；父药水的续接可以排在
尚未完成的真实子CAST后面，但实际执行时不能越过它。
选择异常继续沿原事务回滚状态、程序消费、成分历史、队列和RNG。
终局保留原中断政策，不把未开始成分伪造为完成。

本扩展不增加GameState账户、静态卡面、Effect或载荷类型；只扩展既有续接的可空字段。
core825/schema645拒绝旧1～644。原112玩家程序、4下一法术profile及完整九成分声明保持。
实际运行结果只在两份原台账登记，不能以这里的实现说明代替验收证据。
