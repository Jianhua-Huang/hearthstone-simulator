# 私藏野兽侧板

真实来源为JAIL_831下水道之王，完整原行、原子集标签和严格双语主面在[固定卡牌包](../data/cards/contraband-sideboard-v1.json)。实际验收与下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。

`ContrabandSideboardProfile(source_card_id)`是`sideboards.py`中的有限静态政策，仅接受三个成员、减费3及`contraband-sideboard-v1`版本。原`SideboardProfile`乐队与`DeckCopySideboardProfile`构筑选择保持各自字段和政策；新声明进入已有注册表指纹，不新增玩家、实体、快照、请求或命令字段。

## 原构筑和资格

原始主牌组另附`SideboardSpec(ROOT, (card1, card2, card3))`。原始主牌组包含下水道之王时，必须配置恰好三个已实现、可收藏、符合宿主格式名单及禁限的印刷野兽随从。当前有限子集政策接受属于一个其他职业的野兽，包括有完整“全部种族”印刷元数据的随从；排除中立、猎人及多职业卡。保留原始`ALLOWED_SIDEBOARD_SUBSET=19499`和`SIDEBOARD_IGNORES_CLASS_RULE=1`，不将标签值推测成另一份可执行卡池。

只有这些私藏侧板条目免于原主职业和符文配额检查。死亡骑士野兽因此可以作为私藏成员，而不改变猎人的职业或要求猎人配置死亡骑士符文。同一卡若同时出现在主牌组、普通乐队或构筑复制选择，普通出现位置仍执行原职业/符文检查。全部位置继续共享原格式、收藏资格、数量、传说限制及`deck_identity`副本核算；私藏许可不能授权外国卡进入主牌组，也不能绕过普通侧板限制。未知定义、未知必要职业/种族元数据和不合格成员明确报错。

原始成员只是已有`SideboardState.cards`中的卡牌定义，不是活实体，不加入主牌库或原始构筑事实；消费仍用已有`taken_slots`。本局内生成下水道之王不会伪造原始侧板；没有自己的原侧板时，战吼不提供候选。普通召唤不执行战吼。

## 发现和交付

战吼调用原`DiscoverSideboard`，按本人原侧板剩余槽顺序展示全部候选，不洗牌、不补足候选，不额外消耗随机；相同卡面仍为独立原槽。私藏政策使用`ChoicePurpose.CARD_DISCOVERY`，保留完整原有序菜单、原提供配方和真实选择收据。

已有`_TakeSideboardCard`只增加有限的发现配方适配：核原选择槽，消费原槽，再以`AddToHand(cost=CostSpec(delta=-3))`沿普通创建入口分配新实体。附加费用在获取通知前安装；正常报价、支付、烧牌、回手及附魔生命周期继续由公共模块负责。原提供材料声明为印刷基础牌，原选择配方仍保留侧板槽身份。完整交付和`card_discovered`发布由既有发现交付流程处理，不用普通菜单冒充真实发现，也不另写加手牌执行器。

消费先于普通获取检查点。满手仍消费原槽并沿普通烧牌；重复战吼共用原玩家已消费记录，耗尽后无待选。普通乐队保留其原选择性质和交付，不因新增私藏政策改写旧效果。实际等待、独立注册表恢复、回滚、回放和玩家投影复用原解释器。原侧板、内部槽历史、提供配方及存档不能发送给玩家，只有发现者看见当前候选。

## 证据边界

[官方卡面](https://hearthstone.blizzard.com/en-us/cards/125998/)支持构筑选择三张私藏野兽、战吼发现与减3费。[多职业野兽的原玩家报告](https://us.forums.blizzard.com/en/hearthstone/t/king-of-the-underbelly-does-not-allow-dual-class-beasts/163146)记录了非猎人多职业野兽同样不可选；[缺少一个成员的原玩家报告](https://us.forums.blizzard.com/en/hearthstone/t/soft-locked-brawl/162631)记录了不足三个成员的构筑拒绝。两者均不是国服官方裁定。

恰好三个成员、允许重复的具体规则、单职业子集、按印刷来源职业判断、外国符文豁免、原槽消费及精确发现/获取/减费窗口均为明确的本地政策，仍待固定国服37.0的M6校准。实验合法名单的内部验证不能认证完整正式标准池或全部可达结果；不能将旧乐队内部测试直接提升为这些国服语义的证据。
