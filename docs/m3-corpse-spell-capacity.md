# 原法术残骸分支与实际召唤容量

本契约说明END_005旧时回响对既有支付与召唤的有限复用。实际进度、验证结果和下一项仍仅在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)记录；完整原行和双语官网主卡面保存在[卡牌包](../data/cards/native-corpse-spell-summon-v1.json)。

旧时回响为5费死亡骑士/恶魔猎手暗影流放法术。原始MULTIPLE_CLASSES=8193与两份完整官网multiClassIds=[1,14]独立一致。正文先随机召唤印刷4费随从，再以4份残骸支付一次额外召唤；原接受流放激活时，另追加一次独立召唤，不依赖残骸分支能否付款。

## 使用原支付和原召唤

卡牌仅组合原SummonFromPool与SpendResource。每个请求保留同一真实SpellCast的SummonCause；每次实际召唤都沿完整格式资格、原权重与生成身份去重查询，未知合格内容在RNG前明确失败，不能按已实现定义裁池。多个请求顺序执行，前一次入场与其反应结束后才接受下一次。

SpendResource新增默认false的requires_board_space字段。true仅允许正数残骸、普通非required分支、无失败分支，以及唯一带原法术归因的普通可收藏随从池召唤；玩家、来源和归因必须相符，不接受入场授予、休眠或位置改写等额外形状。它不是另一支付器：实际执行时检查既有Ruleset.max_board及当前物理占位，通过后继续原完整余额判断、全额扣除、CorpseSpendRecord和通知。

首次召唤可能产生新死亡、新残骸或占满面板，不能在出牌时冻结未来余额/空位。休眠对象占用实际位置；容量读取当前规则而非硬编码7。门禁没有空位时跳过扣款。实际扣除后，资源反应仍可改变面板，后续召唤沿原容量政策处理，已发生的支出不因后来没空位而退款。原fixed支出保持原无显式source_id格式，不伪造新的操作来源记录。

普通流放只支付一次法力；共享额外施法仍各有真实施法记录，每根分别检查当时残骸。额外召唤数量沿原SummonQuantity计划，不增加残骸扣款次数。自动施法不伪造手牌边缘激活。

## 保存与范围

原FrameCodec保存新增布尔及完整成功分支，恢复时核原召唤归因与实际施法，拒绝未知/未来施法引用；默认false的其他资源调用保留原行为。无新Effect类、载荷类型、模型状态、实体、能力或账本字段；core421/schema340拒绝旧快照，玩家观察89/命令12/replay1保持，私有分支不进入玩家投影。

本契约不提供未签名存档的来源认证。召唤、残骸支出、资源反应及额外流放的精确国服窗口是明确本地执行政策，待M6校准；内部小完整池不认证正式标准生成池。M0正式版本/热修/合法池、M6及完整可达内容继续独立验收。
