# 原随从残骸门禁、召唤对象与真实选择

本契约说明战场通灵师、空角恐角龙、尸魔花和沃尔科罗斯的有限表达。实际进度、证据、差异与下一项仅在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)登记，四根及三个真实选项保留在[完整原始包](../data/cards/corpse-trigger-choice-v1.json)。

## 原来源的实际付款窗口

`SpendCorpsesForMinion` 保存原 `MinionReference`、完整阈值、不可变成功分支，以及四种有限门禁：原来源、实际空位、尚无复生、原成功召唤对象。它不创建另一资源账户或支付记录，门禁通过后仍返回既有 `SpendResource`，使用原全额成功/不足分支。原固定支出记录沿旧契约没有显式来源，不伪造成 `ResourceConsumptionResult`。

门禁在真正执行时核原活跃存活来源：先前捕获的回调快照不能让已离场、转控、变形或重新入场的对象继续从旧控制者扣款。已经开始后的沉默不追溯抹除已捕获的工作；真正后续事件不再捕获被移除的触发。支付期间来源或目标再发生变化，沿该成功分支的既有引用政策处理，不退回已发生的支出。来源严格匹配与资源通知/奖励次序仍是待国服校准的本地政策。

战场通灵师使用 `TriggerSpec('turn_ended', ..., EndTurnSpec())`，属于原生本人结束主体，可被已有结束机制识别。实际没空位不消耗一份残骸；有余额和空位时原归因请求生成已有 `RLK_061t`，数量额外交付不额外消费。已接受付款后的来源离场不撤销该独立召唤。

空角恐角龙只消费真实其他友方随从的死亡记录，包含该次死亡先入账的残骸。三份全额扣除前重新检查原来源是否已有复生，因此同批先前接受的其他死亡回调不会凭陈旧无复生状态继续付款。授予使用既有严格原来源引用；其死亡与公共复生新体、原生突袭和双种族均走原内核。资源扣除反应中嵌套新死亡的精确先后与关键词状态窗口仍待 M6，不增加猜测的反重入锁。

## 原对手成功召唤对象

尸魔花从原 `minion_summoned` 的事件序号、实体和玩家精确连接 `SuccessfulSummonRecord`。全额两份付款前核原活跃来源和原目标的连续战场驻留；已经死亡或离开的对象不引起该次扣除。

支付后 `DamageSummonedMinion` 沿原成功入场驻留守卫重解同一对象，以 `MINION_ABILITY` 对其造成三点伤害，法伤不额外增加。控制变化或同驻留变形仍跟随；回手再入场不取得旧伤害，后来新召唤有自己的真实事件和独立触发。不能把原伤害不重绑错误理解为禁止新入场触发。来源已在付款后离场仍可执行已接受的独立伤害，后续实际归属/吸血等特殊窗口按原健康层及 M6 政策处理。

多个尸魔花按既有来源顺序分别接受。前一个伤害已杀死目标时后一个不付款；若圣盾只挡掉伤害，目标仍存活，后一个可继续付款造成伤害。这是原健康/死亡检查点与真实目标门禁的结果，不另造伤害处理器。

## 沃尔科罗斯与三个真实选项

官网明确关联的 `FIR_951t2/t3/t4` 分别表达10/20/30残骸和对应+10/+10、+20/+20、+30/+30。它们登记为非物理 `choice_only` 描述，不能从手牌单独使用、不进普通生成池，也不伪造一次法术施放。隐藏费用缺失按官网明确零成本展示处理，保留完整原行，没有捏造更多选项或白板效果。

战吼按原接受局面只提供当前付得起的真实选项，没有可选项则跳过主体。选项、阈值、受益玩家和原来源引用固定在既有 `RequestChoice` 分支中；真正选择后仍重新核原来源和当前完整余额，不能部分支付、改选更小数量或重绑同名物。成功分支用原属性执行器给同一原随从增加对应双属性。原生重复战吼每次重新接受当时余额和可用选项。

可付选项呈现、无选项/单选项窗口、源生命周期、选择后余额变化、资源反应及奖励次序属于明确本地执行政策，等待国服对应证据，不以卡面全文代替时序校准。
