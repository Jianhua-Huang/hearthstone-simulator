# 真实具名生成法术的局部法伤材料

星体平衡 EDR_874 的两份中英文官方关联均为 childIds `[467,823]`，对应原版月火术 CS2_008 和星火术 EX1_173。完整原记录及六份官方完整卡面见 [固定包](../data/cards/created-spell-bonus-v1.json)。原版与已有 Core_CS2_008 身份分别保留，没有用核心版替换或删除必要跨系列内容。原月火术缺省 COST 的完整记录保持不变，可执行费用按官方卡面明确为 0。

## 有限公共表达

`AddToHand` 末尾增加 `spell_damage: int = 0`。正数要求真实原来源，只接受 SPELL 载体，布尔值、负数、缺失或不存在来源均拒绝。0 保留旧行为；没有扩展其他生成入口或增加状态字段、计数器、效果类型。

在普通创建分配完成后、首个 `card_created` 与入手事件前，公共创建安装阶段调用既有物理法术模块的 `attach_local_bonus`。普通 `GrantStoredSpellDamage` 也调用同一安装函数，但保留原 CardReference 与 HAND/DECK 检查。新函数安装原同一种局部能力，原身份、来源及附件 ID 仍进入普通 CAST 材料；不能变成玩家全局法伤。满手时真实分配的爆牌实体同样带完整创建材料，不会执行爆牌的正文。

星体平衡依次发出两次普通 `AddToHand`，各有固定 +1。父法术的局部或全局法伤不会扩大这份固定生成奖励。实际月火术、星火术沿原 SPELL 伤害管线各取得自己的 +1；星火术的后续抽牌走原抽牌和终局检查。

这是沿用既有 R-134 创建材料在首次获得事件前安装的内部政策。卡面证明身份、正文和数值，不能证明国服服务器获得/奖励事件的精确窗口；这项窗口及爆牌政策继续保留 M6 校准。

## 恢复与验证范围

可序列化请求的新参数使用 core385/schema308，旧 schema307 存档使用原引擎。原模型字段与白名单类型清单保持；待选帧中的参数、来源和载体通过原严格结构校验及创建边界核对。实际等待、失败回滚、克隆、独立注册表恢复及回放仍共用原事务与解释器。

[真实专项](../tests/test_created_spell_bonus_cards.py)核对两张原版身份、支付、实际伤害与抽牌、同名旧牌隔离、获得时完整材料、满手爆牌、第一张创建后暂停、延迟创建、普通默认值、坏载体/来源/类型、父法伤隔离、当前复制、后续失败回滚和重算哈希后的坏帧拒绝。准确结果和下一项只在 [项目状态](project-status.md)、[机制执行清单](mechanism-backlog.md) 维护。原存储消费者见 [契约](m3-stored-spell-bonus-consumers.md)，正式标准池、完整生成可达性与国服校准继续独立验收。
