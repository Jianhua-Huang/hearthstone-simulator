# 当前牌库数量条件费用

本契约扩展既有 `IntrinsicCostSpec`，使用原 intrinsic-before-local 定价阶段、支付、资源和回放管线。实际验收与下一项仅在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md) 维护。

```python
IntrinsicCostSpec(
    delta=-2,
    condition='current_deck_count',
    history_profile_id='deck.current-count-v1',
    card_count=25,
    comparison='at_least',
)
```

既有字段名 `history_profile_id` 在此承载明确的条件 profile，不表示读取回合历史。原六字段保留，新添 `card_count/comparison` 两个可选字段；三种旧历史条件必须将它们保持为 `None`。新条件要求非负严格整数和 `at_most`（≤）或 `at_least`（≥），两个比较均含等号。当前来源仅支持一个物理法术的固定减费，`delta<=0`、`set_to=None`、`minimum=0`；多个条件、其他 intrinsic 数量公式和未审查载体拒绝，不隐式扩展到其他牌型。

查询复用 [当前牌库数量条件](m3-current-deck-count.md)，读取实际付款方当前全部 DECK 槽位，所有牌型与重复均计数。完整报价捕获还会检查每个物理实体的区域、控制者及已知定义；职业等无关元信息不参与计数。原构筑容量、起始事实与其他区域不代替当前剩余数量。无玩家计数器或实体减费缓存，新的报价随抽牌、洗入和移除重新求值。

减费在原 intrinsic 阶段执行，再由原本地附魔、外部来源、手牌最低费用和支付账户处理。原法力或生命等资源管线只支付已接受的金额一次。复制和转移不会携带一次计算出的折扣，新实体或实际新付款方重新读取自己的牌库。

原 `IntrinsicCostStageFact` 字段保持，既有 `condition_facts` 保存冻结的 `CurrentDeckCountMatch`：实际玩家、turn/action、实体分配游标、完整有序物理 DECK、阈值、比较符和布尔结果，共八字段。严格检查重复 ID、未来 ID、错误玩家/时钟、未知比较和错误聚合；条件与原定义、报价窗口一致。

原宿主临时 `CostQuote` 和实际 `CostUseReceipt` 各添一个 `current_deck` 可选字段。原三历史条件与普通报价保持 `None`，当前牌库条件完整传入已有支付记录。已提交报价与实际支付记录的完整条件须相等，不能只比较金额；删减后仍满足阈值的单处输入改动也拒绝。该字段是既有支付收据的依据，不是新资源、效果、事件或计数器。

原窗口验证会重新捕获完整清单并逐字段比对。结算后的保留检查允许原实体合法迁移、牌库变化及新实体分配，不拿今天的区域重算过去的金额。已支付后的待选、恢复、clone、回放及异常回滚由原管线处理。收据一致性检查不提供未签名存档的来源认证；不能把同时伪造完整来源和所有证明的内容当作可信官方证据。

存档采用 schema217，旧1～216需要其原引擎；核心与规则身份分别为 core-effects-v240/prototype-v246。观察75、命令11及replay1保持。玩家投影仅提供允许看到的价格与操作，完整条件、物理牌库清单、全知状态和快照仍属宿主私有数据。

[完整本地 JAIL_307 raw](../data/support/current-deck-count-cost-basics.json) 提供真实来源。必要完整实验适配仅在测试注册表：5费战士火焰法术，牌库至少25张时少2费；两次各自查询当时双方存活活动随从，以原 SPELL 伤害批次执行2点伤害，原死亡检查点与法术伤害机制复用。JAIL_311 的持续自身攻击属于独立后续能力，不由费用条件提供。
