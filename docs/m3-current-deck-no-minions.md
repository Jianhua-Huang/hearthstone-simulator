# 当前牌库没有随从牌

`DeckCondition('current', 'no_minions')` 是原牌库声明的有限类型条件。纯查询仍用 `matches_deck_condition`，分支仍用原 `CheckDeckCondition`、typed 帧和解释器，无新类型判断执行器。

## 事实与范围

读取指定玩家此刻牌库中每个物理实体的当前卡面，并以已知 `CardDefinition.kind` 和原 `PoolQuery(kinds=(CardType.MINION,))` 判断。存在任何随从则为假；空牌库为真。无随从不等于全为法术：已知武器、地标等非随从也符合。职业、中立身份、收藏状态、种族和构筑重复身份不决定牌型。

该查询只要求已知牌型；职业等无关元信息缺失，不会使已知随从或非随从无法判断。未知卡牌定义仍明确报错，完整列表全部查验之后聚合，不能因先发现一个随从而静默跳过后续未知定义。原无重复、无中立谓词保留各自的完整元信息要求，不沿用这里的豁免。

手牌、战场、墓地和原开局卡组不参与 current 条件。抽走或销毁最后一个随从会改变新查询；洗入随从也会改变。普通牌库随从换成另一随从仍为随从，按原换面契约保留物理身份，不开放随从到法术的额外变形。查询不消费 RNG、资源，不推进动作、历史或事件。

该 profile 只开放 current。starting 的 no_minions 或其他未审核谓词明确拒绝；不能由 Scenario 或当前剩余牌库推断起始牌库。原字段仍只有 scope/predicate，原无重复/起始范围见 [旧接口](m5-deck-conditions.md)，无中立范围见 [独立职业条件](m3-current-deck-no-neutral.md)。

## 分支及必要代表

原 `CheckDeckCondition` 在轮到执行时检查一次，选中后的效果 tuple 不随之后的牌库变化反向改选；以后新的检查读取新局面。原待选恢复、克隆、回放、操作/选择失败回滚和私有信息边界保持。未知 scope/predicate、缺失/多余字段和非法玩家按原严格解码拒绝。

必要代表只有 RLK_211「魔鬼交易」和精确关联的 RLK_211t「邪能邪犬」。完整原行为：5 费恶魔猎手稀有**邪能**法术，先召唤两个 3/3 吸血恶魔，如果当前牌库没有随从，再召唤两个。每个单位使用原单次 `Summon`；先两次，随后一个条件分支内最多再两次。付款、施法、检查点、成功/满场失败和独立实体分配均沿原管线，未新建批次、数量公式或召唤执行器。

原 SPELL_SCHOOL 标签 7 对应现有审阅映射的 FEL；上批前审文字曾误称 SHADOW，当时没有可执行适配。旧 raw 与历史证据保留，这里的完整适配明确使用 FEL。Token 是原 3 费 3/3、非收藏、恶魔及印刷吸血，不能当作白板或另造身材/授予。

完整 raw/PIN 位于 `data/support/current-deck-no-minions-basics.json`，适配只在隔离测试注册表，未扩大生产代表或正式卡池。玩家可以观察正常出牌结果，但不会获得私有条件对象和完整牌库。
