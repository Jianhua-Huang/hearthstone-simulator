# 构筑黑暗之赐：十种效果与公共接口

从本人牌库发现并授予黑暗之赐须保留原实体和当前材料，不能套用生成副本。有限原牌发现、共享配对、原授予/区域交付及恢复边界见[契约](m3-stored-dark-gift-discovery.md)；这不认证外部随从生成池。

范围依据[国服资料片公告](https://hs.blizzard.cn/news/24179067/)的十种结果和[32.2资格调整](https://hs.blizzard.cn/news/24198086/)。实际验收、差异和下一项维护在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)。十种赐福库存完整，不代表随从发现池或国服时序已经完成M0/M6认证。

## 发现与授予

原`DiscoverFromPool(gift_pool=...)`负责三张不同随从、三个不同赐福的资格绑定、冻结预览、实际选择收据和原子交付。关键词赐福排除已经具有其中任一关键词的候选；粗暴唤醒要求印刷战吼。未知随从定义不能从池中静默删除，没有可行绑定或未知内容时明确失败并回滚。

`CreatedMinionGrant.special`仅接受`living_nightmare`和`rude_awakening`。两者在首次创建/入手/烧牌事件前安装原on_play附件或原self战吼重复附件，没有任意效果程序。普通属性、关键词与生命周期继续复用已有模块。

来源牌的普通减费可以与赐福减费共同进入局部预览和实际创建费用。例如火化减费2加短小利爪减费2，费用最低为0。绝对设费、替代支付及多次发现形状不在此入口中猜测。预览不是包含后续光环的最终支付报价。

`GrantDarkGift(CardReference, gift_id, source_id)`对已有手牌或牌库随从按当前材料检查资格，原子安装同一配方，不创建新实体。它只授予，不抽牌或迁移；实际源牌负责发现、交付与支付。私有`dark_gift_granted`事实不向普通玩家输出实体或来源ID。

## 主体、恢复与玩家边界

活体梦魇复用带`SummonCause`的复制召唤，不再运行战吼或付款。休眠来源可产生复制，冻结`dormant_entry`保留新本体的印刷休眠进入规则和独立时钟；默认复制的活体资格不变。依据见[32.0.2官方热修](https://us.forums.blizzard.com/en/hearthstone/t/3202-hotfix-patch/143615)及[33.2国服战吼修复](https://hs.blizzard.cn/news/24223019/)。精确服务端窗口仍待M6。

粗暴唤醒使用原战吼接受窗口、完整主体和原目标。每次额外战吼复用原选择/恢复/回放及死亡检查点，整次出牌支付一次。与已有重复来源继续取max，不能擅自相乘。

当前复制保留赐福并重新分配附件ID，基础复制清除授予；沉默、普通回手和满血保附魔复生沿原生命周期。玩家仅对可见的己方手牌/公开场上获取`dark_gifts`的ID和名称，不获取来源、附件ID、完整绑定、私有收据或对方手牌新修改。

## 接卡和版本

代表库接入疯狂生物、火化和三个必要普通随从，复用破碎残阳祭司验证战吼资格。代表随从池只有四个明确成员，experimental模式且`complete=False`，不是国服标准/狂野完整发现池。其他来源的条件、残骸、未选结果、原牌发现和特殊消费者继续按M7真实接卡；本批不批量实现这些源牌。

当前：core-effects-v306、快照schema266（拒旧1～265）、player-view-v85、代表包v65/311定义。规则常量prototype-v302、命令player-actions-v12、回放schema1保持。原M0基线和历史证据不重写；等概率可行赐福排列为本地抽样政策，未取得服务端分布认证。
