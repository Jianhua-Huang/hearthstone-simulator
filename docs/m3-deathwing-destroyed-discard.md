# 灭世巨龙死亡之翼的实际摧毁数量与弃牌

[完整固定数据](../data/cards/deathwing-destroyed-discard-v1.json)保存CS3_036原行及LEG_CS3_036证据行，八项完整正文/类型/身材/费用字段相同。两个直接原DBF官网请求均零匹配，完整响应及摘要保留；官网目录中的两份双语LEG主面明确以copyOfCardId关联原DBF66872。主面按自己的真实身份核对，不伪造成原ID主面，也不把证据身份另注册为可执行替身。固定原物理ID及其卡组身份仍是CS3_036，正式版本对齐保持暂缓。

它与NEW1_030死亡之翼分别保留：前者是每实际摧毁一个随从弃一张，后者是弃整个手牌。不能按相似卡名复用后者主体，也不能把摧毁尝试数、场上原数量或全部新增死亡数直接当弃牌数。

新有限DestroyMinionsForDiscard由真实battlecry_id、原source_id和player_id接受。原战吼历史核对来源与玩家、payload_started及失败状态，使原玩家不依赖来源后来归谁控制。原始请求的victims=None表示尚未执行选择；执行时用原MinionScope/物理引用查询捕获双方当前活动、正生命、非待消灭的普通随从，排除来源实体和非普通interactable。休眠和地标不加入。接受后在原请求中保存完整具体引用组，不能以None冒充已接受的完成材料。

具体组沿既有DestroyBatch同窗标记，保留原死亡起点及实际DeathCause，继续共用CompleteDestroyedResources、original_causes和原死亡/亡语/反应协调。逐原身体核来源、目标、控制方、卡面、区域epoch及入场身份；完成时只计属于原接受原因的实际死亡，或既有deferred-doom政策下的原已接受标记。护盾/免疫不把摧毁变成伤害，后来旁支死亡、复生新体、亡语召唤物及来源自己后续死亡不增加原组数量。

该数量最终交给一个原DiscardMatching(count=N)，重新读取原玩家届时手牌。先前亡语抽到或获得的牌可以被弃；空手、逐次随机/反应、弃牌记录、私有边界和终局中断均沿原区域机制。来源已经死去也不删除原玩家的已接受弃牌。没有新的死亡检查点、私有死亡计数或另一套随机弃牌器。

原DestroyMinionsForResources保持仅其他友方随从、原Draw(N)与RefreshMana(N)的用途；新增请求只共享物理验证、摧毁和数量连接，完成时按有限类型分流到弃牌。旧外部声明和原保存材料不因此变成任意奖励DSL。新effect纳入原FrameCodec状态核验；旧schema和旧核心明确拒绝，不自动补字段。core742/schema592，观察117、命令13、replay1保持；GameState、Entity及Player结构没有新字段。
