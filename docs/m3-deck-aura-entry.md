# 原牌库光环直接入场

明日巨匠格尔宾 `TIME_009` 的战吼捕获原牌库中每种光环的一张实体，由公共 `PutStoredAura` 安装原玩家程序。它使用原物理卡，跳过手牌、抽牌、支付和施法流程；没有制造一次CAST来借用安装效果。

## 来源和边界

[数据包](../data/cards/gelbin-deck-aura-v1.json)保留37.0.0.255026的18条完整记录：主卡、16种原始PALADIN_AURA卡面及必要附魔记录。主卡完整双语官网响应复用既有缓存，经当前源行、完整响应指纹和卡面再次核对；两个childIds与侏儒光环、梅卡托克的光环严格对应。相关响应和原始记录见[准备收据](../outputs/card-integration-20261014/k256-gelbin-deck-auras/prepared-03/source-review.json)。16种标记清单用于识别实际牌库中的原牌，不等于16张均为标准合法或均已实现；未知合格主体明确报错。

[34.0.1热修公告](https://us.forums.blizzard.com/en/hearthstone/t/3401-hotfix-patch/153872)明确修复已有光环在场时格尔宾不能正常拉取光环的问题。本实现只按原牌库内身份去重，不按场上已有光环排除。完整原公告及指纹已保存。原牌库顺序、同名第一张物理牌、容量不足时保留未入场原牌、陈旧引用不替换，以及精确安装窗口仍是本地政策，待M6国服校准。

## 共享执行

卡牌回调只做纯候选查询，捕获每个身份的原CardReference并组合公共请求。已经捕获的引用不会因前一次安装反应移动了牌而绑定到另一张同名牌；后一次真实战吼按新局面重新查询。

`PutStoredAura` 验证原DECK驻留、受益者、来源和原生光环定义，再检查既有定时效果及混合区域容量。满区不移动、不消耗、不揭示隐藏原牌；有效原牌经普通移区进入墓地，随后由原AddPlayerEffect安装。程序先原子绑定，再发布既有安装事件，反应完成后处理下一个原请求。源随从后续离场、沉默或转控不影响已安装的程序。

原物理法术的额外时长通过完整 `aura_duration_grants` 保存到玩家实例，与 `aura_duration_cast_id` 两种证明互斥。直接安装时核对实际原载体附件，私人 `aura_duration_direct_bound` 事件绑定安装事件、实例和完整附件材料；原始CAST时长收据继续保持原语义。持续期上界统一交给原aura_duration模块，捕获、普通时钟、到期、移除和回滚共用原程序执行器。

这条路径也保留实际动态光环的原材料索引。需要材料却没有材料的光环明确拒绝；不会把乌索尔光环或未实现光环当作白板。

## 构筑、保存与观察

格尔宾注册原FabledSpec，两个已实现伴生光环复用原定义。完整主卡与两伴生牌占30张原始构筑中的三个物理名额，普通构筑资格与换牌流程不变；该名额政策仍以既有奇闻契约及M6边界为准。

直接时长材料随玩家程序及捕获上下文保存，待选恢复、clone、回放与事务继续使用原帧。schema431明确拒绝旧1～430，core536新增一个公共Effect，内容preview-v359；观察99、命令12、回放1保持。新时长材料和绑定事件不进入玩家DTO或公开日志。

验证中真实格尔宾、伴生牌、格尔宾的凯旋和TIME_064分别走其实际入口；凯旋的时长代表使用显式单成员实验生成池，不认证正式标准生成池。实际执行、结果和下一项仅在原两份台账登记，M0/M6与完整可达内容继续独立验收。
