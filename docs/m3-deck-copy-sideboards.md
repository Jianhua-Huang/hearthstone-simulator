# 构筑选取与开局复制侧板

真实来源为JAIL_397指挥官碧阿崔克丝。完整原行及官方双语主面在`data/cards/beatrix-deck-copies-v1.json`；实际进度、验收及下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 静态声明和构筑输入

`DeckCopySideboardProfile(source_card_id)`是独立于原乐队的有限声明，政策`deck-copy-sideboard-v1`只接受印刷费用2、复制数量10、一个选择。注册表指纹包含声明；原`SideboardProfile`的字段、版本和最多三个乐队成员政策保持。

原`DeckSpec.cards`包含正常容量的完整原始主牌组，另以`SideboardSpec(ROOT,(selected_card_id,))`保存选择，不创建一个隐藏的原随从实体。主牌组含该来源时必须恰好选一张已实现的印刷2费随从；未知、非随从和错误费用明确拒绝。主牌组不含来源、重复侧板和超出数量沿原构筑检查处理。

选牌继续共享普通格式禁限、职业、符文、收藏资格及副本检查。依据原`SIDEBOARD_CARDS_COUNT_AS_MAX`标志的当前政策，所选牌在合并副本核算中占满其普通额度：同一`deck_identity`不能再加入主牌组或其他侧板。普通/传说和显式数量例外共用原`copy_limit`，不以额外十张生成牌放宽原构筑限额。该标志解释及职业特殊来源仍待国服校准。

与乐队不同，合格的2费开局随从也能作为选择；生成副本不因此执行自己的开局钩子。此选择不能经`DiscoverSideboard`或乐队取牌流程消费，`taken_slots`必须为空。玩家保存格式仍使用原`SideboardState`，没有增加状态字段。

## 原开局与生成实体

原`before_deal`钩子只从完整原始主牌组捕获来源。卡牌主体重核开局处于`dealing`、来源ID确为本人原始分配且原卡面是指挥官，以及原侧板选择有效。

随后通过原`ShuffleDeckCards`发布者范围及十个普通`AddToDeck`请求创建十个新的印刷基础实体，保存正常随机插入和来源收据。没有新的抽样器或洗牌账本；实际通知、恢复、回滚和回放沿原解释器。当前本地时序是在原主牌组首次洗牌后、起手抽牌前插入，精确通知及RNG节奏待M6。

普通30张构筑输入在开局因此拥有40张物理牌，但`original_deck`、`OpeningState.original_entities`及生成上下文的`starting_decks`仍是原30张。不能把十张副本预先写入`DeckSpec.cards`，也不对它们再执行原始来源开局钩子。原始套牌条件、换牌、硬币及第一回合共用既有流程。

对局内新生成/打出的指挥官只有其真实5费5/6嘲讽战斗卡面，不重开构筑或补入十张。原始来源之后离区不撤销已经完成的插入。此处没有战吼、持续条件光环或组合机制。

## 信息与证据边界

原侧板配置、完整原始牌序、分配身份和RNG不能直接提供给玩家。沿原玩家投影和信息服务处理原手牌、隐藏牌库及通知，未增加观察、命令或回放字段。

[官方卡面](https://hearthstone.blizzard.com/en-us/cards/126621/)支持选2费随从及十张复制，原完整标签还保留开局、侧板种类和按最大副本计算标记。[36.0官方公告](https://hearthstone.blizzard.com/en-us/news/24287396/36-0-patch-notes)将指挥官列为使用侧板的卡，其竞技场说明不能认证标准构筑的所有细节。

原始成员与生成副本分类、额外十张的准确开局窗口、按最大副本额度的解释、特殊职业资格、通知公开程度及随机消耗均为显式本地政策，仍待国服37.0校准。实验格式的内部通过不等于正式标准合法池、全部随机可达结果或发布验收完成。
