# 当前牌库数量条件与普通战吼目标

本契约说明已有接口如何表达真实牌库数量条件。实际验收、已知差异和下一项只维护在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。

`BAR_916`血岩碎片刺背野猪人的完整本地原始定义是3费3/3术士稀有野猪人，吸血；战吼在自己的当前牌库少于或等于10张时，对一个随从造成6点伤害。完整[原始来源](../data/support/deck-count-conditional-target-basics.json)固定在独立实验注册表；不扩展生产代表包或正式合法池。

## 目标选择

使用原`TargetSpec(TargetMode.IF_AVAILABLE, (Zone.BOARD,), (CardType.MINION,))`和注册、带版本的`PlayerTargetRuleSpec`。纯玩家目标谓词只读取观察DTO内自己的`deck_count`，不读取隐藏牌面、全知状态或工作帧。数量大于10时谓词让合法池为空；数量小于或等于10时沿原普通随从目标规则计算合法池。

- 条件不满足，或满足但合法目标池为空，提交目标为`None`。
- 条件满足且合法池非空，必须提交一个合法随从目标；不能跳过，也不能指定英雄、自身或不存在的实体。
- 敌方潜行、免疫等限制由原目标层处理；友方免疫随从可以被指定。随从战吼沿原伤害类型执行，扰魔不作法术目标限制。

`IF_AVAILABLE`本身已经区别空池与非空池，因此本来源不需要另加`target_condition`值、条件布尔字段、任意条件语言或执行器。[已有接口审计](../outputs/deck-count-conditional-target-basics-20261011/existing-expression-audit.json)保留实际源码节点。

## 原提交与主体执行

原付费出牌接受流程保留原输入状态和实际提交目标，并据原注册规则重建目标合法性。实际战吼派发使用`CheckDeckCondition(player, DeckCountCondition(10, 'at_most'), ...)`，满足时执行原`Damage(target, 6, source)`，吸血由原来源和伤害管线处理；法术伤害加成不增加这个随从战吼的伤害。

原提交目标选择与实际战吼条件判定是两个既有窗口。中间待选或触发使牌库数量变大时，原选中目标仍是提交事实，主体可以因条件不满足而不伤害。原提交没有目标时，后续抽牌使条件满足也不补造目标；目标离开时不重定向。该窗口政策是明确的内部契约，精确国服时序仍待校准。

原付费接受收据、解释器、选择等待、回滚、恢复、克隆和回放继续承载这些事实；本来源不新增状态布局或协议版本。原完整证明和工作帧保持私有，玩家命令使用观察中的不透明引用。结构一致性验证不提供未签名存档的来源认证。

## 范围

本契约只确认这一独立基础需求能由既有目标、数量条件、伤害和吸血能力表达。其他真实条件是否要求新的接受事实，仍须按其对象和窗口审查；不能据此宣称任意条件战吼、正式卡池或最新国服规则完整。
