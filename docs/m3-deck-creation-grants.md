# 直接牌库创建与所选赐福目的地

甜美梦境的真实卡文是“+4/+5，将这张牌置于你的牌库顶”。这是直接生成到牌库的基础交付规则；先入手再移动会产生错误的入手触发，满手时也可能先烧毁。[国服历史资料片说明](https://hs.blizzard.cn/news/24179067/)。具体执行结果和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护，本文描述扩展契约。

## 原子创建

[AddToDeck](../hs_sim/engine/zones.py)末尾可选`minion_grant`接受原不可变[CreatedMinionGrant](m3-created-minion-grants.md)。它使用原`card_creation.validate_creation/install`，与手牌创建共用普通数值、七种已允许关键词及可选身份附魔。错误载体、未知来源或无效声明明确拒绝；恢复时同样核查未选分支。

实体直接创建在`DECK`，原费用和授予都在`card_created`与`card_added_to_deck`之前安装。事件观察者因此看到同一物理实体的完整属性和真实区域；不插入临时手牌实体、入手记录或烧毁事件。牌库顶插入不使用随机数，不再次支付发现来源费用。

正常抽取沿原物理迁移保留属性、身份和原发现来源，抽取才记录实际入手。当前复制保留授予并重分附件ID，基础复制使用印刷材料；出牌后的沉默、回手等重置继续使用原生命周期。普通无授予的`AddToDeck`和旧同名卡不获得新属性。没有新增账户、执行器或通用效果程序。

## 冻结目的地

[DiscoveryMinionGift](../hs_sim/engine/card_creation.py)追加`destination`，仅接受`hand`（默认）或`deck_top`。此字段属于不可变配方，随全部有序绑定进入原待选帧、`DiscoveryPick`和实际`ChoiceResult`的私有收据；它不能独立于原赐福库存被替换。

成对发现继续使用原一次三选、逐次交付入口；外层请求保持`destination='hand'`的既有声明形状，所选赐福的有限目的地负责最终交付。默认配方沿原`AddToHand`，`deck_top`沿原`AddToDeck(position='top')`；两者都只创建一次，保留原来源、费用和完整原子授予。没有推广到场上、多次发现或任意区域政策。

牌库顶选项名称明确展示“置于牌库顶”，预览仍是冻结的局部印刷数值加授予。恢复复核全部选项的库存、资格、名称、预览和目的地绑定。发现期间的异常由原事务完整回滚选择、随机状态、牌库实体和私有收据；创建后等待沿原帧保存已创建实体，不重复交付。

玩家只看到自己的选项和既有公开信息。牌库不向任一玩家提供全知卡牌列表，完整绑定、附件ID、内部收据与帧不进入玩家观察或事件；抽取后的己方手牌显示正常实际属性。

## 实验范围与版本

[完整原行包](../data/support/deck-creation-grants-basics.json)保留33条raw、全部12个本地赐福描述及印刷资格外对照。必要疯狂生物实验只查询三种明确登记的真实3费中立随从，并声明八个可执行配方；甜美梦境是本次唯一新配方。心中的恶魔、活体梦魇、粗暴唤醒和梦魇之鳞保留且明确拒绝，不能静默移出完整结果池。

历史国服说明支持甜美梦境的卡文与三种不同赐福；当前正式池、精确服务端创建窗口和随机分布没有据此得到校准。受限实验不是完整黑暗之赐，也不证明M0正式池、M6国服校准或M7批量接卡完成。
