# 原牌库抽取与真实历史消费者

本契约描述魔网召唤依赖中的真实卡牌效果；实际进度、验证和下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。固定完整记录见[配方](../data/cards/deck-history-native-effects-v1.json)，卡牌主体见[实现](../hs_sim/cards/deck_history_native_cards.py)。

## 仍用原抽牌生命周期

`DrawMatching`追加可选`owner_id`和正向`card_ids`，并支持`lowest_cost`。`player_id`始终是实际抽牌者；未声明owner时维持其自己的牌库。每张牌及其反应完成后，重新查询原指定牌库，不提前搬牌或复制给对手。

高低费用比较复用原DECK本地费用，包含实际存储费用修改，不把未来手牌报价或手牌内在折扣当成牌库中的值；并列由原RNG等权选择。正向身份列表中的未知定义明确报错，不按执行覆盖率筛选。原`empty_deck`政策保留；跨牌库fatigue请求仍交给`draw_one`生成实际抽牌者的疲劳记录和正常健康流程，不偷偷切换到其自己的非空牌库。

`MoveCard(draw=True)`允许原DECK引用流向另一位玩家的HAND，仍必须是DECK到HAND，原引用失效不改绑。普通抽牌、爆牌、手牌驻留、费用和抽牌触发继续由`draw_one`及原移区处理。抽牌记录中的玩家表示实际抽牌者。

另一方实际抽到“抽到时施放”法术时，原实体进入实际抽牌者的GRAVEYARD，再走原`CastDrawnSpell`。这次控制权转移必须传入当时最后一条、未中断、尚待施放的真实`DrawRecord`，实体、卡面、玩家、声明和DECK到GRAVEYARD路径完全匹配；通用`Resolution.move`的其他控制权守卫不放宽。同方抽牌保持旧移区调用。替换补抽由实际抽牌者从自己的牌库执行，外层有限抽取随后再查询原指定牌库。手牌已满时仍先爆牌，不施放或补抽。

没有新增DrawRecord字段、玩家计数或第二套抽牌执行器。`FrameCodec`保存明确原牌库及身份过滤，并核对正向卡牌定义；玩家投影不接收内部请求、抽牌或出牌历史。core349/schema276，旧core按原版本边界拒绝。

| TIME_714 时光领主埃博克 | 从最近关闭的对手本人回合查询真实手牌出牌，再与原成功召唤材料关联到当时的战场驻留。只接受正常成功的随从出牌，排除初始场面、效果召唤、复制、反制和磁力附件；原驻留仍在时交给一次DestroyBatch。换面或控制权变化不冒充重新登场；离场的原驻留不会被同ID新驻留替代。 |
| TLC_110 城市首脑埃舒 | 查询当前牌库随从的完整当前种族，要求整个集合存在共同种族，不只检查两两相交。原TribeState表达全部种族及显式排除，未知明确报错，空随从集合按本地全称政策为真。条件成立后用原跨区批量增益修改当前HAND/DECK及活跃BOARD的其他随从，排除物理源；不创建永久光环或给未来实体追补。 |

## 证据与后续边界

[官方卡库观察](../outputs/card-integration-20261014/k48-official-card-observation-20261016-01/observation.json)冻结这些具体卡面，只支持印刷描述和身份，不证明服务器的所有边界。克罗米重复/顺序和动态计数、匹配空池、高低牌库费用、埃舒空集/种族/休眠区域及埃博克的回合/换面/转移等精确政策仍待国服校准。

TLC_520灌林追踪者的完整源保留在配方中，尚未注册。它需要整局实际洗牌插入事实与正确发起者，不能只监听自身手牌阶段，也不能把重排现有牌库当成插入卡牌。完整魔网五根、三项永久升级、剩余和强化费用候选、正式生成池、全部可达内容及M0/M6仍在原台账保留。
