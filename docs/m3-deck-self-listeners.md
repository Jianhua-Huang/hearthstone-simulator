# 牌库中的实体自身监听

基础需求以海盗帕奇斯CFM_637为必要代表：本牌仍在牌库时，己方打出海盗随从后，召唤本牌原实体。现有物理召唤已经能表达入场；缺口是原手牌进度只捕获HAND，没有原生DECK自身监听资格。当前执行、证据与下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。

## 最小区域声明

原HandProgressSpec增加zone，默认Zone.HAND，旧手牌声明保持。新Zone.DECK入口限定原生普通随从、generic event、goal=1、repeat=True和单个on_complete；拒绝注能/腐蚀/施法进度、多事件门槛、换形、额外on_progress和事件数量基准。不开放双方区域混合、任意授予或特殊来源政策。

原AbilityInstance仍保存进度与事件见证，原AdvanceHandProgress、注册条件和回调执行器继续使用。没有新模块、Effect类型、GameState/Entity/Player字段、候选字段、历史账本、玩法事件、玩家动作或执行器。严格状态读取将zone还原为Zone；缺失或未知字段明确拒绝，typed帧沿原类型白名单处理。

## 捕获及生命周期

保持原普通监听和两方手牌监听的相对顺序，在两方手牌候选后追加牌库自身候选；新候选按当前玩家、另一玩家及各自物理牌库顺序捕获。只捕获当时已经存在、未消费且声明对应区域/事件的实体，不追认前置反应中新建的牌库卡。

执行时复查当前控制者、声明区域中的真实驻留及原能力实例ID。Resolution.move原本就会在每次移区时更新进度实例ID，因此沿用原HandProgressCandidate三字段，不新增epoch或候选账本。离开牌库再返回也不能命中旧候选；单纯重排不更新该身份，已捕获候选仍按原捕获顺序执行。

条件不成立不增加见证；成立时原进度完成再执行单个完成回调。repeat保持每个新合格事件都可尝试，召唤满场失败不将该监听永久消费。实际成功召唤使原实体离开DECK；原移区身份及区域检查阻止继续作为牌库监听。

## 必要原牌召唤

CFM_637条件读取原已完成PlayRecord的冻结卡面：本方正常完成的随从出牌、已知海盗或全种族元数据。若所需种族元数据缺失，明确报错并回滚，不能静默当作非海盗。该冻结印刷依据及反制/特殊提交来源的精确国服政策仍待校准，不扩大到当前动态种族的全部来源。

完成回调交已有SummonStoredCard及原CardReference，移动自己的原牌库实体，保留本地成长和适用附件；不新建复制、额外支付、出牌、施法、抽牌或死亡。同名物理实体各自具有监听身份；容量、原入场、选择、异常及回放共用既有流程。牌在手牌或战场时不执行牌库监听。

新DECK监听的内部完成计数不生成hand_progressed/hand_card_upgraded事件，也不投影为玩家hand_progress。原HAND进度事件和公开投影保持。玩家不能取得牌库候选、能力实例或事件见证；实际召唤入场后才公开原卡面。

## 保存及范围

声明、能力与候选进入原快照和等待帧；离区失效、等待恢复、clone、独立注册表replay及动作/选择失败沿原解释器和事务处理。原ID检查保证内部一致性，不认证未签名存档的外部来源。

仅[完整本地raw/pin](../data/support/deck-self-listener-basics.json)的CFM_637隔离实验定义：1费1/1中立传说海盗，无冲锋。官方[卡牌库](https://hearthstone.blizzard.com/en-us/cards/40465-patches-the-pirate)检索摘要支持从牌库自身召唤卡文，打开页面只返回导航；官方[10.2公告](https://news.blizzard.com/en-gb/article/21361570/upcoming-balance-changes-update-10-2)直接支持历史移除冲锋，不能作为当前国服全部时序证明。生产代表64与合成3保持。

原HAND固定/数值成长已有表达，不新增任意公式模块。MAW_031的牌库注能资格与EDR_487的双方区域黑暗之赐复制属于后续具体来源/授予需求，本次不实现或宣称覆盖。U57整族及其他基础缺口、M0正式池、M6国服校准、M7批量接卡及H2继续开放。

新增私有声明字段使用prototype-v211、core-effects-v205及schema199，严格拒绝旧1～198；观察74、命令11、外层replay1保持。此契约不代替两份台账的实际执行记录。
