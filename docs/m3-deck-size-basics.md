# 原主卡决定每副牌容量的基础

这是 U04 的有限基础子集。原 `DeckPolicy.deck_size` 是双方共用的格式默认值，不能独立表达“这一副原始卡组因来源牌需要40张，另一副仍为30张”。新增声明只解决这个构筑缺口；初始生命复用已有开局钩子和属性效果。实际执行与下一项见[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。

## 构筑声明

`Registry.register_deck_size_rule(DeckSizeRule(source_card_id, deck_size))` 注册不可变、有限的 `deck-size-v1` 声明。当前来源要求已知、可收藏的传说随从；容量必须是至少8的严格整数。全部声明进入注册表指纹，冻结后不能改写。未注册声明时不增加指纹字段，普通格式默认值保持。

校验只读取提交的原始主卡组物理槽。恰有一个合格注册来源时，这一副牌的要求容量采用声明值；否则使用原格式默认值。来源必须在允许名单、未被禁用，并是中立或原构筑职业。两个以上来源明确产生 `deck_rule_sources` 错误，不猜测叠加或优先级；侧板、生成牌、当前手牌/牌库和场上来源均不改变构筑资格。

容量要求不自动补牌或截断。每张牌仍经过原收藏、职业、数量、身份、符文及格式禁限校验。普通开局的最低牌数检查读取各副已校验主卡组的实际长度，而非双方共用的默认值。运行中原职业、符文和主卡组与原 `MatchSetup` 一致；抽牌、打出、死亡及生成不重算已接受构筑。

## 初始生命与开局

必要雷纳索尔王子适配在原 `before_deal` 钩子返回 `SetStats(own_hero, health=40, source_id=source)`。解释器、洗牌、起手、换牌、硬币、回合和选择恢复均复用原流程，没有第二套开局结算器或初始生命状态。

现有 `SetStats` 将40保存为英雄永久属性附件，清除原伤害，印刷基础生命仍为30。这一实验材料与精确时点待国服校准。它不消耗随机数，也不伪造治疗或资源获得事实；后续普通治疗封顶40。必要适配明确要求本项审核的40张声明，缺少声明时不静默建立不完整的真实开局。

钩子只来自构筑开局记录的原主卡实体。换牌不会再应用一次，后来打出或失去王子不重新设置生命。场景入口以及普通30张开局后生成、打出的王子只是普通3费3/4随从；没有追溯开局或战吼。来源本体沿普通随从生命周期处理。
