# 牌库属性总量分配的既有表达契约

本契约描述一个独立的属性分配需求如何使用既有公共能力。实际执行、验收结果和下一项只维护在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md)。它不增加内核效果、状态字段、随机算法或组合机制，也不代表完整正式池支持。

## 原始需求与证据范围

必要来源为 CATA_213 威拉诺兹：6 费 6/6，中立传说元素。完整本地 raw 复用 [起始随从费用和支持材料](../data/support/starting-deck-minion-cost-sum-basics.json)，不改写原始中英文卡文。原起始随从印刷费用之和必须恰好为 100；当前牌库、改费或后来创建的牌不能替代起始事实，未知起始事实明确报错。

[第一份公开对局](https://hsreplay.net/replay/eaytRSsiYnMyjqwciT4dx3) 的两次实际 POWER 窗口分别建立三组 +17/+17、+17/+17、+16/+16，及两组 +25/+25。[第二份公开对局](https://hsreplay.net/replay/RutZoaL6KFT4Hx28Cgmnz5) 也建立两组 +25/+25。每个窗口合计 50 攻击与 50 生命，每个物理目标分别创建攻击和生命附魔。实际数值在后续 ShowEntity 中公开，不能把后公开时间当作原属性执行时间。

两份日志的客户端 build 为 238087，来自玩家自行提供的公开记录，未认证地区或来源，也未证明当前国服目标版本。[说明转述](https://bsky.app/profile/hstopdecks.bsky.social/post/3mfrpvbfkls2b) 称分配为均匀且非随机，但未独立找到开发者原始声明。日志没有公开完整隐藏牌库顺序，因此不能据此宣称余数具体归属、全部中间触发窗口或所有数量政策已经官方确认。完整原始日志、附魔 raw 和逐窗口数据在 [证据目录](../outputs/deck-stat-allocation-preaudit-20261011/distribution-evidence.json)。枚举只按 [HearthSim 格式定义](https://raw.githubusercontent.com/HearthSim/python-hearthstone/master/hearthstone/enums.py) 读取为数据，不执行下载的源码。

## 一次捕获与明确内部政策

`CheckDeckCondition` 使用已有 `DeckMinionCostSumCondition(100, 'printed')`。成立后调用命名的普通分配行为；行为在实际执行窗使用 `minion_references` 与 `MinionScope(zones=(Zone.DECK,))` 捕获当前控制者的有序物理随从引用。

- 只计当前 DECK 中的随从；手牌、场上来源与其他类型不参与。相同卡牌 ID 的多张实体分别占一个位置。
- 非空候选长度为 N 时，对 50 作商余分解。每个引用先获得商；捕获顺序中的前余数个引用另加 1。攻击和生命使用同一数额。
- 每个引用生成一个普通攻击 `BuffStoredCard`，随后生成一个普通生命 `BuffStoredCard`，保留两份独立附件。数额为零不生成空附件。
- 空池产生空元组，不做除法、不消费 RNG。分配本身也不消费 RNG，不套用伤害分包政策。

捕获顺序取当前内核牌库顺序，攻击与生命两次原效果之间采用原解释器检查点。这是可审查的内部政策，余数归属与精确检查点仍待国服校准。它与公开观察的总量、三目标数额和双附件顺序一致，但一致性不是完整官方规则证明。

## 复用实体、附件和解释器

纯行为只返回普通效果元组。公共内核仍负责附件分配、数值刷新、事件、区域迁移、队列、选择、异常回滚与回放；不用独立预算执行器或可变回调保存进展。静态预算与候选可由卡牌行为计算，不据此另立通用状态模块。

接受后的每个引用保留物理 ID、控制者、区域、卡面和 `zone_epoch`。旧引用离区或离区后复入时，原区域守卫跳过其尚未执行的增益；其他引用保留原数额，既不重新抓取后来加入的目标，也不重新分配未使用的预算。来源离场、死亡或沉默不撤销已经接受的普通效果或已安装的独立附魔。

普通当前复制保留属性材料并分配新的附件 ID；基础复制回到印刷材料。普通物理移区保留增益，显式 reset 清除增益。真正抽到手牌并出牌仍沿原生命周期带入属性，进入场上后的沉默清除附件。

## 等待、回放与信息边界

分配前等待恢复后在真实执行窗重新捕获当前候选；分配接受后等待则保存原剩余普通效果及完整物理引用。独立注册表恢复、clone 和 replay 使用原帧编码。失败选择回滚到同一已付款等待边界，不能二次支付或重新分配。

诊断中的等待、移区和新增目标只检验公共生命周期，不作为额外真实卡牌组合。原全知快照仅用于受信恢复；玩家接口不提供隐藏牌库卡面、附件、候选引用、内部队列或 RNG。

原 CATA_213e/CATA_213e2 只作两类附魔的原始证据，不注册为独立可执行卡。必要完整来源只在隔离实验注册表中声明；原正式代表包、合法池、协议和未签名存档来源认证范围保持。精确国服规则、完整来源与批量接卡继续按既定阶段处理。
