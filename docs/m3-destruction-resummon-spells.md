# 原消灭组绑定的生成法术

灵质处决CAP_805与三费灵质CAP_805t使用有限原生法术参数，来源为[两完整原行与四双语官网主面](../data/cards/ectoplasmic-execution-v1.json)。根卡4费暗影、消灭所有随从并分别给予奖励；灵质召回该次消灭的原友方组。来源收据和证据边界见[原始记录](../outputs/card-integration-20261014/k269-ectoplasmic-execution/rule-sources-01.json)。

## 原消灭与交付

`DestroyForResummonSpells`要求实际运行中的原施法记录及注册的`SpellResummonProfile`。解释器捕获双方存活、活跃、尚未将死的随从引用与原左右顺序，在同一handler中调用原`DestroyBatch`；休眠和地标不进入该组。每个原引用对应完整`DeathCause`，普通死亡检查点、亡语和复生继续由既有调度器处理。

`DestroyedSpellGroup`保存原cast ID、死亡起点、完整有序目标及接受原因。`CompleteResummonSpells`在原反应完成后逐次交付双方奖励，空组也有奖励；原施法者先接收，随后另一方。每张奖励携带同一原组及自己的原受益方。创建复用`create_hand_card`，在首次创建/入手通知前安装参数，满手仍按普通创建和爆牌处理。两个交付之间可以正常等待，不重做清场。

## 原生参数和普通召回

`AbilityInstance.spell_resummon_value`只允许有限`SpellResummonValue`：奖励卡面、原受益方和原消灭组；不得混入数值或其他能力。它接入现有native spell value的注册、载体校验、当前复制、CAST冻结和历史继承，不建立新GameState账本。

当前复制取得新的物理附件ID但保留原组；正常转手保留原参数。灵质实际施法时，以参数中的原受益方筛选原组，再将匹配的真实死亡记录按原左右顺序交给普通`ResurrectMinion`，召唤到本次施法者一方。不按新施法者的死亡总表检索，不吸收后来亡语、复生或其他新增死亡，也不根据原实体后来的控制或卡面重算。

普通印刷复活材料、战吼排除、数量修正、容量、入场、亡语及恢复保持既有执行器。旧增益和伤害不复制回来；当前复制、偷取、法术历史重施和整卡历史重放均继承同一原组。基础复制或直接创建的未绑定灵质明确不支持执行，不默认为空组法术。

保存校验原引用、完整原因、真正接受的原施法及对应死亡/暂缓将死事实，拒绝裁掉原因却保留原目标的材料；新载荷和续接沿原frame codec。私有组、来源证明和内部参数不进入玩家DTO。未签名存档不提供来源认证。

本次新增两种Effect、两种有限payload及一个AbilityInstance字段，没有新CardDefinition字段或GameState账本。core548/schema442拒绝旧1～441，观察99、命令12、回放1保持；三类旧动态法术参数仍分别保留原契约。
