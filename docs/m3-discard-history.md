# 本局成功弃牌历史

弃牌历史在[原区域管线](m3-zones.md)上记录成功的物理弃牌，供受信任规则查询。它不执行另一套弃牌或扫宿主事件日志，不改变卡牌揭示、死亡检查点、随机选择和玩家操作。实际进度与验收只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。

`DiscardCard` 的引用仍只接受手牌。过期引用跳过，不产生历史；`DiscardMatching` 每次真实弃牌及其反应完成后重新检索，`ChooseFromZone(operation='discard')` 仍委托同一入口。无候选不消耗随机数。普通烧牌、出牌、开局换牌、生成、复制、区域移动、非死亡移除、牌库销毁和战场死亡均不会增加弃牌历史。

每次成功从 HAND 进入 GRAVEYARD 后，在原 `card_discarded` 发布时提交不可变 `DiscardRecord`，然后沿原事件捕获监听。回调在其原状态中已经看到本次弃牌，不依赖持有计数卡，也不把未来弃牌写入过去的捕获状态。`card_discarded` 的既有字段及空 `data` 保持；新私有参数只允许真实区域处理器提交，不能发布裸弃牌事件伪造规则事实。

记录保存顺序 ID、当时控制者、全局回合/动作、原事件序号、成功手牌获取 ID、揭示策略，以及原牌和可选原因的完整 `SourceAllocationFact`。该事实冻结物理 ID、当时卡牌 ID/类型/owner/controller/区域/修订/顺序和原分配上界，复用已有类型。归属按弃牌时手牌控制者；原 owner 可以不同。牌面已在手中升级时记录当时卡面，不拿最早获取卡面代替。后来的取回、升级或变形不重写过去；同一物理牌再次真实获得并弃掉会产生另一行。

```python
rows = discarded_cards(ctx.state, ctx.player_id)
had_discarded = bool(rows)
minions = discarded_cards(ctx.state, ctx.player_id, kind=CardType.MINION)
this_turn = discarded_cards(ctx.state, ctx.player_id, turn=ctx.state.turn)
```

查询返回原有序不可变记录元组，不按实体 ID 或卡牌 ID 去重，不推进对局或 RNG。玩家、类型和回合参数严格校验，不接受数值相等的布尔/浮点或类型字符串。它是受信任规则接口，不是玩家观察端口。

`GameState.discard_history` 与 `next_discard_id` 保存完整历史和原分配游标，没有新增实体/玩家字段。全局及捕获状态校验类型、顺序、非未来回合/动作、唯一真实获取和原物理分配关系；整局边界另外逐行绑定原弃牌事件及完整事件清单，拒绝裁尾、重复、借用事件或改归属，不能用改游标掩盖缺失。严格 JSON 行、嵌套分配类型和字段均复用公共 codec；选择恢复、克隆、事务、回放及回溯走现有解释器。私有一致性证明不认证未签名历史来源；原揭示策略没有凭空加入一套日志认证。

玩家只看到原公开日志和按原揭示策略可见的卡牌身份。新历史、原手牌获取、内部 ID、原因分配和未来工作不加入玩家 DTO；隐蔽弃牌仍不公开未知身份。公开事件可以作为宿主一致性证据，不意味着玩家能读取全知历史。观察/合法操作查询保持纯读取。
