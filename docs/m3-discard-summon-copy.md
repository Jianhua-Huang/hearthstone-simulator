# 成功弃牌的原材料复制召唤

真实来源为 CATA_494 马洛拉克。随从在己方场上监听本人成功的随从弃牌；原物理牌留在弃牌后的区域，另造一个复制体。普通出牌、抽牌溢出、移区和弃掉非随从不满足条件。对手造成的弃牌仍按被弃牌原控制者判断。

`discard_summons.capture(context, registry)` 读取 `card_discarded` 原事件和该事件冻结的 RuleContext，以事件序号精确连接唯一 DiscardRecord；核对原动作、回合、区域驻留及完整组件。使用原事件状态捕获 `CopyEntryMaterial(profile='discard_summon_copy', mode='current')`，不从后来的同 ID 实体重新取材料。

新 profile 保留原基础数值、独立本地附魔和能力、原青玉尺寸、必要入场强度及完整星舰组件；组件复用 DiscardRecord，不增加第二份组件字段。旧获取的临时手牌期限不复制到场上。复制体使用独立实体和附件 ID，印刷自身来源重绑；不会执行战吼或再次执行被弃主体。磁力和星舰组件随从按普通单体入场，巨型走原肢节流程，印刷休眠沿新实体的普通入场。

原材料捕获与召唤数量接受是两个窗口。前者冻结原弃牌状态；后者在各实际监听主体执行时按新局面捕获完整数量计划。新 profile 允许原材料的附件时钟早于接受计划，不能晚于计划；原 recipient、造成窗口及成功弃牌记录必须一致。旧 board_copy/stored_copy 的严格同窗校验、旧 discard_copy 的只到本人手牌限制继续保留。

召唤委托原 SummonByCard 和共有交付、容量、生命周期、Colossal、死亡与数量结算，不另建召唤器。先响应的监听者对原牌增益或返手，不改写已经冻结的复制材料；原监听者在后续等待中离场不撤销其已捕获主体。多个来源分别接受数量，额外体始终复用各根原材料。满场保留真实弃牌并发布普通失败，不抽随机数。

保存沿原 CopyEntryMaterial codec、DiscardRecord、原解释器帧和完整召唤收据，恢复时检查原事实、接受计划及完整交付。信息投影不公开复制材料、原附件时钟和内部解释器帧。无新生产 Effect、载荷类型或实体/玩家/GameState 字段；解释语义和新 profile 由内核/schema 身份隔离旧存档。

原弃牌状态与触发先后、复制继承、休眠/巨型窗口及数量捕获均是现有公共规则下的内部政策，仍须国服校准。内部证据不能认证完整正式池、实际可达闭包或官方全部交互；执行与实际测试结果只在原两份台账记录。
