# 自身被弃后召唤：原能力表达核对

本契约限定于必要镀银魔像代表。实际执行及下一项只维护在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。这是原机制表达核对，不是新增一个“弃牌＋召唤”组合族。

## 现有入口

原[本牌被弃主体](m3-own-discard-bodies.md)已经提供成功物理弃牌的原记录、原接受状态、玩家和自身来源。原 `Summon(player_id, card_id)` 从注册定义创建新随从，经过现有场地容量、印刷安装、入场、光环、召唤限制、检查点及监听流程。两者通过既有行为和解释器衔接，无须扩展 `CardReference` 或新增墓地移动模块。

必要 `KAR_205` 隔离原生定义声明 `on_discard`，回调返回原 `Summon(player_id, 'KAR_205')`。原弃牌实体留在墓地及弃牌历史，新本体分配独立实体/附件身份，使用当前注册的印刷 3/4；手牌/牌库增益、伤害、消费状态及其他本地附魔不从旧实体复制。新本体按弃牌时玩家拥有并控制，即使原手牌的拥有者不同。

普通手动出牌仍移动原实体并保持适用的手牌增益，与这个新本体政策分别验证。场地已满时使用原 `summon_failed`，不分配新实体、不撤销弃牌记录、不触发死亡或额外出牌/施法；后来腾出位置不会重新执行旧主体。每次实际物理弃牌各自执行，不按名称去重，原过期引用及空匹配不能重复执行。

## 证据及准确范围

完整本地原始记录、哈希和 pin 固定 `KAR_205` 的卡面需求；[官方卡库](https://hearthstone.blizzard.com/en-us/cards/39380-silverware-golem/)的检索摘要确认被弃时召唤卡文，打开页面只返回导航。卡文无法单独证明实体身份、附魔保留或检查点时序。

[官方论坛的历史玩家实测报告](https://us.forums.blizzard.com/en/hearthstone/t/wild-silverware-golem/616)描述弃后召唤不保留手牌增益，并对是否符合意图有争论；原报告还包含手动出牌的问题。它为采用印刷新本体的本地实验政策提供调查依据，不证明当前国服实体身份、当前附魔政策或官方规则意图。未使用二手规则书引用或论坛推测确认当前规则。

因此这项内部验证只证明现有模块能表达并执行该明确的新本体政策。其他卡牌的“召唤它”“返还它”不能因此统一按新实体处理。原 `SummonStoredCard` 保持仅手牌/牌库的物理入口；需要返回原被弃实体、保留/复制原材料的实际规则继续前审。

本项不修改内核、协议、生产代表包或正式合法池；沿用 `prototype-v207 / core-effects-v201 / schema195`。仅新增必要实验记录和专项，不开发授予或组合矩阵。待选恢复、回放、事务回滚和玩家信息边界复用原能力。
