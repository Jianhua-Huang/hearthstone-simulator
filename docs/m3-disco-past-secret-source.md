# 时光之末迪斯科的完整本地奥秘域

`WON_040` 使用原 `CastFromPool` 发起五次普通自动施法，不经过手牌，不逐张支付牌费，不新写奥秘选择器或部署器。原生文本重复、容量、相同奥秘、施法历史与正常终止继续由已有执行器处理。

[固定资料](../data/cards/disco-past-secrets-v1.json)保留完整来源牌、原 `WON_040e` 附魔证据、两个官网主面及 [72 项原始名单](../data/cards/past-secrets-local-reference-v1.json)的完整哈希。附魔仅作来源证据，不注册白板实体。八张旧默认奥秘仅补 `PoolCard.from_definition` 生成元数据，完整定义、印刷职业与学派都与原始数据逐一核对并保持。

## 完整候选与宿主

- 原名单 72 个物理卡面 ID、原成员顺序、每成员权重 1 和原来源版本保持。实际查询使用公共执行器的生成身份排序；原库存顺序与实际查询顺序分别记录，不把排序差异当作缺失或随意重排库存。
- `constructed.local-past-secrets.full-reference-v1` 是独立的完整本地参考域，只向真实 `WON_040` 的全部职业奥秘查询开放。当前 72 项都有完整可执行定义和生成元数据；不按支持程度、当前空位或已部署奥秘裁池。
- 五次原生文本施法使用放回抽取。重复抽中仍有普通 CAST，重复/容量失败沿原部署规则，不替换成另一个候选，不伪造新的奥秘实例。
- 本地宿主读取 [v12 绑定](../data/cards/local-special-pool-bindings-v12.json)，保留 v11 的完整前驱和全部原声明，只增加此池与来源 scope。原标准根、构筑政策和原专用池的成员、角色、权重、排除与顺序保持。

这完成明确本地名单的库存和来源表达，不认证正式国服“过去”定义、重印权重或热修后的合法成员。`formal_pool_complete` 与 `cn_calibrated` 保持 false。

## 实际部署与原截止时间

`SecretExpiryProfile` 只声明这个真实来源的固定五次请求及完整候选。奥秘实际执行 payload、成功沿 `activate` 安装后，来源观察者从真实自动 CAST 的 caster 找到仍在执行的原生产者 CAST，形成 `SecretExpiry`。

该结果保存原生产者与子 CAST ID、实际奥秘物理分配、部署实例 ID、原接受回合/动作/通知序号和原本人回合开始截止。它不按后来卡名查找，也不把生成卡 ID 当成已经成功部署。

截止由原生产者接受时的真实 owner interval 推导，复用 `KeywordExpiry` 与公共本人时钟。在对方回合自动施放时仍使用实际施用者的下次本人开始。相同奥秘已存在、奥秘区已满或已消费的旧实例均不取得新截止，也不会延长原截止。

标记先安装，再发布同一 `secret_set` 通知。私有通知绑定完整原结果，恢复时与实体、原 CAST、分配及本人时钟交叉验证。已经揭示或被移除的实例清除活动标记，历史通知仍保留；之后重新部署的同名牌不继承旧标记。

## 开始清理与恢复

到期集合按实际部署顺序捕获，以 `ExpireSecret` 请求保存每一个原实例；每次执行仍校验原通知、截止及连续驻留，再复用 `consume`/`secret_removed`。被其他反应先移除的原实例普通跳过，不追逐替代品。

本地政策将清理接入原本人时钟已开始、`BeginTurnEvents` 尚未发布的 startup 队列，先清理到期原实例，再进入普通开始触发和抽牌。清理通知可以产生真实等待，原队列、开始中断见证与选择恢复继续由原解释器负责。与其他同开始触发的精确先后属于待国服校准边缘，不等待实测阻塞本批。

原 `CastFromPool` 仍处理每次选取和施法。新来源的请求校验固定五次、放回、按次查询与完整原查询，不能伪装成另一个来源或减少原请求次数；正常文本额外执行仍沿既有机制发起自己的请求，不另造全局次数限制。

## 协议边界

内核 805、快照 schema 627、卡牌内容 709。新增一个 `ExpireSecret` Effect、一个 `SecretExpiry` payload 和独立注册的来源 profile；Entity 增加可空的原部署结果。默认代表注册表无新 profile，其卡牌指纹保持；旧 schema 1～626 继续按原严格门禁拒绝。

玩家投影继续只给其应见的奥秘与通知，私有原截止、全候选、CAST 祖先和全知快照不交给玩家。行为验证、保全结果和下一项仅在原两份台账登记，不从资料或登记数量推断整轮目标完成。
