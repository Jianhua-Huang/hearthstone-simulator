# 原发现材料与原生亡语记忆

DINO_430兽语者塔卡的战吼从任意职业传说野兽中发现一只，获得其印刷属性，亡语召唤选中的野兽。DINO_430e保留完整原始证据，不单独适配实体。实际进度及验证仅在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 原选择与原来源

有限`DeathrattleDiscoveryTarget`保存真实BattlecryRecord ID、原随从驻留引用和接受时的亡语能力ID。`DiscoverFromPool(destination='memory', memory_target=...)`只允许一次普通三选、任意职业可收藏传说野兽的原生形状，不开放额外减费、复制、授予、跨区域交付或多轮组合。

候选、抽样、真实POOL_DISCOVERY选择、原完整菜单、发现历史和选择恢复继续走既有发现流程。选中的牌不创建到手牌，也不创建隐藏临时实体。完整明确宿主域中的合格未实现卡继续报错，不能为让发现成功裁掉它们。

`RememberedDiscovery`只保存原战吼、实际发现记录和选中卡面。原提交记录确认玩家、来源和选中对象；恢复边界进一步从原`OriginalDiscoveryOffer`解码真实`ResolvePoolDiscovery`分支，对照原目标、原战吼和完整池资格。它是内部一致性校验，不提供未签名存档的来源认证。

## 属性与亡语

选中后先把关联写入仍属于同一原驻留的既有亡语附件，再交普通`Buff`增加所选牌的攻击力及生命值。因此属性通知中来源死亡时，原死亡捕获已经包含关联。来源此前死亡或离开原驻留时，不改写已捕获的死亡，也不把关联安装到后来的驻留。

发现完成通知没有物理收件人，复用原选择型`DiscoveryCompletion`。通知、属性反应及待选仍由普通调度器处理。亡语只读实际捕获的附件，按原选择顺序返回`SummonByCard`，由共享召唤处理容量、死亡、复生、反应和随机；不重新发现、不执行被召唤牌的战吼。

当前复制沿原复制材料保留关联，基础复制与回手重置使用空记忆，沉默移除普通亡语能力。每次真实战吼向当时原附件追加自己的选择，多个原选择在一次亡语中依次召唤。这些继承、重复及精确窗口是本地执行政策，仍须M6国服校准，不能从卡面文字推断为已获官方验证。

## 37.0的巨型限制

[官方37.0补丁](https://hearthstone.blizzard.com/en-us/news/24301454/370-patch-notes)修复塔卡能够发现巨型随从的问题。公共默认生成政策不包含巨型禁令，因此本卡查询明确使用`PoolQuery.keywords_none=(Keyword.COLOSSAL,)`，不能修改其他卡的默认生成行为或硬编码排除具体卡名。

`keywords_none`使用不可变、无重复的Keyword元组，与原必备关键词、费用、类型、职业及平面备选条件合取。既有查询默认为空，行为保持；共享JSON查询解码保留严格类型。

本增量使用core531、schema426，拒绝旧425及更早格式；既有记忆增加嵌套发现关联，未增加全局历史或GameState/PlayerState/Entity字段。正式生成域、全部可达、精确国服重复/继承及再次召唤政策仍开放。
