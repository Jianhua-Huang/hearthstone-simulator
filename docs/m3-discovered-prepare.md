# 发现随从的预备授予

通缉海报（CAP_407）的完整源记录和中英主面要求发现法力消耗至少5点的随从，并使其获得预备。预备原有执行器只读取印刷手牌动作；本入口给实际发现的物理实体安装可移除能力，继续复用[基础预备](m3-prepare.md)。实际进度与验证只在两份原台账维护。本页描述内部契约，正式生成池与准确国服时序仍须单独校准。

## 原发现和创建

卡牌层使用原 `DiscoverFromPool`，查询为可收藏随从、印刷费用至少5及普通当前职业发现政策。`minion_grant=CreatedMinionGrant(special='prepare')` 随原 `ResolvePoolDiscovery`、实际 `ChoiceResult` 和发现交付保存；所选随从仍由原 `MaterializeDiscoveredCard` 与 `create_hand_card` 创建。未知合格内容在完整候选检查时报错，不删减候选；没有安装或推断正式卡池。

原 `card_creation.install` 在首次创建、入手或烧毁通知前安装 `AbilityInstance(kind='prepare')`，绑定原来源并使用普通附件ID。授予不预先投入法力，不改印刷定义，也不影响旧手牌或其他候选。满手烧毁保留创建时的完整材料，但没有成功入手或额外发现选择。

新特殊授予只表达预备，不附带数值、关键词或任意行为程序。载体必须是可从手牌使用的随从；来源和动作ID须明确。印刷预备已存在时不重复动作。与原有普通正数值发现授予分别验证，旧配方范围保持。

## 执行与生命周期

`hand_actions.specifications` 汇总印刷动作和当前物理授予，报价、合法动作枚举、玩家手牌视图与命令支持检查共用它。预备仍调用原专用法力报价与 `prepare.activate`，保存原 `HandPreparation` 和减费附件；一次限制、投入数加一的折扣及本全局回合不能打出的规则保持。

授予是独立普通附件，来源离场不会撤销它。当前手牌复制保留能力并重分配附件ID；已预备副本沿原复制器保留投入、折扣和回合锁。基础复制不继承授予；明确基础重置、通常回手、沉默与变形按原生命周期处理。能力在场上不提供手牌操作。特殊保留式迁移及其他具体卡牌交互仍依据其原契约，不从本来源推导新的重置规则。

## 保存与信息边界

原发现待选和创建/支付反应等待均沿现有帧解释器。没有新动作、效果类型、GameState/Entity/Player字段、支付账户或随机抽样。schema390及core473保护新增可执行能力语义，拒绝旧schema；玩家视图94、命令12和回放外层1的结构保持。

授予能力只允许其来源、普通磁力组件归属与可移除生命周期，拒绝混入行为、其他策略、期限或已消费标记。恢复还核对实际随从、可手牌使用定义和原来源。未签名存档不提供外部来源真实性认证。

本人能看到原手牌动作与动态价格，对方只能看到既有公共预备投入事件，不获得隐藏卡面、附件ID、内部配方或费用。原事务负责失败后的完整回滚，重放使用独立注册表重建相同发现与支付。原始主面只能证明卡牌文字；精确授予/创建/发现通知窗口与所有特殊交互未据此认证为国服实测。
