# 亢祖的原发现结果与去向选择

EDR_517亢祖是3费3/4随从，战吼发现一张法术，再决定保留或放到对手牌库顶。EDR_517A轻柔微风和EDR_517B变迁之风为两个真实选项。完整三原行及六份严格双语主面保存在`data/cards/discovered-spell-destination-v1.json`。

两个选项原记录和官网印刷费用均为3；作为`choice_only`定义保留这一展示值，不能成为物理卡或经普通出牌付费执行。注册校验不再把“选项”误等同于“印刷费用为零”，其他类型、属性和可执行主体限制保持。

## 一次发现与一个去向菜单

`DiscoverFromPool.destination='hand_or_opponent_top'`只允许一次普通三选当前职业可收藏法术发现，默认权重、身份和完整候选检查沿原管线。其他附加材料、减费、复制、重复发现、黑暗之赐、召唤或插入位置不能与此有限入口混用。未知合格法术明确报错，不能用已实现子集替代完整池。

原`ResolvePoolDiscovery`先提交一份完整发现选择，再请求去向。去向为普通`EFFECT`菜单，只含两个原真实选项，不增加发现次数。等待期间没有提前入手、烧毁或放入对手牌库，也不再次抽样。

`DeliverDiscoveredSpell`保存原完整池选择、原发现玩家/来源、保留分支和完整去向选择。后续交付卡面只从原选择派生，不搜索同名手牌或后来实体。历史战吼、来源死亡、转控或离开后仍沿原已接受玩家与主体继续；实际玩家政策和精确服务器窗口仍待M6。

## 普通材料化及原交付完成

保留时复用`create_hand_card`，放置时复用`create_deck_card(AddToDeck(..., position='top'))`。仅保留分支受本人手牌容量影响，满手按普通烧牌处理；对手牌库顶不会经过本人手牌。两个分支均使用原发现结果的`MaterializeDiscoveredCard`和`DiscoveryCompletion`，保留实际新实体、同步创建窗口及原完成通知。

新配方的`player_id`是原发现者；实际收件人为该玩家或对手，完整原分支证明及冻结分配事实共同校验收件玩家、卡面、类型与区域。没有放宽普通AddToHand/AddToDeck配方只能交付原发现者的限制。选择等待核对完整原两个选项，嵌套池收据继续由已有发现验证递归校验。恢复一致性不认证未签名存档的外部来源。

费用、区域、容量、获取反应和玩家可见性沿既有机制，没有新实体、玩家、GameState或保存布局字段，也没有第二套发现或创建执行器。精确国服选择/交付/完成窗口及置入对手牌库时的可见性仍待校准；有限experimental池不认证正式生成池。

实际版本、测试结果、进展及下一项仅在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护；M0、M6和全部标准可达仍独立开放。
