# 原发现的实际交付与发现后通知

宝库闯入者（TLC_483）需要对本次真正发现的那张卡减费。卡面相同不能证明实体相同；原不可变 `CardDiscoveryRecord` 仍只表示选中事实，不能拿它冒充入手、移动或召唤成功。实现使用 `DiscoveryCompletion` 保存原完整 `ChoiceResult`、原实际输出的 `SourceAllocationFact` 和原交付请求，继续由既有创建、区域、临时卡及召唤执行器执行。没有新增实体、玩家或游戏状态字段。实际验收、差异和下一项仅在原两份台账维护。

普通手牌、牌库、临时牌、原牌移动、当前/基础复制和弃牌，由 `MaterializeDiscoveredCard` 包装原请求，取得原工厂的实际返回对象。地图首次交付、原牌黑暗之赐、手牌后召唤复制和余项洗入也在自己的原生产者上连接实际返回值。地图奖励是普通效果选择，不新增发现。场上发现及选择死亡记录复活通过原返回的 `FinishCardSummon.root_id` 连接真正的召唤记录，不猜未来实体或根分配游标，不扫描同名实体或诊断历史来给游戏效果找收件者。

每次实际选择只有一个首要收件对象。场上数量加倍只取原第一次实际交付；额外召唤体、赠礼手牌复制及召唤复制保持派生结果。空交付保存空收件，烧掉的对象保存其实际墓地事实，不能改找已有同名手牌。这些首要/派生、休眠与通知窗口是明确登记的本地执行政策，卡面文本证据不等于国服时序验证，仍待 M6 校准。

原同步操作完成时接受私有的 typed 完成工作；原获取、入场及其反应结算后，`FinishCardDiscovery` 或 `PublishDiscoveredSummon` 发布语义事件 `card_discovered`。连续 `after_all` 保留各次不同的原选择，逐次交付和通知后才推进下一项。通知前来源离场不再捕获新触发；已经捕获的触发继续结算，减费还必须核对原对象的卡面、类型、控制者、区域、区域代数与入场身份，原实体离开再回来也不能承接旧驻留的减费。休眠场上收件仅由该受保护入口允许安装普通费用附件。原费用执行器负责数值、下限、材料、移除和实际支付。

`card_discovery_delivery_queued` 是不捕获游戏触发的私有一致性证据。恢复时，原选择与不可变历史对照，同步交付与原操作窗口的创建/移动事件对照，场上交付与原召唤记录对照，完成事件与原接受工作对照；等待帧及原支付续接证明必须保留全部欠付完成工作，拒绝丢失、重复、换玩家、换来源或换收件对象。异常回滚、真正回溯、自动施法、clone 和回放继续使用公共事务与解释器。该检查不提供未签名存档的外部来源认证。
