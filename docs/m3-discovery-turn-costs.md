# 发现后零费的有限固有费用

乱翻库存 TLC_365 的完整印刷三费奥术法术面与三点随从伤害使用普通卡牌层；伤害、法术加成、目标、反制及支付继续原执行器。实际进展、验收和下一项仅在两份原台账维护。

`IntrinsicCostSpec(set_to=0, condition='card_discovered_this_turn', history_profile_id='discovery.card-this-turn-v1')` 只接受一条独立可从手牌打出的法术规则。不接受其他设值、delta、最低费用、混用数量公式或未知profile；未来真实来源按实际需要另审。原 cost.intrinsic.before-local-v1 的固有→本地附魔→外部层→手牌下限顺序保持，不创建折扣附件、可消费次数或实体费用缓存。

`CardDiscoveredTurnMatch` 保存原玩家、全局回合、动作、完整全部有序 CardDiscoveryRecord 前缀和 bool，包括另一玩家及旧回合的不匹配行。条件仅查看同玩家、本全局回合的真实已选发现，未选择、普通生成与普通菜单不算；移区、复制、改变控制者后的报价重新查询收件方当前事实。实际发现生产者与未覆盖的后续触发边界见[发现事实](m3-card-discovery-facts.md)。

完整原报价验证重捕原状态全部事实。保留报价验证要求全前缀与实际状态一致，早于报价动作的遗漏行拒绝；后来发现和回合推进不重价旧付款。紧凑前缀允许同动作后续新发现，不能单独认证未签名存档来源，原支付/接受证明继续绑定实际完整原窗口。原账本在回溯时恢复，不从宿主追加诊断倒推条件。

物理和生成报价、初始费用、外部支付账户、已接受付款和后续选择统一经过原 IntrinsicCostStageFact；只扩有限条件事实类型及严格字典读取。原待选/回溯/异常回滚/独立reader与回放沿现有代码。费用事实和完整发现菜单只供宿主，不传玩家。

该内部契约使用core459/schema376，旧375及更早须原引擎；观察93、命令12、replay1保持。普通前置固有层与发现选择窗口的精确国服政策仍待M6，正式池/热修归M0；本契约不代表官方一致性或完整标准池。TLC_483原实际收件实体与TLC_460/460t完整奖励生命周期保持独立未完成事项。
