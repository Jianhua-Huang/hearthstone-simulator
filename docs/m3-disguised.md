# 伪装基础机制

本页描述独立Disguised的出牌入口，不设“伪装＋其他机制”开发任务。实际执行、验证结果和下一项由[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护；国服正式补丁实测校准仍在M6。

## 依据与范围

[国服官方介绍](https://hs.blizzard.cn/news/24276664/index.html)说明伪装随从可从手牌直接使用到任意一侧，并用伪装的看守说明效果按落位侧生效。HearthstoneTeam的[官方团队答疑](https://www.reddit.com/r/hearthstone/comments/1tux9zu/escape_from_violet_hold_how_does_this_work/)明确：打至对方场面的牌仍算自己使用；战吼重复来源看出牌者，各次主体作用于落位侧。这些介绍与答疑不是国服目标补丁全部时序的实测认证。

静态入口为普通随从的`CardDefinition(disguised=True)`。基础阶段调查的本地完整原始记录中有五张带DISGUISED标签的可收集随从；基础阶段只用JAIL_455伪装的看守与CAP_004伪装的特工验证必要行为，见[完整raw/pin证据](../data/support/disguised-basics.json)。当时它们在专项隔离注册表执行，没有加入生产代表包64，也不代表正式卡池适配完成。标准内容包的CAP_004适配复用本入口，其原生亡语及完整当前卡面契约另见[真实亡语卡](m3-death-followup-cards.md)；基础阶段历史证据和默认代表包不因此改写。

## 出牌者和落位方

`PlayCard.board_player_id`可选：省略时使用出牌者场面，显式选择仅允许伪装随从。位置和容量按所选场面检查，支付、当前手牌归属、使用历史和原始卡面继续按出牌者检查。普通随从、法术、武器、英雄和地标不能借此选择对方场面。

整个入口复用原有顺序：冻结出牌和费用、付款、进入出牌者的Zone.PLAY、承诺反应、反制检查、实际入场、入场反应、主体和完成。接受入场时才把实体放入目的方的战场并设置controller；owner保持。移除旧区域、初始化战场生命周期及刷新光环都在原区域写入路径完成，入场监听已经看到目的方控制的实体。不会先进入己方战场再转控，也不产生control_changed事件。

反制时仍进入出牌者的墓地存储，不召唤、不产生死亡、不执行战吼或亡语。承诺后所选场面变满时沿原board_full政策保留付款、取消入场并存入出牌者墓地。该异常窗口继续依赖R-116内部规则，不能据介绍文本宣称已取得国服一致性证据。

`PlayRecord.player_id`是使用者，`board_player_id`保存原提交的目的方；出牌历史、使用计数、费用证明和战吼/连击接受收据继续绑定使用者。主体的RuleContext.player_id也保留使用者。适配伪装牌的“友方/敌方”文本时，读取接受主体时的`ctx.source.controller`；分段效果先冻结该侧，再通过已有InvokeBehavior在每次执行时查询其场面。伪装的看守用两个独立DamageBatch，第一波死亡处理完成后，第二波重查当时的随从。

## 生命周期与再次使用

伪装是当前卡面拥有的落位权限，不是实体上保存的“以后总打到此侧”状态。普通召唤遵循Summon.player_id，不执行手牌战吼或新增手牌使用历史；手牌复制、回手和转移保留当前卡面的权限，每次新的手动使用重新选择目的方。变形为普通卡面后失去该权限。随从死亡按死亡时的controller结算，原卡牌owner和历史使用者保持独立；特工的亡语因此给死亡控制者的对手抽牌。

官方答疑还说明，卡牌效果重新使用伪装牌时默认己方。这与工程回放重放原玩家动作不同：工程replay保留本次提交的目的方。当前增量验证了默认手牌入口和普通召唤，没有新增历史重新出牌器或适配这些特殊卡；后续真实卡需要时按既有模块补最小必要行为。

## 恢复与玩家接口

引入时schema151新增明确的目的方字段，严格拒旧1～150；动作、完整支付前状态、接受上下文及历史保存同一目的方。恢复检查字段类型、权限、原动作和收据一致性，不能只改外层PlayRecord后借用原支付/结算证明。恢复、clone和工程回放复用公共解释器；未签名存档仍不提供外部来源真实性认证。

引入时命令10增加可选`side: 'friendly' | 'enemy'`，相对调用者解释；默认己方命令保持原形状。玩家不使用内部实体/历史ID或board_player_id。引入时观察64在已知牌面显示disguised，公开待结算牌显示相对观察者的play_side；对方隐藏手牌不因这个属性泄漏牌面。待结算仍属于原出牌者，实际入场后归目的方战场，双方选择授权沿原固定座位接口。

声明只接受普通无显式目标的物理随从；不新增磁力/巨型/抉择落位兼容、任意动态授予或独立主体目标路线。未经支持的声明或玩家输入明确拒绝，不把这些形状另列为当前基础阶段待办。

专项见[独立测试](../tests/test_disguised_basics.py)，验证支付/位置/容量、真实两波战吼、死亡归属、复制/回手/变形、反制、实际承诺/反制/入场/两波之间等待、独立注册表恢复、clone、replay、玩家信息及异常回滚。限定内部验证结果以台账和[实际运行目录](../outputs/disguised-basics-20261009/)为准，不能替代H2整体验收或M6校准。
