# 不同印刷扩展包的牌库招募

真实入口为旅行管理员杜加尔 `WORK_043` 的已接受战吼。完整原行及双语官网主面保存在[固定数据](../data/cards/dungar-expansion-recruit-v1.json)。当前固定原行为10费3/3中立随从，召唤本人牌库中三个不同扩展包的随从；招募不触发这些随从的战吼。[官方介绍](https://hearthstone.blizzard.com/en-us/news/24136211/)确认跨扩展包召唤，但没有给出抽样权重、选择检查点或重印归类细则。

## 声明与原选择链

有限 `RecruitExpansionProfile` 只声明不可变、唯一且有序的原生卡ID到正整数印刷集ID的完整映射。注册表将profile ID和完整映射摘要纳入指纹；原库存与摘要是只读缓存。杜加尔复用[时光之主的23,452条印刷表](../data/cards/time-lord-nozdormu-v1.json)，核对整个原文件、整个映射及自身原行，不复制第二份库存，也不依赖当前最新扩展包政策。

`SummonFromZone.expansion_profile` 是现有物理招募请求的有限选择条件：原归因、本人牌库、随机选择、原计数三、普通数值/入场形状。当前没有为无真实来源的其他查询组合开放接口。

原 `recruit_summons` 继续负责接受身份、容量、原牌库库存、随机状态、选择、原实体移动、额外基础实体、召唤数计划、反应及续接。新选择条件仅在原候选中排除本批已选择的印刷集。每个原选择窗在 `RecruitBasis` 保存profile及有序 `excluded_expansions`，验证时从同一原生产者的前面各次已选原生ID重新推导，不能借用其他批次、当前已变形身体或后来新局面改写原归属。

每个重复战吼/后来实体产生独立原招募批次，从空排除前缀开始。一次被选随从的额外召唤继续使用同一原入场材料，不增加扩展包选择或随机抽取次数。原选择之后的变形、死亡、来源离场和新牌库条目由原执行器处理，不在卡牌回调中维护第二个召唤队列。

## 当前本地政策与待确认项

- 按完整原行 `CARD_SET` 对原生身份分组，不按中文名、英文名或卡ID前缀猜测。同名重印保持各自原行，迷你系列与父系列共享原印刷集；带 `CORE_` 前缀的记录也逐行使用实际数值，不能一概归到同一个集合。
- 每个仍符合条件的物理牌库位置各占一个权重；抽中后排除其整个印刷集，再等待原完整入场和反应结束，按新局面重查下一次。
- 排除消耗绑定原已选择身份，额外副本不消耗新分组；已选择但后来失效的物理引用仍占用原选择组。未核准的失效选择窗口保持为本地政策。
- 满场在原候选查询之前结束；空候选不消耗随机。未知profile或符合类型的未知印刷归属明确失败并由原事务回滚，不给默认集ID，也不按实现状态删牌。非随从不属于这个查询，无须为其杜撰扩展包。

精确官方权重、同时选择还是逐次重查、Core/重印/特殊集的正式分类以及嵌套牌库变化窗口尚未国服校准。动态拼装、僵尸兽等没有被该完整原生表确认的身份若实际进入候选，会明确未支持；本增量不替它们猜测印刷归属。版本对齐与这些规则边界按用户指示暂缓，保留差异继续接入已知内容。

## 保存与信息边界

新增条件进入原请求和原物理候选依据。原记录、事件、等待frame、恢复、clone和回放共用严格解码；当前schema拒绝缺少新字段的旧快照。验证同时保留完整原库存、原候选顺序、原随机前后状态和实际物理入场关联；重算外层hash不能替代原收据之间的一致性检查。这里证明内部一致性，不提供未签名存档的外部真实性认证。

profile库存、排除前缀、随机状态和招募内部收据不进入玩家DTO。公开身体仍通过原观察器展示。生产过去域的成员与资格仍独立核对；单成员实验发现池只验证真实生成→改费→打出→战吼链，不认证完整过去池或国服正式标准合法性。实际结果与下一项仅登记在原[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。
