# 托雷斯与原物理圣盾命中次数

`EDR_258`坚韧的托雷斯使用有限印刷`HealthRule(DAMAGE, SHIELD_HITS, 3, layer=TARGET, target_relation='friendly')`。完整原行及两张严格双语卡面固定在`data/cards/divine-shield-hit-provider-v1.json`。只允许随从的该精确原生声明，不接受动态授予、其他次数或筛选参数；普通防护、健康包、关键词与死亡继续使用原执行器。

## 命中与真正破裂

次数保存在物理`AbilityInstance.divine_shield_hits`，不绑定提供者或借用手牌进度。实际正值伤害到达圣盾时才增加；免疫、零伤害、规则防止和治疗不消费。前两次仍产生原防止结果，第三次消费原圣盾，只有真正破裂才发布`shield_lost`，不提前触发救援者或伯瓦尔式消费者。多个来源取三次，不相乘；英雄圣盾同样先于护甲阻挡。

来源资格沿原同时健康批次冻结，计数则按原有序包逐个提交。已有护盾的后续授予和追加印刷能力继承同一逻辑护盾的已命中数，避免重叠附件将次数重置。来源离开后不立即移除护盾；下一个实际包按当前单次阈值破盾，部分计数保留。此优先级、部分计数和再授予政策是待国服校准的本地契约。

## 生命周期与保存

普通当前复制保留原物理材料中的部分计数；基础复制、变形和普通复活通过已有生命周期生成新的印刷护盾。休眠/苏醒保留实际未消费护盾。活跃护盾只允许0～2，第三次消费后的附件可保存3；非圣盾能力不能携带非零计数。schema416拒绝旧布局，恢复/clone/回放走同一原能力校验，不认证未签名存档来源。

`player-view-v96`仅为场上英雄/随从增加`divine_shield`：无护盾为`null`，有护盾为`hits_taken`、`hits_to_break`、`remaining_hits`、`active`四个公开字段。休眠护盾的`active=false`；不给隐藏手牌提供该字段，不暴露附件、来源或健康规则证明。付费目标输入严格解码该公开形状并保留原接受时的观察；后来命中不改原收据。

[官方32.4修复说明](https://hearthstone.blizzard.com/en-us/news/24205006)仅证明托雷斯及受影响随从从阿纳克洛斯效果返回时应有圣盾，不能据此证明部分计数、再授予、来源离开或国服37.0准确时序；阿纳克洛斯整卡不由本实现认证。M0正式池、M6国服校准及全部标准可达内容保持独立。实际版本、验证和下一项仅维护于[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)。
