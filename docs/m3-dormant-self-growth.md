# 原休眠实例的自身属性增长

真实来源为 `TLC_253` 石化食人魔：印刷3费5/5，起始无限期休眠；休眠时本人实际回合开始，等概率获得+2/+2或改为唤醒。完整原始行与两种语言的主面保存在 `data/cards/native-dormant-growth-v1.json`。这是固定来源的内部实现，国服时序及正式版本/合法池仍须单独校准。

`GrowDormantMinion(reference, dormancy_id, attack, health)` 只接受原 `MinionReference`、正整数休眠实例ID及非负且至少一项为正的属性增量。执行时同时核对物理随从、控制者、卡面、区域代次、入场顺序与本次休眠ID；原实体离场、变形、变更控制、已唤醒或开始另一段休眠时，旧请求明确跳过。来源固定为原自身，不能作为任意外部随从增益入口。

该请求只放行这一个休眠自身接收条件，属性附件、累积伤害、衍生属性、事件反应与后续清理继续使用普通 `Buff` 的同一安装器。普通 `Buff` 和 `BuffCapturedMinion` 的 active 条件保持。唤醒继续使用 `AwakenCapturedMinion`，不会创建新实体、召唤、战吼或即时攻击机会。

原生 `dormant_triggers` 监听 `turn_started`，只接受当前控制者的真实回合开始；额外真实回合正常触发，跳过的时段不触发。先捕获原随从及休眠实例，再把两个等权结果交给已有 `RequestChoice(sample_size=1, min_count=0, max_count=0)`。自动抽选及回调仍由公共选择解释器负责，不调用卡牌私有随机源，不产生玩家待选或发现历史。唤醒后休眠触发声明不再活跃；沉默、复制、回手与变形沿原生命周期执行。

新请求属于既有休眠模块，使用已有 `MinionReference` 载荷；不增加实体/玩家/全局模型字段或玩家命令。内核身份前进到466、存档schema383，旧schema382及更早明确拒绝。待选队列中的请求可经独立注册表恢复，玩家视图不获得内部引用、休眠实例ID或随机状态。
