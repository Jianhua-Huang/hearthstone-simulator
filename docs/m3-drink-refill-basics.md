# 饮料续杯的独立有限使用

[官方胜地历险介绍](https://news.blizzard.com/en-us/article/24108514/announcing-perils-in-paradise-hearthstones-next-expansion)说明每个饮料法术有两次续杯，并列出麦芽岩浆的三个剩余次数形态。有限使用可由既有施法主体和命名手牌生成表达，不需要饮料关键词、额外计数器、双生法术或回响声明。

本契约只核对独立有限使用；卡牌主体调用公共效果是必要适配，不建立“饮料＋其他机制”的组合模块。精确续杯、死亡、费用和特殊来源窗口仍待M6国服校准。实际执行与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 既有表达

分别注册剩余3、2、1次的完整印刷法术。前两种主体在效果尾部返回`AddToHand(player_id, next_form, source_id=source_id)`；最后一种不生成后继。普通手牌施法每次执行一次主体、支付一次费用，不能在一次出牌中自动执行三杯。被反制时原公共施法流程不执行主体，也不产生续杯。

余次由当前印刷card_id确定；不存在另一个需要同步的自定义实体计数。每次续杯是新的物理手牌，原牌在墓地，创建及入手事件沿用原施法source_id。普通AddToHand不额外设置origin_entity_id，不将事件来源与实体复制祖先混同。未知后继由公共创建路径明确报错，不按白板或无续杯处理。

## 生命周期和窗口

麦芽岩浆的主体使用`DamageBatch`对所有敌方角色造成1点火焰法术伤害，包括敌方英雄和当前有效随从。原伤害、反应与死亡检查结算后才处理主体尾部的续杯；对手随从死亡不会被误当成少伤害或重复施法。本地政策复用当前解释器，官方介绍没有证明这个精确窗口。

普通手牌出牌先腾出一个位置，因此起始满手通常能接住续杯。如果前面的反应已填满该位置，下一杯按既有生成规则烧毁，实体进入墓地，不能补发或恢复余次。后继采用自己的印刷费用，前一杯本地减费附件不自动复制；持续费用规则仍由原费用系统负责。本项只核对本地减费边界，完整持续来源另行验证。

current/base复制均从当前印刷余次形态创建，不自动返回3杯；current保留原普通修正，base清除本地修正。普通手牌/牌库迁移和转交保留当前物理形态，下一次成功施法为实际施法玩家生成后继。上述复制、转交、费用、烧牌及对局终止窗口是内部政策，不能代替当前国服证据。

## 恢复和信息

伤害反应待选时后继尚未创建，入手反应待选时后继已经存在；既有队列保存这一先后顺序。独立注册表恢复、克隆和动作回放均继续同一队列，不重复伤害或续杯。后继缺失或后续故障沿原事务回滚支付、伤害、生成、随机变化、历史和玩家知识。

玩家可看到自己的剩余次数牌面，对方隐藏手牌仍是牌背；公开入手事件不向对手提供隐藏card_id。没有新玩家字段、命令、事件、快照或回放格式。结构验证不认证未签名存档来源。

## 必要代表与范围

[四条完整raw/pin](../data/support/drink-refill-basics.json)固定麦芽岩浆VAC_323/VAC_323t/VAC_323t2和实际法术反制EX1_287。三杯都是2费火焰、对所有敌人造成1伤害，分别余3、2、1次；反制只用于验证是否实际执行主体。场景职业底座、普通反应和故障注入探针明确标记为合成，不能算正式卡组或真实卡牌组合。

仅隔离验证一个饮料族的手牌施法及一次基本effect CastSpell入口，其他饮料主体、完整自动/抽牌/历史来源、正式可达池和精确CN规则尚未覆盖。生产代表和合成包没有扩卡。prototype-v167/core-effects-v167/schema162、观察71/命令10/replay1保持；无新内核模块、持久状态或组合机制。饮料有限次数能表达不等于U34整项完成，地图/故事、地标形态与下一张德莱尼等其他轴保留。
