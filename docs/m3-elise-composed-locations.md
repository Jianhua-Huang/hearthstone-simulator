# 伊莉斯的有限地标配方

`TLC_100`只用已有`CheckDeckCondition`和`DeckCostDiversityCondition(10, 'printed')`检查原起始牌库；没有起始事实的实验场景仍显式报未知。当前剩余牌库、当前费用和制造后的手牌不替代原事实。根卡正常战吼进入`CraftLocation`，不另建出牌或费用执行器。

## 完整材料与资格

完整源包为`data/cards/elise-crafted-locations-v1.json`，固定38条原行和52份双语官网主面及完整响应缓存。三个地标原卡面费用为1/5/10、耐久均2；`{0}{1}`只表示这三份完整固定原行的运行时文字槽。效果展示是choice-only，不能作为独立物理法术或玩家程序的物理展示来源。已经实现的`TLC_101t`迅猛龙保留完整定义，不用替身，也不重新注册。

[35.0正式公告](https://hearthstone.blizzard.com/en-us/news/24267727/35-0-patch-notes)给出耐久和数值调整，并明确一费映光水晶不能选择。该原行、官网childIds和12份原附魔证据仍完整保存；实际制造域分别为6/7/7项，不按原数据存在就推断资格。

## 三段制造

`LocationRecipeProfile`声明物理战吼来源、一个原地标模板、完整有限效果域及统一使用行为。`LocationComponent`只声明一个实际效果的行为、使用或亡语时机、实际目标、空位要求和已知执行先后。

第一段提供全部三个费用；随后分别从该档完整域中随机提供三项、选择一项。第二次只排除第一项选中效果，先前未选项可以再次出现。[玩家原始说明](https://note.com/nagon1609/n/ne009f7672ad4)是该菜单与排除行为的历史直接来源，旧数值不用。菜单抽样、国服精确窗口仍归M6校准，不以此认证当前正式国服。

原请求、来源分配、完整候选、实际有序提供及MT19937前后状态保存在私有原事件。选择仍用普通`RequestChoice`与原手动或自动选择事件；自动战吼共用既有选择政策，不伪造手动输入。恢复从原提供继续，不重抽。三次选择合成一次普通`AddToHand`交付，满手溢出沿既有燃烧路径。

## 不可变卡面与使用

`LocationRecipe(template_card_id, first_card_id, second_card_id)`编码规范且有界的`custom-location:`标识，只含三个已审静态材料名。重复成分、跨档材料、禁选水晶、未知材料、递归或非规范编码均拒绝。`Registry.card()`纯解析原模板及两个成分，不写缓存或新增注册项。配方保留选择顺序；目标、亡语、空位要求由真实选中成分导出。未初始化模板不可手动使用。

`UseLocation`仍负责真实准入、原目标、耐久、冷却、死亡检查点及末次空位。只对配方地标的原`location_activated`记录配方与是否捕获主体；普通地标事件不添字段。原使用主体在通知和末次死亡前捕获，再经`BeginLocationUse`及`ContinueLocationUse`逐个执行原成分。

每个成分通过私有STEP取得同一原`SummonCause`和原`BoardPresenceReference`；即使来源已移除也保留原归因，目标离场再入场则不能被相同实体ID重新绑定。需要目标的复制失效时，其它实际成分仍沿原游标执行。中途发现或反应待选保存唯一下一游标，失败沿原事务回滚。

- 喷发间歇泉是原亡语，对当前全部敌人交付一次普通`DamageBatch`；不是每次使用的伤害。
- 皎洁月光用物理地标模板展示的`PlayerEffectSpec(kind='next_spell_damage_until_cast')`；生命周期与原CAST认领见[原契约](m3-next-spell-until-cast.md)。
- 符文铭刻用原`DiscoverFromPool`和原费用附件，不裁掉未知合格法术；正式生成池与实验宿主池独立。
- 咬人植物用当前友方角色的普通本回合`Buff`，不是新到场随从的持续光环。
- 巢穴沿原`SummonOrderedGroup`和物理入场召唤原迅猛龙；熔岩流沿原`GainArmor`；映光水晶沿带原驻留引用与固定数值的`CopyMinion`。

[国服玩家原始攻略](https://www.iyingdi.com/tz/post/5623494)明确记录：复制或迅猛龙与加攻同时存在时，先复制／召唤，再加攻，不随选择先后反转。声明用有限`after`表达这一真实依赖；该记录是历史玩家实测，不能替代当前国服全面校准。其余未得到当前独立时序证据的主动成分按选择顺序执行，作为明确本地政策保留。[35.4官方修复](https://hearthstone.blizzard.com/en-us/news/24266874/35-4-patch-notes)确认恐惧小道首末耐久差异已修复，但没有给出完整检查点顺序。

## 保存与玩家信息

六个有限效果类型追加到原机制类型表；没有新增模型字段、玩家账户或独立地标结算器。恢复核原完整制造阶段、抽样重演、原实际选择、一次物理交付、原激活、逐成分顺序和唯一未完成继续项；重算普通摘要不能绕过这些语义校验。这些是内部一致性检查，不是未签名存档的外部来源认证。

配方只在玩家已经能看见的实体上增加`location_recipe`，对方隐藏手牌不提供材料。完整原候选、抽样状态及内部工作事件不进入玩家DTO。该可见字段使观察版本递增；新有限工作类型和存档验证使内核、schema递增。实际版本、验证结果、已知差异和下一项只在原两份台账维护。
