local_pools先核全部25个原定义及元数据、真实低温贮藏定义，再纯构造十个完整声明。profile使用原公共标识excavate，在当前本地目标/模式下声明全部十一职业：死亡骑士、法师、圣骑士、潜行者、萨满、术士、战士有第四级奖励，恶魔猎手、德鲁伊、猎人、牧师只有三个共享阶。没有新进度器或新历史格式，继续由原Excavate保存终身次数、当前矿脉、层数、真实来源和池版本。

新profile的全部字段进入宿主绑定摘要，池版本同时包含完整新来源包摘要。所有池安装到新目标后才注册profile，最终统一validate。原local-2026-09-23/experimental的一成员阶表及不完整profile逐字段保留，原launch工厂不获取新profile；恢复不能把两个上下文混用。

## 事务、恢复和信息

冻结、原支付、一次实际发掘及手牌交付属于原施法事务。excavated反应等待时已接受的进度和奖励、随机状态不能重抽；选择失败保留待选帧，立即反应失败撤销冻结、法力、历史、实体和随机推进。满手只改变奖励的烧牌结果，终身进度和矿脉仍继续，奖励实体保持各自来源。

对手只获原公开进度和允许的场面信息，私有宝藏身份、内部profile/池版本、随机状态及帧不进入玩家接口。跨座位、独立注册表恢复、clone/回放继续沿原入口。

实际验证使用少量真实入口和已有公共能力：共享成员的种子只纯抽样准备，再以真实低温贮藏逐一取得；十一职业的相同进度能力集中核表，不为每个成员重复回放。原有池/源scope仍使用严格共享宿主保全；新增profile另做全字段旧profile保全，不能因共享观察器没有该轴而漏记。

这里的complete只指明确定义的本地名单。官方随机资格、权重、国服版本及规则边缘没有认证；普通随机法术、符文、传奇和过去来源的递归缺口仍独立登记。真实发掘表和低温贮藏接通不能替代全部专用池闭合。实际执行、结果与下一项只维护在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。
