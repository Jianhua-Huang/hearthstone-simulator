# 最高／最低费用弃牌选择

基础目标只补物理手牌的费用极值选择。必要本地代表是夜影主母BT_301与粗暴的恐怖巨魔TRL_551，各自弃掉一张最高／最低费用牌。当前执行、实际证据和下一项只维护在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。

## 原选择入口

原DiscardMatching.selection增加highest_cost与lowest_cost两个值；原字段、效果类型和解释器保持。DrawMatching及DestroyDeckMatching仍只支持原random／first，未知政策明确拒绝。没有新模块、候选账本、Effect类型、持久字段、事件、动作、报价器或执行器。

原zone_candidates先按当前手牌顺序捕获合格的物理CardReference，保留PoolQuery的原印刷元数据筛选契约。费用区间筛选仍读definition.cost，不将它改为当前费用，也不能借区间筛选假称极值。一个物理实体出现一次，同名重复牌仍是独立候选。

随后对每个合格实体调用已有纯quote_unselected_cost，比较CostQuote.amount。沿原局部费用、固有费用、有效费用光环、玩家CARD范围修正及最低费用查询；比较本身不支付、不消费有限用途、不修改资源、附件或费用历史。候选无需付得起，其支付账户类型也不改变数值比较。

先确定数值最高／最低值，再保留所有同值物理候选及原手牌顺序。空池不产生弃牌也不消耗RNG；唯一极值不消耗RNG；多个同值物理实体各一个权重，执行一次原RNG.choice。旧random即使单候选仍按原规则抽选，旧first仍按原手牌顺序取首个，不改变它们的行为。

## 原弃牌与继续结算

选中的引用交原DiscardCard，实际成功移区、原DiscardRecord、来源身份、信息政策、普通监听及本牌被弃主体仍使用原流程。选择本身不产生额外出牌、施法、抽牌、支付或死亡。

原count循环与续接保持：每次实际移区及其反应结束后，重新查询当前手牌和当前费用，再选择下一张。等待时保留原剩余DiscardMatching及selection/count，恢复后按新局面继续；不提前冻结整个多张候选批次。本次测试只证明原循环得到正确保留，不能据此宣称所有真实“弃两张”来源具有这一规则。

动作或选择异常通过原事务回滚状态、历史、续接及RNG。snapshot／clone／独立注册表replay复用原效果编解码与结算器。内部候选、实体epoch、获取身份、费用输入和完整弃牌历史不进入玩家观察；reveal=False仍按原私有弃牌政策处理。
