# 奇闻的独立构筑包基础

本项补 U08 中已确认的构筑资格缺口：普通校验拒绝不可收藏伴生牌，原开局钩子只能在对局里创建卡，不能证明这些卡是原始构筑成员。新增 `fabled_decks.py` 声明有限主卡与伴生身份，复用原构筑、实体及开局流程。实际进度与结果在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 有限声明与构筑输入

`Registry.register_fabled(FabledSpec(source_card_id, companion_card_ids))` 接受严格不可变的 `fabled-v2` 声明。主卡须为已知、可收藏、本职业的传说随从；伴生牌须为已知、不可收藏、同一印刷职业的可出牌卡，稀有度可为空。伴生身份非空、互异，不得包含主卡或由不同主卡共享。未知卡、缺失元信息和错误声明明确拒绝，冻结后不能更改。非空声明参与注册表指纹；空声明保留旧指纹形状。

`DeckSpec.cards` 仍然表示**完整原始物理卡组**。宿主可先用 `expand_fabled_cards(selected_ids, registry)` 将只含主卡的选择列表展开：紧接每张主卡插入该声明的完整有序伴生列表，返回新元组，不修改输入或使用 RNG。随后仍须执行普通 `validate_deck`。展开函数不校验最终容量、职业、符文、副本或格式禁限，不是导入修复器。

已完整展开的列表直接传给 `DeckSpec`。展开函数拒绝直接选择伴生牌、部分展开或未知身份；`Game.from_decks` 不自动补牌，不将不完整导入静默解释成另一副卡组。本项没有官方卡组字符串解析器。

## 主卡资格与名额

原主卡组中主卡与每张声明伴生牌均须恰好一份。只有完整、本职业、格式允许且未禁用的主卡组，才为这些伴生身份提供不可收藏资格豁免。伴生牌自己的格式禁限、职业、符文及 `deck_identity` 合并检查仍执行，成员身份组的副本上限固定不超过一份；缺主卡、漏成员、重复成员和无声明不会获得豁免。生成或后来打出的主卡不能追加原始伴生牌。

普通奇闻的本地政策将伴生牌计入原来的30个物理名额，不建立32张牌库。依据是[本地完整链表审计](../outputs/fabled-basics-20261010/local-deck-membership-audit.json)：5905、6005、6050三副普通构筑预组牌的链表都完整终止于0、无环无孤儿，30个槽中希尔瓦娜斯、奥蕾莉亚、温蕾萨各一份。5382是神奇的威兹班特殊配方，三者各两份，已明确排除普通副本政策的依据。

这是客户端数据支持的内部政策推断，尚非国服服务器执行证明。[国服扩展公布](https://hs.blizzard.cn/news/24226328/)确认奇闻携带关联传说及三姐妹关系，但所读公布没有明确30张名额和导入行为。竞技场起草／重抓政策不适用于本构筑契约。

本批只审查本职业原主卡资格；侧板中的奇闻来源明确报 `fabled_scope`，伴生豁免也不向侧板导出。其他机制带来的异职业资格及跨机制特殊来源后置，不在本项扩展。

## 空稀有度与奇闻强化版

V1将伴生牌限制为传说；V2依据真实伴生记录及[官方卡牌库索引](https://hearthstone.blizzard.com/fr-fr/cards/119433-tiny-rafaam/)允许保留空稀有度。只有完整、合格的原构筑包成员豁免缺失稀有度校验；其他普通牌仍明确报错。原始 `ELITE` 标记继续作为原始证据保留，不用它填造不存在的 `RARITY`。无论稀有度是否存在，成员身份组最多一份，不能借通用两份默认值或 `max_copies` 放宽。

奇闻强化版沿同一有限成员声明与已有 `DeckSizeRule(ROOT, 40)` 表达；主卡与九个伴生占十个物理名额，另外三十张普通牌，另一玩家仍可为普通30张。它不附送初始生命修改，不额外建立49张卡组或开局生成流程。奇闻强化版适配须明确注册容量与成员两条声明，不能从关联列表推断补齐；省略适配声明不能宣称已支持该真实关键词。

[十一条完整原始记录](../data/support/fabled-plus-basics.json)包括 TIME_005、九个带伴生标签的拉法姆及被排除的绵羊衍生面。[国服34.2推广](https://hs.blizzard.cn/news/24244424/index.html)与本地卡文支持主卡加九伴生和40张方向，精确稀有度判定、导入与国服服务器政策仍待校准。此处只在隔离构筑专项建立身份及静态卡面；战斗主体未适配，尝试出牌明确报错并回滚，不宣称十张拉法姆已支持，也不将它们加入生产卡池。

## 原实体、生命周期与战斗行为

完整成员由原 `Game.from_decks` 一次创建为普通实体，共享现有洗牌、起手、换牌、硬币、回合及原始卡组记录，没有额外开局结算器、生成事件或持续资格光环。主卡之后打出、沉默、回手、变形或死亡，不撤销伴生牌的原始构筑身份，也不重新展开。

只在隔离专项接入 TIME_609／TIME_609t1／TIME_609t2 三个[完整原始记录](../data/support/fabled-basics.json)。基本战吼分别调用原伤害批、牌库增益及发现管线；每次普通出牌支付一次。原出牌历史决定实验重复次数，发现使用明确三张法术的合成实验池，等待选择沿原解释器推进。这些主体适配验证本构筑包能使用既有战斗能力，并不认证完整正式发现池或所有重复窗口。实验主体当前在根生成效果时捕获次数及目标；重复期间的新目标重取等精确行为仍留待真实接卡与校准。

生产代表包64及合成包3保持，没有批量接卡、组合矩阵或新的战斗处理器。

## 保存、恢复与玩家信息

首次落地规则为 `prototype-v179`；当前规则 `prototype-v190`、声明 `fabled-v2`，旧V1声明明确拒绝。效果 `core-effects-v184`、schema179拒绝1～178、观察74／命令11／replay1均保持。奇闻构筑本身没有新增状态、效果或保存字段，规则标识变化后旧规则存档仍明确拒绝；当前共享[场面费用](m3-board-minion-costs.md)及[手牌数量费用](m3-hand-count-costs.md)新增默认费用叶，注册表指纹与费用保存格式随之变化。

声明指纹、原 `MatchSetup` 和玩家原职业／符文／完整原牌序共同绑定构筑身份。稳定边界校验原身份，不根据当前牌库或场上主卡重新授予资格；重算状态摘要也不能隐藏原配置不一致。该一致性检查不认证未签名存档的外部来源。

独立注册表恢复、clone、待选恢复、回放和异常回滚均沿原框架。玩家观察不包含原隐藏牌序、伴生映射或宿主原构筑记录；完整宿主快照不能提供给玩家。

## 剩余范围

U08整族仍开放。奇闻强化版的40张容量、九张实际伴生身份与空稀有度构筑基础已内部验证，复用已有容量与成员声明；完整战斗主体、生成来源及国服政策仍开放，不能将全部 `related_dbf_ids` 当作伴生列表。其他职业奇闻、正式合法／生成池、完整主体和卡组字符串导入归既定接卡范围；本地名额、原身份、生成与战吼精确政策待M6国服校准。M0、M6、M7及基础目标不因本项关闭。

当前共享费用API为prototype-v190/core-effects-v184/schema179，拒旧1～178。新增[本局实际法术法力费用](m3-player-spell-mana-costs.md)复用原物理出牌/付款，不改变本契约自身资格；精确CN仍待校准。
