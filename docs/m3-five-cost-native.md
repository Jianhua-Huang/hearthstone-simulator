# 五费随从与原执行结果

[完整来源包](../data/cards/five-cost-native-v1.json)保留八张真实根卡、霜灼龙裔和五条原附魔记录。附魔由既有类型化附件表达，不注册为可使用卡。执行进度、实际验证、差异和下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。

## 卡牌表达

- 钟表发条暴怒者读取`owner_turn_index`，包含本人的当前实际开始回合；不用全局回合奇偶、入手时点或敌方回合数。永恒龙士兵调用`DoubleStats(attack=True)`，翻倍实际攻击力。
- 霜灼巢母查询原物理手牌中随从的真实黑暗之赐身份附件，复用`public_gifts`的纯身份解析；零属性关键词赐福仍有身份，普通增益或场上赐福不满足“手牌”。两次带归因的`SummonByCard`指定完整FIR_901t，容量和召唤替换由公共层负责。
- 昔时古树使用两次本人开始的原休眠倒计时，以及独立`dormant_trigger`和`EndTurnSpec`。只在休眠时参加本人结束接受；护甲后抽牌均为原效果，唤醒后不继续获得奖励。
- 狱中老鸟使用原重复手牌进度监听，只响应自己的`card_prepared`，将该事件实际投入法力`amount`交给`ModifyStoredCost`。预备卡额外的一点优惠不进入老鸟减费。它本身没有预备动作；离开手牌后不再监听，当前复制沿原能力与局部费用复制流程。
- 聚积旋风只响应自己的原`attack_declared`，校验原窗口ID、源、目标和事件游标后，向声明目标交付3点`MINION_ABILITY`伤害。原`ResolveAttack`随后负责合法战斗或取消；不创造第二套攻击流程，也不受法术伤害加成。延系走原随从`on_play`和有限profile，满足时授予突袭；不将其声明为战吼或在效果召唤时执行。

## 两次原抽牌与原来源奖励

跑路狂猪使用`DrawPhysicalGroup`的两个普通顶牌slot。新增有限奖励`source_charge_if_both_minions`，只捕获原来源的`BoardPresenceReference`，要求两次slot且来源实体相同。

条件读取这两个原`DrawRecord.card_id`的种类。爆牌仍是实际抽到的原卡，疲劳没有卡面；抽到时施放的法术根不会因补抽到随从而被重写为随从。抽牌反应中的额外抽牌不属于原组。条件和原组完成后，原连续驻留仍存活、活跃才交原`GrantKeyword(CHARGE)`；离场再入场或新建同名卡不接收旧奖励。连续变形或控制变化沿原驻留政策，其他奖励仍只操作各自原手牌引用。

此字段不新增GameState账本、计数器或玩家可见信息。当前同一实体缺少有效场上来源的战吼仍执行两次普通抽牌，不能为了保存来源引用而取消其正文。

## 实际消灭组与资源奖励

锯骨巨魔捕获其他存活、活跃友方随从的`MinionReference`，提交`DestroyMinionsForResources`。解释器在同一handler中调用原`DestroyBatch`，保留完整原目标计划、原死亡起点和逐目标实际`DeathCause`，普通死亡检查点和亡语沿原调度器执行。

`CompleteDestroyedResources`按原目标顺序重连不可变死亡原因，核对原来源、控制方、卡面、区域epoch和入场顺序；不能只比较实体ID或数本次新增的全部死亡。实际死亡必须属于原死亡起点之后；原已接受但暂缓的毁灭沿既有献祭的defer政策。额外亡语死亡、复生新体、亡语召唤物和后续重入不增加次数。原来源随后死亡也不删除已接受的原玩家资源奖励。

最终数量交给原`Draw(N)`和`RefreshMana(N)`，抽牌、容量、疲劳、法力上限、等待选择、异常回滚和终局保持原执行器。没有新增死亡检查点或私有可变计数。恢复时重核完整原目标与原已接受原因，不接受裁掉单条原因或借用其他实体的原因。

## 保存与证据边界

新增类型化销毁请求和续接注册到原机制与frame codec。抽牌奖励增加一个有限原来源字段；CardDefinition、GameState、Entity和历史账本结构不变。core372/schema297拒绝旧1～296，玩家观察87、命令12、回放1保持。

当前中英文卡面比对只证明卡面和固定子卡身份。抽牌替换链条件、连续变形/控制后奖励、消灭后抽牌与回费顺序、暂缓死亡以及攻击/奥秘/重定向顺序仍为M6本地规则，待国服证据校准。完整标准池、生成池、其他原生参数来源和阶段发布验收分别保留，不能用本批注册数关闭这些要求。
