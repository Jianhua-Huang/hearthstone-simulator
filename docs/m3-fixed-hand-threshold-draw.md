# 固定手牌缺口补抽：复用现有 Draw

B228 核对的是既有基础能力的表达和生命周期，没有新增引擎机制。实际进度、验收与下一项仅维护在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md)。

必要代表 REV_509 放大战刃在原 `attack_finished` 捕获窗口判断完成攻击的英雄是否属于载体玩家，然后一次计算 `max(0, 3 - 当前手牌数量)`，交给原 `Draw(player_id, count, source_id)`。count 为零时不产生抽牌记录；大于零时原解释器依次执行已有 `draw_one`，原疲劳、自动施放、替代抽牌、等待恢复、回放及信息边界继续生效。没有独立循环、计数状态、随机路径或资源账户。

这是明确的内部初始缺口政策。空牌库时仍只执行初始缺口个有限抽牌尝试，不能递归到英雄死亡。补抽期间如果其他效果改变手牌，是否应动态停止，以及精确武器最后耐久捕获与交付窗口，仍需国服证据；这次表达验证不能证明这些官方细节。

原装备管线在最后耐久损耗时捕获已完成攻击的武器监听，再按原死亡和触发管线交付已捕获主体。后续 Draw 使用原物理武器来源，即使该武器已经进入墓地。原抽到自动施放牌的选择暂停可恢复该补抽链，不另建武器选择解释器。

只适配 REV_509 必要实验定义，3费、3攻击、2耐久、恶魔猎手普通武器；CORE_REV_509 只保存完整原始证据，其耐久字段形式不同，不作第二个执行适配。原冲突、付款、攻击次数、区域移除及异常回滚均复用公共流程。基础代码、prototype-v296/core-effects-v296/schema260 和观察84/命令12/replay1保持。

[官方卡库](https://hearthstone.blizzard.com/en-us/cards/78123-magnifying-glaive?class=demonhunter&set=standard)确认英雄攻击后补到三张的卡文、类型和职业；[24.0.3公告](https://hearthstone.blizzard.com/en-us/news/23840665/24-0-3-patch-notes)确认3攻击及2耐久。两者没有确认上述初始缺口、疲劳及精确国服窗口。完整本地数据见 [隔离支持文件](../data/support/fixed-hand-threshold-draw-basics.json)。

玩家接口只提供可见结果，不返回完整抽牌历史或工作帧。旧模块不因缺少专用“抽到N张”接口而判为未实现；遇到真实不同停止规则时先判断已有 Draw 与后续行为调用是否能表达，再按证据决定公共扩展。
