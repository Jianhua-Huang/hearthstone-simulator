# 固定洗入卡与原实体抽到时召唤

实际进度、证据、差异和下一项仍只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。本页限定真实卡对已有税费、洗牌和抽牌管线的使用方式，不增加随机生成池或独立结算器。

## 完整卡面与依赖

[固定配方](../data/cards/fixed-shuffle-followup-effects-v1.json)保存每张完整37.0原行及摘要。强力裁决（CAP_404）使用已有CAP_400t2t卧底小鬼，其完整定义摘要也固定；不创建一张同名白板小鬼。审讯（TLC_518）的官网关联为119563，即TLC_513t2忍者始祖龟，不按名称猜成TLC_518t。忍者为3费3/3、潜行和抽到时召唤，没有印刷随从种族。

这三张新定义都没有印刷法术学派，卡牌代码不据标题补写学派。官网关联、费用、身材、职业、类型与完整去格式正文逐一对照固定源；卡面存在仍不认证完整正式合法池或国服时序。

## 固定洗入与真实下一回合加费

强力裁决先给实际对手安装独立普通持久玩家实例，再向该对手牌库洗入两张完整卧底小鬼。实例复用已有下一回合随从加费回调：收到受益玩家真实turn_started时移除本实例，并安装当前真实回合到期的普通随从+2费用修正。原来源仍是实际施放的强力裁决，不借用焦油狂潮的来源实体或卡牌身份。

多次实际施放各自有原实例和来源，按原费用相加；尚未开始的效果、其他额外回合及被跳过的槽位仍沿[原未来费用契约](m3-paid-minion-price-keywords.md)。普通卡牌费用、英雄技能、交易等作用域不因复用回调改变。

审讯向实际施放者牌库洗入三张忍者。两张牌都使用recruit_cards.shuffle及公共deck_shuffles.shuffled，保存实际发起玩家、接收牌库、来源和完整声明数量。一次主体的多张插入只是一条语义洗牌记录；重复的真实施放是不同记录。放入对手牌库不会伪造施放者洗入自己牌库的历史。随机位置和失败回滚沿既有RNG/事务。

## 抽牌身份、补抽与生命周期

忍者直接使用原HandProgressSpec事件声明和cards.recruits.physical_draw条件。必须核对实际DrawRecord、HAND成功结果、原物理实体及抽牌玩家，才执行原draw_drawer回调；生成到手、普通手动出牌或效果召唤都不制造抽到时召唤。

回调先公开实际已抽牌，再将同一CardReference交给既有SummonStoredCard，在实际抽牌者一方召唤，最后为原抽牌者补抽。卧底小鬼继续使用原对手召唤回调，所以由谁施放强力裁决不取代实际抽牌者/召唤接收方。潜行、吸血、容量、沉默、离手、复制及成功召唤事实都由原能力与区域管线负责；不按同名牌扫描手牌末位，也不生成替身代替原实体。

现有内部政策是满手烧掉没有成功HAND获取的牌，不触发该手牌回调；满场则公开并保留原手牌，仍补抽。连续抽到忍者/小鬼会按原管线继续，直至普通牌或疲劳。待选保存原实体、补抽尾部与原付款，恢复/克隆/回放不重抽或重复召唤；后续异常回滚整次动作及RNG。精确国服烧牌、满场补抽及这些反应窗口仍待M6校准。

## 兼容与信息边界

内容装配增加新卡、行为和玩家实例定义，公共内核、存档字段、效果/载荷类型及协议版本不变。当前构筑内容身份变化，旧构筑存档不能仅因schema相同就直接混用；默认代表内容及其实际旧存档单独核对。全知快照与完整牌库/洗牌历史只用于内部证据，玩家仍通过既有投影和命令DTO观察、操作。
