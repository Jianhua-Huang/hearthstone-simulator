# 跟随法术与原实体出牌后附件

固定源为37.0.0.255026的CAP_002、CAP_101、CAP_402和CAP_802。完整十二原行、十二双语主面、既有两个随从定义的哈希及本地政策保存在`data/cards/follow-hand-v1.json`。六张附魔行只作原始描述证据，不注册可执行卡牌。

## 原生效果

- 跟随足迹：沿现有完整宿主池发现当前职业或中立的潜行随从；在新体首次创建通知前安装同一跟随效果。
- 跟随引线：沿原随机伤害管线对随机敌人造成基础2伤害，再向手牌中一个符合价格条件的当前海盗授予同一效果。
- 跟随证据：沿原语义洗牌，将既有CAP_400t2t卧底小鬼加入对方牌库，再给一张符合价格条件的手牌同一效果。原3/3、吸血和抽到后为对手召唤的定义及主体保持。
- 跟随幽灵：用原普通召唤创建既有CAP_802t的2/1复生幽灵，再给一张符合价格条件的手牌同一效果。

三种手牌随机授予按当前手牌实体等权选择。当前价格由原报价器计算，本地“可用”政策为报价数值不超过剩余法力；不做目标、场地容量、卡面要求和完整合法动作搜索。引线还检查当前海盗种族。空候选不消耗随机；不会从发现池删去未实现的合格内容。

## 附件和完成边界

`GrantAfterPlay(CardReference, behavior_id, source_id)`只接受原手牌驻留；过期引用不作用于后来重入的新驻留。`GrantRandomAfterPlay`只负责上述价格/种族查询、一次随机和同一普通安装。附件使用既有AbilityInstance的行为和期限字段，新增有限`after_play`族：纯授予、当前全局回合期限、无混合规则。

原`prepare_play`将完整有序附件元组捕获进`PlayRecord.after_play`。`FinishPlay`先完成原卡和`card_played`通知，再由`RunAfterPlay`按原元组顺序调用已登记主体。它不重打卡牌、不创建额外施法、不复用战吼/连击次数，也不在普通召唤时执行。卡牌主体中的等待、死亡、沉默或移区不重写已接受的元组。

携带法术使用普通法术伤害；随从使用普通随从能力伤害，其他类型使用效果伤害。继承的召唤/发现/洗牌由实际已打出载体和玩家发起，不能假装重新施放原始跟随法术。

存储、当前复制、基础复制、沉默、回手重置与所有区域的回合到期沿原附件生命周期。新生成的足迹随从使用有限`CreatedMinionGrant(special='after_play', identity=behavior_id)`，与现有创建安装器共用时点，正常溢出政策保持。此处identity只引用行为，不额外生成永久的空数值附魔；旧数值/标签授予政策保持。

## 保存与证据边界

PlayRecord增加实际附件元组，core520/schema418拒绝旧执行格式；没有新增玩家计数器、独立过期时钟或第二套卡牌执行器。帧只保存已登记的行为名及普通附件，历史拒绝错误族、期限、重复或未分配身份。新原接受材料不进入玩家DTO，仍用原命令、随机保存和事务回滚。

当前元组的准确接受窗、完成通知与其他反应顺序、反制携带者、额外资源支付资格、跨玩家复制/期限以及叠加与重复的精确国服交互仍待M6。本地完整出牌包含完成的被反制载体；原跟随法术自身若被反制则不执行主体。测试不能据此认证全部官方组合规则。严格卡面核对不证明已锁定全部正式生成资格或可达内容；结果、数量和下一项只写入原两份台账。
