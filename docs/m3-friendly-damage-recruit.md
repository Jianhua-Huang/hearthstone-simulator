# 原友方受伤事实与存储召唤

突牙JAIL_421（Warptooth）使用[完整原行与双语主面](../data/cards/warptooth-v1.json)：4费3/3战士传说野兽，冲锋，本人某个回合四个友方角色受到伤害时从手牌或牌库召唤。[官方36.0.3补丁](https://hearthstone.blizzard.com/en-gb/news/24290431)明确将三个角色改为四个，固定37.0来源与完整卡面一致；精确国服热修与窗口仍独立核对，[来源记录](../outputs/card-integration-20261014/k273-tuskgrowl/rule-sources-01.json)保留证据范围。

卡牌只组合现有`damage_records`、重复单事件`HandProgressSpec`和带`SummonCause`的`SummonStoredCard`。没有新增公共执行器、Effect、payload、模型字段或GameState账本。声明只在严格有序的`(HAND, DECK)`范围监听原`health_resolved`，战场身体不参与此存储监听。

条件读取原实际伤害结果：最终流为DAMAGE、实际`damage_dealt`大于零，原目标控制者和原活跃玩家均是本牌玩家，且属于本次实际回合。护甲吸收仍是承伤；圣盾、免疫、零量和纯治疗不计。角色按原`(target_id, target_zone_epoch, target_entered_order)`去重，重复打同一驻留不等于不同角色，不用卡名或之后的控制权重解释原事实。

整批伤害先完整提交历史，再逐条通知。条件沿原历史读到当前真实结果为止，只授予包含当前包的原前缀，不能在第一条通知借用后续包的信用。缺少原结果明确报错，不凭事件次数补猜；回溯、失败和恢复继续采用旧伤害历史的有效事件政策。

完成回调冻结原存储`CardReference`，沿普通物理移动和召唤入场，保留原实体，使用普通容量、区域和生命周期；不扣本牌4费，不伪造抽牌、手牌使用或战吼。原监听身份和原引用保护中途移区，旧手牌请求不能追到同ID新牌库驻留；后续新事件可以让新监听正常执行。多个原物理来源各自接受，沿旧手牌优先、牌库物理顺序，不按同名去重或额外随机。

满场原尝试保留隐藏实体，之后合格伤害可重试；门槛之后才获取的本牌只监听后续合格伤害，没有额外状态轮询。按驻留去重、原包前缀窗口、满场重试、新获取和精确存储捕获顺序是明确本地政策，仍待M6。论坛玩家报告只作为调查线索，没有冒称开发者确认。

恢复、clone、回放、待选失败及整根失败沿原管线。内核core551/schema445、观察99、命令12、回放1全部保持，旧默认快照与全部公共源码保持。实际进度和验证仅在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。
