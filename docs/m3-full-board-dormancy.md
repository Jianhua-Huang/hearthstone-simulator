# 原生满面板休眠条件

本契约描述灰烬虫实际需要的有限条件。实际进度、验证证据、差异和下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。

完整配方见[固定原行](../data/cards/full-board-dormancy-v1.json)与[适配](../hs_sim/cards/full_board_dormancy_cards.py)。CardDefinition.dormant_board_full只允许显式布尔值；true要求普通、非永久、无限期休眠的随从。它安装一个可被沉默移除的原生board_full_awaken能力，不通过不相干的事件名组合猜测满场。

在原规范化流程中，条件读取物理载体的当前控制者、实际player.board长度与Ruleset.max_board。地标、休眠随从及其他真实面板占位都计入，不能写死七随从或只监听minion_summoned。没有合格来源时直接返回，不扫描待执行队列；有来源时按原Ruleset的行动方及入场顺序处理。

条件接受后只生成已有AwakenCapturedMinion，绑定原MinionReference及休眠实例ID。已有队列和本次捕获中相同实体/休眠实例的请求不会重复加入；请求自己进入可恢复的原队列，不建立不可保存的pending集合。真正唤醒仍由原休眠模块负责：无第二次召唤/战吼，重设正常攻击准备，执行已有唤醒主体及后续反应。原接受时满场后又腾空是否仍应唤醒、与死亡检查等准确窗口目前为本地政策，仍须国服证据校准。

沉默移除该能力；当前复制按原附件复制保留独立载体的条件，恢复和转控读取当前物理载体/控制者，不按原来源副本的面板判断。变形、回手、重新入场和新休眠实例均沿原生命周期。初始Scenario中的已满面板也通过同一唤醒执行器规范化，不留一个只能等玩家命令修复的初始状态。Scenario仍是实验入口，不能据此认证正式标准构筑。

新能力kind只有原生、可移除、未消费的空声明，不接受授予来源、主体或其他载荷；实际和冻结死亡载体须有对应印刷声明。新增定义布尔字段的false仅从旧签名/PIN视图省略，true始终参与签名；旧asdict会多出false，不能声称原字节不变。没有新增GameState字段、效果类型或随机状态。该语义使用core358/schema283，旧1～282存档须使用原引擎，默认代表包指纹保持不代表跨schema兼容。
