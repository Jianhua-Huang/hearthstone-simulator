# 生成随从的创建属性

JAIL_448崩坏的卡洛夫的原生亡语获得三张随机传说随从的1费1/1复制；CATA_136艾萨拉的胜利将五张原费用至少8的随机随从洗入牌库，属性翻倍。两者生成新的基础实体，不复制某张已有手牌。完整原行及两张附魔证据保留在[数据包](../data/cards/generated-minion-stat-v1.json)，附魔行不注册可执行占位。

`CreatedMinionStats`是独立的不可变创建声明，使用`set_to=SummonStats(attack, health)`或`double=True`其中之一。设值必须同时提供攻击和生命；翻倍在实际新实体创建时冻结其当前无伤属性为一次加值，沿普通Enchantment和refresh_entity执行，刷新不会再次翻倍。旧CreatedMinionGrant及黑暗之赐配方结构不变，不将数值操作编码为卡牌专用special字符串。

AddToHand、AddToDeck和GenerateFromPool用`minion_stats`转交声明，必须保留真实来源，只允许随从。新实体在第一次card_created、获取、溢出或牌库插入通知之前已有完整属性及独立费用附件，包括烧毁结果。声明不搜索同名手牌、不改旧实体，也不改变原印刷池资格。现有复制、抽牌、正常出牌、沉默和回手生命周期继续负责后续材料。

随机生成仍先核完整候选，再一次选出所有原结果。数值声明目前只允许有来源的可收藏随从手牌/牌库生成；与临时牌、法术附件、其他创建增益或场上交付混用会显式拒绝。普通发现、黑暗之赐及复制入场声明没有因此扩大。

艾萨拉的胜利用GenerateFromPool的`shuffle_actor_id`保留实际操作者，将已选好的AddToDeck组交给原ShuffleDeckCards。五张实际插入共同构成一次语义洗牌，实际插入仍各自消耗位置随机；空候选没有洗牌操作或随机消耗。此有限入口目前要求数值生成、真实来源及随机牌库交付，不借此改变普通位置放置。

core410/schema330增加一个payload类型和四个已有请求字段（AddToHand/AddToDeck各一个，GenerateFromPool两个），拒绝旧schema1～329；无新状态、实体、能力或历史字段。默认311内容指纹保持。保存、回放和玩家信息仍走原管线；玩家只能得到普通公开属性和本人可见手牌，不得到创建配方、完整牌库或内部证明。

精确国服创建/反应顺序、固有成长与翻倍的相对次序、来源排除及重复窗口仍待M6证据；正式标准池及完整可达内容未闭合。此契约不作官方支持声明。实际专项结果、修复过的测试夹具及下一项仅记在两份原台账。
