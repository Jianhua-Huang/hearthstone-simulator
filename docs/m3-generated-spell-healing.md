# 原随机法术结果与费用治疗

`GenerateSpellsAndHeal`表达真实法术“获得随机法术，再按这些法术的费用治疗”的有限需求。请求必须绑定原活动物理施法、来源、玩家和可收藏法术查询；没有独立随机器、卡牌侧治疗结算器或新状态账本。TIME_018修补时间线使用神圣学派、两次有放回抽样及原生回溯声明。

接受时复用完整生成候选与创建费用校验，再用原游戏RNG一次捕获全部结果。私有接受事件保存原请求、施法接受事件、来源分配、池上下文/版本、捕获职业、完整有序候选与整数权重、选中序列及RNG前后状态。未知合格候选在抽样前报错；空池保留空收据且不消费RNG。交付继续使用普通生成、获取反应和手牌溢出规则，不从最终手牌差推断结果。

`CompleteGeneratedSpellHealing`在全部交付反应后、原施法完成前执行。它按原选中卡面的印刷费用求和，向实际施法者的当前英雄提交一次普通SPELL治疗批次。满手烧掉的结果仍参与原费用和；获取后改费、转交及额外随机不会替换原选中序列。费用依据、合并为一次治疗及精确交付窗口是本地内部政策，仍须M6国服校准。

健康提交直接复用`settle_health_batch`共同原语；治疗完成收据绑定原接受序号、真实健康批次、来源、玩家、目标、种类及基础量。返回既有健康反应后可以继续等待，此时原治疗已提交，恢复不得重复。三个完成数值要求严格整数，拒绝等值浮点数或布尔值。没有为本卡增加HealthResult字段或第二套生命修改逻辑。

边界验证重算完整候选并局部重演原抽样，不消耗游戏RNG。每个未完成根必须有且只有一个原完成控制，位于同次FinishSpellCast之前；玩家选项不能注入它。已完成根必须有唯一真实健康批次。实际终局可中断交付，不能凭空要求后续治疗。回溯保留旧诊断收据，以effective_events区分当前根，重试建立新事件身份；这不声称无签名外部存档具有来源认证。

typed帧复用现有Event、SourceAllocationFact和GenerationContext编解码。新增两个Effect类型，core433/schema351拒绝旧schema350；没有新增已有Effect字段、payload类型、GameState/Entity/Ability字段。私有接受/完成事件和帧仅用于全知保存，不进入玩家DTO或玩家事件。

验收及实际执行状态只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护；完整标准生成池、M0及M6仍独立开放。
