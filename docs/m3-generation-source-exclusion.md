# 普通生成的来源排除与条件消费者

普通 `GenerateFromPool`、`DiscoverFromPool` 及复用该候选入口的随机召唤/施法，在抽样前排除来源的可收藏卡牌及已审核的同卡版本。排除先于可执行定义检查；其他符合资格但未实现的内容仍明确失败，不能缩成已实现名单。没有来源的宿主查询不猜测来源。

依据是官方 [18.0.1 热修](https://us.forums.blizzard.com/en/hearthstone/t/1801-server-hotfix/39314) 对发现、随机生成自身的限制，以及 [28.0](https://hearthstone.blizzard.com/en-us/news/24008693/28-0-patch-notes) 和 [28.4](https://hearthstone.blizzard.com/en-us/news/24046221/28-4-patch-notes) 修正不同系列同卡可被发现的问题。18.0.1 同时明确本人牌库中的另一张同名实体仍可被发现。将这些历史规则延续到固定37.0属于有来源的实施判断，不能代替精确国服校准。

`Registry.register_generation_family(sorted_unique_tuple)` 注册不可重叠的版本族；至少两个非空ID，未知可执行定义允许作为独立身份元数据存在，不能据此创建占位效果。声明及派生索引参与验证，非空声明进入注册表指纹。它不改变 `PoolCard.generation_identity`、候选权重、候选数量或构筑同卡数量规则。

构筑包固定数据有258个版本族、262条关系、520条完整原记录。256张当前核心卡的260条明确客户端关系全部保留；其中四张同时指向较早原版和后来的重印。另两张核心重印逐张核对原行及中英官网卡面。此范围没有穷尽所有历史或实际可达版本，不能按名称或 `CORE_` 前缀推导遗漏关系。“呓语书柜”与“满怀希望的树妖”是两张不同卡；前者恢复为自己的构筑身份。

纯 `resolve_candidates` 默认保持查询语义；实际生成入口及其发现、随机召唤、分组候选、手牌选择续接和冻结法术批次的收据验证，显式启用 `exclude_source_by_rule=True`。纯变形候选、装配候选、物理牌库/手牌选择及固定具名配方沿各自已有语义，不因本条规则一律排除同名实体。原显式 `PoolQuery.exclude_source` 保持原独立含义。

没有新状态、实体、能力、请求或载荷字段；schema323布局保持，机制签名升级为core402。空版本族的默认代表注册表指纹保持。旧机制快照不能冒充当前规则存档。

三张真实条件消费者只组合已有能力：

- 妖术长官始终从显式池获取印刷费用至少5的法术。真实起始卡组没有法术时附普通永久减5，条件不决定是否生成。必须有真实开局事实；任意Scenario不能从后来手牌/剩余牌库推断原卡组。
- 虚空幽龙史学家在执行时用既有当前种族查询检查手牌中的龙，包含全部种族，再发普通龙随从发现。
- A3型机械金刚用既有存活友方随从查询检查另一机械，排除原物理来源自身、包含全部种族，再发普通机械随从发现。另一张同名实体能满足条件，但来源同卡版本不能成为该次普通发现选项。

隐式发现职业/中立资格、存活载体政策及精确条件执行窗仍沿已有内部契约，待国服校准。全部需要宿主显式 `GenerationContext` 和对应 `constructed.cards` 资格池；本批不建立正式生产池。
