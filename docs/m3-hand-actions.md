## 1. 动作与定义

卡牌定义新增不可变的 `hand_actions: tuple[HandActionSpec, ...]`。每项具有 `id`、`kind`、`cost`，以及可选的 `upgrade_card_id`、`on_use` 和默认 `always` 的 `use_rule`。本页原批次描述 `trade` 与 `forge` 两种操作；独立 `prepare` 已接入同一手牌动作管线，动态报价与一次状态按页首的预备契约处理；同一张牌可以声明多个不同 ID 的操作。未知种类、重复 ID、缺失升级形态、跨类型升级和未注册回调在对局开始前拒绝。

```python
HandActionSpec('trade', 'trade', 1)
HandActionSpec('forge', 'forge', 2, 'TTN_042t')
UseHandAction(player_id=1, entity_id=card_entity_id, action_id='forge')
```

`UseHandAction` 是正式外部动作，与出牌、攻击和技能并列，进入动作编解码、历史、合法枚举和回放。它要求自己的手牌、行动回合、足够费用，以及声明的使用条件。等待选择时只能处理该选择。普通出牌的目标要求、战场容量和战吼不约束手牌操作。

扩展点是声明、纯条件和返回公共效果的行为；卡牌代码不自行移动实体或扣费。交易/锻造本身不发出 `card_committed`、`card_played` 或 `minion_summoned`，也不会增加英雄技能次数。后续地标/星舰的场上主动操作还需自己的实体与使用规则，不能伪造为手牌操作。

## 2. 独立费用与合法性

`Game.quote_hand_action(entity_id, action_id)` 返回不可变 `CostQuote`。交易／锻造按各自动作声明消耗法力；普通出牌减费、卡牌本地费用附魔、法术费用光环和替代生命支付不会修改这一报价，也不会被它消耗。支付复用 `pay_quote` 与统一法力账目，先消费临时法力；费用不足时无副作用。

`use_rule` 与英雄技能共用注册表，但属于该手牌动作。`visibility='player'` 回调读取分离的 `PlayerRuleContext`，同一条件用于宿主验证、玩家提交和合法枚举。旧全知条件在玩家接口明确拒绝。直接提交手牌操作只检查该操作，不执行这张牌普通出牌的目标谓词。

交易／锻造仍使用声明的固定值；预备沿既有动态投入报价，不适用这一固定费用说明。交易专属费用光环、动态授予/移除交易和更广泛的替代行动条件没有被假装接入普通出牌费用层，列为 R-030；需要这些能力的卡仍须显式实现后才能适配。

## 3. 交易生命周期

一次交易按以下原型检查点执行：支付独立费用 → 在离手前记录交易牌公开身份 → 将同一物理实体随机插入牌库 → 从牌库顶部寻找第一张不同实体并正常抽入手牌 → 发出完成事件。插入使用唯一对局 RNG，不重洗原有牌序。抽到另一张同名牌是允许的；排除的是本次交易的物理实体。

- 手牌位置先释放，满手十张仍可换回一张而不烧牌。
- 原交易牌保留 owner、controller、实体 ID、附魔及能力 ID；它不进入墓地、不算死亡、不获得尸体。
- 进入牌库后双方的追踪句柄退休；抽回时获得新句柄，不能根据旧句柄追踪库中位置。
- 交易前空牌库时不可使用，不进入疲劳结算。该边界继续列入国服校准。
- 普通 `ShuffleIntoDeck` 仍按原契约重置附件；不会因卡有交易声明而改变。

内核在同一 `ActivateHandAction` 检查点中复用区域移动原语；支付、插入和抽牌的事件分别捕获当时状态，但反应在完整交换后执行。抽牌触发能够看到已在牌库中的交易牌。精确事件窗口是 R-029，不声称与官方内部执行栈相同。替换 `MoveCard` 的调度处理器不会自动改写这个原子操作；自定义交易语义需显式替换对应操作处理器并更换机制版本。

`on_use` 可表达“交易此牌后”的专用效果；其捕获上下文包括完成交换后的状态和 `card_traded` 事件。它在本检查点的普通反应后执行。终局会停止剩余工作；回调异常则整次操作回滚。

## 4. 锻造生命周期

锻造支付费用后在原手牌槽位修改同一实体的印刷形态，保留所有附魔和动态授予的能力及其 ID；新形态重新安装自己的印刷能力。普通出牌价格由新形态基础费用加现有附魔计算。一次性升级形态可以不再声明锻造；自引用形态可继续声明，重复效果通过 `on_use` 组合公共指令。

独眼突击者 `TTN_042` → `TTN_042t` 从 3/3 突袭升级为 6/5 突袭。风暴巨人 `TTN_724` 首次升级到基础六费的 `TTN_724t`，之后每次在同一形态附加减二费效果；可降至零费，再锻造仍支付两点锻造费用。厚重板甲 `SW_094` 可以一费交易，或按普通出牌费用获得八点护甲。这五条记录均来自锁定的本地数据快照，只声明实验适配。

锻造可在牌库为空或战场已满时使用；不抽牌、不入场、不执行战吼。原手牌的普通费用附魔不会改变锻造费。附件到期仍使用公共生命周期规则。

锻造的保留表与公开策略是明确的原型契约：对手看见原手牌槽位发生锻造，默认看不到新牌面；先前记忆的旧牌面不再作为当前身份返回，旧事件不会回填或改写。自身观察立即显示新牌面、费用与剩余动作。精确可见性、受伤/沉默/设值附件及重复锻造的事件窗口须 M6 校准。现有 `Buff`/`Grant*` 原语主要面向场上角色；广泛的手牌增益来源尚属 M5，不能因保留测试通过而宣称它们已全数实现。

## 5. 玩家接口、保存与回放

玩家命令只携带可见句柄：

```json
{"revision":"当前观察修订值","action":{"type":"use_hand_action","card":"e4","action_id":"forge"}}
```

自己的手牌新增 `hand_actions` 描述，包括动作 ID、种类和报价；对手手牌仍只有牌背/已知身份，不泄漏能力、费用或新形态。命令解码先检查所有权，再查询定义；无法借用对手句柄探测它是否可交易或锻造。合法列表仍按玩家字段排序，修订值只取可见观察。

交易会在离手前用 `trade_started` 记录公开的原牌，随后库中位置与抽到的新牌沿用私有区域策略；`card_forged` 只按当时权限显示槽位/牌面。任意原始事件数据不透传。详见 [信息契约](m3-information.md) 和 [玩家动作契约](m3-player-api.md)。

抽牌反应或专用回调请求选择时，沿用现有结算帧挂起、预算、恢复与失败回滚，不把未完成工作放入 Python 闭包。恢复后不会重新收费、插牌或抽样。新注册定义字段、动作类型和可见协议改变了指纹；schema 1～21 明确拒绝，没有隐式迁移。外层 replay schema 仍为 1。
