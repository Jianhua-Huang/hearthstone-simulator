# 原手牌期限契约

翡翠厚赠的“暂时不能使用”另用有限HandPlayLock，按既有真实本人开始计数纯查询，不用本页移除/摧毁期限冒充出牌资格，也不提高费用。完整原驻留绑定和复制/重置政策见[抽牌保留契约](m3-draw-retention-limits.md)。

`ScheduleHandRemoval(player_id, owner_ends, source_id=None, retirement='remove', cards=None)` 在 `cards=None` 时保存指定玩家在效果实际执行时的完整手牌；提供不可变 `CardReference` 元组时，只保存显式给出的原手牌引用。经过明确数量的该玩家自然回合结束后，退役仍满足原引用的牌。`retirement='remove'` 保留原非死亡移除，`'destroy'` 显式执行存储摧毁；未知值拒绝。`owner_ends` 必须是严格正整数，玩家只允许 1、2；未知来源和未知卡牌明确报错。

这是一项独立的公共区域能力。回合、死亡、区域、选择和回放仍由已有内核负责。实际验证结果与下一项只在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md) 维护；可核查的本次结果见 [验证记录](../outputs/bound-hand-deadline-basics-20261011/verification.json)。

## 保存与时钟

`GameState.hand_deadlines` 按接受顺序保存不可变的原请求、全部有序 `CardReference`、原来源卡面、接受回合与动作、原本人结束计数和原事件位置。接受时不移动牌，不占持续效果或奥秘槽。空手也保存一个完整的空根，不抽样、不消耗随机数、不覆盖未来收牌。

显式 `cards=()` 是一个确定的空范围，不能回退到整手。给出的引用必须同属请求的原目标 HAND/玩家，每个物理实体只出现一次，且是已有实体及已知区域周期；未知实体、未来 epoch、非手牌定义、重复或混合归属引用拒绝。已知旧引用可以保存，但不升级为实体当前周期；退役时仍沿原守卫跳过。原请求的完整显式元组必须与原根目标一致，私有接受收据区分 `hand` / `captured` 范围；待选也校验这些引用，不准通过恢复扩大到整手或裁去原目标。

时钟读取已有 `owner_turn_history` 的真实结束记录。对手的结束、本人开始、被跳过的调度槽不推进计数；实际额外回合的结束推进一次。由回合结束反应创建的新期限，接受计数包含已经发布的该次结束，因此从后续真实结束计数。

内核在发布自然结束前捕获本边界到期的原根；普通结束反应、结束主体收尾及既有玩家持续效果计时之后，执行这些原根，再进入解冻、当回合失效和回合交接。多个根保留各自期限，按原接受顺序关闭；后根看到原牌已经移除时记录空结果，不重复移除。

上述准确期限与先后顺序是明确的内部政策，尚未取得国服校准证据。

## 原实体生命周期

期限读取已有 `CardReference` 的物理实体、控制者、HAND、卡面及 `zone_epoch`。只有到期时仍同时满足这组事实的牌会移除。

- 出牌、离开手牌、转到牌库等行为使原手牌引用失效。
- 同一实体重新回手有新的区域周期，原期限不能跟随。
- 原手牌变形使原卡面引用失效。
- 后续抽牌、生成牌和复制所得的新实体不属于原目标。
- 原来源死亡或离场不撤销已经接受的期限。

对“献祭”而言，离区复入、变形、复制、重复标记与来源的准确国服政策仍待校准，不能把这些内部引用政策当成已核实的官方规则。

普通移除模式调用已有 `RemoveFromGame`，将符合条件的原牌移入 SETASIDE，不执行本牌的原生被摧毁效果。它不制造随从死亡、弃牌或牌库摧毁，也不触发亡语、复生或尸体资源。手牌中的随从、法术、武器、地标和英雄牌共用这一操作。

摧毁模式按原有序目标逐张派发 `DestroyStoredCard`，沿公共存储销毁路径入墓地、发布实际销毁事实和接受原生 `on_destroyed`。本牌主体及普通监听结算后才检查下一原目标，不吸收后来抽到、生成或复制的新卡。每一步仍检查原卡面、控制者和区域周期；已离区、变形或离区返回的原引用跳过。摧毁本身不是弃牌或场上死亡，不制造亡语、复生、残骸、抽取或施法；本牌主体的 Draw 等效果仍正常执行。

现阶段逐张处理、原引用生命周期及 `reveal=False` 延续既有隐藏身份政策，均为待国服校准的明确本地政策。不能用英文 all 推断同时摧毁，也不能将某张真实牌的变形或重复点燃政策自动套到所有期限。

## 待选、恢复与信息

`ExpireHandDeadline` 是内核的自然结束控制工作。待选保存原根身份、原自然结束事件与后续队列；恢复时检查全部到期根及其顺序，拒绝遗漏、重复、替换结束事件、冒用根或把控制工作藏进选项。普通结束反应引起的选择完成后继续原到期队列；普通移除及关闭先原子完成，移除事件监听者随后可以待选。

摧毁模式在原根保存开始事件、已完成原目标游标和实际销毁事件序列。私有开始、逐张接受和逐张完成收据绑定原自然结束、完整原目标、原引用及真实结果；不是额外时钟或第二个存储销毁账本。`CompleteHandDeadlineDestruction` 在原监听/本牌主体结束后确认实际结果，再继续原 `ExpireHandDeadline`。移区前的等待保留待执行的物理摧毁，移区后的等待保留本牌主体和原目标完成尾；双方均不能裁剪下一目标或把旧引用升级为新周期。全部原目标完成后才关闭原根；终局中断保留未关闭的实际部分进度，不继续处理后面的牌。

原接受、关闭和非死亡移除收据与不可变历史逐项核对。选择失败和后续结算异常复用已有事务回滚，原手牌、历史、随机数、待选及到期队列一并恢复。终局立即停止后续结算；尚未执行的到期根保留在私有终态，不能继续移除。

玩家只能在可见手牌槽上看到 `hand_deadlines` 剩余本人结束次数。对手的未知手牌继续使用不透明句柄；原物理 ID、全部目标、来源卡面、区域周期、接受根和控制队列不交给玩家。期限接受、关闭及摧毁开始/逐张接受/逐张完成都是私有一致性收据，不加入玩家事件列表。实际存储销毁沿既有 `reveal=False` 投影；观察、事件和合法动作不推动时钟或随机数。

一致性校验不提供未签名存档的来源认证。能够核对原收据不等于能够证明一份整体一致地伪造的存档来自真实对局。
