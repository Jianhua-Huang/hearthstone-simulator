# 成功入手通知与原始熊猫人

`hand_history.EVENT`是私有`hand_card_entered`事实。它描述一次已完成的物理入手，复用原不可变`HandEntryRecord`及其直接`source_id`，没有第二份手牌台账、重复执行器或随机实现。

## 原交付窗口

实际交付者在卡牌材料安装、必要附件及本身记账完成后调用`hand_history.publish(resolution, entry_id)`。生成/发现、复制、物理移入/抽取、回手、发掘、临时牌、印刷衍生、碎裂及原生重组共用此入口。初始场景手牌不发游戏通知；开局发牌、真实换牌替换和自然抽牌则由实际交付者发出。烧牌、无效移动及原手牌内变形没有新的成功行，也没有通知。

双方手牌混洗和场上/对方手牌交换先完成整个实际分配；原手牌返还、未来返还和借用牌库手牌先提交原组，再逐个通知。临时复制及起始手牌复制保留原普通创建事件次序，但将新增入手通知延后至完整替换根登记后。仅为这两个真实批量入口增加内部通知延后参数；它不开放为卡牌效果的新选择，也不能用于跳过边界检查。

所有通知仍经过原`Resolution.emit`和原触发解释器。当前本地政策在原普通交付通知之后捕获新的入手通知，使用当时的原来源/控制者快照；后续死亡、转控或其它反应不重写已接受的主体。普通交付、碎裂/重组、开局、批量交付与反应顺序的精确国服规则仍待校准。

## 原记录绑定

事件保存原`hand_entry_id`及完整不可变行的规范摘要。来源、目标、接收玩家、动作及摘要须与该行一致；入口拒绝初始场景、已离开原成功交付窗口、重复发送、关闭触发捕获及伪造事件数据。入手行本身不增加发布游标或可变完成状态，早先已捕获的上下文仍保留相同原行。

完整游戏边界要求所有非初始场景入手行与实际事件一一对应。保存/待选恢复及执行中的回调也核对原行、上下文和实际原事件；漏发、重复、单独替换来源/摘要或借用另一通知均拒绝。该一致性检查不提供未签名历史的外部来源认证。读取原事件可使用`hand_history.from_event(state, event)`。

回溯继续保留原诊断事件，并恢复原State；通知查重、完整性与活动回调校验复用既有`effective_events`时间线，只认当前有效尝试的原记录。旧尝试的相同手牌行号不能阻挡新尝试，也不能作为活动回调的来源；不删除旧事件或另设回溯台账。

core623/schema511拒绝旧schema1～510；虽然手牌行布局保持，当前历史必须包含真实成功通知及完整绑定。通知不会进入玩家事件允许清单，私有行、摘要、全知State、Frame和随机状态不向玩家发布；观察115、命令12和回放1保持。

## BE_997原始熊猫人

普通随从主面使用完整原行及双语官网主面，原2费3/2中立史诗，不创造熊猫人种族。其原触发只读取接收玩家与直接物理来源：本人每次成功入手各触发一次，通过同一物理随从进入的卡除外。另一个同名随从是不同来源，生成的法术后来打出再抽牌也有新的直接来源。

主体依次为原控制者及另一玩家构造普通`GenerateFromPool`请求，沿`constructed.cards`的完整可收集法术资格、原随机选择和`AddToHand`交付执行。双方各抽一次，允许相同结果；满手交付继续沿原创建/烧牌路径，失败交付不触发。当前本人先、对方后，以及各次生成接受窗口属于本地政策，未据卡面文字认证国服精确时序。

实验池验证与正式标准域分开。正式生成域中的未知合格内容必须在执行查找时明确报错，不按已适配卡牌裁剪。代理英雄技能及完整拼装可达内容、精确正式部署/热修/合法池、全部效果和国服校准继续独立核定。实际进度、验证及下一项只在原两份台账维护。
