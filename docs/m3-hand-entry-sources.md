# 成功入手的直接物理来源

BE_997原始熊猫人的原文本要求观察成功进入本人手牌的卡，并排除通过自身进入的牌。已有`HandEntryRecord`负责成功入手、玩家、原卡面、区域世代、回合和原因；抽牌尝试、生成尝试及当前手牌列表都不能替代这份历史。

本增量给同一不可变记录增加显式可空`source_id`，保存本次直接交付的物理来源。没有第二份手牌账本、最近施法者推断或新的入手/随机执行器。`origin_entity_id`仍表示复制材料或衍生原实体，不能当作直接交付者；两者可以不同。

## 写入窗口与来源

`hand_history.enter_hand(..., source_id=...)`只在实际成功进入手牌时写入；来源非空时必须是已存在实体的严格正整数。记录先构造、验证，再重置本次手牌进度和追加历史。初始场景手牌必须无来源。后续每次重新进入手牌各有自己的来源，旧记录不随来源离场、死亡、转控或后来动作改写。

| 原入口 | 本次记录来源 |
| --- | --- |
| 普通生成、发现后交付及复制 | 原`AddToHand`或`CopyCard`请求的`source_id` |
| 普通/跨玩家抽牌、物理移入及手牌转移 | 原`Draw`/`MoveCard`请求的`source_id` |
| 双方手牌原子混洗 | 原混洗请求来源；仅实际转移者新增入手，留在原玩家手里的牌保持旧记录 |
| 普通回手、弃牌材料回手 | 原`ReturnToHand`的显式来源；现有普通接口不携带来源时保持`None` |
| 有原来源的回手限制 | 原`ReturnToHand`来源，不用回手目标替代 |
| 交换场上随从与对方手牌 | 原交换请求已经绑定的场上物理来源 |
| 临时生成及发掘交付 | 原生成/发掘请求的来源 |
| 手动/自动法术及随从的印刷衍生 | 原实际出牌/CAST实体，不用外层自动施法调用者替代 |
| 碎裂与原生双半重组 | 原裂解实体或原有序首载体；初始场景整理仍无来源 |
| 临时复制手牌、借用牌库手牌、未来原手牌返回 | 原保存/替换请求的来源 |
| 烧牌后的原实体返还 | 原返还程序保存的来源 |
| 已消费法术原实体返还 | 原实际法术物理实体 |
| 开局发牌、换牌及自然回合抽牌 | 无显式牌来源，保持`None` |

现有生成溢出、烧牌、施放抽到时施放的牌、同玩家手牌内空操作均不新增成功入手记录。手牌内变形保持原入手记录中的原卡面和来源。物理卡重新进手则追加新行，保留原行及原手牌租约边界。

## 保存与信息边界

来源字段在core622/schema510引入，要求每行保存完整`source_id`，包含显式`null`，省略字段拒绝。后续通知要求及当前版本见[通知契约](m3-hand-entry-notifications.md)。历史一致性检查验证来源类型、存在性及初始场景约束。记录仍属于全知State和原Frame的私有状态，不增加玩家投影字段、命令或回放版本。

本字段记录实际执行的直接来源。后续成功通知通过完整原行摘要与实际事件绑定，见[入手通知契约](m3-hand-entry-notifications.md)；字段或一致性检查均不提供未签名存档的外部来源认证。

## 真实来源消费者

原始熊猫人的普通随从主面消费该成功通知，并沿原完整法术生成域向双方交付法术。材料全部安装、原子交换/批量返回完成后才捕获通知，保留每次实际入手和来源排除；不能枚举猜测旧事件、把溢出算入手、使用第二份历史或裁去未知合格法术。具体通知、保存及未闭合正式域边界以[通知契约](m3-hand-entry-notifications.md)为准。

直接来源、碎裂/重组及各交付发布窗口仍须国服校准。代理英雄技能、完整拼装域、正式部署/热修/合法池与完整效果范围分别保持开放；本增量不证明这些范围完成。实际执行、验证和下一项仍仅在两份原台账维护。
