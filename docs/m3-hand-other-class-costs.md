# 当前手牌其他职业条件与固有费用

B230 提供一个纯当前手牌条件，并让原固有价格阶段消费该条件。实际进度、验收和下一项仅维护在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md)。

```python
hand_has_other_class(state, registry, player_id)

IntrinsicCostSpec(
    set_to=0,
    condition='hand_other_class',
    history_profile_id='hand.current-other-class-v1',
)
```

## 职业与区域依据

条件读取原玩家 `hero_class`，包括已有英雄替换或保留职业政策，不读取最初卡组职业。手牌逐物理实体使用当前卡面的印刷职业元信息，复用原 `PoolQuery(class_mode='other', include_neutral=False)`。中立牌不匹配，双职业包含当前职业时不匹配；不包含当前职业时匹配。所有牌型、重复卡面、零费和每个物理手牌均保留，不能提前在第一个真值处停止验证未知后续行。

范围是实际付款方完整当前 HAND，不读取对手手牌或历史获取来源。物理定价牌仍在 HAND 时也参与；虚拟生成预览不把它插入手牌。这些依据与已有公共职业筛选一致，但自身、双职业、中立及当前/初始职业的精确国服语义尚未校准，不能由卡文单独认定。

未知卡面或必要职业元信息明确报错。当前英雄职业未知或中立时不能执行这个条件，不猜测玩家职业。查询不分配实体、改变区域、推进随机或写费用缓存。

## 原报价与付款冻结

`HandOtherClassMatch` 保存玩家、turn/action、原实体分配界、当前职业和完整有序 `HandOtherClassRow(entity_id, card_id, matched)`。布尔聚合从所有行计算；条件真伪与原冻结注册表重新核对。重复/未来实体、错误类型/职业、未知卡面、篡改匹配均拒绝。

只有一个普通物理SPELL的固有固定费用赋值，不允许同时加法、非零最低费用、其他固有公式或混合条件。价格仍按原 intrinsic-before-local、本地附魔、外部来源、手牌最低费用和资源账户处理。实际资源只按已接受的价格支付一次，零费也保留原付款记录。

原 `IntrinsicCostStageFact.condition_facts` 承载新不可变条件，不新增 State/Player/Entity计数、价格执行器、资源账户或公共 CardDefinition字段。原窗口捕获完整重算当前 HAND；之后使用已接受条件，手牌移除、变形、转移或英雄职业变化不重新定价。当前复制和实际新付款方重新查询自己的当前手牌，不能把先前算出的零费变成永久附魔。

原当前手牌付费记录同时绑定原 `hand_size`、`hand_index` 和物理来源。删掉不影响真值的一张行也不能将其伪装成完整原手牌。回溯根报价继续遵循原根窗口证明，不用后续手牌替代。恢复一致性检查不提供未签名存档来源认证。
