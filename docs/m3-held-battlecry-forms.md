# 欧斯克的原生手牌战吼选择

本文描述真实根卡TLC_452的有限原生表达；进度与下一项仍只在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护。

## 原卡与战吼主体

原物理卡始终为TLC_452，保留6费6/6印刷基础、卡牌身份、手牌到达、驻留、原生种族和本地属性/费用附魔。随机变化只替换一条已有类型的`AbilityInstance(kind='battlecry', origin='printed')`中的行为及`battlecry_card_id`。31份真实非收藏卡面提供既有战吼主体声明，不把原手牌卡变形成非收藏衍生卡，也不把手牌变形清除附魔的政策套用到这里。

`HeldBattlecryFormsProfile(card_id, forms)`保存有序原生主体列表，注册时核原根、身材、可用战吼与有限公开目标规则。完整root/31主体原行、64份完整双语官网响应及原根全部childIds保存在`data/cards/titanographer-osk-v1.json`。这证明完整卡面家族，不证明实际服务端技能资格或权重；本地使用该31主体完整列表等概率重新抽取，允许再次抽到相同主体，待M0/M6确认。

实际战吼仍由原capture、支付接受、BattlecryPayload和执行/重复管线运行。PlayRecord与BattlecryRecord的原牌是TLC_452，payload的声明牌是选中的真实主体；源归因与主体身份分离。没有新增模型字段、对局账户、效果类型或待续执行器。

## 原手牌与接受窗口

原生同步只处理实际TLC_452手牌，不改变用于专项的直接主体实验卡。首次实际手牌获得在观察者捕获前安装战吼；Scenario使用原settle_hands，真实开局在换牌未完成时暂缓。本人真实turn_started重新抽取，未在手牌中的根不参与；候选与原RNG直接进入私有收据。同一手牌驻留的战吼槽ID保持，属性和费用附件保持，不新增实体或手牌到达。

当前复制保留已有主体与原本地附件，并为新实体保留独立战吼槽；初始化复用该主体，不额外抽样。收据连接复制来源此前的原选择。无reset转手保留主体，并按新持有者后续开始更新；普通回手、印刷复制及带reset洗牌继续使用原生命周期，清理旧选择后在实际入手重新抽取。玩家不能仅凭同名卡或额外抽牌替代原实体。

以上即时安装、本人开始、可重复抽到同一主体、复制/回手和换牌窗口均为明确本地政策；官方卡面没有给出这些细节，不能冒充国服校准。原完整生成/发现池仍遵守各战吼既有宿主契约；资料家族完整不授权裁掉未支持候选或把有限实验池当正式池。

## 目标、信息与保存

根卡使用一个原生玩家目标谓词，只读取自身可见的`battlecry_form`及候选目标DTO。当前31主体中五个需要目标，谓词委托各主体既有zones/kinds/relation/source排除与公开条件；其他主体没有目标。普通战吼保护、付费投影、原接受观察、无合法目标可空过及被冻结的战吼主体继续由公共管线处理，不把根卡所有可能目标混成一个合法集合。

“选择并移除两个敌方随从”的内部菜单使用该战吼自己的声明建立目标范围，不能从物理根卡借用出牌谓词；原目标保护、选中驻留与非死亡移除继续复用原管线。

`battlecry_form`只给能看见该实体完整状态的玩家；对手手牌即使曾被揭示也不显示后续私密变化。出牌后主体属于公开随从信息。玩家视图及原支付输入使用player-view-v108，完整候选、RNG、附件ID、原手牌到达与继承证明仍为私有内容。

私有`held_battlecry_form_selected`收据保存原根、物理实体、战吼槽、手牌到达/epoch、初始/继承/本人开始模式、原开始事件、前一主体、完整有序候选、选中主体及MT19937前后状态。恢复时核原到达、唯一开始窗口、主体链、继承来源和局部抽样重演；当前手牌必须与完整收据一致，裁掉整份当前程序也不能默认为无战吼。回溯读取effective_events。收据不是未签名存档的外部来源认证。

旧泽鲁斯等完整变形来源、31主体原静态定义及原两分支战吼执行保持；本功能不扩大旧defining_hand_source契约。M0正式补丁/热修/池、M6国服以及完整标准可达/发布仍须独立闭合。
