# 心灵扫荡者的原持牌条件与战吼来源

JAIL_432心灵扫荡者是2费2/3牧师稀有随从，战吼在持有本牌期间使用过对手卡牌复制后，对所有敌方随从造成2点伤害。完整原行和两份严格双语主面追加到`data/cards/native-held-opponent-copy-v1.json`，原JAIL_433行及主面保留。[官方卡面](https://hearthstone.blizzard.com/en-us/cards/126122)支持原始效果；[已有复制与持牌契约](m3-held-opponent-copy-cost.md)继续负责实际复制来源、原手牌提交、连续驻留与第一份见证。

## 条件在原窗口冻结

战吼主体不能查询当前执行载体手中是否又使用过复制，也不能用后来同名实体的进度替代原牌。复用`HeldOpponentCopyMatch`，只在原来源确定时保存物理来源、原手牌进入、原玩家/时钟、play上界和第一份见证；没有另建进度、出牌或伤害账本。

| 实际来源 | 原条件依据 |
| --- | --- |
| 正常手牌使用及其额外战吼 | 原PlayRecord的提交费用操作数已保存的手牌能力；上界是原play.id |
| TriggerBattlecry效果激活 | 接受实际场上引用及能力序列时的原载体进度，随BeginIndirectBattlecry保存 |
| 已实现整卡物理执行 | 原generated_after_install系列的真实主体接受窗；源材料为当前复制时继承其已赚取状态，基础重演不凭原手牌历史赚取条件 |
| 激活历史及嵌套激活历史 | 原BattlecryRecord保存的条件，包含直接效果的真或假，不借用新载体 |
| 曾使用牌的战吼历史 | 原PlayRecord的提交手牌能力；反制是否纳入仍遵从已有查询政策 |

`BattlecryRecord.held_opponent_copy`保存实际执行的冻结事实，None只用于没有这项声明的主体；真实声明即使条件不满足也保存空见证。手牌付款已经保存完整操作数，因此不加PlayRecord字段。`BeginIndirectBattlecry.held_opponent_copy`承接原效果接受，`PhysicalReplayProgress.held_opponent_copy`承接整卡主体接受；原完整物理证明重算这项事实，记录继续绑定原生成主体。

来源之后被沉默、死亡、回手、转控或换面，不重写已接受条件。普通重新入手继续执行旧重置，显式当前/基础复制继续遵从原材料政策；因而新的手牌阶段可以不满足，而旧历史仍保留原真值。原手牌、历史引用、冻结能力与已存在的复制使用见证相互校验；历史条件不接受当前执行者的身份替换。旧声明没有这项能力时不能伪装为空进度。

心灵扫荡者没有指定目标，也没有已登记的定向战吼目标profile。本批不扩展相应receipt或制造目标组合；无已审来源的定向调用明确拒绝，留待实际卡牌需求。普通、整卡与历史入口继续使用各自已有控制者、次数、付款、保留结果和生命周期契约。

## 当前敌方与共享伤害

原条件与实际伤害取不同材料：条件使用原事实，敌方随从在本次主体执行时按捕获执行玩家的当前局面查询。通过既有InvokeBehavior再次进入当前窗口，再交公共DamageBatch；开始反应新增或移走的随从参与当前选择，不用开始前的旧状态列表。

伤害为MINION_ABILITY，每个当前活跃且存活的敌方随从2点，不伤害友方或英雄；休眠和非随从不在此域，圣盾、免疫、生命与死亡继续由普通伤害执行器处理，不受法术伤害数值加成。普通召唤不自动触发战吼；真正后续触发才读取它的原载体状态。没有目标或条件为假仍完成原合法随从使用与相应战吼记录。

## 保存与边界

core482、schema399拒绝旧1～398。只增加上述三个可选字段，没有新Entity、PlayerState或GameState字段，没有新Effect、付款入口、外部命令或任意条件框架。等待保存原条件和已付款根，恢复不重新获取见证；失败选择回到原暂停点，普通回溯与保留结果沿原账本记录实际执行。

玩家接口保持原手牌进度摘要和普通公开事件，不提供冻结条件、原play IDs、隐藏源实体、完整历史、RNG或解释器帧。复制的复制、连续驻留、效果/整卡接受窗和历史口径继续属于明确本地政策；官方历史变形修复不能认证完整CN37规则。内部测试、M0正式池、M6国服校准与完整实际可达内容分别验收，执行证据与下一项只维护在原两份台账。
