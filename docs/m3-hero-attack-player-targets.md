# 原英雄攻击事实与玩家条件目标

真实来源为 `BT_495` 刃缚精锐，印刷5费6/4，战吼在本回合本人英雄攻击过时造成4点伤害。完整原行及严格中英文主面见 `data/cards/native-hero-attack-targets-v1.json`；该历史随从是标准可达内容的候选依赖，正式过去生成池与国服校准仍单独开放。

适配器注册已有 `PlayerTargetRuleSpec`，只读取玩家观察中本人玩家行的 `hero_attacked_this_turn` 布尔值，并沿用普通 `TargetSpec(IF_AVAILABLE)`。条件不满足时没有可选目标，也不能强行传入目标；满足后使用正常角色目标域。实际战吼再次使用公共原英雄攻击查询，伤害交给普通 `Damage(..., MINION_ABILITY)`。不新增印刷关键词、`target_condition` 枚举、攻击计数器或另一套目标执行器。

本人观察新增的布尔值由已有 `hero_attack_count(..., HeroAttackQuery(window='owner_turn'))` 计算，只计算原完成的自愿英雄攻击；声明、取消、尚未完成、随从攻击及对手时段不计。攻击被圣盾阻挡但真实完成仍计数；英雄换形不抹掉本人原回合事实。原内核对强制/裸英雄交战仍明确拒绝，不能据此宣称新增了这些来源。对手行不携带该字段，也不公布原记录、物理英雄ID、动作号或随机状态。

既有 `PaidTargetObservation` 增加私有 `original_event_cursor`，由实际完整事件流长度捕获；回溯原付款窗口使用已有重试会话的 `event_start`。该字段只参与内部原接受证明，不能混入玩家JSON；玩家的过滤事件游标是另一种时钟，不能用来比较英雄历史的完整事件游标。

恢复原目标输入时，以完整保留的 `HeroAttackRecord` 校验原玩家、全局回合、动作及原游标之前的完成终态。普通付费和生成后的独立目标原点均使用同一校验；间接/历史目标的完整原状态投影也核对该事实。这样，即使同一次英雄攻击在后来完成，也不会把攻击完成前已接受的间接战吼改为有条件效果。原规范化观察、物理映射、原点摘要、独立目标收据和普通当前目标复核继续保留；这不认证未签名存档的外部来源。

本变化增加一个私有冻结证明字段及一个本人视图事实，没有增加实体、玩家或GameState字段，也没有增加生产Effect、载荷类型或玩家命令。内核467/schema384/玩家视图94，旧schema383及更早明确拒绝；命令12/replay1保持。实际验证与后续项只在原两份台账记录。
