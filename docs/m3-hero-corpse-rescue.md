# 哈斯克：原英雄致死、实际残骸与一次性救援

本契约说明永时收割者哈斯克的真实卡牌表达。实际执行、验收证据、差异与下一项只在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护。[完整源包](../data/cards/hero-corpse-rescue-v1.json)保留原根和三个非物理显示/附魔记录；卡面、机制执行、内部验证和国服规则校准分别记录。

## 既有能力的组合

四费5/3亡灵 `TIME_618` 通过真实战吼对当前友方英雄执行已有 `GrantDeathrattle`，并安装已有 `AddPlayerEffect` 的公开、来源独立标记。随从的死亡、沉默、回手、复制或转控均沿原生命周期；已经授予英雄的能力和玩家效果有独立用途。单纯复制随从不重演战吼。

英雄替换仍走原 `replace_hero` 或打出英雄牌流程，原复制器保留授予附件及其已消费状态，玩家效果保留。未使用的生命继续属于该玩家的新当前英雄；已使用的生命不会因替换自动刷新。该行为复用现有执行器，精确官方替换及叠加窗口仍待对应证据。

## 自然英雄死亡与原实际扣量

英雄的自然致死仍由既有协调器处理：先冻结整批普通战场死亡及残骸事实，接受原英雄死亡，原子消费同时批的全部现有英雄亡语，再执行各原亡语计划和终局。普通反应及原续行保持在原屏障后的队列，不新增另一套救援检查点。

哈斯克亡语要求真实 `HeroLethalReference`、`DeathRecord(zone=HERO)` 与原 `hero_died`。来源、受益玩家、死亡ID和事件中的 `SourceAllocationFact` 必须指向同一原物理英雄。手动调用一个活着的英雄的回调不能制造自然致死身份。

付款使用 `SpendUpToResource(... cap=20, profile='hero_lethal_at_debit')`，数量为当时真实余额与20中的较小值。原结果冻结实际量、余额、来源、动作及原致死引用；正量才调用 `RecoverHero` 恢复原英雄至该实际生命值，零量不产生恢复。恢复不是普通治疗，不伪装成法术治疗，也不把负伤前生命或请求上限当成实际支出。

已消费授予在后来再次致死时不执行。真实新战吼可创建新授予；多个真实授予进入原完整接受和消费流程。已接受的多次主体各自使用既有最多消费及恢复失效规则，具体叠加和重复窗口仍是本地契约，不能由卡面独自认证。强制非自然英雄触发及高于当前最大生命的恢复保留原明确不支持边界，不猜测钳制或制造额外生命。

## 原公开标记的退役

原数据把 `TIME_618t` 标为 `VISIBLE_PLAYER_ENCHANTMENT_CARD/HIDE_COST`，两个附魔行亦完整保留。这些显示材料由原英雄附件和公开玩家效果表达，未创建另一个法术实体或一次施法；可执行定义数量只增加真实根。

公开玩家效果沿既有 DTO 显示已知物理哈斯克来源卡面、效果键、种类和期限。当前显示卡面与客户端永时命数的专用提示图不同；它表达同一公开能力，不透露全局附件ID、隐藏实体、原英雄致死材料或随机状态。

原自然英雄主体在真正付款前移除匹配的原标记。范围来自原死亡材料中未消费的哈斯克授予来源，以及原 `hero_died` 分配事实的 `next_order`：只移除该原接受前已经存在的标记。相同物理哈斯克后来重新打出产生的新标记有更晚时钟，不会被旧主体重绑或移除。现有 `RemovePlayerEffect` 对已退役实例保持幂等。

一次性标记的退役属于原亡语主体，独立于普通 `hero_died` 玩家反应；普通反应会被原致死屏障停放，零量终局还可能取消后续普通工作。零量消费也必须在终局前退役原标记。对手英雄独自死亡不消费友方授予或标记；投降及亡语禁止仍沿原终局政策，不额外执行救援。
