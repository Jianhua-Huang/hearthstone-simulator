# 本局历次本人回合的实际承伤费用

`HeroDamageTakenCostSpec(profile_id='cost.hero-own-turns-damage-v1')` 是一个有限固有费用输入。普通、可从手牌使用的随从可声明 `CardDefinition.hero_damage_taken_cost`；验证与取值位于 `hs_sim/engine/hero_damage_taken_costs.py`，执行仍使用原报价、付款和出牌管线。

## 数量与范围

数量来自 [实际伤害历史](m3-damage-history.md) 的原 `hero_damage_taken(state, player_id, own_turn_only=True)`。这里没有传入当前 `turn`，所以累计**本局所有本人回合**：原目标为付款玩家的英雄，原伤害发生时 active_player 也是该玩家。按最终 `HealthResult.damage_dealt` 计量，包含护甲吸收的部分；`health_lost` 单独保留。其他玩家造成的伤害仍可能符合目标与回合条件。

初始生命与护甲、治疗、生命上限变化和生命支付不制造承伤记录。后续治疗不扣除已经发生的伤害。零量、受阻和转换为治疗的原伤害行保留，但最终 damage_dealt 为零；治疗转换成伤害按原公共结果计量。明确的系统疲劳符合目标/回合时计入承伤，不要求卡牌来源信用。未知来源允许用于目标承伤查询，不据此推断英雄技能或其他来源归属。

原固有阶段输入为 `before`，结果为 `max(0, before - quantity)`；数量不因费用降到零而截断。该阶段之后仍执行原局部费用、外部费用、最低费用和支付货币规则。物理卡与生成报价共用同一取值及证明，查询不推进事件、RNG、资源或动作。

## 冻结与恢复

`HeroDamageTakenCostFact` 保存有限声明、实际 payer、原 turn/action、原实体/顺序/伤害游标、**完整有序 DamageRecord 前缀**及 quantity/before/after。完整前缀包括对手、随从、零量和未参与减费的行，不能仅保存命中的英雄伤害。

校验要求严格类型、连续行 ID、单调原时钟及批次/包顺序；原来源、目标、改道、武器身份和入场顺序不能借用未来分配。每行沿原 DamageRecord/HealthResult 严格解析，目标卡牌类型与完整已知卡面必须成立；未知未选中的卡面也不能被跳过。

`IntrinsicCostStageFact.hero_damage_taken` 是默认 None 的私有叶，字典和 typed 帧都要求显式字段。原窗口验证重新查询全部记录与数量。已接受费用则验证原完整前缀，允许之后合法追加伤害，不以新增数量重算原支付根；新报价读取新增事实。原物理报价还要求主体实体早于保存的分配边界。旧金额、原次数和未选中行都不能仅凭相同最终费用替换。

该保存证明用于内部一致性，不认证未签名存档的外部来源。选择暂停、克隆、恢复、继续和失败回滚复用原解释器与 FrameCodec；完整事实仍为主机私有，玩家只获得有权观察的当前费用及原合法操作。

## 声明与生命周期

这一个 profile 限定普通物理随从，不支持裂变/融合/星舰或与其他固有数量公式、有限条件公式合并。新的任意公式、来源授予和组合声明继续拒绝。没有新增 GameState、Player 或 Entity 字段、伤害执行器、玩法事件或动作。

数量属于玩家本局历史，不属于该卡的获取时间；后获取的牌同样读取原历史。普通复制到另一玩家时使用接收者的目标与本人回合；变形后的卡面决定当前是否声明该费用。沉默和回手使用原印刷卡面/移区契约，不能重写已经发生的伤害。

必要实验卡只有 TTN_462「被禁锢的恐魔」：完整本地原行为 9 费 4/4 术士史诗，无种族标签，没有新增战吼、亡语或关键词。原行与完整 PIN 在 `data/support/hero-own-turns-damage-cost-basics.json`；适配仅在隔离测试注册表，未扩展生产代表包或正式池。

引入接口时使用 prototype-v232/core-effects-v226/schema215，旧 schema 1～214 明确拒绝。上述精确承伤资格、固有层顺序、特殊复制/变形和国服窗口仍是待校准的内部政策；本契约不宣称完整伤害归属、全部动态费用或正式卡池支持。实际执行与下一项只在 [项目状态](project-status.md) 和 [机制清单](mechanism-backlog.md) 维护。
