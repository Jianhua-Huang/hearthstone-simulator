# 登山地图：未使用类型与原发现余项

`TLC_464`按固定37.0完整原行及严格双语主面接入。首次发现的条件与后续奖励分开：先找具有未使用类型的随从，再沿[既有原手牌选择跟随](m3-hand-choice-followups.md)等待原牌在本回合使用。实际验收与下一项仅在原两份台账维护。

## 首次候选

回调调用`played_minion_type_facts(..., completed=None)`读取本人已经提交的物理手牌随从，包括尚在原主体中结算的当前提交及反制发生；原卡面和有序种族附魔由[原类型历史](m3-played-minion-types.md)解释。普通召唤不新增使用，之后变形不重写原提交，未知或超出固定类型全集的原资格显式失败。

已使用类型取这些原事实的成员并集。候选至少有一种尚未使用的类型即可；双类型的另一种已使用不自动排除该候选。ALL及其排除只按已核对客户端映射中的十二种构筑类型解释，不从已接卡样本造全集，也不把无类型当作一种新类型。

有剩余类型时声明普通`DiscoverFromPool('constructed.cards', PoolQuery(kinds=(MINION,), collectible=True, class_mode='current', tribes_any=...))`，沿原发现政策筛选当前职业/中立、去重及抽样。原库存中每个合格候选必须有完整可执行定义；未知合格候选或未知元数据在RNG前失败，不删池凑三项。

若所有类型均已使用，已能证明空集合，直接无效果，不用空`tribes_any`误表成“无限制”，也不查询无关池或耗RNG。否则原池恰好无合格候选时，既有模块照常保留自己的`empty`记录。这两种空路径不伪造选择。

## 复用原跟随

首次请求直接交给`DiscoverForPlayFollowup`。原模块保存全部实际选项、来源、抽样、选择结果、实际交付实体与成功手牌驻留；本批不增加持续效果、私有账本、回合计数器或新的解释器。

原牌完成当回合物理出牌后，再选一次原未选项。此时该随从的类型已经使用过，仍不能重新应用首次类型过滤，不能重抽或裁掉原同类型余项。同名旧牌、普通复制和离开后重新进入手牌的驻留不能顶替原获得者。原地图离开执行区不撤销已武装跟随，原回合到期和终局继续原生命周期。

获得/出牌反应中的等待、异常回滚、满手、反制及额外回合继续原公共契约；玩家只得到本人允许看到的原余项，对方不得取得私有候选或宿主引用。
