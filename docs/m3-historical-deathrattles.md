# 历史死亡随从的原生亡语

实际进度、验证结果及下一项仅维护于[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)。本页规定不死徒刑、末日使者安布拉实际需要的有限入口，不认证完整正式生成池或国服全部时序。

`TriggerHistoricalDeathrattles(player_id, count, source_id)`冻结原友方场上死亡记录前缀，从有印刷亡语的随从死亡次数中随机、不放回选取至多`count`项，按选中顺序执行。同名卡的不同死亡记录分别占一个候选；不会把五个随从误作五条额外授予的亡语，执行途中产生的新死亡不追加进原候选。空组不消耗随机数。选择事件保存完整候选、选中项、实体/能力身份及MT19937前后状态，并在恢复时局部重演抽样。

选择后通过普通实体工厂建立独立的基础随从载体，暂存于私有`SETASIDE`，使用其印刷亡语和关键词。不会召唤上场、占用场位、制造死亡/残骸，或让施法者获得旧亡语。原墓地实体保持原样；属性附魔、沉默、额外授予及旧原生增长/抽牌链接不复制。已有原生材料初始化仍由实体工厂负责。`RuleContext.death`和`DeathrattleCapture.death_id`为空；`origin='history'`及独立`historical_root`绑定原选择和历史卡面，不能伪造一次自然死亡。

每个所选随从在实际开始时，沿普通亡语入口接受当前抑制政策、完整印刷主体和重复计划。各随从有各自的接受窗；原选择动作与等待后各次实际接受动作分别保留，后者不得早于原选择。已接受的重复次数及原主体仍由既有解释器、Finish证明和生命周期负责。私有来源的普通后续效果若实际造成死亡或将卡牌送入可见区域，继续走原公共执行器。选择、单个随从及完整根的继续/完成义务在保存边界核对；不能删去尚未执行的选中项或完成证明。

不死徒刑用`register_historical_deathrattle_spell`登记手动出牌的非空死亡候选前置条件，复用原合法动作/支付前检查；不要求场位。自动施法不套用手动前置条件。安布拉没有非空历史的手动限制。登记集合进入注册表指纹；没有该登记的原注册表指纹保持。

schema401拒绝旧1～400保存布局，公共效果为core484；没有新增Entity、PlayerState或GameState字段。新增四种有限控制效果及Capture的可空事件字段。玩家观察、命令和回放协议分别保持94/12/1；随机收据、私有载体列表和完整规则上下文不进入玩家投影。结构证明不能认证未签名存档的来源。

官方[32.4.2公告](https://hearthstone.blizzard.com/en-us/news/24205944)支持安布拉排除额外授予亡语；[36.0.1热修](https://us.forums.blizzard.com/en/hearthstone/t/3601-hotfix-patch/162668)支持不死徒刑满场仍可使用。这两项修复不等于国服37.0全部语义校准。死亡次数权重、随机执行顺序、沉默后的资格、基础原生记忆重建及私有载体的自指/重复微观窗口是明确的本地政策，仍待M6核对；完整标准实际可达内容仍属M7。
