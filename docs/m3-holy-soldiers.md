# 投身战争、誓缚光环与原法术数字

[两完整根、共用衍生物和六份双语主面](../data/cards/holy-soldiers-v1.json)固定BE_142投身战争、BE_146誓缚光环和BE_142t瓦尼尔士兵。前者印刷1费神圣法术、原生剩余法力数字声明；光环为3费神圣法术，原脚本/持续计数都是3。士兵是非收集1费1/1圣盾随从，不把动态召唤身材写成新白板卡，也不猜额外种族。

投身战争扩展原`RemainingManaNumbersProfile`的有限法术分支：在手牌中只同步基础费用，保留法术的零攻击/零生命；旧开锁匠的1/1随从身材、付款排除和冻结战吼保持。普通局部/玩家费用修正仍叠加在原基础数字之后。真正手动CAST用完整原提交报价的`quote_input.base_cost`作为士兵数字，减费改变支付和最终费用，不改写该原数字；一次物理手牌的原生重复保留同一已提交依据。

自动CAST在接受窗口为真实施放者生成明确报价输入，以其当时剩余法力计算数字，仍沿原局部/玩家费用层报价，但不扣牌费、不制造手牌使用。该输入是纯变换，不重写尚在其他玩家手牌中的实体。来源之后移动、资源改变及等待选择不重算已接受数字。不同自动CAST各自接受，召唤数量额外体共用本次原材料。

本批剩余数字沿现有家族的最低1政策。已有[Picklock原始答复](https://www.reddit.com/r/hearthstone/comments/1u1ifvd/comment/oqq89cc/)只证明开锁匠的最低值，不能证明投身战争零法力边界；原印刷1和动态显示也不是该边界的完整官方证据。本数据包明确保留未国服校准状态，最低值及手动/重复/自动的精确接受窗口仍须M6核定，不能以普通数值测试认证。

誓缚光环由原`PlayerEffectSpec(kind='aura')`安装独立三次本人结束倒计时。主体监听原`spell_cast_finished`，核确切原CAST/完成/施放玩家与神圣学派，再读取`source_cost.amount`，将该费用作为一次原召唤材料。费用可为零；自动施法的费用与实际零支付是不同依据，不能据没有付款就生成零身材。原私有报价已经冻结后，前序完成反应改变费用修正或法力也不改写该材料。

新的不可变`SpellSourceCostObserverProfile`绑定真实神圣光环程序。注册表在有该观察声明时，为全部实际神圣CAST保留完整原费用事实，包含尚未安装光环时开始的CAST；否则不能正确处理光环自身或施法主体中途建立观察者的情况。原专用生产者profile仍有其原有限形状，观察者不要求把每张神圣法术改造成该生产者。开始见证、原报价输入/操作、提交付款或自动接受时钟继续严格校验，不能因当前光环移除就丢掉过去费用。新注册表声明纳入指纹，不增设费用账户。

当前内部窗口是光环在自身CAST完成前安装，所以自身神圣施法也触发；本人当前结束计入三次倒计时，对手结束不扣。每个独立实例各自交付，普通反制/失效没有成功完成事件，不借手牌使用近似CAST。实际召唤均交`SummonByCard`及共用士兵：圣盾、零生命入场、满场、数量、死亡和反应共用，不另建数值伤害/召唤执行器。上述自身触发、费用口径、容量和精确国服时钟仍待M6。

保存、独立注册表恢复、克隆、回放、待选与失败回滚共用原CAST、付款、玩家程序及召唤记录。完整报价和原生依据不进入玩家DTO。core637/schema525拒旧1～524，没有新Effect/payload类型或State字段；内容v469，命令13/观察115/replay1保持。正式合法池、完整可达内容、校准与发布仍独立验收；实际结果和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。
