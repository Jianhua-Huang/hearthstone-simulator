# 恶毒恐魔的残骸支付与当前复制

真实标准根`CORE_RLK_745`仍使用[完整原数据包](../data/cards/zone-effects-v1.json)中的4费2/4复生及原结束回合主体，定义、池行和行为身份不替换。原完整客户端行及双语官网响应的实际核验与结果只在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护。

原配方直接返回`SpendResource(4, CopyMinion)`，遗漏了已有召唤类残骸门禁：满场时仍扣四份；两个原主体竞争最后一格时，第二个也扣款却无法召唤。现在返回已有`SpendCorpsesForMinion`的`free_space`请求，绑定原`MinionReference`。真实执行时重核同一来源驻留、控制、存活和全部面板占位，再沿原四份全额支付与当前复制操作。

容量在每个原主体的支付窗口重新检查，不按整轮开始时的空位预付。新复制体不加入已经捕获的本轮结束主体；不足残骸、满场、对手结束或已离开的原来源不产生本次支出。支付已经接受后的反应、等待及复制失败保持原管线的既有规则，不另造退款或复制器。

`CopyMinion`继续使用当前完整材料，保留已消费的复生，不能重新从印刷定义补回。[国际服37.0.1历史热修说明](https://us.forums.blizzard.com/en/hearthstone/t/3701-hotfix-patch/166622)也列出了无复生恐魔复制体不应恢复复生的修复；真实先复生再复制专项确认共享实现已符合此行为。本批没有为这个已正确的复制路径修改内核。

选择等待、恢复、clone、回放、扣款历史和原结束队列复用现有公共能力。没有增加对局字段、Effect、payload或公共引擎代码；只提升构筑实验包版本。满场及微观支付窗口仍待集中M6国服校准，不以内部测试或国际服说明认证国服正式补丁已闭合。
