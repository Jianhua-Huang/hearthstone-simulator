# M3 玩家观察与事件时点的信息记录

原生亡语召唤成长在player-view-v86为可见实体提供deathrattle_summons，仅含token card_id/attack/health；抽牌链接与来源/获取ID不投影给玩家。私有记忆、通知窗口及严格保存见[契约](m3-native-deathrattle-memory.md)，原批次说明和历史版本记录仍保留。

本页原批次运行时 `prototype-v75` / `core-effects-v75`，snapshot schema 74；玩家 DTO 为 `player-view-v44`。本页描述 M3-03a-01 观察与过滤日志契约，M3-03a-02 [受限玩家操作](m3-player-api.md) 已接入。静态实验池、区域选择与交易/锻造已接入，星舰发射与地标主动使用也已接入；完整正式池及具体来源边界继续维护，其他可选组合按真实卡需要处理。总进度见 [项目状态](project-status.md)。

## 1. 使用入口与信任边界

```python
observation = game.observe(1)
events = game.player_events(1, after=0)
cursor = observation['event_cursor']
# 下一已提交边界只获取新增的玩家事件：
new_events = game.player_events(1, after=cursor)
```

两者返回独立、可 JSON 编码的副本；读取不会分配 ID、改变 RNG 或修改对局。只能在已提交边界读取，包含正式等待选择的边界；处理器运行中明确拒绝。玩家必须为整数 1 或 2，布尔值不作为玩家 ID；日志游标必须在本玩家日志范围内。

受信任宿主负责将调用者身份绑定到固定座位，再将 DTO 传给外部策略或客户端。本批不是联网认证或 Python 沙箱。`Game.state/events/history/origin/snapshot/clone/legal_actions/legal_targets/quote_cost/apply` 仍是全知宿主接口，`ActionResult` 也含原始事件和完整摘要；不能一起发送给玩家。现有 CLI 的状态、事件、动作输出同样属于宿主诊断。

M3-03a-02 已建立 `Game.for_player(viewer)`、玩家动作格式、句柄转换、观察修订值、选择提交及受限合法操作。自定义条件必须使用只收到玩家 DTO 的回调；旧全知条件和不支持的隐藏目标域明确报错，不能简单过滤全知动作列表。详见 [玩家操作契约](m3-player-api.md)，不宣称任意卡包已经适配。

## 2. 已实现的观察范围

| 信息 | 当前投影 |
| --- | --- |
| 双方英雄、战场、武器、技能 | 卡牌身份/类型、控制者、当前战斗显示数值、关键词、冻结/沉默、当回合入场及使用次数 |
| 场上地标 | 公开身份、耐久与 `location: {cooldown_remaining, open}`；open 只表示耐久/冷却状态，不替代目标和其他使用条件 |
| 当前职业、原始发射数量 | `hero_class` 与 `starships_launched` 公开；不提供内部发射历史记录和结算帧 |
| 自己的手牌 | 身份、当前数值和实际费用金额/支付种类；不含费用附件 ID 或处理器 |
| 对手的手牌 | 有序牌背句柄；已明确公开过的牌可保留身份，但不显示其后隐藏的费用/属性修改 |
| 双方牌库 | 只给数量；不含实体列表、顺序、位置、RNG 或内部 ID |
| 墓地 | 只列该玩家已知的实体；不发送完整隐藏移出区列表或数量 |
| 等待选择 | 选择方看到提示、选项、数量限制、局部选择/选项句柄；另一方只看到谁在选择 |
| 回合、胜负、法力、过载、已实现资源账户 | 显式列入 DTO 的公共状态，含技能回合累计次数和公共容量 |
| 结算帧、未执行分支、死亡/附件完整历史、原始卡组配置、全局计数和完整摘要 | 不进入玩家 DTO |

选择标签与显式 `card_id` 是卡牌实现主动声明给选择方的内容。选项引用隐藏牌库实体时不会附带内部 ID；需要展示牌面时须由卡牌实现显式声明元数据。观察层不解析任意标签以推测保密规则，因此卡牌行为与扩展处理器仍须受信任。

原批次是最小观察契约，奥秘区域已在 M4-04 接入；当时未包含全部牌库查看/排序揭示、动态能力说明、观战者或完整客户端显示字段，现行具体来源范围以两份台账和扩展契约为准。不能把未投影的信息自动当作不存在，也不能用此 DTO 完整重建全知局面。

## 3. 实体身份与已知信息

内核稳定实体 ID 与玩家可见的 `e1/e2/...` 句柄分开。每个玩家独立分配句柄，顺序只受可见槽位和显式揭示影响；隐藏实体创建数、内部 ID、附件计数不会进入句柄。句柄必须与所属对局、座位一起解释，不是跨对局身份，也不是操作授权凭证。

公开随从回到手牌后，保留该槽位的已知牌面；隐藏费用修改不会因“记住牌面”而自动变成公开信息。公开变形更新当前牌面，既有日志保持当时的牌面。

实体进入牌库时退休当前句柄，并删除当前身份追踪；即使同一实体随后立刻抽回，也获得新句柄。旧日志仍保留当时事实，当前牌库不附加已知实体位置。正常 `Resolution.move(..., Zone.DECK)` 和洗入原语均执行此步骤；自定义处理器应使用公共区域操作，不得绕过迁移契约直接改区域。

## 4. 显式揭示与生成

```python
from hs_sim.engine.effects import AddToHand, RevealHandCard

AddToHand(player_id=2, card_id='CS2_182')  # 默认只由持有者获知身份
AddToHand(player_id=2, card_id='CS2_182', revealed_to=(1, 2))
RevealHandCard(target_id=existing_hand_entity_id, viewers=(1,))
```

`RevealHandCard` 仅接受当前手牌实体和非空、无重复的玩家元组；它公开身份，不授权读取隐藏附魔。指定玩家收到 `card_revealed` 事件，其他人不会收到该揭示事件。`AddToHand.revealed_to` 可为空；开局硬币使用 `(1, 2)`，明确记录双方已知身份，不在观察层按卡牌 ID 猜测。打出的牌、当前公开区域实体及本原型的烧牌会公开身份。

揭示与生成位于正常事务中。随后效果失败时，状态、RNG、句柄、已知身份、过滤日志一起回滚。对局结束不会自动揭示其余手牌或牌库。

烧牌显示、手牌槽位可追踪程度、回手已知信息持续期、公共资源可见程度等属于 R-025 的暂定显示契约；本批内部测试不等于国服目标补丁的完整可见性校准。

## 5. 日志在事件发生时过滤

`Information.record` 在原始事件产生时保存玩家记录；后续公开不能补写早先隐藏的抽牌身份，后续洗牌也不能抹除早先确实已公开的事件。

玩家日志采用显式事件类型和字段白名单，通常只包含 `sequence/kind/player_id/amount/source/target/choice/selected`。不透传 `Event.data`，不复制全局动作号/事件号、候选全集、洗入位置、修正规则路径、附件/来源链或行为名称。未知扩展事件和纯调试事件默认不发布；新增公共事件须单独设计投影并补测试。

来源牌不可见时不返回其手牌槽位句柄，避免仅靠伤害来源暴露暗牌位置。抽牌和入手事件可以展示目标牌背。选择内容与所选项只在选择方日志中出现；选项内部字符串 ID 转换为 `o1/o2/...`，选择 ID 转换为该玩家的 `c1/c2/...`。

每个玩家日志独立连续编号；被过滤的内部事件不会造成游标缺口。日志是精简事实记录，不是全知事件溯源或可以独立重算对局的回放格式。

## 6. 持久化与验证

`Information` 独立于卡牌规则读取的 `GameState` 保存，避免每个捕获上下文递归携带整份玩家日志。其已知牌面、句柄计数、选择映射和过滤日志进入 schema 74 的 `information` 字段及状态摘要；克隆、回滚、恢复和逐步回放均保留。恢复时严格验证字段、计数、引用、事件形状以及与当前选择/可见区域的一致性。

旧 schema 1～73 明确拒绝，不从恢复时的全知状态“猜回”玩家过去是否知道某张牌。外层 replay schema 仍为 1。摘要只能检测意外损坏，不能将不可信存档变为经过认证的信息来源。

运行演示与测试：

```powershell
python -m examples.observe_match
python -m unittest discover -s tests -p test_m3_information.py -v
```

[观察示例](../examples/observe_match.py) 从真实代表卡实验构筑开始，导出双方三个开局边界及各自新增日志到 `outputs/player-1-observations.json` 与 `outputs/player-2-observations.json`，并验证回放后完全一致。示例选择器仍在受信任宿主内运行。

[信息隔离测试](../tests/test_m3_information.py) 覆盖只改变对手暗牌、牌库顺序、隐藏候选数量、隐藏实体数或 RNG 后的观察一致性，也覆盖揭示/回手/洗回/变形、事件时点记录、非法输入、挂起恢复、错误回滚、完整回放与开局硬币。最新实际全量结果见项目状态。


## 交易与锻造补充（观察 v4）

自己的手牌新增 `hand_actions` 描述；对手牌背不包含该字段。交易在离手前显式记录原牌身份，进入牌库立即退休双方句柄；抽牌维持通常的私有身份。锻造事件公开手牌槽位，新形态默认只给控制者，旧记忆牌面退休而旧日志保持不变。此精确可见性仍属于 M6 待校准契约；详见 [手牌动作](m3-hand-actions.md)。

场上随从的 `minion_abilities` 仅公开能力键、展示牌与是否使用；使用开始/完成日志增加 `minion_ability` 描述，来源离场后仍保留事件时点的能力身份。不输出行为 ID、内部附件或条件。契约见 [泰坦能力](m4-minion-abilities.md)。

任务通过 `QuestSpec` / `QuestStageSpec` 声明，进度由带实例/阶段保护的 `AdvanceQuest` / `ResetQuestProgress` 修改。任务/任务线保证起手，支线任务不保证；公开区域与奖励选择共用玩家观察、事务和存档。详见 [任务契约](m4-quests.md)，持续玩家效果已接入 [独立契约](m4-player-effects.md)，奥秘已接入 [独立契约](m4-secrets.md)。

玩家视图自 v12 起提供每位玩家的公开 `player_effects` 列表，以及 `max_ongoing_effects` 容量。每个持续实例展示定义键、卡牌、种类和剩余回合；日志独立校验安装/计时/到期/移除描述，不发送全局附件 ID 或隐藏来源身份。精确公开策略与待校准项见 [玩家效果契约](m4-player-effects.md)。

玩家视图 v13 增加 `players[].secrets` 与 `max_secret_zone`。奥秘只投影牌背句柄、控制者、职业及拥有者或此前合法获知的卡牌身份；不投影隐藏属性、全局实例/窗口 ID 或条件。奥秘施放/部署日志不自动揭示，触发、移除或反制按明确策略公开；后来揭示不回填先前日志。`spell_targeted` 是内部诊断事件，不进入玩家事件白名单。精确公开策略仍待 R-053 国服校准。

玩家视图 v14 增加每方 `cards_played_this_turn` 和 `cards_played_total`，包含被反制的提交；技能/交易等不增加计数。不会输出完整出牌史、暗牌身份、原手牌索引或内部 play ID。历史的来源和结果仍是宿主数据，详见 [历史契约](m5-play-history.md)。

玩家视图 v15 增加公开实体/已知手牌的 `limited_triggers`，仅含关键词和剩余次数（包括 0），不输出能力 ID、行为/条件 ID 或法术候选；对手未知手牌保持牌背。公开 `limited_trigger_used` 事件只带可见来源、关键词和剩余次数。见 [有限次触发契约](m5-limited-triggers.md)。
