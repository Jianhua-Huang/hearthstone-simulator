# 托奇生成法术组与独立返还程序

时光循环者托奇`TIME_861`按当前主面3费3/3、获取3张过去法术接入。[官方34.2.2调整](https://hearthstone.blizzard.com/en-us/news/24250382/34-2-2-patch-notes)将旧4费4/4和4张改为3费3/3和3张，也修复了不应随机生成的内容进入候选的问题。本地`TIME_861e1`仍写4张，完整原行保留为旧说明证据，不用它覆盖主卡面或伪造可执行附魔。两个附魔记录均不注册为空白卡。

`CreateIssuedSpellSet`绑定一次实际原战吼，使用独立完整宿主`constructed.past.spells`、普通当前职业可收藏法术查询及原随机生成排除规则。所有合格定义在抽样前核验，三次有放回抽选沿原整数权重。完整原有序候选、三项实际选择、原职业、来源/玩家及MT19937前后进入不可变`IssuedSpellSet`，私有接受事件绑定原内容；来源或英雄职业以后变化不重新抽选。正式过去资格/系列/身份仍由M0核定，不从已实现列表构造假完整池。

未来进度由已有玩家长期效果承载。原`PlayerEffect`及`AddPlayerEffect`各增加一个可选`issued_spell_set`材料槽，只有精确的独立`card_played`原生进度声明可使用；普通光环、时钟、调查和资源材料不能混入。没有新增GameState账户、卡牌附魔或第二套玩家触发排序。原程序遵循现有双方与获取顺序，托奇离场不会删除已接受进度，重复战吼建立不同原程序。

原入手执行器逐张分配物理实体，先记录实际分配及普通满手结果，再沿既有创建/获取公告运行。相同卡面仍有三个不同实体。一次只排队下一张交付，选择中断后保存原程序和确切剩余项，不重新抽样。原程序安装/移除、各实际创建及接受内容有私有证明，裁掉整个程序或下一张交付会被边界校验拒绝。计划不保存嵌套整局状态，避免重复生成造成递归历史膨胀。

当前内部进度政策读取原三物理实体的真正完成出牌，并按原玩家和事件包含的出牌ID限制历史前缀；同名其他牌、复制的新实体与单纯CAST不替代原成员。反制后仍真正完成的出牌按“使用”计入。计数使用原出牌时冻结种类，[官方34.6修复](https://news.blizzard.com/en-us/article/24242740/34-6-patch-notes)明确变形成随从的生成牌不应返还托奇。复制是否继承原成员、变成其他法术、精确返还窗口及当前CN反制/转手政策仍待M6，当前物理实例政策不能当成官方全部裁定。

三个原成员的首次完成记录齐备时，以原实例调用共享`ConsumePlayerEffect`，移除在公告前提交，已捕获的旧回调不能再发第二份。返还工作携带原已消费实例及确切三个完成记录，私有消费证明要求实际待续奖励保全；原入手执行器负责新托奇与满手燃烧。选择恢复、异常回滚、回放和消耗语义继续共用。

原程序是内核私有进度材料，不进入玩家效果列表或对应公开事件；玩家仅看到本人实际获取的卡。完整候选、RNG、物理分配、内部原实例与程序内容不传给玩家。校验用于内部一致性，不认证未签名存档的来源。

协议core581/schema475、观察106、内容preview-v406；命令12/replay1保持。新执行模块4个效果和1个明确payload，无新模型类或GameState账户。实际进展、验收和下一项仅维护在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)，完整正式过去池与国服校准仍独立开放。
