# 独立青玉魔像成长

对应 B07/U30，只补玩家共享成长和实例固有身材。召唤、普通复制、死亡、复活、回手、沉默、选择与事务继续使用既有模块，不开发机制组合矩阵或特殊授予。引入时 `prototype-v160` / `core-effects-v160`，schema155，观察68，命令10、回放1保持。实际执行、验证和下一项以[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)为准。

## 依据与待校准

[暴雪历史介绍](https://hearthstone.blizzard.com/en-us/news/20372477/secrets-of-the-jade-lotus-11-21-2016)说明青玉帮的三个职业及逐次召唤变强。[社区规则页](https://hearthstone.wiki.gg/wiki/Jade_Golem)描述从1/1逐次增加基础身材、30/30上限、费用最多10、玩家计数归属、沉默保留及满场尝试仍推进；它是次级调查依据，不能替代国服校准。出生身材在普通复制、移区和复活时保留，是本批明确采用的生命周期政策，同样待 M6 核对。

本地36022条提取记录中找到两组各四档模板，分别从1、4、7、20起；完整[原始记录与行哈希](../data/support/jade-basics.json)固定八个模板和青玉之灵、青玉游荡者两张必要来源。模型复用这些已取得的模板，另保存实例身材，没有编造30个新卡ID。这是内部表示，并不证明当前国服只有八种官方实体卡面；历史外部列表还列出不同身材ID。精确实体身份、当前正式池和模板/身材映射仍属于 M0/M6。

## 公共入口

注册 `JadeGolemFamily(id, version, forms)`；`forms`必须是四个不同的命名模板，档位固定为1～3、4～6、7～19、20～30。不同图稿族不能共用模板ID。已适配模板必须是不可收藏的普通随从，基础身材与费用符合该档最低值；缺失命名模板保留为执行缺口。

卡牌返回 `SummonJadeGolem(player_id, source_id=None, family_id='jade.classic', count=1, position=None)`。每次实际执行都读取该玩家共享计数，身材取 `min(30, count_before+1)`，费用取 `min(10, size)`。族只决定模板图稿，同一玩家的两个图稿族共享成长，不按当前英雄职业分开计数。

默认在场上来源右侧召唤，其余来源在右端；显式位置沿既有召唤插入政策。满场不创建实体，但尝试记入成长；下一次可以更大。缺失所选模板即使满场也报错，不能跳过覆盖检查。零次无操作；非法类型、来源、族或预算明确拒绝。多次召唤逐次执行，前一次正常入场反应完成后再处理下一次；等待恢复不重复记数。

## 状态与生命周期

`GameState.jade_history`使用不可变 `JadeGolemRecord`保存原玩家、来源、族/版本、增长前缀、身材、模板、实际实体或满场失败、回合和动作。`jade_count(state, player_id)`读取本人的尝试数，上限只限制身材，不截断历史计数。

`Entity.jade_size`和死亡记录的同名字段保存出生时固有身材；它决定 `base_attack`、`base_health`和 `base_cost`，没有伪造可被移除的附魔。真正的增益和费用变化仍由原附件管理。私有尝试收据与历史校验数量、顺序、玩家、来源、身材和动作；它不增加一个游戏触发窗口。

| 原有操作 | 青玉基础处理 |
| --- | --- |
| 沉默 | 移除普通文字/附件，保留固有身材 |
| 当前/基础复制、手牌复制、冻结复制材料 | 从原物理牌保留固有身材；普通附件仍遵循各自复制模式，不增加成长 |
| 回手、洗入牌库、普通移区显式重置 | 保留固有身材，原重置流程清除普通局部状态 |
| 复活及冻结死亡材料 | 读取原死亡身材，不读取后来玩家成长；不增加成长 |
| 转控 | 身材保持；实际生成来源按执行控制者/原死亡控制者的玩家计数 |
| 明确变形 | 从新模板最低身材开始；变为非青玉清除固有青玉字段，不擦除玩家历史 |
| 直接按模板创建/召唤 | 使用模板最低身材，不冒作一次青玉成长 |

物理手牌/牌库、跨区随从和死亡候选的印刷费用查询读取实例固有费用；冻结招募候选保存原jade_size，不从后来的实体或玩家成长反推。独立生成池的模板元信息仍按其真实记录处理。冻结复制/招募材料显式携带原身材，死亡材料复用完整死亡记录，不从后来实体反推。

## 恢复与玩家接口

非法身材类型、身材与模板/基础属性不一致、其他牌借用青玉字段、成长前缀或版本错、缺失/改写收据均拒绝恢复。引入时快照schema155严格拒绝1～154，旧快照须使用原引擎，不静默迁移。选择、克隆和动作回放沿原公共入口；主体异常沿原事务回滚计数、实体、支付、事件和随机状态。

观察只向本人提供可选 `jade_count`，对手计数不进入该座位字段。公开魔像通过原实体投影显示身材与允许的费用；不新增全知历史、内部身材字段、收据ID、模板族版本或牌库追踪。玩家目标DTO允许本人精确非负整数计数，不能要求对手也提供该字段。

## 实际范围

只有八个真实模板及两张必要来源在隔离测试注册表适配；生产代表64、合成3保持。新图稿不等于其特殊来源牌已接入。未扩展“青玉＋其他机制”、特殊手牌授予、历史重新出牌的逐来源矩阵或批量青玉卡池；没有据此宣称所有历史来源、U30完整卡族、国服校准或 M0/M6/M7 完成。新基础与直接受影响测试的实际报告见[验证证据](../outputs/jade-basics-20261009/verification.json)。
