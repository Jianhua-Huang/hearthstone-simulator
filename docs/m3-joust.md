# 独立比费（Joust）契约

本项只补双方牌库随机揭示、费用比较及结果传递。卡牌的奖励继续使用现有效果，不增加关键词枚举、组合族或卡牌专属调度器。实际验证与下一项以[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)为准。

## 证据与范围

[官方2015年介绍](https://hearthstone.blizzard.com/en-us/news/19843154)说明双方牌库各随机揭示一张随从，发起方费用较高才获得奖励。这是历史设计依据，不是当前国服正式规则校准。

[本地完整原始记录](../data/support/joust-basics.json)固定AT_058皇家雷象、LOOT_170乌鸦魔仆和AT_048治疗波。皇家雷象提供随从比费并抽取选中牌的必要代表，乌鸦魔仆提供法术比费范围的真实文本依据；治疗波当前提取文本为8/16治疗，不能套用历史7/14数值。只有皇家雷象在[隔离专项注册表](../tests/test_joust_basics.py)完整适配，后两张仅作文本证据。生产代表包和正式卡池没有因此扩张。

官方介绍还使用“洗回各自牌库”的表述，不能据此声称已证明牌库顺序保持。本项采用不移区、不重排的本地政策；费用采用实体基础费用及自身费用附魔，空池政策亦属内部规则，均待国服校准。未成功读取的团队历史推文不作为已取得的原始规则证据。

## 公共效果与结果

```python
from hs_sim.engine import Joust, joust_result
from hs_sim.engine.effects import GainArmor

def start_joust(ctx):
    return [Joust(ctx.player_id, 'joust_reward', ctx.source_id)]

def joust_reward(ctx):
    result = joust_result(ctx.event)
    return [GainArmor(ctx.player_id, 2)] if result.won else []  # 奖励示意
```

`Joust(player_id, on_result=None, source_id=None, target_id=None, kind=CardType.MINION)`只接受真实文本已有的随从或法术范围。回调必须是已注册行为且有物理来源；target仅供回调使用。没有回调时仍执行揭示及比较，但不产生奖励。

双方候选复用`zone_candidates`，按当前实体牌面类型筛选自己的牌库。每张物理牌一个权重，相同卡ID不合并。先验证完整双方候选，再按发起方、对手的顺序分别采样；非空池各一次，空池不消耗RNG。不创建实体，不移区，不抽牌、不触发疲劳，也不消耗费用附魔或支付资源。

比较使用已有`local_cost`：实体基础费用经过其费用附魔，最低费用沿原费用系统。没有把牌库牌假装为手牌报价，不执行手牌支付、全局出牌优惠或固有手牌条件折扣。复杂牌库费用语义尚未认证，真实来源需要时按证据补齐。

双方都有牌时，发起方费用严格较高才获胜，平局失败。发起方有牌而对手空池时获胜；发起方空池或双方空池均失败。这些空池行为已经内部验证，不能称为已校准国服事实。

`joust_resolved`保存原双方物理引用、当时费用、范围和发起方。`JoustCard`及`JoustResult`是不可变读模型，`joust_result(ctx.event)`读取原比较而非重新查当前牌库。奖励回调沿公共解释器，接收揭示时捕获的上下文；事件反应或奖励中的选择恢复后不重新抽样，也不因后来改费重新计算本次胜负。每次实际Joust请求独立接受新结果。

## 奖励与实体生命周期

皇家雷象的获胜奖励复用`MoveCard(selected.card, actor, Zone.HAND, draw=True)`，抽取所选物理牌而不是牌库顶牌或同名新实体。正常抽牌、容量、烧牌、历史与反应由已有区域及抽牌模块负责；落败没有奖励移动。

必要公开手牌使用`RevealCapturedHandCard`，绑定准确的手牌区域、卡面和进入序号。烧牌或引用失效时跳过揭示，不把后来同名牌当作原选中牌。公开知识继续由原信息模块维护。揭示与抽牌反应的精确官方先后仍待校准。

Joust本身是一次性结算，没有需要复制、沉默或到期的持久附件；引用失效及奖励移动沿现有实体生命周期。未知卡或行为明确报错，异常沿Game事务回滚付款、RNG、事件及公开知识，不静默删除候选或当作白板。
