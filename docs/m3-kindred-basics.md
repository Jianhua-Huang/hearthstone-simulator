# 延系的独立基础表达

执行结果、已知差异和下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。本页描述已有公共能力如何表达真实延系条件、普通出牌收益和固有减费，不宣布完整延系来源或国服时序校准完成。

[国服公布公告](https://hs.blizzard.cn/news/24204896/index.html)和[暴雪英文公告](https://hearthstone.blizzard.com/en-gb/news/24204896)将延系定义为：本人上一回合打出过具有相同随从种族或法术学派的牌，当前延系牌获得额外效果。它不是“与上一张牌相同”。前一回合中间打出不匹配的牌，不会清除已满足的条件；多个匹配提交也只是一个成立的条件。

## 共用回合与提交事实

```python
from hs_sim.engine import query_for_definition, query_previous_owner_turn

relation = query_previous_owner_turn(
    context.state, context.player_id,
    query_for_definition(registry.card(native_card_id)),
)
if relation.matched:
    return ordinary_effects
return ()
```

直接使用[自身回合与冻结提交卡面](m5-owner-turn-history.md)，不新增延系历史、可变成立标记、资源账户或组合查询。实际提交者、真实自身区间及当时注册卡面的类型、完整种族、单学派均来自原历史；以后变形、转控或离场不重写提交卡面。查询返回完整有序 true/false 候选后才聚合，不让前面的匹配隐藏后面的未知。

原 `owner-turn.latest-closed-v1` 选择本人最近已关闭的实际区间。当前本人回合、对手的提交、直接召唤、获得和自动 CAST不冒充前一自身回合的手牌提交；空的最近区间会取代更早的匹配区间。被反制的成功付款提交仍保留，非法操作及异常事务回滚不保留。额外、跳过与开局继续使用已有真实区间，不按全局回合奇偶猜测。这是既有 R-158 内部政策，精确国服边界仍需 M6 校准。

随从共用原种族交集及 `all` 规则：明确非空种族可匹配 `all`，已知空不匹配；查询主体或所选区间内候选种族未知时明确报错。法术共用明确单学派相等，无学派不与无学派匹配。本批不增加当前种族条件、多学派猜测或任意谓词。

## 效果与付款阶段

环形山实验体没有战吼声明，使用既有随从 `on_play` 主体：条件成立则返回一个普通 `CopyMinion`，直接召唤或复制不会再执行这个出牌主体。封冻沉眠使用原法术主体，先计划四点法术伤害和一次抽牌，成立时再计划一次抽牌；伤害、死亡检查点、抽牌及终局中断由原解释器结算。条件按各原主体接受时的 detached State 读取；已有队列和待选恢复保存这份效果计划，不新增一套延系接受或重复执行器。

墓晨太阳花在原付款前报价使用 `IntrinsicCostSpec(delta=-2)`，其既有默认条件为 `previous_owner_turn_type`，从该原印刷 Holy 定义构造查询。原 `CostQuoteFact` 和固有阶段保留完整回合、候选及付款依据；4费/2费在原接受窗口冻结，主体仍抽两张牌，选择恢复不再付款。其他费用层顺序仍沿既有契约。

本批不修改运行源码，不添加 `Keyword` 枚举成员或协议字段。按延系身份抽牌、下一次延系重复等真实卡牌消费者尚未接入，不能用本页的普通主体和费用证据宣称这些来源已支持；后续依据真实需求处理。
