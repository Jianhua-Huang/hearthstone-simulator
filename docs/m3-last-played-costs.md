# 最近本人使用牌的原费用输入

普通物理随从声明 `PlayerPlayedClassCostSpec(card_class=None, profile_id='cost.player-last-played-cost-v1')`，继续使用 `CardDefinition.player_played_class_cost`。现有模块已承担[原职业](m3-player-played-class-costs.md)、[本回合牌数](m3-player-played-turn-costs.md)及原起始套牌外牌数计费；新有限政策同样读取既有 `play_history`，不新增历史、计数账户、模型类型、费用执行器或组合机制。

## 原根和数值

先捕获全部双方出牌原行，再选择 payer 最近一个物理手牌根。选择结果必须为空或唯一原 play ID，数量是该根原使用时已接受的数值费用；为空时零。它不是总牌数、费用总和、印刷费用，也不是后来实体的当前报价。最近一次零费根会替换先前折扣，数量即使超过本牌费用仍完整保存，结果为 `max(0, base_cost-quantity)`。

原付款可使用法力、生命或其他账户，这个输入保存原数值费用，不猜成“实际法力消耗”。本人跨回合保留最近根，对手牌、英雄技能、普通召唤、自动施法或获取操作不会替换该根。已付款的反制或尚在等待完成的根沿现有原手牌提交政策保留；失败事务回滚则不产生根。这些精确来源/时点仍待国服校准。

`PlayerPlayedClassCostRow`新增严格非负整数 `accepted_cost`，直接读取已校验的 `PlayRecord.cost`，由原提交报价和付款收据约束。完整行仍保存原冻结卡面、turn/action及获取身份；包括未选中的根、对手及零费行。其他消费者继续使用原计数和匹配规则，新增原费用只作为完整前缀的一部分，不修改数量公式。

## 报价、生命周期与保存

原固有阶段、物理/生成报价、合法动作、本地/外部费用层、最低费及付款管线共用。新政策不与另一数量或条件公式叠加，不提供任意来源、职业过滤或费用表达式。当前主体在提交前尚未是最新根，所以不能用这次将支付的价格为自己定价；接受后新报价才可使用该根的原费用。

事实保留全部原行、游标、分配和时钟、payer、完整唯一选择及前后值。原窗口重新捕获完整输入；已接受费用校验原前缀，允许后来完成/中断或新增根，但旧费用保持。变形、转控、死亡、回手及后续费用修改不重写原使用费用；查询不推进RNG、事件或分配，也不把折扣写入缓存以反复叠加。

现有JSON `_row`和typed-frame冻结类型编码要求新字段显式存在，缺失、额外、bool/负值或错误类型拒绝。恢复、克隆、回放、选择续接和异常回滚仍沿原管线。完整费用前缀、原选择和对手隐藏手牌留在宿主内，玩家只获得有权观察的当前费用/动作。内部前缀一致性不认证未签名归档来源。

## 必要代表与规则边界

[完整本地原行](../data/support/last-played-cost-basics.json)只隔离适配CATA_616戈隆巨人：9费8/8中立史诗，无额外主体或关键词。生产代表和正式池不扩张。原卡文证明最近牌费用输入的需求，但没有完整证明印刷/已接受费用依据和各类来源；此处采用明确的原已接受费用内部政策，精确CN仍需校准。

[官方35.4补丁](https://hearthstone.blizzard.com/en-us/news/24266874/35-4-patch-notes)记录了冰冻陷阱回手时重复重新计算戈隆巨人费用的修复，支持保留这种生命周期差异的核查义务；不能据这条说明宣布费用依据、当前CN或陷阱组合已经验收。本增量只验证普通返回和纯报价不反复修改原费用，不扩展专用组合。

新字段也进入原首次/周期费用和连续元素费用的共享出牌行，因此保存结构引入 `prototype-v293` / `core-effects-v292` / schema257，旧1～256需原引擎。观察84、命令12、replay1保持。无新GameState/Player/Entity字段、模型类型或执行器。实际验证、已知差异和下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护，完整基础库存/阶段和M0/M6/M7继续开放。
