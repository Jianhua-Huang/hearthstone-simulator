# 唤光长枪：双方英雄的原吸血恢复

BE_000完整原行和中英文官网主面固定在[data/cards/lightcaller-v1.json](../data/cards/lightcaller-v1.json)。原3费4攻2耐久圣骑士普通武器及吸血关键词保持；没有具名衍生依赖。双方吸血的文字有完整一手卡面，精确国服结算时序仍待M6。

## 有限原生声明

`LifestealRecipientProfile(card_id, recipients='both_heroes')`注册到原Registry，当前只允许印刷带吸血的武器。声明严格、只读且进入注册表指纹；默认代表包没有新声明，原指纹保持。它不是全局治疗光环，也不为玩家安装额外可复制状态。

在原伤害健康批次里，只有实际伤害大于零、原来源含吸血且不是吸血转换包的段，才进入原恢复列表。`lifesteal_recipients.targets`从同一批次开始状态读取真实来源：英雄战斗伤害读取其原装备武器；明确归于该武器自身的效果伤害读取原武器面。其他随从、法术、英雄技能、英雄非战斗伤害和普通吸血武器保留原控制者单英雄接收规则。不能因玩家装备唤光长枪而给所有来源的吸血增加接收者。

本地有序政策为原伤害控制者英雄、另一方英雄。每项请求量都来自该原段的实际damage_dealt，含护甲与过量，不用请求量、目标剩余生命或第一位实际恢复量代替。每个接收者分别报价原治疗类型的来源和目标规则，保留同一原伤害来源与控制者信用；分别记录实际恢复、过量、阻止或转换结果。

## 原健康批次与生命周期

两个普通Heal请求直接并入原settle_health_batch的吸血恢复列表，沿同一组批次开始规则准备，再顺序数值提交。原治疗转换组的一次性消费、反递归、护盾/护甲/替换、健康历史、事件捕获、死亡检查与武器耐久执行器不复制。全部数值结果与历史在原首个事件反应前完成；治疗转伤害包仍有from_lifesteal，不重新产生吸血。

最后耐久的本次实际伤害仍按原装备事实恢复两个英雄，随后沿原攻击完成和损毁；以后换武器不会继承本效果。转移武器后的实际控制者成为伤害及两项恢复来源。来源或目标在后续反应改变，不重解释已提交的原结果。

当前只扩展接收者，保留原型既有同批致死/救援政策。两个英雄的顺序、过量/转换、是否能在终局检查前救回致死英雄，以及来源复制或特殊变形的精确正式继承均需国服证据；没有从普通论坛推测认证这些规则。

## 保存与信息

原HealthResult、damage_history、healing_history、事件及结算帧保存两项实际恢复，不新增计数器、事件、Effect、payload或State字段。原JSON/clone/独立注册表回放和动作/选择事务负责暂停与恢复；恢复不能重新治疗或重新扣耐久。玩家观察继续使用原投影，不暴露注册表声明、私有健康依据、RNG或结算帧。
