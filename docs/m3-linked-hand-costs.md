# M3：原随机手牌费用与原生亡语关联

无穷助祭 `END_018` 使用既有原生亡语记忆，增加有限 `NativeDeathrattleSpec('cost_link')` 和 `DeathrattleMemory.cost_links`。每项 `RememberedCost` 只保存实际战吼 ID、原物理目标、原手牌获取 ID 和本次费用附魔 ID。没有新 `AbilityInstance` 或 `GameState` 字段，不把目标或费用放入通用进度字符串。

`SetRandomHandCostForDeathrattle` 必须属于已开始、未结束的真实战吼，其原主体声明必须是此类型。它从原执行玩家的当前完整手牌按物理实体随机选一张；空手不抽随机。原 `attach_cost` 安装普通本地设费，原生附件记录完整关联后才发布普通费用通知，通知导致来源死亡或复制时已能取得记忆。真实多次战吼各记自己的关联；已离开或失去相应附件的载体仍可执行战吼效果，但不会凭空得到一份新亡语。

`RestoreRememberedCost` 只接受实际已开始、未完成的亡语及其冻结记忆中原有的关联。原获取历史、战吼声明、实体和附件分配范围均核对；若对应附件仍在，则验证它确为原来源的无穷费用层，再用原 `remove_attachments` 删除这一层。其他费用、属性、支付账户与合法后续变化保留，连续存储移动或转手不按新槽位另找目标；旧附魔已被正常重置时不覆盖新卡面。重复亡语不会重新处理已移除的层。

当前复制来源继承原冻结关联，基础复制、普通回手重置、沉默与变形沿既有原生记忆生命周期；复制目标牌本身取得新的费用附魔 ID，不冒充原物理目标。当前/基础复制、死亡捕获、待选帧、恢复和回放复用原解释器。完整关联仅供宿主，不向玩家输出原手牌获取、战吼或附魔身份；费用继续通过原可见实体查询显示。

完整原卡及 `END_018e/e2`、双语官网主面只证明战吼设为无穷和亡语恢复的方向。本地数值政策复用现有正 int32 上限 `2147483647`，恢复采用删除原层、保留其他合法层的政策；精确数值、重叠费用优先级、目标离区与获取/亡语窗口仍须 M6 国服校准。原 e2 作为完整原始证据保留，不声称内部通用附魔标签等于客户端实现。

裂变重组等会创建新实体及新附件的来源不会被此链接自动重定向。旧玩家问题报告可作为校准线索，不能据此判断固定国服37.0是否仍有同样行为或已修复；这部分以及所有实际可达来源仍是完整交付门槛。内部代表通过不等于已闭合完整国服支持，也不提供未签名存档的原始来源认证。
