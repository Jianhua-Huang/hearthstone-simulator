# 相邻活体的完整亡语材料

真实入口为BE_731原始石牙兽，3费3/2猎人野兽，战吼获得相邻随从的亡语。完整原行与中英文完整官网面保存在`data/cards/adjacent-deathrattle-copy-v1.json`。正式卡池、精确国服时序及完整拼装域仍独立验收；实际执行和下一项只在原两份台账维护。

## 当前物理邻位与一次接受

薄适配器请求`GainAdjacentDeathrattles(MinionReference)`。执行时受益者必须仍是原牌面、原控制者和连续原驻留的存活活动随从；失效不映射其他同名牌或后来的驻留。沿本人当前战场序列取紧邻左右两个物理位置，地标不被跨过，休眠/死亡/待销毁的相邻体不提供材料。

每个合格邻体的未消费活动亡语附件按左右及原附件次序完整捕获，不在查询时执行亡语条件。全局禁止触发不抹去结构声明。原组在任何新附件分配或通知前保存；所有新附件安装后才发布原`ability_granted`通知，不逐个重新查询新局面。

## 原声明和记忆

新`CopiedDeathrattleSource`保存原物理分配事实、完整原附件、组合身份及捕获时钟/分配上界；`AbilityInstance.deathrattle_copied_from`持有该材料。保留行为、原印刷/授予声明、已消费卡参数和完整原生记忆，包括原抽牌、弃牌、休眠、发现、费用链接及记住的随从复制材料。它不复制同体的其他触发器或关键词，后来的原体变形、沉默、增长或离场不会改写已取得的亡语。

新附件有独立递增ID、此次授予来源与新的可移除永久生命周期；不借用原临时期限、磁力组或消费状态。它与`deathrattle_inherited_from`在顶层互斥，原旧来源仍完整保存在材料中。取得的亡语再被取得，或死亡继承与活体取得互相衔接时，原附件ID必须严格早于新附件，禁止未来、自引用或截断来源。

原物理抽牌/弃牌等链接仍交已有独立历史校验；新附件须等于原材料按同一规范化函数生成的完整值，不能只留下行为名称或改写一部分记忆。对未签名存档，不宣称能认证原接受局面的外部来源、所有附件原属关系或整套主体计划；原驻留/声明/分配界限和材料一致性校验与这种认证不同。

## 普通生命周期和保存

取得的亡语继续交原自然死亡、主动/历史触发、重复与数量解释器执行，不新增亡语执行器、死亡检查点或状态账本。沉默、回手、变形、转控、当前/基础复制及事务回滚复用原能力生命周期；当前复制保留材料，基础复制和回手重置不保留授予。控制归属按实际亡语捕获决定，原记住的物理牌不会换成新的同名牌。

原死亡记录继承新附件时，顶层改接真实`death_id`，完整活体来源仍在原死亡记录内，不伪装成没有发生的死亡。普通记忆载体的既有组合限制保持；有完整活体取得证明的新授予可在其有效随从载体保存，不能据此认证尚未闭合的拼装来源或完整可达域。

新材料进入原FrameCodec和严格JSON读取，原状态、死亡记录、待选/执行捕获及复制材料都核验同一证明。schema507拒绝旧1～506，core618；观察115/命令12/replay1保持，玩家DTO不包含原材料、行为、记忆、队列或随机状态。精确邻位/休眠/受益者变形窗口、临时亡语取得后的期限、原记忆继承和通知顺序仍为待M6的内部政策。
