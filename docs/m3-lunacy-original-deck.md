# 愚人套牌：原牌库法术的随机保费变形

DMF_108「愚人套牌」按固定本地过去法师名单接入，为两费、无学派的传奇法术。完整原行、附魔证据及两份官网主面见 [源记录](../data/cards/lunacy-card-v1.json)，经共享准备器核对固定目录和完整官网响应缓存。本契约说明运行规则；实际进度、执行证据和下一项只维护在 [项目状态](project-status.md) 与 [机制清单](mechanism-backlog.md)。

原生主体只组合已有 `TransformStoredFromPool`。它在原 CAST 的主体窗口，以原牌库顺序捕获当前本人所有物理 SPELL 的完整 `CardReference`、当前局部费用、原费用层查询和保留费用。手牌、随从及后续反应插入的新卡不进入这份清单；两个同名实体仍分别占一项。所有请求在第一次交付前构造，不用后来场面重建原库存。

本地费用层为 `min(10, max(0, local_cost)+3)`，保留值为原捕获的局部费用。输出从固定普通宿主的全部职业可收藏法术中选择，使用原完整池、权重、整数抽样及当前存档版本；不能只留下已实现的输出。实际空层沿现有 `empty='skip'` 保留原牌且不消费随机，缺少可执行定义的真正候选仍明确报错并走原事务回滚，不能当作空池。

[2024 年社区说明](https://us.forums.blizzard.com/en/hearthstone/t/deck-of-lunacy-with-incanters-flow/135816)支持用已减费的牌库费用决定变形层和保留值；[历史高费讨论](https://us.forums.blizzard.com/en/hearthstone/t/how-does-deck-of-lunacy-work-with-high-cost-spells/47181)描述十费封顶和跨职业输出。这些不是当前国服开发者裁定。[历史官方已知问题](https://us.forums.blizzard.com/en/hearthstone/t/known-issues-%E2%80%93-patch-200/56567)曾提到变形可能覆盖卡牌固有减费，因此高于十费、缺层、固有与外部费用层次、精确同时窗口仍登记为待校准边缘。本轮按上述明确本地政策执行，不等待实测。

公共入口仅扩展原 `TransformStoredFromPool` 的费用保留：牌库路径要求原目标为法术、输出为可收藏法术、明确单一费用层且不超过十、存在原来源，并继续禁止混入随从属性材料。旧手牌保费与随从完整数值路径保持。原 `transform_stored_entity` 负责重置成新印刷卡面、附加原保留费用、生命周期及通知；实体 ID、owner/controller 和牌库槽由原执行器处理，不创建手牌或新实体。

每步执行使用原请求和当前连续驻留；原目标离开、重新入手或换面后跳过旧引用，不借同名新体。来源在第一次通知中回手，不取消已经接受的后续请求。等待保留原后续引用、查询与费用；已有私有 `StoredPoolTransformDraw` 保存完整有序候选、原来源/目标分配、所选卡和 MT19937 前后状态，并沿原恢复、clone、回放、事务与玩家投影边界核验。本批不另建变形器、付款器或状态账本，也不提供未签名存档的外部来源认证。

core809 保护新增的受限牌库保费语义，schema629、Effect/payload 类型集合与状态布局保持。内容包 v713 新增这张实际可达历史法术及元数据，不改变标准根、部件或其他专用池的成员、角色和权重。原牌库法术输出可执行与整个过去法师来源闭合仍分别验收，不能以一张定义注册替代完整目标。
