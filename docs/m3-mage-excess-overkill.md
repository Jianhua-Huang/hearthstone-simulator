# 法师的邻位超量伤害与原结果超杀

[完整来源包](../data/cards/mage-excess-overkill-v1.json)保留DRG_321火球滚滚、SCH_348燃烧、TRL_317冲击波的三条完整原行及六份中英文官网主面。它们是标准过去法术来源的可达依赖，不新增标准组牌根；名单和完整生产域的资格另行验收。

DamageMinionExcess只允许neighbors和rolling两种有限政策，绑定原MinionReference、实际SPELL来源及非负基础伤害。原引用失效按普通stale处理；不寻找同名或同id的新驻留。它接入既有excess_damage分派和settle_health_batch，没有另写扣血、死亡或反应结算器。

来源层先报价，包含一次法术伤害及来源倍率；每个已分配份额再独立经过目标层、护盾、免疫、重定向、生命底线和共同死亡检查点。来源转换和来源材料沿原prepare_health/partition_source传递，不给每个份额重新增加法术伤害。用于判断火球是否需要抽方向的纯报价不消耗能力或随机数，实际结算窗口会重新核同一来源。

| 卡牌 | 有限分配方式 |
| --- | --- |
| 火球滚滚 | 对原目标分配min(来源预算, 当前生命)，余量沿单一方向依次分配。每个原目标最多消费当前生命大小的预算；边界外不回头，不重新选择方向。 |
| 燃烧 | 原目标接受完整来源预算；左右原紧邻各接受max(0, 预算－原目标当前生命)。两侧不分摊彼此的余量。 |
| 冲击波 | 对双方当前活跃、存活且未待死亡的普通随从创建同时SPELL伤害批；每个原HealthResult按既有is_overkill决定一次普通Mage法术生成。 |

火球只有存在余量且两侧都有物理槽位时抽一次方向；只有一侧则使用该方向，孤立目标和无余量不抽。左右候选保留物理槽位，抽中非法阻挡方向会停止，不改抽另一侧。这是明确的本地RNG窗口政策。沿路休眠、地标、交互对象或其它非活跃槽位阻断；燃烧不跳过非法紧邻寻找更远随从。[暴雪27.6说明](https://news.blizzard.com/en-gb/article/23989479/27-6-patch-notes)明确火球不再跳过休眠或地标。

一次原批冻结全部受击者和份额，再沿普通共同结算执行。亡语召唤、复生或其它反应产生的新对象不加入原路径；死亡前已报价的来源能力不因批内死亡而消失。护盾、免疫和目标倍率不改变已分配的后续余量。原始349脚本标签原样保留；它不被简单等同于整张法术不受法伤影响。[玩家对莫尔葛的讨论](https://us.forums.blizzard.com/en/hearthstone/t/rolling-fireball-and-moarg-artificer/29940/1)及[护盾比较](https://eu.forums.blizzard.com/en/hearthstone/t/piercing-shot-divine-shield-interaction/5998/4)支持这些局部解释，但不作为国服精确校准证明。

冲击波沿原结果事件回调，不扫描后来生命或墓地推测击杀。超杀要求原活跃玩家等于来源控制者、原生命为正且未待死亡、实际未被防止的伤害大于原生命并达到致死；友方随从也可符合，精确击杀、护盾、免疫和对方回合均不符合。奖励用原constructed.cards完整普通候选和Mage职业条件，明确排除中立与其它职业；满手、空域、未知合格定义和生成RNG复用原公共管线。未知成员报错并回滚，不能裁掉后继续生成。逐原结果交付的精确反应窗口暂为本地政策。

内核core-effects-v789/schema613新增一个Effect，序列化依原公共FrameCodec，拒绝旧1～612；没有新增payload或状态字段，玩家观察/命令/回放布局保持。点燃的原生递增材料仍是下一增量，不作为本批支持项。版本/热修对齐与国服规则边缘按用户授权暂缓；完整目标、实际验证和下一项仍只在原两份台账维护。
