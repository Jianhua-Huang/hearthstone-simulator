# 原生模块化构筑与印刷卡面

本契约对应奇利亚斯豪华版3000型自身的构筑规则。执行结果与下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护，不把任意两个机制的组合列入本项。

## 依据与输入

[国服公布](https://hs.blizzard.cn/news/24056183/index.html)明确：构筑时选择两个不同功能模块与一个外观，合并费用、身材和效果。[资料片官方页面](https://hearthstone.blizzard.com/en-gb/expansions-adventures/whizbangs-workshop)列出八个功能模块、八个外观选项。数值来自固定本地快照，[22条完整原始记录](../data/support/modular-deck-basics.json)保留主卡、功能模块、外观与附魔原文；canonical pin为`e28d94d06f1f30ee48724f821c7c4052cd7f4792776e6644995febb05d1087a4`，不据此认证最新正式池。

主卡raw费用、攻击与生命为空，是构筑蓝图。不能给空值补0并当作普通随从，也不能直接套用E.T.C.消费侧板或星舰建造组件。

`ModularProfile`声明原始主卡ID、名字、审核过的中立可收藏传说构筑身份、有限功能与外观选项，政策为`modular-v1`。`ModularSelection`保存两个不同功能模块和一个外观。功能选择顺序没有战斗意义，只对这两个ID做规范排序；外观原身份完整保留。原始关联外观标签不直接当作“只能选择对应外观”的限制。

## 构筑编译

注册表分别保存蓝图、非物理功能模板和已编译卡面。功能模板采用已有不可变`CardDefinition`，本项允许原费用、身材、关键词、战吼、亡语、触发、光环及固有费用声明，并保留已独立核实的[场上随从计数费用](m3-board-minion-costs.md)声明；其他字段明确拒绝。普通定义校验和命名行为引用校验复用原注册表。有限选项可以尚未适配；选择未适配模块明确报错，不能作为白板，也不能悄悄从选项中删除。

宿主在冻结注册表前调用：

```python
selection = ModularSelection("TOY_330", ("TOY_330t96", "TOY_330t99"), "TOY_330t5")
face_id = assemble_modular_card(registry, selection)
# 完整DeckSpec.cards使用face_id；格式合法池使用原可收藏主卡TOY_330。
```

编译只创建实际请求的卡面，不枚举全部224种配置。ID由政策版本、原蓝图、完整两个模块及外观的规范SHA-256生成，不消费RNG。费用、攻击和生命相加，关键词合并去重，已有触发、光环与固有费用声明保留各自有序条目。原生族最多一个战吼、一个亡语；遇到两个同类主体明确报未审核，不提前造任意主体组合接口。编译先完成声明、模块、引用和结果校验，再同时安装卡面与选择映射；失败不留下半张卡。相同选择重用相同ID，冻结后不能新增或重新编译。

蓝图、功能模块和外观没有普通物理卡定义。只有审核并编译的完整卡面可以进入普通区域。编译卡面的格式资格继承原主卡ID，原主卡禁牌和单个卡面禁牌都适用；所有配置共享原传说`deck_identity`副本限制。不能仅靠将合成ID列入合法池绕过原主卡资格。普通职业、符文、牌库容量与其他构筑检查保持。

## 战斗与生命周期

编译结果是普通随从的完整印刷定义，不是对0/0主卡追加临时增益。`Game.from_decks`沿原开局、实体创建、洗牌、换牌及硬币管线，每个实体读取对应卡面的原费用、身材和能力。双方可选择不同配置；不会以全局覆盖原主卡定义让双方共用一张卡面。

沉默移除能力与增益，保留合并后的印刷身材。当前复制沿当前状态；印刷复制、回手、洗回及死亡历史复活沿完整印刷卡面重新安装原能力。转控保持同一物理身份，变形改为目标普通定义。没有星舰`components`，也没有新增实体、玩家、效果、帧或快照字段。

本项必要隔离代表只适配病毒、完美、输能三个真实功能模板。病毒＋完美为9费5/7，六个印刷关键词；输能＋完美为8费5/4，原输能光环只给其他随从＋1攻击。其战斗使用既有关键词和光环处理器；生产代表包及合成卡包不增加。其余五模块主体及更多实际配置继续随真实接卡处理；若现有能力无法表达真实主体，则登记必要基础缺口。

## 恢复与信息边界

完整原始卡组保存编译ID；注册表指纹绑定蓝图、模板、完整选择映射和生成印刷定义。恢复／回放需重建同一声明、模板和已请求卡面，和普通已注册卡牌一样依赖匹配的定义包，宿主不能只保存蓝图ID替代配置。稳定边界校验`MatchSetup`与玩家原职业、符文、完整原卡组一致；重算摘要也不能隐藏原配置不一致。注册表会重算编译结果，拒绝裁剪选择映射、冒用ID或篡改印刷卡面。本项不提供未签名存档来源认证。

首次落地规则`prototype-v181`；当时效果`core-effects-v175`、schema170拒绝旧1～169、观察74、命令11及replay1保持，只有规则语义标识变化，没有布局迁移。当时未使用该API的普通注册表指纹不增加空字段。当前共享规则`prototype-v190`、效果`core-effects-v184`、schema179拒旧1～178；modular-v1及原配置保存不变，必要计数模块印刷声明复用纯场面报价。所有定义/固有阶段新增默认数量叶导致当前注册表指纹与费用保存格式变化，见[场面](m3-board-minion-costs.md)及[手牌数量](m3-hand-count-costs.md)费用契约；没有把手牌数量能力额外开放到无真实来源的功能模块。

玩家观察复用普通隐藏身份和公开随从属性，不输出宿主构筑选择目录或对方未公开卡面；公开打出后能见合并身材与关键词。全知注册表、构筑配置和宿主快照不能给玩家。

## 已知边界

原模块数值及外观选项取自固定证据，正式合法池、官方导入编码、精确国服复制／洗回／沉默政策与特殊来源仍需M0/M6/M7。构筑编译与必要生命周期的内部测试不能代替八模块完整战斗适配、官方服务器校准或U09整族验收。跨机制授予、任意机制对及特殊生成来源均不在当前基础增量扩展。

当前共享费用API为prototype-v190/core-effects-v184/schema179，拒旧1～178。新增[本局实际法术法力费用](m3-player-spell-mana-costs.md)复用原物理出牌/付款，不改变本契约自身资格；精确CN仍待校准。
