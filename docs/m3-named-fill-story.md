# 固定具名填场与拉卡利的故事

TLC_466沿原objective玩家实例执行三次本人自然回合结束，包括施放所在回合。每次先用DiscardMatching随机弃一张实际手牌，再执行固定小鬼填场；弃牌为空不取消后续。UNG_829t3为官网真实关联的既有3/2虚空小鬼，完整旧定义保持，不因本批重复接入。两完整原行、四严格双语主面及两父子关联保存在[data包](../data/cards/native-lakkari-story-v1.json)。

新增FillBoardWithCard(player_id,card_id,cause)仅将普通固定卡填场转交既有SummonOrderedGroup。接受时复用PoolFillCapacity捕获实际规则容量和全部有序物理占位，包含休眠与地标；由当时空位生成固定数量、同一普通SummonEntryMaterial的独立有序出现项。所有主体、入场、数量额外体、位置、死亡、等待和关闭继续由原召唤组与SummonByCard子请求执行，无新GameState、实体账户或召唤循环。

原SummonOrderedGroup新增默认均为None的fill_capacity与fill_card两个字段。有限声明要求完整配对、同一受益者、与初始空位恰好相等的原有序出现项，不带逻辑producer profile、group额外策略或bonus计划。正常定量/异质召唤组保持原默认行为。每个子请求仍按自身真实接受窗使用既有数量机制，不能把数量额外体当成新的原填场次数。新容量先核工程预算再物化出现项。

弃牌及其所有反应结束后才捕获容量；召唤中途释放位置不延长原组，中途占位由原执行器按实际容量交付或失败。满场保存含固定卡配方的零数量组，无抽选；即使零数量仍校验具名材料，未知内容不能静默跳过。固定填场不依赖GenerationContext或随机池，不把单一具名配方伪造成可变生成池。过去接受的请求不能借后来同名实体或更新容量改变原次数。

容量、原固定材料、完整出现项和父子身份进入既有私有接受/完成事件；原窗口检查实际占位，等待/关闭恢复另核实际规则容量及完整事件链。队列、异常回滚、终局、Retry、独立reader恢复和回放复用原解释器。内部fill_capacity/fill_card及完整组不进入玩家DTO，公开objective仍只有原卡面与剩余回合。

真实故事的召唤原因来自原玩家实例的卡牌来源，回合结束时为card_effect，不伪造新的施法或战吼。实例独立计时，移除后不触发，末次主体与到期沿原顺序。随机弃牌、弃牌反应后捕获一次初始容量、后续空位政策和相关精确时序是当前明确本地规则，仍待M6国服校准；卡面证据不证明这些细节或CN37.0热修集合。
