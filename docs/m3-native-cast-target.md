# 原施法目标与完成后的消费者

[虚无残遗完整源](../data/cards/native-cast-target-v1.json)使用原`spell_cast_finished`和精确`cast_id`。只对本人实际成功完成的施法、完成窗口中存活的原来源，以及原目标类型为随从的事实执行普通`Draw`。目标后来死亡、回手或换成其他类型不改写原资格；英雄、无目标、对方施法、反制或失败尝试不提供成功完成奖励。

`SpellCastRecord`末尾增加`target_origin`，复用既有不可变`SourceAllocationFact`。手动施法在原重定向完成后、每次真实施法开始前捕获最终目标；重复迭代分别捕获，自动施法在原选择结果确定后捕获。原实体、卡面、类型、归属、区域、驻留和分配边界一起保存，不按完成时的当前实体反推，也不把完成后抽牌移到施法开始。

已有`spell_cast_started`内部数据增加原目标的规范JSON收据，保留原事件数量和类型。边界验证对有效回溯时间线核对每次原施法的唯一完整开始事实、来源/玩家/目标/action、原分配材料和接受游标；缺失、重复或与记录不符均拒绝。实际历史查询读取状态记录，诊断事件仅用于一致性验证。失败和反制尝试同样保留其真实目标或明确无目标，不能伪装成成功完成。

保存恢复使用已有原分配解析和校验，拒绝未来分配、错误归属、另一目标、缺失材料及原类型与开始事实不一致的重算hash存档。已经离区或换面的合法原目标仍能恢复。该证明不认证无签名外部存档的来源；同时重写所有来源事实不是本契约的外部认证范围。

没有新增全局历史、效果类型、载荷类型或玩家字段。完整状态和原收据保留在宿主，观察、合法操作和玩家事件不输出`target_origin`或内部类型。原支付、目标选择、施法次数、死亡、抽牌替代、触发捕获和回溯执行器保持。core392/schema315拒旧格式；观察88、命令12、replay1保持。

官网卡面验证身份和文本；准确国服目标接受、来源存活、施法完成及抽牌通知窗口仍待M6证据校准。实际验证与下一项只在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护，不据此声明完整标准卡池或生成可达内容已经闭合。
