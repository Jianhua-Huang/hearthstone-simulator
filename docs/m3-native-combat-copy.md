# 原攻击致死与不可变基础副本

[原始剑齿豹完整源](../data/cards/native-combat-copy-v1.json)的主体沿既有`attack_finished`窗口执行。`completed_attack`连接原`CharacterAttackRecord`，只接受本体发起、已经完成的真实攻击；原本体须在该窗口存活并保持原战斗驻留。普通防守、其他攻击者、法术消灭和裸兼容`CombatDamage`不提供这份信用。

原目标须为场上将死随从，其`DeathCause`必须携带原战斗窗口中的`COMBAT`伤害或剧毒结果；来源、来源驻留、目标、目标卡面及目标驻留与该次原事实一致。此处不查询未来的`DeathRecord`，也不提前编造死亡。死亡提交仍由原检查点执行。

原事件先捕获不可变`RuleContext`。即使较早的反应暂停待选、正常死亡检查点已清理目标，后续主体仍读取该原上下文，不能改读最新实体或最近一条死亡。主体在原上下文内调用`CapturedCardCopyMaterial.capture`冻结原随从材料，再交`CopyCard(mode="base", destination=HAND)`执行。这复用已有分配、复制、创建、获取、容量及爆牌流程，已接受的材料可跨后续离区和换面保持。

`CapturedCardCopyMaterial`原有手牌、牌库和已消费牌范围继续保留；新增`BOARD`仅接受`MINION`。`CopyCard`把该区域的冻结材料限定为`base`，不开放冻结场上当前复制。其完整原分配、接受时钟、附件边界、具名组件与引用仍受原校验约束，恢复时拒绝未来分配、非随从场上材料、未知组件及错误复制模式。`MinionReference`的既有实时复制政策没有改变。

基础副本保留原卡面、印刷组件和已有青玉固有尺寸；旧战场数值附魔、受伤、沉默和临时手牌材料不作为新卡附魔继承。新实体的原生能力、费用、创建/获取通知及玩家信息投影继续使用公共生命周期。准确国服复制继承、来源存活窗口与通知顺序仍待M6证据校准，官网卡面只证明身份和文本。

没有新增死亡账本、`GameState`字段、效果类型或载荷类型，也没有移动攻击/死亡窗口。core391/schema314对旧存档使用原格式守卫；观察88、命令12、replay1保持。实际进度、执行验证与下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。该接口不提供外部存档来源认证，也不声明完整标准合法池或全部可达内容已完成。
