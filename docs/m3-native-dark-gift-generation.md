# 原生黑暗之赐生成来源

EDR_102狡诈拷问者和END_013戮屠末日巨口分别从当前英雄职业加中立的可收藏传说随从、原费用1随从中发现，并为选中牌配黑暗之赐。前者是中立4费5/4恶魔，后者是猎人/圣骑士3费3/3野兽；后者的完整原行使用MULTIPLE_CLASSES，不能假设每张牌都有CLASS。完整原行、四份主卡面与十个既有赠礼原行见[数据包](../data/cards/native-dark-gift-generation-v1.json)。

卡牌行为只提交`DiscoverDarkGift(player_id, pool_id, query, source_id)`。这是固定三项配对发现、普通手牌获取的有限入口，要求有原来源和可收藏随从查询；不提供可编程赠礼、任意交付、额外次数或其他组合声明。

内核在实际执行时读取宿主GenerationContext，用其target/mode构造已有完整`dark_gift_pool`，再委托原DiscoverFromPool。卡牌回调不访问私有Game，也不硬编码实验目标。不同对局的目标和模式分别绑定；缺少上下文、完整池或任何合格候选实现时，原动作明确失败，不能回退到实验池或裁掉未知牌。

完整十配方、资格检查、不同赠礼的可行配对抽样、原所选配对、可见预览、普通创建费用和附魔、甜美梦境置顶、溢出、选择恢复、异常回滚、克隆和回放都由既有模块负责。没有新增赠礼执行器或修改旧配方。真实战吼重复各自接受一次新发现，付款仍属于原整次出牌。

已经展开的待选保存实际完整赠礼库存及宿主绑定；尚未执行的原生请求保存typed query和原来源。FrameCodec校验新请求的已分配来源及玩家，不允许用重算摘要掩盖未来或不存在的来源。保存校验提供结构一致性，不认证未签名存档来源。玩家输出保持既有观察/命令结构，不暴露内部库存、配对证明或对手的私有选项。
