# 成功弃牌的原生亡语记忆

宝石囤积者（CATA_897）的战吼选择本人另一张手牌，实际弃掉后由该随从的亡语重新获取并减费。这需要原生附件记忆；仅扫描 source_id 的历史不能表达复制、重置或已接受的亡语材料。实现扩展既有 NativeDeathrattleSpec/DeathrattleMemory，不增加玩家 memo 或第二套弃牌执行器。

## 原操作与接受顺序

`DiscardForDeathrattle(card, reference, ability_ids)` 捕获原 HAND CardReference、原随从连续驻留和原生亡语能力 ID。请求验证已知实体、原定义、非未来驻留/能力分配，随后委托普通 `discard_card`。原目标已经离手时既不弃牌也不创建记忆；来源或原附件失效时，已接受的弃牌仍按原身体执行，但不会绑定到同 ID 的新驻留。

只有成功 HAND→GRAVEYARD 才创建原 DiscardRecord。它保留原手牌获取、物理卡面/来源、事件序号，并额外冻结基础复制需要的组件和翡翠固有身材。该小配方不保留手牌增益、局部费用、伤势或临时手牌期限。普通弃牌和这类弃牌共用完全相同的移区、事件、原生被弃主体、检查点及回滚。

原 `card_discarded` 提交钩子先提交记录，再把其 ID 写进仍有效的原附件，随后才捕获观察者及原生被弃主体。因此通知导致来源死亡或当前复制时，接受到的状态已经包含关联。不能用较晚的 `on_success` 反推这一窗口。

## 记忆、复制和执行

`NativeDeathrattleSpec('discard_link')` 使用有序、无重复的 `discard_ids`，不能混入旧成长值或抽牌关联。每个 ID 必须引用实际原弃牌记录及对应原生来源声明。当前复制继承原记忆、以后独立追加；基础复制、回手重置、沉默及变形沿原附件生命周期处理。已捕获的亡语仍用自己的冻结材料，不读后来活体。

普通 NativeBattlecry 正文只捕获已接入的原生记忆附件。目标失效或没有其他手牌时不造关联；每个实际成功的重复正文追加自己的原记录，不按卡名去重。已有特殊授予若没有原生记忆仍明确未支持，不能凭行为 ID 补初值。

`CopyCard` 额外接受真实 DiscardRecord 的 `mode='base'` 小配方，其他模式拒绝。它验证完整已提交原记录，再复用原复制创建、组件/固有身材、局部 CostSpec、容量、爆牌和获取通知。宝石囤积者每条原记录创建一张基础副本，向当前实际亡语执行者交付，并在首次创建/获取通知前安装 `CostSpec(delta=-1)`。原被弃实体后来移动或重新获取不会重绑这份原配方。

这里采用基础重新获取政策：保留原卡面、已支持组件和固有印刷身材，清除旧局部增益/费用/伤势/期限；不把它写成原物理实体回手。准确国服返还身份、材料及多次正文/通知窗口仍须独立校准。结构和引用一致性检查也不认证任意未签名存档的外部来源。

## 保存与边界

内核 core389、schema312 保存原弃牌基础材料和附件 ID 列表，旧1～311需原引擎。新请求及原 DiscardRecord 复制可在选择中保存、恢复并验证原引用；既有原抽牌/成长记忆的解释器不变。没有新 GameState 字段、玩家状态或玩家观察字段；观察88、命令12及 replay1 保持。

完整记忆、弃牌 ID、原分配与来源只属于宿主状态和恢复器，不输出给玩家。原有可见弃牌/获得事件仍遵守揭示政策。正式池、任意尚未接入的生成家族、特殊记忆授予及精确国服窗口不由这个契约认证。实际进度、验证与下一项仅在[项目状态](project-status.md)和[执行清单](mechanism-backlog.md)维护。
