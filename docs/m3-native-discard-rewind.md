# 原生弃牌与回溯

真实来源 TIME_008「过去的末日宣言者」沿普通战吼依次提交本人、对手的 `DiscardMatching`，原生 `RewindSpec` 负责整次出牌检查点、恢复及最终一次支付。完整原行见 [来源包](../data/cards/native-discard-rewind-v1.json)。本人先于对手、逐次反应和精确随机窗口仍属内部政策，待国服校准。

## 有效事实与诊断日志

回溯恢复 `GameState.discard_history`，原始事件日志保持追加。旧尝试的 `card_discarded` 仍可供诊断，但不能再充当当前已提交弃牌的证据。

`discard_history.validate_boundary` 使用现有 `hero_health_history.effective_events`，按合法 `timeline_rewound.event_start` 移除已回退区间，再将有效弃牌事件的完整有序序号与状态账本逐项比对。检查点之前的已提交弃牌必须保留。没有回溯标记的额外弃牌、缺失行和错配的原目标仍明确拒绝。

每条状态记录继续按原始事件序号核对事件类型、来源、目标、玩家、动作和载荷。该修复不删除日志、不放宽原物理材料校验、不另建账本，不改变快照字段或 schema303；执行身份升级为 core379，旧执行身份存档明确拒绝，内容身份另行版本化。

## 生命周期

弃牌、本人弃牌主体、实体区域、随机、嵌套选择和回滚沿既有公共执行器。重试重新执行实际主体，但最终账本只保留生效尝试；旧诊断身份不能冒充当前物理弃牌记录。失败重试恢复原待选、状态和随机流。玩家投影不接收完整弃牌证明、检查点或随机状态。

实际验证、已知差异和后续工作只在 [项目状态](project-status.md) 与 [机制台账](mechanism-backlog.md) 维护。该来源包及内部测试不能认证完整标准环境或官方国服时序。
