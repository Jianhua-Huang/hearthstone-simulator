# M3：原生手牌连续镜像

米尔雷斯的“在手牌中变成对手上一张随从的3/4复制”使用独立 `CardDefinition.hand_mirror=HandMirrorSpec(3,4)` 声明。完整本体、原生来源附魔和独立3/4附魔保留在[固定材料](../data/cards/mirrex-native-hand-mirror-v1.json)。这不是[回合开始变形来源](m3-native-defining-hand-source.md)的替代；该旧来源后续无reset原牌转手政策见[转手契约](m3-original-hand-entry-theft.md)，当前复制拒绝保持。

## 原来源、实际提交与当前卡面

原生声明在真实HAND实体上安装一条纯 `hand_mirror` 能力，`HandMirrorBinding` 保存原声明卡牌、控制者和最近对手随从出牌ID。来源与当前卡面独立，物理来源ID必须指向载体自身，不从当前卡名猜来源。注册表编译只读来源ID集合；无相关声明的注册表直接跳过该同步，不在报价、观察或合法动作查询中修补状态。

同步只读取存在真实 `card_committed` 通知的原 `PlayRecord`，按对方MINION出牌的最近记录选择。准备付款或尚未提交的私有选择不计入，主体完成不是前提；原随从随后回手、死亡或变形不改写已经冻结的出牌卡面。自己出牌、对手法术和直接召唤不产生新的对手随从事实。

本地材料政策为：以冻结 `card_id` 对应的完整注册印刷定义重建当前卡面，再沿已有 `SummonStats` 设置3/4；费用和固有能力来自被复制卡面，不猜测固定3费，不读取后来战场附件或对手私有手牌进度。精确的固有进度、特殊复制费用和例外继承仍须国服执行校准。

## 同步与反应窗口

共享通知点包括真实提交、出牌以及创建、获取、移动入手、抽到、返回和存储变形。普通获取先完成原实体/手牌安装，同步才读取完整实体。没有额外创建、抽牌、出牌、召唤或随机消耗。

`Resolver.emit` 先记录原公开通知的信息事实，再进行镜像同步，最后捕获普通反应。同步先将所有物理载体完整换面，再逐个发布原 `stored_card_transformed` 通知；第一个通知的冻结反应上下文也看不到只换了一半的镜像集合。内部同步保护避免自身通知重复换面。

相同控制者、原出牌ID及卡面不重复重置，后来的手牌增益/减费得以保留；对方再次实际打出同名随从仍是新出牌，会重置旧卡面附件、费用和驻留epoch。换面、光环、隐藏知识处理和3/4属性层复用原存储变形管线。

## 复制、转手与退役

- 当前HAND复制保留原声明绑定及当前附件，但为新物理载体重绑自身来源；同一对手历史下不再次清空已有增益。
- 基础复制使用当前卡面的印刷定义，不借用旧原生来源；若该印刷卡面自身就是米尔雷斯，则按新实体原生声明安装并同步。
- HAND转手沿原区域管线，在接收方完整入手后按其对手历史重新同步。
- 离开HAND退役原镜像来源，保留当前复制卡面。当前复制到DECK也不携带已退役来源；以后只有实际印刷米尔雷斯卡面重新入手才重装。沉默后的当前战场复制不恢复已移除文本。
- 普通外部换面清理旧来源；目的印刷卡面确有原生声明时才重新安装。回合开始来源的当前附件复制及带reset转手仍明确拒绝；原牌无reset转手按[转手契约](m3-original-hand-entry-theft.md)保留声明并重置前一持有者见证。

以上为待国服校准的明确本地生命周期政策。当前复制同时需要保留原生满血复生的自身来源约束，因此仅对这两种必须绑定新物理自身的原生附件执行重绑；不普遍改写其他印刷附件的来源归因。

## 恢复、签名与信息边界

能力绑定使用严格类型解码，实体校验原声明、物理来源、区域、控制者和冻结历史；整局稳定边界另核对最新真实公开提交。缺少原生绑定的存档明确拒绝，不在恢复或查询时静默补齐。选择挂起、回滚、clone和回放复用原解释器，不增加GameState历史账本；未签名存档不提供来源认证。

新增可空 `CardDefinition.hand_mirror` 与 `AbilityInstance.hand_mirror`，schema281拒旧1～280，core-effects-v356；观察85/命令12/replay1保持。旧定义的asdict多出新空字段，旧摘要比较仅规范化该新增None，不能说原始asdict未改变；默认代表注册表签名和旧依赖PIN视图在空声明时保持，真实非空声明参与签名。

原绑定和隐藏卡面只供可信内核使用，玩家仍通过原投影访问；对手不接收私有变形通知、声明来源或完整附件。官方[33.4.2国服说明](https://hs.blizzard.cn/news/24223779/)确认3/4调整，但不单独证明这些窗口、复制和退役细节。实际验证、已知差异与下一项仅在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护。
