# 原生物理来源的逻辑数量

本契约用于克罗雷船长的火炮手额外射击。它复用`ProducerQuantitySpec(unit_id, additional)`的声明类型，不复用随机召唤的`AcceptedProducerAmount`或全局结束主体的max重复政策。当前唯一已开放单位为`cannoneer.shot`；未知单位明确拒绝。

`NativeProducerQuantityProfile(card_id, receiver_card_id, unit)`注册实际来源、实际接收卡面和正额外数量，进入只读登记与指纹。来源是普通物理随从，接收者有分类的原结束主体。原`install_printed`在来源的普通能力列表安装唯一纯印刷`native_producer_quantity`附件，保存原声明卡面；不增加CardDefinition字段。活体及死亡材料校验完整原声明和物理/组件允许数量，拒绝借用或重复附件。

数量查询只读取指定受益玩家面板上的当前活跃、存活、未标记消灭的来源及其实际未移除能力。匹配当前接收卡面和已知逻辑单位，返回基数1加各实际来源的additional；多个船长分别贡献一次。手牌、对手来源、沉默、离场、休眠及已删除附件不贡献；控制改变和当前复制由普通能力生命周期处理。静态印刷标记不支持任意动态授予或混入其他附件字段。

结束解释器保存的原上下文早于兄弟主体执行。火炮手的既有`cannon`入口因此先交普通InvokeBehavior续行`cannon_accept_shots`，在这个真实新窗口报价一次，再保存完整有序的`cannon_execute`工作尾部。已接受数量不因第一发反应中的来源变化而裁减或扩张，后面尚未开始的火炮手重新报价。每一发仍在实际执行时调用原characters/RandomDamage，独立抽选当前敌人，沿普通伤害、死亡与反应结算，不提前抽完后续随机。

同一原入口供自然结束和真实手炮调用。额外射击不新建结束主体、回合、施法或支付；手炮使被沉默火炮手按具名主体开火时，也沿相同数量入口。炮手自身的结束触发与船长提供者能力是两个生命周期，不能以炮手丢失结束触发为由屏蔽手炮的明确调用。

当前卡面匹配、附加数量按来源相加、主体逐次新窗和完整尾部接受均为内部政策，精确国服时序及交互仍待M6。原完整RuleContext与后续工作由共同FrameCodec保留，不提供未签名存档的来源认证。schema408拒旧1～407，core495；仅AbilityInstance增加原声明卡面字段，无GameState/PlayerState/Entity、CardDefinition或Effect新增字段/类型，观察95/命令12/replay1保持。原完整状态、声明附件和单位标识不交给玩家。
