# 原生随机目标的来源和候选域

原生来源、候选域、手动目标、地标/on_play、原手牌选择/投入及攻击接受使用不可变候选材料。CORE_CFM_670的完整9费5/4原行与两种语言的完整官网主面保存在数据包；标准注册表继续将这张根卡视作未实现，不能把有限消费者当作整卡支持。代表来源仅由专项测试的私有夹具注册，没有生产卡牌适配器或标准装配入口。

`register_random_target_card`登记原生随从声明。普通初始化添加纯印刷`random_targets`附件，复制、沉默和重置沿已有生命周期；没有增加CardDefinition字段、AbilityInstance字段或GameState账户。`current_sources`只读取场上活跃、未沉默、未濒死且有有效原声明的实际随从，保存物理来源和完整附件身份。双方来源均有效，同一物理载体只登记一次。

## 两种候选域

`manual_partition`接收实际物理来源、有效目标定义和原提交目标，复用手动目标谓词。卡牌类型、区域、敌我范围和结构/玩家谓词保持；敌方潜行、免疫、魔免等手动选中限制仍有效。它不调用普通自动施法的宽松候选查询。实际效果玩家可以与当前物理来源控制者分开，原事实与效果玩家分别保存。

`attack_partition`必须绑定真实、仍开启的攻击窗口。在原攻击已合法声明后，才准备敌方角色的替换域；嘲讽、潜行及攻击者自带的手动目标限制不作本替换域过滤。它不能让冻结随从、未就绪随从或没有合法起始目标的攻击凭空发生。原窗口或原驻留失效时不准备替换。当前攻击替换政策继承既有重定向执行器的边界，更多确切国服规则仍待校准。

两者都返回私有的不可变`NativeTargetPartition`，包括有效定义摘要、原物理来源、效果玩家、原目标、全部原生载体以及完整有序候选事实；不生成事件、不支付、不接受一次出牌或战斗。

`sample`仅接受显式`random.Random`操作数，返回`NativeTargetSelection`及MT19937前后状态。没有适用来源、没有提交箭头目标或没有目标声明时保留原值且不抽RNG；有替换域时等权抽选，单候选也按普通随机抽样消费RNG；空替换域返回显式no_target。构造时局部重演校验抽样和状态，不能将此当作原候选完整性或未签名外部来源的认证。

## 手动目标接受

普通手动法术在真实`spell_target_phase`接受替换；反制已生效时不抽选。手牌战吼及连击在每次真实主体开始时分别接受，手动英雄技能在一次原使用时接受，其重复主体沿原技能记录使用该目标。这里不接管自动施法、自动战吼或普通发现、抉择；各种重复的精确国服抽选窗口仍待校准。

`native_target_acceptance.accept`使用原有效目标定义、原支付条件与实际效果玩家的知识重算完整候选，消费对局原RNG，再由原施法窗口或主体记录连接选中目标。`PlayRecord.target_id`和原付款事实保持，不能将结果伪装成玩家提交。三个主体历史仅添加可空`native_target`材料槽，不增加对局账户；普通无原生来源的执行保持原路径。

私有`native_manual_target_selected`保存完整有序候选、来源、原提案、抽样及前后RNG；唯一`FinishNativeTarget`在未完成队列中携带原完整状态、规则和必要的玩家知识，以便恢复时重算有效定义和原候选。已结束的历史只留有限选中材料，不把整份状态递归嵌入记录。恢复、回溯和回放使用原解释器；内部一致性检查不是未签名存档来源认证，私有收据及全知状态不进入玩家DTO。

目标在原手动提交后全部失效时，空候选不消耗RNG。战吼、连击和技能记录实际目标失败；已付款法术保留原使用及次数，各次CAST均以`no_target`结束而不执行主体。该法术失败必须能追溯真实空域接受，不能凭空改历史成为失败，也不能误记为反制。没有提交箭头的效果不凭空增加目标。

控制随从的实际主体须使用这次接受的驻留引用，即使选中实体ID恰好等于原提交目标，也不能重用该实体离场前的引用。普通没有随机替换的控制仍保留原提交引用的防重绑规则。

## 攻击接受

`native_attack_targets`在真实`attack_declared`捕获各物理来源的检查项，位置沿既有`listeners`顺序：当前玩家优先，再按实际入场顺序；不把效果塞到每次伤害或重新发起一次攻击。检查执行时原来源、窗口或攻击者/目标驻留失效则跳过，不凭空允许非法的初始攻击。这个精确来源顺序目前是复用现有内核的本地政策，仍待当前国服校准。

原`CharacterAttackRecord.declaration`和英雄原声明身份保留；该记录只添加一个可空`native_target`槽。选中结果通过普通`RedirectAttack`的有限原生参数写入原窗口，保留真实目标驻留，并将强制友方/全随从攻击的交付关系切换为敌方角色。普通重定向不获得这项关系切换权限，支付、攻击机会、武器耐久和战斗伤害继续由原执行器负责。后续奥秘可以继续重定向，最终交付仍对应同一声明和有序重定向链。

私有接受收据保存原窗口、原捕获检查、完整候选和RNG前后材料；待完成`FinishNativeAttackTarget`持有完整原状态以重算候选。来源在接受后消失不会取消已选结果，选中随从离场再入场则按原驻留取消攻击。当前每个原窗口按本地单次策略接受一份选择，后续检查和奥秘打断不再重抽；多市长来源的确切叠加方式仍未由当前官方证据确认，内部双来源检查不能认证该规则。空原生域走实际取消，不静默继续命中原友方对象。

[官方2017年10月17日修复](https://hearthstone.blizzard.com/en-us/news/21098848/hearthstone-update-october-17-happy-hallow-s-end)说明食人魔及市长的错误攻击目标效果不应因奥秘打断而在同次攻击重复触发。它支持避免重复触发的要求，不能单独证明当前国服来源先后、多来源叠加或强制攻击的全部细节。

## 地标与原生on_play接受

`native_active_targets`在真实地标使用前或实际非战吼`on_play`主体开始时接受，原请求分别是完整`UseLocation`或原付费`PlayRecord`。只替换实际主体及使用事件的目标；原玩家提交、费用、延系/快枪手条件、战吼和连击接受保持各自路径。地标的耐久、冷却和末次使用仍由原执行器负责，最后耐久耗尽后不丢掉已接受的主体。

不可变`NativeActiveTargetProof`在唯一待完成Finish中保存原状态、有效定义、完整主体、候选/抽样和必要知识；闭合后的私有收据保留原请求与有限选择，不新增对局账户或模型字段。目标查询使用原完整玩家DTO来源与目标引用，不能用缺少`ref`的自造来源视图调用真实手牌谓词。恢复时重算原定义、完整主体和候选；私有材料仍不进入玩家投影。

非战吼on_play遇空目标仍执行真实条件包装器并传入None，真实数值主体自行无效果，不能连延系激活、历史和一次程序一起跳过。当前手牌交易/锻造/预备没有目标参数，已有艾欧娜的三个主动能力也没有目标声明，不为这些入口增加抽选。将来接入实际指向型随从主动能力时仍需相应消费者；当前静态盘点不证明完整可达内容已穷尽。

## 原内部手牌选择与投入

真实内部手牌箭头由`RequestChoice.targeting`显式声明，普通发现、抉择和固定效果菜单保持None。请求保存每个原物理候选的`target_facts`，等待帧只添加可空`native_target_request`；不增加对局账户或模型字段。私有`native_hand_targets_offered`记录完整原选项、附带效果和回调，恢复时与原公开选择及帧逐项对应，不能靠删掉标记绕过目标替换。

玩家`choice_selected`事实和原选择保持；`ResolveNativeHandChoice`在原选择反应之后、主体之前接受当前来源，并从原提供且仍有效的手牌驻留等权抽选。新HAND驻留不因实体ID相同成为原候选，原费用/引用等材料保持冻结。实际结果同时驱动`on_select`和所选项的普通效果，因此既适用于拆分/变形，也适用于手牌减费锚点和点燃。空域不抽RNG且不执行目标主体，原战吼仍正常完成；来源在此前反应中消失则保持原玩家选择。

`NativeHandTargetProof`在唯一待完成Finish保存实际接受前状态、完整原请求、原用户结果、执行结果和抽样。已闭合的私有收据保留有限材料；失败回滚到原待选，恢复/clone/回放共用原解释器。自动战吼/施法等已有选择producer保持原路径，不为它们再加一次手动抽选；该边界及精确当前国服窗口仍需独立校准。

裂隙使用的是`UseInteractable.card_entity_id`而非菜单。`native_active_targets`在原使用提交后、实际投入前接受，使用原可投入手牌域，原命令不改写；实际移出原选中牌、一次owner区间消费和召唤仍交给原可交互对象执行器。其接受证明复用原active控制路径，不把投入记为弃牌或出牌。

## 原场上后续目标与双目标

祭礼之舞的第二目标、撼地巨吼的持龙追加目标、欧斯克的两个敌方目标和恐怖海兽逐次偷取生命的目标，都显式声明`RequestChoice.targeting`。它们共用已有`native_hand_targets`提供、接受、等待及Finish路径；历史载荷名称保留，场上域的origin为`board_choice`。候选同时受原完整提供、原物理驻留及当前普通手动可选中限制约束，不把新入场同ID或后来新增对象接到旧选项效果上。第二目标的“不同”限制保留在原提供域，首目标使用此前已实际接受的目标。

欧斯克的两个箭头在同一原接受窗逐次等权、无放回抽选；第二份候选为第一份完整候选去除已选对象，并保留连续RNG证明。两份选择仍驱动原一次`RemoveFromGame`批次，没有拆成两次移除或死亡。该抽选窗口和无放回方式是根据原不同目标约束实现的本地政策，尚未由当前国服校准认证。恐怖海兽则沿原三次主体分别在新局面提供、接受，不跨三次共享去重或旧候选。

选择反应可能只留下一个有效候选。原用户`ChoiceResult`仍满足原两个目标的输入要求，原`PendingChoice`上下限不改写；仅实际执行使用带完整原输入、原请求和两份抽样的`NativeChoiceResult`子集。它不能冒充新的手动选择，也不能删掉第二份空域证明。全空域不抽RNG、不执行目标主体，原战吼照常完成；后一箭头或普通菜单中的等待仍保存前一份唯一Finish和完整接受证明。上述私有材料不进入玩家视图。

## 限定来源与边界

[2020年玩家原始实战报告](https://us.forums.blizzard.com/en/hearthstone/t/mayor-noggenfogger-interaction-with-deathwing-mad-aspect/37893)记录市长将死亡之翼的强制攻击转向英雄；[2021年另一原始报告](https://us.forums.blizzard.com/en/hearthstone/t/mayor-noggenfogger-the-mayor-who-doesnt-work/65583)及其讨论说明攻击并不会击中己方角色。这些是历史玩家证据，不是当前国服37.0的官方结算轨迹。

[官方36.2修复公告](https://hearthstone.blizzard.com/en-us/news/24290432/36-2-patch-notes)明确修复市长在场时第二张Conjuration Specialist能选中自己的问题。这是实际手牌目标消费者及类型过滤需要检查的证据，不能据此随机替换所有内部选择，或宣称通用箭头入口已经覆盖它。

手动可选中限制的精确分类、强制攻击关系切换、重复来源数量与顺序、各类主体何时重新抽选、反应先后及当前国服行为均保留待校准；本地当前候选政策没有被宣称为官方完整规则。实际场上箭头接通后，生产整卡仍须核对当前有限消费者、装配及其相关验证；静态直接调用审计不能认证完整可达。普通发现/抉择、有限卡牌展示与猜测菜单保持原producer，不能仅凭entity_id或文字“选择”改成箭头；其精确国服表现同样不由本次源码审计认证。这里没有绕过这些接受证明或在回调里偷偷改目标。
