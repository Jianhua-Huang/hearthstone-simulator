# 原生随从的法术法力条件冻结

伊希斯特 BE_259 的真实战吼为两个10/10构造体，冻结直到消耗15点法力值用于法术。适配只构造两份既有 `SummonByCard`，复用原容量、归因、战吼重复与逐次入场。普通召唤伊希斯特不执行战吼，没有新召唤执行器。

来源有明确限制：[完整固定源包](../data/cards/isiset-v1.json)保留 BE_259、BE_254 两份原始行，只有根卡两份官网主面严格通过。BE_254“冰寒巨人守护者”是同系列、同职业、非收藏10费10/10，其正文恰为消耗15点法力用于法术前冻结；本地没有其他满足这些条件的10/10。BE_259 没有 childIds，BE_254 的两次完整官网查询均未返回卡面。两者的对应是明确标记的推断，**官方依赖关联未确认**；不得把本批内部适配称为已完成官方来源核验或正式支持。原失败响应保持，不合成替代衍生物，也不修改核验工具使其通过。

公共 `SpellManaFreezeProfile(card_id, amount)` 限定普通非 choice-only、非星舰随从。原物理实体每次进入战场时分配独立 activation，保存原实体、印刷卡、战场驻留及两类付款历史的起点。状态只挂在该实体的 `spell_mana_freeze`；既有普通 frozen 标记继续决定攻击资格。普通回合解冻跳过仍开放的条件门禁，其他随从的 Freeze 沿旧管线。

原 `commit_play` 提交事实时调用状态更新，实际发布另走公共通知阶段，保持支付投影可重算。额度读取原 PlayRecord 的实际法术 Mana 支出，不重新报价，不以原印刷费用代替真实付款；零费、随从、生命支付和免费自动施放不计。真实付款后被反制的法术仍计。显式 `SpendMana` 读取原消费记录的实际量及原法术来源，原消费结果、消费与账户变化的连续通知不被打断。新解冻通知在原付款来源数字保护窗口内发布，冻结相关响应、待选和回滚仍交原解释器。

每个开放实例对之后每条付款/消费保留一次完整前缀，包括额度为零的记录；每次以该物理随从当时的控制者计算，不追溯新控制者此前付款。转控保留原驻留和已累计额度；达到阈值时先提交全部相关实例的状态，再发出原 `unfrozen` 通知。来源伊希斯特离场不控制构造体的原生能力。

本地政策是：沉默、显式解冻和获得不能被冻结关闭该实例，后来普通 Freeze 不重新开启；回手重入、复制、复生和变为原生卡重新从印刷额度开始。休眠保留原战场驻留并继续累计控制者支出。该生命周期政策以及达标发生于付款提交、法术主体前的精确窗口仍待国服校准，不能仅由卡面文字推定为官方行为。

私有入场、进度和关闭收据保存原身份及额度来源；恢复核对完整 typed 状态、实际原付款记录、连续前缀及收据，拒绝丢失绑定或修改额度/付款。这些检查提供本地一致性，不认证未签名存档来源。玩家观察仅沿既有 frozen 字段显示可见状态，不能获得私有步骤、历史游标或完整宿主状态。选择、恢复、克隆、回放与错误回滚共用原实现。

本契约为 core648/schema534，新增三个不可变 payload，没有新增 Effect 或顶层 State 账户；旧版本存档由对应旧内核读取。注册表只有非空声明时才把本能力加入指纹，未使用声明的默认代表包身份保持。实际验收、差异与下一项只在原两份台账维护，M0 正式来源/合法池、M6 国服校准和 M7 完整内容分别验收。
