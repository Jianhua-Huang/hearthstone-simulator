# 殒命暗影的原生手牌法术镜像

CORE_RLK_567保留完整核心、原版及两个原生附魔来源，缺省费用按完整双语主面明确核对为0。原空卡面manual_playable=False，只有原生手牌文本；它的空施法主体明确注册，不以未知卡白板代替。核心限量身份按原858/DECK_RULE_COUNT_AS_COPY_OF_CARD_ID关联RLK_567，不改变生成身份。完整材料见[数据包](../data/cards/shadow-of-demise-v1.json)。

Registry显式登记原始法术ID集合，非空时进入指纹，默认空集合不改变旧代表库身份。实际HAND安装一条纯原生spell_mirror能力，SpellMirrorBinding仅保存原声明卡牌和上次实际cast_id；来源物理ID必须指向当前载体。当前卡面与原声明分离，不从当前卡名推断其是否仍是暗影。

同步使用已有spell_cast_accepted及accepted_cast，覆盖真实手牌、重复、效果、抽到施放和历史施法；对手、非法术、被反制或未接受主体不生成本人合格施法。复制窗口处于实际主体接受时，后续从该法术抽到或发现入手的新暗影不追溯这次施法。国服[36.2](https://hs.blizzard.cn/news/24290432/index.html)与[36.4](https://hs.blizzard.cn/news/24293283/)确认原空暗影不能因非法术或弑君者抽到而直接打出，精确接受窗口仍待M6。

从实际原施法实体一次冻结完整当前材料，沿原reset_stored_entity和copy_current_stored_state复制数值、费用、局部法伤、固有参数及能力；每个接收者获得独立附件ID，再只装回其原镜像来源。原声明/能力ID、实体、手牌槽和所有权保持，换面epoch按既有管线推进。所有物理暗影安装完毕后才逐个发布原私有换面通知，不创建法术、重新施放、抽样或付款。[官方28.2](https://hearthstone.blizzard.com/en-us/news/24008697/28-2-patch-notes)明确修复过仅复制基础版本的问题，专项验证实际减费和局部法伤复制。

当前HAND复制保留原绑定并重绑新物理自身；基础复制使用当前印刷卡面，不借用旧暗影来源。无reset转手保留当前材料，未来跟随新控制者的真实施法，旧cast_id仅说明原来取得的卡面，不强行改为新持有者的历史。普通外部换面和离开HAND退役旧来源，当前复制卡面之后再入手不从卡名复活来源；真正印刷的空暗影获取时按原声明安装新来源。这些生命周期与特殊暂存/逆向移动例外仍是待国服校准的明确本地政策。

原空暗影通过异教地图从牌库到手牌使用原物理交付，不追溯地图已经开始的施法；[37.0公告](https://hs.blizzard.cn/news/24301454/index.html)说明该交互有过修复，但未描述完整服务端顺序，不能将本地选择路径当作完整M6证据。复制形成的法术沿原报价、目标、普通Cast及退役执行，原镜像附件不作为玩家命令或动态效果程序。

绑定使用严格模型、codec和稳定边界验证，核对声明、物理HAND、已接受历史及当前卡面；缺失原声明、未来cast_id和错误类型明确拒绝。不新增GameState账本或新的施法器。原私有换面、当前成本和法术卡面沿已有玩家投影；原绑定、来源附件、队列和全知历史不进入玩家信息。未签名存档不提供来源认证。实际进度、验证与下一项只维护原两份台账，M0正式池、M6国服和全部实际可达仍分别验收。
