# 下一次完整治疗效果的转换

真实来源 `CATA_301` 红玉圣殿是1费、3耐久地标，使用后使本回合下一次本人的治疗效果改为等量伤害。完整原行与严格双语主面保存在 `data/cards/native-healing-conversion-v1.json`。卡牌的使用、耐久、冷却、支付及最后一次使用沿原地标流程。

原 `PlayerEffectSpec` 增加有限种类 `next_healing_damage`，只表达本回合的这一件事，不带触发、额外主体、法强、光环、费用、倒计时或可变计数。实例仍是原 `PlayerEffect`；没有新增其字段或实体/玩家/GameState字段。安装须来自该声明的原卡面，受益玩家在安装时固定；来源地标离场或英雄替换不撤销实例，复制地标也不会复制已安装的玩家效果。

`next_healing_conversion.claim` 在同一健康批次开始时接收已准备的原健康包，识别实际由本人提供、原流为治疗且有有效存活角色目标的效果。若有待用实例，复用 `ConsumePlayerEffect` 的原实例门禁统一消费，并把同一普通 `HealthRule(HEALING, CONVERT, source_relation='friendly')` 加入该批次规则。数值、来源、学派、防护、护甲、重定向、历史、死亡检查和终局仍由原健康管线负责，不另造事后伤害。

一个 `HealBatch` 是一个完整治疗效果，全部包使用同一原接受结果；连续返回两个独立 `Heal` 仍有两个效果边界。一个原伤害批次中实际产生的固有吸血恢复组，也先作为完整组接受，再交给同一转换逻辑。没有实际恢复的防护伤害不会凭空消费实例；已转换的吸血恢复伤害保留原不递归守卫。这里沿原健康请求的批次边界解释“效果”，不把一个施法根中的所有独立子请求强行合并。

重复待用实例都指向同一次下一治疗，统一消费；原规则仍按附件顺序只执行一次流转换，不反复翻转或叠加伤害。空组、无效或休眠等非有效目标不消费；有效零量治疗消费且保留零量结果，不制造正伤害；满血目标仍按原治疗量转换。这些组边界、零量和规则优先级政策属于内部契约，仍待国服校准。

健康原子批次内仅允许此种无属性/光环贡献的实例使用原移除器的私有 `atomic` 路径；只移除原实例，把原移除通知并入健康批次事件缓冲。不会在吸血等结算中途刷新全场光环或捕获半套健康历史。整批健康史提交后再统一发布原通知及健康事件；选择和反应沿普通解释器恢复。其他 `ConsumePlayerEffect` 和 `RemovePlayerEffect` 保持即时刷新、通知及成功主体语义。

未消费实例复用原当前回合效果清理，在本回合结束后、下一玩家开始前到期；不占用带倒数的持续效果栏。公开视图只沿原玩家效果摘要，私有实例和健康规则不公开；事件校验认可该有限种类的到期。内核468/schema385，旧384及更早明确拒绝；视图94/命令12/replay1保持，没有新生产Effect或载荷类型。实际进度、证据及下一项仅在原两份台账维护，正式合法池与M6国服校准独立开放。
