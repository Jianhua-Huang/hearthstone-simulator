# 夜影花蕾与原牌库发现的直接执行

[固定数据](../data/cards/nightshade-deck-actions-v1.json)保留CORE_REV_311、两个真实内部选项REV_311t2/REV_311t及原版REV_311四份完整原行。原版两份完整双语官网主面均明确copyOfCardId包含Core身份，费用、类型及完整英文文本也与Core原行一致；物理ID保留Core，构筑去重身份REV_311。本次Core及两个内部选项的官网API均零匹配，[完整响应与逐项状态](../outputs/card-integration-20261014/k553-nightshade-deck-actions/primary-availability-01.json)保留，不把接口缺失解释为没有这些选项。选项只作为内部choice_only面，运行费用0不覆盖原行印刷费用8，也不进入生成库存。

原生抉择继续使用ChooseOneSpec，随从、法术及兼得三个主体明确声明。没有先复制或抽取到手牌：随从分支发现原牌库随从后直接移动该实体上场，法术分支发现原牌库法术后直接免费施放。兼得先完成随从发现、实际入场及全部反应，再让第二个请求从当时的牌库读取法术；前次入场反应可改变第二次发现的候选。兼得的资格、原支付、自动分支和重复机制仍沿现有公共解释器。

DiscoverDeckCardAction(player_id, kind, cause)只接受原法术CAST归因、本人牌库和MINION/SPELL两种真实类型。取样复用sample_zone_choices与已存在的物理库存接口：最多三个不同实体槽，同名物理副本保留各自权重，空匹配无选择/无随机。不增加生成池、不按已有适配裁候选、不按当前英雄职业过滤已经在牌库中的牌。同名槽权重属于明确本地政策，尚未国服校准。

SelectDeckCardAction保存原请求、完整有序DeckTakeOffer、当前CardPreview与选中索引。待选恢复核对原源归因、每个物理牌库驻留及完整预览；实际选择另与已提交发现的原OriginalDiscoveryOffer逐字段匹配，不能借同名同预览的另一实体替换。玩家只得到既有可见预览，原cause、完整工作、牌库顺序和随机状态继续私有。

随从交付委托SummonStoredCard及原招募/数量/巨型管线，保留物理ID、当前存储修改及原CAST来源，不执行战吼。实际返回的FinishCardSummon根连接既有PublishDiscoveredSummon，因此发现完成通知知道实际首身体；没有空位时普通归因召唤记录失败，原牌仍在牌库，不借手牌烧毁或制造白板。已离开原驻留的引用按原失效政策跳过。

法术交付仅为原MaterializeDiscoveredCard增加有限CastStoredSpell配方：原本人牌库、普通随机目标/自动主体选择，不接受预设分支、指定目标、目标偏好或改成手牌来源。实际施法仍委托既有cast_stored，移动原牌到墓地并创建它自身的子CAST，不额外付款、不记为一次手牌出牌，也不触发抽牌/入手。子法术即使因无合法目标而失败，仍有真实尝试与原实体结果。

原发现交付证明把该实际实体保留为recipient；同步窗口中必须存在唯一spell_cast_started，其实体、牌面、施法者、玩家和原区域与配方一致。完成通知沿既有队列置于子CAST工作之后，恢复会核完整接受/完成证明与原身体；等待中的原法术、原施法及未完成发现不能被重复、裁尾或改换。满手与这两种直接执行均无手牌容量关系。

精确客户端的同名发现权重、选择通知、“发现后”反应与子施法的相对窗口仍是明确待校准政策；原数据已记录，不宣称官方全部等价。本轮按用户要求暂缓规则边界与版本对齐，继续补实际内容。新入口只增加两个公共effect，复用原DeckTakeOffer与所有执行器，没有新增GameState字段或第二套施法/召唤逻辑；core739/schema590区分新协议。

真实教师/学生验证使用独立的单成员实验过去域与真实范达尔兼得来源，不能因此把德鲁伊21张直接安装成所有职业的生产过去域。实际验收、差异、后续生成依赖与下一项只在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护。
