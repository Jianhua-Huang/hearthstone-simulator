# 恩佐斯：原亡语入场与四个技能

本文保存来源、表达及本地政策。实际执行、验收和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。

## 固定来源

[完整源包](../data/cards/nzoth-v1.json)绑定固定37.0完整源的BE_017及父官网响应明确列出的BE_017t3、BE_017t5、BE_017t6、BE_017t4。保留五份完整原行、各自哈希和十份完整双语主面响应/收据，使用card_batch.prepare复核。原本体为15费5/7中立传说古神。

四个描述符的固定源cost为空，两种语言的完整主面均明确显示manaCost=0，准备清单只声明此字段补零；原行没有被改写。描述符沿既有非物理choice-only角色注册，激活不产生法术CAST或技能卡付款。卡面数据核对不能证明国服行为校准完成。

## 原成功召唤的亡语身份

`SuccessfulSummonRecord.deathrattle_ids`保存原minion_summoned发布时尚未消费的亡语声明ID。与原入场属性一起由原发布器写入私有`_entry_deathrattles`，随后在监听者捕获前提交到已有成功召唤历史，不增加另一套召唤或玩家计数器。非整数、重复、未来附件ID及与原发布事件不一致的身份被拒绝。

当前政策按声明结构保留休眠入场的亡语；初始Scenario场面、变形、控制转移、失败/满场召唤没有额外成功事件。实际出牌、普通召唤、复制、复活及复生每次成功入场分别记录。后来的沉默、变形、追加亡语和控制变化不会改写已有行；带原当前亡语材料的新复制则记录自己的新入场。这些结构与接受窗仍待国服核定。

`PlayerSummonCountCostSpec('cost.player-summoned-deathrattle-count-v1')`沿已有固有费用阶段，对付款者的完整原历史前缀选择非空deathrattle_ids的行，每次减1，最低0。原图腾/野兽查询保持原部族政策，只有新有限profile按亡语声明选择。原冻结费用事实、当前/生成报价、支付、复制、恢复与前缀验证复用；不从当前场面或已重置的坟场实体重新数过去的亡语。

## 四个真实主体

- 恩佐斯的召唤：使用普通当前职业及中立、可收藏、印刷费用至少5、印刷亡语的完整发现域，选中后沿原board发现交付和SummonCause召唤。未知合格内容保持显式失败，不能从池中裁去。
- 恩佐斯的大军：原`Resurrect(count=4, distinct='card')`，当前以死亡卡面及印刷亡语资格选择。沉默过的原生亡语仍可选，普通随从后授予亡语不进入此池；同CardId多次死亡只选一个。这份资格/去重政策待M6核定，不借原描述文字认证精确内部身份。
- 恩佐斯的领域：向另一个友方随从追加真实、可沉默和可按既有规则复制的亡语声明。执行者是承载随从，造成2点全体敌方随从伤害时沿原DamageBatch与实际控制者，不借古神充当伤害来源。
- 恩佐斯的操纵：用原`TriggerDeathrattles(..., times=2)`执行另一个友方随从的亡语，原所有声明、主动触发及次数规则保持。当前目标域为另一个友方随从，精确无亡语目标资格待M6。

四次实际激活继续沿[旧神独立基础机制](m4-old-god.md)：每回合首次免费，其后占原普通攻击机会；四个物理槽耗尽前不能普通攻击。不套用克苏恩专属的整局四种完成与三倍规则。

## 保存与边界

首次布局core642/schema529，schema1～528需原引擎。既有成功召唤行增加一项原声明身份，未新增State账户、Effect或payload类型。新字段进入费用事实及其原历史前缀，事件见证和当前State一致核对；玩家DTO不包含声明ID或原费用证明。

发现、复活的随机/候选接受、待选、容量、失败回滚、JSON/clone/回放继续使用原解释器。技能描述符与源古神保持区别，局部政策和当前内部通过不替代M0正式生成域、M6国服规则或M7完整效果的独立验收。
