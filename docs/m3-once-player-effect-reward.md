# 原玩家实例的单次兑现

实际进度、执行结果和下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。本页描述公共契约，不代替正式卡池和国服校准。

`ConsumePlayerEffect(player_id, instance, on_success=())` 接收完整原 `PlayerEffect`，在实际执行时检查全局分配身份、所属玩家及仍存活的完整实例。只有原实例仍在对应玩家列表中且完全匹配，才复用普通移除流程，并继续不可变的成功效果元组。实例先从列表移除，再刷新光环、发布原移除事件，随后沿原解释器处理反应和成功分支。两份早已捕获的回调、嵌套回血和移除反应因此只能兑现同一实例一次。

已经移除的原实例跳过，不寻找同名的新实例；另一个玩家、被改写的原实例、未来分配身份、非严格类型和可变分支明确拒绝。队列保存完整原实例和成功效果，沿统一帧编码、恢复、事务、回放和玩家隔离处理。校验仅保证内部结构一致，不认证未签名存档的外部来源。

原 `RemovePlayerEffect` 仍仅移除实例，不控制后续独立效果；原 `TickPlayerEffect` 的继承、预期倒计时和到期主体不变。普通已接受的 `PlayerEffectDamage` 仍可在其来源实例移除后执行；新增消费门禁只在消费者显式请求时生效，不修改既有触发的存续政策。

## 阿莱克丝塔萨，生命守护者

完整固定原行、双语主面及附魔原始证据见[固定数据](../data/cards/native-alexstrasza-full-health-v1.json)。`CATA_307` 的战吼建立独立待兑现玩家实例，使用既有 `SetHeroHealth` 将剩余生命值设为15；保持生命上限、护甲和原健康赋值流程。普通召唤不执行战吼。每次真实战吼产生自己的实例；来源后来的死亡、沉默、变形、回手和转控不撤销该实例，复制随从不会复制已经建立的玩家效果。

本地时序政策是在赋值前建立并捕获来源，防止赋值反应修改原物理载体；赋值及其反应后再读取当前英雄是否已经满血。未来的判断读取原健康事件已有的完整 `hero_health_transition`：原来缺血、变化后存活且达到新上限时兑现。因此治疗、直接赋值、上限降低后的满血、英雄替换等均复用原事件，没有新增健康监听器或可变计数。满血时的过量治疗不制造新的“到达满血”；每个实例的初始满血检查最多也只兑现一次。这些精确时序和满血政策尚未国服校准，不能将卡面核对写成官方时序证据。

奖励先消费原实例，再使用既有独立玩家健康来源，对主体捕获时的当前敌方英雄造成15点普通 `EFFECT` 伤害。原来源事实及受益玩家不变，伤害、护甲、免疫、健康历史、死亡和终局共享原流程；不会按已变形或转控的旧随从重新解释伤害归属，也不继承后来授予的吸血等关键词。该伤害分类沿[玩家健康来源契约](m3-player-effect-health-source.md)，精确国服分类与关键词交互仍须M6证据。

`CATA_307e` 保留完整原行作待兑现文字证据，没有独立物理附魔适配；待兑现状态由公开玩家效果表达。玩家DTO只使用既有公开摘要，完整实例、原来源捕获与成功分支不公开。新增可挂起请求提高统一snapshot/core版本；旧格式须使用其原引擎。
