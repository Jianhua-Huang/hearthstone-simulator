# 尼利的原费用与两次实际施法

TLC_836环形山的尼利为3费2/5猎人随从。完整原行、双语主面及TLC_836e/e2原附魔证据固定在`data/cards/one-cost-play-provider-v1.json`；两个附魔不新增可执行定义。

随从入口复用原`card_played`、完成的PlayRecord与原成功入场事实。1费依据为提交时的完整报价数值，独立于实际消耗的资源；不读取更晚费用。奖励通过原连续驻留查询和普通DoubleStats执行，复用有序属性与沉默生命周期。效果召唤、对手出牌、来源自身及离场再入场不冒充原接收者。原helper对磁力结果的显式未支持保持，不能据本批注册宣称该组合已经闭合。

## 原法术接受

有限`RepeatCostFilter('cast_quote', minimum=1, maximum=1)`只接受class_mode=any、casts=2及无其他匹配组合的真实声明。手牌施法沿原重复接受/支付管线，读取原提交报价；已消费折扣不被更晚报价覆盖，生命付款也不把费用误记成实际法力消耗。

自动施法在原实体移区和目标随机之前捕获相同费用器的当前完整报价，以及存活、激活、未标记死亡的友方来源。effect、draw和history原施法共用这一有限桥接；不付款、不消费费用修正器。多个来源共用两次计划，不相乘。首次施法失败不接受额外工作；接受后来源死亡不撤销额外工作。

额外工作沿原payload与FinishSpellCast建立一条`native_repeat`实际施法记录，绑定原cast的recast_id并保留原物理来源、目标、分支和条件；没有额外整次出牌或抽牌。实际执行时使用当前动作编号，因此选择等待后恢复不会借用旧动作。法伤、主体、普通选择、回滚及回放沿共同执行器，不递归调用自动施法入口。

私有接受计划保存完整费用、来源分配与能力、原主体；原接受事件、唯一子施法和欠付继续义务在保存边界核对。它提供结构一致性，不认证未签名存档来源。新来源语义使schema升至413，旧schema显式拒绝。

## 真实消灭奖励修正

EDR_531虹吸生长的冻结源为1费、消灭友方随从以获得8护甲。旧配方错误把消灭和护甲作为两个独立步骤，重复后会从已死亡目标再次获得护甲。配方现在显式将护甲放在destroy的success分支，复用原DestroyCapturedMinion.on_destroy；只支持原单一目标成功分支，不增加无依据的失败或全体消灭组合。该卡唯一有意变更的旧定义字段为on_play，其源行、元数据与池记录保持。

手牌和自动施法真实对照均为两次施法、一次成功消灭、合计8护甲。[官方36.2修复公告](https://hearthstone.blizzard.com/en-us/news/24290432/36-2-patch-notes)也登记过尼利与虹吸生长的重复护甲问题；这不替代CN37实际时序校准。

费用依据、来源捕获、额外施法目标/条件和重复来源重叠等精确国服窗口仍待M6。正式标准池、全部可达效果及发布验收保持独立。版本、实测结果和下一项仅在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。
