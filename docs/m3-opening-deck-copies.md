# 阿扎莉娜的原构筑与开局复制

JAIL_430裂魂者阿扎莉娜保留完整7费7/7卡面、20张主牌构筑声明、40点初始生命和抽到手牌上限的战吼。根与JAIL_430e1复制提示的完整原行及严格双语主面固定在[data包](../data/cards/azalina-original-deck-v1.json)；复制提示只作原证据，实际复制来源由普通copy_origin负责，不注册一个空白附魔。[国服36.0.3公告](https://hs.blizzard.cn/news/24290431/index.html)明确新增40点初始生命，不能据该公告认证全部37.0热修或复制时序。

## 原提交与新物理牌

Registry使用已有DeckSizeRule登记原20张主卡组要求，不自动裁剪或补足提交内容。原收藏/职业/副本/禁限/符文及多种容量来源的校验保持。PlayerState.original_deck、OpeningState.original_entities、MatchSetup及GenerationContext.starting_decks仍指向原提交内容，不能用对方后来手牌或已经改变的牌库重建。

新增OpeningState.deck_copies保存独立OpeningDeckCopy，区分原构筑资格与补入的物理复制。真正BeginGame在普通首次洗牌、before_deal、发牌及选择之前，先冻结双方全部原物理主卡槽。只有本人原提交中的阿扎莉娜接受一次20张复制；双方都有时，各自从对方原20张选择，不将刚补入的副本当作第二轮来源，也不递归执行构筑。

有限政策按玩家编号抽样，每个物理槽一个权重，无放回选择20张；同名不同实体不去重。原候选必须全部有已实现定义，沿Game.from_decks的原构筑校验拒绝未知内容。当前实验输入若不足20个对手原槽则明确拒绝，不猜测补足、重复或缩减。这一边界及正式合法输入范围仍须M0/M6确认。

每份交付调用原CopyCard的base配方，分配新的本人实体、独立附件及普通外来复制信用；对方原实体不移动、不抽牌、不施法或执行战吼。底部定位不消耗插入RNG；全部准备完成后才进入原双方首次洗牌。此处是组成牌组，不冒充一条有actor信用的ShuffleDeckCards语义操作。

## 接受记录与发布

OpeningDeckCopy保存原本体SourceAllocationFact、完整有序对手候选、原20个选中实体、20份实际分配及MT19937前后状态。记录核原MatchSetup的物理槽、玩家、卡面、出生区域/代数、连续新分配和实际base-copy创建/定位通知，并重演原抽样及与先手选择连接的RNG前缀。单一数组或实体总数不能替代完整原域。

普通物理复制仅新增默认开启的内部publish参数与原通知发布函数；原普通使用的通知、烧牌和区域分支保持。准备期间先分配全部独立复制、安装双方完整接受记录，再发布原私有收据和普通创建/入库通知，避免任何观察者捕获半份不可变开局来源。没有第二套复制、区域、随机或选择解释器。

原牌之后变形、离区或死亡不改写已接受的复制材料。等待保存、独立注册表恢复、克隆及回放继续沿原执行器；完整重哈希也不能裁原候选/交付、换原随机前缀、丢整侧准备记录或借对方原实体冒充新复制。内部一致性不认证未签名存档的外部来源。

## 普通开局及卡牌生命周期

开局钩子读取原提交槽加本批实际交付槽；后来普通开局效果新生成的牌不会再被追溯列为开局来源。共享is_hook_source核实际冻结的来源。厨师奈瑟雷克沿原资格条件继续；阿扎莉娜的原7费本体会使本人原“全部至多3费”条件失败。碧阿崔克丝使用收件玩家本人原侧板选择；复制来源缺少该选择时不伪造或继承对方配置，原提交来源仍严格拒绝无效选择。复制侧板如何处理仍为明确待M6政策。

40点初始生命沿已有before_deal及SetStats英雄属性执行，保持原雷纳索尔实验材料：基础生命30，永久属性附件设为40并清除原伤害；不发治疗或资源伪事实。复制的阿扎莉娜不重复设置构筑生命。后来从手牌实际7费打出只执行普通DrawToHandLimit，自然召唤不触发战吼，场景入口不追溯构筑或初始生命。

原提交来源与预备复制的分类继续沿现有原始牌组/物理来源查询和生成资格：这项独立接受记录没有静默将原20张身份改成40张，也不放宽对方职业或未知生成牌。无放回抽样、先手/复制/洗牌/开局窗口、base材料、原始牌组条件的依据、复制侧板、40生命材料和通知公开程度均仍待国服逐案校准；不能用卡面或内部通过宣布官方完整支持。

新增保存内容仅OpeningState的deck_copies字段，类型由专门解析器恢复；原GameState、实体、玩家、卡牌定义及Effect声明保持，无新公开动作或观察字段。源牌库、抽样、分配和随机材料不能进入玩家DTO。实际执行、验证、版本、差异及下一项仍只在原两份台账维护，M0/M6和全部实际可达内容独立开放。
