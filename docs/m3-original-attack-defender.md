# 原攻击窗口的防守驻留

原 `ForceAttack` 即使收到 `BoardPresenceReference`，也曾在打开窗口后只留下目标实体ID。攻击声明反应将目标回手并以同ID重新入场时，旧攻击误伤新体。修正适用于真实手动、英雄和强制攻击，共享原战斗执行器。

`ActionWindow.attack_target_presence` 保存原防守随从的既有驻留引用；英雄目标为None。攻击源已有同类保护。窗口接受后、实际已交付战斗开始前均核对原驻留，旧体离场重入时取消旧攻击。原攻击机会、隐身消费、取消/完成历史和武器账目仍交既有执行器；无原窗口的历史裸战斗保留原damage-only契约，不虚构攻击信用。

同一驻留的变形、沉默和控制变化不伪造成离场，当前属性和战斗阵营仍沿原规则核对。合法 `RedirectAttack` 捕获实际新目标驻留，原声明另行保留。它也可在先改向英雄后，合法再选择原ID的新驻留；不能把合法显式替换与旧窗口自动重绑混为一谈。

原声明和改向的诊断事件保存私有驻留/窗口身份；接受证明重建原所选目标并与实时或已交付窗口核对。原完整记录、FrameCodec及快照解析拒绝缺失、未来、错实体或与原事件不符的驻留。诊断字段不进入玩家DTO，结构校验不提供未签名存档来源认证。事件按序号与窗口索引，避免每条历史记录重扫整个事件表。

JAIL_435捕获原敌方随从组，各自用普通强制战斗攻击原本体；预备复用原手牌动作。EDR_014按原手牌实际付款或独立间接执行时的当前费用判断，成立时一次抽选最多两个不同原敌方驻留，再按原顺序攻击。完整原行/官网没有突袭，不增加此关键词；普通召唤不触发战吼，失效引用不改选新体。敌我以执行时来源控制者接受，后续仍核对当前实际战斗关系。

内核424/schema343对应原窗口的新字段和英雄取消原因；观察90、命令12/replay1保持。没有新战斗模块、Effect/payload类型、GameState/Entity/Ability字段或第二调度器。精确国服目标窗口、原生条件费用语义、正式池和完整可达仍待独立证据。实际结果、差异和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。
