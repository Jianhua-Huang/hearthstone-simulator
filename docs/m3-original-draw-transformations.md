# 原抽牌变形与实际入手结果

本契约服务真实 `YOP_017` 蕉猾诡计，复用现有 `EX1_014t` 香蕉完整定义，不新建第二套抽牌或施法执行器。完整原行、两个官网主面与来源固定在 [卡牌资料](../data/cards/shenanigans-secret-v1.json)。这张牌属于标准宿主实际可达的过去奥秘依赖，本批不扩展标准根卡名单。

## 原卡与实际结果

- 原 `DrawRecord` 的物理 ID、原卡面、原抽取者、来源、回合、动作、原生/授予的抽到施放声明与补抽亲缘保持。成功普通入手额外绑定真实 `hand_entry_id`，不再由两张历史表的相同下标猜测对应关系。
- 揭示后的有限 `TransformDrawnCard` 保存完整原抽牌行、原 `card_drawn` 事件、实际奥秘分配、接受动作与目标驻留。恢复时校验实际原事件及其后的奥秘揭示；原始工作中保留已执行请求可以验证，重复执行请求被拒绝。
- `DrawTransformation` 是独立不可变结果，保存实际变形前后物理分配、原事件、原接受与执行时钟和真实入手 ID。每项结果须有唯一私有提交事件，与原抽牌一一对应。
- 普通入手的原实体在同一手牌驻留内变成香蕉，不制造第二次抽牌或第二次入手。原手牌在揭示反应中真正离开后跳过，不追逐后来同名体或重新入手。
- 原生或授予的抽到施放牌已经在原暂存墓地区域时，原实体变成香蕉并沿普通移动/容量规则尝试入手。原待执行 CAST、补抽与原 `after_draw` 不再执行；原声明及授予依据仍保留供历史验证。满手时使用既有墓地交付溢出证明，提交真实退役驻留，不伪造成功入手。

## 原抽牌后续

直接减费的 `FinishDrawDiscount` 和匹配后续的 `CaptureMatchingDraw` 等原抽牌完成后再捕获结果；只读取该根原抽牌，不借额外反应抽牌或未变形自动施放的补抽。

既有物理抽牌组继续沿自己的原补抽链完成，再读取该次实际到手结果。费用奖励可作用于香蕉；随从属性奖励跳过实际法术；三张抽牌后弃法术按实际香蕉法术处理。原印刷类型资格、原复制材料与 `DrawIfCheap` 接受前的费用判定保持原政策，不因此改写全部历史消费者。

原生抽牌亡语的 `DrawForDeathrattle` 请求进入原抽牌私有依据；普通入手继续沿原入口建立记忆，转换的自动施放牌在真实入手后、通知前建立同一原物理记忆。香蕉后来离手再入手不会冒充原记忆中的那次获取。原授予 CAST 依据可以与原生抽牌观察者共存。

所有伤害、香蕉增益、减费、弃牌、死亡、容量、区域与通知均交现有公共执行器。没有在卡牌层另写随机、支付、死亡或补抽循环。

## 已知证据与本地政策

[官方 21.0 修复说明](https://hearthstone.blizzard.com/en-gb/news/23663246)明确记录蕉猾诡计应能把灵魂残片变成香蕉，支持不能遗漏抽到施放牌这一结论。这是历史官方行为证据，不认证当前国服全部时序。

本批按原对手、本回合第二次成功 `hand`/`cast` 抽取触发；初始手牌、普通移动、生成、疲劳与已经烧毁的入手尝试不发布成功抽牌事件。先烧毁再腾出空位抽取时是否占用第二次计数、揭示反应改变目标、多个转换来源的优先级、转换接受后满手的精确国服处理均作为待验证规则边缘保留。本地政策不充当官方认证，不等待实测阻塞本批。

选择可推进实际动作号，因此只要求原抽牌动作 ≤ 奥秘接受动作 ≤ 实际转换动作，不强行相等。完整原队列、选择恢复、回放、异常回滚与玩家信息边界沿共享解释器；私有原卡面、观察者、结果证明和全知状态不交给玩家。

## 协议与范围

内核 `804`、快照 schema `626`、卡牌内容 `708`。新增三个有限 Effect（`TransformDrawnCard`、`CaptureMatchingDraw`、`FinishDrawDiscount`）及一个 `DrawTransformation` payload；`DrawRecord` 增加原入手、原观察者与转换结果字段。旧 schema 1～625 按原严格版本门禁拒绝。

本批接通单卡与必要公共后续，不据 72 项参考奥秘定义已登记宣称完整过去奥秘来源、五次施放生产者、其他过去卡池或国服规则已完成。实际执行与验收结果只在两份原台账登记。
