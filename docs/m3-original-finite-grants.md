# 原接收随从与有限触发授予

`GrantLimitedTrigger`增加可选`recipient: MinionReference | None`。显式提供引用时，目标ID必须一致；排队、执行及保存恢复核对原实体分配、非未来区域代次/进入序号与原卡随从类型。实际授予还要求当前卡面、控制者和连续驻留与原引用一致，过期对象沿公共stale处理，不能把后续附件绑到同ID的新入场随从。

`recipient=None`保留原先按当前ID授予的入口，供明确需要该语义的调用者使用；不会把所有原有授予悄悄改成捕获型。引用仅约束授予请求，成功后的附件继续使用原有限触发执行器、次数和生命周期，没有增加持久来源/接收对象账本或另一执行器。沉默、变形、回手、当前/基础复制和消耗均沿已有公共规则。

`FrameCodec`在等待恢复时验证有引用的请求，包括未知/未来引用、错误目标和非随从原卡；结构变化为core426/schema344，旧schema343及更早执行状态须使用原引擎。该检查不提供未签名存档的来源认证，也不认证外部任意修改后的因果来源。

## 安魂仪典

[完整原行与双语主卡面](../data/cards/native-ceremony-v1.json)定义DINO_417「安魂仪典」，普通1费暗影法术。主体只捕获一次原施法玩家的活跃存活随从组；对每个原引用依次调用普通攻击增益、突袭授予与有引用的有限触发授予。首个反应使后一个原随从回手再入场时，后续请求都不能接到新驻留。后续新召唤对象不在原组内。

死亡附件使用`EndTurnSpec('either')`加原施法玩家座位的已注册条件，而非授予后随从的当前控制者。已安装后转控仍在原施法玩家的自然结束执行；原生有限一次用途负责消费，普通销毁负责死亡。间接在另一玩家回合施放时，附件也须等到原施法玩家的结束，故不使用当前全局回合的到期值。结束收集完成后再安装附件时仍遵守既有收集窗口，不另造补执行轮次；精确国服窗口待M6。

最终销毁同样使用原随从引用，已接受结束过程中的反应不能把旧死亡效果接到同ID的新体。已安装附件的控制/复制/移除规则复用原生命周期；原始组捕获、逐项增益与授予顺序、复制和非当前回合的精确国服政策分别待校准。

全知引用、等待载荷与原施法座位条件不进入玩家DTO。实际进度、验证结果、差异与下一项仅在[项目状态](project-status.md)和[机制台账](mechanism-backlog.md)维护。
