# 原牌库置顶对象与成功召唤奖励

实际进度、证据、差异和下一项仍只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。本页说明腐败警员和暗金教主谋实际需要的两个有限请求，不扩展任意跨机制组合。

## 同一物理牌完成随机置顶与增益

`PutMatchingDeckMinionOnTop`仅声明实际牌库接收玩家、明确的完整随从ID集合、原来源与非负攻血增量。卡牌声明中的未知定义、非随从和不存在来源均明确拒绝。真正执行时从该玩家当前物理牌库捕获所有匹配CardReference，每个实体一个权重，不按卡名或定义去重。

空池不取RNG；普通单候选随机仍取一次RNG，沿既有随机约定。选中后共享一个引用：先把该实体置顶、保留其他牌相对顺序，再交给原BuffStoredCard。同次选中不用第二次随机或重新按名字筛选。原ReorderZone只改变次序，保留存储驻留、区域附魔和已有增益，不重置牌，也不增加语义洗牌记录。

后续保存的是原有序重排和原CardReference增益。待选恢复不重新抽选；若真正后续反应使原牌离开该驻留，旧增益不会跟随同名牌或后来重入的实体。查询不选择、不消费RNG；牌库候选、原内部引用及完整顺序不输出给行动方玩家。

腐败警员声明实际对手、CAP_400t2t及+2/+2。每次真正战吼独立重读当前牌库；重复战吼可能再次选中同一仍在牌库的小鬼，按原普通增益累加。不把“置顶”当成抽牌或洗牌。

## 原成功召唤事实与连续战场驻留

`BuffSummonedMinion`声明原召唤玩家、实际SuccessfulSummonRecord ID、原奖励来源及非负攻血增量。它不新增召唤、玩家计数或GameState账本。验证原记录存在、编号/玩家/时钟正确，奖励来源已分配，执行时再核原SourceAllocationFact。

以记录中的原实体及entered_order解析既有BoardPresenceReference，再同步委托原Buff执行器。同一连续驻留内的变形或转控仍是原接收实体，不按后来卡名或控制者重新判定已经接受的召唤资格；离场、死亡、回手再入场不重绑，失效原奖励也不会复活目标。新的真正入场有自己的记录，可以独立取得新奖励。

暗金教主谋战吼安装既有普通持久PlayerEffectSpec。原minion_summoned回调核对本方实际事件和唯一原成功记录，仅原卡面CAP_400t2t接受+2/+2，随后交给公共奖励请求。对手召唤、其他同名定义、初始Scenario摆放及失败召唤不伪造资格。普通手动使用和实际效果召唤都能形成真实成功记录；由对手抽出的卧底小鬼按真实召唤接收方判断，不能把牌库所有者当成召唤玩家。

实例不依赖来源继续存活、未沉默或原控制权。独立战吼和真实重复战吼各安装独立实例，奖励按正常属性层累加。CAP_406e保留完整原始证据，不注册成没有正文的可执行附魔。

## 保存与证据边界

两个新请求由显式FrameCodec白名单校验来源和实际事实，正常待选保存原选择/受益记录，坏选择或后续异常沿原事务回滚付款、区域、附魔和RNG。只增加两个公共请求类型，无新存档状态字段、卡牌定义字段、载荷类型或调度器。采用core362/schema287严格拒旧1～286；默认卡牌指纹、观察86、命令12和外层replay1保持，旧完整存档不自动迁移。

[固定配方](../data/cards/imp-entry-followup-effects-v1.json)保存两张真实根卡、原卧底小鬼依赖及原附魔证据。官网完整卡面与child身份只能支持数据核对；精确随机权重、单候选RNG、置顶/增益通知、变形/转控继承及国服反应窗口仍须M6校准。本页不认证所有置顶、特殊授予或召唤奖励来源，也不把内部验收扩大为正式标准完整支持。
