# 原随从入场事实与回合结束奥秘

本批接入 JAM_003 暗藏深意及 LOE_027 神圣试炼，作为标准来源实际可达的历史奥秘依赖。完整两原行、四个官网主面和名称差异见[数据包](../data/cards/turn-play-secrets-v1.json)。原固定目录、完整候选和版本保留；本批不认证完整正式池或国服精确时序。

## 原入场事实

`PlayRecord.minion_entry` 保存一个不可变 `MinionPlayEntry`：实际手动使用随从的原 `BoardPresenceReference`，以及成功入场前原使用者场上其他活跃、存活、未标记死亡随从的完整有序引用。数量由成员长度计算，不另建计数器或第二份出牌历史。

付款、反制、磁力与满场判断完成后，紧邻原实际移动冻结门槛；入场后的光环刷新、反应及战吼均不能倒改原成员。只有 `minion_result='summoned'` 具有此事实。反制、磁力、入场失败、自动召唤和其他牌型不伪造手动随从入场。

严格解析保存中的嵌套类型，检查原来源身份、已分配驻留和其他成员不重复、不含原随从或未来驻留。唯一 `minion_play_accepted` 事件的原来源、使用者、动作、驻留及完整其他成员私有收据须与当前事实一致。回溯保留被撤销尝试的诊断事件，因此边界验证复用现有 `effective_events`；卡牌查询只读恢复后的 State，不能从诊断日志数牌或选对象。没有未签名存档的来源认证承诺。

## 神圣试炼

在完整手动随从出牌完成时检查原使用者与至少三个原其他随从的门槛。原接收者仍须处于同一连续在场、活跃存活且未标记死亡；战吼产生的新随从不会补足原门槛，原其他随从后来离场也不改写已捕获的资格。

`DestroyCapturedMinion` 只增加已有 `BoardPresenceReference` 这一引用形式，复用 `live_reward_minion` 和普通 `Destroy`。原严格 `MinionReference` 的卡面、控制者和驻留匹配政策保持。新形式跟随同驻留变形或转控，真正离场后不再命中手牌或同 ID 的新驻留；死亡、圣盾、复生、尸体与续接仍交原内核，不另建死亡执行器。

历史来源包括[2019 年玩家时序说明](https://us.forums.blizzard.com/en/hearthstone/t/bug-if-sky-claw-is-the-5th-minion-that-completes-the-righteous-cause-sidequest-it-does-not-get-the-11-buff/21108)和[两随从后打砰砰未触发的原始报告](https://us.forums.blizzard.com/en/hearthstone/t/bug-sacred-trial-does-not-trigger-vs-ranger-arha/7925)。它们支持战吼新增单位不补门槛的实现方向，是历史社区证据；论坛内其他回复有相互冲突的解释，不视为官方国服结论。

当前明确本地政策：门槛在成功入场前、付款/反制后捕获，排除休眠、地标及已致死单位；同驻留战吼转控仍指向原被使用随从。最初提交与此窗口之间的精确排队、休眠计数、战吼移除其他单位及转控后的正式规则仍待校准。本批不开发覆盖全部奥秘的通用排队系统。

## 暗藏深意

原对手 `turn_ended` 奥秘检查时读取其实际可用法力，包含临时法力；必须等于零，并有原己方空位。接受后的揭示反应不撤销原零法力条件。主体沿原完整绑定的三费可收集随从池、`SummonCause`、数量和实际交付路径召唤，不执行战吼，不裁候选、不按实现状态重抽，不增加冲锋。普通原对手结束入场的单位按现有规则于下个本人回合获得攻击机会，休眠继续沿自身规则。

满场检查不满足时保留奥秘；完整空池、揭示后容量变化、未知定义或缺少绑定继续采用原生成器政策。结束中的等待、期限、临时法力失效和下位玩家开始沿原结束流程。[原公布时的玩家讨论](https://us.forums.blizzard.com/en/hearthstone/t/new-hunter-hunter-dk-cards/108145)说明了在对手结束阶段召唤与下个本人回合行动的区别，不能据此认证全部结束触发优先级。

其他结束触发在本奥秘检查前改变法力时，当前实现按实际检查窗口读取；精确正式排队优先级保留待验证。
