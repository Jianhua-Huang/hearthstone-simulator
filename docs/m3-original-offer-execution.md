# 从真实发现菜单执行未选项

`PlayDiscoveredOptions` 将实际 `CardDiscoveryRecord`、完整原菜单和冻结材料交给已有整卡解释器。`OfferedCardSelection` 保存原顺序、原选中项和接受时钟；菜单槽用发现、选择及选项身份定位，与付费出牌历史的编号分开。接受时不重新抽样、不合并同名项、不制造付费出牌记录。未知定义或生产者明确报错。

法术沿原自动施法与目标管线执行；随从、武器、地标和英雄沿原安装、进入、主体、战吼、连击及重复管线执行。普通召唤的额外复制和巨型肢节不会变成额外整卡主体。新发现可接受独立嵌套根，父批次仍保留原有剩余工作。工程预算耗尽继续回滚并报错，不能冒充官方结束对局。

## 原材料与交付奖励

- 印刷生成项使用原定义。物理项依照原生产者的当前或基础复制政策使用菜单接受时的材料，不重新寻找后来同名的牌，也不移动或消耗原实体。
- 原当前材料保留已有局部附魔、费用、能力、组件和有作用域的抉择预选。基础复制及死亡、弃牌基础配方仍使用各自既有规则。新体的来源指向实际执行者。
- 每个选项固有的黑暗之赐随原配对执行，包括赐福本身的减费。只在选中后授予的减费、临时手牌寿命、额外副本或交付位置，不会因此授予其他项。
- 活体梦魇可以读取实际生成整卡的物理主体上下文，沿原普通复制召唤一个2/2；它没有伪造付费出牌，也不会使复制再次执行整卡主体。休眠主体的原激活政策继续适用。粗暴唤醒仍使用原战吼重复计划。

这些材料政策是明确的本地规则，精确国服行为仍须M6验证。准备材料不等于正式候选池完整；原菜单中的未知内容不能被删除来凑成可执行候选池。

## 源生之石与原武器身份

完整 `TLC_460` 任务以真实发现完成事件累计八次，并生成 `TLC_460t`。武器接收本人一次原发现后，执行全部未选项，再尝试扣除原武器的一点耐久；单选项菜单也完成这个批次。该窗口、顺序及嵌套政策仍待国服校准。

扣耐久复用 `ModifyWeapon`，其目标可以是已有 `EquippedWeaponReference`。它同时绑定实体、玩家、卡面、区域世代和装备顺序。中途换装、转移后重入或同名替换不会将旧义务绑定到新装备；已经接受的整卡批次继续沿原解释器结算。普通整数目标语义保持。续接codec只对这个明确的效果及引用类型增加允许路径，不放宽其他实体编号校验。

## 保存与验证边界

原选择来源、材料、执行根、子主体、目标和RNG证明均进入已有账本与私有续接帧。真正等待、独立注册表恢复、clone、回放及异常回滚复用公共事务。原菜单和未执行主体不能进入玩家接口。内部一致性校验不认证未签名存档的外部来源。

core464/schema381引入一个生产效果和两个来源payload；没有新增实体、玩家或GameState字段。旧1～380存档明确拒绝。实际验收结果与下一项只维护在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。M0正式补丁与合法生成池、M6国服校准及完整可达内容继续分别验收。
