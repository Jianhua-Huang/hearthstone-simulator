# 原版尤格萨隆的个人历史与随机施法

实际入口为 `OG_134` 尤格-萨隆的已接受战吼。10费7/5中立随从、完整原行和两份双语官网主面固定于[原始数据](../data/cards/original-yogg-native-v1.json)。标准宿主究极边境实际能够给出这个跨系列原生身份；它自身的狂野组牌合法性仍属独立格式问题。

## 薄适配与接受窗口

卡牌主体用原 `spell_history_candidates` 查询本人 `hand` 来源的完整历史，然后只计已经接受主体且没有失败的原手动根。反制过的牌、自动施法、抽到施放、历史重施和同次手动法术的额外重复不增加这个数量；已接受但尚未完成的手动主体仍计入。这个政策与现有个人施法数量契约一致，细节保留待国服确认。

每个实际战吼主体独立捕获数量，按已登记的30次本地上限交原 `CastFromPool`。原批次固定该次数，后面出现的尤格自动施法不回灌延长当前次数，也不增加后来尤格的个人根数量。数量为零时不创建施法请求、不解析生成池、不消耗随机。

施法使用当前格式已绑定的 `constructed.cards`，查询全部职业的可收集法术，允许再次选中同一法术，逐次按原局面刷新。目标和选择分支使用原自动随机政策。实体创建、CAST记录、实际费用资源、目标合法性、过载、反应、选择恢复、终局、错误回滚和回放均交既有执行器；自动施法没有新增手牌出牌或普通费用支付。

## 来源变化与明确差异

[官方16.6补丁](https://hearthstone.blizzard.com/en-us/news/23319440)确认尤格离场后继续施法。本地请求固定最初接受的玩家，离场、回手、沉默或变形后仍完成原批次，终局照常截断。

30次上限的直接当前国服证据仍缺失；[历史论坛解释](https://eu.forums.blizzard.com/en/hearthstone/t/tesspionage-rogue-bug/383/3)只是玩家材料，本轮按明确本地政策采用30。[控制权变化的玩家报告](https://us.forums.blizzard.com/en/hearthstone/t/yogg-saron-random-spellcast-transfers/128563)称后续施法可能转给新控制者；本地保留原接受玩家，记录此差异，不依据该报告重写公共施法归因。

精确个人根计数、特殊嵌套接受窗口、官方随机法术的排除项/权重和完整正式资格均未认证。当前池来自既有格式绑定，不因实现状况裁减；缺少绑定或符合条件的定义时沿用显式失败。单成员实验池仅用于固定复现，不代表完整随机池或过去域。版本对齐及这些规则边界按用户指示暂缓。

## 验证与信息

普通路径使用小型代表注册表和真实原生适配，必要的完整宿主生成链单独使用完整本地格式，避免每个规则断言重复构建全部卡牌。验证覆盖实际付款、原个人历史、原自动目标/选择/失败与资源、原批次在等待中的独立恢复/clone/回放，以及宿主发现后设1费打出。30次边界通过真实连续手动施放31张法术建立历史。

内部历史、批次续接、候选及随机状态保持原玩家信息隔离。没有新增公共状态结构或快照字段，执行版本保持既有公共契约；内容注册独立升级。具体结果、未运行检查和下一项仅在原[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。
