# 高弗雷的原爆牌等待与回手

本页是有限真实来源的内部契约。执行证据、差异及下一项仍只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护；没有认证完整国服时序或全部等待卡源的排序。

[固定数据包](../data/cards/overdraw-return-v1.json)保存JAIL_509的完整4费5/4术士亡灵卡面及JAIL_509e原监控提示。后者不是另一个可打出实体。开局来源沿既有`is_hook_source`与`before_deal`安装一份永久玩家程序；此后获得或普通打出本随从不会执行开局效果。永久程序不依赖来源继续留在场上。

## 原抽牌与销毁

只在原`draw_one`已经确定`burned`并完成真实物理入手失败后接受记录。绑定原DrawRecord、真实`card_burned`及原毁牌前分配事实；生成入手失败、满手回手、普通弃牌和直接销毁不能混作过量抽牌。

原抽牌结果保持burned，原存储亡语和销毁响应先照常结算。[原始玩家报告](https://www.reddit.com/r/CompetitiveHS/comments/1vf8hbu/thoughts_on_this_burn_godfreylock_that_made_16/)提供弃牌小鬼被抽爆仍触发、随后可以回手的实际观察；不据此把全部爆牌改为弃牌，也不把玩家观察当官方技术认证。[36.0.3公告](https://news.blizzard.com/zh-tw/article/24290431/36-0-3)只提供狂野禁用的背景，不改变本轮标准范围或证明CN37精确部署。

到原`FinishDraw`时，仍匹配的原墓地实体进入SETASIDE并隐藏；不复制新实体，不重置其当前材料。若原响应已经合法改变该物理驻留，则记录departed，不从后来的区域强行取回。当前真实弃牌小鬼只执行原伤害主体，不触发该失效分支；该政策仍待M6。

## 空位与返回

公共解释器在普通效果检查点为可返回原组排一个`RefillOverdrawn`标记，已排标记不重复插入。既有捕获反应保留原顺序；标记执行时重新核实际手牌容量及存储组。当前采用活跃玩家优先、每次从该玩家完整剩余物理组均匀选择一个的局部政策；单候选不消耗RNG。

返回沿原区域移动/手牌历史，保留同一entity ID和owner，对方牌库抽取时保留原owner及实际收件controller。使用公共`attach_cost`安装一次永久-1费用附魔，再发布普通费用与入手通知。不是新抽牌，不执行“抽到时施放”或补抽；原费用及属性材料按普通存储规则保留。每次重新出现空位或提高容量时继续，直到没有可用原牌或没有空位。

这里仅定义有限检查点顺序，没有认证所有其他等待来源的完整优先级。任务奖励的满手等待及优先于本卡返回的内部交付见[任务奖励契约](m3-quest-hand-rewards.md)；完整来源、精确排序与国服一致性仍须校准。

## 保存和玩家边界

新增`GameState.overdraw_returns`保存不可变原记录，专门严格解析；实体、玩家和原DrawRecord字段保持。记录保留原抽牌/烧毁身份、开局程序来源、原隐藏驻留、实际手牌分配与费用附件、完整随机候选及MT19937前后状态和返回次序。只有一个新Effect，没有新的显式帧payload类型。

恢复连接原烧毁、完整接受/存储/返回收据及原选择工作，拒绝漏组、借抽牌、重复标记和连同随机收据一起裁候选。已关闭的候选通过实际存储/返回顺序重建，不按当前同名随从猜测。原Rewind有效事件视图用于退役被放弃尝试；终局保留真实已执行前缀，不继续回手。

私有等待列表、物理租约、候选、RNG和内部收据不进入玩家DTO；原可见烧毁及普通入手信息沿既有投影。检查证明内部一致性，不认证未签名存档来源。精确随机、优先级、材料失效和可见性仍需M6国服校准，标准正式池及完整可达范围继续独立验收。
