# 卡牌自身被弃时的原生主体入口

原生亡语例外：真实卡面明确要求存储退役触发时，可声明`stored_deathrattle=True`并沿[存储亡语契约](m3-stored-deathrattles.md)使用原亡语接受、禁止和重复协议。它与本页普通`on_discard`/`on_destroyed`主体互斥，不创造场上死亡事实；未声明的旧路径保持本页原语义。

本契约描述独立基础能力。实际执行与下一项只维护在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。国服精确时序尚待校准，本文不宣称完整弃牌族或最新正式卡池已经支持。

## 声明和接受

`CardDefinition.on_discard` 默认 `None`，非空时引用注册表中已存在的行为。仅支持可从手牌使用的普通原生卡牌；选择专用定义、非手牌载体和融合载体不开放。注册表冻结时校验行为，不把未知主体当作白板。

原 `install_printed` 为实体安装 `on_discard` 印刷附件。附件使用既有身份、来源与可沉默生命周期，不增加通用授予入口；消费、到期、融合或其他无关载荷明确拒绝。复制、变形、回手及重置沿原生命周期处理。

只有原弃牌管线真实完成 `HAND -> GRAVEYARD` 并提交成功 `DiscardRecord` 后，才捕获这张物理卡牌的主体。重复使用过期手牌引用、烧牌、出牌、死亡或普通移区不会产生主体。不同物理卡分别接受，不按卡名去重。主体的玩家是弃牌时手牌控制者，主体来源是被弃的卡；原记录的 `source` 仍保存造成弃牌的原因，原拥有者可以不同于控制者。

本地调度政策是在原普通事件监听、手牌进度和手牌后续捕获之后追加本牌主体。已有监听顺序不变，此相对顺序必须在 M6 国服校准，不能单凭卡文证明。

## 使用原解释器

接受结果是原 `BehaviorCall`，其分离的 `RuleContext` 增加 `discard`，保存本次不可变原记录；`event` 与 `trigger` 保存原弃牌事件和印刷声明，`state` 保存真实移区后的原接受状态。`play/cast/draw/power/battlecry/combo/physical` 等其他主体根为空，不自动把弃牌视为施法或出牌。

回调返回普通 `Effect` 序列。抽牌、烧牌、疲劳、检查点、选择、暂停恢复和回滚仍由原解释器处理，没有第二套弃牌执行器、事件、对外动作或新的状态计数器。只增加 `CardDefinition` 声明和 `RuleContext` 输入字段，复用原弃牌历史及现有序列化类型。

若主体请求选择，原始事实可用于构造冻结的选项效果。原有 `on_select` 回调仍使用既有的新上下文政策，不自动继承 `discard`；需要的原操作数应在选项或既有受支持载荷中冻结。排队主体已经接受后使用其原状态，不因后续局面重新判断是否弃过牌。

## 恢复与边界

原 `FrameCodec` 编解码和主体执行共同验证：typed 记录、原事件、当前原接受回合/动作、完整弃牌游标、最新原记录、真实墓地分配、对应原生声明和回调身份必须一致。一般当前载体及死亡记录也校验声明唯一性。恢复不把今天的局面覆盖原捕获状态。

这些是受信任内部状态的一致性约束，不提供未签名存档来源认证，也不声称通过内部字段证明所有任意删改队列的来源。玩家接口不增加弃牌历史、完整规则上下文、行为标识或内部证明。

协议升级为 `prototype-v207 / core-effects-v201 / schema195`，旧 schema 1～194 明确拒绝。默认没有 `on_discard` 的注册表定义不因空声明改变原指纹。

## 最小真实验证与保留范围

仅新增 `BT_300` 古尔丹之手的完整原始记录与 pin，隔离原生定义以同一原 `Draw(3)` 表达出牌和被弃时抽三张。数据、内部实现和国服校准分别登记；生产代表包和正式合法池不据此增加完整支持声明。

`KAR_205` 自身被弃后召唤只提供后续调查依据，本项不实现该召唤或假定原物理材料语义。弃牌批次候选冻结、历史返还材料、其他主体、任意授予、卡牌组合、完整 U59 与 M0/M6/M7/H2 均保留。现有能力能表达的后续效果优先复用，不再造模块。
