# 宁静旷林的沉睡与原玩家结束时钟

MEND_044宁静旷林是2费、2耐久地标。完整原行、两个附魔证据原行和严格中英文主面固定在`data/cards/native-owner-end-sleep-v1.json`，附魔证据不注册为可执行实体。正常激活使原随从获得+2生命与嘲讽，然后沉睡至激活玩家的下个真实回合结束；目标可以属于任一玩家。放置不选择激活目标，激活不支付法术费用或制造CAST，耐久、冷却与末次使用退役继续由普通地标执行器负责。

英文原文是`falls asleep`。[官方30.4说明](https://hearthstone.blizzard.com/en-gb/news/24135706)记录修复困倦的岛民作用后的强制攻击，[32.2说明](https://hearthstone.blizzard.com/en-us/news/24198086)再次记录自动攻击修复。由此不把沉睡解释为无法参与战斗的DormancyState。实现使用普通`cannot_attack`策略限制自愿攻击，保留目标活跃状态、可被选取、嘲讽防守、原触发与普通强制攻击路径；不冻结、离场、重新召唤或重置已消耗攻击机会。

主体接受时保存原`MinionReference`及`next_owner_end`期限。生命、嘲讽与攻击限制分别调用既有捕获目标授予器；前次反应使目标离场、死亡、变形或改变控制时，后续授予不重新绑定新实例。来源地标在最后耐久退役后，已接受的尾部仍可以完成。期限跟随原激活玩家，不随目标控制者或来源后来控制者改变。

`GrantAttackPolicy.until_next_turn_end`承接已有`OwnerTurnExpiry`，只放行有真实来源与捕获随从的独立`cannot_attack`声明，不借用数值附魔、休眠、关键词或全局turn+2。`AbilityInstance.attack_policy_expiry`是唯一新增附件字段，默认None；`validate_next_owner_end`用原创建回合和真实玩家区间检查下个结束期限。额外回合可以成为下个真实区间，跳过的时段不算真实开始或结束。普通中性/条件/次数等原攻击策略维持既有接口和时序。

共享`timed_keywords.expire`在对应自然结束的到期阶段统一移除全部到期限制，再发布原`attachments_expired`事件；结束反应等待时限制仍可存在，不在下个开始过早清除。当前实体副本保留原玩家和原期限，基础副本不继承该授予；死亡历史保留原冻结期限，即使当前尸体附件稍后被清理。回手、变形、沉默与当前复制继续走原附件生命周期，不另设第二个复制或定时器执行器。恢复对当前、冻结死亡与待交付限制分别校验原期限。

上述强制攻击行为有官方历史修复依据，但不是国服37.0逐案校准。该地标的沉默/冲锋/突袭细节、分阶段授予的微观反应顺序及自然结束前后窗口仍明确列为M6待校准；当前可移除授予、冲锋/突袭不消除独立攻击限制是本地执行政策，内部测试只认证此政策的一致性。

内核479、快照schema396拒绝旧1～395。没有新增Entity、PlayerState、GameState字段、Effect或冻结载荷类型；既有攻击授予新增可选期限参数及能力附件字段由新schema解释。默认代表注册表不接入真实地标，原311指纹保持。观察/命令/回放接口形状保持，玩家投影和事件不返回内部期限对象、物理引用、等待帧或RNG。
