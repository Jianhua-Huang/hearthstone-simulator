# 双任务施法与随从半体拼合

真实消费者为TLC_817寻求平衡（Reach Equilibrium）及四个必要形态，完整六行和严格双语主面见[固定包](../data/cards/seek-balance-v1.json)。TLC_817t5完整拼合体已有定义和主体，消费者核其完整定义指纹后复用。实际验证及下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 两个独立子任务

`QuestSpec('paired_quest', (holy_stage, shadow_stage))`明确声明两个独立子任务，不解释为顺序阶段。每个stage必须与其独立普通任务定义的完整唯一阶段相同，子任务不能递归或被其他双任务来源共享。根牌使用印刷任务关键词并保证正常起手，自己不进入任务区；其主体沿普通施法流程施放两张声明中的真实子任务法术。一次手牌出牌只支付根牌费用，子法术有独立实体和实际施法记录，不伪造手牌使用或额外付款。

`CastQuestChild(parent_cast_id, card_id)`只接受仍在执行、已进入主体且未中断的原双任务施法。自动施法记录以`SpellCastRecord.quest_parent_cast_id`绑定该原父ID，现有施法开始收据同时保存这项私有来源；完整历史验证核父定义、子身份、原施法者及玩家。选择恢复后的动作编号可以变化，不能要求子法术与父法术在同一动作编号内执行。原施法后来正常结束或被终局中断，不撤销已安装的子任务。

`QuestProgress.activation_cast_id`保存原安装施法，任务线阶段及重复任务周期沿用该来源。重复施法的后一次同实体尝试不能覆盖已经安装任务的来源；原自动一费额外施法明确清除子任务配对许可。只有属于同一次原双任务施法的两个主任务可以共存；其他主任务继续互斥。完成其中一项后，剩余一项仍阻止新的普通主任务。

根牌正常手牌准入先核两个实际任务及共享区域空位；自动施法失败沿原任务失败路径。两个子任务分别监听真实完成施法，按原施法者和冻结法术派系判定，以原cast ID去重；此前、对手或其他派系施法不计入。各自达到四次即发放对应原半体，进度、奖励等待、移除与结束仍由原任务模块处理。

## 同手随从拼合

`HandCombinationProfile(result_card_id, left_card_id, right_card_id)`只声明三个互不相同的普通随从卡面；所有已注册家族互不重叠，不允许递归拼合链。声明只读并进入已有注册表指纹，空注册表不增加默认指纹字段。处理按稳定的结果ID顺序进行，不依赖注册先后。

原手牌结算入口同时处理此类随从，保留既有初始化、换牌暂停及每个效果后的检查窗口。同一玩家手牌中存在互补的当前卡面时即可拼合，无需相邻；至少一个未沉默半体仍具有其原印刷拼合文本。两个旧实体移入墓地，在两者较左位置分配新的完整随从实体，不制造死亡、弃牌或尸体；不同玩家的半体、已离手半体和两个相同半体不配对。

拼合使用已有`recombine`获取分类和`cards_recombined`私有事件。当前本地材料政策复用`shatter.inherit`的规范左半继承：新体具有自己的完整印刷主体，保留左半的原附魔、非印刷能力和临时期限；物理左右次序不改变该来源。该材料政策用于随从拼合的准确性仍须国服校准，不能从法术裂变的旧内部证据推导官方规则。这里不添加裂变关键词、不拆分完整随从，也不改变原法术相邻裂变规则。

左半单独打出保留4/4嘲讽及本体当前复制战吼，右半单独打出保留4/4复生及随机敌人5点普通随从能力亡语。两者直接复用既有完整索利托斯的相应主体；拼合体的原8/8、嘲讽、复生、战吼和亡语定义不改写。

## 保存和校准边界

新增一个公共效果及上述两个可选来源字段，schema424拒绝旧423及更早，当前内核身份见原两份台账。没有新增GameState、PlayerState或Entity字段，也没有新动作、命令或玩家投影字段。原父施法、安装施法、完整帧和宿主历史不能提供给玩家，公开任务进度仍用原DTO。

[官方根牌](https://hearthstone.blizzard.com/en-us/cards/117544/)、[生命之息](https://hearthstone.blizzard.com/en-us/cards/118551/)和[死亡之触](https://hearthstone.blizzard.com/en-us/cards/118552/)支持卡面目标、半体主体及持有两部分时拼合。双任务的精确施放/区域准入顺序、原施法计数窗口、拼合检查点及附魔/费用/临时材料继承仍须固定国服37.0的M6证据。奖励继续沿现有AddToHand及满手烧牌内部政策；正式满手奖励规则也保留M6核查，不能把该旧政策当作官方认证。全部内部测试均不能代替M0正式合法/生成池、全部可达内容或最终发布验收。
