# 原战吼消灭组的亡语记忆

[完整资料](../data/cards/past-destroyed-group-memory-v1.json)保留塔隆·血魔 BT_126 的固定完整原行、完整双语主站面、两条原附魔证据及完整过去732传说参考。BT_126e 是原消灭记忆的附魔证据，BT_126e2 是 +1/+1 的附魔证据；两者在已核主站目录中没有对应面，不注册成物理卡或生成成员。恋旧风潮仍为未绑定来源，完整过去池和其他目标域保持开放。

`NativeDeathrattleSpec('destroyed_group')` 在原 `DeathrattleMemory` 末尾保存有序 `destroyed_groups`。每组包含完整原接受战吼、物理来源分配、死亡起点、完整有序原随从引用及对应原消灭原因。类型、来源、原控制者、物理驻留、顺序和实际死亡/暂缓将死事实一起校验，不能按同名卡、后来死亡总表或当前控制者重新拼组。其他原生记忆声明和字段保持；新种类不能混入旧成长、抽牌、弃牌、复制或囚禁材料。

实际战吼在一个普通 `DestroyBatch` 中消灭当前其他活跃、存活、非将死友方随从；休眠、地标及可交互载体不进入组。同步标记全部原目标后、公共死亡检查点前，把整组写进原连续载体上已接受的亡语附件。目标亡语杀死塔隆时，冻结死亡材料能够保存完整组；光环移除的生命调整仍遵从原属性层，不自行制造死亡。原载体/附件已经离开则不绑定后来的新驻留，清场仍由原战吼执行。每次实际重复战吼分别保存该次新组，不重用第一次候选。

只有真正正在执行的原亡语才能读取它已冻结的组。按原组、原成员顺序匹配确切不可变死亡记录，并交普通、有来源的 `ResurrectMinion`。基础身体、原组合、动态印刷数字、召唤数量、容量和入场继续使用原复活器；旧伤害、临时增益和旧战吼不带回来。复活单次入口与原死亡材料末尾仅增加有限 `entry_grant`，只允许有原来源的普通相对 +1/+1，不能混入设值、后续主体、数量父生产者或一血复活。每个实际额外体都在首次通知前安装普通属性附件，之后的沉默、复制与回手继续沿原生命周期。

当前复制、亡语继承和活体亡语复制保留这份不可变原组并分配独立附件；基础复制、沉默、变形和回手按既有规则清空或退役。提前触发和实际重复亡语使用同一原组，死亡记录不因复活被消费。真实未绑定的新身体使用已知空原生记忆，不把未知定义或未知死亡来源当空组。

待选恢复重核原战吼/亡语执行、完整组及原死亡材料。关闭的 Retry 旧材料校验冻结结构和物理分配界限，不用后来复用的历史ID认领旧来源；未签名存档仍不提供外部来源认证。完整组、死亡起点和内部战吼材料不进入玩家DTO。原战吼记录解析提取为共享函数，状态历史与新记忆共用同一原解码规则。

同步标记到记忆写入之间的内部 `destroyed` 通知快照仍保持原捕获时点；精确通知、死亡顺序、跨控制/特殊重入和原组次序为明确本地政策，待国服校准。精确执行证据、差异和下一项仅在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护，不因原十二根前审完成而声明完整目标达成。
