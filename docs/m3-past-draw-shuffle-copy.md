# 过去真实抽牌与洗入复制消费者

本批接邪能领主贝图格、塔克·诺兹维克。完整原名单、四个客户端原行、六个双语主站面和附魔证据见 [数据文件](../data/cards/past-draw-shuffle-copy-v1.json)。原十二根前审和高弗雷、塔隆两个实际剩余需求保持，进度仍只在原两份台账登记。

两类主体均复用原事件接受时冻结的 `RuleContext` 与完整不可变复制材料。此前反应移走、使用或更改原牌，不会使已接受的复制改为另一个当前实体。复制关系、附件重新分配、手牌容量、入场和信息边界仍由原执行器负责，不新增抽牌器或洗牌器。

贝图格核真实 `DrawRecord`、原接收玩家及随从面，只对成功进入本人手牌的原随从抽牌接受 `stored_copy/current` 材料，再以原 `SummonCause` 普通召唤。保留原手牌与当前复制属性，不触发新战吼；满场和数量扩展沿原召唤执行器。烧牌、原抽牌变形和休眠的精确官方窗口继续保留待校准差异。

原 `CopyEntryMaterial` 仅末尾追加成对 nullable `draw_id/draw_event`，只允许上述当前手牌复制及有限临时授予形状。状态验证绑定原真实抽牌、原 HandEntry 身份/驻留和原回合/动作；召唤原因绑定原接收者、原触发来源和原时钟，完整事件验收再核确切唯一、早于召唤接受的原抽牌通知。仅关闭后的历史收据可由该确切通知证明原时间线，避免后来回溯删除原状态记录导致身份被重绑。只有这个有明确原记录的分支允许材料早于后来入场接受窗口，原普通复制的严格相同窗口守卫保持，不能用修改时钟或放宽全局守卫掩盖选择后的差异。

只在现有 `CreatedMinionGrant` 增加有限 `turn_end_destroy` 形式：必须只有突袭、明确的结束死亡行为身份，无属性、复生或其他混合。只允许原当前 HAND 随从的 stored-copy 场上交付，在第一项入场通知之前安装突袭与普通 `turn_ended` 附件。普通生成或手牌交付不能偷用此形式；保存和原复制材料验证核行为注册。没有增加 Effect、载荷、调度器或 GameState 类型。

结束附件通过原连续驻留引用执行 `DestroyCapturedMinion`，不按实体ID消灭离开后重入的新驻留。采用任一自然回合结束、当时活跃的普通触发语义；沉默、变形和回手清除附件，当前复制保留，新的基础/复生实体不保留。控制变化按当时载体控制者和普通死亡处理。没有另写时钟或亡语结算器。

塔克监听原三类实际牌库插入通知，读取原六项 `deck_insertion` 和对应 `DeckShuffleRecord`。只有实际随机洗入且语义发起者、接收者均为本人时，每个物理插入成员各复制一次原事件时的完整当前材料；同一次操作的多张牌不合并成一次复制。已知对手发起和顶部/底部等位置放置不触发。本人牌库随机插入但原发起者未知时明确报未支持，不猜测来源所有者或控制者，不静默忽略。

以上事件接受、复制属性、任意回合结束/休眠、控制与未知发起者政策为明确本地实现，精确国服边缘和版本/热修对齐继续暂缓。本批不认证正式标准池或整个过去名单完成，未知候选不得从任何池中删除。
