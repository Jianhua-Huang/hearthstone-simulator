# 过去传说的原始事件消费者

[完整资料](../data/cards/past-legendary-event-draws-v1.json)保留酸喉、克洛玛古斯、观星者露娜、“鲨鱼”加佐和加兹瑞拉五个原始面，以及原 732 张过去传说的完整身份与顺序。七份完整原行和十四个官网语言面用于核对资料；执行与验收见[项目状态](project-status.md)。本批是标准实际可达内容的依赖补齐，完整过去传说来源继续单独验收。

酸喉响应原正伤害通知，只对当时的敌方随从提交 `DestroyCapturedMinion`。原物理引用保护目标驻留；圣盾、免疫、零伤害、死亡与后续事件仍由原健康和死亡管线负责。加兹瑞拉响应自身正伤害，用下面的公共入口逐次翻倍当前攻击力。

`DoubleCapturedMinionStats` 在执行时核对 `MinionReference` 的原身份、控制者、区域纪元和入场序号，再委托原 `DoubleStats` 执行器。两个同批受伤事件按先后取各次结算时的可见攻击力，6→12→24；接受后离场并以同一实体 ID 重新入场时，旧引用失效。接口复用原攻击/剩余生命选择器、数值附件与刷新流程；未知来源、未来引用、错误选择器和未知随从定义在执行或帧解码时明确拒绝。

新增一个 Effect，没有新增载荷种类。core828/schema648 拒绝旧1～647存档；构筑内容748。原支付、抽牌、生命、伤害、死亡和属性结算器保持，旧三种捕获式属性/变形载荷的帧路径继续沿原实现。

克洛玛古斯读取实际 `DrawRecord`，只复制本人成功抽取到手或抽到即施放的物理牌。前者冻结原手牌当前材料，后者按原抽取面作基础复制；复制交给普通 `CopyCard`，不会制造另一条抽牌记录。原牌后来被更早的反应移走时，已接受复制仍保留原材料。烧毁、疲劳和普通入手没有成功抽牌通知，满手的额外副本沿原生成烧毁规则。

露娜读取已完成的 `PlayRecord.hand_index/hand_size`，用提交前的最右位置决定抽牌，不从效果结束后的手牌反推。自身入场与对手出牌排除；被反制的本人物理出牌仍是一张已使用的牌。额外重复施法或出牌主体内部自动施法不制造另一条个人出牌记录。

加佐绑定原 `attack_declared` 的唯一声明和事件序号，在战斗前为双方提交普通抽牌。当前政策按该通知时各自缺到三张的数量报价，由控制者先执行；普通抽牌处理替换、疲劳和额外通知。其他反应在补牌中改变手牌数量时是否逐次重查，以及精确国服先后，保留为待验证差异，不额外编写抽牌循环。

抽牌转换、当前材料继承、同窗接受与源消失等精确国服边界沿现有本地政策登记。MIS_701 与完整萨满来源仍未绑定；YOG_522、其他过去来源及其余专用域继续在原两份台账维护。版本、热修与规则边界本轮暂缓，不将注册数量当作完整效果或正式资格完成。
