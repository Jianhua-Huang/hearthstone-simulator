# 过去法师法术的原抽牌后续

[完整源包](../data/cards/past-mage-draw-followups-v1.json)保留清凉的泉水BAR_542、怨灵之书GIL_548、畅游海底VAC_431的三条完整原行及六份中英文主面。它们是标准过去来源的跨系列依赖，不增加标准组牌根；完整179张过去法师源继续按原台账补齐，不按已有实现裁剪。

## 三个有限奖励

三张牌均使用原DrawPhysicalGroup、DrawRecord、HandEntry及原续接，不扫描后来整手牌，不把反应额外抽牌混入原槽。

| 原牌 | 原抽牌计划 | 组后结果 |
| --- | --- | --- |
| 清凉的泉水 | 两个普通牌库顶槽 | 每个原根为成功hand/cast法术时，分别调用既有RefreshMana复原2水晶 |
| 怨灵之书 | 三个普通牌库顶槽 | 仅原根为hand法术、仍属于该次原HAND引用的牌进入共同弃牌批 |
| 畅游海底 | 一个排除来源卡牌身份的实际法术匹配槽 | 用选中原根抽前完整材料中的存储本地费用，从完整普通域召唤同费用可收藏随从 |

新奖励kind分别为refresh_drawn_spells、discard_drawn_spells、qualified_spell_cost_followup。前两者限定完整两/三普通槽；后者限定单一排除来源的法术检索，无任意目标或场上来源。没有增加新的Effect、payload或状态字段。

泉水不直接改写可用法力：仍走原mana_spent账户和RefreshMana，不制造临时法力或额外水晶。两个槽及其全部反应结束后再给奖励。原实体后来离手不撤销已经发生的原抽牌信用；同一实体发生两个真实根抽牌时，每个根各自判断。

怨灵之书保留每个原根与其原手牌驻留。烧牌没有第二次弃牌，draw-cast根已施放，不把其补抽当作本牌的待弃对象；额外触发抽牌、预先持有牌及旧引用失效后的新驻留不冒充原受益。若同一实体被放回牌库后又成为本组后续真实根，只处理其中有效的新HAND引用一次。

zones的原单张弃牌拆为准备原事实、移动和发布三个内部步骤；discard_card仍按原单张顺序调用，保留deathrattle_memory及on_success。有限discard_cards只接受同一来源、唯一物理引用、无额外成功续接的普通批，先准备全部原事实、移走全部有效接收者，再发布原card_discarded与原弃牌历史。全部监听看到已经共同移出的组，不在两个弃牌之间执行回调；没有另建弃牌记录或死亡处理。

畅游海底在真正选中牌库实体、调用draw_one之前，复用既有CapturedCardCopyMaterial冻结完整原材料；此处只读取材料中的本地费用，不创建副本。后续手牌减费或换面不改原捕获费用，之前已有的牌库本地费用变化则保留。原根与材料、来源、控制者和DECK身份照原校验绑定。资格回调带完整draw_group与原draw，取得原仍在执行的CAST以构造普通SummonCause，召唤和容量、随机、入场反应继续交给SummonFromPool及原数量结算器。

## 本地政策和公开资料边界

完整卡文不能确定所有烧牌、补抽及费用时点。本地明确采用：泉水仅计本次两根中hand/cast的法术，不计烧牌/疲劳、补抽链叶子或额外反应抽牌；怨灵之书仅弃原根hand法术；畅游海底用抽前存储本地费用，hand/cast原根有效，烧掉的根不召唤，空匹配跳过不疲劳。以上精确边缘尚未国服校准，版本/热修与规则边缘按用户授权暂缓。

[玩家关于怨灵之书与炸弹的讨论](https://www.reddit.com/r/hearthstone/comments/1dal9gh/)描述抽到即施放先于弃牌；[社区Casts When Drawn说明](https://hearthstone.wiki.gg/wiki/Casts_When_Drawn)区分成功抽牌、溢出及补抽链。它们只作有限观察，不能认证这里全部时序。卡面和数字仍以保存的完整固定原行及主面为依据。
