## 原生执行

点唱机图腾使用普通所有者回合结束触发、实际控制者、存活/沉默政策和 SummonByCard，召唤已有 CS2_101t。数量、位置、战场容量、召唤归因和后续反应仍由旧执行器负责。主面省略的是原完整文本中的实时新兵身材槽及英文冠词尾缀；共享准备工具只对完整固定 JAM_010 原行允许相应省略，0攻击必须另有双语数值证明，不允许省略静态规则或改填身材。

灯火机器人声明 `cost.player-holy-cast-count-v1`，同一声明供根卡和真实 MIS_918t 使用。它读取原完整施法历史中属于该玩家、神圣学派、payload已接受且没有失败的每个真实施放；手动、普通重复、效果、抽到施放、历史重放和 native_repeat 各自计数。未开始正文的自动施法、反制、失败和对手施法不计入。耀眼创意本身也是神圣法术；实际发现时便已贡献一次，不能只按生成后发生的事件减费。

新增有限费用profile复用旧完整前缀、付款窗口、生成报价、保存和验证。PlayerSpellCountCostRow 补齐公共施法账本已有的 native_repeat 来源形状：没有手动play_id，iteration大于1；不能冒充手动根。旧手动根、邪能根与不同学派profile保留各自原计数操作数。core761标记新接受范围，字段和线格式不新增，schema600/观察119/命令13/replay1保持。跨内核版本仍按原恢复门禁处理。

扩大沿 HandDerivativeSpec/普通手牌容量交付。原卡的+5/+5发现增益、临时费用和其它实例附件不会复制成扩大形态；终态印刷8费8/8加Gigantic及同一神圣费用声明，继续受全局已接受施法数影响，终态再次打出不再生成。

纯净馆长先交普通 CheckDeckCondition 的 current/no_neutral，再用 DrawPhysicalGroup 的12个完整种族槽顺序抽取。顺序按固定种族表为德莱尼、亡灵、鱼人、恶魔、机械、元素、野兽、图腾、海盗、龙、野猪人、纳迦；All按通用匹配规则参与。每槽从当时实际牌库选择，已抽实体不能重复使用，没有合格牌跳过而不造成疲劳；真正手满的物理抽牌照常爆牌。双种族/All的跨槽归属和顺序是明确本地政策，未作CN边界认证。

报警安保机器人沿实际亡语，使用原物理抽牌组的随从查询与 `set_stats_cost_all(5)`。原卡面明确写 another/其他随从；查询排除原 YOG_510 身份，不自行合并未确认别名。成功进入手牌的原抽取驻留才设攻击、生命和费用为5，不是加5；本来手里的同名随从、额外反应抽到的牌、已离开的原驻留及爆掉的牌不能借用这次奖励。[官方卡面](https://hearthstone.blizzard.com/en-us/cards/101009/)支持原规则文字；隐藏别名、资格和特殊窗口继续留档。
