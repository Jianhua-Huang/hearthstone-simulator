# 原物理库存、完整牌库复制与武器装备

这些真实牌使用[完整原始资料](../data/cards/past-physical-inventory-weapons-v1.json)和[原生适配](../hs_sim/cards/past_physical_inventory_weapons.py)。资料存在、行为内部验证和正式国服池认证分别记录；实际验收和下一项仍只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。

## 原区域与实际消灭

帕奇维克依次提交手牌、牌库、战场的 `DestroyRandomZoneMinion`。每项在实际执行窗重新查询完整物理候选，空池不使用随机数，同名实体分别占权重；选中后交原 `DestroyStoredCard` 或 `DestroyCapturedMinion`。储存牌被消灭不冒充弃牌、场上死亡或残骸。未知牌面仍明确报错。

纳多克斯使用原 `IF_AVAILABLE` 友方当前亡灵目标规则，包含全种族及真正的种族变更。定向战吼不能选择自身；无其他合法目标仍可普通出牌。该通用约束有[暴雪开发者原说明的转载](https://www.hearthpwn.com/news/64-hearthstone-puzzle-2-blue-posts-extravaganza)。

`SacrificeForFriendlyAttack` 委托原 `DestroyBatch`，以确切原受害者、原驻留和 `DeathCause` 连接原 `DeathRecord` 的实际攻击力。原死亡及亡语检查点结束后，对当前存活友方随从施加普通攻击增益，不要求来源继续存活，也不把旁支死亡算成成功牺牲。亡语新随从是否接收这一后续增益、延期死亡时的接受窗仍为本地契约，未以此宣称国服逐窗校准。

## 发掘、变形与返回原拥有者牌库

芬利读取本人原 `ExcavationRecord` 累计历史，至少两次才捕获当前活跃敌方随从并逐个交原变形器。不是看当前发掘层数、对手次数或手牌里的奖励数量。

固定客户端原行的 `COLLECTION_RELATED_CARD_DATABASE_ID=69723` 明确指向已有 `CORE_LOEA10_3`。该鱼人宝宝的旧完整定义和元数据保留；[28.4 客户端资料研究](https://www.hearthpwn.com/news/10637-patch-28-4-all-card-changes-datamined)也记载这一确切关联。当前直查 CORE 主面返回空列表，原 `LOEA10_3/13879` 的完整双语主面只另证普通零费 1/1 鱼人本体，不冒充当前 CORE 主面或正式生成资格。[调查记录](../outputs/card-integration-20261014/k729-past-physical-inventory-weapons/Finley-child-source-investigation-01.json)保留这一差别。

抱龙王保留真实冲锋，捕获双方活跃随从的当前攻击力和原 `SourceAllocationFact`，仅将严格低于来源攻击力的原体返回其物理 `owner` 的牌库。每个目的玩家一项 `ShuffleDeckCards`，里面复用 `ShuffleOriginalMinion`；控制者不同不改写拥有者。原反向移区规则清除普通附魔，不制造死亡、弃牌或新实体。已经接受的组不因来源后来死亡而重选，离开原驻留的目标不重绑。

## 两次真实发现与一次原手牌交换

西塔尔的 `DiscoverHandExchange` 先接受本人完整物理手牌的发现；第一次实际发现完成并结算其监听后，才接受对手当时的完整手牌。保留原可见卡面、完整原交付配方及物理引用，同名牌不是同一个候选。第一次选择没有新获取对象，第二次完成指向实际换入的原实体。

共享 `transfer_hand_cards` 只支持普通单张转手或一个双方配对。先核最终净手牌容量，再同时移除两个旧槽、提交双方控制者和原入手历史，最后才发布移动通知。双方满手不会烧掉互换牌，监听看不到只交换一半的状态。原拥有者、普通手牌附魔及原生命周期政策继续保留；已选原体移区后不按名字重选。

恢复证明绑定两次原选择、原纪元、实际交换通知和实际接收对象；选择错误与反应异常复用原事务及随机回滚。内部配对通知不进入玩家公开事件白名单，原始配方和对手未公开手牌不通过玩家 DTO 输出。

## 完整原牌库复制

`CopyOpponentDeck` 在实际接受窗冻结对手完整有序当前牌库的 `CapturedCardCopyMaterial`，随后复用原 `CopyCard`。支持原五种可用牌类型，不按职业、普通开局张数或效果覆盖裁剪，不消耗原牌。

托尼先以原非死亡移除器将本人旧牌库移到 `SETASIDE`，再按对手原顺序创建完整当前复制；替换不产生弃牌、牌库消灭或语义洗牌。只有原接受的压轴条件成立，才在替换后普通抽一张，空牌库沿原疲劳处理。本尼迪塔斯保留本人原牌库，将完整复制作为一项语义洗牌组加入。容量、当前附魔复制、获取通知和失败处理仍由原执行器负责。

## 装备与原边位强制攻击

布林顿和马尔考罗克使用原完整可收藏武器查询，不按职业或可执行覆盖删候选。`EquipRandomWeapons` 仅增加末尾默认 `opponent=True`；布林顿双方、马尔考罗克本人，均不加属性。旧入口默认双方装备且本人 +1/+1 保持，普通装备替换及原武器亡语沿原管线。零增益不制造属性修改通知。

库尔特鲁斯读取原接受的流放条件，先给原场上驻留本回合免疫，再提交左右两端原敌方驻留的普通 `ForceAttack`。唯一一个仍存活敌方随从同时占两个端点，因此攻击两次；[官方 20.0.1 修复说明](https://us.forums.blizzard.com/en/hearthstone/t/2001-server-patch/58519)明确修复过只攻击一次的旧行为。来源已离场、首战死亡或原目标移区不创造新的攻击者或新边位；后续原战吼重复也遵守来源存活要求。伤害、反击、攻击历史、死亡及回合到期继续由公共模块执行。

休眠、地标占位与边位解释，原死亡/获取通知的精确国服排序，以及版本/热修对齐继续记录为待校准差异。上述有限表达不建立另一套区域、发现、复制、死亡或战斗结算器，也不认证过去来源或其他专用域已经完整闭合。
