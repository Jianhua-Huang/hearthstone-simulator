# 牧师过去自然视图与湍流旋涡

本契约连接先知者沃TIME_013的完整牧师过去自然视图，并为TSC_209湍流旋涡增加一次性的全区域随从复制清除。完整固定资料见[来源文件](../data/cards/past-priest-nature-source-v1.json)，宿主声明见[v17绑定](../data/cards/local-special-pool-bindings-v17.json)。这些是明确的本地参考政策；正式版本对齐、热修和国服边缘校准仍单独登记。

## 完整名单与职业范围

沿原39个过去系列、可收藏自然法术及职业规则，在完整固定快照中取得174个联合身份。独立推导的牧师视图恰为DEEP_026大地坠饰、TSC_209湍流旋涡；死亡骑士、恶魔猎手、法师、圣骑士、术士五个可玩职业视图为空。梦境不是本批可玩职业范围。空视图依据完整174项原行及职业元数据推导，不能从当前已实现的86项中推定。

共用自然池保留德鲁伊原85项的完整顺序和每身份权重1，仅在末尾追加TSC_209，成为86项；已有DEEP_026不重复追加。池ID沿用`constructed.local-past-nature.druid-reference-v1`以保留原路由。德鲁伊实际候选仍须严格等于原85项，牧师实际候选须严格等于上述两项，五个已证实空视图须真正无候选，不创建选择、不消耗抽样随机数。

运行时逐项核对86个完整原生定义及PoolCard，并核对源牌和既有依赖定义。来源版本、完整有序成员、权重、角色、排除、目标、模式和池摘要必须匹配。六个新增scope只接受TIME_013、原自然查询和对应当前职业。猎人、潜行者、萨满、战士仍有非空而未闭合的完整名单，必须明确拒绝，不以已实现子集、其他职业池或空池代替。

先知者沃继续在本人每个成功完成的法术后触发，沿原CAST收据及来源存活门禁；不是只在自然法术后触发。旋涡将沃消灭后不会再从该已离场来源触发发现。发现、入手、支付和信息投影沿原执行器，新牌不扩大标准构筑合法根。

## 一次性复制清除

官方[牌面](https://hearthstone.blizzard.com/en-us/cards/72481-whirlpool/)说明清除全部随从及它们无论在哪的复制；实际固定数值、语言面和完整原行以本项目已审核资料为准，不随网页更新改动。本地执行政策如下：

1. 在同一个handler中，一次性捕获双方当前活跃、存活、未标记消灭的普通战场随从。休眠、地标和特殊交互载体不作为种子。
2. 复制身份使用当前规范`card_id`。附魔、费用、当前属性、所有者和原牌组复制来源不改变身份；相同显示名称不合并不同ID，变形后按当前面识别。合成配方已有独立规范ID，不新增按名称或配件猜测的匹配器。
3. 对上述身份，一次性捕获双方手牌和牌库中当前物理复制，保留各自原实体、控制者、区域、面和区域驻留引用。先验证完整捕获组、来源和预算，再沿公共区域移动提交全部存放区离开。
4. 战场原组交给既有`DestroyBatch`；所有标记完成后，才由普通检查点、死亡和反应调度器继续。存放区原组随后发布原销毁通知，固有`on_destroyed`由原管线捕获。不是抽牌、弃牌或自然死亡，不为手牌和牌库目标增加死亡行、残骸、亡语、复生或星舰贡献。
5. 这些操作只接受一次原组。亡语、复生、销毁主体或后来效果生成、抽取、洗入的新实体不会被这次请求重新捕获。

本地不删除墓地死亡历史、场外暂存体或复活资格，也不建立禁止未来生成同名牌的持续状态。公开[玩家报告](https://us.forums.blizzard.com/en/hearthstone/t/priest-whirlpool-not-working-as-card-states/91287)支持一次性结算；历史[变形复制报告](https://us.forums.blizzard.com/en/hearthstone/t/whirlpool-priest-spell-not-destroying-cards/93267)存在未解决争议，不能据此认证全部身份边界或仿造历史故障。

## 公共执行与恢复

新增`DestroyMinionCopies(source_id)`仅负责接受原身份组并连接公共执行器。`DestroyStoredBatch(cards, source_id, reveal)`把已有牌库整批销毁的提交部分推广到手牌/牌库严格引用；旧`DestroyDeckBatch`仍保留原仅牌库形状，转交同一个提交函数。没有在卡牌层重写区域、死亡、支付、反应或随机机制。

存放区目标按原引用跳过变面、离场、回入或转控后的新驻留。全部移动完成后才发布显式销毁通知。显示政策复用原公开销毁默认值，只有实际被销毁的目标获得对应揭示；其他手牌、牌库身份和内部候选库存不进入玩家投影。精确通知/揭示先后、CORE别名、特殊变形与星舰面、同身份休眠体等仍是已记录的待核边界。

新增两个frozen Effect，继续使用原FrameCodec、选择解释器、异常回滚和回放。没有新增状态字段、载荷类型或动作。内容版本726，core816/schema636；旧schema按原政策拒绝。完整空局结构只允许schema/core、新增两个有序Effect类型及相应状态哈希变化。实际测试范围、结果、保全和下一项只在原两份台账维护。
