# 过去萨满：当前过载、自然施法价格与充能召唤

对应 `data/cards/past-shaman-history-prices-v1.json`、
`hs_sim/cards/past_shaman_history_prices.py`。实际执行结果与下一项仍只记原两份台账。

## 三种不同的原始事实

变音和弦 ETC_356 使用现有 PlayerOverloadCostSpec 的有限新增 profile
`cost.player-current-overload-discount-v1`。报价同时保存原完整实际过载账本和原当前
`overload_owed`/`overload_locked`，任一正数只减 3。两账户不是整局过载总量；
初始 Scenario 可以有过载账户而没有历史增量，解锁后也可以有历史增量而没有当前过载。
原 `cost.player-overload-v1` 的随从整局水晶求和政策保留，不能混用字段或承载类型。
原接受报价在后续解锁、跨回合、等待恢复中保持，当前手牌重新查询才使用新账户。
本体仍为普通随从目标、SPELL 伤害 6 和印刷吸血。

雷电崩鸣 TTN_831 使用现有 PlayerSpellCountCostSpec 的有限新增 profile
`cost.player-turn-nature-cast-count-v1`。原完整 CAST 前缀及显式原报价回合确定数量：
同一实际全局回合、本人、印刷自然、已开始且未失败的每次施法均计数，包括真实自动/重复施法；
被反制及无合法目标等失败尝试不计。付款前不追认本牌未来的施法。
新事实的回合必须等于 IntrinsicCostStageFact 原接受边界；后续施法和回合不重写旧付款。
旧全局/邪能/神圣/不同学派政策保留，旧政策必须没有新回合过滤字段。
本体仍为所有敌方活跃角色的普通 SPELL 伤害批次，每个目标基础伤害 3。

充能召唤 SW_035 直接查询既有 played_cards 原始物理出牌账本。
过载牌分类从完整固定 23,452 行数据提取全部 98 份正向 OVERLOAD 原行，逐行保留完整字段和摘要，
且注册时与整份原始源重新核对；不是从已实现定义、职业、当前来源池或过载通知倒推的名单。
仅印刷相关词而没有实际 OVERLOAD 标签的变音和弦/充能召唤不因此成为过载牌。
被反制的真实过载牌仍是出牌；自动/重复施法、普通召唤及水晶数量不增加物理使用次数。
已使用原始身份在固定源中未知时显式报错，不能默认为非过载牌。
发现费用为 `min(10, 1 + 过载牌实际使用次数)`，查询完整当前可收集随从域并直接交付战场，
保持原 SummonCause、候选身份、容量、正常入场和玩家选择。

## 数据、保存与边界

新增两种价格均沿原报价、外部费用、支付、生成 DTO、合法行动、回滚和恢复管线。
现有事实新增有限可空标量；旧价格政策使用空值，新政策严格验证类型和来源窗口。
core822/schema642 拒旧 schema1～641；不增加 Effect 或载荷类型，不改其他旧卡定义。
这些本地原接受事实及可复核账本不提供未签名存档的来源认证。

相关回归复现了原有的随从入场校验错误：物理出牌已提交，但在提交反应中等待选择，
恢复后当前动作编号增加，入场事件仍属于同一次原物理出牌。原校验错误地要求两个动作号相等。
仅将此项改为入场事件不得早于原提交；原 play_id、来源、玩家、目标、原驻留、重复接受和
入场结果的校验继续保持。修改前五个实际依赖引擎模块按原 Git 内容加载后也复现相同失败；
诊断在托管 runner 内进行，不能作当前源码验收。修复后相关范围全部重新执行。

三份新完整根、四份既有依赖和十四官方双语面分别核验；原萨满 71 项名单、顺序、权重保持。
98 个分类记录是印刷属性证据，并非新增可生成池，也不声称对应 98 张效果全部完成。
本批不绑定仍未完成的萨满完整来源，不据执行能力裁减候选。

和固定完整卡面；变音和弦 6 伤害依据
[官方26.0.4更新](https://news.blizzard.com/en-us/article/23935323)。

不冒称国服实测证明。
当前过载的待锁/已锁资格、成功施法窗口、被反制过载牌的物理使用资格和来源相对发现范围
仍作为明确本地政策登记；版本/热修与国服边缘校准继续暂缓。
