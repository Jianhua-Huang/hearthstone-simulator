# 过去卡池：属性、当前种族与青玉接入

本批接入固定37.0原始资料中的维拉努斯、弗瑞兹·光巢、艾雅·黑掌、塞拉赞恩及巨型图腾埃索尔。完整源行、双语官网响应、原732张参考清单和既有四张青玉模板保存在 `data/cards/past-stat-tribe-jade-v1.json`；不调整参考池成员或生成权重。数据与实现登记不表示MIS_701整源、正式国服合法池或规则校准已经完成。

维拉努斯只将敌方当前存活、可交互的场上随从生命设为1，委托原捕获引用与属性设值效果。弗瑞兹捕获本方牌库中每个当前龙随从实体，分别授予费用-2，复用普通费用层的零下限。塞拉赞恩的真实亡语捕获本方手牌和牌库当前元素随从，以当时攻击与最大生命分别追加相同数值；已有属性和费用保留，后续再次执行按更新后的数值翻倍。埃索尔的本人回合结束效果复用三区域种族增益，排除物理来源本身；另一张同名牌仍是可匹配对象。种族均采用现有current规则，包括all及显式移除，不以印刷种族覆盖当前改变。

艾雅的付费战吼与真正亡语各调用一次既有青玉成长。自然死亡采用原死亡位置，战吼沿用来源右侧；控制变化后的新亡语属于新控制者，已接受召唤仍属于原玩家。成长、复制、复活、沉默、四模板选择及尺寸上限沿用既有青玉契约，见 [青玉基础](m3-jade.md)。

真实青玉来源现在携带原始 `SummonCause`，将本次尺寸通过有限的 `JadeEntryMaterial` 交给原召唤数量执行器。每次原始请求创建一条成长记录并绑定唯一召唤根；数量额外实体共用该次尺寸，不再增加成长。下一次战吼或亡语重新接受成长与数量计划；满场尝试仍增加成长，实际额外实体遵循原容量、位置与数量计划。尺寸在普通入场通知之前写入固有基础。额外实体不调用候选战吼，青玉的现有复制/复活不会触发成长。

成长记录只追加可空的原召唤根ID。材料必须与完整原成长记录的玩家、来源、时钟、模板族、版本及尺寸相符，且不能挪用另一根；第一次实际交付与原实体记录保持对应。私有收据和挂起帧使用同一类型解码与来源验证。原无cause实验入口在没有数量源时保持旧语义，遇数量源显式拒绝，避免悄悄漏召。五个既有原生青玉适配点只补原cause，不改卡面、池或其他主体。

数量额外青玉采用同尺寸、每原请求只成长一次，是明确的本地规则；未取得该交互的国服实测证据。规则边缘与版本对齐本轮暂缓，不等待用户测试。艾雅官网的动态显示只在精确完整原行及精确locale声明下选取两段等价正文；不允许吞掉战吼、亡语或其他规则。埃索尔原行缺少ATK时，仅依两份完整官网主面明确的0攻击补零，原行保持不变。

实际专项、受影响检查、源码保全和当前下一项只登记在 [项目状态](project-status.md) 与 [机制台账](mechanism-backlog.md)。阶段及发布的集中全量义务保留。
