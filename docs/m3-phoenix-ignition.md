# 点燃手牌与成功弃牌后的基础复制

毁焚火凤 `CATA_EVENT_001` 的完整原行、附魔提示行及两份完整官方主面固定在 `data/cards/destructive-phoenix-v1.json`。本体为4费5/5术士随从；提示附魔只作证据，不注册为可执行卡。此处是有限内部契约，正式国服支持仍需M0/M6验证。

卡牌行为只构造本人当前手牌的真实选择。原手牌卡面、玩家、实体与区域周期由 `CardReference` 保存；已有未关闭的 `discard_copy` 期限若仍匹配同一驻留，不再进入候选。无候选时不创建假选项、不随机、不登记空点燃。重复战吼逐次构造新的未点燃候选。选择和支付仍走原解释器。

公共 `ScheduleHandRemoval` 增加有限退役模式 `discard_copy`，只接受一个显式原手牌引用和一个真实随从来源。原 `HandDeadlineRecord` 保存来源当时卡面，接受后的来源死亡、变形或离场不修改该配方。没有新状态字段、平行期限列表或卡牌专用计数器；已有 `remove` 和 `destroy` 模式保持。

时钟复用原实际本人结束记录：接受时尚未发布的当回合结束计第一次，第三次实际本人结束到期。对手结束和跳过的调度机会不计，真实额外本人回合计一次。结束反应中接受的根按原时钟从后续结束计数。到期时原引用不再匹配则记录空结果，不能追踪重新入手、转交或变形后的新驻留。

到期使用真实 `DiscardCard`，不是摧毁或非死亡移除。只有成功弃掉原牌，才在普通弃牌反应和本牌弃牌主体之后执行私有 `SummonHandDeadlineCopy`。该继续项核原根、原结束、原目标步骤及实际 `DiscardRecord`，然后交给普通 `Summon`；不重放战吼。满场仍成功弃牌，普通召唤失败；弃牌导致终局则停止后续复制。多个原根保留各自原接受和实际处理顺序。

当前复制采用**原接受来源卡面的基础新实体**，不读取来源后来属性或带入原附魔。它依据原作者关于基础版本的实际报告；同帖对于存活来源是否应保留附魔仍有争议，没有开发者裁定。此项及精确变形/转交、附魔继承和结算顺序明确保留M6，不把这项本地政策称为已确认的完整官方复制规则。

原期限的逐张进度复用于实际弃牌；私有复制接受收据另核原成功弃牌、完整基础配方、分配位置及容量。已关闭步骤须匹配实际普通召唤历史或满场失败；等待中的原弃牌、成功续接与召唤工作不能被裁剪、换根或重复。选择、完整动作失败回滚、独立恢复、回放和玩家信息边界继续共用已有管线。收据校验不提供未签名存档的来源认证。

期限及复制收据不进入玩家事件；只沿原手牌槽展示剩余次数，对手手牌仍使用原未知信息投影。没有新观察字段、命令或回放版本。本次内核574、schema468、实验内容preview-v399；旧schema不能静默读成缺少新继续项的状态。
