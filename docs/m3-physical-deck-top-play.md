# 原牌库顶顺序执行

欧恩哈拉的真实结束主体只返回`PlayTopDeckCards(player_id, source_id, SummonCause.capture(context), 3)`。卡牌层不直接移动实体、扣费、施法或执行战吼。原`EndTurnSpec()`决定自然本人结束的接受范围；同一分类主体仍可被原主动结束能力来源调用，不靠回调里硬判事件名限制入口。

每次请求读取执行时本人的实际`deck[0]`，完成其主体和反应后再处理下一次。剩余次数和原归属保存在既有解释器的不可变续接中，不新增GameState账本或另一套出牌器。空牌库直接结束，不抽牌、不疲劳、不取RNG；请求受原解释步数预算限制。逐次读当前顶、精确满场行为和特殊来源仍保留国服校准，不能从正文“顶三张”认证全部复杂窗口。

## 五类实际载体

- 随从：原`SummonStoredCard`，带同一原`SummonCause`，复用物理第一体、已接受额外复制材料、巨型/入场、数量和反应管线。保留区域附魔，不执行手牌战吼或其他出牌主体。
- 法术：原`CastStoredSpell`绑定原`CardReference`，保留真实强化及原DECK来源，沿既有自动目标/随机选择、施法历史、失败和完成流程执行；不伪造抽牌或手牌使用。
- 武器：原`equip_entity`装备该确切实体，替换武器的死亡和亡语仍由原生命周期负责；不执行武器战吼。
- 地标：原物理实体通过公共`Resolution.move`进入BOARD，发布既有`location_placed`，不激活`on_use`。
- 英雄牌：同一`play_hero`安装原物理英雄牌，显式`origin=Zone.DECK`。普通手牌调用保留默认HAND入口；实际生命、护甲、附魔、技能与职业替换共用原实现，不另造新英雄或执行战吼。

若当前战场已满且顶牌是随从或地标，交原`Draw`把该顶牌正常抽入手牌；满手照常烧掉，原抽牌/获取及通知均保留。其他类型仍可处理，后续每次重新判断实际容量。不会因第一张卡无法占位而反复卡住同一顶牌，也不把场上所有类型都当随从召唤。

自动处理不产生手动`PlayRecord`、不支付法力、不消费下一张普通出牌费用修改器。法术仍产生真正的`SpellCastRecord`，随从仍走真正的召唤/入场事实。实体ID和区域版本只按原物理移动改变一次，不经过临时HAND或新白板复制。未知类型/非物理选择面明确失败，不静默丢卡。

## 续接与信息

已开始主体的后续次数归属原玩家，来源死亡或转控不会改成对手牌库。新召唤的结束主体不追加入已经接受的同一自然结束窗口；原结束重复来源可接受另一次完整三次处理。终局沿原解释器中断后续工作。这里不为任意跨机制组合新建旁路。

`FrameCodec`对新请求校验严格整数、原玩家/发起者与`SummonCause`的一致性，并在保存/恢复时核对真实来源分配和时钟。构造阶段拒绝未来分配，保存帧拒绝结构合法但借用其他实际实体的来源。正常等待保留完整剩余请求；未签名宿主快照不提供原始调用次数的外部来源认证。完整续接、原分配、未来牌库身份只给可信宿主，玩家继续使用原观察投影。

新增一个Effect类型，无新持久状态字段；内核534/schema429包含此请求，观察98/命令12/replay1保持。原默认代表注册表指纹不因此改变；不能从它推出跨schema存档兼容或官方完整支持。实际验证、保全、进展与下一项只在原两份台账维护。
