# 原随从与对手手牌交换

狂乱报警机JAIL_502在当前控制者的回合开始时，调用有限`SwapWithOpponentHand`。原战场驻留、原造成来源及玩家必须一致；死亡、离场或已变形的旧引用不能交换。只从当前对手手牌中的实际随从实体抽选，同名实体各占一个权重；没有候选时不回手、不揭示、不消耗随机。

## 来源与入场

[完整来源](../data/cards/alarm-hand-swap-v1.json)保留37.0原本体及JAIL_502e证据行。本体原数据缺省ATK，以既有逐卡printed-zero声明核对完整双语官网主面明确的整数0；执行为3费0/3中立稀有机械。JAIL_502e的旧减费文字只作证据，没有据前缀添加减费效果。

公共入口把选中的原CardReference及出场的MinionReference交给既有物理召唤。`SummonStoredCard.swap_minion`和`RecruitEntryMaterial.swap_minion`只表达一次有限交换：原随从离开产生一个战场位置，被选中的手牌离开产生一个手牌位置；两处原占位均可使用，不会因满场或满手误判失败。新随从放在原位置，原物理owner保持，controller变为接收者。没有一次手牌出牌、战吼、磁力融合或星舰发射。

交换先提交两实体的完整区域分配再发布普通通知。出场的报警机转入对手手牌，以原定义重置伤害、增益、冻结和费用层，记录新的return获取；入场原牌保留当前手牌材料。回手通知及召唤反应均观察完整分配。现有属性刷新、连续来源、死亡检查、等待、失败回滚、恢复和回放仍由公共执行器负责。

## 原召唤与额外实体

召唤数量在原接受窗捕获，第一体移动选中的原牌，额外体使用原不可变材料创建，只有第一体返回原报警机；额外体不再交换或重新抽选，容量逐次按普通召唤检查。巨型沿原肢节展开，磁力和星舰部件仅保留其印刷/当前能力。`CopyEntryMaterial.stored_components`仅为stored_copy/current保存真实组件，实际回手星舰及额外体保留完整组合；这一字段不开放其他复制模式的组件继承。

恢复严格解码新字段、原来源/手牌/玩家和召唤材料，玩家接口不暴露随机候选及内部载荷。core540/schema435拒绝旧1～434，观察99、命令12、回放1保持。未签名存档不提供历史来源认证。

物理等权抽样、单候选随机消耗、原占位/回手重置及额外实体政策、回手与肢节/召唤通知的精确顺序仍待国服校准；完整主面证明卡面数据，不能证明这些内部时序。实际进展、验证和下一项仅在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护，正式池、国服校准与全部实际可达内容仍独立验收。
