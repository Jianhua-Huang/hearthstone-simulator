# 可用法术的纯资格查询与临时交付

`GeneratePlayableTemporarySpell` 为 JAIL_986 的真实需求提供一个有限入口：从完整的可收藏法术池选取一张在接受时可手动使用的法术，并通过普通 `CreateTemporaryCard` 创建本回合临时牌。不把剩余法力当作完整资格，也不通过 `Game.apply`、试打或真实实体分配来查询。

`entity_materialization.create_entity` 是原 `Resolution.create_entity` 的共享实现；原执行器委托它，查询只在独立深拷贝状态上使用。查询副本保留当前英雄、当前回合与实际行动方、手牌历史、资源、费用来源及原知识账本，按普通创建语义将候选放在手牌末尾，再附上真实 Temporary 材料。不会发出获取事件、消费一次费用、付款或推进 RNG。满手仍按假设入手查询，实际交付继续按原容量烧牌。

`hand_admission` 从原手动出牌入口提取逐卡检查及普通目标/分支枚举，`body_player_commands.independent_hand_play_actions` 提取原独立主体目标入口。真实出牌和查询共用这两条原路径。检查包括手动资格、当前禁止、武器要求、任务/奥秘/持续区域、实际费用与支付账户、抉择分支及合法目标。玩家谓词仍只接收原玩家投影。查询仅省略全局“此刻是否能提交动作”的回合/等待门禁，不伪造接受玩家的当前回合；向非行动方交付时仍保留真实行动方。

完整普通候选先按原生成规则解析；未知合格内容在随机前报错，不从候选池删除。新入口对每张候选检查是否至少有一个合法手动动作，然后按原整数权重抽取一次，空池无 RNG。候选数量受原结算预算限制。原仅支持临时随从的通用池包装约束保持；本入口直接组合普通池查询和既有临时卡交付，无第二套创建、支付或区域执行器。

私有 `PlayableSpellDraw` 保存原完整 `RuleContext`、知识账本、请求/池上下文及版本、完整有序带权候选、完整可用子集、所选结果与 MT19937 前后状态。恢复时重算完整原池及原资格，并局部重演抽样；之后的获取反应可以继续合法改变局面和 RNG。缓存仅保存完整输入摘要对应的可用子集，以冻结注册表对象、内核版本、原完整状态、知识、候选和规则隔离，最多64项；不信任存档自报子集。该内部一致性证明不提供未签名存档的来源认证。

接受政策为“新临时牌已假设入手、获取反应尚未执行”；获取后局面变化可以让真实牌不再可用。该精确窗口、临时牌对资格的影响和非行动方语义仍待国服校准。完整正式卡池和官方支持范围独立验收，接口存在不表示所有法术或整套正式环境已经支持。原型内核/保存版本及实际执行结果仅在两份原台账维护。
