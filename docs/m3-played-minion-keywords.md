# 原出牌随从的关键词奖励

本契约说明真实出牌监听如何复用原事实和关键词执行器。实际进度、验收证据、差异和下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。

[完整固定源](../data/cards/played-minion-keywords-v1.json)与[适配](../hs_sim/cards/played_minion_keyword_cards.py)分别表达黑市监管者的亡语随从突袭、梦缚迅猛龙的随从额外效果。原card_played事件必须对应完整、已完成的PlayRecord，玩家及物理来源匹配。效果召唤、对手出牌、法术/技能和监听者自身这次出牌不进入本地配方。亡语资格取原submitted_cost.quote.quote_input.abilities，不能按后来变形后的牌名重新判断。

原随从以本次真实动作内首条对应SuccessfulSummonRecord绑定首次实际入场，再用BoardPresenceReference辨认连续战场驻留。后续同驻留变形可以改变卡面；离场再入场不能只凭相同entity_id重新获得旧奖励。奖励主体先返回带原play_id的InvokeBehavior，真正执行时按当前局面解析原驻留，再委托GrantCapturedKeyword或GrantRandomBonusEffects。这样早于该奖励执行的其他反应也受原驻留约束，而非只检查战吼结束时的旧状态。

原监听者是奖励归因来源，原被使用牌是续接的物理来源，两者不能混淆。具名续接使用已有严格play_id/来源校验，未增加GameState字段、公共请求类型或随机算法。额外效果仍由公共模块选择完整当前可用关键词；原突袭、攻击许可、沉默、随机、健康和死亡负责实际行为。既有[额外效果契约](m4-bonus-effects.md)中的构筑政策不因这两张卡扩大为战棋规则。

磁力合并等未核实的接收形态保持显式UnsupportedDefinitionError，不任意奖励合并来源、宿主或裁掉真实候选。自身入场排除、原提交亡语资格、转化与反应的准确窗口仍需相应国服证据；配方内部验证不替代这些校准或正式标准池完整性。其他真实来源按需核实，不能从接口推演组合待办。

## 阿穆纳伊的来源独立出牌复制

[阿穆纳伊](../hs_sim/cards/ammunae_card.py)用原`AddPlayerEffect`安装整局`card_played`监听，不要求原来源仍在场。完整原始8费德鲁伊传说6/6及双语主面见[源包](../data/cards/ammunae-v1.json)。它只从完整已完成的`PlayRecord`和原提交费用输入的未消费亡语附件判定资格；普通效果召唤、法术、技能、对手使用和反制不冒充合格使用。

`played_minion`新增显式布尔`exclude_source`，默认True保留旧场上监听者的自身排除，来源独立玩家程序明确传False。原首次实际入场查询抽为`original_played_presence`，仍取原动作内对应物理来源的首次成功入场并保留既有磁力未知接收政策；原`original_recipient`继续解析同一引用并执行旧活跃/存活门槛。旧关键词及其余出牌监听消费者的默认政策不改变。

新配方直接交`CopyMinion(BoardPresenceReference, player_id, cause=SummonCause.capture(context), allow_dormant=True)`。实际执行时由原复制器重核连续驻留并读取当前完整材料，前序反应中的变形/沉默/增益可改变材料，离场再入的同ID不能冒领旧复制。原玩家是接收者，当前原对象转控不改玩家程序归属。原非定向休眠许可明确启用，仍交现有休眠复制语义，不另造活跃对象或基础替身。

复制归因使用原实际来源与普通召唤原因，数量增幅、完整当前材料、独立附件、场位/满场失败、额外交付、死亡及反应全部共用原管线。来源死亡/变形/转控不取消实例；多个独立实例各执行自己的复制。复制属于召唤，不产生新的付费出牌或复制体战吼，不递归领取同一出牌奖励。已使用的牌只支付一次，复制没有额外牌费。

普通接受/当前材料、原动作首次入场关联、休眠、来源卡面/归因、当前生命与默认放置位置均沿上述既有本地政策，精确国服窗口仍待M6，不能将这些内部场景认证为全部正式交互。共享查询对未核定的磁力合并接收形态继续显式报unsupported；当前拟议1322根没有原生MAGNETIC，其他生成可达性留M0确认，不将狂野专属组合列为本轮门槛。

本项没有修改战斗内核、状态布局、公共执行指令、协议或schema；core630/schema518和默认代表快照保持，构筑内容标识随新适配推进为v462。旧内容指纹的存档仍须匹配其原注册表，不能由版本号相同推导构筑内容可隐式迁移。实际执行、验收与下一项仅在原两份台账登记。
