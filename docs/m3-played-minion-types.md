# 原提交随从类型与群山之灵

`TLC_229`群山之灵的固定原行及严格双语主面要求使用六个不同类型的随从，奖励沿既有完整`TLC_229t14`阿沙隆定义。实际执行、测试与下一项仅在原两份台账维护；本契约不把内部计数政策当成国服实测。

## 原始材料与纯查询

`submitted_minion_types(record)`读取原`PlayRecord.played_face.metadata`及`submitted_cost.quote.quote_input.enchantments`，按原有序种族附魔应用`normalized/apply_change`。原付款者、物理实体、卡面和类型必须逐项一致。后来的变形、沉默、死亡、转控或回手不重写旧提交；同实体再次使用是另一个出牌发生。未知资格明确失败，已知无类型返回空集合，不能把未知当作无类型。

`played_minion_type_facts(state, player_id, exclude_ids=..., completed=True)`提供原玩家的冻结出牌编号及`TribeState`。它复用现有物理手牌提交账本，不扫描宿主事件、不创建影子出牌、不消耗RNG，也不把普通召唤、复制、复生或生成一个实体当成另一张使用。未使用的种族附魔和原完整支付材料仍由原公共管线保存及验证。

## 一个发生最多匹配一种类型

`match_minion_type_plays(facts, types)`要求调用者提供完整、固定且不含ALL的类型集合。群山之灵使用已核对客户端种族映射中的十二种构筑类型，包括德莱尼；不从当前已接入的卡牌样本推断全集。ALL及其排除由原`TribeState`解释，未知全集外类型拒绝。

一个物理出牌发生最多贡献一种类型，一种类型最多匹配一个发生。当前内部政策使用最大二分匹配；后一个单类型随从可让此前双类型随从改配另一类型，避免贪心选择因遍历顺序少计。多张ALL也逐张最多计一，已知无类型不贡献。官网卡面能证明目标为六张随从，不能独立证明最大匹配、ALL、动态类型或反制的精确国服政策；这些仍待M6。

## 原任务边界与执行时重核

`QuestProgress.completed_before`捕获本次任务启用时已经完成的物理出牌编号tuple。完成前已提交、但在启用后才发布完成事件的发生仍可被后续原监听者看到；已经完成的旧发生不追溯计入。重复任务的新周期、任务线新阶段和显式重置使用各自的新完成前缀；原实例、阶段及完成守卫继续沿既有任务器。

`AdvanceQuestFromPlayedTypes`在原Effect执行窗口读取当前完整已完成提交，排除任务原开始库存，重新匹配后仅把与现有进度的正差委托原`AdvanceQuest`。不在回调捕获时计算一个后来可能过时的增量；嵌套反应已推进的进度不会再按旧值相加。原奖励继续普通`AddToHand`及完整阿沙隆定义，满手、待选择、失败回滚、终局及阶段退休沿原任务管线。

当前查询的输入域是既有物理手牌提交账本；有独立`GeneratedActivationReceipt`的自动全卡执行不会伪造`PlayRecord`。各真实间接来源是否计入此类任务、历史“使用过”的范围、反制后完成、任务启用/完成窗口及多类型分配仍需按来源补证和M6校准，不能以本批查询证明所有自动起源完整。

## 保存与玩家边界

schema372要求显式新字段并拒旧371及更早，core455保护这项新执行语义。没有新的GameState、Entity或Player字段、玩家计数器、Effect私有历史账本或显式payload类型；只扩展原嵌套任务进度、增加一个薄Effect及纯查询。原完成库存须严格有序、唯一且确实对应已完成记录，JSON和帧都按原严格编解码保存。

观察92、命令12及replay1保持。玩家只看原公开任务进度及奖励，不获得原完整提交、付款附件、私有开始库存或匹配材料。结构校验及哈希保护内部一致性，不认证未签名存档的外部来源。
