# 已使用任务事实与条件目标

任务助理（TLC_987）需要判断本人本局是否使用过任务。当前任务槽和墓地不能回答：任务可能已完成、移除或被反制，也可能仅被弃掉。条件使用既有完整提交账本，不新增可变历史计数器。

`quests_from_plays(records, registry)` 只匹配原提交的SPELL及其不可变 `played_face.card_id` 所指向的原生 `QuestSpec`。原玩家、记录范围由调用方提供；四种既有原生任务类型都计入是明确本地匹配政策，待国服校准。任务线推进及重复任务奖励不新增手牌提交。被反制的已提交根计入，未使用/非法尝试/生成/弃牌及效果施放不计入；实际效果施放任务仍可建立任务槽，不因此成为手牌使用。

`Information.observe` 只在viewer本人行提供非负整数 `quests_played_total`，对方行不含该字段。原目标输入解码要求完整、精确整数及不超过手牌使用总数，拒绝缺失、布尔值和对方字段；真实付款证明重投影原完整状态，关闭的独立付款证明则与原 `prior` 提交前缀比较。即使重算外层摘要，合法格式的虚假计数仍会被拒绝。它不提供未签名存档的来源认证。

任务助理以已有纯DTO玩家条件声明 `IF_AVAILABLE` 的敌方随从目标；正向时存在合格目标必须选择，否则无目标。正文复用相同历史投影和普通3点 `MINION_ABILITY` 伤害。普通召唤不触发战吼，间接战吼按实际载体控制者和原公共目标执行器运行，也可在非其回合使用自己的viewer行。没有自定义目标、伤害、任务或回放执行器。

观察版本90、内核423及schema342对应新增原观察字段，旧存档由旧引擎读取；命令12/replay1保持。旧模型、效果/载荷字段、默认代表注册表指纹保持，默认完整快照的information仅版本号变化。精确国服任务家族匹配、条件与执行窗口以及正式标准池仍须独立闭合。实际验收、差异及下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。
