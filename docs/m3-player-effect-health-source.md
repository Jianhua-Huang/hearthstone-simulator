# 独立玩家伤害来源与下一次真实对手回合

本页维护表达与恢复契约；实际进度、验证和下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。完整莫格莱尼、异教低阶牧师原行与配方见[固定数据](../data/cards/player-period-effects-v1.json)。

## 玩家效果的原始健康来源

普通 `AddPlayerEffect` 保留原行为。只有明确声明 `capture_health_source=True` 的请求，在建立实例时额外保存完整 `SourceAllocationFact.payload()` 和原受益玩家 `source_player_id`。原实体、完整卡面/类型、物理归属、控制者、区域及驻留、入场顺序、分配器边界一起冻结；捕获时的顺序须与实例建立顺序相符。原卡面、受益方、物理分配与当前实例之间的结构关系在状态/帧恢复及请求执行中校验。来源后来死亡、沉默、变形、回手或转控不改写这些材料，也不迁移已建立的受益玩家。

莫格莱尼建立一个无区域容量占位的独立整局 `PlayerEffect`，使用原 `TriggerSpec('turn_ended', ..., EndTurnSpec())` 接受己方结束主体。每个实例独立捕获、执行和保留，普通召唤不执行战吼，原结束重复与选择协调不另建执行器。

`PlayerEffectDamage(player_id, instance, target_id, amount)` 携带完整原实例。它只委托原 `settle_health_batch`；健康准备层读取冻结卡面和原受益方，结果层将原驻留事实写入既有 `HealthResult` 字段。实际目标仍在主体生成时定位当前敌方英雄。健康规则、护甲、防护、死亡、历史、反应与回滚保持共享。请求只支持普通 `EFFECT` 伤害，不能冒充法术/战斗/拆分包，不继承旧随从后来获得的吸血、剧毒、潜行或法伤。这个来源政策是明确的内部契约，精确国服归属和关键词交互待校准；不据此宣称所有持续伤害来源均已穷尽。

已接受的普通请求可在实例被移除后继续完成；队列中保存原完整实例与受益方，不重新绑定当前同名实例。未捕获的来源、受益方不符、未知卡面、未来分配/驻留等明确拒绝。结构校验不提供未签名存档的外部来源认证。

## 下一次真实对手回合

异教低阶牧师向对手建立一个独立的待执行玩家实例，当前不立即抬高任何费用。它只接受受益方下一次实际 `turn_started`，随后添加当回合 `SPELL` 加1的原 `AddCostModifier` 并移除待执行实例；原回合到期流程撤销该层。不会用 `全局回合数+1` 推测未来玩家，不因其他人的额外回合或被跳过的槽位消费待执行资格。进入该对手实际回合后，新取得法术、多个法术付款和源离场都沿同一层处理；紧接的第二个额外对手回合属于新期间。

固定源的 `SCH_713e` 描述为当前回合增加费用。英文官方[36.0.1热修公告](https://us.forums.blizzard.com/en/hearthstone/t/3601-hotfix-patch/162668)明确记载将错误施加给自己的效果修正为作用于对手；这支持受影响方，不能认证本项目的额外/跳过回合、开始反应精确窗口或国服37.0实际热修状态。普通启动时，本实现先在原开始事件反应中交付税层，再继续自然抽牌；这些详细窗口仍是M6事项。

## 保存与玩家边界

`PlayerEffect` 新增的捕获字段只在全知状态/恢复帧中保存，公开 `player_effects` DTO不变。当前格式由 `serialization.SNAPSHOT_SCHEMA_VERSION` 统一声明；旧格式必须使用原引擎，没有静默迁移。状态、重复/数量/拆分贡献中的嵌套玩家实例共用同一严格解码函数，保存不得把完整原事实降为当前来源ID。健康结果继续沿原字段和玩家事件白名单投影；新字段不进入玩家接口。

格式常量也用于现有测试的“当前格式”断言及可执行示例元信息，旧格式拒绝输入和历史证据保持原样。格式边界检查不替代机制与阶段整体验收。正式标准池、完整可达内容、国服热修集合与官方语义校准仍需各自证据。
