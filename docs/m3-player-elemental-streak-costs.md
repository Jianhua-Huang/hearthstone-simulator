# 连续本人回合元素数量费用

实际验证结果与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。本页定义独立数量输入及费用契约；内部时序政策仍待国服校准。

`CardDefinition.player_elemental_streak_cost=PlayerElementalStreakCostSpec()`声明有限 profile `cost.player-consecutive-elemental-turns-v1`，只用于普通可从手牌打出的随从。数量来自已有[完整本人回合印刷类型关系](m3-owner-turn-type-history.md)，按原冻结提交卡面匹配 `MINION/ELEMENTAL`，金额为原 base 减去连续数量，最低零。声明不接收任意谓词、其他种族、任意运算或额外授予，也不与另一固有数量公式或原 bool 固有费用同时声明。

## 本人区间与报价窗口

每个真正存在的本人回合区间最多计一次；同回合打出多个元素不会多计。向后读取本人区间：最后一个尚未关闭且没有元素提交的本人区间暂不终止此前连续段；跳过这一个开放区间后，遇到已关闭且没有匹配提交的本人区间便停止。开放区间已有匹配提交时，该区间计入连续段。没有本人区间或没有连续匹配时数量为零。

这项开放空区间政策是待校准的内部选择。[官方艾泽里特巨人卡库](https://hearthstone.blizzard.com/en-us/cards/100234-azerite-giant/)确认连续回合减费需求及中立、史诗、元素身份，没有给出全部开始/自然结束/提交细窗口的国服证据。不能把本政策或内部恢复验证称为官方时序认证。

本人序号和前驱取原实际回合记录，额外同玩家开始各是一个区间，跳过机会不制造空区间；场景首区间保持其 `scenario` 来源，构筑开局前不造回合。真实开始尚未发布事件、自然结束正在结算、开始中断与已关闭状态保持原字段，不用全局回合奇偶代替本人时钟。

报价发生在本牌提交之前。本次已接受报价不会把本牌自己的未来提交算入原数量；本牌接受后产生的冻结提交卡面可以影响后续报价。费用始终使用报价玩家的历史，牌何时获取、来自哪位玩家或当前载体经历过什么变化不改变历史归属。

## 完整依据与原事实复用

`PlayerElementalStreakCostFact`保存原 spec、payer、turn/action、实体分配上界、完整 `OwnerTurnQueryBoundaryFact`、两位玩家完整有序 `OwnerTurnRecord` 元组、所有类型/玩家的原物理提交行、匹配区间 ID、quantity 及 before/after。保留空区间、非匹配行、其他玩家行、开局前和非行动方内部提交；这些记录不能因不影响当时金额而删除。

提交行复用已有 `PlayerPlayedClassCostRow` 的通用物理事实结构：原 `FrozenPlayedFaceFact`、turn/action、hand_entry_id/turn。该结构名称来自早期类别费用消费者，本模块不使用其职业筛选或数量规则。捕获复用原 `_rows` 验证实体、手牌获取身份和原支付收据。行不嵌入历史 `PlayRecord` 或以前的费用收据，避免新报价递归保存旧报价。

全历史关系收集器、原历史结构检查及原区间进展前缀检查由 `owner_turns` 原代码提取后共享。公共 `validate_history` 仍严格要求真正 `GameState`；保存事实通过私有只读元数据投影使用同一检查，不创建虚假世界状态或第二套回合规则。原最近已结束本人回合接口与其未知范围保持。

种族按原提交时的印刷卡面；后续变形、控制转移、死亡不重分类。原 `all` 与非空已知种族对称匹配，已知空不匹配。全部本人区间候选先执行原谓词校验，较早断段之前的未知种族也明确报错。其他玩家及本人在非本人区间的未知卡面保留；这些记录不被误当成本人元素。召唤、生成和自动 CAST不伪造手牌提交。

## 接受证明、恢复与信息边界

原完整报价窗口重新捕获全部依据，要求与已保存事实相等；不能用同金额的更短前缀冒充实际捕获。保留历史验证要求原完整物理行前缀相等，并复用原区间单调进展规则，允许后来合法发布、自然结束和关闭；更晚主体合法增加历史不重算旧报价。unsigned 存档的原来源认证仍不由这一紧凑检查单独提供。

费用叶在公共固有费用阶段应用，随后沿原局部/外部费用、支付、出牌、待选和回放管线处理。没有新费用执行器、提交执行器、回合推进、事件、动作、State/Player/Entity 字段或可变连续缓存。异常事务、真正回溯、独立注册表恢复及玩家投影继续使用原管线。`consecutive_elemental_turn_count`仅提供全知引擎的有限只读数量；冻结依据不交给玩家观察或命令。
