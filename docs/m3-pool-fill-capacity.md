# 按实际容量填充随机随从

真实不败冠军与末世的姆诺兹多使用 `FillBoardFromPool`，把实际受益玩家、完整查询和原随从归因交给现有带归因池召唤批次；没有新的召唤执行器或 GameState 计数器。

接受窗口在此前入场反应完成后。`PoolFillCapacity` 保存规则实际容量与当时全部有序物理占位，地标和休眠也占位。原数量等于实际空位，完整候选照常检查并抽选，后续逐项沿原召唤、数量、位置、死亡及等待管线执行。后来释放空位不增加原尝试次数，后来占位由原执行器跳过；满场保存零数量根且不取随机数。未知合格内容即使满场也明确报错，不能裁掉生成候选。

容量、占位分配、归属与数量关系进入保存和事件证明，原恢复、回滚、回溯及回放共同验证；当前和关闭根的容量必须等于实际规则。玩家 DTO 不公开这些内部材料。原定量召唤默认不带容量声明，其行为保持。

姆诺兹多沿原种族查询纳入全种族，填场后从当前英雄最大生命生成完整治疗，再交原跳过本人回合效果；其名字不能代替原印刷种族资料。完整治疗保留过量治疗及已有治疗转换规则。

这里只接实际非施法随从来源、可收藏随从池、有放回填场。现有复合候选入场限制仍明确报错，不据此认证完整标准生成池。接受/抽选窗口、后续场面变化、治疗及跳过回合的精确国服时序待 M6 校准。实际进度与验收只记在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)。
