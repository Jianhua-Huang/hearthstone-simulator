# 随机填手与原生成费用

遗忘纪元TIME_615要求用随机亡灵填满当前玩家的手牌，并使这些牌仅在本回合消耗生命值。卡牌行为不读取规则对象，也不把默认十张当作固定上限；完整原行和双语主卡面固定在[配方](../data/cards/native-pool-hand-fill-v1.json)。

`FillHandFromPool(request)`只包装一个原`GenerateFromPool`的合法单张规格，实际数量完全由填手入口确定。请求须有物理来源、完整可收藏随从查询、放回抽样及普通手牌交付；现有普通费用声明可随请求保存。额外召唤、临时/数值/分裂材料等非本请求形状仍拒绝，不扩张组合矩阵。

执行时调用原`hand_capacity(player, rules)`，同时考虑当前规则默认值和玩家覆盖值，按当前持有数量捕获一次空位。随后同步委托原`generate_from_pool`，完整资格、未知内容报错、整数权重、整组随机冻结、普通创建、附件、溢出与事件均沿原管线。空位为零也不跳过完整候选校验；空池或零数量不消费随机。超出预算沿原限制报错。

尚未执行的填手请求如果因普通选择等待，恢复后才按执行窗口计算容量；已经抽样的批次不因后续扩容、缩容或手牌移区重新补抽。后续入手仍按每次交付时的原容量规则，可能溢出。此处沿用固定卡填手和普通生成批次的本地政策，精确国服窗口仍需M6校准。

真实卡使用亡灵/all元数据资格，并将原`CostSpec(payment=HEALTH)`及当前实际回合的到期值交给普通生成请求。只有实际创建的物理卡拥有局部费用附件，既有同名卡不变；原支付、当前/基础复制、区域生命周期和到期清理保持原实现。未知合格内容不会因未接卡或满手被删去。

只增加一个Effect，无既有材料字段、payload类型、GameState/Entity/Ability字段或第二执行器。嵌套请求使用原typed codec、费用及玩家边界验证，私有请求与随机不进入玩家DTO。版本、实际验证、差异和下一项仅在两份主台账维护。
