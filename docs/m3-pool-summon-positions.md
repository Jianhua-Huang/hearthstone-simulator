# 原死亡位置与随机池召唤

P34源审发现，随机池适配器没有转交原死亡位置。实际擎天雷龙位于两个随从之间时，选中随从被追加到最右侧。固定名字召唤已有明确位置能力；这里补齐随机池到同一执行器的连接，没有另建位置或死亡结算器。

`SummonFromPool.position`转交原`SummonByCard.position`；`GenerateFromPool.board_position`只允许带原因的场上交付，独立于原牌库插入位置。`PoolSummonBatchSpec.position`保存原批次起点，后续原根按此前实际交付数量累计偏移，数量额外体继续使用既有单根位置顺序。父子请求必须保留相同来源、材料与对应位置，恢复校验拒绝改写子请求位置。

已接入的斯尼德的伐木机、腐化杂种犬、擎天雷龙分别在真实亡语接受时读取原`DeathRecord.position`。活体效果触发亡语时使用该载体右侧的位置；两者均从原生亡语上下文取得，不能猜墓地实体序号或取当前最右侧。后续召唤仍沿共享容量、随机、额外数量及死亡/获取反应管线。

当前位置政策以原接受标量及前根实际交付为依据，沿既有执行器的插入与钳制规则；反应改变邻位、同时死亡和复杂重复顺序的精确国服校准仍开放，不因这次修复宣称全部位置时序已认证。实际P34最终验收与本次验证在原两份台账记录。
