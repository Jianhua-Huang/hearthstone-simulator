# 原生随从边位关键词光环

实际执行、验证结果和下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。本契约描述BE_230拉维兹所需的有限表达，不能据此认证完整标准池或国服交互。

## 两个独立原生声明

复用`KeywordAuraSpec`既有字段，新增两个严格的target值：

```python
KeywordAuraSpec(Keyword.RUSH, 'friendly_leftmost_minion', include_self=True)
KeywordAuraSpec(Keyword.IMMUNE_WHILE_ATTACKING, 'friendly_rightmost_minion', include_self=True)
```

左侧范围只接受Rush，右侧只接受Immune while attacking。两者必须显式包含自身，condition为always；不同时声明相邻、种族或卡牌身份过滤。只允许普通原生随从的印刷声明，复用既有原生光环附件、沉默移除、完整声明核验和非融合载体要求。动态GrantKeywordAura、有限期限、消耗态、不可沉默或冒充别的原卡声明均拒绝；不扩展为任意位置与关键词的组合目录。

声明本身不表示来源持续拥有这两个关键词。它们分别选择当时友方的最左、最右随从；只有来源自己处于相应边位时才可能同时受益。关键词贡献位于既有aura_keywords集合，不添加永久附魔或印刷关键词，也不改写随从基础属性。

## 当前边位与生命周期

`keyword_auras.refresh_keyword_auras`沿原刷新窗口读取实际控制者的有序战场。先保留随从顺序，再选第一个或最后一个：地标、构筑中的星舰和可交互物件不占该随从索引。真正休眠的随从保留其位置，随后按原active接收条件不获得关键词，不能因此跳到第二个活动随从。临死场面和检查点继续采用原光环刷新政策；这些精确国服窗口仍待校准。

入场位置、召唤、离场、死亡、变形和控制权变化后的选择继续由同一刷新机制完成，不另存边位、目标引用或第二份光环状态。失去来源时撤回贡献；多个来源以普通并集合并。沉默接收者不移除仍存在的外部贡献，沉默或休眠来源则按原规则停止贡献。源的当前/基础复制保留相应原生声明；接收者复制不把光环贡献烘焙为固有能力。

攻击期间免疫继续交给原`IMMUNE_WHILE_ATTACKING`及原战斗作用域。该标记不会令随从在普通法术伤害或防守时免疫，也不允许Rush在入场回合攻击英雄。攻击声明后进入等待，后来失去光环或被新随从挤离右侧时，后续原伤害窗口按实际当前贡献计算，不冻结已经失效的免疫。
