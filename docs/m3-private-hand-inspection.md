# 私密手牌检视与后续条件

上古预言师JAIL_303检视三张敌方手牌，探员摩洛克·福尔摩斯JAIL_851指认时检视四张。二者只共用有限`InspectHandCards`：按当前物理手牌抽样，私下展示给选择者，保存原卡引用、获取ID及必要来源材料；不生成、抽取或转移牌，也不冒充一次发现。

## 来源与范围

[完整数据](../data/cards/private-hand-inspection-v1.json)保留两根、原幸运币及三个附魔证据的完整记录，并核对双语官网主面；幸运币的既有完整定义固定核验。三个XML附魔只作来源证据，原生记忆和玩家程序表达其实际行为，不把附魔卡当可出牌内容注册。

[独家揭示](https://www.invenglobal.com/articles/22833/exclusive-june-hearthstone-card-reveal)说明指认看四张、对手不知道所选牌、奖励不要求福尔摩斯继续留场。官方[36.0.1热修](https://us.forums.blizzard.com/en/hearthstone/t/3601-hotfix-patch/162668)明确排除在自己的回合触发奖励。两份完整HTML与字节收据保留于本批来源目录；它们不能替代固定37.0国服对局校准。上古预言师本体当前双语文本为弃牌，旧附魔文本的“摧毁”不覆盖本体及真实弃牌管线。

## 公共检视

原实体不按同名卡折叠，每张实体各有一次候选权重；最多抽取请求数量，不足时显示全部现有实体，空手不消耗RNG。超过实际选择预算明确报错，不静默缩减规则数量。只有被展示的牌加入选择者的既有知识；原实体、获取ID和来源上下文留在内部选项材料，玩家接口继续使用o编号。选择结果保留原接受材料，不在后续重新随机或改选同名牌。

当前以物理实体无放回抽样、执行时实际手牌及原普通通知窗口为本地政策，重复同名候选和精确窗口待M6。CardReference与HandEntryRecord分别承担当时卡面/驻留引用和稳定的入手身份，二者不能混作同名检索。

## 原生亡语选择

有限`NativeDeathrattleSpec('hand_selection')`沿已有DeathrattleMemory保存hand_entry_ids。检视前捕获原来源驻留及原生能力ID；选择后只有来源仍属该驻留且目标仍属原手牌获取时才写入记忆。普通当前复制保留记忆，基础创建、回手重置、沉默及变形沿原生命周期；来源转控不把已选择的目标改成另一位玩家的手牌。

真正亡语只读已经接受的DeathrattleCapture材料。DiscardRememberedHand核对该活动亡语与原获取ID，确认目标仍在同一获取身份后，以当前卡面委托原DiscardCard；真实弃牌历史、弃牌触发、区域、死亡、回滚和恢复仍由已有内核负责。选中牌在原手牌内变形仍关联，离手再回或转入另一手牌的新获取不重绑。重复战吼暂按顺序追加选择，重复同一原牌不会把已离手的牌再弃一次；该继承/重复/驻留政策待国服校准。

## 独立按名奖励

有限HandInvestigation保存选择时的卡面、原手牌获取、原对手和下一个真实对手回合序号，挂在原PlayerEffect上，不另造时钟或全局历史。程序与原受益玩家绑定；本体死亡、沉默、回手、变形或后续控制权均不取消或转移已经安装的程序。

原card_played事件连接完整PlayRecord，按冻结卡面的注册名称匹配，允许另一实体或同名另一ID触发。只在保存的对手真实回合内匹配，自己的回合不匹配；下一对手回合结束时原程序消费退役。首次匹配用ConsumePlayerEffect消费原完整实例，再按原AddToHand交付三张幸运币；并行接受的后续反应不能再从已消费实例重复发奖，多个独立指认实例各自结算。手牌容量和溢出沿普通交付。

一次奖励、名称别名口径、被跳过的预定回合是否应消耗窗口、反制/自动使用和精确通知位置继续保留M6；当前回合依据既有实际开始记录，不能以全局单双数替代。

## 保存与信息

新数据只扩展现有原生记忆和玩家程序，未增加GameState账本。私密选中牌与回合索引不输出到玩家DTO，公开程序仍用原固定来源与通用kind字符串描述。恢复核对类型、原获取、打印声明和活动亡语载荷；未签名存档不提供原始选择来源认证。

core539/schema434识别三种有限Effect及HandInvestigation载荷，拒绝旧1～433；观察99、命令12和回放1保持。实际进度、验证、已知差异和下一项仅在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护，M0正式池、M6国服和全部可达内容继续开放。
