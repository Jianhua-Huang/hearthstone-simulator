# 翼手龙蛋的原交付与全体生命偷取

`TLC_831`是3费0/3亡语随从：召唤原3/3幼年翼手龙，后者从所有其他随从处各偷1点生命。完整原行、四个严格双语主面、真实父子关联和原`TLC_831t`定义pin保存在[来源包](../data/cards/native-pterrordax-egg-v1.json)。原始attack空值仅按显式零值声明处理。实际验收和下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。

## 原具名交付

父牌亡语只声明普通`SummonByCard`和`SummonEntryMaterial(TLC_831t, on_summon=...)`。接收者从原`original_named_reference`取得，不搜同名随从或最近分配ID。既有幼年翼手龙仍是完整3/3白板，不为父牌的后续效果添加永久战吼/亡语；直接从手牌使用它不会偷生命。

实际入场及反应结束后，具名续接绑定原连续`BoardPresenceReference`。死亡、休眠、转控、离场重入导致原接收者失效时跳过，不将能力交给同名或同ID新驻留；同一驻留内变成另一随从卡面仍由现有原交付政策接收。每个数量额外体完成自己的入场及偷取后，才推进下一交付；不同亡语调用各有原请求与接收者。

亡语召唤的归因仍是原蛋。偷取时，属性事件和普通附件的来源明确是实际偷取的原翼手龙自身；不能把正在杀蛋的玩家或其他来源当受益者。此来源归属、入场后窗口及连续变形政策仍待M6校准。

## 全体原子转移

`StealHealthFromOtherMinions(player_id, beneficiary, amount, source_id)`只接受原`BoardPresenceReference`和原接收玩家，source必须等于该实际随从ID。它不放宽旧`StealHealthToMinion`的敌方捐献者限制，也不改变旧英雄最大生命预算。

执行时读取双方完整BOARD，核当前卡面/区域/控制者，排除受益者本身、休眠、死亡/待死亡及非随从。友方、敌方、潜行、免疫和圣盾随从都不能按手选目标保护被裁掉；这是非目标属性变化。未知实际内容明确报错。普通已存活捐献者的原扣减量先一起固定，再通过原`_buff_to(notify=False)`安装全部扣减和受益者总增加，刷新一次光环后发布普通属性事件。

首次通知已经观察到全部提交，不让前一捐献者的反应改写后一笔已接受量。保留原已受伤害和普通可沉默附件生命周期；生命归零继续原死亡管线，不制造伤害、治疗、吸血、生命支付包或消耗圣盾。无捐献者或零量不分配属性附件/RNG。来源合法性仍先核对，零量不掩盖不存在的源。

所有原记录、继续工作、选择恢复、异常回滚、终局中断与回溯退休继续沿原公共框架。没有新的GameState/Entity/Player字段、显式payload类型或另一套死亡/召唤循环。只新增一个Effect；schema368拒旧1～367，core451，旧执行身份存档须原引擎。原具名收据、附件游标和完整宿主frame不进入玩家DTO。

## 仍需核验

当前量采用请求与当前剩余生命的较小值，普通捐献顺序为玩家1/玩家2各自场上顺序，全部提交后依次发布捐献者和受益者通知。原1点效果、全体批次、负生命与光环、来源归属及精确入场/死亡窗口仍为内部政策，未作国服认证。完整正式池、所有标准可达内容、M0/M6和阶段发布不能由本卡的内部通过代替。
