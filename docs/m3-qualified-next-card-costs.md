# 下一张指定牌的费用与本人真实开始禁疗

本页维护表达、保存和边界契约；实际进度、验证与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。五张真实卡的完整原行和配方见[固定数据](../data/cards/qualified-next-effects-v1.json)，实现见[卡牌适配](../hs_sim/cards/qualified_next_cards.py)。

## 费用资格复用原付款管线

`AddCostModifier`及其持久`CostModifier`增加三个有限字段：`combo_only`、`temporary_only`、`maximum_cost`。前两项及既有种族筛选分别独立使用，不为任意组合扩展接口。连击和临时筛选要求有限用途；完整价格上限只允许带种族限制、有限用途的纯生命支付转换，不参与数值变化，避免用自身改变的价格循环判断自身资格。已有随从种族筛选允许减费、固定价格及上述生命支付。

- 狐人老千：当前物理牌的有效、未消费连击能力决定结构资格，不要求这次连击已激活；新生成候选按完整印刷定义判断。减2与当回合到期、实际付款消费仍由原公共层负责。
- 洞穴专家：临时资格来自该物理手牌的`HandLifetime`，同名普通手牌不匹配。整组换手的租约不自动成为临时关键词，未取得实际临时期限的假想生成卡也不匹配。未使用减费没有额外回合期限。
- 提克迪奥斯：本回合下一张当前恶魔随从设为0。英雄免疫是原生持续关键词光环，由当前来源的沉默、控制和离场生命周期管理；战吼已经交付的减费有自己的期限。
- 速逝鱼人：下一张当前鱼人随从的完整当前价格不超过3时改为生命支付。先用全部数值层及原手牌最低费用求完整金额，再判上限，保留有序贡献和原支付/用途收据。后续减费、加税都影响资格；0费仍消费一次用途，免疫不免除生命支付。

物理报价的`CostQuoteInput`保存完整原`HandLifetime`，并校验原最低费用；手牌离开HAND后的已接受法术报价继续带原期限和下限，不借当前区域重造临时资格。匹配、生成报价、付款证明及恢复校验共用这些材料，预览不消费用途。未知卡面或种族信息仍明确报错。

当前种族依据、完整价格阈值和各数值层的精确排序是明确的本地规则政策，须以对应国服证据校准；完整原行的文字不能单独证明全部交互窗口。

## 禁疗到本人下一次真实开始

`GrantHealthRule(..., until_owner_turn_start=player_id)`只支持英雄载体，并与全局回合到期互斥。它复用`OwnerTurnExpiry`和原真实owner时钟，将期限保存在健康规则附件的`health_rule_expiry`；不新建回合账本或健康执行器。

环形山鳄鱼给当前敌方英雄安装目标侧`HEALING/PREVENT`规则，原期限绑定施放者。来源死亡不结束已交付的规则；英雄替换沿原附件复制保留原期限。其他玩家的额外回合、跳过的本人槽位不触发到期；本人紧接的额外真实开始会到期。到期在开始事件及反应接受前统一移除，治疗、防护、吸血结果、等待恢复和回滚继续走公共层。精确国服开始反应政策待校准。

## 保存、玩家接口与演示

当前格式由`serialization.SNAPSHOT_SCHEMA_VERSION`声明；新增嵌套期限和报价材料使用严格解码，旧格式需原引擎读取，不静默迁移。原观察、玩家命令和回放外层协议保持，完整期限、报价操作数和恢复帧不得进入玩家DTO。

`python -B -X utf8 -m examples.card_qualified_next`通过玩家命令演示五张适配及各稳定位置的独立恢复、clone和回放。洞穴专家场景使用一个显式标为“非正式卡牌”的临时牌生产夹具，生成真实雪人；夹具不进入生产注册表或正式池，不冒充已实现的真实生产卡。正式标准池、完整可达内容和国服官方校准仍须分别闭合。


## 阿迦玛甘的有界对手生命支付

真实战吼返回`AddCostModifier(player_id, CostSpec(payment=PaymentType.OPPONENT_HEALTH), uses_remaining=1, source_id=..., maximum_cost=10)`。复用既有玩家费用附件及原分配/用途账本，不为这张卡新增可变计数器或付款执行器。此有限声明要求实际来源、有限用途、普通五类卡牌、明确非负上限，且只改变账户；不能附带数值操作或假装是无来源的印刷生命费用。普通召唤不发起战吼，来源后来死亡/转控不改变原修改器玩家。

先由共享价格层完成当前费用，再决定是否能支付。对手生命账户的`maximum_cost`是使用上限：超过时仍保留原账户与来源，由`payment_error`明确拒绝出牌；不回退到法力，不把11点截为10点，也不在预览时消费来源。既有本人随从种族/生命费用的资格阈值政策保持。零费牌也是下一张实际使用的牌，会消费接受的原用途；英雄技能不匹配五类普通牌。多项原来源的消费、先后覆盖及重复战吼按现有价格/用途契约执行，精确国服层序仍待校准。

`payment_projection.payment_plan`使用原报价玩家消费费用附件，以其当前对手的实际英雄为扣血账户，沿共享`HealthLossKind.PAYMENT`和生命变化记账投影结算。对手支付不经过护甲或伤害包，也不采用本人支付的生命必须富余限制，允许致死；最终生命损失替换仍以被扣除的真实英雄为目标。原`opponent_health_spent`事件的player_id为出牌玩家，原生命过渡/记录的玩家为对手；恢复校验必须核对二者相反，不能把实际扣血者改成出牌者。后续等待、回滚、支付证明、完整回放继续共用原管线。没有新GameState字段或Effect类型。

[完整固定源](../data/cards/agamaggan-health-payment-v1.json)保留根卡及两个原始腐蚀棘刺附魔，附魔仅作证据。官网主面支持完整正文及10点文字上限；[低生命实测报告](https://us.forums.blizzard.com/en/hearthstone/t/agamaggan-can-pay-more-life-than-you-have/145088)记录了6生命支付9费后成为-3，[护甲/上限讨论](https://us.forums.blizzard.com/en/hearthstone/t/why-cant-agamaggan-cast-the-ceaseless-expansion/157570)支持区分生命损失与伤害。报告/社区规则不是暴雪正式国服认证；超过10费无法使用、零费消费、致死和各精确接受窗仍分别保留M6核对，不能以正文或内部测试关闭校准。

公开报价增加`payment='opponent_health'`，公开支出事件沿原过滤器，只给玩家应见的类型、金额和归属。完整费用附件、上限声明、支付证明及英雄过渡不进入玩家DTO。观察98、内核533/schema428包含新枚举与事件形状，旧格式需原引擎；实际验收及下一项仅在原两份台账维护。


## 下一张亡语随从的原支付与附带死亡

TID_078碎冰蹒跚者增加`deathrattle_only`结构选择器及`destroy_after_play`有限随从后续声明，保存在AddCostModifier与CostModifier。前者使用原手牌CostQuoteInput中的有效未消费亡语能力，生成候选按印刷定义判断；不把提及“亡语”的卡面文字当作自身亡语。它与已有种族/连击/临时选择器互斥，需要有来源的有限普通随从用途。附带死亡只允许一次该类减费，不与无来源或其他付款声明拼成任意组合。

实际报价、最低费用、付款与CostUseReceipt仍是唯一用途消费来源。零费也消费，预览/召唤不消费；来源后来沉默、死亡或转控不撤销已交付的玩家修改器。多份原来源可共同减费并分别消费，但不为同一原随从复制死亡流程。成功物理手牌入场时捕获原SourceAllocationFact，DestroyPaidMinion由原支付中完整声明产生；原付款来源和载荷必须在对应收据中逐项相等。

当前内部时序为完整原战吼/连击及召唤完成后、FinishPlay及card_played之前，委托普通Destroy/死亡检查。目标按原board_presence绑定，原地变形或转控保留同一驻留，回手后重入场则是新驻留；副本也不是原目标。反制、入场满场失败和磁力贴合沿原分支消费已付价格，不能制造新的随从死亡或改杀磁力宿主。支付时未带亡语、后来主体才获得亡语及其他自动/效果真实出牌上下文仍需独立核查，不能据本入口宣称完整覆盖。

付费死亡可能接受真实等待。原FinishBattlecryAcceptance及FinishComboAcceptance在完整主体已结束后，按同一实际出牌的唯一死亡后续延后关闭；仍保留原证明对象、顺序和既有完整性校验，不删证明、不伪造再次接受。原外层提交证明保留其最后关闭顺序。巨型的延后主体也沿此规则；终局、回溯及失败恢复共享旧解释器。FrameCodec为新工作显式检查付款、原在场材料和分配边界，拒绝未来材料及来源篡改。没有新State/Entity/Player字段、死亡/付款账本或显式载荷类型；现有两个费用载体各增加上述两个字段，core715/schema574拒旧1～573。
