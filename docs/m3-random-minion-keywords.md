# 随机原随从与指定关键词

当前Core齿轮光锤的战吼须随机选择一个友方随从，并向同一个原接收者授予圣盾与嘲讽。[完整来源包](../data/cards/random-minion-keywords-v1.json)保存当前Core原行及旧GVG身份依据，旧卡只作证据，不重复注册根卡。

`RandomGrantMinionKeywords` 只新增有限随机入口，接收不可变且按物理实体唯一的 `MinionReference` 候选和指定关键词。目前仅允许圣盾、嘲讽的非空唯一有序元组，不是随机额外效果池，也不执行任意回调。未知来源、未知/未来分配、错误原卡类型和超预算库存明确报错。

执行时复核原驻留、控制者、卡面、活跃、存活与待死亡资格，按实体ID排序，用公共随机流抽一次。空池不消耗随机；已经具有这些关键词的随从仍保留正常物理权重，不按“是否有收益”裁池。

选中后返回原有 `GrantCapturedKeyword`，两次授予共享同一原引用。授予间的普通反应可以移动、转控或重入来源，后续只复核原驻留，不再抽选、不改投新实体，也不将同ID回场当原随从。实际关键词、沉默、复制、到期、通知与死亡仍归公共执行器。

卡牌从实际战吼窗捕获完整友方在场候选，普通装备/支付/战吼归原管线。直接装备不触发战吼。没有新增模型状态字段或引用payload；新effect明确进入注册执行身份，core381/schema304拒绝旧1～303引擎存档，观察87/命令12/replay1结构保持。

候选接受窗、圣盾后嘲讽的通知顺序、单元素池随机消耗及精确国服行为仍是内部政策，待M6。实际结果、已知差异及下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)登记。
