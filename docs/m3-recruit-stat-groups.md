# 原攻击档招募组与一次属性奖励

`RecruitAttackGroupForStats`仅表达真实战吼所需的0、1、2攻击档三次物理招募。卡牌提交完整原`RuleContext`，引擎绑定实际原战吼、施益玩家、原来源连续在场身份和接受窗；内部继续项保持完整原请求及接受状态。每次原招募开始前保存确切producer ID，`SummonFromZone.stat_group_id`同时进入原请求/原生收据。嵌套招募可以占用其他ID，不因同来源、同外部动作或相同战吼原因被混为一组。

每个档位独立重新查询当前牌库攻击力，空池/满场仍保留该原请求，不消耗无意义随机。选择、原实体移动、额外数量、巨型附肢、休眠、反应、死亡及支付继续由原执行器负责。候选门禁允许已支持的物理巨型入场，其他原不支持内容仍明确报错；不能删除未知合格候选。这里只连接原招募根、原CardSummon子根、实际主交付及原成功入场事实，附肢和嵌套召唤不是主交付。

本次适配明确采用**内部待校准政策**：依0/1/2顺序逐次完成，每个实际主交付（包含原数量额外体）贡献其原成功发布时的攻击与非负剩余生命；巨型附肢不贡献。三次请求全部完成后合计，交给一次普通`BuffCapturedMinion`。入场后被杀、变形、转控或加属性不会倒改已冻结的操作数。来源连续驻留可跟随当前脸和控制权；离场或同ID再入场不能得到旧奖励，来源离场不取消剩余招募。休眠/存活等施益门禁继续沿用原在场属性执行器。原成功事实同时保留最大生命，但本profile不使用它。

上述顺序、发布时点、剩余/最大生命、额外主交付和来源政策仍需M6国服证据核定。卡面文本本身没有证明这些细节，内部验证不能代替正式规则校准；其他获得属性卡不能默认套用本profile。

接受、逐档、奖励及结束收据均为私有。保存边界核完整原生链接、全部实际操作数及唯一剩余继续项，并与原付费选择证明中的实际工作逐项比较。恢复不能删除、重复或换借继续项，不能删除组收据却保留引用它的原生招募；闭合收据继续对齐原子根/交付和属性事实。失败事务、选择恢复、clone和replay复用原解释器；终局允许原流程中断未完成组。一致性证明不认证未签名保存的外部来源。
