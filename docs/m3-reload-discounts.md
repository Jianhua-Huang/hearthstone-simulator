# 重新装填：发现、实际减费与溢出续接

BE_555完整原行及双语官网主面固定在[data/cards/reload-v1.json](../data/cards/reload-v1.json)。原8费猎人奥术法术先发现一张法术并减费8，再以溢出减费量重复。当前适配复用普通当前职业、可收集、非中立法术发现域；正式合法域、禁限和国服精确交互仍属M0/M6。

## 单一发现执行器

`DiscoverFromPool(..., cost=CostSpec(delta=-remaining), excess_discount=True)`是原发现请求的有限新范围。只允许有来源、三个选项、一次普通手牌发现、每次交付、允许后轮再次发现同名牌；不能附加另一类发现配方或用固定轮数近似预算。旧默认False及固定discoveries次数不变。

每轮沿原完整候选、随机抽样、OriginalDiscoveryOffer、ChoiceResult、生成成本安装、物理创建和语义发现完成执行。只有真正执行选中分支时，才调用原`capture_generated_quote_fact`分别接受不带本次减费及带本次减费的完整报价。没有假实体、假入手或额外RNG，不消费报价中的一次性费用政策；手动和自动施法都使用这一普通来源。

`DiscoveryDiscountStep`保留原预算和两份生成报价。预算消费量为`min(remaining, max(0, before.amount - after.amount))`；后轮预算是精确差值，不按印刷费用直接扣数，也不把外部费用层忽略。两份报价绑定同一对象、基础输入、原固有阶段及接受窗口；局部和外部规则各自保留原操作事实。费用光环或其他真实反应随后改变时，过去的预算不重算，下一次实际选择按新局面报价。

源减费仍是原CostSpec，在创建/获取通知前安装到新实体，经过原满手、复制、区域和后续付款机制。零费用或实际没有减费的选择不消费预算、不被裁去，也不伪造“至少扣一点”；重复直到预算用完、候选为空或真实终局。工程上限仍明确报错并回滚，不成为游戏规则中的提前结束。满手沿原烧牌，选中报价和续接仍保持；该窗口待国服校准。

## 生成报价与原生数字

普通生成报价继续取已声明印刷基础与原固有/外部阶段。对已注册RemainingManaNumbersProfile的真实法术，GeneratedCostQuoteInput额外保存原`mana_numbers`，基础数字沿既有`max(1, mana)`政策；只读真实受益者接受时的法力。验证器要求该声明、牌型、原数字和基础值一致，不允许普通牌借用此依据。最低1继承既有本地政策，仍未认证新法术零法力的国服行为。

这同时保证真实投身战争被发现时不会只按印刷1费扣预算。初始费用、固有历史、一次性政策、资源种类和真正入手后的数字继续走公共费用/生命周期，不能用报价生产虚假实体或消费付款用途。

## 保存与原续接义务

原始菜单私有标记`_excess_discount`由实际配方派生；选择提交前没有预算消费。选择反应暂停时，挂起的是原ResolvePoolDiscovery，仍未接受报价；实际接受后，原ContinuePoolDiscovery保存全部已提交选择和报价，预算为零时结束，空池则保存实际类别/来源的空域依据。

私有接受及结束事件绑定完整有序进度、原菜单、原选择、预算和报价窗口。验证器拒绝丢失全部预算见证后绕过快速检查，拒重复/裁剪续接、同一父预算分叉成多次菜单、篡改原费用或提前结束；可以处于已提交选择但尚未计算报价的合法等待窗。旧普通菜单不携带新标记。验证是当前存档内部一致性，不提供未签名存档的外部来源认证。

选择/获取等待、异常回滚、真实施法重复及回放使用原解释器。玩家只看到原发现、牌面、费用和结果，私有报价、预算依据、原完整配方与结算帧不进入玩家观察或日志。
