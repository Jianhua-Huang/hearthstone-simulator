# 真实出牌成长与随机手牌困住

雷弗拉尔`EDR_526`的完整原行、基数1、必要附魔及配方见[固定数据](../data/cards/renferal-native-traps-v1.json)，主体见[适配](../hs_sim/cards/renferal_native_cards.py)。实际进度、证据与下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。

## 出牌次数与战吼次数

卡牌主体从原`PlayRecord`读取当前玩家已经完成的本卡MINION出牌，排除该战吼所属的当前出牌ID，再加印刷基数1。第一、第二次实际打出分别计划1、2张；不同物理副本共用同一玩家的已冻结出牌历史。重复战吼不会制造额外出牌，直接召唤和其他玩家的出牌不提升本方次数。没有另设可变计数器、按存活实体扫描或用触发次数代替出牌。

数量在原战吼调用状态接受；目标手牌候选在实际困住请求执行时读取。后续效果来源可以已离场，但必须仍是原存在分配。当前仅是明确的本地成长接受政策，反制、终局中断和特殊历史来源的精确国服口径仍须对应校准。

## 私有随机生产者

`hs_sim.engine.hand_play_locks.TrapRandomHandCards(player_id, count, source_id)`解决真实卡牌需要的随机多牌选择；不扩展为任意筛选、区域或授予组合。参数要求明确玩家、正整数数量与原存在来源；带`origin_state`的FrameCodec也拒绝未知来源，空手牌不能掩盖非法请求。

候选是目标玩家执行时的完整物理手牌。同名牌分别有一个权重，同一批不重复抽取；已被困住的牌仍是后续批次候选，因此不同批次可能重叠。数量小于候选数时无放回抽样；数量达到候选数时按原物理顺序取全部，空池与取全部不额外消耗随机数。抽样只决定集合，标记按原槽位顺序安装。

选中后同步逐张委托既有`LockHandCard`，没有新的禁用算法、选择对话框或中途反应窗口。使用已有零数值`HandPlayLock`标记和原引用，保存、复制与移区政策继续由原附件和生命周期处理。候选、选中身份及工作请求均属于宿主；生产者不发布暴露隐藏卡面的随机选择事件。

## 一段实际目标回合

困住在目标当前正在进行的回合内生效时，到其下一次实际开始失效；在另一玩家回合内生效时，覆盖目标接下来的一整段实际回合，到目标再下一次实际开始失效。分别使用既有`owner_starts=1/2`，而非全局回合数加一。其他玩家回合和未实际开始的跳过回合不能代替目标时钟。

实际禁止出牌仍由原`play_error`及合法动作/提交校验执行；标记到期后沿旧政策保留为惰性材料。该精确窗口、已困住候选是否应排除、满池是否取随机数及特殊手牌动作均尚未国服逐项认证，不能把本地内部测试当作官方证明。
