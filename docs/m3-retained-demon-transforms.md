# 阿莱纳希的手牌数值保留变形

EDR_493的完整原始记录和中英主面固定5费5/5恶魔猎手传说随从，种族同时为野兽与恶魔；战吼将本人手牌随从变为随机恶魔并保留原属性和费用。实际进度与验收只在原两份台账维护。正式标准生成成员及精确国服数值/时序基准仍是M0/M6项目。

## 原材料和局部数值政策

卡牌层在实际战吼主体接受时，按本人原手牌顺序捕获每个MINION的原CardReference。数字使用已有 `enchantment_stats` 的有序局部攻击/生命和 `local_cost` 的局部费用，属性按原非负数值政策保存；不把最终费用报价或外部持续加成烘焙进保留值。普通法术、武器、之后新加入的牌不补入原集合。每次新的真实战吼主体重新捕获。

这是明确的内部解释：原局部附魔数值计入，旧能力、支付账户和其他附魔不继承。目的恶魔安装自己的原生能力和支付声明，外部持续规则按新卡正常重算。准确印刷/局部/条件数值依据、跨项接受窗口及特殊保留交互未据卡面文字认证为国服实测。

## 共用完整随机池和变形器

原 `TransformStoredFromPool` 末尾增加成对可选 `retained_stats: SummonStats` 与 `retained_cost: int`，默认均None，旧通用请求保持。新声明只接有来源的原手牌随从、完整两项属性和非负费用，查询须明确为可收藏随从；不能混入不完整属性、布尔费用、牌库引用或非随从原体。

阿莱纳希查询为任意职业的可收藏恶魔，不限制原费用档，也不额外排除来源自身。既有完整候选查询在RNG之前检查全部合格定义和实际目的面；未知内容明确失败，不删除候选或用同费用恶魔替代。每个仍有效的原对象沿原整数抽样接受一次，旧引用过期跳过且不抽样；真实空池保留原skip政策和空抽样收据。没有把当前注册表自动变成正式池。

原 `transform_stored_entity` 继续负责唯一的物理重置；先使用已有保费 `attach_cost(CostSpec(set_to=...))`，再沿普通Enchantment安装局部属性设值，完成后才进行原持续重算、隐藏卡面及变形通知。没有创建新实体、改变原槽位/获取记录，或执行新卡战吼/召唤。原附件清除和区域修订保持，通常回手和基础复制重置数值，当前复制沿原附件层保留并分配新ID。

## 保存、恢复和玩家边界

原抽样收据保存完整请求，因此原接收者、冻结数字、完整有序候选/权重、结果、RNG和唯一变形事件一同进入原验证。尚未执行项在原等待帧中保留原引用和数字，已执行项不重复抽样或重置；后来的合法反应继续沿原解释器。异常由原事务回滚。未签名外部历史不提供来源真实性认证。

没有新Effect、payload类型、状态字段、费用账户、随机算法或变形执行器。core474/schema391保护新增请求形状，拒旧390及更早；视图94、命令12、回放外层1保持。内部抽样/数字请求不向对方投影，公开过的原手牌身份按普通变形重新隐藏。


## 偷贩炼金师：只保留费用的法术变形

JAIL_313使用普通RequestChoice，在战吼主体的当前本人手牌中逐实体报价并保存原CardReference、当前费用报价和局部附件费用。来源已在场，不会选到自己；随从、法术、武器、地标及英雄牌都保留，同名不同实体不合并。选项内部材料沿原私有选择保存，玩家获得既有不透明选项ID；普通效果选择不计发现。

实际选择后才查询完整宿主constructed.cards域：任意职业、可收藏、费用档等于原当前报价+5的法术。所选原对象已离手、转交、换面或重入时不重绑；此检查先于创建实际池请求。正常空档沿原skip与空抽样记录，不消耗RNG；未知合格定义或缺宿主池明确报错并保留原待选事务，不裁候选或临时推断注册表为正式池。

TransformStoredFromPool沿用原字段，新增的有限形状只允许有来源的HAND引用、明确可收藏SPELL查询及非负整数retained_cost，retained_stats必须None。原随从属性/费用成对保留限制保持，不能借此给随从目的面单独保费或将半套属性混入法术。原transform_stored_entity已能只安装费用，本次直接复用，确保首次变形通知前已完成原重置和费用附件；不创建新实体，不施法、抽牌、召唤或获取。

当前内部数值政策为原当前报价决定+5目的档、原局部费用用于保留；外部持续规则对新法术正常重算，原支付币种/能力不继承。两个数字在原菜单接受时冻结，选择反应中的后改不重报价。跨类型持续费用修正、准确“原始费用”依据、选择/变形窗口仍待国服校准，不能据内部测试认证官方行为。

没有新Effect、payload、状态字段或保存字段。core490保护新增请求语义，schema404布局保持；旧core489的同schema存档仍不能作为当前机制版本恢复。视图94、命令12及replay1保持；原请求、数字、完整抽样池和RNG不进入玩家投影。M0正式池、M6国服及完整可达内容仍由原两份台账单独维护。
