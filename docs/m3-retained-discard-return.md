# 原被弃材料的成长和回手

已施放法术的物理归还使用独立ReturnSpentSpell，原分配绑定GRAVEYARD且按本地归还政策重置定义后交普通获取/溢出流程。它不使用DiscardRecord，不修改本页萨瓦丝成长保留入口；时钟、源引用和待校准项见[原材料契约](m3-original-material-spells.md)。

基础目标只补已有区域机制不能表达的原材料保留需求。`UNG_836`的必要实验主体为“本牌成功被弃后+2/+2，再回到手牌”，不增加组合机制、任意授予或新的执行器。当前实际结果和下一项只记录在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。

## 原事实和物理引用

`DiscardRecord`仍是成功HAND→GRAVEYARD迁移后提交的不可变事实。新的材料使用该事实，不把任意墓地区域开放给`CardReference`。`BuffStoredCard.card`可以接原记录；`ReturnToHand.discard`为可选原记录，未设置时仍走原战场回手及重置流程。

材料要求普通可手动出牌的随从，原记录必须等于其状态中对应的成功弃牌行。执行时要求物理实体、原owner、受影响controller、卡面、类型、GRAVEYARD及原HAND epoch+1全部一致。已真实离开该获取轮次的材料按原跳过事件处理；伪造/借用记录明确拒绝，不静默当作空牌。

原生主体的`RuleContext.discard`仍按[本牌被弃主体契约](m3-own-discard-bodies.md)捕获，不新增原接受窗口。原事实不随以后回手、再弃、复制或其他牌的弃牌改变；同一实体重新获取后可形成新的独立成功弃牌记录。此接口不把历史行当作外部存档来源认证。

## 成长及交付

原`BuffStoredCard`数值附魔执行器处理+2/+2。原材料入口只支持普通攻击/生命数值，拒绝费用、期限和别的来源身份；本实验声明使用本牌作为附魔来源。保留原本地属性、附件及同一物理实体，避免以创建印刷新牌代替成长。

随后复用原物理迁移、手牌获取及刷新流程，将实体交付给成功被弃时的受影响玩家；原owner与controller不同仍分别保留。新手牌获取有新的entry和epoch，清除属于旧获取的`hand_lifetime`，手牌进度按原获取入口重置或更新，其余适用本地附件不通过战场回手重置。普通后续出牌保留适用成长，普通战场回手和沉默仍走既有生命周期。

手牌已满时保留已发生的弃牌及数值成长，实体留在墓地；以新的epoch终结这次失败交付，发出原`card_burned`，不形成新获取，也不能再次使用旧材料回手。该容量/保留政策为本地契约，待国服校准。

新入口不支持`to_owner`、回手费用、其他卡类型、复合实体或任意墓地取回。复制被弃材料尚未接入；`TRL_252`只保留下一项的原始需求，不能以两次`AddToHand`声称其当前属性复制已完成。

## 等待、回放和玩家边界

主体只返回原效果，继续使用原解释器、选择、事务和回放。等待帧中的新材料由共享遍历核对；在`RuleContext`内部使用其原捕获状态，外部效果使用当前状态，允许合法等待期间发生的其他弃牌而不要求材料永远是最后一行。

独立`FrameCodec`只负责类型编解码；带状态的Game等待边界才核对材料与实际历史，不能声称单独编码提供来源认证。原生上下文、全知状态、材料身份及内部epoch不进入玩家观察或命令。选择失败或后续主体异常沿用原事务回滚，不另造一次弃牌、支付、出牌、施放、抽牌或死亡。

新增`ReturnToHand`私有字段及材料语义使用schema196，拒绝旧1～195；规则`prototype-v208`、效果`core-effects-v202`。观察74、命令11、外层replay1及生产代表包不因此扩充。没有新模块、Effect类型、GameState/Entity/Player字段、历史账本、玩法事件、动作或执行器。
