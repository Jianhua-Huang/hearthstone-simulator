# 符文分组发现与原随从奖励

洞见之子 BE_298 使用 `ChooseFromPools.rune_recipient` 的有限形状：同一版本池按鲜血、冰霜、邪恶顺序分别声明一个 `PoolOfferGroup`，每组一个选项，查询恰为可收藏及该印刷符文。来源必须是原 `MinionReference` 的实体和玩家；不接受费用变更、临时牌、可支付筛选、奥秘配对或特殊生成例外。普通旧分组菜单继续是 `EFFECT`，没有被整体改成发现。

这条真实发现沿既有纯候选查询、完整适配检查和分组抽样。所有组先准备完才使用随机数，未知合格卡或未知死亡骑士符文显式失败；空组不借别组补齐，全空不产生菜单或随机消费。同一多符文卡在独立组中可能占不同槽，槽 ID 保持区别。

非空菜单明确使用 `CARD_DISCOVERY`。原发现 offer 捕获完整分组请求、候选、预览和原牌材料；公共选择边界将真实 `ChoiceResult` 绑定到 `ResolvePoolOffer`。恢复与执行核对原提交记录、完整有序菜单、来源、选中槽及卡面，不以同名卡、最后一个选择或后来手牌反推本次结果。选择后由 `MaterializeDiscoveredCard` 执行原普通入手和发现完成通知，再用原 `GrantCapturedKeyword` 授予原随从。没有新建发现、区域、随机或关键词解释器。

奖励读取所选卡的完整印刷符文：正鲜血需求授予吸血，正冰霜授予复生，正邪恶授予突袭；同类多枚只授予该关键词一次，多种符文可以同时授予多个关键词。满手烧牌仍有真实选择并继续奖励来源。原对象死亡、变形、转控或离场使捕获引用失效时不重绑；获取反应和发现通知先于关键词奖励，是本地时序政策，仍待国服校准。

公共 `resolve_candidates` 同时落实 [26.0.4 官方系统更新](https://hearthstone.blizzard.com/en-gb/news/23935323/26-0-4-patch-notes)：印刷需求总计三枚符文的卡不进入普通发现或随机生成候选。筛选在可执行适配检查前完成，与是否已实现无关；一、两枚及混色两枚仍按查询参与。纯 `matches_metadata` 继续描述真实印刷事实，具名交付、物理原牌、构筑合法性和正常使用不借此删除卡牌。没有开放三符文生成例外；目标补丁正式资格及后续变更的完整核对仍属 M0/M6。

完整一行原数据及两份严格双语主面在 [固定源包](../data/cards/scion-insight-v1.json)，开发者多符文答复与历史系统更新依据在 [规则核查](../data/support/scion-insight-rule-audit-v1.json)。设计师明确确认多符文候选和多关键词；该答复没有确认菜单必定每种符文各一张，也没有确认跨组去重。因此当前独立三组及重叠槽政策是内部执行选择，不能写成已获官方行为验证。

新增有限请求字段和原选择绑定字段由 core646/schema532 保护，旧存档须用对应旧引擎；内容 v479，动作13、观察115、replay1保持。没有新 Effect、工作 payload、State 或玩家账户。实际进度、执行结果及下一项仅在原两份台账登记；本契约不认证完整标准支持。
