# 萨格拉斯与不可触碰的自主传送门

本契约接入固定候选快照中的TTN_960、TTN_960t、TTN_960t6和三个choice-only技能，复用已存在的TTN_960t5邪焰地狱火。两条附魔原行仅作来源证据，未注册为物理卡。九条完整原行和十四个双语官网主面保存在[来源包](../data/cards/sargeras-portal-v1.json)。完整十二泰坦参考名单、权重及排除保持，专用发掘生产绑定独立推进。实际验收和下一项仍只在原两份台账维护。

## 已有证据与明确的本地政策

[官方27.4补丁](https://news.blizzard.com/en-us/article/23999071/27-4-patch-notes)修正了敌方萨格拉斯复制品操作原敌方传送门的行为。[玩家多传送门实测](https://www.reddit.com/r/hearthstone/comments/16qmmlt/)报告，军团进攻只增强对应传送门；[另一实测及回复](https://www.reddit.com/r/hearthstone/comments/175nnlr/)记录重复战吼产生两个传送门、技能操作后一个，并讨论未触发战吼的召唤寻找已有友方传送门。这些历史资料支持区分物理门，不能认证当前国服所有窗口。

当前本地规则如下，均没有删除完整候选或等待用户实测：

- 开门在当前玩家场面末尾占一个位置，不算普通随从召唤；满场失败，不覆盖此前成功开门的绑定。
- 每次成功开门将仍是原活跃驻留的萨格拉斯绑定到新门。重复战吼只替换成功绑定，旧门继续自主工作。当前复制保留原绑定，基础复制和回手重打按原生命周期清除。
- 有显式绑定时只核这扇门仍在原友方场面，不能改找另一扇门。无绑定的萨格拉斯在技能主体执行时寻找最早的友方传送门。寻找发生在入场还是使用时、多门优先级及复活细节仍是本地窗口，不冒称官方校准。
- 没有合格传送门时，三个已知技能仍按正常泰坦规则消耗用途，主体不生效。
- 打入虚空一次非死亡移除双方其他活跃普通随从，不触发亡语、复生或尸体；休眠、地标和不可触碰物体不被当成普通活跃随从。
- 每个军团进攻单位使该物理门未来召唤的小鬼和地狱火增加2点生命并获得嘲讽，原已在场恶魔不变。每次实际召唤使用现有入场属性和关键词材料，先于召唤通知安装；满场和多次召唤交既有数量执行器。
- 已接受主体保留原玩家；原萨格拉斯离场不取消已接受开门或门的工作。控制变化与反应中的精确先后继续登记为待校准差异。

## 最小公共表达

`PassiveBoardObjectSpec(behavior_id,binding_card_id,unit_marker_id)`使用已有`CardDefinition.interactable`声明槽及`Entity.interactable_object`，没有增加每实体状态字段，也不把不可触碰物体伪装为永久休眠。静态载体只能是不可收藏0/1、零尸体MINION，附带唯一印刷本人结束触发；普通战吼、主动技能、投入、光环、额外触发或战斗属性均不允许。旧`InteractableSpec`的声明、支付和每本人回合用途保持。

`InstallPassiveObject`接原玩家、原开门卡和`MinionReference`，由普通实体分配器安装物体。成功后以普通零属性附魔`passive_object_binding.<门卡身份>`连接原萨格拉斯，`source_id`是实际门；名称中不编码实体编号或数值。只有最后一次成功开门替换这一绑定，复制、沉默、回手等继续交原附件生命周期。新物体事件不冒充`minion_summoned`。

`UpgradePassiveObject`绑定原`BoardPresenceReference`，给该门安装一个声明认可的`passive_object_unit.<附魔身份>`。一个附件表示一次真实升级，不维护新的数字缓存；源死亡后门及升级继续存在。实体、复制材料和死亡记录校验已知身份、载体及零属性形状；普通投入历史不能借被动物体伪造用途。

现有触发调度只为带不可触碰标记的载体开放`trigger`，其静态与状态校验保证唯一本人结束主体。它仍不是活跃角色；战斗、普通选择、属性、区域等资格保持原排除。门的两次具名召唤和地狱火技能复用`SummonByCard`、`SummonCause`及入场材料，打入虚空复用`RemoveFromGame`，没有卡牌层的随机、区域、死亡或时序执行器。

## 观察与保存

双方只见门的公共卡面、控制方、场位和`passive_object={upgrades:N}`。没有攻击/生命缓存、原绑定、附件、驻留或内部来源编号；不提供手牌投入动作。原玩家输入接受这一精确惰性行，和印刷声明及不可战斗的物理事实对照；当前完整输入另由实际投影比对，关闭收据的有限形状校验不提供未签名来源认证。

观察版本121，命令13及replay1保持。core783增加两个效果类型，既有结构schema611不变；旧机制签名仍要求原执行器。等待中的开门、升级、第一次召唤后的余下请求继续沿同一效果队列保存、独立注册表恢复、克隆、回放及异常回滚，不额外创建动作或重复支付。
