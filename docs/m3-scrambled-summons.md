# 费用档召唤组与属性置换

异化 `TIME_859` 为7费法师奥术法术：随机召唤十费、一费随从各一个，然后打乱其属性。完整原行、提示附魔及两个完整官方主面固定在 `data/cards/anomalize-v1.json`。提示附魔仅证据；主体只声明 `SummonAndScramble(player_id, pool_id, (10,1), SummonCause.capture(context))`。

公共入口先沿原完整生成查询核两个印刷费用档；未知合格卡在任何抽样/部分召唤前明确报错。两个原 `GenerateFromPool` 请求交原 `accept_batch`，保存各自完整候选、抽样、`SummonCause`、数量计划和原入场记录。两次抽样在入场前接受，先十费后一费档；这是当前有限时序政策，仍待国服校准。普通空位、重复数量、巨型、入场反应、失败及终局继续由原执行器负责。

私有 `ScramblePoolSummons` 绑定原请求、两个完整生产者根与原接受事件。它只从这两个根连接实际 `CardSummonDelivery` 的主实体，不从场上按卡名重找，不纳入旧随从或巨型附肢。额外数量产生的实际主体也有自己的交付位置，空间不足的失败不伪造身体；已经离开原场上驻留的交付不追踪后来新周期。

在两个原生产者完成后，冻结仍在原场上驻留的各主体当前攻击和剩余生命，每个数值占一个独立位置。普通两体就是四个数值，重复数值仍各占位置；不把总和重新分点，也不固定交换哪一对。一次均匀置换保存输入、有序下标及MT19937前后状态。空组不增加置换随机消耗，单体只置换自身两个数值；原两个卡池抽样仍遵循旧生产者的随机政策。

写入复用普通属性设置的 `_set_stats_on_entity`，原来源、局部附魔、清除伤害和通知保持；所有操作数先冻结，同一效果内完成可写主体的赋值，之后普通监听、属性额外奖励、光环刷新与死亡检查继续执行。多个值写入不因第一个身体暂时变为零生命而丢失后一个已接受目标。

当前休眠身体贡献其原数值，但沿既有普通属性设置准入不写入。此行为与一份历史玩家实测报告一致；该报告将其称为缺陷，不能据此认定当前国服仍如此。精确入场反应窗口、剩余/最大生命依据、光环层序、休眠/转控/变形及随机推进次序继续待M6。

原组接受、置换和完成是私有一致性收据。恢复核两个原生产者、实际交付、完整个体数值、局部随机重演、普通设置事件及仍存活的局部属性层；等待中不能裁去原组继续项。首次召唤后的选择、赋值后的监听等待、错误选择、整次动作回滚与终局中断复用原管线。没有新增GameState字段或第二份召唤历史，两个新Effect使用原帧编解码器。收据不能认证未签名存档的外部来源。

同批补齐普通随机生成的奇闻限制：[开发者原答复](https://www.reddit.com/r/hearthstone/comments/1nzs1hs/comment/ni4r7wp/)确认奇闻根及附带卡不能随机生成。注册真实 `FabledSpec` 时声明完整族排除；独立1188候选编译器还读取原 `FABLED` / `FABLED_PLUS` 与 `DONT_PICK_FROM_SUBSETS`，使未实现根同样获得真实资格排除。`resolve_candidates` 在执行定义检查之前应用冻结的 `fabled_generation_exclusions`，并进入注册表指纹。该限制与实现覆盖无关；未被真实规则排除的未知候选仍报错。原物理卡、具名交付和构筑族展开不经过这项普通随机查询。

完整固定候选域中，十费实际候选为9张，一费65张，均有执行定义；此前两张未实现十费根是被真实规则排除的奇闻牌。接入异化后，蔽影密探的11个职业法术候选定义检查全部通过，并实际验证了完整候选池中发现异化后正常施放的流程。[域审计](../outputs/card-integration-20261014/k295-anomalize/generation-domain-audit-01.json)不替代正式标准合法池、全部生成内容或逐卡官方校准。
