# 两个随机奥秘分别为双方施放

神秘无面者TIME_860使用既有`ChooseFromPools`，只增加有限`delivery='secret_pair'`。该模式要求一组两个候选，完整查询固定为可收藏奥秘法术、任何职业；不允许费用修改、临时手牌或支付能力过滤。默认`hand`交付保持原契约。

候选仍通过宿主原GenerationContext、版本化池、来源排除、原始牌组资格和规范身份去重确定。先验证全部合格定义与SecretSpec，再无放回抽样；未知合格卡明确失败，不按已实现范围裁池。不会依据任一方已挂奥秘、空位或法力删候选。已接入的11个候选标准根是固定37.0源的内部调查结果，不认证M0完整正式生成池。

菜单是普通EFFECT检视，不生成Discover事实。原完整候选和两项预览复用PoolOfferReceipt、原私有选择帧及其恢复检查。选定项先交原`CastSpell`为原选择玩家施放，再把另一个原抽样项交同一入口为对手施放；不重新抽样，不通过SetSecret直接安装，不伪造手牌/付款/出牌。来源死亡或转控不改写已保存的双方身份。空池无选择且不耗随机，单项池只为本人施放；这是明确的稀疏池本地政策。

每次施法继续原物理实体、施法记录、奥秘激活和反应流程。重复奥秘或区域已满使用原失败政策，余项继续执行；反应致死、异常、嵌套待选、回滚和回放也复用原解释器。私有全知快照不能给玩家：选择者可记住原两张，另一玩家只得到自己的奥秘及正常公开信息。

完整卡文及双语主面保存在[data源包](../data/cards/secret-pair-v1.json)。精确生成资格、抽样/施放次序、检视是否计发现、稀疏池及所有国服窗口仍待M6；现有收据只检查原结构和候选一致性，不认证无签名存档的来源真实性。执行版本、测试和进度只维护在原两份台账。
