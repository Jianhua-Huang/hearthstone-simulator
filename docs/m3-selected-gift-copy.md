# 发现赠礼后的同材料复制

FIR_924影焰猎豹是4费4/3术士野兽＋元素，原生战吼发现带黑暗之赐的恶魔，并获得其复制。完整原行、两份官网主卡面和十份已有赠礼原行在[数据包](../data/cards/native-gift-copy-v1.json)。候选为当前英雄职业加中立的可收藏恶魔随从，仍须完整宿主生成池；未知合格效果在随机前报错。

`DiscoverDarkGift(..., gift_copy_to_hand=True)`仅表达这一真实来源的有限续接。它沿原请求绑定宿主上下文并委托`DiscoverFromPool`，后者在原所选赠礼交付处接受两份不可变创建配方：原牌按赠礼目的区域交付，再将同一牌、同一赠礼和同一费用材料创建入手一次。赠礼不是重新抽选；`count`仍是报价数，`discoveries`仍是重新发现次数。复制不查询后来手牌、不寻找同名牌、不复制第一张经获取反应修改后的状态。

这是明确的本地预览政策`selected-gift-creation-material-before-acquisition-v1`。甜美梦境原牌置顶、复制入手，两者保留原赠礼属性；每次原获取反应独立结算，烧毁仍安装完整赠礼。创建层分配独立实体、附件和能力生命周期，原战吼来源随后离场不取消已接受续接。精确原件/复制目的区域及获取反应窗口尚待国服校准，不能据内部验证宣称整卡正式支持。

该标记必须为显式布尔值；启用时要求来源、完整赠礼库存、可收藏随从、一次普通手牌发现，不允许另附来源费用/临时/普通属性授予。原无复制请求和赠礼配方保持。普通手牌后续使用包装器不接受这种额外交付形状，避免丢弃续接语义。

中途等待保存原请求和选中材料，由原解释器继续两次创建；异常回滚、克隆、独立注册表恢复、回放及玩家投影复用原管线。未签名快照仍不提供来源认证。没有放宽物理`CopyCard`对已花费或场上材料的限制，没有新增effect/payload、状态、实体或能力字段；两类已有请求各新增一个布尔字段，内核415/schema334拒绝旧schema。

正式标准生成池、全部可达内容和国服窗口仍是独立验收。实际进度、测试结果与下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。
