# 真实洗牌操作与整局费用历史

本契约定义真实卡牌需要的整局洗牌操作记录及内在减费。实际批次、测试结果、差异和下一项仅在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)登记；本地契约不代替国服规则校准。

## 语义操作与物理区域

`hs_sim.engine.deck_shuffles.ShuffleDeckCards`保存发起玩家、接收牌库、原来源和有序原始操作，只接受随机放入DECK的`AddToDeck`、`MoveCard`、`CopyCard`与`ShuffleIntoDeck`。各项仍调用原区域处理器，消耗原结算预算；不新增区域执行器或异步调度器。一次命名洗牌可以包含多张牌，整批只有一个操作记录。普通插入反应沿原队列执行；同步原语未来若返回异步工作或选择请求，必须显式拒绝，不能丢失批次身份。

首个真正成功的随机插入发布不可变`DeckShuffleRecord`，保存原发起者、接收者、回合、动作、首事件、原实体分配、原来源及声明数量。没有实际插入的空请求和过期目标不产生信用，也不消耗随机。成功移入原手牌保留原物理ID；创建和复制仍使用原分配。多个独立效果各自接受新的洗牌操作。

`GameState.deck_shuffle_history`是唯一新增持久字段，没有另设游标计数。插入事件中的宿主私有`deck_insertion`标记关联该操作，稳定边界核对完整记录、首个真实见证、成员数量、顺序、原发起者和接收者。非随机顶/底/索引放置，以及同一牌库内已有实体的重新排序，显式标记为placement/reorder，不获得洗入信用。开局随机及换牌不伪装对局中的插入事件。

`actor_id`与接收牌库不同：向敌方牌库洗入不算敌方自己洗入。亡语由真实执行上下文归因，原所有者或最外层操作玩家不能代替当前执行者。旧卡牌配方必须显式使用`shuffled(context, entries, player_id=...)`或该效果传递原归因；不能从被动来源当前控制权猜全部历史。

## 历史报价和支付

`IntrinsicCostSpec(condition="own_deck_shuffle_count", history_profile_id="deck.shuffle.operations-game-v1", delta=-1)`只开放已核对的普通随从原生费用形状。`DeckShuffleCostMatch`捕获完整原历史前缀及所有属于实际付款玩家、接收牌库也为该玩家的操作ID，数量作为一次规则的减费乘数，再交既有费用层处理，下限0。

历史在灌林追踪者尚未生成、尚未入手时也记录。当前/基础复制和控制权转移使用实际付款玩家的既有历史，不给卡牌实体装永久减费监听。纯报价不变更状态、随机或一次用途。付款后的真实反应可以继续洗牌，但已冻结报价及历史前缀不能被后来的分配号或新操作改写；保存恢复、clone和回放复用原内在费用/支付证明。

## 已知边界

未分类的旧直接随机插入保留`actor_id=None`；临时手牌取回的随机返回目前单列`temporary_return`且不猜发起者。若报价玩家的牌库历史出现这种操作，TLC_520报价明确抛出不支持错误，不能静默当0或随意计入。这是尚未覆盖的来源边界，注册该牌不表示所有标准可达历史已经接通。精确国服批次、反应窗、发起者、临时返回和开局口径仍需对应官方行为证据。

宿主完整历史、原来源和插入标记不进入玩家DTO。玩家观察沿原事件白名单投影，不将`Event.data`或全知快照直接交给玩家。严格保存使用core350/schema277，真实旧schema276拒绝，不提供未签名存档来源认证。

完整原始卡面和配方见[固定数据](../data/cards/shuffle-native-effects-v1.json)，可执行原生入口见[示例](../examples/card_shuffle_native.py)。其他真实洗牌来源按实际需要分类，不为不存在的机制组合预设矩阵。
