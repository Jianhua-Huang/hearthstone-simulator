# 塞特斯的自身回合延迟与实际护甲转换

塞特斯 BE_557 的实际战吼仅组合已有 `GainArmor(20)` 和 `AddPlayerEffect`。每次战吼安装自己的待兑现玩家实例，来源后来死亡、沉默、变形、转控或回手不改变受益玩家；普通召唤不执行战吼。延迟使用整局玩家程序和原自身回合历史，不另设倒计时账户，也不占奥秘/定时效果栏。

原 `turn_started` 捕获该玩家实例的普通触发。主体只接受本人真正的开始发布，核对实际 `OwnerTurnRecord`、原事件及发布游标；从实例 `created_turn` 对照完整已有历史得到安装时自身开始索引。第二个后续实际本人开始才兑现，不按全局奇偶或对手回合数推算。额外本人回合算实际开始，跳过机会不算；同一边界中后来安装的新实例仍从未来开始计数。此第二次本人开始及精确相对窗口仍为待国服校准的本地政策。

兑现先交原 `ConsumePlayerEffect` 消耗精确实例，成功后才发出 `LoseArmor(amount=None, on_result=...)`。已移除的旧实例不能借同名新实例继续，重复及错开安装的来源分别保留自己的期限；同一开始内各实例依原获得顺序独立读取实际账户。没有新写删除、计时、护甲或效果循环。

`LoseArmor` 在真正执行时读取当前已安装英雄和全部护甲，原回调读取完整 `ArmorLossResult.actual`。消耗实例的反应若先增加护甲，会进入本次实际扣除；扣除通知的反应后来增加护甲，不改写已经接受的原实际量。回调仅把该实际量作为 `SummonStats(attack=actual, health=actual)`，通过原 `SummonByCard`、`SummonEntryMaterial` 和 `SummonCause` 召唤既有 BE_561t 钢铁魔像。不是20点固定奖励，也不读取清空后的余额或用伤害/支付代替护甲清空。

钢铁魔像原完整定义保持3费3/3嘲讽；新实体的实际属性由原召唤材料赋值，不改注册表。零护甲按普通0/0入场及死亡管线处理，满场仍先失去护甲再由普通召唤失败处理，不退款。这些零值、容量与反应顺序政策尚未国服校准，不能仅据文字或内部测试认定官方一致。

[固定源包](../data/cards/setesh-v1.json)保留根、已有魔像及 BE_557e2 延迟标记共三份完整原行，根与魔像四份完整双语主面严格核对。原魔像完整定义摘要固定，缺失或变化直接报错；ENCHANTMENT 标记只作证据，不伪造新的可执行类型。原两枚延迟标签支持延迟数量，不单独证明具体触发窗口。

本接法只新增真实卡牌与一个玩家声明，复用原 core647/schema533、654 Effect/256 payload 和全部状态模型；内容 v481，观察115、动作13与replay1保持。没有新增公共模块、Effect 或保存字段。原等待恢复、克隆、回放、异常回滚、实际死亡与玩家隔离继续共用；实际结果、差异及下一项仅在原两份台账登记，M0/M6/M7分别验收。
