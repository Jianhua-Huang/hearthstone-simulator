# 独立 E.T.C. 侧板基础

本文描述 U06 中原独立乐队的有限公共契约及 ETC_080 适配证据。真实构筑复制侧板使用独立[声明与开局契约](m3-deck-copy-sideboards.md)，下水道之王使用有限[私藏野兽政策](m3-contraband-sideboards.md)，不改变下述乐队字段和消费规则。完整正式禁牌/可达池和国服精确行为仍开放，不开发游客与侧板、特殊授予或其他组合矩阵。执行结果及下一项以[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)最新增量为准。

## 原始构筑与储存

`DeckSpec.sideboards` 保存不可变 `SideboardSpec(source_card_id, cards)`；主卡组长度只计算 `cards`。配置来源须在原始主卡组、已注册 `SideboardProfile`，同一来源只能有一个配置。当前 `sideboard-v1` 支持 E.T.C. 的最多三张成员政策；没有配置与显式空配置均可表达空乐队。少于三张的合法性为待国服校准的实验政策，不能仅从官方“用三张牌组建乐队”的描述认定完整最低数量规则。

每张成员都经过原构筑的明确格式名单、禁限、已实现定义、收藏/稀有度、职业和符文检查。主卡组与侧板合计按同一 `deck_identity`、普通/传说/单卡副本上限计算。原始主卡组仍决定职业资格；侧板不能另行开启游客权限。当前政策排除已有开局钩子的牌，并可声明审核过的具体禁牌 ID。未知成员或来源明确拒绝，不丢弃或当作白板。

注册声明完整进入注册表指纹；未使用侧板注册时没有新增指纹字段。声明只读、冻结后不可变。历史 25.6 公告中的特殊禁牌和当时的迦拉克隆限制不冒作最新国服完整禁牌表；特殊来源及正式池交给 M0/M6/M7。

`PlayerState.sideboards` 保存玩家自己的原始成员顺序和 `taken_slots`。原始成员不是活实体，不分配实体编号、不进入牌库或普通 `SETASIDE`，也不进入原始主卡组生成上下文。原有 `ChooseFromZone` 不能代替尚不存在的原始侧板输入或筛出只属于该乐队的成员，因此新增储存和生产入口；共享发现、选择和加手牌执行器保持。

## 普通选择与获取

`DiscoverSideboard(player_id, source_card_id, source_id)` 读取指定玩家的原始乐队；必要 E.T.C. 战吼按行动玩家提供 `player_id`。它按原始槽顺序产生现有 `RequestChoice`，每个尚未消费槽一个选项，相同卡面不会折叠两个独立槽。没有洗牌或额外抽样；空/耗尽乐队没有待选，也不消耗 RNG。

选中通过内部 `_TakeSideboardCard` 校验原始槽和卡面，先永久记录本局该槽的消费，再返回已有 `AddToHand`。新牌具有普通独立实体、归属、费用、获取及生命周期；不是抽牌，也不移动主牌库。满手按普通规则烧牌，该槽仍消费。E.T.C. 返回手牌再使用不会重建乐队。消费、重复使用、空乐队以及精确获取优先级都是本地执行政策，待国服校准。

选择可沿原解释器暂停、恢复和回放；不增加命令、观察字段或第二套发现执行器。内部消费事件仅作宿主一致性历史，不触发额外卡牌反应，也不发布给玩家。普通获取事件、选项私有性和手牌卡背沿原信息层处理：只有选择者看见成员，敌方仅见等待的玩家，宿主完整侧板/消耗记录不能发送给玩家。

## 保存与验证边界

本项首次落地布局为 schema169（拒绝 1～168），规则 `prototype-v176`、效果 `core-effects-v174`；玩家观察74/命令11/replay1保持。后续当前版本及执行结果以项目状态为准。宿主未版本化配置 JSON 可以省略空 `sideboards`，当前快照的构筑与玩家行必须显式保存该字段；不迁移旧存档。

当前状态的乐队与原构筑严格一致，原职业、符文、主卡组也与原配置绑定。消费顺序必须匹配各方内部选择历史，拒重复槽、越界、改卡面或恢复已消费槽。历史规则状态捕获也保留同一原乐队身份；真实待选的完整有序选项必须等于当时全部可用槽。该检查不认证未签名存档的外部来源。

异常只回滚失败的动作：初次选牌后的同动作错误恢复原待选、未消费槽、手牌、RNG与信息；已经合法完成选牌并在后续获取反应等待时，继续动作失败恢复该后续等待，先前合法消费保持。不会把此前付款或已成功动作一并撤销。
