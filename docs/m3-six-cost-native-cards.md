# 随机召唤依赖的原生主体与复制驻留

魔网族的随机召唤必须覆盖实际候选，不能按执行定义是否存在筛选。固定源中基线6费随从只是依赖调查入口，不能据此认证正式生成池，也没有覆盖强化后的其他费用。本契约描述其中可复用的真实卡牌主体；实际接入、验证和下一项只在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)维护。

## CopyMinion 的原战场引用

`CopyMinion.target_id`接受既有整数实体ID或原`BoardPresenceReference`。整数路径保持原语义。引用路径先验证已分配实体和非未来的驻留号，再用原`resolve_board_presence`解析；原驻留已经结束时跳过，不因同一实体回手后再次登场而重绑。

这没有新建复制执行器、材料账本或批量接受政策。每次成功解析后仍用原`accept_copy`、`CopyEntryMaterial.capture`与`SummonByCard`接受当前材料。因此前一个复制或触发分配附件，不会使后一个复制携带旧的接受时钟。现有`on_summon`仍只对实际成功交付执行。

`FrameCodec`只为这一效果的`target_id`接受该已注册引用类型，继续严格校验其他实体字段。恢复时同样拒绝未知实体或未来驻留，合法旧驻留可以恢复并在执行时跳过。公开玩家投影不接收内部引用、复制材料或待执行队列。core348/schema276；旧core快照按原机制版本守卫拒绝。

## 官方证据与待核实边界

[国服34.0公告](https://hs.blizzard.cn/news/24243857/)明确修复了奥普战吼与连击之间的随从死亡处理，因此二者之间必须存在正常死亡结算；原公告和当前卡库观察已[冻结](../outputs/card-integration-20261014/k47-official-native-observation-20261016-01/observation.json)。这项明确顺序证据不等于整族国服校准。

复活的印刷费用和不同身份口径、手牌报价窗口、最低生命并列及强制战斗、存活交换时点、延系条件和多复制的接受/转移/变形政策仍是已登记的本地执行政策，精确国服差异待对应证据校准。完整魔网族、其他候选依赖、强化后的实际召唤池、正式合法性、热修和全部动态可达内容继续保留；不能以这些主体接通宣称魔网或标准环境已经完整。
