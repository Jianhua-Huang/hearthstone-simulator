# 灵魂献祭与当前技能伤害

固定源为37.0.0.255026的JAIL_EVENT_101和JAIL_EVENT_101hp，原始完整行及四个双语官方主面保存在`data/cards/soul-sacrifice-v1.json`。英文原名为Soul Immolation。技能动态`@`仅使用P71相同原行的已有显示声明，基础伤害仍为原脚本整数2。资料核对、内部实现与国服校准分开记录。

## 卡牌表达

普通2费暗影法术在主体执行时读取本人的当前主技能。其他技能或空主槽使用原`ReplaceHeroPower`安装新的坍缩之星；当前已经是坍缩之星则使用原`GrantHealthRule`，为同一个物理技能增加一个永久伤害附件。首次安装不同时升级；后续升级不改变技能费用、物理身份、已用次数或复原状态。

P71中原技能定义和主体不变：费用1，随机对一个敌人造成基础2点HERO_POWER伤害，本人实际召唤当前种族为恶魔的随从后复原原技能。加成在普通伤害规则阶段生效，不作为法术伤害。

## 最小公共扩展

`power_damage_rule()`返回有限的`DAMAGE/ADD/1`、`source_relation='self'`、仅HERO_POWER伤害规则。`GrantHealthRule`在技能载体上只接受这个永久授予，不接受友方全部来源、其他数值、印刷附件或计时版本。状态恢复与实际收集均校验该范围。

伤害规则收集器增加当前主槽和额外槽中的实际技能，沿原附件顺序、来源匹配和伤害管线执行。技能没有角色生命值，因此不使用角色存活判断。`self`使每个附件仅影响自己的伤害来源；移出技能槽的旧体和暂存体不提供规则。新安装体没有旧加成，原实体若经既有流程合法返回则保留自身附件。没有新的状态字段、玩家计数器、序列化类型或随机算法。

普通出牌、反制、法力支付、技能使用、选择、失败回滚、保存与回放保持原入口。当前版本身份由原两份台账记录；本批不认证正式生成池。

## 证据边界

内部覆盖首次安装、连续加1、用后升级不复原、恶魔复原后保留加成、双方隔离、独立额外技能的来源隔离、其他伤害加成、技能退休与重新安装、效果触发、反制、三个等待窗口、独立注册表恢复/clone/回放、玩家命令及拒绝错误规则和重算哈希的错误快照。

精确响应窗口、与外部加成的算术顺序、重新安装/临时原体返回及真实多技能卡的交互仍沿本地公共政策，待M6国服校准。本批额外槽测试证明公共附件的来源隔离，不据此认证灵魂献祭与所有多技能卡的官方组合规则。执行数量、结果和下一项仅维护在`project-status.md`及`mechanism-backlog.md`。
