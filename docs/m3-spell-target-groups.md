# 同一次法术的多个不同目标：输入规划契约

`hs_sim.engine.spell_target_groups`提供纯查询和不可变输入材料。其需求来源是BE_302烈焰震击的真实双目标文本：两个不同敌人各受到伤害，整张法术仍只有一次使用和一次过载。完整原行、双语官网主面保存在`data/cards/flame-shock-v1.json`，未知tag1724/2731没有被解释为新关键词。

`prepare_spell_target_group`接收真实物理法术、实际效果玩家、明确的目标数量上下限和手动／自动模式。调用者可以传入自己的实际有效定义；该定义必须仍是同一张法术。数量政策和有效定义是受信producer的输入，不能从玩家请求、剩余候选数量、卡牌文字或计划自身反推。此接口不证明某个窗口已经接受这些输入，也不判断费用或是否轮到该玩家。

查询复用`targeting.accepts_target`，完整枚举一次当前有序候选，不在每个箭头之间推进状态。普通手动选择继续受潜行、免疫、魔免等限制；自动模式保留原自动候选政策。实际效果玩家与自动来源的物理控制者分开，原来源事实不被覆盖。自定义玩家谓词仍须使用原观察工厂，不把全知状态交给玩家谓词。

`SpellTargetGroupPlan`冻结原物理来源、有效定义摘要、数量政策、模式、回合／动作及完整候选事实。所有事实共享同一分配窗口。场上随从另保存完整、逐候选对应的`BoardPresenceReference`，复用原物理驻留身份，不能根据卡面、zone_epoch或新局面猜补。`SpellTargetGroupSelection`保存有序且不重复的目标ID，并从原候选连接各自完整事实。改变箭头顺序不会被排序吞掉；不能重复同一个实体凑数量。没有足够目标时，精确数量请求没有合法输入，不自行补目标、缩减数量或调用其他效果。

`spell_target_group_selections`按原数量政策惰性枚举有序、无重复输入。此枚举不是随机选择，不消耗RNG。真正的宿主仍须在枚举边界执行原资源限制，不能将任意规模的笛卡尔结果一次展开。`validate_spell_target_group`要求调用者独立给出原来源、玩家、数量政策、模式及有效定义，在原窗口重算完整计划；不能只拿一份自带候选的计划自证合法。候选被裁剪、原驻留或目标限制变化、来源或政策被替换都会拒绝。完成后的历史不能借较晚新局面重算旧接受。

纯规划材料不能替代`PlayCard`、`PlayRecord`、原法术窗口或`SpellCastRecord`的接受证明。实际消费者必须绑定原支付前整组输入、真实目标阶段／重定向后的整组结果和每次实际CAST，再将伤害等主体交给已有执行器；自动施法、重复和保留原目标的来源也各守自己的接受政策。真正的目标输入不能伪装成战吼／连击向量、两次施法或普通效果菜单。模块不另建付款、随机、反制、伤害或过载执行器。

仅有一个可选敌人时是否仍可手动使用、多个箭头的精确替换／反应窗口、自动及保留目标政策均须由实际卡牌适配与国服校准分别确认。规划器可以验证调用者明确给出的数量政策，这不认证哪种政策属于国服烈焰震击。数据包的`behavior_verified=false`不因纯查询检查通过而改变。实际执行、验收证据及下一项只维护在项目状态与机制清单。

## 原付费入口与普通手动CAST

注册表的`SpellTargetGroupProfile`声明固定普通法术的两箭头政策。当前消费者限定同一必要目标域、内建谓词及两目标，不替抉择或条件目标编造组合。`shortfall=reject`要求完整数量，`available`要求当前可供数量与二者的较小值；有足够目标时两者都必须提交两个。该声明被纳入实际注册表指纹，空声明保持旧指纹；不能由玩家提交政策或自己选择少选一个。

`PlayCard.target_ids`是非空时必须完整提供的有序向量，原`target_id`必须等于其第一项，作为旧单目标管线的兼容引用。旧动作在JSON中仍省略空向量；新增向量采用严格数组编码，不接受布尔ID、重复、空数组或不一致首项。原准入及合法动作生成同时校验整组；没有声明的普通卡不能悄悄接受额外目标。

原`prepare_play`在付款前重算并冻结整组，`PlayRecord.spell_target_group`进入原`HandPlayCostProof`。关闭证明仍从完整原支付前状态重建全部出牌记录，包含原第二目标、完整候选及政策；回溯根动作保留完整原向量。真实提交发布唯一私有`spell_target_group_submitted`事实，绑定原记录和完整组材料。Game边界使用原有效事件时间线核对一一对应，不另建组账本，不把私有候选／分配字段送入玩家DTO。

普通手动目标阶段保留原一次窗口。每次实际手动或手动重复CAST都从原出牌记录携带同一完整原组；反制保留原提交，但不发布目标或执行主体。原`FinishSpellAcceptance`、`FinishSpellCast`、选择恢复、事务回滚及回放继续负责闭合。具体伤害主体应继续组合原批次效果，不能复制伤害或死亡结算。

玩家命令版本为`player-actions-v13`；新增`targets`数组只含原玩家可见引用，`target`存在时必须匹配第一项。旧命令形状保持，玩家观察版本保持。完整存档为schema513/core625，旧1～512需原引擎；当前schema缺少原输入、实际组、原候选驻留或窗口箭头字段亦拒绝。

## 实际目标接受、逐箭头阶段与重定向

`spell_group_targets`在真实目标阶段保存独立的`SpellGroupTargets`，连接原完整输入、实际物理来源、有效定义摘要、全部初始实际目标、原生抽样和最终目标。`PlayRecord.spell_target_receipt`与每次手动CAST的同名槽保存实际组；原`spell_target_group`及原出牌target_id不改写。CAST的标量target_id仅连接第一个非空实际位置，执行仍使用完整组。

原生来源存在时，所有箭头复用同一原状态调用`manual_partition`，再沿原RNG逐次`sample`；后一完整候选只移除先前已选对象，不在两次抽选间推进主体或重新捕获来源。完整原生载体、候选、各次MT19937前后状态和原输入均保留。一个或全部候选在该窗口不足时，实际组仍保留每个原输入位置和相应空抽样，不伪改原手动选择数量；空池不消耗RNG。已接受第二目标不因首箭头反应令原生来源离场而重抽。

同一原ActionWindow依次以`spell_target_index`标明当前箭头，发布该箭头的目标事实，待反应结算后接受该位置的实际驻留，再推进下一位置。已有`RedirectSpellTarget`和`SummonSpellTarget`继续沿原结构域政策作用于当前箭头；新实体使用实际召唤返回值。重定向不重跑手动敌我／潜行等限制，也不重新抽取另一箭头。不同原输入与原生无放回约束保留；后续实际重定向的重复落点单独记录，不伪装成新的合法手动输入。该沿用政策及两个箭头的精确国服反应顺序仍需M6确认。

初始和最终目标各有独立物理驻留引用，重定向亦保存新引用。随从变形或转控不以印刷卡面或面板epoch自动失效，离场后重新进入则不能借同一ID重接旧驻留；英雄沿实际当前英雄身份处理。`target_ids(context)`只读当前实际CAST已接受组与其仍有效的物理驻留，不拿后来完整候选重新选目标。

唯一`FinishSpellGroupTargets`保留原接受前状态、各箭头原发布／结算状态和实际事件。恢复及完成时重算完整原生候选和抽样，逐步绑定重定向、当前箭头及之前位置，并复用原历史／全局来源前缀约束连接当前状态。通用窗口续接检查和完整付款证明队列都把原箭头结算节点作为同一待完成法术窗口，组工作必须在原付款接受关闭前完成，不能仅保留第一个箭头或删掉唯一Finish。

私有接受、重定向、逐位置结算和完成事实与原记录一一对应，重定向另绑定实际公开事件。每次位置结算同时保存原目标发布事件编号；等待证明里的接受、发布和结算事件必须逐项等于实际有效时间线中的原事件，不能拿形状相同的未发布事件冒充。原有效事件时间线仍是共同依据，不增加组账户或另建回放器；这些事实与全部FullState／抽样证明不进入任一玩家DTO。闭合材料提供内部一致性，不认证未签名存档的外部来源。

自动／原存储／历史及相关原生重复producer尚未接通多目标组，对应入口继续明确失败并事务回滚；普通旧单目标来源保留原路径。仍须连接各producer原目标、随机偏好和保留／重复政策，验证真实入口后才能注册完整BE_302适配。这里没有注册BE_302，也没有宣称其过载或整卡效果完成。
