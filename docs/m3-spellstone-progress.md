# B09a：法术石的数值进度与升级费用

本契约只补法术石自身的基础能力：按合格事件的实际数值积累手牌进度，以及真实升级时的本地费用处理。复用已有 `hand_progress.py`、`hand_upgrades.py` 和公共解释器，没有另建法术石模块。其他法术石、阴谋及圣契仍须分别核对；实际测试和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。

## 真实需求与证据边界

[完整原始记录](../data/support/spellstone-progress.json)固定小型法术玉石及两个升级形态 `LOOT_051 / LOOT_051t1 / LOOT_051t2`，来源与逐条摘要均保存。三个形态都是1费自然法术，分别对一个随从造成2/4/6点伤害；前两段需要累计获得3点护甲。官方[卡牌库](https://hearthstone.blizzard.com/en-gb/cards/43288/)用于基本卡文核对，本地完整记录是此次适配的固定输入。

[玉石调查](https://hearthstone.wiki.gg/wiki/Lesser_Jasper_Spellstone)说明一次获得6点护甲只升一级，分两次获得则可以升两级；[升级调查](https://hearthstone.wiki.gg/wiki/Upgradeable)还记录了升级丢失此前本地减费。两者是社区调查证据，不是官方客户端或国服校准。本实现据此采用明确的内部政策：一次实际事件最多完成当前阶段，超额不进入下一阶段；真正换面时清除本地费用行，重新走新印刷费用和仍有效的玩家/光环报价。费用增加、替代支付及精确窗口的正式细节仍待M6，不把该政策推定为所有升级卡的规则。

## 复用进度声明

```python
HandProgressSpec(
    'event', 3, 'LOOT_051t1',
    event='armor_gained', condition_id='jasper.owner.armor',
    amount_basis='event_amount', upgrade_cost_policy='clear_local',
)
```

注册条件仍先决定资格，返回严格布尔值；玉石只接受该手牌控制者的 `armor_gained`。`amount_basis='one'` 是旧行为的默认值，每个事件增加1。新增 `event_amount` 只允许非重复的通用事件进度，读取该已发生事件的精确整数 `amount`；非正值不计入，布尔或其他类型明确报错。没有按事件名称自动猜测含义，也不扫描此前历史补计新获得的牌。

同一事件在一个进度链仅消费一次。每次只接受 `min(amount, goal - value)`，随后完成当前阶段并换面；不会把一个大事件拆成多次升级。下一形态继续使用原链身份、完成次数和见证，当前值从0开始，之后不同的实际事件可以继续推进。控制者和能力身份检查、手牌顺序及挂起队列沿用已有规则，不新增调度顺序。

`progress_units` 与 `progress_keys` 一一对应，保存每个事件实际接受的正整数单位，而不是原始事件总量。获得2点护甲保存一条见证和 `(2,)`；再获得8点，当前阶段只需1点时保存 `(2, 1)`，下阶段为0。一条巨大事件仍只有一条有限收据。单位、计数、完成次数和当前阶段一起进入不可变能力、冻结复制材料、快照及挂起帧；玩家DTO仍只给原有进度摘要，不给收据或全知身份。

## 升级与生命周期

`upgrade_cost_policy='preserve'` 保持旧升级规则。显式 `clear_local` 只在实际换面时清除实体本地费用、费用设值、最低费用和替代支付部分；同一附件的其他已有载荷保留，玩家持续费用修正和光环仍由既有报价管线处理。部分进度不清费用；相同牌面也不清费用。普通 `UpgradeHandCard`、锻造、腐蚀和注能继续默认保留，不自动套用玉石政策。

当前复制继承已经获得的进度和收据，基础复制从当前印刷形态的空进度开始。普通不重置移区保存已获得进度，但非手牌区不监听；重置移区沿原生命周期规则处理。选择中保存、独立注册表恢复、克隆和回放不重计见证。回调或金额类型错误使原动作完整回滚，费用、随机、护甲和进度一起还原。

开发身份为 `prototype-v165 / core-effects-v165`，schema160严格拒绝旧1～159。新能力字段及新声明字段必须显式存在，不加载时补默认值；玩家观察70、命令10及外层replay1保持。这个收据只证明内部结构和执行一致性，不认证未签名存档的外部来源。

## 适配范围与保留缺口

三形态只在 `tests/test_spellstone_progress.py` 的隔离注册表接入，真实伤害主体、费用和随从目标完整；生产代表与合成包不因本项扩大。选择及异常使用明确的公共测试探针，不给真实玉石编造选择或额外主体。

其他法术石不能仅因公共接口存在就宣布完成。例如过载水晶量和受伤来源资格需要真实事件事实；已有 `mana_changed.amount` 是当前法力的实际变化，不能冒充本次新增的过载水晶数。阴谋的回合成长、圣契的永久玩家减费与类别资格继续单独核对。跨机制组合、特殊授予及完整来源接卡后置，M0正式池、M6国服校准、M7及完整目标保持开放。
