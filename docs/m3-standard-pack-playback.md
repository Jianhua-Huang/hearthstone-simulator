# 具象炉石的标准卡包使用

`CORE_WON_145`保留完整9费5/5中立传说及原战吼，只返回`OpenStandardPack`。原卡数据、两份双语完整官网响应及来源说明保存在`data/cards/avatar-standard-pack-v1.json`。卡牌登记不等于正式卡包池或国服全部行为已经校准。

## 独立卡包域

宿主必须提供同一明确`GenerationContext`下、声明完整的`constructed.standard_pack`。它负责实际标准补丁、可从包获得的印刷版本、排除项及有权重成员，不由已实现注册表倒推，也不把全部标准可用卡直接当作可开包卡。核心、活动赠牌等是否合法入构筑，与能否从包中获得是不同问题，正式范围由M0独立核定。

`pack_candidates`复用原元数据查询与有权重抽样，逐项验证全部合格的五类内容。未知合格内容在抽样前明确报错；不裁池、不当白板。不同印刷版不能凭空增加同一卡的权重，宿主必须明确所需印刷身份。普通发现、生成的来源排除和特殊关键词禁止不是卡包资格的推导依据；本入口不改变这些普通规则。

当前本地政策`standard-pack-host-weights-v1`按完整宿主权重有放回接受五个有序occurrence。没有把商店开包保底、稀有度概率、收藏保护或账号保底计数器套进战吼，也没有内置一个未经核定的正式池。空池、不完整池或缺失上下文均报错。精确抽样分布、重复和资格仍待当前国服证据核定。

## 无手牌依赖的普通执行

[官方31.2说明](https://hearthstone.blizzard.com/en-gb/news/24163459)明确取消具象炉石的手牌空位要求。不能把首发版本的“先入手再使用，满手会少用牌”保留为当前机制。

一次原战吼接受完整池、五项顺序、原来源和随机前后状态，然后按顺序逐张执行。每张完成其普通结算与反应后，再沿`PlayStandardPackSlot`进入下一项。随从调用原`SummonByCard`，法术创建原物理法术后调用普通自动CAST，武器和地标调用原生成安装器，英雄调用原英雄/技能安装器。物理安装不执行战吼、连击或地标主动能力，也不伪造手牌提交、付款或玩家PlayRecord；原普通手动卡牌和整卡重放配置保持。

满场、没有合法法术目标及其它普通失败沿各自管线处理，再继续下一项；终局可自然中断余项。空手或满手不改变已接受的五项。普通召唤数量、巨型入场、伤害、死亡、区域和英雄替换仍由已有内核处理，不另写卡牌结算器。

[原玩家的后续卡牌换边报告](https://us.forums.blizzard.com/en/hearthstone/t/avatar-of-hearthstone-playing-minions-on-the-opponents-side/162273)记录来源被台风洗到对手牌库后，之后的随从转为对手所有。当前每张在实际入口读取原物理来源的当前控制者，不把整包固定为最初玩家；这份历史报告仍不构成当前国服全部控制/移区窗口认证。来源死亡不会将已接受的包改成新抽样或丢掉余项。

## 恢复与玩家边界

私有提供保存原完整请求、池版本、完整有权重候选、五项顺序和MT19937前后状态。恢复重演原抽样，不重抽。每项开始保存实际原来源和当时执行者，唯一下一项游标跨召唤、施法或其它反应的选择等待保留。不能删除、重复或借用另一个包的游标；失败回滚沿原命令事务。完整接受证明只保证内部一致性，不认证未签名存档的外部来源。

玩家只获得原正常公开事件与本来可见的实体；完整域、随机状态和未执行项不进入玩家DTO。卡包动画向玩家显示未来内容的精确可见窗口仍须M6单独核定，不能把全知快照交给玩家。

没有新增模型字段、对局账户、开包计时器或手牌绕过规则。实际版本、执行结果、未完成范围和下一项只在原两份台账维护。M0正式池、M6当前国服及完整实际可达内容保留开放。
