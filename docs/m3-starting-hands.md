# 最终起始手牌与临时起手来源

独立基础由 `hs_sim/engine/starting_hands.py` 维护。开局冻结历史卡面，临时取回复用[原手牌保存](m3-temporary-hands.md)；卡牌不保存完整局面或读取后来原实体的状态。实际验证与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 来源与证据边界

官方[换牌介绍](https://news.blizzard.com/en-us/article/21363040/opening-moves-mulligans)说明先手三张、首回合再抽一张，后手四张加硬币，开局前可以换牌。[超时空鳍侠卡库](https://hearthstone.blizzard.com/en-us/cards/120774-the-fins-beyond-time?class=paladin&set=standard&sort=manaCost%3Aasc%2Cname%3Aasc%2Cclasses%3Aasc%2CgroupByClass%3Aasc%2CgroupByClass%3Aasc)支持 `TIME_706` 的战吼方向：临时替换为起始手牌，在本人回合结束时换回。这些材料没有证明所有特殊开局顺序、复制材料或当前国服的精确清理窗口。

[三完整原始记录](../data/support/starting-hand-basics.json)的 pin 为 `e328f70eaece0b279bf07368bc83ed4334e9bd727a0bf3e29ca4aa8b26616a7f`。只对必要来源 `TIME_706` 作隔离实验适配；`TIME_706e2/e3` 仅保存原始附魔证据，没有执行适配。没有扩大生产代表包或正式池，没有新增组合机制。

## 捕获最终起手

`OpeningState.offered` 是换牌前的物理候选，`selected` 是退回清单，`original_entities` 是原卡组实体；三者都不等于最终起手。新增 `OpeningState.starting_hands` 保存按玩家编号排列的两组不可变 `StartingHandCard(entity_id, card_id, zone_epoch, hand_entry_id)`。重复卡面仍对应独立物理来源，不按名称去重。

当前捕获政策为 `after-opening-before-first-draw-v1`：双方换牌完成、后手硬币交付、所有 `after_mulligan` 工作和既有手牌整理完成后，在 `StartFirstTurn` 内标记开局完成并一次捕获两组；随后才建立实际本人区间、刷新资源、发布公开开始和正常抽牌。普通开局先手记录三张，后手记录四张加实际硬币，首回合正常抽到的第四张不进入记录。

特殊开局以这个窗口中实际仍在手牌的卡面和顺序为准，包括在窗口之前加入的牌；开局期间生成、离区、换面或整理后的精确国服含义仍待 M6。记录只冻结卡面与来源，未宣称保存开局时所有附魔或本地数值材料。

`None` 表示尚未到达捕获窗口，不等于两组中的合法空组。换牌或开局能力等待时保持 `None`，恢复继续原流程；开局能力致命终止时不伪造起手或首回合。普通 `Game.from_scenario` 没有构筑开局记录，读取起手或执行所需来源明确报错，不能拿场景初始手牌、当前手牌或原卡组猜填。

私有 `starting_hands_captured` 收据绑定政策、先后手和完整有序身份。构筑恢复核对唯一原收据、换牌完成与公开游戏开始之间的事件顺序、有效卡面和原成功手牌获取。完成开局必须有严格类型的记录；后来原牌离区、变形、转控或使用不会重写历史卡面。这些结构检查不能认证任意未签名存档的外部来源。

## 临时恢复起始手牌

卡牌返回 `ReplaceHandWithTemporaryStartingHand(player_id, source_id)`。请求必须来自当前行动方、来源存在，且有最终构筑起手记录。超出当前容量、未知定义或不能作为物理手牌的记录明确报错。卡牌代码可以通过 `starting_hand(state, player_id)` 读取私有固定组；不能把这个返回值放进玩家接口。

内核先保存本人当前剩余原组，再按历史卡面和顺序创建独立实体，使用普通生成入手的材料化入口。新实体的 `origin_entity_id` 指向实际历史来源；即使原牌已经打出、移进牌库或换成另一卡面，也不移动或复制其后来状态。当前 `own-end-starting-printed-v1` 政策以历史卡面作为普通创建的印刷定义，不继承后来原实体的本地费用、附魔、伤害或动态能力；正常全局创建和获取规则仍由内核负责，精确国服复制材料仍待校准。生成不是抽牌，不产生疲劳或额外抽样。

`TemporaryHandReplacement` 复用原组、历史来源、新实体、原接受回合/动作和阶段；请求类型严格区分对手当前手牌与本人固定起手来源，私有接受/取回事件也区分生产者。全部实体建立并保存根后才执行反应，不在等待恢复时重新创建或重新捕获。

本人结束时复用既有 `ExpireTurn`、`ReturnTemporaryHand` 和原组完整提交：按最后保存、最先取回处理本机制自己的多次使用；移走整个当前手牌，再按原顺序取回保存的实际原实体。已打到战场或移入牌库的临时牌留在所在区域；后来抽到或生成且仍在手牌的牌按当前完整清理政策移入私有 `SETASIDE`。这一精确清理及结束优先级仍待国服校准，不能推广为[秘密通道](m3-temporary-deck-hands.md)的获取资格规则。

保存/材料化/取回反应异常按公共事务回滚付款、原组、RNG、知识和结算帧；终局把活动记录标成 `ended`，保存组保持私有。真实结束等待必须保留实际可执行到期工作，历史工作副本不能替代当前队列。

## 历史费用、恢复和玩家信息

历史费用证明可能在实际游戏开始后重建换牌阶段。重建原 `opening_stage` 时，若原阶段尚未完成，须同时清除后来捕获的 `starting_hands`；只有原阶段为 `complete` 才保留固定起手。不能让未来的开局事实影响过去报价，也不能放宽真实完成边界的必要记录约束。这个修正维护原历史证明，没有新增开局出牌能力或组合入口。

当前开发内核为 `prototype-v171` / `core-effects-v171`，snapshot schema166 拒绝旧1～165。玩家观察72、命令10、replay1保持，没有新增玩家操作。快照保存原起手和严格请求，恢复、克隆及完整动作回放继续原身份和同一份根。玩家 DTO 不含全知起手、原组、私有来源或内部收据；本人通过实际取得的临时牌看见卡面，另一方仍沿正常隐藏手牌政策观察。

完整来源、永久替换、全手互换及精确国服政策仍开放，U37保持部分实现。M0正式池、M6校准、M7批量接卡及整个基础目标没有因这项增量完成。
