# 原牌库随从发现与黑暗之赐

梦魇之王萨维斯必须取得牌库中的原实体，生成基础副本会丢失原修改并错误保留原牌。本契约覆盖这一真实来源所需的有限公共入口；完整固定37.0原行在[数据包](../data/cards/stored-dark-gift-source-v1.json)，实际进度和验收只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护。

`DiscoverDeckDarkGift(player_id, source_id)`从本人当前物理牌库取得普通随从候选，不建外部随从生成池，也不按当前职业过滤已经在牌库中的牌。复用原`zone_candidates`及完整已注册定义；未知内容明确失败，不能从候选中删除。按已有物理take政策最多抽三个不同实体，同名牌是不同物理候选；这一去重/权重政策及精确国服窗口仍待M6核对。空池不生成选择或消耗RNG，实际选项上限在抽样前检查。

`StoredGiftOffer`保存原CardReference、当前CardPreview、当前战吼资格和真实gift ID。十种构筑赐福及32.2资格规则沿[原公共模块](m3-dark-gifts.md)；共享`sample_eligible_gifts`对完整有序可行绑定抽样，普通生成发现仍按原打印定义调用，原排序、排列和RNG调用保持。原牌库发现使用当前存储材料，已有关键词、零攻击和已有战吼资格不会被印刷基础定义覆盖。三个赐福不同，不能因某牌不合格而静默删牌。

每个选项显示叠加赐福后的当前数值和名称，保存完整有序offers及选中索引到`SelectGiftedDeckCard`。待选恢复验证各分支、预览、配对、原玩家、来源、原物理驻留和当前材料一致；选择后不重抽或重新付款。当前材料是本次已接受预览，不含对方私有事实、来源附件ID、完整队列或RNG。保存校验提供结构一致性，不认证未签名存档的原始来源。

实际选择先验证原实体仍在同一牌库驻留，再用原`GrantDarkGift`安装赐福，随后通过原`MoveCard`把同一实体送入手牌；甜美梦境把同一实体置于牌库顶。不是复制、抽牌、召唤或新分配。原数值、费用和能力修改保留，满手沿原烧牌管线，未选牌的实体和相对顺序保持。授予通知导致原牌先离开时，尾部旧引用失效而跳过，不能复制或拉回；已接受玩家和实体不随来源后续死亡或转控重绑。原Grant通知/交付时序及甜美梦境的精确官方政策仍须对应国服校准。

实际萨维斯声明4费4/4恶魔、原生战吼和上述一个请求，无静态发现池。正常战吼重复/粗暴唤醒分别重新读取当时牌库，每次沿已有完整战吼接受窗，整次出牌支付一次。只有选择继续后的新动作失败会回滚该次选择，保留此前已经提交的原付款和待选边界。自动战吼选择、终局和其他管线继续沿共享解释器。

新增两个effect和一个冻结payload，无GameState字段、模型声明或第二套区域/赐福执行器。core377/schema302拒绝旧1～301，观察87、命令12、replay1保持；既有CardPreview和普通effect选择DTO即可展示，不增加玩家私有字段。默认代表包和旧卡完整定义保持，旧schema和内核身份不能以布局近似恢复。

官网萨维斯childIds明确等于原十种赐福DBF身份；这些是复用的配方来源，没有新增十个可构筑根或静态随从池。其余恶魔来源依赖完整传奇/龙/恶魔生成池，年兽的攻击后成长值也不能从身材或无关历史猜测；均保持未支持，不能以本入口交付宣布整族或虚空灵魂已完成。

`python -B -X utf8 -m examples.card_stored_dark_gift`用真实玩家命令展示原实体入手、正常出牌，以及原实体置顶后自然抽牌、出牌。跨职业、短牌库和显式法力是内部Scenario，不认证标准套牌、正式生成资格或国服时序。
