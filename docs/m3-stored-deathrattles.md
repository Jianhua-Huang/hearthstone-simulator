# 明确声明的存储亡语

实际进度、验证证据及下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。本页规定真实卡面明确要求在手牌或牌库退役时触发亡语的有限入口；普通弃牌、存储销毁和溢出不因此具有场上死亡语义。

`CardDefinition.stored_deathrattle=True`只允许原生亡语、可从手牌打出的物理随从，不能同时声明`on_discard`或`on_destroyed`，不能用它给任意卡动态授予跨区域亡语。默认值为严格布尔`False`；默认注册表指纹省略这个默认字段，显式许可进入指纹。星舰组件不在该入口范围。

`stored_deathrattles.py`从实际的原始退役事实接受执行。弃牌要求原`DiscardRecord`及对应`card_discarded`事件；显式手牌/牌库销毁、抽牌和创建溢出要求既有`CardDestructionRecord`或`burn_destruction`收据。原物理实体、卡面、牌型、拥有者、控制者、墓地区域、完成后的epoch、实际回合和动作必须一致。存储实体的`active`属性不表示区域，不能据此拒绝墓地实体。新建溢出保持原epoch，不伪造曾经的手牌驻留。

原弃牌或销毁通知继续先接受监听者，本牌执行组按原队列排在其后。`capture_body`和`capture_destroyed_body`交付效果元组：普通原生主体是单项，未声明为空，存储亡语交付完整的既有亡语接受组。该组直接进入原解释器，不以包装回调隐藏尚未开始的亡语及Finish证明。

`DeathrattleCapture.origin='stored'`区别于自然`death`及显式`effect`。它绑定实际载体、原退役事件和原处置来源，`death`上下文和`death_id`为空。它不创造`DeathRecord`、残骸、复生或额外出牌/施法事实；主体的伤害等后续效果若造成真实死亡，仍照常产生各自的死亡事实。

声明许可后仍使用原活跃亡语能力集合、禁止政策、重复计划、逐次调用身份和完整Finish证明；没有新的计数器、随机源或持久状态账本。原等待、异常事务回滚、独立注册表恢复、clone和回放共享既有执行器。保存的原始退役身份和未开始计划必须可验证，不能用同名空通知替代实际退役。玩家观察不获得完整收据、隐藏卡牌状态或全知快照；结构校验不认证未签名存档来源。

`core-effects-v340`和schema273保护新声明与新的origin；旧1～272保存布局明确拒绝，观察85、命令12及replay1保持原协议。

## 真实卡牌配方

完整原行和有限配方存于[demon-zone-effects-v1.json](../data/cards/demon-zone-effects-v1.json)，注册入口为[demon_zone_cards.py](../hs_sim/cards/demon_zone_cards.py)。

- 小鬼地狱火声明原生亡语及存储许可；命名主体一次捕获双方其他角色并交付`DamageBatch(3, MINION_ABILITY)`。它在场上的自然或主动亡语沿原入口，不额外执行存储主体；法术处置它也不让亡语获得处置者法伤。
- 小鬼马仔的亡语两次交付原`AddToDeck(position='bottom')`。小鬼奶奶的完整8/8、嘲讽和吸血卡面由原DBF127507及官网关联共同固定；不使用临时白板代替它。
- 雷兹迪尔在战吼执行时查询本人上一实际关闭回合的种族提交；延系成立弃对手一张，否则弃本人一张。随机选择复用完整物理手牌和原RNG，空敌手牌不改弃本人牌。
- 魔神暴龙使用普通`on_play`延系入口，没有战吼。成立后一次捕获敌方物理左右随从端点并交付两份6点随从能力伤害；单随从收到两份，直接召唤不运行出牌主体。当前端点政策保留休眠位置、排除非随从交互物；准确端点和健康结算仍待国服校准。

两张延系牌共享[上一自身回合查询](m3-kindred-basics.md)，不增加延系计数或单卡状态。原生命值、防护、死亡、费用、随机、区域和恢复仍由公共内核执行。`python -B -X utf8 -m examples.card_demon_zones`展示真实玩家命令及检查点。

这些配方与执行窗口属于内部实现；精确国服退役触发、亡语禁止/重复、端点及伤害时序仍需M6校准。年兽的成长量与原生可复制效果值未被本契约猜定；完整恶魔生成池及虚空灵魂升级也不由本入口自动获得。
