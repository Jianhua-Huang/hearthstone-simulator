# 原存储卡牌的完整随机池变形

`stored_pool_transforms.TransformStoredFromPool`将一个原HAND/DECK的`CardReference`连接到已有的完整候选查询、整数抽样及普通存储变形。请求携带池、查询、来源、既有生成政策及空池政策；它不锁随从、原类型或费用档。没有新随机算法、变形执行器、费用账户或状态账本。

执行时先用`resolve_candidates`检查全部合格候选，再用`stored_destination`验证全部物理目的地和固定面板映射。未知合格内容或不支持的物理定义在游戏RNG前报错，不裁池或只等抽中后报错。普通变形沿既有纯查询政策，不额外排除来源家族；查询自己的exclude_source仍有效。实际目标引用过期也先校验内容，再跳过且不抽样。

每个活跃请求通过原`sample_candidates`抽一次，再同步调用`transform_stored_entity`共同原语。卡牌ID、类型、身材、原生能力和费用沿原打印重置，旧附魔/局部减费清除；实体ID、owner/controller、区域、物理槽位保留，驻留修订推进。既有身份隐藏及`stored_card_transformed`反应保持，不抽牌、生成、施法、召唤或执行目的地战吼。后续反应可以等待；恢复后尚未执行的其他请求才接受各自的抽样。

私有`StoredPoolTransformDraw`保存原请求、原接收者/来源分配、上下文/池版本、必要当前职业、完整有序候选及权重、结果、MT19937前后状态，以及实际变形事件序号。边界校验重算完整池、局部重演抽样并核对唯一原变形事件的物理对象、来源、归属、旧面与实际新面；固定面板目的面继续由公共映射解析。空池skip保留空收据、不消费RNG，error明确失败；没有实际目标的原生主体不提交请求。

typed等待帧复用现有解释器；旧诊断收据可以在回溯后保留，以原分配上界和原事件核对，不要求当前实体仍是旧面。后续合法操作可以推进RNG、转交或移走卡牌；收据不进入玩家观察或事件。这些检查证明注册表内的一致性，不认证无签名外部历史来源。新增一个Effect和一个payload类型，core434/schema352拒绝旧351；无新增已有字段、GameState/Entity/Ability字段。
