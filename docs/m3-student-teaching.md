# 原学生入手、发现法术与教学

上层精灵教师`TIME_704`先获取原2费2/2小学生`TIME_704t`，再发现过去7费以上法术并教会它。教师为7费6/6；完整原行及十份中英官网主面保存在本批资料中。野性赐福`EX1_183`和溢流`ULD_273`用于核验真实历史法术的执行，炎爆术复用既有定义；这些代表不构成完整过去卡池或当前正式资格认证。

`CarvedSpellProfile(..., teaching=True)`显式声明真实学生能力，原树人profile默认保持False。教师只发出`CreateStudentDiscovery`，依原已接受战吼确定来源/玩家，再使用普通`create_hand_card`分配小学生。原分配事实与战吼ID绑定私有接受事件，随后沿原入手/满手公告运行。其他反应可以先等待；排队发现保存原学生，不能在选完后另造一个替身。

`constructed.past.spells`由宿主按固定目标/模式声明完整。当前有限查询为普通当前职业、可收藏法术、印刷费用至少7；“过去”的确切系列、身份和国服资格仍待M0/M6，不能从现有执行列表或系列猜测正式池。创建学生前核完整声明及所有合格执行/携带法术能力，未知候选或不兼容目标明确报错，不能偷偷删去。空职业域沿普通发现的空池规则，保留未学会法术的原学生。

发现使用已有`destination='memory'`及新的不可变`StudentTeachingTarget`，包含原战吼、学生分配事实和接受事件。原死亡记忆目标的验证和执行继续保持原分支。候选、抽样、完整原选择、保存/恢复与普通发现语义由原发现管线负责。选中法术不作为另一张手牌交付，而是写入原学生既有`carved_spell_id`槽，再通过共享选择型发现完成器通知实际`card_discovered`。

当前有限驻留政策要求原学生仍在同一控制者手牌、同一卡面及同一区域epoch。提前复制保留当时空值，原学生后来独立学习；原学生已弃掉、离手、转手、变形或原本满手燃烧时不绑定另一个同名对象。发现仍完成，无补造学生。当前复制/基础复制、普通沉默/重置、原战吼冻结参数、目标推导及实际法术CAST复用[携带法术契约](m3-carved-spell-minions.md)，不会再支付被教法术的印刷法力。

小学生的战吼沿原携带法术施放器；抉择等自动CAST分支仍由既有执行器处理。[玩家在官方论坛的原报告](https://us.forums.blizzard.com/en/hearthstone/t/highborne-mentor-choose-one-issue/159475)观察到自动抉择，但没有提供当前CN37裁定。原驻留/转手/满手及反应先后、完整过去资格与这些自动分支仍待正式校准。

原生参数由已有玩家投影显示给本人或公开对象；对手暗牌不会得到法术值、完整池、原分配或接受信息。官网小学生主面只省略动态法术名，来源工具仅为其完整原行SHA显式允许`{'{0}': ''}`；中英施放正文、数字和全部元数据仍严格比较，原树人的精确例外保持。

新执行层只有1个效果和1个明确注册payload，无新模型字段/对局账户、选择用途或玩家DTO字段。协议core580/schema474、玩家观察105及命令12/replay1；实际进度、验证和差异仅在[项目状态](project-status.md)与[机制台账](mechanism-backlog.md)登记。
