# 临时手牌保存、复制与回合末取回

本契约只覆盖自己本回合结束的临时手牌复制来源。公共状态由 `hs_sim/engine/temporary_hands.py` 维护，卡牌不保存局面快照、不直接改写手牌列表。实际验证及下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 必要来源与范围

当前裂心者伊露希亚 `SCH_159` 把自己的剩余手牌暂时替换为对手手牌的复制，直到回合结束。[21.3 官方改动](https://hearthstone.blizzard.com/en-gb/news/23724327/21-3-patch-notes)确认这个主体方向；它不证明所有复制属性、后来取得的牌如何清理或当前国服的精确到期窗口。

仅这一张必要真实来源有隔离实验适配。[完整 raw](../data/support/temporary-hand-basics.json)的 pin 为 `606f92ef5057899af2ae0d09ed2fe9fe62be70a32194f564b5a0cb5ab68114ee`。旧 `SCH_159e` 仍描述双方手牌及牌库互换，不能据此恢复旧规则。生产代表包和正式池没有扩充。

秘密通道的原牌库实体、下回合换回，以及超时空鳍侠的起始手牌来源，须分别确定候选、期限和清理政策。秘密通道的独立牌库来源已有[另行契约](m3-temporary-deck-hands.md)；超时空鳍侠的必要最终起手来源已有[独立契约](m3-starting-hands.md)，精确材料／特殊开局仍待校准，没有展开跨机制组合。

## 保存与复制

卡牌返回 `ReplaceHandWithTemporaryCopy(player_id, source_player_id, source_id)`。两个玩家必须不同，接收者必须是当前行动玩家，来源实体必须存在。未知定义、错误类型及无效请求明确报错，由原事务整体回滚。

接受时一次捕获接收者当前剩余手牌顺序及对手当前手牌的全部物理 `CardReference`。把接收者原组移入私有 `SETASIDE`，记录每张原实体的卡面、区域修订和原获取身份；再按原对手顺序复制。复制使用从普通 `CopyCard` 抽出的同一个 `copy_physical_card`，`mode='current'`，绑定每个原候选与实际新实体。对手的物理手牌不移动，复制不抽牌、不消费 RNG。

保存完整原组后才复制，原手牌不占复制容量。原组保留 owner、controller、物理身份及当前本地状态。复制卡得到接收者的 owner 和新实体身份。复制产生原有手牌获取事实，保存不伪造弃牌、销毁、死亡或移出游戏事实。

## 到期与清理政策

期限绑定真实接受回合及接收者。来源随从死亡、沉默或普通离场不取消已经成立的保存记录；结束对局时将仍活动的记录标成 `ended`，不继续开始下一回合，原组保持私有。

当前内核在真实 `EndTurn` 的结束主体、玩家倒计时及解冻之后进入 `ExpireTurn`。临时手牌取回是 `ExpireTurn` 的第一项：调度最新活动记录的内部 `ReturnTemporaryHand`，然后再次执行同一个 `ExpireTurn`。原取回反应先结算，再处理其余原记录及普通附件／临时卡到期。这是本地明确顺序，国服精确优先级仍待 M6 校准。

本模块的政策标识为 `own-end-replace-current-v1`：到期捕获并移走接收者**整个当前手牌**，再按原顺序取回保存组。因此复制后新抽取或生成且仍在手牌的卡，也会移入私有 `SETASIDE`。已经打到战场或移进牌库的牌不在本次清理范围。这个政策是当前伊露希亚实验契约，不能推广为所有临时手牌来源的共同规则；后来取得的牌是否保留、精确复制材料及清理窗口尚未国服校准。

内部取回只允许真实结束窗口，按同一机制最后保存、最先取回的顺序处理一次。两次伊露希亚替换属于该机制自身的重复生命周期，不形成另一个组合模块。原组必须仍是保存的 `SETASIDE` 实体、控制者、卡面、修订及获取身份，否则明确拒绝。

先把当前组全部移出，再把原组全部移入，提交完成记录后才发布每张 `card_moved_to_hand` 的反应。监听者不会看到只取回了一部分的原组。取回是普通移动获取，记录 `from_zone=SETASIDE, reason='move'`，使用新的获取身份；不建立抽牌、弃牌、死亡或疲劳事实。

## 状态、恢复与信息边界

`GameState.temporary_hands` 保存严格类型的有序历史：原请求、来源卡面、回合及动作、原组、复制候选、新实体、阶段和实际移走／取回组。阶段为 `active`、`completed` 或 `ended`。保存恢复只接受固定字段与固定 payload 类型，不使用动态导入或 pickle。

原接受和取回收据是私有事件，与历史逐字段绑定。验证原物理候选／新复制来源、原获取记录、保存驻留、分配顺序及到期期限；不能通过删除整个历史或重排原组丢弃取回义务。原回溯已撤回尝试的日志按现有 `timeline_rewound` 检查点处理，不作为当前接受事实。这些检查不能认证任意未签名存档的外部来源。

结束待选恢复必须保留实际可执行 `prefix/continuation` 中的 `ExpireTurn`；历史接受证明内的旧工作副本不能替代真实队列。内部 `ReturnTemporaryHand` 不能成为玩家选择项。选择中断、克隆、独立注册表恢复和完整动作回放延续原组，不重新捕获对手新手牌。保存、复制或取回反应中出错，原付款、队列、RNG、知识及全部区域状态整体回滚。

保存及清理退休旧知识和句柄；原组、复制来源、原实体 ID 及私有收据不进入任何玩家 DTO 或玩家日志。控制者只能看当前手牌，其他玩家只获得原接口允许的公开信息。读取不修改状态或 RNG。

## 扩展与保留需求

当前开发内核为 `prototype-v171`／`core-effects-v171`，snapshot schema166 明确拒绝旧1～165。玩家观察72、命令10、replay1保持，没有新增玩家动作或公开事件。

普通卡牌只返回入口效果。`ReturnTemporaryHand` 是内核到期工作，不能把它暴露为自选效果或在卡牌回调中提前取回；也不能直接修改历史、使用整局 rewind 还原手牌，或把私有保存伪装成 `RemoveFromGame`。

秘密通道的原牌库实体与下一真实本人开始取回已另行实现，精确政策保留CN校准，见[独立契约](m3-temporary-deck-hands.md)。最终起始手牌的定义须另行核对换牌、硬币和开局能力；`OpeningState.offered`、`selected`、`original_entities` 分别是换牌前候选、退回实体和起始卡组，不能直接当成最终起始手牌。永久替换、全部手牌互换、完整来源及国服校准继续开放，U37仍为 partial。
