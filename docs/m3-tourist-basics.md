# 游客独立构筑资格

本契约描述 `tourists.py` 的基础能力；实际验证和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。当前目标先完善独立基础机制，不开发组合机制。

游客是构筑规则。原始主卡组中加入本职业游客，才允许加入其目的地职业的“胜地历险记”卡牌；目的地游客不能加入，也不能沿游客继续开放第三职业。[国服官方介绍](https://hs.blizzard.cn/news/24108514/index.html)明确说明这一范围。[官方上线公告](https://hearthstone.blizzard.com/en-us/news/24110439/perils-in-paradise-is-now-live)和[资料片FAQ](https://hearthstone.blizzard.com/en-us/expansions-adventures/perils-in-paradise)说明每副卡组最多一张游客；[迷你包公告](https://hearthstone.blizzard.com/en-us/news/24136211/extend-your-vacation-with-the-traveling-travel-agency)说明有新增游客，因此不能假定同一原职业永远只有一种游客卡可选。

## 声明与构筑过滤

来源包注册不可变的 `TouristSpec(card_id, destination_class, pool_id, eligible_card_ids)`，政策版本为 `tourist-v1`。`pool_id`和有限、有序、无重复的卡牌名单由来源包审核，表示目的地的明确资格。不是根据卡牌ID前缀、中文名称或文本正则在运行时猜测资料片归属，也不是将整个外职业注册表开放。

```python
from hs_sim.engine import CardClass, TouristSpec

registry.register_tourist(TouristSpec(
    'VAC_437', CardClass.SHAMAN,
    'perils-reviewed-shaman-v1', ('WORK_011',),
))
```

上例只是必要实验子集。注册前须提供完整审查过的来源和候选定义；它没有声明完整资料片、正式标准/狂野资格或整个游客族均已接入。注册表验证来源为可收藏、本职业单职业传说随从，目的地为另一可玩职业；名单必须引用已知、可收藏、可手牌使用且职业匹配的定义，排除所有已声明游客。未知引用明确报错，不删除候选或推断为白板。包负责证明列举候选的资料片归属，内核现有元信息不含可推断正式轮换的扩展包字段。

`validate_deck`仍先验证普通卡组、初始英雄/技能、长度、可执行定义、元信息、收藏资格、禁限、同名组数量和符文。游客只放宽本人或中立之外的职业过滤；不能绕过这些限制。原始主卡组中所有已声明游客的物理数量不得超过一张，包含两张本职业不同游客以及同一游客重复。没有有效本职业来源、来源被禁用/轮换、来源属于外职业或数量超限，都不会提供游客权限。

`CardMetadata.classes`保持印刷职业，外职业牌不会被改为双职业。普通牌无需游客便可从其他合法对局来源获得并使用；游客权限不进入战斗付款、当前英雄职业匹配或随机/发现生成过滤，也不随来源抽取、入场、死亡或控制权变化重新计算。

## 符文与原构筑身份

死亡骑士主职业沿用原符文规则。目的地为死亡骑士的有效本职业游客也允许原 `DeckSpec.runes`，使用 `DeckPolicy.rune_slots`分配和原每牌最大需求比较；多张牌不累加相同符文需求。无死亡骑士构筑资格的职业仍不能配置符文，未知符文元信息仍报错。

游客带来的符文资格是当前明确的内部政策：依据游客目的地卡牌按该职业加入的规则，以及[官方死亡骑士符文介绍](https://hearthstone.blizzard.com/en-us/news/23852696?blzcmp=blizzard-news)作推导；尚未找到直接说明游客符文选择细节的官方文本，未作国服实际校准。不能把这个推导写成已经校准的国服行为。

没有新增状态或快照字段。原 `MatchSetup`、`PlayerState.deck_class/runes/original_deck`保存原构筑身份，注册了游客的构筑对局会严格比较三者。保存时换成当前英雄职业、改写符文或原卡组，即使重新计算摘要也会被拒绝。普通英雄变化不改变原构筑资格。此为一致性检查，不认证未签名存档的历史来源。

## 固定来源、恢复与信息边界

声明、目的地、政策版本、池身份和完整名单进入注册表指纹。未注册游客时省略新增指纹字段，实际旧开局夹具指纹保持，见[比较证据](../outputs/tourist-basics-20261010/unregistered-fingerprint.json)。不同声明不能恢复同一存档。现有换牌选择、克隆、快照和动作回放共同复用原构筑开局，无第二套选择或规则执行器。

玩家观察不增加原卡组、名单、权限对象或完整构筑配置；两副仅改变敌方隐藏游客身份的卡组不改变行动方观察。外职业卡实际打出时仍通过原公开卡面与事件披露。官方客户端的游客来源提示是否对应额外公开身份、其精确时点，保留为国服信息校准问题，未扩展为新的提示/动画入口。

当前只提升规则身份为 `prototype-v175`。效果173、schema168（拒旧1～167）、观察74、命令11和replay1保持；布局相同不能让旧规则174存档冒作新规则175接受。

## 必要代表与限制

[完整本地原始材料](../data/support/tourist-basics.json)包含七条卡牌记录，原始行哈希和完整pin固定。扣子、饮水图腾、滑坡分别复用普通各派系定向抽取、相邻结束增益、冻结后按实际场面抽牌；没有为它们新增组合机制。其精确顺序、随机资格和检查点仍随原基础政策待国服校准。

达克玛洛、蕾拉、斯奇拉、曲奇只用于必要构筑身份及拒绝边界，其其余战斗主体未在本实验实现；正常付费使用明确报“不支持”，实测付款和整个动作回滚。未宣称其生成/召唤等其他来源已支持，也未加入生产代表包或正式生成池。对这些具体卡的完整主体接入留在后续阶段，不能把构筑记录当作完整卡牌效果。

[实际验证](../outputs/tourist-basics-20261010/verification.json)记录专项、受影响测试、初始失败和最终源码绑定。正式完整游客来源/目的地池、国服游客符文及信息细节、M0/M6/M7、其他独立基础缺口仍开放。
