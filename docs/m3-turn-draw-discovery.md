# M3：正常回合抽牌的原牌库发现替换

指挥官迦顿 `CATA_591` 的战吼用原 `AddPlayerEffect` 安装普通永久程序。静态 `TurnDrawReplacementProfile(spec_id, behavior_id)` 独立登记在 Registry，验证其指向一个无额外文本的永久玩家效果和真实随从声明；只有非空登记进入指纹。没有新玩家状态字段、模型字段或回合副账本。源死亡、沉默、回手或转控不会删除已安装的程序。

原 `DrawAtTurnStart` 先沿已有活体来源抑制政策，再从当前玩家的永久程序中找到最新适用的替换，交原 `Resolver.call` 捕获普通玩家效果上下文。普通 `Draw`、检索和其他额外抽牌保持。多次实际战吼仍保留原各实例，一个正常抽牌位置只接受最新一份替换；该去重/优先政策待国服校准。空牌库返回普通无来源 `Draw`，沿原疲劳和信息流程，不构造空发现或另外抽随机。

`ChooseFromZone` 仅新增默认空的 `cost` 和默认假的 `destroy_unchosen`。启用它们时必须是本人的实际牌库、`take`、按物理实体区分及真实卡牌发现；不能给其他旧选择操作拼入这些字段。普通旧路径保持。原 `sample_zone_choices` 选择最多三个原实体，同名复制各占一个位置；新的 `DeckTakeOffer` 只冻结原 `CardReference` 与玩家应见的当前 `CardPreview`，不暴露牌库次序或隐藏引用。

每个选项使用有限 `SelectDeckTake`，原选择边界绑定完整 `ChoiceResult` 并记真实发现。执行器核对原完整请求、选项、预览及选择，然后依次交原 `ModifyStoredCost(delta=-3)`、`MaterializeDiscoveredCard(MoveCard(...HAND))` 和原 `DestroyDeckBatch`。选中原实体、已有属性与附魔保持，不新建副本，也不伪造抽牌；实际入手/烧牌、发现完成与其后的反应沿旧交付。其余原候选一次移出后才发布销毁，原引用失效时不重新寻找另一张同名牌；销毁不制造战场死亡、亡语或弃牌。

完整候选材料沿已有 OriginalDiscoveryOffer 在选择与减费前冻结，新增类型只接到原物理材料捕获入口。仅选中牌取得的减费不进入其他选项的固有材料；原 offered-card 执行器字节保持。待选校验会对照实际原牌库实体及当前可见材料，既有恢复/克隆/回放、支付、回滚和玩家隔离继续共用。

根卡、`CATA_591e/e2` 的完整原行和两份官网主面保留在固定源数据中。原 e1 的“另两张”支持三候选；原卡面只建立正常抽牌替换、选中减3费与其余销毁的方向。重复实例优先、抑制与替换的先后、物理重复权重、空牌库、取牌不算抽牌、销毁公开范围及精确反应窗口仍是明确本地政策，待 M6。当前销毁沿原默认公开政策，不据此宣称固定国服37.0所有细节已经核实。

引入时 core561/schema455，新增一个 Effect 和一个显式预览载荷；ChooseFromZone 的两个新字段由严格待选解码识别。旧1～454需要原引擎，观察100/命令12/replay1保持。实际进展与结果仅在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。
