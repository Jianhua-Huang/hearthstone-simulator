# 奥迪尔隔离区：入场后的首次符文锁

本文保存规则依据和有限执行契约；实际执行、验收及下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护。

## 真实来源

[完整固定源包](../data/cards/uldir-quarantine-v1.json)保留BE_780完整原行、哈希及两份完整双语官网主面/收据。该卡为3费、3耐久、鲜血/冰霜/邪恶各1的地标，原ULDIR_QUARANTINE_TRACKER=1及LOCATION_ACTION_COOLDOWN=2保持；card_batch.prepare严格复核，不推导完整正式生成资格。

[设计师John McIntyre的原答复](https://www.reddit.com/r/hearthstone/comments/1whw4cv/comment/paez8zr/)明确：只在入场后记录；只需首次解锁，剩余用途沿正常两回合冷却；一张多符文牌可满足多个条件，第二个隔离区能解锁第一个。完整答复及作者身份依据见[规则审计](../data/support/uldir-quarantine-rule-audit-v1.json)。这不是“本局曾经各用过一次”的整局计数条件。

## 有限公共表达

`location.runes-after-entry-v1`通过原地标use_rule声明。真实板上实体拥有独立不可变`Entity.location_lock`，保存原实体/卡面、区域epoch、入场order、下一原出牌ID、入场控制者及完整有序步骤。每次原出牌记录同时冻结实际施用者、当时地标控制者和原印刷三符文数；多枚同类符文只满足该类，不当成三种。不同实体和入场不共享进度。

原`commit_play`与支付投影共同更新这些事实，在新地标自己的入场之前完成，因此本体自己的三符文不解锁自己。过去的牌不追溯计入；对手出牌和无符文牌保持在完整前缀中但不提供本人的符文，普通召唤/效果置入不是额外手牌出牌。已接受后被反制的牌仍沿原出牌事实。原metadata未知且会影响本人条件时显式报错，不把未知当无符文。

同步进度/开门通知尚在实际来源离开手牌之前，须沿原`payment_window`保护刚被接受的动态数字；不得让通知的普通规范化将开锁匠的原身材或投身战争的原报价改成付款后的值。其余手牌仍按原资源变化刷新，原接受证明及物理移出继续由原支付管线负责。

第一次满足后停止接受步骤，解锁事实随该驻留保留；激活、普通冷却和重新开启不重置符文要求。新实体、手牌复制后的实际新入场重新开始，原reset清理旧状态。当前公共手牌/牌库CardReference不支持任意在场地标引用，本项没有为诊断夹具虚构在场复制或回手卡牌效果。

原出生与每次进度进入私有事件收据。保存核步骤连续无漏重、原冻结牌面/施用者、原实体和epoch、首次完成截止及当前完整前缀；边界核实际出生/进度事件和原出牌外壳，拒绝只改状态、剪去步骤或删除全部私有证明。与既有存档相同，这不是未签名文件的外部来源认证。

## 地标、玩家与召唤

普通地标合法性增加该有限锁判断，原玩家可见`location.open`同时包含符文锁与冷却；形状保持。原use_rule回调只看玩家DTO，不读取全知历史。首次完成沿原location_opened通知；普通RefreshLocation只清冷却，尚锁定时不发布错误的已开门通知，也不能绕过符文锁。

真实主体使用原SummonFromPool和SummonCause，从完整所有职业、可收藏、印刷费用恰为5的随从域召唤一次。随机、容量、实际交付、后续反应、死亡、回滚和恢复仍由共享执行器负责，未知合格内容显式失败。当前requires_board_space及末次耐久先腾槽沿原R-037政策；精确国服支付通知/开门窗口、容量和来源资格仍待M6核定。
