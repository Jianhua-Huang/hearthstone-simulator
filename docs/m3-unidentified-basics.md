# 未鉴定卡牌的手牌身份

[官方历史介绍](https://news.blizzard.com/en-us/article/21160660/kobolds-catacombs-tempting-treasures)说明未鉴定药剂抽到时获得四种额外效果之一；本地盾牌原文也明确额外效果在手牌取得。现有显式换面可以保存结果，但没有覆盖实际获取与初始手牌的自动抽选。这个独立缺口由[unidentified模块](../hs_sim/engine/unidentified.py)驱动，复用既有MT19937、upgrade_face、区域与信息模块。

本契约不开发组合机制或任意效果授予。实际进度、验证与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 声明

注册具有实际主体的基础牌与四个结果，再注册固定族：

```python
from hs_sim.engine import UnidentifiedFamily

registry.register_unidentified_family(UnidentifiedFamily(
    'unidentified-shield-v1', 'LOOT_285',
    ('LOOT_285t', 'LOOT_285t2', 'LOOT_285t3', 'LOOT_285t4')))
```

基础与四个结果必须不同，不能与另一未鉴定族共用成员。形态保持类型、费用、职业和学派；物理法术必须有主体，武器复用既有完整定义校验。这里只建立法术/武器载体的声明契约；必要盾牌法术族得到隔离运行证据，其他族和来源仍待实际覆盖。

族ID、有序结果及固定unidentified-v1政策进入注册表指纹。未声明时不扫描或改牌，既有注册表指纹保持。当前prototype-v167/core-effects-v167/schema162、观察71/命令10/replay1保持，没有新增存档字段、事件、账户、附件或选择类型。新族通过不同指纹区分；后续改变政策或卡牌回调必须升级相应版本，不能借全局身份相同加载不同规则。

## 实际获取与保存

只有实际HAND区的未鉴定基础牌抽选；牌库、烧毁、墓地和已确定结果不抽选。生成、真实抽牌、普通移动和复制在实体与复制材料安装完毕后、原事件反应前结算。场景初始化在信息对象建立后结算。一次按结果元组等权抽选，更新原实体的印刷形态与zone_epoch，不新建替代实体。

内部政策在双方换牌及after_mulligan流程完成、opening.stage变为complete后确定最终手牌形态；待选换牌手牌保留基础形态，换回牌库的实体不提前抽选。其精确窗口仍待M6；历史官方介绍没有证明这个完整顺序。

已鉴定结果本身存储身份，普通复制、转交、进牌库再抽取不重新抽选。current复制保留本地修正；base复制由当前印刷形态开始，清除原本地修正，不能把base解释成鉴定前的历史牌名。未鉴定牌库实体复制入手时，新副本独立抽选，原件不变。普通换面保留创建时费用修正；这些复制、转交、洗回和费用细节均是当前内部政策，待国服校准。

原HandEntryRecord与DrawRecord保留实际入手/抽取接受时的基础牌名；实体随后有新形态，不能覆盖过去事实。旧捕获引用失效。后续无关事件不改变形态或消耗随机数。

## 选择、恢复与信息

沿原事务回滚实体、费用、知识与RNG；等待前或等待后都能独立注册表恢复、克隆与回放。恢复只验证：正式开始后手牌仍有已注册基础牌时拒绝存档，不补抽或修复。换牌阶段的基础手牌允许恢复。

玩家只能看到自己的结果或普通已公开信息，对手隐藏手牌保持牌背；候选族、随机状态、全知实体/区域历史和zone_epoch不送给玩家。继续使用原换面的隐藏知识政策，不新增公开随机诊断。结构验证与确定性回放不能认证未签名存档的原始来源。

## 必要代表与边界

[七条完整raw/pin](../data/support/unidentified-basics.json)保存盾牌、四个结果、钢铁魔像和5/2武器。基础5护甲、额外10护甲/5伤害/5×5魔像/5×2武器均用原公共效果，只有伤害形态要求目标。没有批量接入生产卡牌；四个已知本地基础牌仅作为发现线索，不是M0正式池分母。

官方历史介绍支持四结果与抽到后的额外效果；均匀权重、换牌窗口、全部获取来源、复制、转交、返回与费用政策仍需M6国服校准。U33完整来源、谐振轮换、M0、M6、M7及完整目标保持开放。
