# 虚空牌堆的独立基础

本项补 U05 的私有原牌储存及获取能力，仅用必要伊莉达·寻罪的完整隔离适配验证。已有 `SETASIDE` 能保存实体，但 `CardReference`/`MoveCard` 限于手牌和牌库，玩家效果也没有私有成员数据；不能用全部 setaside 成员冒充虚空。执行结果与下一项见[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)。

## 公共入口与原牌资格

`SendDeckToVoid(player_id, source_id=None)` 使用有限 `void-original-keep-one-v1` 政策：执行时捕获当前牌库，随机留下一个原物理实体，其他成员同时成为该玩家私有虚空成员。空牌库不留牌，单牌库原样保持；这两种情况不消耗 RNG。既有虚空成员保持，后一次送入只追加当时当前牌库的新成员。原构筑事实保持，手牌、墓地和其他 setaside 成员不成为候选。

`PlayerState.void_cards` 是不可变 `VoidCard(entity_id, card_id, zone_epoch)` 元组。实体实际占普通 `SETASIDE`，记录只表示其中合格的私有子集；保留 owner/controller、当前卡面和既有属性材料。它没有第二份实体、额外通用区域或新的开局输入。每个成员必须仍在该玩家 setaside 中，当前卡面、区域修订及物理身份一致；重复、未知或过时成员明确拒绝。

送入不伪造抽牌、弃牌、牌库销毁或普通移出对战事件，也不产生死亡、亡语、复生或尸体。只有整个原组移动完成后的私有一致性事实，原解释器负责随后检查点。随机留下哪张、原组材料和时点均是待国服校准的内部政策。

## 逐次获取与普通回合

`GetFromVoid(player_id, count=1, source_id=None)` 每次重新读取当前合格成员，随机取一个，消费记录并将同一物理实体移入普通手牌。满手则普通烧牌到墓地，仍消费。空堆和 count=0 没有获取、疲劳或 RNG；单候选不消耗 RNG。取出的原实体有新的普通手牌获取身份，并可照常出牌、装备或放置。

普通 `card_moved_to_hand`/`card_burned` 事实沿现有信息和触发层处理。本次获取的反应、选择及检查点先完成，剩余次数作为原解释器工作继续；后续取牌不提前抽选。不会复制新实体、重建已消费成员或从当前牌库补足虚空。

必要 JAIL_719 战吼只组合送入和原 `AddPlayerEffect`。整局玩家效果在本人 `turn_started` 返回 `GetFromVoid(..., count=2)`；来源死亡、沉默、回手、变形、转控及复制不撤销或转移已安装实例，普通召唤/复制来源不执行战吼。每次获取及自然抽牌共用原回合管线，**没有取消自然抽牌或替换成 Draw(2)**。虚空耗尽不触发自己的疲劳；牌库自然抽空仍照常疲劳。

获取两张相对于自然抽牌的精确优先级、再激活的完整政策、随机顺序、原物理牌还是复制及费用/附件材料仍待 CN；内部原牌消费政策不能当作官方执行证明。整局效果的通用生命周期继续由既有玩家效果模块负责。

## 保存、回滚与玩家信息

首次落地规则 `prototype-v178` / 效果 `core-effects-v175`，schema170拒绝1～169；后续当前版本及执行结果以项目状态为准。玩家观察74/命令11/replay1保持；快照玩家行必须显式包含 `void_cards`，没有旧存档迁移或新的玩家操作。

独立注册表恢复、clone、待选和回放沿现有框架执行。失败动作回滚本次移动、成员消费、付款、RNG和队列；已经完成一次获取并等待其反应时，后续选择失败只回滚后续动作，不恢复先前合法消费。等待期间尚未执行的获取和自然抽牌保持在队列中。

`void_deck_stored` 保存原牌库、留下实体和全部移入成员；`void_card_taken` 保存原消费成员。二者是无额外卡牌触发的私有一致性事实，不发布玩家字段或事件。宿主按历史重建当前成员，校验 all-but-one、顺序、重复、来源及原消费；不认证未签名存档的外部执行来源，也没有重演历史 RNG 的认证声明。

玩家仅看到已有公开牌库数量、来源和整局效果，以及实际取出后的普通手牌/烧牌信息；虚空行、隐藏卡面、数量清单和引擎实体 ID 不进入玩家接口。完整宿主快照不能给玩家。其他 setaside 的私有原组不会因此开放获取权限。
