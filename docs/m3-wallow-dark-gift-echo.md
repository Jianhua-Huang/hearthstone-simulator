# 瓦洛的原授予监听与黑暗之赐复制

瓦洛EDR_487复用原HandProgressSpec，在当前控制者的手牌或牌库中监听真实dark_gift_granted。每个物理瓦洛分别接受原事件、原玩家与原驻留；场上不监听，后来生成的瓦洛不追溯历史。原居留改变使已捕获的旧候选失效，仍按共享存储监听政策执行，精确国服接受窗口待M6。

原子创建安装器对完整、具名的十种DARK_GIFTS配方发布一次原授予通知；普通手牌/牌库生成、对手牌库复制时的新授予、原牌授予及未选原发现的实际执行共用这一入口。通知前已经安装实际属性、关键词和原生主体，原费用由各既有生产者负责。复制已经带赐福的物理材料不发布新授予，不能从附魔名字或card_created推断一次新授予。

CopyReceivedDarkGift携带原CardReference及原Event，校验注册的存储监听声明、原事件身份与真实事件库存，再复用原card_creation.install安装同一配方。复制不重新应用发现选项的资格过滤，因此可再次叠加同一赐福的属性，已有关键词也不使整次复制丢失。复制发布单独dark_gift_copied，不作为新的原授予回响；原授予若直接给瓦洛，本地按卡文接受一次自身复制，不递归。此自身与多载体接受政策仍须国服校准。

AbilityInstance仅新增可选dark_gift_id，明确关联真正由赐福授予的关键词、活体梦魇或自身战吼重复；严格核对原配方，不允许标记无关主体。数值沿既有created_minion_grant标记，费用沿普通附魔；没有新的GameState历史或第二个赐福执行器。当前复制、沉默、复生与基础复制仍走共享生命周期。旧原牌GrantDarkGift的短小利爪费用修正为Enchantment要求的整数，避免将CostSpec当数值写入。

[国服32.2说明](https://hs.blizzard.cn/news/24198086/)明确：瓦洛因自身甜美梦境从手牌进入牌库时保留所有黑暗之赐，其余增益仍清除，外部逆向移动不适用。实现先沿普通定义重置清除其他材料，再保留明确的赐福属性/能力，并从每个真实赐福标记恢复固定赐福减费；来源减费即使曾与短小利爪合在一行也不会保留。新增甜美梦境后，以原MoveCard把同一瓦洛置于本人牌库顶。已在牌库的瓦洛当前只获得配方、不重排，精确顺序仍待M6。

[国服34.6说明](https://hs.blizzard.cn/news/24242740/)修复过迅猛龙先锋回溯后瓦洛残留短小利爪的问题。实际回溯继续恢复原事务，复制没有独立保留层；专项覆盖真实迅猛龙先锋、原减费、待选恢复与重试，不以诊断事件重建已撤销收益。

玩家只从原可见随从信息读取赐福名称和实际数值，dark_gift_id、原事件、来源附件与队列不进入玩家投影。普通隐藏事件政策保持，未签名存档不提供来源认证。完整卡面与十种原配方保存在[数据包](../data/cards/wallow-v1.json)；实际验证、差异和下一项只维护原两份台账。部分明确官方规则已有依据，不代表完整M0正式池、M6时序或全部标准可达内容已闭合。
