# 脱困古神尤格的原生技能与随机施法

固定快照中的YOG_516为9费7/5中立泰坦，三个技能分别转控一个敌方随从、令敌方随从互相攻击、用1/1混乱触须填满手牌。每次该物理尤格完成自己的技能后，普通触发器接受两次随机施法。[六完整原行与八双语主面](../data/cards/yogg-unleashed-v1.json)保留根、三个choice-only技能、已有YOG_514和一条证据附魔；触须的完整定义、元数据和实际主体均复用，历史减费附魔不变成当前固有费用需求。

[官方32.0公告](https://hearthstone.blizzard.com/en-us/news/24187196)记载费用从10回调9，和本地完整行及本次官网主面一致；这不是当前国服热修对齐认证。完整十二泰坦名单和权重仍按原[参考来源](../data/cards/titan-reference-khaz-argus-v1.json)保存，不因本轮原生定义补齐而自动认证正式生成资格或所有递归依赖。

## 有限公共能力

`ForcePlayerMinionsAttackEachOther(player_id,remaining=None)`在公共强制攻击模块表达“指定一方的随从互斗”。原`ForceEachMinionAttack`的字段和默认双场范围保持；二者只共用候选筛选和顺序续接，不在卡牌层复制战斗执行器。

首次实际执行捕获该玩家当前活跃、存活、未标记消灭的普通随从驻留。随机选择尚未执行的原攻击者，再从该玩家当前其它合格随从中随机选防御者，交给既有`ForceAttack(combat_relation='any_minions')`。余下原引用随同一效果类型续接；新召唤物可以防御，不追加为原攻击者，已离场或转离该玩家的原引用跳过。零或单个合格随从时不抽样。初始名单、随机顺序、新体防御、零攻击资格和精确反应窗口继续作为本地政策记录。

驻留引用、随机状态、原已接受攻击及剩余向量进入原帧；等待后不重抽已选物理配对，独立注册表恢复、克隆、回放、死亡检查及失败回滚仍由原执行器负责。冻结、正常攻击次数、嘲讽、剧毒、吸血等强制战斗政策沿已有公共管线，不为尤格创建特殊伤害或死亡规则。

## 其余主体与接受边界

转控使用原强制敌方随从目标和`ChangeControl`，无目标时不能接受该主动技能，满场和生命周期按现有政策。触须攒聚使用`FillHandWithCard`：首次接受当前空手牌位数，再逐张普通交付；支持真实手牌容量，满手仍可接受技能，之后仍有两次随机施法。已有触须升级按本人原程序保存，不能因这次生成重置或另造白板触须。

`minion_ability_used`触发器只响应自身和完整三个原生技能。其它泰坦及另一物理尤格的使用不会额外触发本体。触发接受时的控制方启动`CastFromPool(count=2)`，沿完整当前普通可收藏法术查询、每次刷新、允许重复、自动随机目标和随机选项；不按职业或已实现状况裁池。自动CAST不伪装成手动出牌提交，也不支付手牌费用。

已接受的两次施法保留该玩家，首次施法后源死亡、沉默、变形或转控不重定向或取消该批；终局仍交原解释器截断。源控制变化时的触发捕获窗口、随机法术的官方资格/排除/权重及精确国服时序未校准。这些差异沿用已明确的本地政策，不作为等待实测的阻塞项；未知符合候选的定义仍明确失败并回滚，不能从完整池删除。

## 运行与验收边界

core784只增加一个效果类型，既有结构schema611、观察121、命令13和replay1保持。玩家不获得内部剩余驻留、随机状态或帧。普通行为测试使用不足400定义的小注册表，并从完整宿主复制已有触须的完整不可变声明、真实主体和原升级程序；关键完整宿主入口单独执行，避免每个断言重复建立三千余定义的对局。
