# 命运主宰尤格与六个轮盘结果

实际入口为 `DMF_004` 尤格-萨隆，命运主宰的已接受战吼。完整原行是10费7/5中立随从，原阈值标签为10；六个隐藏费用结果及两个附魔原行也完整保留在[固定数据](../data/cards/yogg-wheel-v1.json)。两份完整双语官网主面同时核对常规文本、剩余计数和就绪显示；现有源核验器仅省去原生显示分隔符与实时计数槽，没有删除10法术条件。

六个 `DMF_004t1`～`t6` 注册为非物理结果标签，费用0只用于隐藏费用描述符，不能当作正常手牌或随机池成员使用。两个附魔只保留原始证据。炎爆术沿用完整既有 `EX1_279` 定义及其摘要，没有覆盖原定义。

## 阈值、抽选与公共组合

原版尤格和命运之轮共用 `personal_hand_spell_count`：只计本人已接受、未失败的手动hand根，包含已接受但未完成的主体；排除反制、自动施法、抽到施法、历史重施与同次法术的额外重复。每个真实战吼独立捕获数量；不足10时不抽选。

公共 `ChooseRandomEffects.weights` 保存与完整有序选项一一对应的正整数权重；空元组仍使用旧均匀抽选及原RNG调用。轮盘当前按本地配置采用五项各19、燃烧权杖5。原候选、权重和所选结果进入内部事件；通知反应后的等待保存实际已选效果，不重新抽取或按当前支持程度删选项。

- 神秘魔盒：按原接受的个人施法数量、最多30次，组合原 `CastFromPool`；使用当前格式已绑定的可收集全职业法术、允许重复、随机合法目标和随机选择。原数据是“每施放过一个法术”，并非固定十次。
- 命运之手：原 `FillHandFromPool` 捕获有效空位，再交原生成/费用管线，新增有限的法术set-to-zero与当前回合截止组合。普通生成费用、容量、反应及到期清理保持既有执行器；其它未声明减费形状仍拒绝。
- 血肉诅咒：按原接受玩家、对手的顺序，分别执行原 `FillBoardFromPool`，保留各自容量、候选、随机和原召唤归因；两侧完成后才给当前活动存活友方随从授予突袭，包括原已在场的友方身体。休眠者不获得该授予。召唤数与额外入场仍交原内核。
- 夺心护目镜：`TakeRandomEnemyMinions` 在一个原窗中无放回抽取最多三个活动敌方实体，交原 `TakeCapturedMinion` 逐一转移；后续已变形、离场或失去原引用的对象跳过，不另抽替代。容量处理使用原控制转移政策。
- 吞噬之饥：原 `destruction_resources` 增加属性奖励载体，复用同一批摧毁、原死亡原因与完成续接。只从匹配本次原摧毁的实际死亡记录或仍被延迟清算的身体取攻击和非负剩余生命值，再用原 `BuffCapturedMinion` 授予原驻留的存活来源；来源回手或换驻留不获追补。休眠、地标、其它附带死亡或后来新身体不混入原组。
- 燃烧权杖：`CastSpellUntilHeroDies` 每次返回原 `CastSpell` 与同一有限请求，由原解释器逐次选择目标、执行炎爆术、处理反应和终局。来源死亡后仍保留原接受玩家继续；不能终局的状态显式耗尽原工程步数并回滚，不伪造胜负或默认为成功停止30次。

这些扩展只提供选择或组合请求。伤害、普通费用/过载、死亡、生成、控制转移和区域生命周期保持原执行器。公共源计数查询也供原版尤格复用，避免两套个人施法规则。

## 未确认政策

[官方发布介绍](https://news.blizzard.com/en-gb/article/23533210/its-madness-at-the-darkmoon-faire-hearthstones-newest-expansion)支持10法术条件与轮盘存在，文字没有认证整张概率表。[历史玩家讨论](https://www.reddit.com/r/hearthstone/comments/jg1i4n)涉及稀有5%结果；当前19/19/19/19/19/5仍明确是本地配置，没有标为国服认证。

个人计数的特殊窗口、结果是否单独形成CAST记录、精确官方概率及法术/随从资格、两侧填充顺序、突袭范围和额外召唤交互、控制满场，以及吞噬在光环/延迟死亡下取数的精确检查点均保留校准差异。当前六个结果由原战吼直接分发公共效果，结果标签不额外制造手动法术或独立结果CAST；实际随机法术及炎爆术仍有真实自动CAST记录。

燃烧权杖在免疫等状态下是否有额外正式次数上限，当前证据不足；本地采用原文本直到英雄死亡，并以工程预算显式拒绝不能终止的动作。全部这些规则边界及版本对齐按用户指示暂缓，继续推进已知生成依赖。

## 保存与信息

权重及新增有限请求进入严格公共效果解码，当前schema拒绝缺少新字段的旧存档。未抽选请求、已选效果、原控制引用、原摧毁原因、剩余施法请求均通过原等待/恢复/clone/回放管线。内部随机选择事件不在玩家事件允许表中；玩家只通过原公开控制、死亡、施法与状态观察到结果，不能得到候选、权重收据、RNG或frame。

实验池只为固定复现提供实际成员，不代表生产过去域或完整正式随机池。原定义、源记录、UI和历史证据保全另有逐项收据。执行结果、未运行检查与下一项只登记在原[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)。
