# 僵尸兽原生延系与存储成长

本契约处理独立角色参考中的 END_015、TLC_825、TLC_827。完整三原行、六个官网双语主面、原完整定义与构筑身份、两个原延系 profile 和女王的原目标 profile 固定在[数据包](../data/cards/zombeast-native-kindred-growth-v1.json)；[适配模块](../hs_sim/cards/zombeast_native_kindred_growth.py)先核整组，再登记捐赠能力。它不增加独立定义、标准合法根或候选池。实际验收和下一项只在原两份台账维护。

## 延系正文与条件对象

原部件提供自己的 on_play 包装器、成立正文及原亡语，合成体保留实际物理来源。END_015 的延系和亡语沿用同一个原生成正文；延系只执行原成立计划，亡语不伪造另一次延系或付款。TLC_825 沿原纯延系目标主体，以执行时当前合成体攻击力提交普通随从技能伤害。

`condition_definition`仅对原部件属于规范配方的已审合成体返回完整合成面，解析同时核两部件许可、完整声明和原蓝图。接受、恢复及已关闭历史核对采用同一条件对象；普通原牌保持原查询。实时请求仍检查物理 components 与配方精确一致，不能在另一合成体上借用原包装器。已经接受的历史从冻结 SourceAllocationFact.card_id 重建条件对象，后续当前实体变化不改写原条件。

条件采用完整合成面的印刷类型，是本地明确执行政策。例如当前僵尸兽面具有野兽和亡灵，原女王或 END_015 的正文可以被前一个本人真实回合中的亡灵牌激活。它仍使用既有 owner-turn 历史关系查询，不读取当前回合的牌来替换上一本人回合，也不制造回合或匹配记录。下一次延系的真实来源、max2计划、一次性消费、执行身份和完成尾继续由原解释器负责。此政策未取得对应组合的当前国服实测，不作为本轮前置，也不宣称官方校准。

## 原生条件目标

`profile_for_definition`对普通原牌返回原目标 profile；合成面只可从一个已有目标部件推导同一个原 profile，不新建虚拟原生声明。另一个部件若也要求目标则明确报未审范围，不用一种条件覆盖另一种箭头。完整合成定义必须与规范解析一致。

原 `effective_target_spec`、本人的 `play_conditions.kindred`、普通出牌合法性、自动物理入口和原目标历史重建共用该推导。未成立时无箭头；成立且有合法敌方随从时必须选目标；成立但域空仍允许出牌。恢复目标时保留原付款前缀与原 owner interval，后续回合关闭不把当前区间误作当时的前一回合。对手不得获得隐藏手牌条件、原历史或匹配证明。

## 一个原生存储成长实例

合成声明新增允许一个已审的原生 hand_progress：严格为本人结束事件、目标1、repeat、一个完成回调、一个条件、单位进度及有序 `(HAND, DECK)`，其余升级/进度形状明确未支持。完整合成面保留该原规格；实体继续通过原部件安装一个原生附件，不额外安装聚合副本。多个存储成长部件明确报未审，不能成为删候选的理由。

TLC_827 原 `attack=null` 且无 ATK 标签，两个完整官网主面均明确为零；只对该固定身份归一化为0，原行不修改。手牌和牌库沿原 HandProgressSpec 与 BuffStoredCard，战场沿原结束触发及属性管线。本人结束成长，对手结束不成长；实际抽牌、当前/基础复制、能力身份更新、回手重置和沉默继续使用原生命周期，没有额外成长计数器或属性结算器。

## 保存与范围

没有新增状态、卡牌字段、Effect或玩家事实类型；使用既有 hand_progress 字段和 kindred 布尔事实。core753/schema598，观察118/命令13/replay1；普通原声明与默认卡池身份保持，新增语义由机制版本保护。

名单和角色仍以[独立参考](m3-zombeast-local-reference.md)为准；这三个能力不能认证完整官方池、来源共池、权重或其它未确认成员。未知合格部件保留并显式失败。专项通过真实付费驯兽师、两次角色选择、合成体出牌及实际回合验证原延系/目标/成长，见[测试](../tests/test_zombeast_native_kindred_growth.py)。


原生正文可执行与其它卡牌能否识别其资格分开：既有托加物理检索仍只按原/拼装 kindred_profiles 成员识别首张牌，尚未识别带原生延系部件的规范合成 ID。因此本契约不认证该检索依赖已闭合，实际记录在原两份台账。
