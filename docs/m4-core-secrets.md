# 当前核心奥秘内容适配

完整审核配方见[固定数据](../data/cards/core-secret-effects-v1.json)，复用[公共奥秘解释器](m4-secrets.md)。实际进度、证据与下一项只在[项目状态](project-status.md)及[机制台账](mechanism-backlog.md)维护；本内容适配不是完整标准奥秘池或国服时序认证。

## 当前身份和完整主体

CORE_EX1_287法术反制、CORE_EX1_289寒冰护体、CORE_EX1_610爆炸陷阱、CORE_EX1_611冰冻陷阱使用固定37.0卡面的元数据/学派，复用原完整SecretSpec条件及行为。其唯一性key与旧版保持同一个原身份，不能同时部署旧版与核心版同一奥秘。普通付款、反制、源牌学校、隐藏槽位、揭示和消费沿原内核。

CORE_BAR_812绿洲盟军在当前有效敌方攻击以本人实际随从为目标且有场位时召唤真实DBF395水元素CS2_033，保留已有伤害后冻结主体。它不是隐藏退役CORE_CS2_033卡面，也不是另造白板token。旧CS2_033完整原行及元数据与固定37.0源逐字段匹配，未创建数据覆盖接口。

CORE_GIL_577捕鼠陷阱读取原完成手牌出牌事件和当前全局回合的实际手牌提交前缀，至少三次出牌且有场位才召唤实际6/6的GIL_577t。被反制的物理出牌仍计数，普通召唤和自动施法不额外计作出牌；下一全局回合重新计数。第三张时满场不消费，在同回合以后实际出牌且有场位时仍可满足，是明确待CN校准口径。

CORE_ULD_152压感陷阱在对手实际手牌法术完整完成、未反制且有当前可消灭的敌随从时，复用RandomDestroy随机消灭一个。候选使用当前active/live普通随从，不把死亡/休眠/惰性物体当候选；空场不消费或抽RNG。由随从等来源自动施放的法术不伪造手牌出牌事件；重复信用与准确完成窗口仍待CN校准。2021年[社区一手讨论](https://us.forums.blizzard.com/en/hearthstone/t/sword-of-the-fallen-crossroads-watch-post-interaction-broken/57789)包含同一施放区别，但不是当前Blizzard规则声明或国服实测。

## 原时序和边界

SecretSpec只声明事件/条件/主体。原CheckSecret逐项实时验证、在揭示前消费实例，之后反应可等待，主体继续由已有解释器派发；不能在卡牌回调直接改秘密槽位或暴露牌面。成功/错误选择、回滚、clone/独立注册表恢复、随机和回放沿原路径，不新增秘密执行器或保存字段。

冰冻陷阱仍使用原ReturnToHand(to_owner=true,cost=+2)。满手失败按当前[普通回手死亡契约](m2-full-hand-return-death.md)处理；m4-secrets原历史段落的“无死亡/亡语”不是当前行为。

七根K13a适配本身只有卡牌定义、纯条件及公共效果组合，当时没有修改执行内核、core314/schema268、观察85/命令12/replay1或历史代表v65，内容身份为constructed-cn37-preview-v13。后续独立爆炸符文使用下节的新公共指令，由新的机制及内容签名保护；不改写K13a历史验证。公开投影只输出原允许的槽位、揭示和结果，不输出条件、原instance ID或隐藏身份；两个同职业未揭示核心奥秘保持等价的对手观察/合法动作/历史。

## 后续独立的数值分流适配

K13a当时明确未注册的CORE_LOOT_101爆炸符文现由独立excess_secret_cards.py及[过量分流契约](m2-excess-damage.md)表达，完整卡面另保存在excess-secret-effects-v1.json，不回写K13a原七根数据或历史证据。共享一次SPELL预算，在随从与英雄之间正确分流；不能先给随从完整6伤害，再把过量点数当另一段伤害，否则实际伤害单位/法强信用可能重复。当前实际证据仍只在两份台账维护，不把内部通过等同于国服认证。

其他标准奥秘及正式生成池、自动/重复/特殊来源细节仍按实际卡需求和国服证据推进，不据这七张或静态数据宣称范围穷尽。
