# M4：一般休眠与唤醒

永久不可交互传送门共用本页生命周期，另有严格原生永久声明和不可唤醒限制，见[永久载体契约](m4-permanent-board-carriers.md)。下列版本及测试数量是一般休眠最初落地时的记录；实际终态仅在两份项目台账维护。

M4-02a 通用入口已通过内部契约测试。当前 `prototype-v75` / `core-effects-v75`，snapshot schema 74，代表包 `representative-m5-v38`；玩家观察为 `player-view-v44`，命令仍为 `player-actions-v7`。最终以国服验收，完整状态见 [项目状态](project-status.md)，阶段顺序见 [长期计划](roadmap.md)。

## 依据与范围

[外域的灰烬官方介绍](https://hearthstone.blizzard.com/en-us/news/23369565) 说明休眠随从入场后暂不可交互、双方可见，并在唤醒时产生效果。[32.4 补丁](https://hearthstone.blizzard.com/en-us/news/24205006) 修复过休眠牌复生后满血、以唤醒状态复生，以及再次休眠导致既有亡语重置的问题。[30.4 补丁](https://hearthstone.blizzard.com/en-us/news/24135706/) 明确修复过“休眠期间”效果不工作的情况。因此模型保留实体和附件，将休眠专属触发与普通场上触发区分。

这些历史官方资料没有给出完整执行顺序，也不证明当前国服部署。本批明确维护 **R-040**（开始回合、唤醒、攻击资格和死亡窗口）及 **R-041**（复制、临时附件、反复休眠和区域保留）两个待校准契约。集中实测继续安排在 M6；当前没有运行官方客户端。

## 状态与公共入口

- `CardDefinition.dormant_turns`：`0` 表示没有印刷休眠，正整数表示控制者回合倒计时，`None` 表示必须由条件效果显式唤醒。
- `Entity.dormancy`：为空表示清醒，否则为不可变 `DormancyState(id, remaining_turns, started_turn, permanent=False)`。实例 ID 与附件共同使用单调分配器，用于识别旧队列；它不是可沉默附件。显式永久实例使用原初始化层和额外严格标志。
- `MakeDormant(target_id, turns, source_id)`：使仍存活且活跃的场上随从进入休眠，保留实体 ID、位置、控制者、伤害、已消耗能力和持续附件。已经休眠的目标视为过期，不重置倒计时；休眠不能充当死亡替换。
- `AwakenMinion(target_id, source_id)`：显式唤醒定时或条件无限期休眠；原生永久实例跳过。正常唤醒恢复活跃资格和光环，发布 `minion_awakened`，执行 `on_awaken`。
- `AdvanceDormancy(target_id, turns, source_id)`：推进正数回合数，减至零即唤醒；无限期休眠不受倒计时推进影响。

实现见 [dormancy.py](../hs_sim/engine/dormancy.py)。休眠占据原场位，满场仍能原地唤醒。共同 `entity.active` 判据覆盖攻击、普通目标、伤害/治疗、沉默、附魔、区域操作、普通触发、法伤、费用/生命规则及攻击/生命光环；普通死亡检查跳过休眠实体。星舰建造有独立字段，不接受这些休眠效果，地标也不属于休眠随从。

`on_play` 在休眠入场时仍可运行，避免把带战吼的休眠牌错误当作无战吼。`dormant_triggers` 声明只在休眠期间有效的事件触发，供未来条件式唤醒复用；普通 `triggers` 暂停。已在前一窗口捕获的行为仍按既有捕获上下文契约结算。沉默后的能力不会因再次休眠/唤醒重新安装。

## R-040：回合与唤醒时序

控制者开始回合时，先冻结当前有时限的休眠实例，按既有入场顺序安排 `TickDormancy`。当前原型在普通 `turn_started` 反应之后、自然抽牌之前逐项执行这些倒计时。对手回合不递减；回合开始反应中新进入的休眠不在该批队列中。

队列携带实体、控制者和休眠实例 ID，执行时重查。如果旧休眠已经唤醒又被重新施加，旧倒计时不会推进新实例。一次唤醒产生选择时，剩余倒计时和自然抽牌都进入结算帧，保存后可以精确恢复。

唤醒不创建新实体，不新增召唤、打出、战吼或死亡历史。将攻击准备回合标为当前回合，普通随从需等待，突袭可攻击随从，冲锋遵循共同攻击规则；不重置本回合已用攻击次数。`on_awaken` 与普通唤醒事件反应/死亡检查沿用现有结算器窗口，尚未实现全套官方召唤时延迟反应。

以上跨触发先后、唤醒准备度、死亡前后与特殊召唤延迟均需国服目标版本校准，不能据此宣称精确复刻所有休眠卡。

## R-041：生命周期与复制

| 操作 | 当前原型契约 |
| --- | --- |
| 从手牌打出、直接召唤、场景建局 | 入场时初始化印刷休眠；手牌/牌库本身没有场上倒计时 |
| 变形成印刷休眠随从 | 保留原实体、按新定义初始化休眠；直接变形休眠中的目标仍不可用 |
| 当前状态复制已唤醒随从 | 复制既有伤害和附件，保持清醒；精确单卡复制差异待校准 |
| 基础复制、复生 | 使用印刷休眠；复生是新实体、1 点生命、复生能力已消耗 |
| 唤醒后回手或洗回 | 清除场上休眠，按已有区域重置表处理；再次入场重新初始化 |
| 外部施加休眠再唤醒 | 不恢复成基础牌，不清除伤害或永久增益，不重置亡语附件 |
| 临时附件到期 | 原型继续按既有回合期限移除；不是暂停计时；冻结沿用既有期限规则 |

普通复制/回手/洗回/转控都不能直接选中休眠实体。特殊“消失”、死亡转休眠、野性之种完整池、长期进度、休眠时特定变形，以及召唤后反应延迟，需要在 M5 以具体卡牌扩展，当前没有隐式模拟。

## 信息、恢复与代表卡

双方可以看到场上休眠牌身份，以及 `dormancy: {remaining_turns: n}`；无限期为 `null`，清醒实体的 `dormancy` 本身为空。内部休眠实例 ID 和起始回合不通过玩家 DTO 公开。新事件使用既有字段白名单；没有添加玩家可随意唤醒的操作。

快照严格校验休眠字段、类型、正倒计时、场上随从资格、实例 ID 唯一性/分配器和起始回合，拒绝旧 schema 1～73。回放外层仍为 schema 1，但规则版本、内容指纹和效果签名必须匹配。

新增四条真实代表记录均从已核验 SHA256 的本地提取文件逐条固定哈希：被禁锢的眼魔 `BT_004`（唤醒群体伤害）、被禁锢的邪犬 `BT_156`（两回合与突袭）、潜水俯冲鹈鹕 `TSC_647`（一回合与突袭）、玛维·影歌 `BT_737`（外部定向休眠）。代表台账现有 269 条真实记录、100 类机制；仍全部是实验样本，不作为正式卡池分母。

## K483 原休眠实例后的法术费用查询

TSC_657嗜睡的藻农使用已有无限期休眠、休眠专用触发及原`AwakenCapturedMinion`。只新增有限只读`DormantSpellManaProfile(card_id, goal=5)`声明，要求真实可用随从、非永久无限期休眠和一个`spell_cast_finished`休眠触发；声明进入注册表指纹，空映射保持默认指纹。

`DormancyState.first_cast_id`在普通休眠安装处记录当时`len(cast_history)+1`，原字段保持。当前内部政策只计算该原休眠安装后接受、由当前控制者成功完成的CAST，原先已开始但随后才召唤载体的同次施法不追计。查询直接汇总原完整`SpellCastRecord.source_cost.amount`，不增加第二份进度、金额账户或施法执行器。跨回合保持；多个原随从各有起点，后来再次休眠重新取起点。已完成的嵌套子CAST也参与汇总，不按外层cast ID上界误删已完成子施法。

声明存在的注册表对所有SPELL保留原接受费用报价，沿已有手动支付前输入及自动接受报价、开始摘要、完整历史与恢复校验；不按当前是否有休眠载体改变历史结构。减费后的实际报价、每个原重复CAST及自动CAST各读取其原金额，支付只由原路径执行。反制、失败、未完成、对方施法和非SPELL不推进。这里的“费用”采用原有效报价，不按印刷数字或重新报当前价格；自动/替代资源及精确源资格政策仍待CN37校准。2022年[玩家原报告](https://us.forums.blizzard.com/en/hearthstone/t/another-bad-interaction/93234)只支持冰冻陷阱退回的已付款法术不唤醒这一历史观察，不认证当前完整国服规则。

达到五点后仅返回绑定原随从驻留和原dormancy ID的`AwakenCapturedMinion`。等待中已唤醒又重新休眠的同ID实体不被旧请求唤醒；原唤醒、突袭、伤害、死亡、选择、回滚和回放保持。来源费用观察与数值主体权限分开：`spell_source_costs.amount`仍要求原法术本身声明生产者profile，不能借观察所保存的报价调用任意未声明主体。

新增字段只在宿主保存，玩家仍只接收原休眠DTO；字段严格为正且不超过当前CAST分配边界。schema564/core705拒旧563及更早，不自动补默认起点迁移历史状态。精确接受/完成时序和全部费用来源仍属M6边界，实际执行与验收只在原两份台账登记。


## K485 原休眠实例后的实际死亡

DormancyState新增first_death_id，两个原安装入口均保存state.next_death_id。它是原单调分配边界，不是death_history长度；回溯保留的死亡ID跳号不能改变本次休眠的起点。已有first_cast_id及全部原字段保持；新字段严格拒绝布尔/非法整数和未来边界。

deaths_since_installation只读原death_history，计入边界后的实际BOARD随从死亡，双方均计；武器/英雄记录、安装前死亡和失败尝试排除。死亡批次中先已接受全部死亡，随后亡语才创建的新休眠载体不追溯消费生产者或同批旧死亡。没有平行进度计数、资源支付或另一套唤醒执行器。

通道沉眠者TOY_866声明原无限期休眠和minion_died的dormant_trigger；达到七次只返回已有AwakenCapturedMinion，绑定原驻留及原dormancy_id。自然回合不推进它，同一物理来源再次进入休眠有新起点，多个来源彼此独立；普通唤醒不构成新召唤，工作等待/恢复和整体失败继续由原解释器负责。精确国服批内窗口及特殊材料继承仍待M6；保存一致性不认证未签名来源。实际验收仅在原两份台账维护。


## 原生合成材料的入场政策

上文普通休眠牌允许原生on_play/战吼入口的政策保留。真实僵尸兽材料现支持TSC_647的单个正整数印刷倒计时，合成面保留该值后仍交原initialize_dormancy与原倒计时/唤醒流程。原DormancyState、Effect和恢复载荷字段没有变化；清醒当前复制、基础重建、实际阿穆纳伊的休眠亡语复制、复活/复生、回手和变形沿原物理生命周期。

[历史原始反馈](https://us.forums.blizzard.com/en/hearthstone/t/zombeast-dormant-battlecry/98303)反映潜水俯冲鹈鹕造物的战吼被跳过。当前采用独立且明确待CN37校准的原生合成入场政策：合成安装一个纯印刷crafted_dormant_entry声明，物理休眠存在时不接受其捐赠on_play/战吼/连击主体，唤醒后恢复入口资格，但不补执行过去的战吼。普通休眠牌没有此声明，继续原政策；这条历史玩家观察不认证当前全部官方执行窗。

声明复用既有AbilityInstance字段并由实体/死亡载体校验绑定原有序材料，不能任意授予到普通牌或没有原时钟的造物。合法沉默移除文字不取消独立物理休眠；持有入口而剥掉阻断声明的快照被拒绝。多个、无限期/条件式原生材料未由本次开放，不推定组合语义。完整资格、精确时序与实际验证只在原两份台账维护。
