# 独立场上交互物与手牌投入

真实临时任务、五费奖励及原裂隙沿[接卡契约](m3-underfel-rift.md)使用本页公共入口，三个野兽复用原定义并携带原召唤归因。下文“任务完成来源后置”和隔离适配范围保留为基础阶段记录；当前接线不改变原容量/次数/投牌待校准政策。

本契约只表达一个实际基础缺口：场上不可触碰的物体允许本人每个真实回合投入一张手牌，再执行声明的主体。必要来源是邪能地窟裂隙的开门法术和物体；任务完成来源、特殊授予及跨机制组合后置。实际执行结果和下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)登记。

## 证据及本地政策

[官方物体卡库](https://hearthstone.blizzard.com/en-us/cards/120968-underfel-rift/)的检索结果支持选择裂隙、投入一牌、召唤两个随机邪能野兽、每回合一次；[官方法术卡库](https://hearthstone.blizzard.com/en-us/cards/118227/)支持开门来源。[34.0.2公告](https://news.blizzard.com/en-us/article/24247520/34-0-2-patch-notes)将奖励费用改为5，和本地完整行一致。这些证据没有证明国服当前补丁全部精确执行规则；直接卡库页面的动态导航也没有提供完整时序。

[必要完整raw](../data/support/interactable-basics.json)包含任务、附魔、开门法术、物体和三个野兽的七条原始行，每行保存完整内容及摘要。只为必要五个实体提供隔离测试适配，没有注册任务或附魔，没有扩充生产代表或正式生成池。原物体为MINION、0/1、不可触碰、隐藏身材和费用、允许选手牌、交互费用0；这些标签用于界定载体，不被当作完整执行器。

当前明确保留以下待国服校准政策：物体占一个普通场面位置并附加在末尾，满场安装失败；安装后即可投入；每个物理物体按真实本人回合计一次；投入先移除原手牌并揭示卡面，随后按普通检查点执行主体；两次普通随机召唤分别抽选，满场跳过召唤且不消耗该次随机。精确位置、容量、次数刷新、揭示与优先级、抽样和满场规则不能凭内部测试声称已与官方一致。

## 声明与入口

`CardDefinition.interactable=InteractableSpec(behavior_id)`声明一个固定主体。载体必须是不可收藏的0/1 MINION、`corpse_value=0`；除身份、印刷费用、元信息和交互声明外，所有普通生命周期字段保持默认。不能同时声明战吼、亡语、触发、主动随从能力或其他普通能力。物体不是可打出的手牌，不能通过普通生成到手或召唤伪造。

`InstallInteractable(player_id, card_id, source_id=None)`验证来源和声明，复用普通BOARD实体身份、区域及容量，成功时发布`interactable_installed`，失败时发布`interactable_install_skipped`。安装不发布`minion_summoned`，不进入普通随从入场主体。

`UseInteractable(player_id, entity_id, card_entity_id)`是独立外部动作。Game先检查真实行动方、普通对局阶段和待选状态，再检查本人当前BOARD物体、次数和本人当前HAND可存储牌。合法动作按每个可用物体与本人每张手牌枚举；空手无动作，非法或旧引用明确拒绝。未增加自由输入的效果、次数或费用。

## 支付、时钟与结算

接收动作后捕获当前手牌`CardReference`和实际获取身份，用既有`RemoveFromGame`将同一个物理实体移入私有SETASIDE，显式`reveal=True`。这不是打出、施放、弃牌或死亡，不支付该牌费用，也不执行被投入牌的主体；交互本身费用固定0。

同一个接收检查点保存`InteractableUseRecord`及`interactable_use_started`。记录绑定物体身份/场上presence、原当前卡面、获取、真实`OwnerTurnRecord`、动作和移除收据。原移除反应开始前，手牌和这次用途都已消费。次数查询直接从不可变历史和当前或最近本人区间计算；只有下一次真实本人开始创建新机会，不采用全局回合奇偶或独立可变缓存。

原主体交给既有`BehaviorCall`和效果解释器；卡牌包为裂隙声明两次顺序`SummonFromCandidates`及三个完整野兽。追加`FinishInteractableUse`，完成后保存`interactable_used`事件。正常反应、死亡检查、等待选择和累计结算预算继续由原结算器执行，没有第二套随机或选择流程。

## 不可触碰与玩家信息

物体保存精确bool的`Entity.interactable_object`。该标记同时排除`active`和`is_character`，普通攻击、目标选择、伤害、消灭、增益、沉默、回手、变形及原活跃能力流程沿既有资格检查跳过。标记必须和静态声明一致，存档不能给普通随从加标记使其不可触碰。物体不产生死亡历史或尸体。

玩家仅见原公共身份、控制方、BOARD位置、MINION类型及`interactable={used, uses_per_turn:1}`；内部0/1、原用途/获取/presence与SETASIDE不提供给玩家。投入牌只沿原移除事件公开卡面和来源区域，没有可复用的已移除目标句柄。

玩家命令`{type:'use_interactable', object:公共句柄, card:本人手牌句柄}`按绑定座位和当前revision提交，再经Game同一校验。敌方手牌句柄、原始实体ID、额外字段和失效句柄不能授权投入。

## 恢复与限制

新动作参与原动作codec和回放；记录、标记和原待选帧进入快照。边界核对原接收事件、前一完整移除收据、完成事件及实际待选队列中的Finish；正常playing最多一个未完成根，必须绑定原动作。等待后继续不重新投入或重新消费，异常由原事务整体回滚，克隆和独立注册表恢复复用原编码器。

终局可以留下已投入、尚未执行主体或Finish的历史，原结算器废弃后续工作；不会产生未来刷新或取回义务。未签名快照的这些一致性检查不是来源认证，也不外推任意物体离场、转控、动态主体或其他输入/收费政策。

该入口首次采用schema167（明确拒绝旧1～166）、玩家观察73／命令11；外层replay1保持。机制版本随实现提升，未使用交互声明的旧卡牌注册表忽略新增空字段，保留其声明指纹。

## 原玩家输入的惰性行

B16修正既有公开观察与原目标输入校验不一致：原输入也接受已经公开的六字段行`ref/card_id/controller/zone/kind/interactable`。只能是BOARD中的MINION，使用摘要只能有精确bool的used和精确int的uses_per_turn=1。普通战斗字段、费用、种族、主体、内部历史和其他附加字段均拒绝，不能为通过校验给玩家补回隐藏身材。

原输入与被冻结物理事实对照时，公开身份／控制方／区域／种类必须一致，原卡牌定义必须确有交互声明，原物理状态仍为不参与战斗、0攻击、1生命且未受伤、无武器耐久、关键词或种族附加状态。普通随从不能借这种最小行隐去真实属性，真正物体也不能删掉使用摘要；引用及双方完整位置继续按原契约核对。

实际付款前仍由完整原状态重新投影全部输入，包含真实used值；已关闭收据保留当时接受的输入，不能拿当前回合的使用状态改写旧值。结构校验不将未签名的历史输入变成来源认证。普通目标域继续排除物体，公开回调仍只有分离的玩家副本。

此校验修正采用prototype-v174；效果包core-effects-v173、schema168、观察74、命令11及replay1保持。没有新效果、状态字段、命令或卡牌声明，原B14暂定国服政策继续开放。实际验证及下一项只见[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)。

## 自主不可触碰物体的有限声明

[萨格拉斯契约](m3-sargeras-portal.md)增加PassiveBoardObjectSpec作为同一静态槽的另一精确类型，复用惰性BOARD标记及容量，不提供投入动作。它只允许印刷本人结束触发和声明认可的单位标记；原InteractableSpec仍只允许投入主体，原InstallInteractable不能安装被动物体。观察121的passive_object行仅公开升级单位，原interactable行与原用途历史保持。下文及此前的“无触发”约束继续适用于投入物，不能拿新类型放宽旧声明。
