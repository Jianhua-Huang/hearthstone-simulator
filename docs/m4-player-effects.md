# 持续目标、咒符与玩家长期效果契约

真实回手禁止须绑定成功到达的原物理对象；控制归还和“下个本人回合结束”按实际原玩家区间计时，普通/对方/结束反应安装分别接受。有限入口和仍未支持的控制层叠边界见[时间效果契约](m3-temporal-spell-effects.md)。

古神降临与泰坦降临使用既有turn_rule/allowed_card_types，抽牌及其反应完成后复原水晶，再安装仅随从/仅法术的当前回合资格。手动根与原付款证明共享现有门禁，自动施法不受该手动权限拦截，细节见[契约](m3-draw-retention-limits.md)。

显式玩家健康来源保存原物理事实与受益方，普通玩家效果默认保持原语义；逻辑伤害委托原健康层，下一真实对手期间复用原实例/费用/时钟。严格捕获、解码、玩家隔离和统一格式常量见[玩家健康来源契约](m3-player-effect-health-source.md)，实际进度与验收仅在两台账。

当前运行时 `prototype-v75` / `core-effects-v75`，snapshot schema 74，代表包 `representative-m5-v38`，观察 `player-view-v44`、命令 `player-actions-v7`。本页是 M4-03b 内部原型契约；国服目标补丁的精确交互仍待 M6。总体进度见 [项目状态](project-status.md)，阶段顺序见 [长期计划](roadmap.md)。

## 状态与定义

`Registry.register_player_effect(PlayerEffectSpec)` 注册不可变定义，纳入校验、冻结与指纹。定义包括公开展示卡、种类、持续期、计时边界、触发行为、到期行为、加法法伤和友方随从属性光环。未知定义、行为、过滤卡或不支持的种类明确拒绝。

`PlayerState.player_effects` 保存独立 `PlayerEffect` 实例：实例 ID、定义 ID、原始来源实体和卡牌 ID、创建回合、获得顺序、剩余己方回合数。它不附着于英雄或来源随从。来源死亡、沉默、回手、变形、转控，以及英雄替换均不撤销效果或改变受益玩家。复制来源不会复制已经建立的玩家效果；再次执行战吼可以添加新实例。

实例共享附件 ID 分配器，获得顺序共享入场顺序分配器；不复用 ID，同名实例独立计时、独立移除、数值叠加。`persistent` 持续整局，无倒计时；`objective`、`sigil` 使用正整数持续期和 `turn_started` / `turn_ended` 计时策略。当前只支持公开玩家效果，不能用来存储未揭示奥秘。

## 安装与结算

- `AddPlayerEffect(player_id, spec_id, source_id)` 安装效果，来源必须存在；`RemovePlayerEffect(player_id, instance_id)` 只移除指定实例，失效引用跳过，主动移除不执行到期行为。
- 持续法术通过 `CardDefinition.ongoing_effect_id` 声明安装，普通根是不带普通 `on_play`、目标或任务定义的实体法术；有效抉择根可以具名声明[安装许可](m5-ongoing-choose-roots.md)。共享普通出牌费用、事务、完成事件和玩家命令；法术本体进入墓地，持续规则由玩家实例保存。
- 默认 `max_ongoing_effects=5`，只限制定时效果；整局效果不占此容量。手动打牌在支付前检查容量，内部效果安装失败则记录失败并继续。v26 同时检查 `max_secret_zone`：奥秘、任务和定时效果共同计数，整局效果不计入。默认五及具体混合占位仍是 R-048 暂定规则，须国服校准。
- 触发与场上实体共同按当前玩家优先、获得/入场顺序捕获；回调收到独立状态副本及 `RuleContext.player_effect`。已捕获的普通触发不因实例后来移除而撤销；倒计时则重新检查实例和预期剩余值，防止旧任务扣减新实例或重复扣减。
- 每个回合边界先固定待计时实例，再发布回合事件；事件中新建的实例不会在同一批立即扣减。己方结束时先普通反应，再计时，再解冻/临时附件到期/下一回合。己方开始时先普通反应、已有休眠倒计时、玩家效果倒计时，最后自然抽牌。这些精确窗口仍为 R-047 暂定契约。
- 倒计时归零先移除实例、刷新光环、发布到期事件，再执行捕获的到期行为。多个咒符逐个结算，各自读取当时场面，段间处理死亡与亡语。游戏结束立即停止后续队列，不强制消耗剩余效果。

## 数值与扩展边界

玩家法伤与存活角色的法伤相加，由统一伤害准备层在执行时读取；仅作用于符合既有法术伤害分类的包，不增幅普通效果伤害。烈焰咒符使用到期时法伤，施放后新获得或失去的法伤会影响它。

`PlayerAuraSpec` 提供友方活跃场上随从的攻击/生命加法光环，可按显式卡牌 ID 列表过滤；空列表表示全部。它与实体光环同时重算，支持新随从、变形、控制权变化、复制和沉默交互；持续光环不会因目标沉默消失，也不会被烘焙进复制的永久属性。移除生命光环沿用已有生命钳制规则。安装/移除在发布事件前刷新派生属性，确保捕获回调读取更新后的数值。

丹巴达尔桥使用召唤事件产生永久附魔；因此其增益可以沉默，且持续目标到期后已经获得的增益仍保留。这与持续属性光环是两种不同的公开原语。

当前还没有统一实现长期费用替换、法术转向、英雄技能改写、免疫/伤害替换、隐藏长期状态、额外回合，以及每张特殊效果的定制交互。持续效果受益者独立于来源，但通用伤害包仍沿用现有来源/学派规则；若后续卡需要来源变形或转控后的特殊伤害归属，必须增加明确契约，不能仅凭 `source_id` 推断全部语义（R-049）。

## 玩家信息、快照与恢复

双方观察公开 `player_effects` 列表与持续效果容量，重复效果分别展示。每项只包含 `effect_key`、`card_id`、`effect_kind`、`remaining_turns`，不暴露全局附件 ID 或隐藏来源实体 ID。安装、计时、到期、移除事件进入白名单日志，字段和数值由严格定义校验；其他诊断数据不自动公开。

快照保存实例、捕获上下文、带守卫的计时步骤、待执行回调及原回合结束状态。到期行为请求选择时，可保存、恢复、继续；剩余计时与自然抽牌只执行一次。非法状态、超额容量、重复实例/顺序、未知定义、错误期限和陈旧派生属性明确拒绝。执行失败回滚整个外部动作，包括时钟、实例、信息与分配器。

新格式为 schema 74，旧 schema 1～73 明确拒绝，外层 replay schema 仍为 1。需要旧引擎读取旧存档，没有隐式迁移。

## 后续有期限持续效果与抉择组合

普通持续法术保持原AddPlayerEffect队列；具名install_then_branch抉择根在原CAST窗口调用同一安装器，再捕获独立分支视图。法伤和光环已安装，安装反应可先执行；后续触发/到期各自独立，PlayerEffectSpec拒绝engine.choose_one作为未来文本。现有实例身份/来源/获得顺序、共享容量、owner时钟、移除/到期、等待恢复和回滚均复用，不把整局或持续效果绑定到当前来源生存状态。所有分支仍安装相同静态效果，分支依赖文本须独立持久契约；详见[组合契约](m5-ongoing-choose-roots.md)。
