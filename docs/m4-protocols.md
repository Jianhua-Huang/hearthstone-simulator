# M4-01b-02：埃索达协议与可保存的后续效果

当前运行时 `prototype-v75` / `core-effects-v75`，快照 schema 74；代表包 `representative-m5-v38`，观察 `player-view-v44`，玩家命令 `player-actions-v7`。埃索达及三个指令选项已接入实验包，代表记录共 260 条，其中三个是专用选择描述。内部测试通过不代表国服官方时序已校准。范围与下一项见 [项目状态](project-status.md)，基础机制见 [星舰契约](m4-starships.md)。

## 1. 来源与规则边界

埃索达 `GDB_120` 与三个选项 `GDB_100a/b/c` 的文本、标签和哈希来自锁定的本地 build 36.6.0.251952 快照。[官方 31.0.3 补丁](https://hearthstone.blizzard.com/en-gb/news/24161533) 支持其费用/身材改为七费 6/8；该公告不说明协议的完整时序。

当前采用的顺序是：打出埃索达并支付其费用 → 检查己方正在建造的星舰 → 免费发射那艘星舰 → 完成组件发射能力和死亡阶段 → 读取该舰状态并提供三个协议 → 选择后执行分支 → 完成出牌。没有己方建造实体时，战吼不发射也不提供选择；已发射舰体不满足条件。埃索达仍需要正常随从出牌的空位，发射沿用舰体已有位置。

**R-034 为待校准约定**：协议的精确请求窗口、数值捕获窗口、损伤生命取值和来源归属尚未有国服对局证据。当前以提供选项时的状态冻结攻击、剩余生命和组件列表；选择请求/选择提交的反应不重新计算这些操作数。协议伤害来源为埃索达战吼，不继承星舰自身的吸血或法术伤害。范围不同的特殊来源规则不能仅凭本批推断。

绑定的是实际发射的实体 ID；后续新建星舰、复制舰体不会替代它。若该舰已死亡，使用其最近一次含组件的死亡记录；生命操作数不小于零。若对应实体已变形成普通随从、失去组合身份，当前跳过协议。回手/转控/变形/致死状态及光环的官方行为仍需 M6 校准，不视为已认证规则。埃索达本体离场不自动取消已触发的战吼；英雄死亡沿用终局停止队列的原型政策。

## 2. 通用后续执行接口

`LaunchStarshipEffect(..., followup=(...))` 接受不可变效果元组，只有指定建造实体成功发射才安排它。队列先执行随机发射能力，再执行 `FinishStarshipLaunch` 及其死亡反应，最后执行 followup。过期发射不会误执行后续效果。免费发射继续遵守“消费下一次减费但不付法力”的 R-032 契约。

`InvokeBehavior(behavior_id, source_id, player_id, target_id=None)` 在执行时读取当前状态，调用已注册的纯行为，并复用统一效果队列。它不保存 Python 闭包，行为和实体引用必须存在。埃索达以此在发射完成后生成协议选择；内核不按埃索达卡牌 ID 特判。

发射能力可以先请求其他选择。原后续回调、剩余发射能力、阶段结束标记均进入结算帧；恢复后不会重复发射、扣费或重新随机排列。协议内部新增的伤害/生成效果也可触发嵌套选择，其剩余工作同样保存。

## 3. 三个协议与公共原语

| 协议 | 当前执行契约 |
| --- | --- |
| 紧急修复 `GDB_100a` | 两条独立 `GainArmor`，每条金额为捕获的星舰剩余生命；可以各自触发反应，不合并成一条双倍金额 |
| 攻击队形 `GDB_100b` | `SplitDamage` 将捕获攻击分成一点伤害，每次重新查询该敌方玩家当前英雄/随从并随机选取 |
| 乘务转运 `GDB_100c` | 按组件列表顺序、保留重复项，分别创建基础定义的复制并将费用设为一；不复制死亡组件原实例的增益 |

`SplitDamage(player_id, amount, source_id=None, include_hero=True)` 当前明确表达**非施法效果的一点分段伤害**。每次命中经过公共伤害与死亡检查：圣盾可以吸收一发，死亡与亡语产生的新实体影响下一发候选。排除非活跃建造、已致死/标记消灭的角色；没有候选即停止。伤害修正、防止、重定向与吸血仍由公共伤害层处理。零伤害不抽随机；工程预算耗尽报错回滚，不伪造游戏平局。

它尚未定义“法术总段数加法伤”等规则，不能直接用来宣称奥术飞弹等法术已经实现。分段伤害与普通触发的精确官方窗口继续由 R-034/M6 跟踪。

`AddToHand(..., cost=CostSpec(set_to=1))` 在发布创建/入手事件之前安装费用附件。新实体与费用在同一效果中建立，入手触发和事件时点观察直接看到一费；没有依赖“最后一张手牌”的易失引用。费用附件复用 `costs.attach_cost`，来源、复制、沉默和区域移动遵守原生命周期契约。指定费用的卡牌类型过滤必须匹配，错误整次回滚。

满手生成按既有烧牌规则处理：仍创建对应的墓地实体，但不产生场上死亡记录、尸体或亡语。多张生成按队列逐条执行，前一张的反应可能改变后续容量。对手手牌身份仍受现有知识策略限制；本批不新增推理式身份揭示规则。

## 4. 专用选项不是可打出的卡牌

三个协议保留原始 SPELL 标签供来源审计，但运行时显式标记 `CardDefinition.choice_only=True`。零费用仅是隐藏费用的描述占位；执行行为由协议选择分支提供，不是空白零费法术。

这类定义可以作为 `ChoiceOption.card_id` 展示，不能加入构筑、在场景中创建实体或生成到手牌/牌库。候选池若错误纳入它们，操作明确报错，不静默删去候选。损坏快照中出现此类实体也被拒绝。标记进入注册表指纹；三个选项的名称、ID、来源数据均保留。
