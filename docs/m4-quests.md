## 定义与运行状态

任务仍是通过 `PlayCard` 支付并打出的法术，进入独立 `Zone.QUEST` / `PlayerState.quests`，不占随从和地标场位。每张卡声明 `QuestSpec(kind, stages)`；`quest/sidequest/repeatable_quest` 一阶段，`questline` 三阶段。重复任务使用印刷 `Keyword.QUEST`，奖励结束后保留同一物理任务与原槽位，以新的 `QuestProgress.id` 开始下一周期，旧周期已捕获进度不能推进新周期；不新增玩家动作或另设计数器。每阶段 `QuestStageSpec` 声明展示牌、目标数量、监听事件、进度行为及奖励行为，注册表验证全部引用。

实体上保存独立 `QuestProgress(id, stage, value, keys, completing)`。实例 ID 防止移除后的旧效果继续推进；阶段编号防止上一阶段捕获的事件计入下一阶段。第二、三阶段用非物理 `choice_only` 描述展示，当前保留同一根任务实体，未模拟官方内部实体 ID 的变化。

进度行为是纯回调，通过公共效果修改计数。例如按自身召唤事件推进：

```python
def progress(ctx):
    if ctx.event.player_id != ctx.player_id:
        return []
    q = ctx.source.quest_progress
    return [AdvanceQuest(ctx.source_id, q.id, q.stage)]
```

`AdvanceQuest` 支持非负数量和可选唯一键；有键时每个不同键贡献一次，重复键不重复计数。`ResetQuestProgress` 清空当前阶段数值和键，供卡牌声明回合内等期限；没有自动将所有任务按回合重置。`RemoveQuest` 明确移除任务，不产生随从死亡或亡语。未知行为、非法进度和损坏状态均拒绝。

## 激活、开局与生成

枚举、玩家提交与执行共用激活检查。当前允许一个普通任务或任务线，与不同支线任务同时存在；同名任务不可重复激活。任务区域默认容量五，可由 `Ruleset.max_quests` 明确配置；v26 同时用 `max_secret_zone` 检查与奥秘及定时玩家效果的共享容量；默认五和具体混合占位仍待 R-048 国服校准。满随从场不阻止任务出牌，非法出牌不支付费用。

普通任务与任务线在洗牌及开局回调后优先进入原有三/四张起手牌，不额外增加手牌数量；支线任务不享有保证。可以换走任务，替换先从其余牌库取得，再洗回弃选牌。多个保证起手的任务会一起占据原手牌名额；超过配置名额当前明确拒绝，特殊开局选择规则尚未模拟。

静态随机生成/发现池依据独立关键词元数据排除普通任务和任务线，即使对应牌没有可执行适配也按规则排除；支线任务仍可生成，合格但未实现的牌继续报错。牌库中的任务可以正常抽取、复制或检索；特殊施放、盗取和自动部署入口仍待实际卡牌扩展。

官方设计说明支持“打出后才能推进、双方可见、起手保证”，[来源](https://hearthstone.blizzard.com/en-us/news/20567342)。官方资料片说明确认任务线有三个阶段及分段奖励，[来源](https://hearthstone.blizzard.com/en-gb/news/23706628)。29.0 明确保留同名任务/任务线/支线任务的单实例限制，[补丁说明](https://hearthstone.blizzard.com/en-us/news/24064735)。区域总容量、不同主任务并存及特殊起手规则仍需国服校准，不能从这些简短说明推导全部细节。

## R-044：捕获、完成与奖励窗口

任务按当前控制者/入场顺序加入既有事件捕获序列。行为读取事件时点副本，返回带实例和阶段标识的推进效果；事件不会从历史日志反向补算。任务本身的 `card_committed/card_played` 不计入自身进度。成功召唤按既有 `minion_summoned` 事件推进，满场失败不产生计数。

达到目标后钳制计数并标记 `completing`，停止接收新进度，发出阶段完成事件，然后执行奖励。奖励中等待选择时保留任务占位、完成标志及后续帧。奖励完成后进入下一阶段或移入墓地；上一阶段溢出不转移。奖励中的事件可以推进其他任务，不推进尚未开始的下一阶段。捕获、移除、奖励导致终局以及多任务之间的具体顺序仍为原型约定，待国服 M6。

## R-045：身份、容量与可见性

任务身份和进度公开；手牌中的任务仍是普通隐藏手牌。玩家 DTO 的 `quests` 列表包含根实体句柄及 `quest` 描述：种类、当前阶段展示牌、阶段数、进度/目标和完成中标志，不公开实例 ID、内部唯一键或回调名。任务日志保存事件时点的同样描述，阶段变化不会回填旧日志。

主任务互斥、五个任务位、同根实体贯穿阶段、超量保证起手拒绝，以及特殊复制/移除/重新施放均列为后续校准或扩展项。任务和奥秘各自保存区域/实例，共同检查总容量，已接入的整局玩家效果另有独立契约，不表示全部特殊长期规则已完成。

## R-046：英雄获得攻击力

新增 `hero_attack_gained` 事实事件，在单个效果检查点重算后比较英雄攻击力的正向差值，供游园迷梦等条件消费。包含已装备武器的数值，但不把武器随回合亮起当作再次获得攻击力；设值只有正增量才推进，临时攻击到期不增加计数。

22.4 修复过游园迷梦与装备感知宝珠后的攻击力进度，[官方说明](https://hearthstone.blizzard.com/en-us/news/23761712)。本实现对武器替换、负值钳制、到期恢复、英雄替换及单个复杂效果中的多次变化采用“检查点净增量”契约；并未据此宣称所有攻击力获得窗口与官方相同。

## 可重复任务的独立周期

`QuestSpec('repeatable_quest', stages)`声明一个可重复的主任务，仍只允许一个阶段并使用原`Keyword.QUEST`。普通任务、支线任务与三阶段任务线保持原声明和终态。注册表核对物理法术、首阶段身份、原任务关键词以及全部进度/奖励引用；没有新的卡牌类型、动作、关键词枚举或持久字段。

完成本轮后先执行原奖励，奖励等待选择期间任务保留占位并维持`completing`。奖励完成后发布原`quest_completed`，同一物理任务保留在`Zone.QUEST`，用原附件分配器创建新的`QuestProgress`实例，清除计数/唯一键并发布`quest_stage_started`。不回手、不再支付、不重新打出任务，不释放主任务互斥及共享区域占位。新的实例身份让旧周期已经捕获的推进、重置、完成及结束指令失效；溢出不带入下一轮。奖励导致移除或终局仍由既有解释器处理，不强行重启。

沿用R-044的完成/奖励窗口：奖励事件不推进尚未启动的新周期；随后真正独立的事件可以继续推进，多次完成没有人为循环上限，仍受原结算预算保护。这是明确的内部窗口政策，尚未进行国服校准。恢复、回放、异常回滚、起手保证、换牌、随机生成排除与玩家信息复用现有路径；公开种类增加`repeatable_quest`，公开计数/阶段布局保持，内部实例与唯一键不提供给玩家。

## 后续显式长期载体抉择

有效任务/支线任务/任务线根可显式声明install_then_branch和独立即时分支。原CAST窗安装后，分支事件可按原实例/阶段政策推进，但本根commit/play仍排除。长期进度/奖励独立，完成后重复可新安装；不能依据当前物理预选猜原分支。见[公共契约](m5-long-term-choose-roots.md)，实际验证与下一项仅维护在两份主台账。


区域数量条件另有两个有限订阅：QUEST_FULL_BOARD_TURNS和QUEST_FULL_THEN_EMPTY_HAND。它们在原通知点按实际规则/容量预筛选，再调用既有进度行为；不是通配事件或另设计数器。原实例/阶段、奖励等待和公开进度保持，具体接受与机制身份边界见[任务区域状态契约](m3-quest-area-state.md)。
