# 奥秘、隐藏区域与打断窗口

当前核心内容适配见[核心奥秘契约](m4-core-secrets.md)，旧代表身份保留。下文为原M4历史契约；冰冻陷阱满手失败的当前行为已由[普通回手死亡](m2-full-hand-return-death.md)修正为正常死亡/适用亡语，不再采用下文旧“无死亡/亡语”表述。准确国服时序和正式完整池仍未认证。

原M4批次记录为 `prototype-v75` / `core-effects-v75`，snapshot schema 74，代表包 `representative-m5-v38`，玩家观察 `player-view-v44`，命令仍为 `player-actions-v7`。这是 M4-04 内部机制契约；国服精确时序尚待 M6，正式完整卡池尚待 M0/M7。进度见 [项目状态](project-status.md)，顺序见 [长期计划](roadmap.md)。

## 定义、实例与区域

实体法术声明 `Keyword.SECRET` 和不可变 `SecretSpec(key, events, condition_id, behavior_id, turn, requires_board_space)`。注册表独立登记纯条件回调，冻结时校验全部条件/行为引用，定义和条件标识参与指纹。相同 `key` 表示同一奥秘身份，可用于显式关联基础/核心别名；不会仅根据本地显示名猜测身份。

`PlayerState.secrets` / `Zone.SECRET` 保存物理实体；`Entity.secret_instance_id` 从共用附件分配器取得，重新部署使用新标识。普通打出复用费用、玩家操作和施法窗口；只有未被反制才进入隐藏区。`SetSecret` 直接生成部署，不伪造出牌、抽牌或召唤；重复/满区时失败，不创建白板或暴露失败牌名。`RemoveSecret` 揭示并移入墓地，不执行奥秘行为，不产生随从死亡。

本批将任务、奥秘和有期限的玩家效果纳入共同 `max_secret_zone` 容量，默认五；整局玩家效果不占用。此前任务和定时效果各自的上限仍作为附加配置保留。普通出牌在支付前检查容量和同名唯一性；内部部署再次检查，防止前置反应改变容量。同名持续目标/咒符仍可独立叠加，同名任务/奥秘仍不可并存。

**共享区域默认上限五及具体占位仍是 R-048 原型策略，尚无当前国服精确对局证据。** 29.0 官方说明支持同名奥秘保持唯一、持续目标/咒符允许重复，但不单独证明容量和所有混合占位细节。[官方补丁](https://hearthstone.blizzard.com/en-us/news/24064735)

## 触发资格与消费

发布事件时固定候选奥秘实例及顺序，队列保存 `CheckSecret`。执行每项检查时重新读取当前场面，而不是预先把所有奥秘都认定为触发；实例已经离场或被替换则跳过。默认仅在对手回合触发；拥有者回合或任意回合必须由定义显式声明。需要召唤空间的奥秘通过共同 `requires_board_space` 检查实际规则容量。

条件回调收到隔离的 `RuleContext`，返回值必须为布尔；行为返回公共效果。窗口事件同时提供 `context.window`，内含当前来源、目标和阶段。条件成立后先消费实例、移出隐藏区并揭示，再执行捕获的行为，避免递归事件重复消费同一实例。揭示后的行为可以请求选择，剩余奥秘检查和原始动作随后继续。

“通常只在对手回合触发”的基础方向来自 [1.0.0.4944 官方补丁](https://hearthstone.blizzard.com/en-gb/news/13154924)；后来的特殊奥秘仍须逐卡接入。当前事件排序沿用本引擎当前玩家优先、入场顺序的策略，逐项实时检查、死亡/亡语和揭示反应的精确次序仍属于 R-050/R-051 待校准范围。

## 施法：反制、替换目标与执行

支付后法术进入待处理状态，内核建立唯一 `ActionWindow(kind='spell')` 并发布 `card_committed`。此时可进行施法反应和反制检查。接下来进入独立 `SpellTargetPhase`：未被反制且存在目标时发布 `spell_targeted`，允许扰咒术等效果替换目标。最后关闭窗口，执行未被反制法术的任务/奥秘部署、持续效果或普通行为，并发布 `card_played`。

`CounterSpell(window_id)` 标记当前法术被反制，不退费、不放回手牌、不执行法术主体。前后施法反应仍存在；这一点有 [9.2 官方补丁](https://hearthstone.blizzard.com/en-gb/news/21098848) 支持。此处的两个阶段避免将“施法”和“选定法术目标”混成同一个奥秘时点，但阶段相对其他普通触发的完整顺序仍待国服校准。

`RedirectSpellTarget` 修改指定窗口的目标；`SummonSpellTarget` 通过共同召唤入口创建实体，用实际返回的实体作为替代目标，不猜测 ID 或扫描最后一个随从。目标替换保留类型/区域等结构域，但不重新执行友敌关系、潜行等主动选择限制；法术最终读取替代后的目标。替代目标在召唤反应中死亡，不恢复原目标。复杂目标选择条件、非角色目标、来源变形及更多替换策略留在 M5/M6（R-052）。

本原M4批次反制的是普通手牌法术；后续普通手动随从反制已由[随从承诺窗口](m5-minion-counters.md)和[载体反制政策](m5-counter-policies.md)扩展。英雄牌反制、自动施放来源、复制施放、多目标与完整抉择前置阶段不能由本批证据推定完成。

## 攻击：检查、返回手牌与替换目标

攻击消耗已有攻击次数并显形后建立 `ActionWindow(kind='attack')`，发布 `attack_declared`。奥秘依次检查当前攻击双方及当前目标；攻击者死亡/离场或双方成为友方后，后续依赖有效攻击的奥秘不会照旧消费。最后关闭窗口，复用原有战斗合法性、同时伤害、吸血、死亡与武器耐久结算。

`RedirectAttack` 允许替换为存活的对立角色；`SummonAttackTarget` 使用共同召唤入口返回的实体，立即绑定为新目标，再处理召唤反应。若新目标此后死亡，攻击取消，不回退攻击原英雄。强制攻击也使用相同窗口，但保留原有“不额外消费普通攻击次数”等规则。

冰冻陷阱扩展共同 `ReturnToHand`：`to_owner=True` 返回原拥有者，成功入手后可附加 `CostSpec`。先重置场上状态，再安装额外费用；满拥有者手牌按既有烧毁路径处理，没有随从死亡或亡语。它不会错误返回当前控制者，也不会给烧掉的牌附加可用手牌费用。

目前攻击替换只接受敌对角色，不含误导让攻击者攻击同侧角色等特殊强制战斗；额外攻击判定、被冻结后的奥秘资格、旧英雄目标和其他例外需各自校准或扩展。

## 隐藏信息与玩家接口

双方都能看到奥秘槽位句柄、控制者和公开职业；拥有者看到卡牌 ID，对手通常看到 `card_id=null`。此前已经合法获知的手牌身份可继续记忆，但不会因此获得隐藏属性。普通施放奥秘的 `card_committed` 不自动公开牌面，部署与 `card_played` 日志只提供牌背；触发/移除才揭示。被反制的奥秘作为已反制法术公开，此策略列为 R-053 待核对项。

日志按事件时点保存，后来揭示不会回填早期日志。全局实体/附件/窗口 ID、条件、行为、捕获队列及内部 `spell_targeted` 诊断事件不会进入玩家 DTO。当前奥秘不能作为普通玩家直接选择的实体目标；隐藏区域交互通过明确公共效果扩展，不允许猜宿主 ID。

专项测试将法术反制与寒冰护体交换，在相同可见局面中核对对手观察、日志、修订值和合法操作完全相同。奥秘触发后的实际结果当然可以提供规则允许的信息。当前公开职业、既有身份记忆和移除/反制时揭示策略仍需国服 M6 核对。

## 挂起、回滚与兼容性

`GameState.action_windows` 是可序列化的嵌套窗口栈，窗口 ID 单调递增。选择帧保存奥秘候选、捕获事件、窗口上下文和后续关闭步骤；恢复时验证每个活动窗口都有匹配且顺序正确的继续步骤、正确的施法阶段与合法实体引用。攻击中的嵌套强制攻击使用另一实例，不覆盖外层窗口。

成功动作边界不能遗留窗口；游戏结束停止后续工作并清空活动窗口。条件/行为异常回滚整个外部动作，包括费用、攻击次数、揭示、区域、分配器和等待帧。旧 schema 1～73 明确拒绝，外层 replay schema 仍为 1，没有隐式迁移。
