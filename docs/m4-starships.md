## 1. 规则依据与边界

[暴雪“深暗领域”官方 FAQ](https://hearthstone.blizzard.com/en-us/expansions-adventures/the-great-dark-beyond) 描述：组件死亡贡献基础属性和效果；建造中的星舰占一个场地格，不能被攻击、伤害、选中或消灭；支付五点法力发射；每方同时只建造一艘，发射后后续组件开始构建下一艘。

[32.2 官方补丁说明](https://hearthstone.blizzard.com/en-us/news/24198086) 明确将组件的“发射时”效果改为随机顺序。内核使用对局唯一 RNG 打乱这些能力实例，重复组件分别执行。

以上是历史官方规则依据，不是国服当前补丁所有交互的校准记录。下列细节目前是显式原型约定（R-031）：同批死亡贡献的窗口、建造位置、发射沿用实体 ID、召唤事件与发射回调的相对顺序、沉默/复制/回手后的组合保留。原始舰体数据隐藏且缺少费用；实验适配显式采用五费卡牌基础费用，**尚未据官方实测证明回手后的卡牌费用**，不得将发射五费说明当作这一边界的证据。

[32.0 官方修复](https://hearthstone.blizzard.com/en-us/news/24187196) 明确：解放者继续伤害尚未移出场的致死随从，相关受伤触发仍可发生。内核据此引入发射阶段死亡延迟；**整个发射组共用边界是实现推断**，并非官方公开的完整调度模型。

范围修正：[31.6 公告](https://hearthstone.blizzard.com/en-us/news/24179332/31-6-patch-notes) 中的战列巡航舰升级法术池属于酒馆战棋。它不属于本构筑模拟器的验收目标；埃索达的三个协议已通过构筑机制内部验收。

## 2. 状态与静态定义

`Keyword.STARSHIP_PIECE` 是可沉默的能力。死亡前有效关键词决定能否贡献；死亡记录的 controller 决定受益方。转控后归当前控制者，回手、洗入和烧毁不算死亡。组件复生后再次死亡，可以再次贡献。

`CardDefinition.starship_for` 是不可变的职业元组，显式绑定舰体模板。注册表拒绝重复职业映射；优先使用当前英雄职业，缺少英雄职业时使用构筑职业，再使用中立后备模板。缺少合适模板时整次操作报错回滚。模板零攻击/零生命只用于组装，不能被无组件地召唤或生成。

每个组合实体保存 `components: tuple[str, ...]`，按贡献顺序记录组件定义 ID，允许重复。`DeathRecord` 同样保存构成。基础攻击与生命由这些定义求和，印刷能力实例分别安装；不复制死亡实体的增益、伤害、临时能力或已经消耗的圣盾状态。组合时排除 `STARSHIP_PIECE` 本身，避免舰体自行循环构建。重复亡语保留为多个独立能力；重复圣盾标记仍按普通圣盾规则一次消费。

`Entity.starship_building` 表示当前建造阶段；`Entity.active` 是普通效果参与资格。建造实体真实地位于 `PlayerState.board`，因此占用容量和位置。`construction(state, player_id)` 查询这一唯一真值，不再维护容易失配的玩家副本指针。每方最多一个建造实体。

一般休眠通过独立 `dormancy` 状态共用活跃资格，见 [休眠契约](m4-dormancy.md)；泰坦已有独立随从能力入口，见 [随从能力契约](m4-minion-abilities.md)，地标采用独立类型与冷却契约。普通板上随从查询须同时检查区域与 `entity.active`；不能把 `len(board)` 当作活跃随从数量。

## 3. 死亡、合并与发射

同一死亡批次先捕获全部死亡记录、移出全部死亡实体并累计尸体，再加入组件，随后发布资源/死亡事件并安排反应。第一次贡献在死亡组件原位置附近建立建造实体，后续贡献追加到已有实体。建造先占住空位，因此满场组件亡语再召唤会受到容量限制。这一精确窗口须 M6 校准。

建造不发布 `minion_summoned`。普通目标、攻击、伤害/治疗、消灭、属性/费用修改、冻结、沉默、回手/洗入、变形、复制及转控都跳过建造实体；它也不提供嘲讽、触发、属性/费用光环、法伤或伤害/治疗规则。光环不会作用于它。公共随机伤害从候选中排除它。

```python
from hs_sim.engine import LaunchStarship, LaunchStarshipEffect

game.apply(LaunchStarship(player_id=1, entity_id=ship_id))
# 卡牌行为可返回下列指令，免费发射捕获时指定的那一艘：
LaunchStarshipEffect(player_id=1, entity_id=ship_id)
```

手动发射要求行动回合、没有待选项、自己的指定建造实体和足够法力；普通卡牌减费或替代支付不改变发射费，也不会被它消耗。基础费用五点，专属修正后的费用复用公共资源账目。舰体已经占位，因此满场也可原位发射，无需空出第八个格子。

发射沿用实体 ID/位置，重新记录激活入场顺序与本回合召唤时间，恢复能力和光环，发布 `starship_launched` 与 `minion_summoned`，再按原型反应队列执行随机排列的 `on_launch`。发射不运行 `on_play` 战吼，也不发布出牌事件。普通召唤失调适用；继承突袭/冲锋时沿用公共攻击规则。

发射时只冻结能力资格和随机顺序；`ResolveLaunchAbility` 在轮到该能力时读取当前局面。例如医疗运输机先召唤的陆战队员可以计入后执行的超级电容器，引力置换器可以复制先前获得的增益。

`FinishStarshipLaunch` 关闭本次发射死亡阶段。在这一阶段内，普通触发继续结算，生命耗尽或已标记消灭的随从暂留场上，范围伤害仍可命中；随机伤害/消灭会排除致死候选。阶段关闭后统一处理死亡。英雄死亡沿用立即终局策略并清理已致死实体。死亡标记、光环来源、治疗救回及英雄终局的全部交互尚未校准，登记为 R-033。

免费效果要求指定实体仍是该玩家的建造实体。过期效果明确跳过，不能误发射后来出现的另一艘。发射后下一次组件死亡建立新实体，与旧舰体独立。

## 4. 组合生命周期

| 操作 | 当前内部契约 |
| --- | --- |
| 沉默 | 保留组合基础属性，移除可沉默能力和附魔 |
| 当前复制 | 新实体；保留构成、当前伤害/附件，附件获得新 ID |
| 基础复制 | 新实体；按构成重新安装完整印刷能力，不复制临时增益/伤害 |
| 回手/洗入牌库 | 同一实体；保留构成，重置普通运行属性/附件，重新安装组合基础 |
| 变形 | 清除旧构成，安装新定义；不允许无构成的舰体模板 |
| 转控 | 保留构成，使用公共转控与召唤时间规则 |
| 复生 | 从死亡记录构成创建新实体，普通复生消费/一血/满场规则适用 |

组合基础在 `lifecycle.install_base` 集中安装，不通过永久增益伪装，亦不在运行中修改冻结注册表。被动态授予组件关键词的舰体再次死亡时，当前契约将其组合定义展开贡献，避免递归模板。这一罕见边界也属于 R-031。

舰体回手后普通出牌走普通卡牌费用层；发射走独立报价。`CostModifier.scope` 默认是 `CostScope.CARD`，星舰专属修正显式使用 `CostScope.STARSHIP_LAUNCH`。SCV、回收地堡、锁定和震荡弹均通过 `AddCostModifier(..., uses_remaining=1, scope=CostScope.STARSHIP_LAUNCH)` 声明下一次发射减二费。

专属修正按获得顺序应用，可叠加到零；不依赖建造实体是否已经出现，来源离场后仍有效。普通出牌与发射各自只匹配自己的作用域。成功发射消耗每条匹配有限次修正一次，非法/过期发射不消耗，异常回滚恢复全部修正。当前约定免费发射也消费“下一次”修正，但不支付法力；此消费细节及混合设费优先级仍待 M6（R-032）。作用域不接受卡牌类型过滤或非法力支付，避免无依据的隐式组合。

## 5. 玩家操作与持久化

```json
{"revision":"当前观察修订值","action":{"type":"launch_starship","starship":"e8"}}
```

双方都能查看公开舰体的 `starship` 描述，包含 `building`、组件 ID 列表和建造阶段经专属修正计算的 `launch_cost`。自己的手牌舰体可见构成；对手手牌仍沿用牌背/已知身份限制，不泄漏后续隐藏状态。过滤事件只返回既定白名单字段，不透传内部死亡 ID、能力 ID 或 RNG。

动作验证和合法枚举共享 `launch_error`，玩家命令解析可见句柄后仍经过同一事务。异常回滚包括费用、组件构成、随机状态、事件和信息台账。发射回调可请求选择，未执行的随机顺序已固化在结算帧中，恢复不会再次支付或洗牌。

当前快照 schema 74 严格编码费用作用域、实体/死亡记录构成和建造状态；校验组件引用、基础属性一致性、单一建造实体和非活跃状态约束。旧 schema 1～73 拒绝；外层回放格式仍为 1。注册表与效果签名、规则和观察版本均参与恢复校验。

等待选择的 `ResolutionFrame.death_deferrals` 保存发射嵌套深度，并必须与剩余队列中的结束标记数相等。只有这种正式等待边界可保存尚未移除的致死随从/损坏武器；恢复后继续原队列，直到最外层结束才清理。普通稳定边界仍拒绝未结算死亡。阶段深度/结束标记损坏、预算耗尽及无匹配阶段均明确报错。
