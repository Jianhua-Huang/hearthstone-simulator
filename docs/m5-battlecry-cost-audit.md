# 13d-02d 前置审计：战吼身份条件与双方费用光环

这是v77时的前置审计，保留当时缺口；v78实现及证据见[公共契约](m5-battlecry-costs.md)。原审计如下。固定候选[来源分类](../outputs/m5-13d-02-modifier-candidates.json)中的FP1_017尼鲁巴蛛网领主，中英卡文均表达“具有战吼的随从费用增加2”，不是反制或禁止执行战吼。正式池与目标补丁适用性仍待M0，必要代表只作公共机制验证。

现有`CostSpec`仅有card_types/card_ids筛选；`costs.matches_cost`没有卡牌声明或实体能力上下文。`_quote_card`只扫描付款者自己的随从/武器来源，无法表达对双方生效或只影响敌方的费用光环。生成费用预览走`quote_generated_cost`，没有实体；不能在实体路径单独追加规则而造成预览/候选支付能力不一致。

已有`CardDefinition.battlecry`及实例`battlecry`能力明确区分通用on_play和抉择，捕获记录有独立声明卡来源。下一步需明确查询契约：印刷声明、当前附件、沉默/变形/存储复制后的身份如何匹配；目前不能据卡文断定特殊动态战吼身份的正式行为。优先建立类型化筛选声明与统一匹配入口，以实际公共需求决定维度，不引入任意可变回调或全池ID穷举。

费用影响关系应在声明中明确友方、敌方或双方，来源仍遵守活跃、存活、沉默/休眠/转控/离场资格。既有本地费用层、公共附件顺序、最低费用和支付种类保持原契约；有意改变层顺序须独立版本与证据，不和本批混改。费用增加不会影响非战吼白板、法术、英雄技能或主动手牌操作；具有其他入场行为不自动成为战吼。

验收至少覆盖：双方报价/可用动作/支付相同；匹配与不匹配牌、印刷/当前能力差异；假想生成报价与实际创建后报价一致；多个来源、费用设值/减费/替代支付/有限次修正组合；来源沉默、休眠、死亡、回手、转控和复制；己方隐藏手牌费用正常可见，对手隐藏内容不能因报价或报错泄漏；保存恢复、事务回滚与回放。先实现通用条件，再新增一个必要代表。

仍未纳入本项：全局禁止战吼（无已确认来源）、动态战吼主体授予、条件/种族战吼重复、深岩矿工的中英文条件冲突和13d-03间接/历史来源。来源文本、原型假设、内部通过与国服校准须分别记账。
