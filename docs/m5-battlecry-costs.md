# M5-13d-02d：战吼身份条件与双方费用光环

v78 的公共契约。57 项专项、3982 项全量及61示例通过，实际结果以[项目状态](project-status.md)为准。国服尚未校准，R-118 保留身份变化、来源排序和生成预览的官方语义核对。

## 条件与来源

`CardAbilityCondition(ability='battlecry', present=True, basis='current')` 表达结构性能力条件。目前只接受显式战吼，未知能力名明确拒绝。`present=False` 查询不具有战吼；`basis='printed'` 读取卡牌声明，`current` 读取未消耗的实体能力实例。实际实体必须与卡牌定义的 ID 和类型一致；生成候选没有实体，按新建基础实体查询。

结构性身份与此时能否执行战吼分别处理。休眠不会使卡牌失去战吼身份，沉默移除当前能力，印刷声明仍存在；普通 `on_play`、抉择、卡文引用战吼都不是战吼声明。没有通过检索中文卡文或穷举战吼卡 ID 实现判断。动态战吼主体授予接口仍是 M5 缺口。

`CostSpec.ability` 与既有卡牌类型、ID 过滤取交集。匹配函数由真实报价、生成报价、候选支付能力、玩家修正、实体费用修改及原子生成/存储增益验证共用。实例路径使用当前实体；基础生成路径使用定义。`ModifyCost` 不匹配时保留既有跳过诊断；原子创建、存储增益不匹配则失败回滚，随机操作先检查全部候选再消耗随机数。附魔安装后就是本地费用运算，不会继续根据后续身份变化撤销。

`CostAuraSpec(cost=CostSpec(...), relation='friendly')` 将筛选与影响付款者的关系分开，关系仅接受 `friendly / enemy / any`。印刷 `cost_auras` 和 `GrantCostAura` 都使用该包装；`AddCostModifier` 仍属于指定玩家，不能把关系字段塞进普通费用规格。旧 API 和旧快照不默默猜测迁移。

报价扫描双方场上随从、地标及装备武器的有效费用能力，按来源当前控制者匹配付款者关系。死亡、沉默、离场、变形和失效耐久撤销来源；休眠暂停，唤醒恢复，转控改变关系。当前复制保留能力并分配新附件 ID，基础复制只保留印刷来源。

## 费用、支付与候选

费用仍先计算实体本地层，再按统一附件 ID 混合应用双方有效光环与付款者自己的玩家修正，最后应用临时手牌最低费用。没有引入新的“敌方来源先算”规则。跨玩家的设费与加费顺序、有次数修正、替代生命支付均有组合测试，但该顺序仍是待校准原型契约。

手牌视图、合法操作、支付和生成候选报价共享结果。支付完成后来源离场不退款，随后出现的光环不追加扣款。过滤不匹配不会消耗有限次数修正。英雄技能和交易费用不会被“战吼随从”过滤命中；星舰发射规格不允许卡牌能力条件。

发现时的候选预览冻结；选后场面变化可能令实际到手费用不同。候选产生时的实时费用与同一状态下新建实体费用一致，不意味着冻结预览永远代表今后的实时报价。对手隐藏手牌不新增费用、能力或牌名投影；玩家观察/合法操作的非干扰检查保留。
