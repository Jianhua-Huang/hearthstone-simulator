# M5-13d-02b：玩家战吼次数、消费与到期

当前 `prototype-v75` / `core-effects-v75`、snapshot schema 74、representative-m5-v38；观察升级至 v44，命令 v7、外层 replay 1 保持。旧快照 1～73 明确拒绝。本批在 [场上重复契约](m5-battlecry-repeats.md) 上增加玩家持有的次数修正，不表示真实抑制、反制和间接/历史来源已经完成。

## 公共模型与来源

`AddBattlecryRepeatModifier(player_id, spec=BattlecryRepeatSpec(), source_id=None, uses=None, expires_turn=None)` 创建玩家独立修正。`uses=1` 表示下一张匹配的手牌战吼，正整数表示有限个匹配；None 表示不按次数消费。`expires_turn` 是包含该回合的全局回合编号，None 表示不随回合到期。二者可组合，表达本回合下一次、本回合全部、跨回合有限次或整局持续政策。

`PlayerState.battlecry_modifiers` 保存不可变 `BattlecryRepeatModifier`：统一附件 ID、次数声明、来源实体及当时卡面、创建回合、剩余用途、到期回合。`RemoveBattlecryRepeatModifier` 按玩家和实例 ID 撤销指定修正，错误持有者或已消失实例不影响其他修正。每次授予创建独立实例，不按卡名合并。

来源仅是归因。死亡、沉默、复制、休眠、回手、变形、转控或英雄技能替换都不移动或移除已经授予玩家的修正；再次打出来源可按其主体新建实例，普通复制不会虚构战吼。修正不占随从、奥秘、持续目标或咒符场位；不将限时战吼政策伪装成objective/sigil。

## 匹配、捕获与消费

只有明确的手动战吼主体集合调用捕获，普通on_play、抉择、法术、召唤和效果装备不会消费。按实际打出的物理类型匹配 `BattlecryRepeatSpec.kinds`；原型暂不支持条件/种族或任意谓词。来源玩家捕获窗口沿用13d-01/02a，普通与巨型的区别继续留R-113/R-114。

匹配玩家修正与场上光环一起取最大次数。`BattlecryRepeatPlan` 冻结所有贡献附件 ID 和其中的 `consumable_ids`。每个匹配有限修正都在共同手牌主体捕获点消费一次，即使它的次数低于另一来源；同名多个“触发两次”不会相乘，也不会排队留给不同出牌。空效果战吼仍消费，非法操作、工程次数预算错误及事务失败不会留下消费。

捕获点在普通主体与战吼执行前。新战吼授予的修正不追溯作用于自身；铜须下的低语元素产生两个新实例，下一张匹配出牌同时消费它们，仍取最大次数。提交反应或消费事件反应中新增的修正只影响后续捕获，移除旧修正不能取消已冻结计划。

一张牌含多个继承战吼时，整份手牌主体集合只消费一次，而不是每个组件、重复遍或回溯结果各扣一次。保留多种回溯结果使用同一冻结计划；普通回溯重试先恢复原始玩家预算，再为新尝试消费。可信诊断日志保留被放弃尝试的事件，当前状态和历史才表示接受后的次数，不可从整段日志的消费事件数量倒推实际剩余预算。

## 到期、终局与恢复

到期复用 `ExpireTurn`。结束回合的反应先执行，再清理双方所有 `expires_turn <= 当前回合` 的修正；依据全局回合而非受益玩家的回合倒计时。到期事件反应中新建的同回合修正由同一稳定循环继续清理，工程步数预算防止无穷续建。所有到期实例先移除，再投递通知，避免同批次仍可读到已失效修正。

接受主体之后、激活之前若终局，已发生的消费保留，未开始的战吼不伪造激活。主体中途失败则回滚到共同事务边界；若此前已暂停，后续选择失败恢复到挂起帧，包含当时已经发生的消费。保留结果与重复迭代不再重新消费。终局/反制的正式窗口仍需R-115和13d-02c核对。

快照保存修正、计划消费集合和待选帧。检查实例顺序/唯一附件身份、来源引用/原卡、类型筛选、用途/期限、贡献集合包含关系与现有批次关闭规则。对局边界拒绝过期遗留项。此类完整状态仍只供可信宿主使用。

## 玩家投影

双方观察增加 `battlecry_modifiers`，每项仅有 repetitions、kinds、uses_remaining、expires_turn。新增四类公开事件：battlecry_modifier_added/used/removed/expired，白名单只投影上述规则事实；不暴露附件ID、来源卡面或隐藏来源实体，事件source/target也不承载这些内部引用。

用途消费事件可以显示零，表示最后一次被用掉；当前活跃列表不能包含零用途。无限次修正不发消费事件，无期限修正不发到期事件；恢复严格检查这些公开事件字段。玩家命令没有新增动作，出牌、技能与发现继续走现有受限接口。
