# M5-13d-02a：场上战吼重复与独立批次

兹伊的真实被动技能按原随从出牌序号向既有max计划贡献一次原生声明，接受后不因换技能而改次数。有限技能来源与校准边界见[契约](m3-mugzee-passive-powers.md)。

此场上重复增量交付时为 `prototype-v74` / `core-effects-v74`、snapshot schema 73、representative-m5-v37；观察 v43、命令 v7、外层 replay 1 保持。旧快照 1～72 明确拒绝。本篇保留场上增量的历史验收；玩家次数/期限已由[13d-02b](m5-battlecry-modifiers.md)扩展，真实抑制与间接/历史来源继续归M5。

## 声明与捕获

`BattlecryRepeatSpec(repetitions=2, kinds=(MINION, WEAPON, HERO))` 表示次数设值，不是乘法或额外次数。卡牌通过 `CardDefinition.battlecry_repeats` 声明；`GrantBattlecryRepeatAura` 向在场、活跃随从授予同类能力，可带来源和到期回合。每份能力有独立附件身份，复制、沉默、到期、转控、休眠、回手与变形复用通用生命周期。

只查看被捕获玩家控制的活跃、未致死场上随从。`kinds` 筛选实际打出的物理卡类型，多个匹配声明取最大次数。能力载体可有多个声明；对手载体、休眠、沉默及已死亡载体不贡献。该设值契约并不实现“额外触发一次”、条件/种族筛选、玩家永久状态或反制。

共同手动主体入口在执行普通 `on_play` 前，捕获 `BattlecryRepeatPlan`：次数和贡献能力 ID。普通出牌沿用此前主体捕获点，提交事件反应后不重新计算；巨型仍在附肢后的主体检查点捕获。保留回溯结果同时冻结这份计划，后续累计结果不重新查光环。能力集合与计划都进入待选帧和快照，不依赖可变闭包。

## 执行、目标与顺序

每个实际开始的主体批次建立 `BattlecryBatchRecord`，包含原出牌、捕获玩家、能力序列、重复计划、回溯结果关联及进度；普通 `on_play` 仍只执行一次。按能力附件顺序处理，每份能力执行完所有重复，再进入下一份，例如两组件、两遍为 A1、A2、B1、B2。未开始即终局的队列不伪造批次或激活。

每次实际执行仍走 [战吼身份契约](m5-battlecries.md) 的开始/完成入口。`BattlecryRecord.batch_id` 关联批次，`repeat_index` 表示本能力第几遍；原 `iteration` 继续只表示保留的回溯结果遍数。两种结果、每种双战吼产生 `(iteration, repeat_index) = (1,1),(1,2),(2,1),(2,2)`，只有一次支付与手牌出牌，不创建法术施放记录。

所有重复保留同一手选目标引用，不自动重新选择。目标离场后公共效果按各自 stale 规则处理；即使没有实际效果，该遍仍可正常完成。每遍行为读取当时状态重新规划，所以随机效果与发现各自执行，普通发现需要两次独立选择，不沿用法术重复的 `repeat_key` 记忆。目标发生同实体变形/换控制时，效果沿用原有公共生命周期规则；这些边界未新增“重新通过一次手动目标筛选”的隐含步骤。

已捕获的来源或次数光环在第一遍死亡、沉默、回手、变形或转控，不撤销剩余批次。后一张牌重新捕获当前政策。沿用普通死亡和反应检查点，不增加法术重复专用的死亡延迟；来源亡语可能在两遍之间结算。终局中断剩余遍数，已完成激活保持完成，当前未完成激活记中断。

## 恢复与边界

队列必须按战吼完成、当前重复完成、批次完成、回溯结果完成（若有）、原出牌完成的顺序关闭。恢复验证原出牌/声明/贡献附件范围、计划关联、能力及遍数顺序、已完成子记录、去重和精确关闭标记。完成事件的反应可暂停，此时子记录已完成但批次计数尚未推进，属于显式允许的中间状态。

失败复用共同事务回滚：未暂停动作失败撤销全部遍数，待选后失败恢复到选择前的挂起批次。普通回溯重试替换上一尝试的整份批次。记录供可信规则和宿主诊断使用，不进入玩家观察或过滤日志；公共玩家命令保持一次手牌出牌，发现选择仍使用既有命令。
