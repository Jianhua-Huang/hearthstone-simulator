# M5-13d-03d-01 有上限的历史战吼序列

v83新增通用序列；代表包45和281条样本保持，本批没有接入沙德沃克。48项专项、4264项全量与67示例通过。对应前置问题见[审计](m5-bounded-battlecry-audit.md)，规则假设归R-124。

## 查询、筛选和计数

`played_battlecry_payloads`沿用`PlayedBattlecryQuery`的所属玩家、回合、出牌上界、排除ID、卡牌类型和反制政策。结果是不可变`PlayedBattlecryCandidate(play_id, payload)`，先按出牌历史、再按该次提交时的附件顺序展开。一张组合星舰的两份声明是两个候选；两次打出同一张牌也是独立候选；铜须两次实际执行不增加提交声明数量。普通on_play和普通召唤不构成战吼声明。

`PlayedBattlecryFilter`明确区分三个可叠加的排除维度：`exclude_played_cards`匹配捕获出牌卡面，`exclude_declaring_cards`匹配声明卡面，`exclude_behaviors`匹配声明行为ID。组合实体尤其不能混用三者。过滤先于限额；不从数据库文字推断资格，也不自动把“当前play_id”当成所有自身战吼的排除政策。

`RepeatPlayedBattlecrySequence(player_id, source_id, limit, ...)`的limit为非负整数，计数单位是该序列直接请求的一份主体，包括无合法目标的失败尝试。不因失败补抽，不按成功次数补齐。0或空候选不执行、不消耗随机数。实际候选少于上限时全部使用；工程预检依据实际请求数量，不能仅因声明了很大的上限就误报预算溢出。

## 选择与执行顺序

| 参数 | 政策 |
| --- | --- |
| selection=oldest | 从过滤后的完整候选取最早的limit份 |
| selection=newest | 取最后的limit份，子集仍按历史顺序排列 |
| selection=random | 从完整候选中无放回抽取limit份，再按历史位置整理子集 |
| order=chronological | 按所选主体的历史位置执行 |
| order=random | 使用共享RNG打乱已选子集，随后冻结顺序 |

两阶段独立：random/random先抽子集，再打乱；不是每次执行时从动态历史里重新抽取。保存候选、确定的索引顺序、捕获载体卡面/玩家、历史边界、当时未完成出牌和已发起记录。目标在每个主体开始时按原声明的目标域与当前局面随机选择；选择流程沿用`choices=player|random`。载体变形、沉默、死亡、回手或转控不会替换已接受的主体、原玩家或载体身份。

## 结算、嵌套和恢复

继续使用现有间接战吼入口、公共效果解释器、死亡检查和选择暂停。每次产生`origin=played_history`记录，关联原play_id和payload；没有额外付款、出牌事件或伪造旧手牌上下文。父卡自己的手牌重复次数先捕获；每次父激活启动独立序列，子激活不再次消费/应用手牌重复政策。

父序列的上限只覆盖直接主体。某主体内部再次触发鹦鹉或另一限定序列，遵循其独立政策，不能倒灌到父候选中。未排除的递归仍可耗尽`Ruleset.max_resolution_steps`，此时明确报错并回滚当前操作，不把工程预算当成卡牌的20次规则或对局平局。终局中断后续序列；普通回溯撤回子历史，保留结果的回溯让各次父激活各自拥有上限。

`ContinueBattlecrySequence`与`FinishSequenceAttempt`是类型白名单中的续接值，不新增另一套解释器或全局候选缓存。完成标记将当前尝试绑定到计划的下一位置；只有子战吼完成后才继续。恢复校验候选与原提交声明、所有者、规则上限、唯一索引、可确定的选择/顺序政策、已发起记录及父子结束标记顺序；缩短已执行前缀以重复消耗的尝试会被拒绝。嵌套计划互不认领同一尝试。

随机子集/随机顺序是合法已保存结果，恢复不重新抽签。快照属于可信宿主接口，结构与语义校验不等于带签名的存档真实性认证，不能证明任意协调修改的随机状态和记录来自原对局。玩家接口不暴露候选、计划索引、行为ID或内部历史链接。

持久GameState布局未改变：schema80、replay1、观察46和命令7保持；规则/效果提升83，新类型进入效果签名。旧规则或旧处理器签名仍须原引擎读取，不隐式迁移。

## 内部验收与剩余问题

[专项](../tests/test_m5_battlecry_sequences.py)覆盖独立筛选维度、重复物理提交、星舰多主体、无目标消耗、实时目标、共享随机、铜须/有限次政策、反制声明、普通/物理/嵌套来源、生命周期、回溯、终局、恢复拒绝与事务/信息隔离。[示例](../examples/bounded_battlecries.py)使用明确命名的合成牌，21次真实手牌提交后从21份主体中选20份，逐次选择并恢复/回放；不是沙德沃克适配完成声明。

官方[11.1更新](https://hearthstone.blizzard.com/en-us/news/21738246)只为历史20次上限提供直接证据。R-124保留当前国服上限、组合主体/失败计数、沙德沃克自身排除维度、候选截断与抽样顺序及嵌套重演的实际政策。下一项13d-03d-02先审计具体政策，再接入必要代表和真实历史组合。动态主体、连击/种族重复、其他牌库条件、M0完整池、M6校准、M7批量适配仍未完成。

最终内部证据：48专项（7.444秒）、4264全量（614.182秒）、70代表检查与67示例通过；63个既有摘要共同结果字段不变，见[比较报告](../outputs/v83-example-count-check.json)。下一项[政策审计](m5-shudderwock-policy-audit.md)保留官方原文取回及来源生命周期缺口。

v84兼容补充：默认捕获来源/玩家政策保持；显式来源和转控扩展见[生命周期契约](m5-sequence-lifecycle.md)。BattlecryRecord新增归属与目标政策字段，因此当前schema81拒绝旧1～80；本篇v83数字是历史验收记录。
