# 13d-03a 前置审计：间接战吼与历史重演

本页保留v79前置审计。v80已接入间接执行与成功激活候选，见[公共契约](m5-battlecry-sources.md)；卡牌级“使用过”历史政策与必要代表留13d-03b。原审计如下。候选[冻结来源](../outputs/m5-13d-03-source-candidates.json)来自同一客户端数据；正式合法池和国服准确时序仍未验证。

艳丽的金刚鹦鹉 `DED_509` 要重复上一个使用的战吼；伯尔纳·锤喙 `SW_115` 要重复本回合第一个战吼；沙德沃克 `GIL_820` 涉及本局其他卡牌的战吼及随机目标。它们需要历史选择和新的效果执行，不能用铜须式的当前手牌重复次数表达。只应先接一个代表验证公共来源，不同时扩三张复杂卡。

现有 `BattlecryRecord.origin` 只接受 hand，BeginBattlecry 和重复批次都绑定未结束的 PlayRecord；validate_boundary 要求对应 FinishPlay。直接把历史战吼塞进这个入口，会错误借用旧卡牌的控制者、目标、主体和支付历史，也可能把新触发计为另一次出牌。当前 activated_battlecries 查询实际激活次数，与“曾使用过的战吼卡”不是天然相同集合，铜须会令同一次出牌有多个实际记录。

下一步先建立类型化间接激活：明确当前执行载体、能力声明来源、原历史依据、来源种类、目标/选择政策和独立开始/完成记录。需要执行能力时复用普通调度、死亡检查与选择帧，不能让卡牌适配直接调用行为回调绕过来源验证。重演不支付原卡费用、不新建原主体、不凭空增加手牌出牌记录；原来的手牌入口仍保留原契约。

历史查询应明确：按出牌还是按实际激活取样、原记录成功/被反制/中断时是否合格、排除正在执行的重演载体、窗口和所有者、第一/最后/全部策略。基础牌面还是捕获能力，以及原目标、随机重选、无目标和不适用情形都须显式定义。对原来源离场、变形和转控，不可事后读新实体状态冒充过去声明。

验收覆盖普通与定向战吼、随机和需要选择的战吼、铜须/玩家有限次政策、反制、来源离场、嵌套重演、回溯、终局、错误回滚、保存恢复、回放及隐藏信息。工程递归预算报错不能伪装成官方连锁上限。需要官方依据的精确政策继续记入M6，不靠自测推导正式规则。

02系列剩余动态主体授予、条件/种族重复和混合声明不因切入03而关闭。当前检索没有证明所有剩余抽象都有构筑来源；注能换形已有基础，应以真实行为确认必要缺口。M0正式池、M6国服校准与M7批量卡牌门槛保持。
