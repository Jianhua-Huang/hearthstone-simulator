# M5-13d-03a 间接战吼执行与历史候选

本批为 prototype-v80 / core-effects-v80、snapshot schema79。54项专项、4084项全量及63示例通过，实际结果见[项目状态](project-status.md)。这是R-120暂定公共契约；没有新增真实卡适配，不能据此宣布金刚鹦鹉、伯尔纳或沙德沃克已支持。

## 入口与来源

| 入口 | 接受对象 | 执行含义 |
| --- | --- | --- |
| 原手牌入口 | 已提交的随从/武器/英雄牌 | 原有付款、出牌记录、重复批次、保留回溯结果不变 |
| `TriggerBattlecry` | 已捕获的场上随从物理引用 | 复查在场、存活、控制者/卡面/入场代次；接受时冻结当前全部战吼主体 |
| `RepeatBattlecry` | 玩家、当前载体、已完成的战吼记录ID | 用当前载体执行原记录捕获的能力；载体可为随从、武器或英雄 |
| `RepeatBattlecries` | 上述载体与显式历史查询 | 一次选定第一/最后/全部候选，按历史或随机顺序冻结执行队列 |

间接执行不支付旧卡费用、不新建旧卡实体、不产生新的手牌出牌、不复制旧卡的亡语/触发/关键词附件，也不消费或再次应用手牌战吼次数政策。铜须可以令外层手牌战吼重复，两次间接子执行仍各执行一次。正常召唤与装备仍不会自行激活战吼。

`BattlecryRecord`统一记录hand/effect/history。`source_id/card_id`是当前执行载体及接受时身份，`payload`保存能力附件ID、行为与声明卡，`caster_id`是请求来源，`history_id`是重演依据，`parent_id`标识嵌套激活。effect/history不借用PlayRecord或BattlecryBatchRecord，`play_id/batch_id/outcome_id`为null，重复与回溯索引为1。

物理引用在入口前已失效则跳过；入口接受之后的沉默、死亡、变形不替换已捕获能力。历史重演也不从原实体的当前卡面重新取能力。行为上下文source指向当前物理载体，player_id指向捕获执行玩家；因此转控后两者可以不同，适配者不得用source.controller替代执行玩家。间接主体的`ctx.play`为空，不能假装仍在执行旧手牌出牌；`ctx.battlecry`保存独立记录。

## 历史口径与冻结选择

`BattlecryHistoryQuery`默认取己方hand来源、已完成且无失败的实际激活。可指定来源、回合、严格小于的记录界限、排除ID；hand查询还支持严格小于的play_id界限。

- `distinct='activation'`保留所有实际记录，包括铜须造成的多次激活。
- `distinct='play_payload'`仅允许hand来源，按“同一次出牌+同一能力附件”保留第一个合格记录，折叠普通重复和保留回溯迭代，但保留组合实体上的不同能力附件。
- 未完成、中断、无目标失败不属于成功候选。被反制的出牌没有实际战吼记录，查询不会凭空生成一条。
- 以上是可配置引擎口径，**不等价于任何卡牌文案中的“你使用过的战吼”已被正式校准**。特别是反制的出牌、重复执行当前重演牌时的排除，以及复制/组合卡如何计数，下一批须单独定义卡牌政策。

批次入口一次冻结ID序列；子执行产生的新记录不扩展当前序列。随机顺序使用同一可回放RNG，不重放旧随机结果。嵌套历史只指向更早、已完成的记录；没有自行设定官方重复上限，工程结算预算耗尽报错并回滚。

## 目标、选择与结算

目标限制来自原能力声明卡；关系判断使用本次捕获玩家和当前场面。random重新选择合法目标，explicit使用指定目标。required无目标或显式非法目标仍留下已完成失败记录，但不进入主体；if_available无候选允许空目标执行。每段执行共用调度、触发、死亡检查、伤害与区域效果。

选择政策为random或player。来自同一执行载体/玩家的随机选择走公共RNG及选择回调，不挂起；player允许正常选择帧、玩家命令和恢复。对手/其他来源请求的选择不被强制套入当前随机政策。

开始记录与进入主体分为两个阶段，`payload_started`区分开始反应期间的暂停/死亡；`failure`记录no_target或invalid_target。开始反应杀死英雄会中断未执行的主体；主体致死也中断祖先激活和后续队列，不能伪造完成。开始和完成事件携带战吼ID，宿主可审计，玩家投影不暴露内部历史和随机选择明细。

外层普通回溯恢复已保存的完整历史；保留结果重新运行其间接子效果。子激活不创建新的手动回溯检查点，也不继承外层attempt数字。特殊“历史战吼自身是否具有独立重试”等卡牌政策未在本批擅自添加。

测试覆盖物理引用失效、沉默、原来源死亡/变形/转控、当前载体变形与转控、目标与随机、自动/人工选择、冻结序列、嵌套、铜须、玩家有限次政策、整牌反制、两类回溯、终局、预算、动作回滚、恢复篡改和玩家隔离。示例`python -m examples.indirect_battlecries`使用既有铜须/宝石甲虫与两个明确的合成入口，5动作31事件、5次战吼、仅2次手牌出牌；选择中恢复和逐步回放一致。合成入口不计入真实适配数量。
