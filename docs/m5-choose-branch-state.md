## 独立的物理预选状态

[choose_branch_state.py](../hs_sim/engine/choose_branch_state.py) 提供 `SetChooseBranch(card, branch_id, origins=('hand',), combination='override', source_id=None)`。`card` 必须是捕获的 `CardReference` 或已安装的 `HeroPowerReference`；`branch_id=None` 清除预选。卡面、区域、控制者及区域版本等沿原引用守卫，移动、变形或技能替换后的旧引用只登记跳过，不重绑另一实体。未知分支、卡面、来源范围或组合策略明确拒绝，异常沿公共事务回滚。

不可变 `ChooseBranchSelection` 保存原卡面、分支、明确来源范围及组合策略；实体仅保存一份当前声明。它是物理选择配方，不是场上光环或可消费玩家用途，不另分配附件ID。默认仅用于手牌根；随从可显式授权 `physical`，法术可授权 `cast_effect/cast_draw/cast_history`，英雄技能仅接受 `power_manual/power_effect`。目标种类不适用的来源不能借用其他入口。

`combination='override'` 表示合并来源在新接受窗优先，原预选仍保留；`strict` 表示冲突时没有合法分支，自动尝试明确报错并回滚。显式预选combined可在没有合并来源时使用，但不能由普通分支名称自动推断combined。玩家长期/有限次合并政策仍由[独立模块](m5-player-choose-both.md)在实际合格根接受和消费。

手动动作仍须提交明确的合法 `branch`。动作枚举、目标查询、玩家命令与执行验证读取相同实体声明；查询不消费、付款、分配实体或推动RNG。自动来源先选分支再选目标，单个预选分支不抽分支随机数；目标仍按自己的真实来源政策选择。未授权入口沿原普通/合并策略，新创建的同名实体不能借其他物理卡的预选。自动显式分支与适用预选冲突时拒绝。

## 生命周期与已接受根

| 操作 | 预选的处理 |
| --- | --- |
| 非重置移动、转交另一个玩家 | 保留同一物理配方，之后由新控制者按其局面接受 |
| 当前手牌/牌库复制、当前场上/存储随从复制 | 复制当前声明；新实体、附件与原接受来源保持独立 |
| 基础复制、重置移动、变形、默认回手重置 | 清除声明，不能借旧卡面的分支 |
| 沉默 | 此物理选择配方保留；能力与主体仍沿原沉默规则 |
| 兼容回溯形态 | 同一底层抉择声明，重绑配方卡面；原动作与原支付保持 |
| 普通召唤、基础复活或新技能安装 | 新印刷实例，不借另一个实体的预选 |

`CopyLocalState` 捕获完整原预选，真实归因复制沿原冻结材料生产者保存及解析它。后续局面不借当前源覆盖已接受材料；经典无归因复制入口继续采用其已有生命周期。完整快照、解释器状态、原接受上下文和复制材料采用同一严格类型。原接受后的branch仍在Play/Cast/Power或实际物理child记录中冻结，反制、重复、独立BC/Combo、暂停或来源改变不重新读取预选。

回溯恢复原物理状态后执行原动作；兼容形态和保留多结果路径都重绑预选卡面，仍只支付原接受一次。配方不会将自动施法伪装成付费手牌，也不会使当前复制自动重演普通出牌主体。

## 显式历史继承

`RecastSpell(..., branch_policy='inherit')` 创建真实新history cast，并从指定原施法记录取branch，不借原来源实体的当前卡面。默认 `current` 仍重新选择。继承配方只授权此次history入口；当前合并政策在新窗口优先，各新真实根分别消费自己的匹配用途，重复和保留结果复用原接受。

四个已注册物理历史profile可用 `ReplayWholeCards(..., physical_branch_policy='inherit')`。每个child读取自己的实际occurrence对应的原PlayRecord，不能把整批第一张或同名另一张的分支套给后续卡。默认 `current` 仍重新选择；继承必须有真实physical profile，不能同时提供 `physical_branch_id`。非抉择child保持原路径，不产生虚构分支。

物理分支收据增加 `branch_policy/inherited_branch_id`，绑定原occurrence、卡面、完整原窗口与实际请求；原合并来源、玩家政策、候选、原branch及RNG前后均沿原证明。完整证明按原历史接受状态和原pre-child状态复算，紧凑记录也核对原历史身份和分支。继承在安装之前接受，目标和独立主体仍在自己的原接受窗捕获。完整证明只用于可信宿主恢复/回放；未签名存档的内部一致性不能认证外部来源。

## 玩家信息与保留缺口

可见抉择实体的 `choose_selection` 仅投影branch、来源范围与组合策略，没有授予来源ID、完整状态或历史证明。敌方隐藏手牌即使记住过卡名，也不显示其后续预选；牌库配方不提供区域位置或身份。改变事件为所属玩家的私有白名单事件，双方观察与待选恢复继续复用原信息层。

本批仅用必要合成声明验证。真实执行范围和所选相关检查见[验收证据](../outputs/v274-choose-branch-state-20261009/verification.json)，未执行内容不算通过。U17B不同分支费用的报价、合法性、支付账户和原接受证明仍未实现。批量 `RecastFromHistory`、整牌重演中的法术路径及其他特定来源没有因这两个新参数自动获得继承授权；后续按各producer补齐，仍在M5。特殊技能替换继承、真实预选/合并冲突例外也待来源契约和国服证据。

U18特殊根、U14/U64/U65整轴与其他已知机制继续保留；M0正式补丁/热修/完整合法可达池、完整H2、M6国服校准及机制和校准之后的M7均未完成。最近完整阶段验收仍H1。
