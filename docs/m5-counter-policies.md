## 公共接口与结算

`CounterPolicySpec(kind, uses=1, key=None)`只接受随从/法术类型和正整数预算。`GrantCounterPolicy(carrier, spec, source_id, expires_turn)`把策略授予捕获的`MinionReference`；实体ID、卡面、控制者、区域修订和入场序号共同绑定一次在场身份。无效或已离场身份不授予；非法来源、未来引用和过期请求明确报错。`RequestChoice`直接组合这个效果即可表达秘密选择，无需公开抉择动作，也不占奥秘区。

授予产生独立`AbilityInstance(kind='counter_policy')`，拥有附件ID、来源、类型化声明、剩余次数与期限。无key时每次授予独立；有key时只刷新同载体、同key、同类型的策略，分配新ID以使已捕获的旧检查失效。不同类型并存。这个重复选择政策是显式原型契约，不能从卡文或内部测试推断为正式规则。

法术在`card_committed`，随从在`minion_counter_check`捕获候选。候选按既有控制者/入场顺序与附件顺序进入队列，执行时复核：载体仍为同一有效随从、存活且非待死；附件仍存在且有剩余次数；窗口仍为对应类型/阶段、对手打出且尚未反制。只有全部成立才原子标记出牌与窗口、消耗一次，然后发布使用事实和标准反制事件。后续奥秘或载体候选看到窗口已反制，保持未用次数。

`CounterCard`继续使用同一标记/公告路径。公共反制不消灭随从实体，不会产生死亡、复生或尸体；本次被反制的随从未入场、战吼未接受。普通召唤、间接施法、英雄技能和自己的出牌不匹配此手动出牌策略。整次取消语义见[反制窗口](m5-minion-counters.md)。

## 生命周期与知识

| 变化 | 策略实例 | 玩家信息 |
| --- | --- | --- |
| 死亡、回手、洗入、基础重建/复生 | 死亡记录可保留历史；离场不再监听；重置/新基础实体无旧授予 | 历史事实不等于当前能力 |
| 沉默、变形、到期 | 沉默删除授予，变形重置，到期移除 | 不发布尚未使用的选择类型 |
| 休眠/唤醒 | 原实例和预算保留；休眠不生效 | 当前控制者仍可查看自己的策略 |
| 转控 | 实例/预算保留；旧候选身份失效，后续保护新控制者 | 新控制者收到事件时的私有策略清单；前控制者保留过去日志 |
| 复制当前状态 | 新实体/附件ID，复制预算，包括已消耗状态 | 复制的控制者得到副本的私有清单；原载体的当前隐藏状态不因此公开 |
| 基础复制 | 只按印刷定义重建 | 不携带隐藏选择 |

当前实体DTO中`counter_policies`对控制者是事实列表，对另一方恒为null；不通过策略数量、key、附件ID、能力名称或刷新次数暗示隐藏选择。列表只含kind、uses_remaining、expires_turn。grant事件只进入控制者日志；used事件双方可见，但只披露实际使用的那一项。

`control_changed`及`minion_summoned`日志给事件时的控制者附带私有清单。已知信息作为不可变历史收据保留；失去控制后不继续提供当前精确策略，防止后台刷新泄密。普通回溯按现有日志分支规则退回检查点；回溯累计结果允许各次独立选择。这种知识语义明确登记R-117，尚未国服校准。

## 保存与验收

能力声明进入严格快照字段；保存的检查与选择分支进入类型化继续帧。恢复验证载体来源、附件和窗口关联，允许真实旧身份因中间反应自然失效，拒绝未来引用、错误窗口、类型、预算或私有日志载荷。snapshot1～75明确拒绝，replay外层仍为1。全知快照/回放不提供给玩家。
