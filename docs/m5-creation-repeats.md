## 声明与原子创建

`CardSpellRepeatGrant(casts=2, expires_turn=None)`是不可变的创建声明。casts必须为至少2的整数，expires_turn为独立的全局回合截止值。`AddToHand`、`AddToDeck`、`GenerateFromPool`、`DiscoverFromPool`增加可选 `spell_repeat` 字段，默认None保留原行为。

```python
DiscoverFromPool(player_id, pool_id, source_id=source_id,
    query=PoolQuery(kinds=(CardType.SPELL,), min_cost=5),
    spell_repeat=CardSpellRepeatGrant(casts=2))
```

生成后不再搜索同名手牌：`opening.add_to_hand`和`zones.add_to_deck`持有新实体，在费用附件安装之后、`card_created`和入手/入库/烧毁事件之前，直接安装card_spell_repeat附件。动态授予和创建安装共用身份分配与附件构造。创建不会另发“后来授予”的中间事件，首个创建反应就能看到完整状态。

满手时仍创建一个新烧毁实体，并在该实体上安装声明；它进入墓地，没有成功入手历史，也不修改已有同名牌。此策略与现有生成费用一致，烧毁反应读取新实体属性。它是可校准的明确策略，不据此推断正式来源的所有烧牌交互。

安装来源使用生成指令的source_id；None允许无来源。不存在的来源、过期期限、不兼容载体在分配身份/消耗随机数前失败。源实体随后死亡、沉默或转控不撤销已有声明或已创建附件。

## 池、连续选择与交付

所有合格候选必须能承载法术附件，再抽样或请求选择；混合随从池整体失败，不能静默移除不兼容或未实现候选。显式PoolQuery可以合法限定法术。向board交付明确拒绝。零轮发现和空池仍验证上下文、来源、期限和池内容；空结果不分配附件身份。

既有ContinuePoolDiscovery.spec保存完整冻结声明。after_each每轮先交付，再继续发现；after_all保存全部选择后逐张交付。允许重复选择时，每张新牌拥有独立实体/附件身份；去重选择仍按原生成身份处理，池耗尽后交付已有结果。交付中的复制、转移、选择暂停、满手、致死或失败沿用既有调度和事务规则。

在获取反应中复制新牌，当前复制能继承独立附件；转移给另一玩家，附件随物理牌保留。失败选择回滚本次选择、随机状态、生成身份和附件，不撤销此前已经成功提交的选择；终局中断后续交付。普通回溯恢复生成前状态，重试按冻结规则重新生成。

## 费用、来源与信息边界

原生成指令的 `expires_turn` 仍专属于 `cost`，没有cost时不能单独提供。法术重复期限只存在于 `spell_repeat.expires_turn`，二者可以分别到期；重复效果不要求存在费用修改。安装后全部继承、出牌冻结、三路次数合并和自动施法限制沿用R-133。

自动施法执行发现后可以生成带“手牌使用时重复”属性的新卡；这不意味着自动施法本身读取或消费该属性。未来手牌使用才会捕获它。分组选择ChooseFromPools、历史发现和其他特殊来源没有新增此字段，本项不泛化为所有生成入口已覆盖。

拥有者手牌使用已有观察51的casts/期限投影；内部声明、附件ID、来源和结算帧不可见。发现选项保持既有卡面展示，交付声明不序列化给玩家接口。对手只知道公开获取/数量，即使身份被显式揭示，也不显示私有修改。牌库不因安装获得追踪句柄；配对状态验证对手观察修订和事件相同。
