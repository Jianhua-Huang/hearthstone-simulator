## 在发生时捕获，在死亡后查询

`DeathCause` 是冻结值，保存原因类别、检测操作、目标本次区域/入场身份、当时卡牌/控制者、回合、行动方，以及可确定的来源实体/卡牌/控制者和安装身份。来自伤害的原因还保存已经验证的 `HealthResult` 元组负载，通过 `cause.health_result` 解码；它与宿主结果事件共用严格数值校验，批次/段序号可关联到原伤害段。不是根据最终负血量重算，也不需要卡牌访问全知日志。

实体上的 `death_cause` 保存尚未清理的致死事实；进入死亡批次时，`DeathRecord.cause` 冻结该事实。尸体离开区域后实体字段清空，历史记录不变。英雄按现有终局机制保留其实体上的归因，不新增虚假的随从死亡记录；地标、武器记录也使用该类型。

| 原因 | 捕获规则 | 不代表什么 |
| --- | --- | --- |
| `damage` | 此段开始时存活，实际生命损失达到此前生命，数值致死 | 护甲吸收量不直接等于生命损失 |
| `poison` | 此前未待消灭，伤害使其待消灭，但数值后仍为正生命 | 不能因之后又补伤害而改为荣誉消灭 |
| `destroy` | 显式消灭指令；`Destroy(target_id, source_id=None)` 可声明来源 | 消灭不伪装成伤害或精确击杀 |
| `health_loss` | 直接生命扣除或生命支付造成致死 | 不应用伤害关键词和伤害数值条件 |
| `health_state` | 属性设值、上限变化、光环移除、沉默/到期等导致非伤害致死 | 没有唯一来源时明确为 `None`，不把光环提供者遭受的伤害记到旁边随从 |
| `durability` | 武器/地标耐久耗尽；原攻击英雄、修改来源或地标自身按入口捕获 | 不计为角色伤害击杀 |
| `replaced` | 装备新武器挤出旧武器，记录替换来源 | 旧武器不必先降到零耐久 |

直接属性操作捕获显式来源；一般派生状态变化没有可确定的唯一来源时保留空值。`reason` 是内核检测操作的诊断名，不是正式卡牌效果身份，也不承诺一个光环变化只有一个参与来源。星舰建造状态不参与致死条件；休眠只改变死亡处理资格，本身不把已有致死事实当作治疗清除。

## 生命周期和组合策略

原型使用**本次生命期间的第一次致死转变**。同批后续伤害、已经待消灭目标、或延迟死亡期间追加消灭不会覆盖它。伤害同时具有剧毒且已数值致死时，归类为 `damage`；若只有剧毒致死，则归类为 `poison`。这些精确窗口仍归 R-110。

如果延迟清理期间恢复到正生命且没有待消灭标志，旧原因清除；之后再次致死会捕获新的来源和段数。生命损失替换、固有吸血、治疗和属性恢复均按实际结果处理。仅治疗剧毒/直接消灭目标不撤销其待消灭标志，因此不会当作已救回。

回手/离场、重新入场和变形清空实体原因。复制不会复制原杀手：当前状态复制若得到零血体，它的死亡属于自身的非伤害状态变化。复生创建新实体，不继承上一条死因。控制权变化保留原致死时的控制者和来源；死亡记录另保存真正离场时的控制者。来源先死或换形，也不改写捕获卡牌和区域身份。

保存、克隆、选择中断、回溯和异常回滚包含此状态。重试回溯丢弃旧分支死因；亡语请求选择后恢复仍读取原死亡记录。解码检查必需字段、冻结结果、角色/来源引用、非未来回合/区域身份及实体是否仍处于致死状态；等待中的致死实体不能删除原因，死亡历史也不能省略它。快照校验提供一致性检查，不是历史真实性签名。

宿主字段不进入玩家观察或日志，观察版本保持 v42。没有新增公开死亡原因事件，也没有把 `health_resolved` 暴露给玩家。

## 亡语消费者与必要代表

`was_honorably_killed(death_record)` 读取数值致死原因，复用已有荣誉消灭的来源回合、敌方目标和精确生命损失条件。参数 `None` 表示显式触发一个尚未死亡的亡语，返回假；其他错误类型拒绝。卡牌不能通过最终 `damage == max_health` 代替此查询。

血怒者科尔拉克 `AV_143` 使用冻结的 4 费 3/5 数据，只组合公共查询与普通召唤：未被荣誉消灭则在原死亡位置尝试召唤基础科尔拉克，不复制旧增益；无实际死亡上下文时按普通召唤处理。转移到其他随从的亡语也召唤卡文指定的科尔拉克。满场、终局和召唤反应沿用公共机制。

[冻结卡文](../outputs/v69-death-attribution-candidate.json)与[官方卡牌库](https://hearthstone.blizzard.com/en-us/cards/70258-korrak-the-bloodrager/)均要求该亡语查询此前是否被荣誉消灭。它们证明公共归因需求，不证明本原型的所有时序或当前国服合法性。

运行 `python -m examples.death_attribution`：火球术对科尔拉克造成超额伤害，亡语召唤新实体；月亮的祝福选择中途保存恢复；寒冰箭后跨回合用神圣新星精确消灭新实体。7 动作/40 事件，旧记录保留，两次死亡的原因分别可查询，玩家接口和完整回放一致。产物：[快照](../outputs/death-attribution-snapshot.json)、[回放](../outputs/death-attribution-replay.json)、[玩家观察](../outputs/death-attribution-view.json)。这是人工跨职业机制场景，不是正式合法卡组。
