# M5-13d-02k-02：场上亡语次数来源与重复计划

2026-09-25。内核`prototype-v93` / `core-effects-v93`、快照schema90、代表包53；观察51、命令7、replay1保持。**R-137是可替换的原型政策，尚未完成国服校准。** 本批闭环场上次数来源，玩家期限、自身授予范围和主动固定次数仍是后续依赖。

## 次数来源与接受窗口

`DeathrattleRepeatSpec`声明设定次数及载体类型范围，默认友方随从两次，可显式指定武器或地标。来源目前限活跃场上随从；印刷声明与`GrantDeathrattleRepeatAura`共用生命周期，动态授予支持来源实体及已有回合到期规则。沉默、变形、回手、休眠、复制与转控复用原附件机制。

`DeathrattleRepeatPlan`保存完整来源证据：来源实体、当时卡面与控制者、能力附件及规格。多个适用来源取最大设定次数，保留每个贡献者，不将“两次”相乘或当作额外一次相加。来源在后续亡语中消失、变形或转控，不改写已接受计划；新一次触发重新捕获。

自然死亡在既有死亡检查中移出同批死亡实体后捕获次数；来源健康值不大于零或已被标为消灭时也不贡献。因此男爵与目标同时死亡不重复。这一窗口属于R-137待校准政策。已替换武器沿用自己的既有入口，没有为重复插入额外死亡检查。主动`TriggerDeathrattles`对活跃随从捕获当前来源，仍不制造死亡、尸体、复生或星舰贡献。

## 完整计划与实际执行

`DeathrattleBatch`保存原始能力有序元组和次数计划，ID沿用首个捕获ID。每个能力按附件顺序完成其全部重复，再执行下一个能力，即A1、A2、B1、B2。相同的两个授予仍是两个能力；同一能力重复不分配新附件ID，每次执行另有捕获ID与`repeat_index`。所有预定位置在复制回调上下文前完整写入历史，排队不代表实际开始。

每项能力的第一次回调保留k-01的接受窗口；额外执行通过原`Resolution.call`读取前一次结算后的新局面，保留原能力、载体、控制者、事件和真实死亡身份。新的随机效果和选择各自结算，不复用战吼或法术重复的选择缓存。主动载体后来回手、变形或转控不取消已接受主体。首次回调与额外回调的状态窗口，以及每能力循环排列均列R-137，不能当作已证实的国服细节。

仍使用`InvokeDeathrattle/FinishDeathrattle`控制工作；不发额外玩法事件，不新增死亡或光环检查点。普通载荷效果保持原结算、嵌套和选择流程，复生只在原死亡流程中发生一次。预分配之前检查工程预算，每次实际控制工作继续计入预算；超限回滚，不冒充官方平局或无限循环规则。

## 恢复、事务与玩家边界

schema90保存来源计划和所有重复位置，明确拒绝schema1～89。恢复校验批次连续覆盖、能力顺序、重复序号、贡献范围/控制者、由来源重算的次数、逐次开始/完成状态和挂起标记；不能只用能力集合去重来判断完整性。尚未开始的工作还核对其接受上下文与当前批次，来源后来消失不要求它仍存在于当前战场。执行位置与挂起队列不一致、来源引用不存在或范围不匹配、删除一轮等损坏都会拒绝；结构一致性校验不代替存档的真实性认证。

终局保留未开始位置并标记中断，已完成的保留完成事实。普通回溯撤销旧计划及调用，保留结果式回溯每次建立新组；嵌套死亡具有自己的计划和执行顺序。回调失败、超预算或选择分支失败沿用原事务。完整来源计划仅供可信宿主，玩家DTO与玩家事件不含批次、贡献者或重复序号。
