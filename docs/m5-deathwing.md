## 公共有序选择

[ordered_choices.py](../hs_sim/engine/ordered_choices.py) 提供 `ChooseInOrder(player_id, options, count=1, source_id=None, prompt=..., purpose=...)`。选项复用 `ChoiceOption`，每项包含不可变效果元组。

- 每次请求选择一项，执行该项效果及其普通反应、死亡/亡语、嵌套选择，再显示余下选项；选过的项不会再次出现。
- 总次数在请求创建时固定。后续状态变化不改变剩余次数，但 `InvokeBehavior` 可以在分支实际执行时重新读取场面。
- 剩余选项、次数和分支全部存入普通结算帧；不保留 Python 调用栈或可变闭包。保存、恢复、克隆、回放复用原入口。
- 所有候选分支都通过允许列表编解码校验，不能把未知回调藏在未选项中。零次请求也检查来源与候选，且不挂起。
- 每段仍受同一根动作的结算预算限制；单次选择失败回滚到该选择前已提交的边界。终局停止后续选择与尾部效果。
- 玩家入口使用现有选择句柄、座位权限和 revision；旧 choice ID、重复选项、对手代选继续拒绝。

它与 `RequestChoice(min_count=..., max_count=...)` 的区别是顺序由多次单选表达；原多选继续按选项声明顺序执行，行为未改变。

## 公共指定卡牌费用

`CostSpec(card_ids=())` 新增不可变、唯一、非空字符串组成的白名单。空元组表示不限制 ID；非空时与 `card_types` 同时匹配。这里不要求白名单中的所有牌都已实现，也不会让未知牌自动获得执行定义。

```python
AddCostModifier(player_id, CostSpec(delta=-3, card_ids=('CATA_190h',)))
```

玩家持续修正、有限次修正、费用光环和单实体费用附魔使用统一匹配函数。玩家修正在每次报价时读取当前卡面，可影响后来生成的匹配牌；非匹配牌不消耗次数。生成费用在抽样前验证全部合格候选，不能靠随机抽中匹配牌来掩盖非法请求。单实体 `ModifyCost` 不匹配时跳过。

费用仍按本地附魔、玩家/光环附件顺序计算，最低为 0；当前复制不会把玩家修正另复制一次。期限与有限次数沿用公共生命周期。星舰发射费用不接受卡牌 ID 过滤。新字段进入快照、费用光环与挂起帧，因此提升 schema。

## 证据与暂定规则

[国服机制公告](https://hs.blizzard.cn/news/24245219/index.html) 支持兆示升级与死亡之翼灾变数量的关系；[国服上线公告](https://hs.blizzard.cn/news/24250357/index.html) 确认机制上线。卡面数值和分支来自冻结的 [本地数据](../data/extracted/cards.json)。这些来源不能证明精确服务端时序。

- **R-075：灾变顺序。** 原型固定战吼开始时的 1/2/4 配额，由玩家逐次选择不同分支，每段反应结算后再选择。四项全选是否在正式游戏自动执行、选择与效果执行的间隔、固定顺序、最高生命并列和终局窗口，仍待国服 M6 校准。
- **R-076：奥卓克希昂。** 暂定减费为“1 + 本次战吼开始前已完成兆示次数”，不采用士兵的 1/2/4 封顶倍率；其自身兆示之后安装已捕获的数值。暂定为来源独立、玩家永久修正，作用于当前/未来的审核死亡之翼 ID。具体公式、自身兆示计入点、手牌/牌库/后生成作用域以及历史/核心别名仍未取得国服逐项证明。显式白名单排除后嗣、死亡之翼子嗣和英雄皮肤；白名单内未适配旧版本仍明确不支持执行。

上述均是可复现的内部假设，不能称为官方校准通过。
