# M5-13d-02f 前置审计：牌库条件与永久次数政策

本页只记录下一开发项，不声明新机制已实现或对应卡牌已适配。

本地来源中，DEEP_020深岩矿工布莱恩要求“套牌里没有相同的牌”的起始条件，英文明确`deck started with no duplicates`；LOE_011雷诺·杰克逊的条件是当前牌库没有重复。两者不能查询同一个当前牌库列表后就当作一致。具体文本及指纹见[冻结来源](../outputs/m5-13d-02f-deck-source-candidates.json)，原始数据不等于国服目标补丁的最终有效文字，接入前应保留版本核查口径。

2026-09-25核对了官方[29.2.2补丁说明](https://hearthstone.blizzard.com/en-us/news/24087317)：2024-04-25对决战荒芜之地这组无重复卡作出调整，明确包括Deepminer Brann，把打出时检查改为开局卡组检查。这为拆分两种查询提供直接历史依据，不能代替当前国服完整热修核对，也没有证明同构筑身份归并、换牌边界和间接来源的全部细节。

现有代码已经在`Game.from_decks`保存`PlayerState.original_deck`，开局校验将其与MatchSetup绑定；后续抽牌、洗入、销毁不能修改原构筑事实。DeckPolicy校验已经用`metadata.deck_identity`归并同一构筑身份。普通Scenario只有局面，没有明确起始卡组证明，original_deck默认为空。不能将此空tuple直接判为已知宇宙套牌；未知和已知空牌库必须分开。

当前缺口是供规则组合的统一查询及其边界，不是缺少第二份起始卡组存档。永久次数政策已有AddBattlecryRepeatModifier（uses=None、expires_turn=None），来源离场和重复激活的次数合并也已有基础。先补查询，再验证条件→授予→之后手牌战吼捕获的全过程，避免把“起始条件成立”和“每次捕获时实时条件成立”混为一类。

恢复检查补充：`validate_opening_boundary`在缺少MatchSetup时只检查opening也为空；没有把Scenario中非空original_deck当作有证据的原卡组。新查询必须检查起始事实是否受开局记录约束，不能只看tuple长度；需测试人为填入original_deck的Scenario仍不能伪造“已知起始条件”。from_decks在BeginGame前保存原卡组，开局回调也已有original_deck输入，这个时点可复用，但需用保存/恢复和实际开局测试确认。

## 建议验收范围

- 明示查询当前牌库或起始卡组，使用已审阅构筑身份，未知元数据与未知起始事实不静默判真。
- 当前牌库为空/一张/重复，异卡ID同deck_identity，以及起始有重复但后来抽空的区别；必要时明确身份是否按基础/变形后卡面查询。
- 起始无重复后洗入重复、开局保证/换牌、后续卡组变化，都不重写原事实。
- 实际构筑开局、任意Scenario、保存恢复、完整回放和篡改拒绝；不得通过玩家观察导出对手原卡组。
- 条件成立后授予永久次数：来源死亡/沉默/变形仍保留，重复授予依公共政策组合；先决定自身战吼是否被既有捕获计划影响，再检查之后出牌。
- 同铜须、有限次政策、反制、伯尔纳和金刚鹦鹉组合，间接重演使用当前执行玩家的已知起始事实，不借用原出牌时条件结果。
- 必要代表优先DEEP_020；LOE_011只是对照需求，不为凑齐卡牌数量提前适配。场景未知时的处理应可解释且严格，不能从现有手牌/牌库猜造起始构筑。

沙德沃克集合/循环、连击重复、临时潜行、按种族筛选的正式来源调查均保持独立待办。Spirit of the Shark的重复类型已有kinds过滤基础，但连击尚不是独立可重复主体，不能直接把普通on_play全部重复。动态战吼授予应由真实构筑来源提出，不能从酒馆或冒险记录倒推出本主线需求。
