## 公共接口

`DeckCondition(scope='current'|'starting', predicate='no_duplicates')`为不可变声明。当前仅实现无重复条件；其他predicate明确拒绝，不把奇数/偶数、全法术等需求默认当作已支持。`matches_deck_condition(state, registry, player_id, condition)`供宿主和规则查询已验证状态，返回布尔值；不能把全知状态或对手卡组列表提供给玩家接口。

| 范围 | 使用事实 | 不会代替它的事实 |
| --- | --- | --- |
| current | 此刻牌库中的实体当前卡面 | 开局卡组、手牌、墓地、历史卡面 |
| starting | 构筑开局已保存并绑定MatchSetup的original_deck | 当前剩余牌库、猜测的初始手牌、Scenario中的空tuple |

按审阅后的`CardMetadata.deck_identity`归并同构筑身份；未指定别名时用card_id。当前牌库空或只有一张时满足无重复。需要检查的卡牌缺少元数据则抛出`UnknownDeckFacts`，不会因为此前已看见一对重复而掩盖未知信息。查询任一玩家都明确使用该玩家的事实。

起始事实要求存在构筑开局记录，恢复时由既有开局校验绑定原卡组和MatchSetup。任意Scenario没有该事实，即使人为填入original_deck也不能据此判定。此时抛出UnknownDeckFacts，不能当作条件失败，更不能判真。错误消息不返回未知牌的ID。

## 条件分支和保存恢复

`CheckDeckCondition(player_id, condition, on_match, on_miss=())`组合效果；两个分支都是不可变Effect tuple。条件轮到执行时读取状态，选定一次后将该分支交给公共结算器。条件之前的抽牌、洗入、销毁和变形已经生效；选中分支随后改变牌库或暂停，不会重新选择分支。新的一次战吼激活会重新执行查询。

```python
CheckDeckCondition(
    c.player_id,
    DeckCondition('starting'),
    (AddBattlecryRepeatModifier(c.player_id, source_id=c.source_id),),
)
```

条件声明和分支进入显式帧类型白名单，选择前后的待执行工作都可保存、克隆和回放。恢复还核对每个捕获RuleContext的起始卡组tuple及“有构筑起点”标志，必须与主状态一致；只核对这些不可变事实，不把旧上下文的当前牌库强行改成现在的牌库。未知事实按普通事务错误回滚：未暂停的操作回到操作前；已等待选择的操作回到该等待点。分支中的死亡、终局、反应和嵌套选择沿用公共调度，不另造队列或私有状态。

本批没有新增持久状态字段，因此snapshot schema仍为80，旧1～79仍拒绝；规则/效果包升至82，代表包45。旧schema80快照仍须匹配其原规则、处理器签名和注册表，不自动迁移到新版。观察46、命令7、外层replay1保持。

## 深岩矿工布莱恩与R-123

适配器只将起始无重复条件与既有永久战吼次数政策组合。成功授予没有使用次数和回合到期；来源死亡、沉默、变形、转控或回手不会撤销已授予的玩家政策。已有铜须可以重复授予，多份政策按现有取最大次数契约组合。该次战吼的次数早已捕获，自己刚授予的政策不会追溯修改自身批次。

反制原牌就不执行条件或授予；普通回溯重试恢复原状态，保留结果型回溯可以保留多份授予。伯尔纳和金刚鹦鹉的历史重演重新执行条件；物理载体转控后再激活时，查询这次执行玩家的起始卡组。所有这些仍与既有来源/回溯政策一起进入国服校准。

起始检查的历史依据是官方[29.2.2补丁说明](https://hearthstone.blizzard.com/en-us/news/24087317)，明确将包含Deepminer Brann的荒芜之地无重复卡组改为检查开局卡组。原始中英文字与指纹见[冻结来源](../outputs/m5-13d-02f-deck-source-candidates.json)。这不证明当前国服完整热修、合法池或所有边界；原始数据仍原样保留。

R-123待校准：起始事实相对开局改牌的准确时点、不同ID的身份归并、当前实体变形后的重复身份、条件求值检查点、间接来源重新求值和永久政策叠加。本批内部测试只证明实现契约，未关闭M6。
