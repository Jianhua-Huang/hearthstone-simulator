## 入口与物理身份

`Dredge(player_id, owner_id=None, source_id=None, on_select=None, reveal=False)` 从指定玩家牌库底部最多三张建立候选；owner_id 省略时使用选择者。选择者与牌库所属者可以不同，也可以由非当前行动方选择。候选是现存实体，不查询生成池，不排除重复、不可收藏或不在构筑池的牌。

每张牌保留独立 `CardReference`，包括所属玩家、区域、牌 ID 与修订号。同名而有不同增益的牌仍可分别选择。候选展示使用冻结 `CardPreview`：本地费用、攻击力、生命、最大生命、耐久与关键词，不含内部实体 ID 或可追踪牌库句柄。此结构也可用于其他明确允许展示当前属性的选择。

选择成功后将原实体置顶，保留所有未选牌的相对顺序和实体附件，不抽牌、不重新获取、不消耗资源、不召唤。置顶更新引用修订号；此前捕获的引用不再可用于该牌。离开后返回、变形或转控的旧引用跳过；纯洗牌仍可选择原实体。

## 后续行为与复制

`on_select` 是注册行为 ID。成功置顶后，内核以选中的实体作为 `RuleContext.target_id` 捕获行为上下文；未选中或引用失效不执行该行为。来源离场不撤销已捕获的探底。没有来源时，回调使用选择者英雄作为执行主体。

回调可以按选中的牌决定费用/属性修正、抽取、伤害、护甲、复制或召唤，普通选择可以继续暂停。对物理牌的后续操作应使用新的 `CardReference.capture(...)`，不能重新读取牌库顶并把另一张牌当成所选牌。反应将所选牌移走时，引用型效果跳过；已捕获的数值结果仍可执行。这一精确窗口登记为 R-094。

新增 `CopyStoredMinion(card, player_id, position=None, mode='current', stats=None)` 支持从手牌或牌库复制随从入场。原牌保留，新主体和附件分配新 ID；current 保留本地属性和附件，base 使用印刷定义。`SummonStats` 在入场通知前设定身材，复用巨型附肢和普通死亡检查；不会触发战吼。满场不复制，非随从明确报错。直接召唤所选原牌继续使用 `SummonStoredCard`，满场时保留原牌。

## 信息、来源与可恢复性

只有选择者看到候选身份、当前属性与选择结果。普通 `card_dredged` 公共事件只告诉另一方哪一方牌库发生探底；`reveal=True` 明确向双方展示选中牌的身份和属性快照，仍不创建牌库追踪句柄。未选牌不揭示，历史展示不跟随未来隐藏修改。

探底复用普通选择帧、玩家命令和累计结算预算。自动施法按其明确的 random/player 策略处理；重复法术每次重新读取牌库底部，不复用上一次选择。嵌套选择、克隆、保存恢复、动作回放和错误回滚均经过验证。加载检查选项数量、物理分支、描述与引用一致性，拒绝畸形预览或泄露给错误玩家的结果日志。

## 证据与未校准边界

[官方关键词说明](https://news.blizzard.com/en-gb/article/23765277/announcing-voyage-to-the-sunken-city-hearthstones-next-expansion)明确“查看底部三张、选一张置顶”。冻结卡文进一步要求对手牌库、揭示、按所选费用伤害、召唤原牌与鱼人复制。必要代表仅新增缴械元素 `TID_700`、损毁神像 `TID_703`、K9-0 型机械狗 `TID_099`、迷潮挖掘者 `TID_003`；不扩展为完整系列卡牌支持。

**R-094 暂定契约：** 候选展示顺序经本局 RNG 打乱，不暴露底部精确顺序；不足三张展示实际候选，一张仍提供选择，空库无选择且不疲劳。候选预览与当前代表的费用条件使用实体本地费用，精确光环/替代支付影响待校准。置顶前选择反应、置顶后反应、所选数据捕获、复制身材与外层死亡延迟均需国服组合证据。内部测试不等于官方一致性。
