# 进化封顶与退化空档

公共费用档变形采用[官方32.2补丁说明](https://hearthstone.blizzard.com/en-gb/news/24198086)公布的进化/退化规则。完整响应及SHA见[来源记录](../outputs/card-integration-20261014/k265-evolve-published-rules/rule-sources-01.json)。这项规则证据不认证国服37.0全部热修、正式合法池或卡牌特殊例外。

## 费用档计算

`cross_zone.transformed_cost_tier(source_cost, delta)`只计算起始目的档：正增量且原费用不超过10时封顶10；原费用超过10时保持原费用。负增量从`max(0, source_cost + delta)`开始寻找；零增量只查原费用，不启用退化回退。同卡面也是真正变形，仍执行原重置与入场流程。

`TransformMinionsInZones`及已有定向入口继续使用显式`cost_basis='printed'|'local'`。保留费用的`retain_cost_basis`独立计算，不因进化封顶或退化降档改变。各真实来源究竟使用哪种依据仍须逐卡核对，不能从公共参数推定。

## 空档与完整候选

负增量只按当前不可变版本池中实际存在的费用档降序探测，不按整数逐档循环。原费用很大时，工作量仍受物理池档位数限制。每档继续合取原职业、查询和生成政策；物理池存在该费用并不意味着过滤后有合格随从。

探测不抽样。遇到第一个合格档后保存完整有效查询；其中未知的合格定义必须报错，不能跳往低档或删除未知候选。没有任何合格档时保留原`empty='skip'|'error'`政策。整批先验证、捕获最终费用档和原费用保留，再开始实际随机与变形；较早目标的反应不会重算后续已接受档位。

物理引用、区域/位置、休眠、巨型、复制材料、原生或授予亡语、选择恢复、回滚、回放及玩家信息边界继续由既有执行器负责，没有新增结算器、状态账本或载荷字段。

## 原生变形替代

[魔荚人替代](m3-native-transform-replacement.md)复用同一费用档计算，输入仍是原目的随从的印刷费用，其既有额外增量为2。原目的9费或10费时目的档封顶10。原目的大于10费时当前实现沿同费计算；这项具名替代的高费特殊行为、区域、空池与复制例外仍是待M6的显式政策，不能由通用公告认定全部获得官方确认。
