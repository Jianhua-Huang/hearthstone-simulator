# M5-13d-02k-04：固定主动亡语次数

2026-09-25。内核`prototype-v95` / `core-effects-v95`、快照schema92、代表包55；观察51、命令7、replay1保持。**R-139为明确的原型政策，尚未国服校准。** 当前支持固定次数与既有场上/玩家亡语次数组合；仅自身获得亡语的范围仍待后续实现。

## 两类次数与执行位置

`TriggerDeathrattles(target_id, source_id=None, times=1)`在既有主动入口声明正整数轮次，拒绝bool、零、负数或其他类型。`DeathrattleBatch.trigger_count`记录该要求；`DeathrattleRepeatPlan.repetitions`仍只记录场上/玩家设值来源合并后的次数。两个字段不能互相代替：本批政策为主动轮次乘每轮来源次数，两个“两次”设值来源继续取最大值。

每个`DeathrattleCapture`增加`trigger_index`；原`repeat_index`保留为来源重复序号。同一能力在不同轮次保持同一附件ID，每次实际执行仍有独立捕获ID/执行序号。排列为主动轮次、能力顺序、来源重复。例如两个能力A/B、主动两轮、来源两次：第一轮A1/A2/B1/B2，再第二轮A1/A2/B1/B2。完整位置在复制挂起上下文前一次性登记。

这两个维度均属于亡语批次。外层战吼重复先按照既有战吼机制执行，每次到达主动入口再产生独立亡语批次；历史战吼重演也经同一入口，不把战吼索引混进亡语重复索引。

## 接受、生命周期与新局面

一次主动入口接受时冻结载体、控制者、原能力顺序、来源计划和固定轮次。目标随后沉默、变形、回手或转控，以及次数来源随后移除，不取消已接受的执行。新增能力或更强来源不进入这次已接受批次；新的主动入口重新捕获。无载荷不创建空批次，失效/休眠目标仍沿用既有stale处理。

第一轮每项能力的首次回调保持原接受上下文；来源重复以及第二轮起的回调读取先前结算后的新局面，保留接受的身份与次数。该窗口延续R-137并由R-139扩展到固定轮次；不能据此认定目标离场后继续执行或排列已与国服一致。

主动触发仍不制造死亡、尸体、复生或星舰组件。载荷引起的真实死亡各有自己的自然批次，自然批次的主动轮次永远为一；自然来源重复仍可为多次。原`InvokeDeathrattle/FinishDeathrattle`控制工作、死亡/光环检查点、终局截断和原子事务保持，不新增平行解释器或玩法事件。

## 保存、恢复与工程预算

schema92保存`times`效果参数、批次`trigger_count`和每次捕获`trigger_index`；旧schema1～91明确拒绝，无隐式补默认值。批次位置函数统一生成与校验完整二维次数顺序；恢复还核对挂起工作/实时批次一致、唯一位置、按序执行、来源次数及自然入口的一轮约束。缺失整轮、重复位置、改动次数或乱序挂起均拒绝。

批次创建前按完整总位置检查预算，防止超大固定次数先分配巨大历史。其后每个控制工作仍计入原累计预算。暂停发生在主动效果之前或任一执行位置时，保存原要求并从原位置恢复。普通回溯撤销完整计划，保留结果式回溯建立新计划；错误和终局延续公共处理。玩家DTO没有新增内部次数轴，完整计划仅供可信宿主。
