# 自动整牌的实际族身份与重复许可

这是传统构筑的内部机制契约，当前证据和下一项仅在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护；不以物理来源接通宣称最新卡池或国服时序完整。独立目标声明沿[生成主体契约](m5-generated-body-targets.md)，卡牌只组合公共能力。

## 四种实际来源

| ReplayWholeCards.physical_profile | 战吼次数 | 连击次数 | 保留结果 |
| --- | --- | --- | --- |
| generated_after_install_v1 | 每条一次 | 激活后每条一次 | 无 |
| generated_battlecry_repeat_after_install_v1 | 自己的完整 max | 激活后每条一次 | 无 |
| generated_family_repeat_after_install_v1 | 自己的完整 max | 自己的完整 max | 无 |
| generated_retained_family_after_install_v1 | 自己的完整 max | 自己的完整 max | 自己的原结果组 |

所有来源先完成实际安装及入场反应，在安装结束窗捕获当时完整普通文本、战吼和连击向量。召唤数量增加的额外交付沿召唤契约，不另制造整牌主体。满场或安装失效不伪造接受。

执行身份与次数许可是两个能力：单次与仅战吼重复入口同样需要实际 ComboRecord、原 ComboAcceptanceReceipt 和完成标记，不能直接回调文本、借用手动 PlayRecord，或为了获得身份误选族重复入口。

## 连击接受及实际执行

`generated_combo_repeats.py` 的 SINGLE_PROFILES 和 REPEAT_PROFILES 明确次数许可，PROFILES 覆盖四种实际来源。`capture_generated_activation` 核对真实子项、来源、完整声明、当前安装及原历史窗口后，单次来源仅产生默认 `ComboRepeatPlan(1, (), ())`。

单次来源不查询场上连击重复来源、不匹配玩家连击政策、不消费任何连击重复用途。它们保存自己的空政策收据并完成一次 application，供统一历史和恢复校验；这不意味着消费一个空池以外的政策。仅战吼重复入口仍按自己的战吼政策保存完整 max，并且一次消费相应用途。族重复及保留入口保持原连击 max 与用途契约。

连击条件来自实际执行者在该安装结束窗的已提交手牌历史；其他执行者可以 disabled。disabled 保存完整声明而不产生实际 ComboRecord；no_payload 保存空声明和接受义务；地标不伪造连击族。没有手牌支付、出牌前政策窗或第二条 PlayRecord。

每条激活连击在执行前绑定实际记录、物理 child、原 payload 和自己的 repetition/iteration 身份，再发布 combo_started。主体运行后按原 FinishCombo 完成；启动监听、主体选择和完成监听均可挂起，完成监听看到已完成但仍绑定的当前记录。解释器继续队列不得裁掉 FinishCombo 或物理根的 Finish。

采用独立目标来源时，各声明分别冻结自己的门槛、目标域、原选择与 RNG。随机、指定目标、必选空池和当前目标失效沿既有生成模块；失败也有实际记录并完成，只跳过对应主体。普通根空目标不删除连击。单次窗口不因为主体改变水晶重新接受剩余条件。

## 生命周期、事务与证明

安装反应前的选择尚无主体接受；接受后沉默、转控、死亡、变形或跨区不替换剩余原向量与执行者。晚授予不扩张向量。终局只保留实际已开始记录，不伪造后续执行；未知主体造成整个动作的安装、支付、用途、历史和 RNG 回滚。

活动 PhysicalBodyProof 重捕原窗口、完整族接受和政策前缀；实际记录及挂起完成标记与原接受一一对应。关闭校验依据实际 activation.profile_id：单次来源禁止非空连击政策、贡献者、用途或大于一的计划，即使注入真实存活政策 ID 也拒绝。不能裁实际 ID、替换物理根或借用付费身份。各来源不因共享目标值类型获得其他来源权限。

快照恢复、clone 和独立注册表动作 replay 沿公共引擎；证明、原状态和物理映射不进入玩家接口。关闭事实提供内部一致性，不能认证未签名存档的外部来源或独立恢复全部过去资源。
