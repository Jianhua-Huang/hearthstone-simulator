# M5-09d：动态回响与手牌关键词

本批补齐持续手牌关键词光环、对手牌/牌库卡的直接关键词授予，以及动态回响的提交资格。使用合成定义验证，真实卡牌适配数量不变。实现见 [keyword_auras.py](../hs_sim/engine/keyword_auras.py)、[hand_keywords.py](../hs_sim/engine/hand_keywords.py) 和 [temporary_cards.py](../hs_sim/engine/temporary_cards.py)；[55 项专项测试](../tests/test_m5_hand_keywords.py) 覆盖生命周期、恢复、来源窗口、玩家接口及组合。

## 两种公共能力

```python
# 场上随从提供实时光环，随来源失效而撤销。
KeywordAuraSpec(Keyword.ECHO, 'friendly_hand_minions')
# 也支持 friendly_hand_spells 或 friendly_hand（随从与法术）。

# 针对捕获的手牌或牌库引用，赋予实例附件。
GrantStoredKeyword(CardReference.capture(card), Keyword.ECHO,
                   source_id=source_id, expires_turn=turn)
```

光环复用 `CardDefinition.keyword_auras` 和 `GrantKeywordAura`。新手牌范围没有场上相邻/包含自身选项；来源仍须是生效中的场上随从。随从手牌也支持已有非消耗型连续关键词，例如风怒和嘲讽；法术/混合手牌范围目前只支持回响。圣盾、潜行、复生等消耗型能力不接受连续光环，避免重新计算时不断补回已消费能力。

直接授予用 `GrantStoredKeyword`，接受带区域修订号的 `CardReference`。支持随从的普通关键词和回响，法术仅回响；牌移动后旧引用失效，即使原实体重新回到手中也不误命中。未知来源、已过期授予和不支持的卡牌/关键词组合明确报错；双生法术、微缩、泰坦等需要专门声明的关键词不能靠该接口伪造。

## 生命周期与资格

| 情况 | 持续手牌光环 | 直接授予的实例能力 |
| --- | --- | --- |
| 原来源死亡、沉默、变形或回手 | 撤销贡献；其他来源仍可维持同一关键词 | 附件继续存在，直到自己的删除/到期规则生效 |
| 来源转控 | 对新控制者手牌生效 | 已授予目标不随来源一起转移 |
| 来源休眠 | 不贡献光环 | 不追踪来源后续是否休眠 |
| 目标从手牌进入场上/牌库/墓地 | 手中专属贡献撤销 | 沿用附件保留/重置规则；普通出牌保留，回手重置清除 |
| 当前复制 | 不复制光环贡献；按目的地重新计算 | 复制附件，重新分配附件 ID |
| 基础复制/重置 | 按目的地重新计算 | 不保留授予附件 |
| 升级换形 | 重算目标类型对应的光环 | 复用升级的附件保留及类型转换限制 |
| 重叠来源 | 关键词并集，不叠成多个回响副本 | 与印刷/光环回响同样去重 |
| 到期 | 来源能力到期后撤销 | 只移除能力；不是弃牌或删除原牌 |

出牌前从有效关键词捕获回响，印刷、光环和直接授予共用一个重复入口。即使支付、进场或后续效果使原来源失效，已经捕获的本次提交仍生成一张基础副本。第一个光环来源不追溯给自己的出牌加回响；已有另一个来源时则可获得回响。

生成的临时副本保留 [回响契约](m5-echo.md) 的当回合期限和最终 1 费下限。光环来源之后离场，只影响是否还能继续生成，不撤销已经生成副本的期限与下限。直接授予回响不随基础复制自动继承；若无其他印刷/光环来源，返回的基础副本没有回响。无关键词重复与回响同时有效时，当前策略合并为一张具有回响下限的副本。

## 状态、事件与信息

`Entity.hand_aura_keywords` 是独立派生缓存，与场上 `aura_keywords`、永久能力附件分开。普通重算同步更新；事件捕获前还会更新手牌贡献，使新抽到/生成的卡在获取事件的冻结上下文中已经具有光环能力。该过程不提前重算场上属性和关键词的既有窗口。

原型采用“死亡检查实际移除来源后撤销”的规则，延迟死亡期间仍在场的来源继续贡献。选择挂起时可以保存这种状态；恢复检查派生缓存和来源一致，无法用伪造缓存添加能力。精确死亡/事件窗口属于 R-086。

新增私有事件 `stored_keyword_granted`，只给目标控制者且仍受已知身份限制；不揭示未看见的牌库牌。拥有者观察使用已有 `keywords`，对手即便记得卡牌身份也看不到后来的隐藏能力变化。内部贡献字段、能力来源和附件 ID 不进入玩家接口。

当前 snapshot schema 74 拒绝旧 1～71；新私有事件使玩家视图升级为 player-view-v44，玩家命令仍 player-actions-v7，外层 replay schema 1。保存、恢复、克隆、动作回放和失败回滚纳入专项验收。

## 依据与 R-086

冻结的 `GIL_618`（格林达·鸦羽，dbf 47295）文本要求手中随从获得回响，表明必须有实时手牌作用域。原始卡牌数据指纹与该依据见 [目标清单](../data/targets/local-2026-09-23.json)；这不证明国服合法池、服务器实现或每个边界。

官方回响介绍支持基础副本；2019 年费用调整明确包括格林达，支持动态来源生成的回响副本同样受 1 费下限约束。[官方关键词说明](https://hearthstone.blizzard.com/en-us/news/21658543)、[官方费用调整](https://hearthstone.blizzard.com/en-us/news/23239986)

**R-086 原型假设：** 获取事件前的手牌重算、延迟死亡期间贡献、一次直接授予产生的基础副本不继承附件、临时期限不因光环撤销而取消、无关键词重复与回响去重，均需国服校准；内部测试只验证这些明确选择。

本批不声明任意条件光环已齐全。种族/条件筛选、玩家长期效果作为手牌光环来源、其他特殊关键词的动态授予继续登记在 M5；具体真实卡适配归 M7。[招募与死亡历史复活](m5-summon-sources.md)、[自动施法与独立历史](m5-spell-casts.md) 已有公共子集内部验收，[抽到时施放/抽取链](m5-draw-casts.md) 已内部验收，M5-10d 历史重施/历史发现与池内批量施法已有内部验收；M5-11a 回溯检查点已内部验收，M5-11b 次数卡面与生命周期已内部验收，M5-11c 保留多结果已内部验收，M5-12b-01 发掘进度通过内部验收，多技能组合已内部验收，当前执行位置见 [项目状态](project-status.md)；统一校准仍安排在 M6。
