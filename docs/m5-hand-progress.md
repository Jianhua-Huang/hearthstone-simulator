# M5-03b：手牌进度、腐蚀与注能

当前 `prototype-v75` / `core-effects-v75`，snapshot schema 74，`representative-m5-v38`，`player-view-v44`。这批完成手牌进度的内部契约及七组真实卡形态；完整卡池、特殊例外和国服精确时序仍未验收。

## 声明与独立实例

`CardDefinition.hand_progress` 使用 `HandProgressSpec`，由生命周期模块安装独立的 `AbilityInstance(kind='hand_progress')`。每个实体分别保存当前计数、完成次数、已消费事件键和能力实例 ID。同名牌不会共用计数，回调不保存可变进度。

```python
from hs_sim.engine import CardDefinition, CardType, HandProgressSpec, Keyword

card = CardDefinition(
    'example.base', '示例', CardType.MINION, cost=2, attack=2, health=3,
    keywords=(Keyword.INFUSE,),
    hand_progress=HandProgressSpec('infuse', 3, 'example.infused'),
)
```

目标形态、条件和回调必须事先注册。`condition_id` 引用共用条件注册表，返回严格布尔值；它可读取冻结的死亡或出牌记录。`on_progress` 和 `on_complete` 分别返回公共效果。只写裸 CORRUPT/INFUSE 关键词会被拒绝；它们必须关联有效声明。宿主不会从卡牌文本自动推导行为。

`kind='event'` 可监听显式事件并使用注册条件，这是内部扩展接口；它不代表任意手牌触发已经具有官方规则。重复进度使用 `repeat=True` 并通过完成回调表达效果；多段换形则让下一形态带有新的进度声明。

## 具名重复与多段需求的现有表达

“无限注能”沿既有`HandProgressSpec('infuse', goal, on_complete=..., repeat=True)`。每个合格友方随从死亡各消费一个独立死亡见证，达到门槛后清零当前计数、增加完成次数并继续监听，不设完成次数上限。例如五个死亡、门槛二，形成两次完成并剩余一；余量来自后续独立死亡，不是把同一事件的超额单位递归转给下一轮。`event_amount`目前只支持非重复generic事件进度，不能用它伪造一次死亡的多个无限周期。

“再次腐蚀”沿连续印刷形态：基础形态指向第一升级，第一升级仍声明`corrupt`并指向最终形态。两次分别合格的出牌各推进一个阶段；各形态费用继续参与原提交前报价。内部进度升级保留链身份和已消费play键，所以一个出牌不会反复腐蚀同一条链。每阶段进度归零，最终形态不需要再声明腐蚀；选择、复制、外部变形和区域恢复沿上文既有政策。

这些是已有公共能力的具体路由，无需新增“无限注能”或“再次腐蚀”执行器。固定本地`REV_906/CORE_REV_906`和`DMF_117/t/t2`的原行只证明具名需求，未认证当前正式数字、完整德纳修斯伤害主体或连环灾难随机主体。独立流程证据、原专项实际结果和下一项只在[项目状态](project-status.md)及[机制清单](mechanism-backlog.md)维护，精确国服规则仍待校准。

## 腐蚀的资格与完成

出牌提交前，`prepare_play` 同时冻结该牌的费用报价与手牌中腐蚀牌的当前报价。仅严格更高费用满足资格；相等、较低和随后才生成、抽到或复制的牌不计入。候选保存实体、控制者和能力实例 ID，进入原 `PlayRecord`，不能在出牌完成时重新扫描并追认新手牌。

升级在 `card_played` 完成事件中处理，出牌本体及其死亡结算在先。反制仍沿既有“已打出但效果被反制”的完成路径计数；技能、交易和锻造不是出牌。英雄致死中断、未完成的出牌不伪造完成事件。一个 play ID 在同一条进度链只消费一次，恐怖增生体不会递归腐蚀自身。

费用比较使用提交时的数值报价；特殊替代支付及卡牌单独例外尚未完成正式校准。**R-061** 跟踪候选冻结、费用比较、反制/终局及场上触发和手持触发之间的窗口。

## 注能的死亡见证

捕获手牌候选时保存能力实例，执行时根据事件的 death ID 读取不可变 `DeathRecord`：必须是战场随从，死亡时由该手牌控制者控制。敌方随从、弃牌、武器和地标不计入；对手回合中己方随从死亡可以计入。复生后的随从是新实体，其再次死亡产生新的见证。

同一死亡键不能重复增加进度。批量死亡仍逐个推进；达到门槛后通过 [公共升级](m5-hand-upgrades.md) 换形。连续多段升级保留进度链 ID 和已消费键，下一阶段计数归零，因此同批余下死亡仍能推进下一阶段。无限进度每完成一次减去一个门槛并保留余数。普通外部换形不继承这条链。

当前捕获顺序为原有场上/玩家等监听在先，手牌监听在后；手牌按当前回合玩家、另一玩家及各自槽位排序。前置反应如果让候选离开手牌，其待处理进度失效；死亡后才生成的手牌也不会追认旧死亡。此顺序是明确的原型契约，不能当作官方顺序认证。

## 生命周期与保存

| 操作 | 进度处理 |
| --- | --- |
| 单纯重排或增益 | 保持实例、计数和已消费见证 |
| 当前状态复制 | 新实体/能力 ID，复制计数与见证；不继承尚未执行的候选事件 |
| 基础复制 | 按当前卡牌定义新建，进度归零 |
| 无重置移区 | 保留计数但更新能力 ID；非手牌区不监听，旧候选失效 |
| 重置移区、打出后回手 | 按当前定义重装；未完成计数归零，已升级牌面保留 |
| 进度自身换形 | 保留实体、附魔和连续进度链；下一阶段按新声明开始 |
| 外部换形 | 安装新印刷进度，旧事件不再命中 |
| 保存、克隆、回放 | 保存见证、候选、阶段、挂起帧及选择；恢复后不重复消费 |
| 回调错误或无效条件 | 当前动作完整回滚，含费用、死亡、进度和玩家知识 |

进度完成先写回，再执行完成回调；回调可以请求选择。后续死亡和升级能跨选择保存、恢复。随从变武器复用显式生命转耐久规则，详见 R-059；复制、跨区保留与连续阶段的官方例外由 **R-062** 跟踪。

## 玩家信息与版本

控制者手牌观察增加 `hand_progress`：种类、当前值、目标值、完成次数与是否完成；不会返回能力 ID、候选或见证列表。`hand_progressed`、`hand_card_upgraded` 为控制者私有事件。对手视图和日志不因隐藏牌的不同进度而暴露其身份。公开实体可显示其进度字段；实际公开提示及已知手牌的身份处理仍归 R-060 校准。

快照 schema 74 保存 `HandProgressSpec`、实例计数/见证以及 `PlayRecord.corrupt_candidates`，旧 1～71 明确拒绝。载荷使用注册类型白名单和严格字段校验，不读取可执行回调。玩家动作 v5、外层 replay schema 1 不变。
