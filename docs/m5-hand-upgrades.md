# M5-03a：区域引用、存储卡增益与手牌升级

原upgrade_face新增内部显式spell_to_minion参数，仅供generic accepted-cast进度的真实SPELL到MINION配对。普通UpgradeHandCard不自动拥有该转换；原费用/数值附魔保留，额外授予能力明确拒绝，原目标卡面和普通随从出牌/战吼复用，详见[契约](m3-held-draw-forms.md)。

本页原批次为 `prototype-v75` / `core-effects-v75`，snapshot schema 74，代表包为 `representative-m5-v38`，信息版本为 `player-view-v44`。本页记录 M5-03a 的基础契约；M5-03b 已在此基础上接入 [手牌进度、腐蚀和注能](m5-hand-progress.md)。M5 整体仍未完成。

## 为什么先建立公共升级操作

既有锻造已经在手牌中替换印刷形态，但代码位于独立主动操作内。腐蚀、注能同样需要升级，却有不同触发资格；直接调用战场 Transform 会错误地清除附魔，也无法处理储存区的属性变化。

另一个实际缺口是区域引用只核对实体 ID、控制者、区域和卡牌 ID。同一实体离开手牌、原样返回后，旧引用又会匹配。进度事件和选择的延迟结算尤其需要避免这种误命中。本批先补修订号并提取公共操作，锻造已迁移使用同一实现。

## 捕获引用的修订号

`Entity.zone_epoch` 是单实体的非负整数，`CardReference.capture(entity)` 冻结它。构造 `CardReference` 时必须显式提供修订号；推荐总是使用 capture。

以下动作推进修订号：实际移区/换控制者的区域操作、公共移动、洗入牌库、手牌变成英雄，以及印刷牌面发生变化。换手牌顺序、普通增益、改费、同名形态的重复升级不推进修订号。复制分配新实体，初始修订号为零；快照和克隆保留原值。

引用在执行时同时核对身份、控制者、区域、牌面和修订号。任意不符即发布宿主诊断 `zone_target_skipped` 并跳过；不会把离开后返回的卡视为原候选。旧 MoveCard、CopyCard、DiscardCard 及区域选择也复用这个检查。

这不是玩家知识字段，也不是每次属性变化的版本号。它不保证任意宿主代码在内存中强行修改实体也能维持不变量；扩展应通过公共效果变更区域和形态。

## 公共效果

```python
from hs_sim.engine import BuffStoredCard, UpgradeHandCard
from hs_sim.engine.zones import CardReference

card = CardReference.capture(context.state.entities[entity_id])
effects = [
    BuffStoredCard(card, attack=2, health=3, source_id=context.source_id),
    UpgradeHandCard(card, "registered.upgraded.form"),
]
```

BuffStoredCard 接受手牌或牌库中的随从，写入普通有序附魔；负攻击可表达减攻，生命增益必须非负。它支持来源和回合到期，零改变量不创建附件。当前不支持用此效果修改武器、法术、地标或英雄的储存属性；错误类型明确报错。它不会扩大战场 Buff 的目标域，不会让已离场的伤害/战场增益突然继续命中手牌。

UpgradeHandCard 只接受手牌中的物理牌，目标定义必须已注册、可从手牌打出且不是组合星舰模板。普通升级保持卡牌类型；改变类型必须使用下面的显式转换。它保留实体 ID、原主人、当前控制者和手牌位置，更新印刷攻击/生命/费用、耐久、类型与规则；旧印刷能力重装，动态授予的能力及普通附魔保留原实例 ID。属性设值附魔仍覆盖新基础值，费用修正仍经过既有报价管线。

升级本身不支付出牌费用，不生成 PlayRecord，不算召唤、抽牌或再次打出；战吼在之后实际打出新形态时才执行。相同牌面不重装印刷能力，避免重置已经消耗的能力。锻造仍通过 UseHandAction 支付独立费用、发布既有 card_forged 事件；其升级步骤现在调用同一公共函数。

### 生命转耐久

`UpgradeHandCard(..., health_to_durability=True)` 仅允许随从变成武器。它把变化前的剩余生命冻结为新耐久，将当前基础改为武器定义，清除伤害/护甲/冻结/消灭状态，以及附魔中的生命加值/设值，保留攻击和费用部分。由此武器不会同时具有随从生命；仅在之后打出时才进入装备位。

当前允许转移武器已能解释的动态攻击关键词、亡语、普通触发、费用光环和非暴怒有限次触发。其他授予能力没有转换规则时明确报错并回滚，不能默默删除。组合星舰也明确拒绝此通用升级。转换后原临时攻击仍会到期，冻结的耐久不跟随原生命附魔反向变化。

这一转换来自当前本地数据中魔钢处决者随从/武器形态及“生命成为耐久”的附魔线索，但尚无完整国服交互校准。**R-059** 跟踪附魔、受伤生命、临时效果和特殊授予能力的正式解释。M5-03b 已另行适配魔钢处决者的真实腐蚀形态，正式转换边界仍需校准。

## 生命周期、信息与恢复

| 情形 | 已实现行为 |
| --- | --- |
| 升级后复制当前卡 | 新实体、附件 ID，复制当前附魔和升级形态 |
| 升级后复制基础卡 | 新实体，按升级后定义建立基础属性 |
| 打出再回手 | 保持升级后卡牌定义，按原有回手规则移除普通增益 |
| 过期附魔 | 保留原到期回合，由共用到期流程处理 |
| 牌面 A→B→A 或手牌→牌库→手牌 | 即使回到原名称/位置，旧引用也失效 |
| 手牌升级 | 保留对手槽位句柄，撤销已知旧牌面，不自动揭示新身份 |
| 隐藏增益 | 对手即使记得卡名也看不到新增属性或私有增益日志 |
| 选择中保存 | 记录带修订号的效果引用，恢复后按真实区域/形态重新检查 |
| 异常 | 整个动作回滚，含附魔、修订号、费用、牌面和玩家知识 |

`stored_card_buffed`、`hand_card_upgraded` 是独立的私有事件种类，只允许控制者接收；牌库身份仍不对其公开。它们不会在对手日志中暴露“某一张隐藏牌升级了”这一额外提示。观察 schema 的结构未加入修订号，该事件允许集于 v16 加入，该更早批次信息版本为 v32。**R-060** 保留自动腐蚀/注能的官方可见提示和公开已知牌面策略待校准项。

原批次快照 schema 74 包含实体修订号及引用载荷，旧 1～71 拒绝加载。缺失、布尔、负值或字符串修订号不补默认值。新效果在既有类型白名单中注册，JSON 不加载回调代码。外层回放 schema 1、玩家命令 v6 保持。
