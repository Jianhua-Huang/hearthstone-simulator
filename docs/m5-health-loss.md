# M5-07b-03b-05：生命损失替换与奥妮克希亚

运行时 `prototype-v75` / `core-effects-v75`，snapshot schema 74，代表包 `representative-m5-v38`，玩家观察 v39、命令 v6、外层 replay 1。旧 schema 1～73 明确拒绝。本页定义可执行的原型契约，精确国服交互仍由 R-082 跟踪。

## 共享的生命损失入口

`health_loss.py` 处理最终生命扣除，与伤害数值、治疗和费用报价分开。`HealthLossKind` 区分 `DAMAGE`、`PAYMENT` 和显式效果 `EFFECT`。卡牌通过 `CardDefinition.health_loss_replacements` 声明公共能力；动态效果使用 `GrantHealthLossReplacement(target_id, spec, source_id, expires_turn)`。

```python
health_loss_replacements=(HealthLossReplacementSpec(),)
```

默认只保护当前控制者的英雄，且只在该玩家自己的回合生效。来源必须是活跃、尚未死亡的场上随从。`own_turn_only=False` 和 `kinds=(HealthLossKind.PAYMENT,)` 可分别扩展回合范围和损失类别。字段严格校验，未知类别、重复类别、空集合和非布尔开关均拒绝。

每项能力有独立附件身份，沉默、死亡、休眠、变形、转控、回手、复制及到期复用既有生命周期。多个合格来源只替换同一次损失一次，选择附件 ID 最小者作为诊断来源；不会按来源数量重复增长。

## 三条结算路径

| 路径 | 原型结算顺序 | 事件与限制 |
| --- | --- | --- |
| 伤害 | 转换/重定向/数值修正 → 免疫/圣盾 → 护甲 → 最终生命损失替换 | 保留名义伤害和吸血计算；替换时补充实际扣血为零的诊断 |
| 生命费用 | 公共费用报价/资格 → 护甲 → 最终生命损失替换 | 仍记录一次完整 `health_spent`，不制造伤害或治疗事件 |
| `LoseHealth` | 检查存活角色 → 最终生命损失替换 | 绕过护甲、免疫、圣盾和伤害修正；无替换时可致死 |

伤害批次开始时捕获替换资格，同批次中来源先受到致死伤害仍适用于该批次英雄伤害；不同效果之间重新检查来源。替换本身不会插入死亡检查点，仍在公共批次结束后运行死亡和反应。

伤害和治疗的转换先执行：伤害已转换为治疗时不会进入损失替换，治疗转换为伤害时会进入。重定向使用最终目标判断是否保护英雄。吸血目前沿用未被防止的名义伤害；这些精确语义是明确版本化的暂定合同，不等同官方验证。

生命支付的资格检查与实际结算调用同一个纯查询。替换生效时允许支付超过剩余生命与护甲之和的费用；仍只支付一次，不重复写入出牌历史。尚在手中的奥妮克希亚不能保护自己的入场前支付。护甲费用本身、法力和尸体支付保持各自资源语义。

## 上限增长、事件与保存

被替换的生命扣除改为永久上限增长：增加上限与当前生命相同数值，保留原有缺失生命，例如 23/30 遭遇 3 点生命损失后变成 26/33。`GainMaxHealth(player_id, amount, source_id)` 也可显式请求该操作。

增长使用有独立 ID、保留来源的英雄附魔，不随保护来源离场消失，也不因沉默移除。英雄替换沿用既有附件保留规则。它不是治疗，不发出 `healed`，不受治疗倍率影响；后续治疗仍按真实缺失生命结算。

新增公开事件类型 `health_lost`、`health_loss_replaced`、`max_health_gained`；其中 `health_lost` 用于未被替换的显式损失。伤害仍使用 `damage_dealt`，支付仍使用 `health_spent`，消费方不能只依赖 `health_lost` 统计全部生命变化。全知事件携带损失类别、替换来源/能力 ID、增长前后属性与附魔 ID；玩家日志只投影既有公共字段，不公开内部附件身份或隐藏卡信息。

能力与附魔进入普通快照；选择分支可直接携带 `LoseHealth`、`GainMaxHealth` 和授予效果，经允许列表中的类型化队列恢复。无额外全局状态、闭包状态或独立卡名结算器。失败沿用事务回滚。

## 真实代表和证据边界

`CATA_155` 复活的奥妮克希亚按冻结本地记录为 9 费 3/6、两枚鲜血符文、巨型+2。主体声明公共替换能力，左右附肢使用既有 `CATA_155t` / `CATA_155t1` 实验生成和本回合生命费用规则；没有空位生成附肢时，主体能力仍生效。

官方 35.0.3 明确修正了奥妮克希亚生效时，生命费用超过剩余生命也应允许打出的资格问题。这支持本次共享资格查询，不单独证明全部结算窗口或国服热修的精确部署时间。[官方 35.0.3 更新说明](https://news.blizzard.com/en-us/article/24271854/35-0-3-patch-notes)

官方 35.4 修复了裂命者无法识别奥妮克希亚带来的英雄生命增长。该记录支持保留独立增长事件；本批没有接入裂命者，也不据此推断增长等同治疗。[官方 35.4 更新说明](https://news.blizzard.com/en-us/article/24266874/35-4-patch-notes)

**R-082：** 当前采用增长保留缺失生命、同批次捕获资格、多个来源只替换一次、名义伤害/吸血不变的原型语义，国服集中校准未完成。直接设定生命、减少生命上限、英雄替换和消灭不自动当作 `LoseHealth`；其中上限增减与转移已有独立 [公共操作](m5-health-transfer.md)，一般生命设值仍按具体卡牌规则补充。生成池仍是实验池；奥妮克希亚的次要种族标签尚未从本地数值标签可靠解码，不能声称相关种族筛选已完整支持。
