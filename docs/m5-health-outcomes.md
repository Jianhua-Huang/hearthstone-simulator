## 在结算点保存事实

每个有效目标的伤害或治疗段结算后，都生成宿主事件 `health_resolved`。包括伤害被阻止、零伤害、零实际恢复和满血治疗；失效目标仍走原有跳过诊断，不伪造结算结果。旧的 `damage_dealt`、`damage_prevented`、`healed` 事件及其实际触发次数保持，新增事件不会冒充又一次伤害或治疗。

不可变 `HealthResult` 保存在事件的元组负载中，由 `health_result(event)` 严格解析，回调也可读取 `ctx.health_result`。它不是另一份可变生命账户，复制、回手或变形不会改写旧结果。主要字段分组如下：

| 分组 | 捕获事实 |
| --- | --- |
| 关联 | 批次标识、批内段序号、回合和当时行动方 |
| 来源 | 来源实体、卡牌、控制者、区域修订和入场序号；正式攻击的原装备实体/安装身份 |
| 目标 | 实体、卡牌、控制者、角色类型、区域修订和入场序号；原目标与重定向路径 |
| 数值 | 声明数值、规则修正后数值、法伤、实际伤害、护甲吸收、生命损失/增加/被替换量、实际治疗与过量部分 |
| 前后状态 | 每段开始前和结算后的生命、上限、护甲、待消灭标志 |
| 路径 | 原始/最终伤害或治疗流、类型、转换/吸血标志、预防原因和规则实例 |

批次标识使用该批开始时的宿主事件游标，不增加第二个状态计数器。段序号还区分同批内的吸血恢复。原来源属性和资格按已有同时结算契约从批次开始快照读取，目标前后数值则按每段实际结算顺序捕获；同批第二段不能把第一段已经降到零血的目标重新算作新的精确击杀。

生命损失替换可能增加生命及上限，因此 `health_gained` 与 `health_replaced` 独立于普通 `healed`。例如原有生命损失增长替换把 30 血变为 33 血时，结果保存增加三点和替换三点，而不是伪造三点治疗。初始英雄或存储来源的入场序号允许为零。

## 三个共享条件

- `is_overkill(event, source_id)`：最终是未被阻止的伤害，归属于指定直接来源或该次攻击的原武器，来源控制者正处于自己的回合；目标在该段前仍有正生命且尚未待消灭，生命损失超过此前生命并造成数值致死。原型允许友方目标；此边界留待 R-109 校准。
- `is_honorable_kill(event, source_id)`：采用上述来源、回合和原先存活条件，另要求敌方目标，生命损失恰好等于此前生命。
- `is_overheal(event, target_id)`：最终是未被阻止的治疗，指定目标在该段前仍存活，修正后的治疗量超过缺失生命。没有己方回合限制，满血接受正治疗也有过量部分。

条件只读捕获结果，不读取执行回调时已经变化的目标。护甲先吸收后，以生命损失判定数值致死；圣盾、免疫、预防及不足以数值致死的剧毒不满足击杀条件。治疗转伤害可满足数值击杀，伤害转治疗可满足过量治疗，均按最终流分类。被生命损失替换而未致死的伤害不满足击杀条件。

这些函数提供判定，不会给任意实体自动安装卡牌效果。常驻随从、武器使用已有 `TriggerSpec('health_resolved', behavior_id)`，在行为中调用共享条件后组合普通效果。动态授予、复制、沉默、变形、到期和转控沿用原能力生命周期。需要有限次触发时，可以把共享条件注册为 `LimitedTriggerSpec` 的 `condition_id`，复用实例守卫和消费逻辑。

## 一次效果的结果续接

`Damage`、`Heal`、`RandomDamage` 新增可选 `on_result: str | None`。有续接时必须指定有效来源，行为 ID 在结算或随机抽样前验证；未知内容不能因空候选而静默跳过。批量伤害/治疗的每段可各自声明续接：

```python
def strike(ctx):
    return [Damage(ctx.target_id, 3, ctx.source_id,
                   DamageKind.SPELL, on_result="my.exact_bonus")]

def exact_bonus(ctx):
    if is_honorable_kill(ctx.event, ctx.source_id):
        return [GainArmor(ctx.player_id, 2)]
    return []
```

这解决法术来源离开手牌、自动施放等入口的一次效果后续，不把法术登记成常驻战场监听。续接捕获原来源和该段结果，整批结算及已有死亡/反应处理后按段序执行。吸血产生独立结果，但不复制原伤害的 `on_result`。终局停止尚未开始的续接。

续接可以请求选择，帧会保存捕获结果和上下文；恢复不重新伤害或抽样。动作失败恢复全部事务，选择失败恢复到该选择之前的已提交边界。手动回溯恢复奖励和目标状态，保留结果则累计已执行奖励；已经离场的旧目标不会在第二次保留结果中凭空再受伤。
