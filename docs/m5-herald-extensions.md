## 公共相邻光环

`AuraSpec(..., adjacent_only=True)` 声明印刷光环，`GrantAura(..., adjacent_only=True)` 授予动态光环。相邻限定与 `include_self=True` 冲突时拒绝。该字段进入能力实例、死亡记录、复制和快照。

- 相邻按共享场位列表中来源的左右各一位计算，不跳过地标、休眠随从或其他占位实体。
- 只有活动随从能获得属性；地标/休眠实体既不受益，也不让更远随从穿过它获得光环。
- 插入、死亡移除、回手、转控、休眠/唤醒、沉默和临时能力到期均通过统一光环重算更新。
- 保留原有同时重算和生命上限移除钳制规则，不把光环写成永久 Buff。
- 兆示士兵/附肢首次入场时按捕获等级放大其印刷光环，当前复制保留结果，回手/基础重建重新捕获；之后的兆示不会追溯强化旧光环。

**R-071：相邻位置与强化的精确窗口仍属原型契约。** 物理左右位置、休眠/地标阻隔、移除时点与动态授予能力是否参与特殊强化需要国服校准。当前仅士兵/附肢印刷光环参与兆示放大。

## 生成时原子安装费用

三个入口统一接受 `cost: CostSpec | None` 与 `expires_turn: int | None`：

```python
AddToHand(player_id, card_id, cost=CostSpec(delta=-2))
AddToDeck(player_id, card_id, position='random', cost=CostSpec(set_to=1))
GenerateFromPool(player_id, pool_id, query,
    cost=CostSpec(payment=PaymentType.HEALTH), expires_turn=current_turn)
```

生成到场上的效果不接受费用修正。到期必须附带费用规则，类型/期限严格校验；过期或类型不匹配直接报错。随机生成在抽样前验证全部合格候选的费用类型，不能靠抽中哪张牌来决定请求是否有效。未知候选仍按原池契约报错。

实体创建后、`card_created` / 入手或入库事件前，安装统一费用附魔；事件反应和玩家视图从第一次观察起就看到同一费用。费用不修改卡牌定义，后续仍与费用光环/玩家修正组合。满手烧毁的生成牌也经过相同安装流程；它不会变成成功获取记录。

永久减费保留到后续回合；临时支付随现有到期流程移除，留在牌库也会到期。当前复制保留独立附魔及期限，移入手牌不重新起算。生命支付先扣护甲、不算伤害；无替换时不能支付最后有效生命。奥妮克希亚的 [生命损失替换](m5-health-loss.md) 已接入公共资格和支付结算，生效时允许超出剩余生命的费用。

**R-072：生成费用与事件窗口待国服校准。** 候选先统一抽样、随后逐张入区；附魔在创建事件前安装，期限为触发时的当前回合。它们是可恢复、可测试的明确内部契约，不能作为官方时序认证。

随机生成要求显式 GenerationContext。缺失上下文时回滚整次动作，不从注册表自动凑池；满场导致未生成士兵时仍记兆示，但没有入场生成效果。无生成需求的萨满光环可以不配置生成池。
