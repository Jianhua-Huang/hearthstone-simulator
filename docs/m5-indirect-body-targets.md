# 间接战吼：独立来源与逐次目标接受

本文描述主工程 prototype-v145 / core-effects-v145 的公共子集。实际范围与验证在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护；构筑国服时序尚未校准。

## 注册与实际入口

```python
registry.register_body_target_profile(BodyTargetProfile(
    'my.indirect', origin='indirect_battlecry', selection='random',
    acceptance_window='indirect_invocation',
))
registry.register_indirect_battlecry_binding(IndirectBattlecryBinding(
    carrier_card_id='my.carrier', profile_id='my.indirect',
))
registry.register_body_target_binding(BodyTargetBinding(
    'my.declaration', 'battlecry', 'my.indirect',
    origins=('printed', 'granted'), carrier_kinds=(CardType.MINION,),
    carrier_card_ids=('my.carrier',),
))

# 卡牌行为返回效果；引用必须来自当前真实场上随从。
TriggerBattlecry(MinionReference.capture(subject), source_id=ctx.source_id,
    targeting='random', choices='player', profile_id='my.indirect')
```

声明卡与载体卡须先注册。每个实际战吼，包括无目标和印刷主体，均需各自完整的 `BodyTargetBinding`。来源绑定、规格、主体绑定进入注册表指纹。只登记 profile 不构成权限；付费手牌、整牌生成和间接历史分别具有自己的执行来源。

连接此入口的载体必须是当前场上活跃、存活的物理随从。`GrantBattlecry` 可依据完整间接绑定在场上存储异构主体，授权阶段不执行条件、报价或选择目标。连击没有借此取得间接执行权限；手牌/牌库的异构授予仍需要其已连接的付费入口。已有普通共享目标授予与未连接的旧 `TriggerBattlecry` 保持原契约。

## 两个接受窗口

触发效果实际运行时，冻结当前完整有序战吼向量及每条附件的物理身份、声明、印刷/授予来源和期限，同时记录原载体、控制者与真正的触发者。此阶段只查结构，不选择目标。当前没有战吼时仍保存并完成空根，不消费 RNG。

每个实际调用开始之前，分别捕获该声明自己的条件和完整目标域。连击条件读取该执行者当时已经提交的手牌出牌前缀；渴求读取本次最大法力水晶和该声明的门槛。流放、压轴和快枪为 false，因为该调用没有手牌位置、支付或入手时钟。`BodyPlayReference` / `IfBodyCondition` 读取这一次真实调用的冻结条件。

前一主体改变法力水晶或目标属性后，下一主体从新局面接受。已经接受的条件和目标不会被之后的启动监听、等待、死亡或转控改写。启动监听沿原战吼检查点运行，先于主体执行；等待时实际记录仍未开始主体。既有公共效果负责目标后续离场的处理，不另选替代目标。

本入口沿原间接战吼政策，每个接受的物理主体调用一次；不会消费或乘上手动战吼重复政策，也不执行连击主体。外层实际触发两次会形成两个独立根，分别接受自己的窗口。其他来源的次数政策继续由自己的模块决定。

## 目标、随机与玩家输入

`random` 使用同一引擎 RNG，对当前完整有序自动目标域抽一次；单候选也属于一次真实抽选，空池不抽选。必要目标空池记 `no_target`，不执行该主体；可用时/可选目标的空池按原目标模式处理。每次调用保存完整候选和 MT19937 前后状态，可局部重演此次抽样。

`explicit` 使用请求中的同一个指定目标，需要目标的主体独立检查自己的域。一个目标可以对第一条有效、对第二条无效；无效调用记录失败，不改变其他主体，也不消费 RNG。没有目标域或条件未激活的主体接受 None 并正常执行相应分支，不被其他主体的指定目标抑制。此接口没有新增玩家目标向量或对玩家暴露物理附件 ID。

声明式属性、关键词和动态种族规则与普通根共用。[显式玩家条件](m5-player-target-inputs.md)使用冻结的当前可见 DTO 和私有物理引用绑定；旧 visibility 声明、全知回调没有获得此原输入授权。回调看不到暗牌属性或原始 GameState。来源随后离开可见区域时，DTO 中相应字段可能不可用，不能假定来源一直在场。

## 生命周期、恢复与证明

公共复制为载体和附件分配新身份，下一次触发重新取得完整来源授权。基础复制、回手重置和沉默按原生命周期处理；到期发生在下一触发之前时不再捕获该授予。转控发生在触发之前时使用新控制者；触发之后保持已捕获执行者。

原向量冻结以后，消费、移除、沉默、变形或死亡不替换尚未执行的原主体，新授予也不延长已接受向量。嵌套触发有自己的根和实际记录，内层结束后外层继续。整次失败复用公共事务回滚，终局中断保留已实际开始的记录，不制造剩余激活。

紧凑 `IndirectBodySequence` 保存原载体 JSON、完整原向量及实际调用收据。完整 before-state 仅由等待队列中的调用证明保存，关闭记录不嵌入旧 GameState/事件/历史树。恢复重算原来源授权、调用条件和目标域，并检查完整继续队列、实际记录与 Finish 顺序；clone 与真实动作回放共用这些检查。

关闭记录可以校验原向量、声明、条件前缀、实际记录和抽样一致性，不能仅靠后续局面重建全部过去目标属性或资源；完整原窗口重算由尚未关闭的证明或可信动作回放提供。未签名存档不提供外部来源认证。所有原事实、物理映射和完整证明仅供可信宿主，玩家仍取得原公开观察与过滤事件。

## 仍开放的来源

新的间接绑定不能授权付费或整牌生成。持有间接授予的实体若进入付费路径，必须有其自己的完整付费目标 producer；整牌生成必须注册[自己的实际来源与原窗口](m5-generated-body-targets.md)，现已连接四种已声明物理来源及生成抉择子集；间接绑定自身不授予此权限。五个实际历史战吼入口现可注册[自己的历史来源与逐次接受](m5-historical-body-targets.md)，不借用当前物理授予。其他自动来源、抉择剩余混合/长期/下一次轴、完整U14生命周期组合与U65、正式池、H2和国服校准继续推进。

当前格式 schema140，拒绝 schema1～139；观察59、命令9、外层回放1保持。没有添加正式卡牌适配。
