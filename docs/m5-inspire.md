## 公共完成条件

`completed_manual_power(state, event)` 返回对应的不可变 `HeroPowerRecord`；无事件或其他类型事件返回 None。只有 `hero_power_used`、真实历史引用、manual、成功completed、未interrupted且无failure才有资格。函数核对事件的来源、目标、玩家、数值和动作边界；缺失/重复/非法引用或与历史矛盾的完成事件抛错。它用于可信引擎事件一致性检查，不是外部事件的真实性认证，也不是防重放接口。

`is_inspire(state, event, player_id)` 在上述条件上核对使用者归属，返回 bool。普通触发可在行为中调用，有限次触发可将其注册为 `condition_id`。两者读取冻结历史，不依赖 `context.power` 是否由入口注入。开始事件、间接完成、失败与非技能事件不匹配；不能根据当前技能卡名、所在主位、使用次数或费用推断。

```python
registry.register_trigger_condition(
    'my.inspire', lambda c: is_inspire(c.state, c.event, c.player_id))
# 普通激励：行为在内部检查 is_inspire，复用 TriggerSpec。
# 有限次扩展：LimitedTriggerSpec('hero_power_used', 'my.effect', 'my.inspire')。
```

技能在主体结束时只发布一次完成事件。空主体也可成功完成；手动技能免费或以生命支付不改变资格。替换或移除本次技能后，历史仍指向原使用实体。主位和额外技能按每次手动激活独立触发；间接执行、无目标/被动失败不伪造玩家使用。选择恢复可发生在后续外部动作，完成事件 action 不必等于启动记录 action。

## 捕获、生命周期与组合

| 情形 | 当前内部契约 |
| --- | --- |
| 完成之前召唤/获得/变形获得激励 | 完成事件发布时在位即可成为监听者 |
| 完成之前沉默/死亡/离场 | 已失去监听能力，不成为候选 |
| 完成之前转控 | 使用发布时控制者判断归属 |
| 完成事件的早先反应授予新能力 | 本次候选已捕获，新能力等待下一次使用 |
| 普通反应捕获后被沉默/转控 | 保留冻结行为及原控制者；效果执行时仍检查实际目标 |
| 有限次实例捕获后、消费前被沉默/转控/重装 | 沿用能力ID、入场顺序与控制者护栏，旧候选取消，不误消费新实例 |
| 有限次消费后暂停选择 | 次数已扣，恢复继续既有行为，不重新消费 |
| 当前复制／基础复制／回手再打 | 沿用公共能力生命周期，当前复制保留有限次消耗，基础复制与再入场安装新印刷实例 |
| 休眠／建造中来源 | 沿用公共活跃能力限制，不因激励新增另一条监听通道 |
| 刷新、同回合多次使用 | 每条真正完成的手动激活独立触发 |
| 回溯重试 | 回滚整个尝试的激励效果和次数，再结算重试；提交后仍只有一条手动激活记录 |
| 保留多结果 | 主体多次执行全部结束后一次完成；嵌套间接技能有自身记录，但不增加外层激励次数 |
| 技能主体导致终局 | 未完成记录标中断，无激励完成事件 |
| 激励反应导致终局 | 技能已完成，保留完成记录；其余待处理反应按终局规则停止 |

普通与有限次触发的消费/重检政策来自既有公共队列，不为激励新增私有队列或次数。以上精确窗口统一登记 **R-111**，不能将内部一致性当成国服事实。
