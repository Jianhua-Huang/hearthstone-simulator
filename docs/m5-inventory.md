# M5：机制依赖盘点

本页与 [长期计划](roadmap.md) 和 [项目状态](project-status.md) 配套，防止以重复接卡替代机制闭环。它是可继续完善的初始盘点，**不是标准/狂野完整机制清单或正式合法池**。

## 可复现产物

- [依赖计划](../data/support/m5-mechanism-plan.json)：29 组机制族、已存在的公共模块、前置依赖、当前范围和下一项工作。
- [本地数据调查结果](../data/support/m5-inventory.json)：固定源文件与计划哈希，按标签匹配的记录数量、最多五条示例及其原始记录哈希，另保留未归类的命名标签。
- [调查工具](../tools/inventory_mechanisms.py)：检查依赖缺失/循环和标签重复归类，拒绝错误源哈希或完整支持声明；不安装卡牌行为、不改变运行时支持状态。

```powershell
python tools/inventory_mechanisms.py --source data/extracted/cards.json --plan data/support/m5-mechanism-plan.json --out data/support/m5-inventory.json
```

本次固定源含 36,022 条记录，其中 8,170 条带 collectible 标记。它们包含不同玩法、英雄外观、同牌别名及预加载内容，**8,170 不是合法卡组牌数**。报告保留 124 个尚未分配到这些机制族的命名标签，其中含元数据、视觉标签和待审规则；不能把每个标签都视为一个缺失机制。无关键词的文本效果与可达衍生物也必须另审。标准/狂野适用性统一保持 unverified，正式分母仍为 null。

## 每批更新规则

1. 从固定来源定位真实样本和当前版本的行为证据，确认模式范围或继续保留待核实。
2. 明确缺的是公共状态、效果原语、调度阶段、候选池，还是单卡例外；补依赖，避免依靠卡牌 ID 在内核分支。
3. 实现公共机制与交互用例，仅补必要代表卡，更新实际验证状态；没有测试或仅有标签匹配不得标记支持。
4. 若修改计划，重新生成调查结果以更新 plan_sha256；若更换数据，建立对应目标版本，不能静默覆盖锁定来源。
5. 持续审查未归类标签与非关键词文本，完成正式合法根卡及可达内容盘点后，才可能验收 M5 整体依赖闭环。当前 `inventory_complete=false` 不因本批验收改变。
