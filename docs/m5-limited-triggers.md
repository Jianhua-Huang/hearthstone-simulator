## 共用能力实例

`LimitedTriggerSpec(event, behavior_id, condition_id="always", uses=1, keyword=None)` 描述有限次被动触发。`spellburst(behavior_id)` 和 `frenzy(behavior_id)` 是具有固定事件、一次使用及关键词的便捷构造器。它们与 [泰坦主动能力](m4-minion-abilities.md) 分属不同操作，但复用实体附件身份和生命周期。

每份能力有独立 attachment ID、声明、剩余次数和 consumed 标记。重复授予产生独立实例；通用声明允许多次使用，法术迸发/暴怒必须一次。能力不会以卡牌 ID 全局计数，也不会在卡牌回调的闭包里保存进度。裸关键词不足以表达行为，注册和 GrantKeyword 都会拒绝此用法。

注册条件通过 `Registry.register_trigger_condition` 提供，接收与主状态分离的 `RuleContext`，必须返回真正的 bool。条件在捕获时判断，失败不消耗。待处理检查冻结来源实体、能力 ID、控制者和入场顺序；执行时再检查来源仍有效、身份未替换、能力仍可用，然后先减次数再调用行为。因此同批多个候选不会重复消费一次能力，递归伤害也不能重用刚耗尽的暴怒。

行为可读取 `context.trigger` 中已消费的不可变实例。消费之后发布 `limited_trigger_used`，已捕获的行为通过冻结上下文继续结算；此后来源离场不自动撤销行为，但普通效果仍检查实际目标是否有效。消费前被更早的反应移除的来源则不触发。这样的消费/反应相对顺序是 **R-056** 原型契约，仍待国服校准。

## 法术迸发资格

[暴雪通灵学园上线公告](https://news.blizzard.com/en-us/article/23486106/scholomance-academy-is-now-live) 说明法术迸发是场上随从或武器在施法后生效的一次性能力，未给出全部嵌套反应窗口。

当前实现采用下列明确步骤：

1. 手动打出法术，在支付完成、打开法术窗口时记录己方当前有效且未消费的法术迸发实例。
2. 处理提交反应、奥秘反制/目标替换和法术本体。选择暂停时，候选和原出牌记录进入快照。
3. 法术完成并发布 `card_played` 后，只检查原候选中仍有效的实例。法术中途召出、变形获得、重新装备或动态授予的新实例等待后续法术。
4. 被反制的法术也进入完成事件，保留法术迸发资格。历史依据是 [9.2 官方反制说明](https://hearthstone.blizzard.com/en-gb/news/21098848)，不能据此宣称当今国服所有反制交互均已验证。

对手施法、普通随从出牌、技能、交易、锻造不会消费法术迸发。武器能力由武器自身执行，关键词不会转移给英雄。终局中断未完成法术时不会伪造完成触发。自动、重复、复制和抽到时施放已接入共享施放入口；来源资格与窗口按[施放契约](m5-spell-casts.md)及[抽取链契约](m5-draw-casts.md)维护，不能假冒普通手牌打出。

## 暴怒资格

[暴雪贫瘠之地上线公告](https://news.blizzard.com/en-gb/article/23652237/forged-in-the-barrens-is-now-live) 说明暴怒在随从首次受到伤害并存活后触发。当前只接受自身的正数 `damage_dealt` 结果，并要求活跃场上随从生命大于零且未标记消灭。

零伤害、圣盾、免疫等防止结果没有资格；致命伤害和剧毒导致的消灭也不会触发。现有伤害批次先应用各伤害包，再发布结果，因此同一批前一包非致命、后一包致命不会触发；多个非致命结果只消费一次。普通战斗、己方或对手回合均可触发。治疗不会恢复次数。暴怒造成的伤害继续走公共伤害管线，受到来源剧毒/吸血等规则约束，不按法术伤害放大。

批内存活、先前反应移除来源、死亡检查及不同暴怒之间的精确相对顺序登记为 **R-057**，需要 M6 用国服场景校准。

## 生命周期、恢复与信息

| 操作 | 当前公共契约 |
| --- | --- |
| 复制当前随从 | 分配新实体和能力 ID，保留剩余次数与 consumed |
| 复制基础定义、变形 | 按目标定义安装新能力，恢复印刷次数；不继承原法术候选 |
| 回手再打、复生 | 按既有重置规则安装新印刷能力；复生是新实体 |
| 沉默 | 移除可沉默能力；已移除实例的未消费候选失效 |
| 转控或离场再返回 | 入场顺序/控制者护栏阻止旧候选误用 |
| 动态授予 | `GrantLimitedTrigger` 分配新实例，可指定来源和回合到期 |
| 休眠、建造中的星舰 | 非活跃来源不捕获或执行这些场上触发 |
| 快照/克隆/回放 | 保存能力次数、窗口/完成步骤候选及捕获上下文；恢复检查类型、引用和消费一致性 |

多余、缺失、非法类型、负次数、超出上限、次数与 consumed 矛盾、重复候选和越界来源等均拒绝恢复，不用默认字段补齐旧格式。事务异常回滚费用、手牌、历史、能力消耗和可见日志。

玩家观察中的 `limited_triggers` 只显示关键词及剩余次数，保留用尽的公开实例；不显示能力 ID、条件/行为名称或施法候选。对手未揭示手牌不会显示这些字段。全知快照仍仅供宿主。

## K468 法术迸发反制资格修正

上文第4项“被反制仍保留迸发资格”及原测试保留为历史审计记录，当前实现不再采用该政策。[2017通用反制公告](https://hearthstone.blizzard.com/en-gb/news/21098848)早于法术迸发，不能单独证明较晚关键词的完整资格；后续[2020讨论观察](https://us.forums.blizzard.com/en/hearthstone/t/consistency-with-casting-spells/39311)和[2025报告/回复](https://us.forums.blizzard.com/en/hearthstone/t/counterspell-not-working-properly-with-escape-the-underfel/151142)明确区分反制后的计数与迸发。这些是玩家观察，不能标作官方当前国服裁定。

当前内部修正：仍在原手动法术提交窗捕获候选，沿原支付、反制窗口、完成事件和不可变PlayRecord执行；有限触发capture在play.countered时不制作迸发检查，延迟check也复核原记录，防止已排队旧请求消费该用途。原手动反制历史与费用保留，后来的成功手动法术可正常消费。自动/effect来源仍不伪造手动候选，未扩大来源政策；普通keyword=None有限触发、暴怒、其他施法消费者和已接受迸发主体生命周期不自动套用此条件。

完整真实反制后的未消费用途、下一次成功消费、等待恢复/clone/回放及新GDB_116消费者均在当前机制版本验证。core692/schema551拒绝旧1～550，当前国服37.0资格和精确窗口仍须M6独立复核；不能据本次修正认证全部反制或全部“施放”文案。
