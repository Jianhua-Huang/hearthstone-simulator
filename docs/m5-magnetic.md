# M5-05：磁力合体与附件归属

本批为 `prototype-v75` / `core-effects-v75`、snapshot schema 74、`representative-m5-v38`、`player-view-v44` 与玩家命令 v6。建立从手牌打出时的磁力分支，并接入八张真实代表。仍是通用原型的内部验收，不代表所有磁力牌、特殊效果来源或国服精确时序均已支持。

## 位置就是选择

沿用 `PlayCard.position`：它表示插入位置，当前位置右邻是己方存活、活跃、种族匹配的随从时，磁力牌合体；其他位置独立登场。省略位置相当于最右侧独立打出。普通机械也可以作为宿主，无需自己带磁力。

| 场景 | 当前行为 |
| --- | --- |
| 放到己方机械左侧 | 合体，宿主 ID、位置及控制者保持 |
| 放到末尾、非匹配随从或地标左侧 | 正常打出，占用一个空位 |
| 七个场位已满 | 仅合法合体位置可打出，不产生第八个场上实体 |
| 休眠、建造中、濒死或敌方实体 | 不可作为磁力宿主 |
| 卡面允许其他种族 | 使用来源的 `magnetic_tribes`，不是全局放宽机械规则 |
| 宿主为全部种族 | 与当前磁力种族声明匹配 |

磁力放在左侧合体、其他位置独立登场，依据[官方磁力介绍](https://news.blizzard.com/en-us/article/21953431/hearthside-chat-with-stephen-chang-magnetic)。满场可合体依据[26.2 官方更新](https://news.blizzard.com/en-us/article/23935322/26-2-patch-notes)。两篇来源支持这两项基础规则，不证明本页全部边界。

玩家动作列表为磁力牌新增可选 `magnetic_target` 句柄，说明该位置对应哪位宿主。该字段只是位置的派生提示和一致性断言；提交错误句柄会拒绝，省略它仍可按位置出牌。它只指位置宿主。原宿主意图与普通入场后备目标按既有独立目标声明处理。已撤除的“抉择＋磁力”仅保留[历史撤除说明](m5-magnetic-choose-roots.md)，该历史页不是现行开发或扩展入口。枚举、验证和执行共用同一宿主判定。

## 宿主、材料与不可变历史

合体保留宿主实体，冻结材料当前攻击力和当前生命值，生成一个数值附魔及若干授予能力。材料移到墓地区域作为已消耗的手牌保存，不独立入场，不建立死亡记录，不增加尸体。合体仍是一次手牌出牌，正常支付费用，写入出牌历史，参与连击和已有出牌进度。

`GameState.magnetic_history` 保存不可变 `MagneticRecord`：合体 ID、原出牌记录 ID、材料/宿主实体 ID、当时控制者、材料/宿主卡面、数值贡献及首次分配的附件 ID。`PlayRecord` 新增 `position` 与 `magnetic_target_id`。以后宿主变形、复制或易主，不改写合体时的历史。

每个当前附件带 `magnetic_id` 关联这次合体。材料费用不加给宿主，宿主原伤害、攻击次数、入场回合和冻结状态保持。已有场上光环继续按宿主重新计算，不重复计入材料贡献。

合体逻辑位于 [magnetic.py](../hs_sim/engine/magnetic.py)，使用既有费用、附魔、能力实例、移区、光环和结算队列。代表卡只声明种族和组合公共效果；内核不按真实卡 ID 特判。

## 能力继承与生命周期

持续关键词、亡语、普通触发、光环、有限次触发及已有主动能力可作为新的授予实例接到宿主，分配独立附件 ID，保留原消费/次数/到期信息。行为上下文的来源是宿主，来源追踪则保留材料实体。例如飞弹机器人的伤害能使用宿主的剧毒或吸血，蜘蛛炸弹的亡语按宿主当前控制者执行。

入场专用能力和关键词不作为持续能力复制：`on_play`、地标使用/星舰发射/唤醒回调、休眠触发、手牌进度，以及磁力、连击、流放、压轴、法力渴求、快枪手、腐蚀和注能标记。合体分支暂不执行材料战吼；只有独立打出才执行其 `on_play`。有同名主动能力键冲突时明确报错并回滚，不能覆盖宿主能力。

| 生命周期操作 | 当前附件处理 |
| --- | --- |
| 再次合体 | 新增独立组；数值叠加，多个亡语各自执行 |
| 多个圣盾 | 保留能力实例，但一次破盾消费当前全部圣盾，不提供多层护盾 |
| 沉默 | 清除全部可沉默磁力属性和能力 |
| 移除某个磁力数值附魔 | 同时移除该实体上同组能力；不影响其他组或复制品 |
| 当前状态复制 | 新实体、新附件 ID，保留贡献与合体来源关联 |
| 基础复制、回手、变形 | 按既有生命周期重建基础，不保留磁力附件 |
| 复生 | 以宿主原卡重建一血实体，不把材料当独立复生对象 |
| 控制权转移 | 保留附件，未来行为使用当前控制者 |

材料的数值附件会折算进一次永久贡献，临时数值增益当前也如此；授予能力自身的到期信息则保留。这是待校准的明确契约，不能据此宣称已复刻全部临时增益、设值和特殊磁力例外。

## 原磁力材料与返还

TTN_906修理机器人X-21的亡语使用有限的`ReturnMagnetizedMechs`。普通磁力接受成功时，`MagneticRecord.source_material`保存被消耗物理卡的完整`CapturedCardCopyMaterial`：原分配身份、局部基础/附件、固有组成与接受边界；不只保存card_id或加到宿主的数值。原磁力仍不是死亡，被消耗的源先沿原区域流程进入墓地，再捕获材料，不能凭这条历史获得死亡/复活资格。历史校验绑定原出牌、原物理源、控制者、种类和时钟，拒绝空材料、借用别的源、未来附件/组。

自然亡语读取完整冻结DeathRecord的附件组；主动亡语读取该次主体接受的完整载体材料，排队后宿主失去附件不裁掉已接受组。额外触发轮次沿旧亡语规则重新读取新局面，宿主可能已变形；原物理载体和原受益者仍保持。每组按磁力历史顺序出现一次，同名的多个物理材料不合并，Mech资格按原材料的种族状态查询。当前复制的宿主可继承原组；基础复制、沉默、回手重置和变形沿既有附件生命周期。

全部选定原材料在第一次交付前冻结，逐一委托原`CopyCard(mode='base')`。普通临时增益按已有入手重置政策清除，固有配方/组成和原复制来源由共享复制器保留；容量溢出、入手通知、等待、回滚与玩家投影也由原管线负责。不能把交付替换成按card_id创建白板，不能从当前墓地实体重新拼材料。磁力历史增加此私有字段，快照schema572拒绝旧1～571；没有新GameState、Entity或Player字段，原玩家磁力列表仍只公开卡牌身份。

上述是本地内部政策；国服37.0精确重置、种族依据、顺序和接受窗口仍需M6校准，特殊组成的完整可达域仍需M7核查。DEEP_012影石潜伏者在这份数据中仅保留原始证据，不是可执行定义。其历史修复明确区分首次亡语的倍增和后来的独立触发，见[官方已知问题](https://us.forums.blizzard.com/en/hearthstone/t/284-known-issues/119362)及[28.4.1补丁说明](https://hearthstone.blizzard.com/en-us/news/24046220/28-4-1-patch-notes)；这两份历史材料不认证国服37.0。现有穆拉丁资料的每次返还手牌复制政策不能直接充当取走当前武器、首次归还消费和重新装备。
