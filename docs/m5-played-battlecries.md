# M5-13d-03b 出牌战吼声明与历史政策

本批为prototype-v81/core-effects-v81、snapshot80、representative-m5-v43；56项专项、4140项全量及64示例通过，实际结果以[项目状态](project-status.md)为准。只新增DED_509艳丽的金刚鹦鹉作为代表，279条真实记录/280定义，14条choice-only；不声明标准/狂野完整合法池或正式卡牌完全支持。

## 两类历史分别保存事实

`PlayRecord.battlecries`在付款和区域迁移前捕获当前有效战吼附件的不可变tuple；每项保存能力附件ID、行为ID及声明卡ID。它和卡面、手牌位置、费用等出牌事实一起保存，不另造第二套出牌历史。

`BattlecryRecord`继续保存实际执行。铜须/有限次政策/保留回溯可增加实际激活次数，但不会增加原出牌或重写已捕获声明。整牌反制、满场导致入场失败、磁力融合等已提交但未激活的情况，仍可保留出牌声明；具体卡牌是否将它们视为候选，由明示政策和后续校准决定。

来源后来死亡、转控、变形、沉默、回手或重新打出，都不能修改过去声明。再次出牌产生新的play_id和附件捕获。组合星舰保留各组件战吼的声明来源与附件顺序，不能退回组合卡基础牌面的单一战吼。

## 查询与执行契约

| 公共接口 | 行为 |
| --- | --- |
| `PlayedBattlecryQuery` | 玩家、回合、严格小于的play_id、排除ID、主体类型、countered策略 |
| `played_battlecry_candidates` | 按历史顺序返回已完成、含声明的PlayRecord；每次出牌最多一个候选 |
| `RepeatPlayedBattlecry` | 执行指定完成出牌捕获的全部战吼主体，每个主体一次 |
| `RepeatPlayedBattlecries` | 第一/最后/全部候选，历史或随机顺序；入口一次冻结选中play_id序列 |
| `battlecry_play_window` | 根据当前战吼来源取得原执行的排他性历史上界，供选择政策显式使用 |

countered可取exclude/include/only，默认exclude。include仅表示允许已被反制但完成提交的记录参与，不伪造它当时执行过战吼。未完成或中断的出牌不可作为本接口的重演依据。普通召唤不构成出牌，普通on_play、连击、抉择等也不会仅凭事件或关键字被当成战吼主体。

重演记录使用`origin='played_history'`及`history_play_id`，与实际激活历史的history_id互斥；自身play_id/batch_id/outcome_id仍为空。每个执行的payload必须属于该原出牌的捕获列表，原出牌归属必须与本次执行玩家一致。当前载体、历史原卡和能力声明分离，沿用[间接战吼契约](m5-battlecry-sources.md)的目标/选择、触发、死亡、父子记录、回溯、回滚和信息隔离。

重演不会重新支付原费用、创建原卡实体、安装原卡其他能力或再消费铜须/玩家次数政策。`ctx.play`不借用旧出牌；规则通过`ctx.battlecry.history_play_id`显式访问原依据，不能把过去手牌状态冒充当前执行条件。

## 金刚鹦鹉的实验政策与R-121

适配器只组合公共查询和重演，不直接调用别的卡牌回调。当前实验政策是：

1. 选择当前玩家、已完成且拥有捕获战吼声明的最后一次出牌，**include被反制的记录**。
2. 当前手牌战吼以其play_id为严格上界，铜须的第二遍也用同一个上界，不把第一遍新产生的实际激活当作另一张打出的牌。
3. 借用出牌的主体继续使用该原出牌的严格上界。连续鹦鹉因此沿更早的出牌窗口重演；没有更早候选时为空效果。一个组合出牌中的多个能力保持捕获顺序，每项一次。
4. 物理间接激活没有新的手牌出牌，窗口为它开始时已经提交的出牌范围。它可以先选到该载体早先的出牌，然后沿更早窗口执行；实际激活历史的重演会追溯其原依据。
5. 目标和选择重新随机，使用当前场面及共用RNG；不会重放原来的目标、随机数或发现选择。

**这些是明确登记的原型假设，不是已获国服认证的精确行为。** 本地[中英卡面来源](../outputs/m5-13d-03b-macaw-source.json)确认“上一个使用的战吼”，不足以证明反制、磁力/满场、嵌套窗口、物理再激活、组合卡取样和选择政策。官方[36.0修复](https://hearthstone.blizzard.com/en-gb/news/24287396)与[23.6修复](https://hearthstone.blizzard.com/en-gb/news/23817873)支持不错误复制原卡亡语的方向，仍不能证明上述细节。R-121在M6校准，查到不同规则时调整政策，不能用内部测试证明自己假定的规则就是官方规则。

特殊手牌/付款条件、动态附加主体、条件性重复限制和复杂重演器之间的循环规则仍需相应机制，不因鹦鹉可执行而关闭。工程预算仅防止无界结算，报错回滚，不冒充官方重复上限或游戏结果。
