# 13d-03b 前置检查：使用记录与实际激活

本页保留v80前置检查。v81已接入捕获声明、显式历史政策及金刚鹦鹉实验代表，见[当前契约](m5-played-battlecries.md)；R-121未国服校准。原检查如下。源码位置为`play_history.py`的prepare_play、`model.py`的PlayRecord及BattlecryRecord，以及`battlecry_sources.py`；真实候选仍取[已冻结来源](../outputs/m5-13d-03-source-candidates.json)。

当前PlayRecord记录提交时卡面、费用、手牌位置、派生卡声明及反制结果，没有捕获完整战吼主体列表。BattlecryRecord在实际激活时建立，铜须可产生多条，同一出牌的保留回溯也可产生多条；被整牌反制时一条也没有。v80的play_payload查询只能去重已有成功激活，不能代表所有提交过的战吼卡。

DED_509文案为重复上一个使用的战吼。实现前需要分别确认或明确登记以下暂定政策：

| 情形 | 必须决定的依据与回归 |
| --- | --- |
| 普通上一战吼 | 用捕获能力执行，不读取原实体后来的变形或控制者 |
| 铜须令当前鹦鹉执行两遍 | 排除当前整次出牌，不能让第一遍新记录变成第二遍的“上一个” |
| 上一个也是鹦鹉 | 当前载体、借用声明和原历史窗口分别保留；嵌套不能查询到正在执行的自身 |
| 物理间接激活一个鹦鹉 | 没有新的手牌出牌；须明确载体过去出牌是否排除，不能凭当前ctx.play猜测 |
| 上一个战吼牌被反制 | 官方/集中校准依据不足；若政策包含该牌，需要提交时的捕获声明，不能从后来的实体重建 |
| 一个组合实体有多个战吼 | 明确按整个出牌、单能力还是实际激活取样；不得用普通印刷卡面替代组合声明 |
| 条件战吼和特殊手牌信息 | 间接执行没有ctx.play，不能伪造旧付款/手牌位置；需明确当前条件与冻结条件来源 |
| 发现或定向目标 | 在当前场面重新求值；自动选择政策及无目标结果仍需R-120校准 |

若确需提交历史，优先扩展现有不可变PlayRecord的类型化捕获字段，不另建第二份可变牌局历史。若只需成功激活，则继续复用v80查询。选择由真实来源和明确规则要求决定，不为了凑一个代表提前新增未被证明需要的层。

验收必须有“上一战吼→鹦鹉→再一只鹦鹉”、铜须双遍、被反制、当前载体变形/离场、物理间接入口、组合主体与回溯场景，含暂停恢复、玩家命令及完整回放。先接DED_509一个代表；SW_115第一战吼监听和GIL_820本局集合/随机顺序在其自身历史政策明确后再接。M6国服校准、正式卡池和02系列其他缺口不因此关闭。
