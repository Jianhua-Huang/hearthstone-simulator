# M5-12c-03d：支付能力候选、分组选择与临时交付

当前为 `prototype-v75` / `core-effects-v75`，snapshot schema 74、`representative-m5-v38`。旧 1～71 快照拒绝；观察 v42、命令 v6、外层 replay 1 保持。[60 项专项](../tests/test_m5_pool_offers.py)已内部通过，完整回归结果见 [项目状态](project-status.md)。本批扩展既有费用、生成/选择和临时手牌机制，不新增重复的机制类别。

## 明确“可用”的判定范围

[国服 32.2.4 公告](https://hs.blizzard.cn/news/24204920/)将月亮的祝福改为生成“可用”的牧师随从或法术，但没有完整定义该词。历史[玩家直接报告](https://us.forums.blizzard.com/en/hearthstone/t/blessing-of-the-moon-bugged/146412)描述技能曾在没有敌方随从时给出需要敌方随从目标的法术；这是玩家观察，不能当作官方规则确认。

因此将公共接口的策略明确命名为 **affordable（支付得起）**，不等同于完整出牌合法性。它共用真实费用报价与支付账户检查；不检查场位、目标、重复奥秘或出牌前置条件。候选可以支付，但仍可能没有合法的 `PlayCard`。月亮的祝福暂用该策略；若国服校准证明有更多条件，应扩展明确策略，不能无声改变普通生成池。

## 不创建实体的公共费用报价

`quote_generated_cost(state, registry, player_id, card_id, cost=None, minimum_cost=0)` 计算候选被生成后的手牌报价。已有 `quote_cost` 和该入口共用 `_quote_card`：本地基础费用/生成附件 → 按既有顺序处理当前光环和玩家修正 → 临时牌最终费用下限。`cost` 支持设值、加减、下限和替代支付；类型/卡 ID 条件必须匹配候选。

返回的 `CostQuote.entity_id` 为 `None`，不能作为某个实体的支付凭据。查询不创建实体，不消耗 ID、随机数、法力、有限次修正或手牌获取历史，也不运行卡牌效果。付款资格仍由 `payment_error` 判断，因此法力、生命/护甲、护甲、尸体和已有生命支付替换共用同一规则。来源技能已经支付的费用、已经消费的修正会影响查询时可用资源。

该接口只承诺已有费用系统可表达的规则。未实现的特殊费用公式仍归 M5；不能仅凭计算基础费用就声称完整模拟所有巨人等动态卡牌。

## 各组独立抽样，再选择一个结果

```python
ChooseFromPools(
    player_id,
    groups=(PoolOfferGroup(pool_id, minion_query, count=1),
            PoolOfferGroup(pool_id, spell_query, count=1)),
    source_id=source_id,
    cost=CostSpec(delta=-discount),
    temporary_until=current_turn,
    affordable=True,
)
```

`PoolOfferGroup` 指定版本池、普通 `PoolQuery` 和本组抽样数量。`ChooseFromPools` 先解析和验证全部组、全部合格定义及费用修正，再过滤支付能力，最后抽样；未知池、缺适配或不支持的物理类型不会被高费用或满手掩盖。沿用生成身份去重、成员权重和特殊内容资格，不从已适配列表倒推候选池。

每组无放回抽样，顺序按声明的组保留；不同组相互独立，重叠候选可以在不同选项中出现，不自动做跨组去重。空组省略，不从别组补足；全部为空时不创建选择、不抽随机数，后续效果继续。满手仍可选择，交付按普通容量烧牌。申明的最大选项数超过规则预算时，在抽样前拒绝。

选择前保存不可变 `PoolOfferReceipt`：分组声明、当时合格 ID、抽样结果、可见费用预览、当前职业/来源卡面和捕获回合。尚未执行的接口在恢复后才读取资源；已捕获的选项不因后续反应变更法力、职业、灌注或光环而重新抽样。选择后不再次要求支付得起，实际打出仍使用当时的正常权威报价。

恢复校验候选是否属于已声明版本池、组顺序/容量、生成身份、卡面预览、来源/回合以及选项和分支的一致性。捕获的支付筛选结果是保存状态的一部分；不拿选择之后的局面重新计算过去的候选，也不把可重写的快照摘要当作历史真实性证明。

选项使用现有私有 `EFFECT` 选择与 `CardPreview`；拥有者看到减费后的捕获价格，对手看不到候选和费用。预览不保证之后报价不变。自动施法和间接技能沿用已有随机/玩家选择策略，不另建不可恢复的交互栈。

## 原子创建带费用的临时牌

`CreateTemporaryCard` 新增可选 `cost` 与 `cost_expires_turn`。创建实体时先装入普通费用附件和 `HandLifetime`，再发出创建/入手事件；反应不会看到只有临时期限尚未减费的中间状态。卡牌期限 `expires_turn` 与费用附件期限 `cost_expires_turn` 是两个不同概念，可以独立声明。

分组选择的 `temporary_until` 非空时使用该入口；否则交给已有 `AddToHand`。选中前不会创建候选实体或获取记录；选中后只创建一张新实体。临时牌当前复制、转移、洗入、打出、回手及到期继续遵守 [临时手牌契约](m5-echo.md)。例如临时随从打出后不会因到期而死亡；洗入牌库后到期清除期限但不销毁实体，永久费用附件继续存在；普通回手重置费用与期限。

失败动作回滚所有结果；失败选择只回滚本次选择提交并保留待选局面。回溯恢复已生成卡牌、费用、使用次数和来源历史，再重新执行选择，不累积第一轮结果。选择反应造成终局时停止后续交付。
