## 统一激活入口

`UseHeroPower` 和 `TriggerHeroPower(player_id, source_id, target_id, targeting, choices)` 共用 [技能模块](../hs_sim/engine/hero_powers.py) 的激活与完成过程。后一效果解析执行时的当前技能，不在卡牌回调里直接调用另一个行为、不假造手牌出牌或法术施放。

| 行为 | 手动使用 | 卡牌效果间接触发 |
| --- | --- | --- |
| 来源 | `manual` | `effect`，可记录激活者实体 |
| 费用 | 捕获报价，通过公共支付路径支付并消费有限次费用修正 | 无支付，不消费下一次技能减费 |
| 次数 | 消耗当前技能和玩家的本回合使用次数 | 不消费、不刷新这些次数；已有次数上限保留 |
| 使用条件 | 检查行动玩家、当前位置、次数、费用、场位、使用谓词和目标 | 执行当前技能内容，略过手动按钮的使用条件；效果自身仍按公共召唤/伤害等规则执行 |
| 目标与选择 | 现有玩家合法动作和选择 | 显式目标或固定种子的随机目标；选择策略为随机或交还玩家 |
| 事件 | `hero_power_started` / `hero_power_used` | `hero_power_trigger_started` / `hero_power_triggered`；无有效目标有失败事件 |

不把间接触发写成手动使用，以便后续激励、次数条件与其他技能反应明确选择来源。上述来源区分与精确交互属于 **R-101 暂定契约**，尚未通过国服实测；现有传统手动技能行为保持。

## 独立历史与上下文

`HeroPowerRecord` 保存技能实体和卡牌身份、执行玩家、回合与动作、来源、激活者、目标、选择策略、已接受的付费类型/金额、激活前技能/玩家使用次数、完成/失败/中断状态。嵌套激活记录 enclosing `parent_id`，不复用手牌 `PlayRecord` 或 `SpellCastRecord`。

`activated_powers` 是宿主和可信规则使用的查询，按玩家、来源、回合、成功与历史上界筛选。默认包括失败和未完成记录；成功要求已完成且无失败。`RuleContext.power` 提供捕获的当前激活，相关开始/完成事件反应也可读取它。卡牌行为仍收到分离的不可变捕获上下文，不获得直接修改内核的权限。

手动支付和历史在同一动作事务内；异常恢复费用、次数、随机数、历史与其他状态。付费类型可为现有法力、生命等替代资源。间接触发可在零法力、技能已使用或另一玩家回合内执行；缺失技能和不存在的激活者明确报错，不伪造空技能或无来源记录。

## 目标、选择与反应窗口

本批把自动施法原有的目标选择及分离玩家观察上下文移入公共 [目标模块](../hs_sim/engine/targeting.py)，自动施法和技能触发共享它；选择采样也共用 [选择模块](../hs_sim/engine/choices.py)。随机目标仍使用角色/区域/关系和目标谓词，采用既有自动来源对潜行、魔免等手动目标保护的政策。显式目标非法、必选无目标分别记录 `invalid_target` / `no_target`，跳过技能内容后继续外围效果；无效外部实体 ID 不写入历史。

技能自己的选择可按随机策略立即结算；独立随从反应、对手拥有的选择不继承该策略。嵌套法术仍用自己的施法选择策略。选择选项与后续工作都经过现有严格类型编解码检查，不能因随机采样未选中坏选项而隐藏缺失实现。

在开始事件之后、反应执行之前捕获技能内容，延续原手动激活行为。反应替换技能位置不会把已捕获内容改成新技能；来源随从离场也不取消已接受的激活。多个嵌套激活各有完成标记，按内层到外层恢复。致死沿用立即终局政策，将未完成记录标记中断并清理队列；未完成技能不发出成功事件。

## 保存恢复与玩家信息

新增历史、捕获上下文和完成标记进入快照、克隆与动作回放。加载检查字段/枚举、技能实体、历史顺序、父级身份以及未完成记录与恢复队列的一致性。选择提交失败只回滚该次选择，已提交的外层激活保留。

手牌回溯可恢复间接技能记录；技能自身的检查点和保留结果也已接入，按 `HeroPowerRecord` 关联独立激活。见 [技能回溯契约](m5-power-rewind.md)。

玩家日志公开区分使用、触发与触发失败；全知历史、激活者内部 ID、嵌套关系、费用诊断和自动选择的内部选项日志不直接暴露。观察和动作协议继续按当前玩家权限提供信息；不会把宿主历史作为玩家状态直接返回。

## 代表卡与证据

冻结来源 [EDR_519 小精灵驾驭者](../data/support/power-activation-source.json) 为 5 费 4/4，战吼先灌注再触发英雄技能，行为仅组合 `Imbue` 与 `TriggerHeroPower`。使用当前职业映射：法师、德鲁伊、潜行者、死亡骑士、猎人、萨满、圣骑士和牧师代表可执行，无灌注技能职业仍可触发未被替换的技能；八个声明技能均有实验适配，未知内容仍明确报错。

[国服 32.0.2 修正](https://hs.blizzard.cn/news/143615/)提到小精灵驾驭者在萨满职业下的触发修复，证明这类跨职业间接激活需要处理，但没有给出全部费用、次数或时序细节。萨满技能已在后续增量中实验适配；该历史公告不代表本实现已经经过官方校准。

`python -m examples.hero_power_sources`：通过玩家接口打出驾驭者，灌注并触发法师技能，保存后再手动使用一次；最终花费 7 点法力、手动次数为 1、造成 2 点技能伤害。2 动作、19 事件，保存恢复/完整回放/CLI 校验一致，见 [示例](../examples/hero_power_sources.py)。该机制场景不是合法构筑卡组证明。
