## 声明与执行

随从定义使用 `retain_rewind_outcomes=True` 声明保留结果能力；`GrantRewindRetention` 可动态授予并指定到期回合。能力是独立附件，沿用复制、沉默、变形、转控、回手、到期和失活规则。只读取友方场上活跃且未死亡的持有者，多个来源不叠加。

普通[回溯检查点](m5-rewind.md)仍负责撤销/重试；本能力走独立的累计执行路径，**不恢复局面，也不拼接两份状态**。一个额外回溯预算对应两个依次执行的结果，多次预算对应 `retries + 1` 个结果。无需保留/重试选择，效果本身的发现或其他选择照常发生。

一次手动出牌只支付、入场和提交一次；一次施法只建立一个施法记录。每个结果保留生成、伤害、死亡和区域变化，下一结果读取已经变化的局面，RNG 持续推进。完成全部结果后才结束本次出牌/施法。随从只保留一个主体，重复的是被捕获的打出行为，不会重新召唤或重付费。法术的自身效果与衍生物共用一套执行入口。

`RewindOutcomeRecord` 单独记录来源、出牌/施法关联、能力持有者、捕获的行为 ID、总数和执行进度。它区分多种效果结果与多次施法：与法术重复机制组合时，每次施法各有一个保留结果记录，仍只支付一次。

## 生命周期、来源与窗口

以下是 **R-093 暂定契约**，内部测试不等于国服认证：

| 情形 | 当前执行语义 |
| --- | --- |
| 手动打出 | 使用支付前检查点捕获保留能力；之后来源死亡、沉默、变形、回手或转控不取消本次总数 |
| 效果施法、历史重施、抽到时施法 | 实际效果开始时捕获当前能力；不创建手动回溯会话 |
| 中途新增持有者 | 不追溯改变原已接受的手动出牌；后续新施法重新捕获 |
| 结果间死亡/触发 | 沿用正常检查点。普通场景中先结算死亡与亡语，再开始下一结果；若存在星舰或法术重复的外层死亡延迟，则仍遵守该外层边界，精确组合顺序待 M6 |
| 反制、目标失败 | 不启动效果结果；没有额外支付或重试 |
| 满手、满场、候选为空 | 每次按当前容量/候选处理，不覆盖前一结果来腾位置 |
| 有限次数卡面 | 每次额外结果推进卡面；保留附件和实体身份，已发生变形则不改回原卡；游戏历史仍记录最初激活身份 |
| 随从来源离场 | 已捕获行为继续；不会复制主体或重新触发入场 |
| 终局 | 沿用立即终局，剩余结果记为 interrupted；不额外提供撤销窗口 |

`RuleContext.rewind_attempt` 在当前结果中从 0 递增，让时间之沙一类行为使用对应分支。每次效果读取当前状态；保留状态与重新抽样，不等同于两条独立时间线最后的任意合并。精确源捕获、次数叠加、卡面身份、重复法术组合和触发/计数仍需国服证据。

## 保存恢复与玩家信息

内部选择可暂停在任意结果或嵌套自动施法中。进度保存在 `GameState.rewind_outcomes`，序列化帧包含每层结果完成标记；加载检查来源、激活关联、次数、嵌套顺序，以及结果必须先于所属出牌/施法结束。克隆和动作回放保持进度和 RNG 一致。

失败仍走工程事务回滚：同一动作中后续结果失败，回滚本次动作；先前已提交的选择边界保持可恢复。工程预算累计，不把耗尽当作玩法结束。

公开事件 `rewind_outcome_started/finished` 仅投影结果序号和已有可见来源；玩家 DTO 不包含内部结果历史、能力持有者列表或检查点。牌库中的原实体即便推进卡面，也不重新获得跟踪句柄；旧发现命令不能作用于下一发现。
