# 回溯检查点与结果重试

原始 M5-11a 批次公共子集，运行于 `prototype-v75` / `core-effects-v75`、snapshot schema 74、player-view-v44。动作仍为 player-actions-v7，回放外层仍为 1，真实内容包为 `representative-m5-v38`。检查点的 58 项内部验证见 [专项测试](../tests/test_m5_rewind.py)；M5-11b 另补次数卡面和两张生成代表，见 [卡面与生命周期](m5-rewind-forms.md)。实现见 [rewind.py](../hs_sim/engine/rewind.py)，整族保持 partial。

## 声明与执行范围

本页描述手牌入口。英雄技能已通过 `on_use` + `RewindSpec` 接入同一检查点，使用独立技能历史且每次激活重新获得预算；不使用手牌递减卡面链。见 [M5-12c-02b 与 R-102](m5-power-rewind.md)。

物理法术或随从同时声明 `Keyword.REWIND`、`rewind=RewindSpec(retries=1)` 和打出行为。`retries` 是**这次手动打出允许的额外尝试数**；初次尝试不计入重试。未声明的标记、不合法的类型、无打出行为和裸动态授予均拒绝。持久次数需另外声明 `next_card_id` 的完整递减卡面链；单独的 `retries` 不代表持久消耗。

手动 `PlayCard` 在支付前捕获独立 `RewindSession`，执行原出牌及全部续接、触发和死亡结算，再提供 `ChoicePurpose.REWIND` 结果选择。沿用已有 `SelectChoice`，无需新玩家动作。选 `keep` 保留当前状态并结束；选 `retry` 恢复检查点，再执行原目标/位置的出牌；预算耗尽后自动保留末次结果。

当前原型将整次手动出牌作为尝试范围，因此反应、费用、法术重复迭代、生成与抽取都在同一检查点内。来源死亡、变形、回手不会抹去本次捕获的资格。反制没有有效载荷结果，因此直接提交；自动施法、抽到时施法与效果召唤不会开启新的手动回溯会话。以上精确来源和窗口政策为 **R-091 暂定契约**，并非国服认证。

`RuleContext.rewind_attempt` 向该出牌实体的行为提供捕获的尝试编号，初次为 0，重试后递增；其他来源默认为 0。可用于表达“回溯后改用另一候选范围”等行为，不要求卡牌回调读取可变全局对象。

## 恢复哪些状态

| 恢复到尝试前 | 保持单向推进 |
| --- | --- |
| 双方资源、伤害/护甲、区域、实体附件、光环贡献与公共机制状态 | RNG 流；相同结果仍可随机再次出现 |
| 游戏内出牌、施法、抽取、死亡及其他状态历史 | 宿主动作历史、全知事件和双方过滤日志 |
| 尝试前的牌库和手牌 | 动作编号、实体/附件/入场顺序/死亡/窗口/选择的已分配上界 |
| 尝试前的身份映射与已知卡牌 | 玩家已见信息、日志游标、已分配观察/选择句柄的上界 |

先恢复支付前状态再执行支付，最终净消费和出牌历史只保留一次。不会把撤销的抽牌、亡语、尸体或法术计数留在当前游戏历史中。新生成实体使用更高 ID，撤销分支的实体 ID 不会绑定另一张新牌。连续数组历史重新使用自己的记录序号，不将其暴露为玩家句柄。

恢复是解释器控制操作，不作为一次属性增加或伤害/死亡检查，因此不会凭恢复前后差值误触发英雄获得攻击力等效果。工程步骤预算累计跨过内部选择及所有重试；重试报错或超预算时，事务回滚到用户选择之前，不丢失已有结果。后续选择仍受剩余工程预算约束，预算耗尽不会自动提交或冒充玩法终局。

## 玩家知识与日志

日志只追加。`timeline_rewound` 明确说明此前分支被撤销：玩家事件中的 `rewind.after` 是**该玩家自己的事件游标**，`attempt` 是新的尝试编号。宿主事件记录全知起点，玩家 DTO 不包含它，也不包含检查点、牌库顺序或 RNG。`rewind_kept` 表示本次会话提交。这两个控制标记不捕获卡牌触发。

从检查点恢复原有身份映射，并保留仍使用相同句柄、相同卡牌身份的已见信息；已撤销的新实体句柄退休。所有已见事件仍可回看，看到一张抽出的卡不会因此获得恢复后牌库位置的跟踪句柄。双方 `next_ref` 和 `next_choice` 不回退，旧选择命令即便附上新观察修订值也会被拒绝。

## 保存、终局与验证

会话是快照的独立 `rewind_session` 字段；包含原动作、支付前状态、此前玩家知识/日志和起点、尝试编号。它不递归嵌套自身。当前结算帧继续保存效果队列与累计预算，能够在原牌发现、对手选择、结果选择以及结果选择触发的内层选择处保存恢复。

加载时验证原动作合法、检查点稳定、回合和原动作对应、资格/尝试数、事件起点、分支标记、历史前缀、身份上界及剩余控制续接。克隆各自拥有状态/知识副本。所有已接受选择仍进入动作回放，逐步重算分支及日志摘要。

本批沿用现有英雄死亡立即终局政策，终局清除回溯会话和未完成队列，不提供致死后的撤销窗口。该规则尚缺精确官方证据，不能把当前行为当作标准答案。

58 项专项覆盖法术/随从、保留/多次重试、随机流、净支付/历史、身份不复用、双方知识、牌库隐私、旧命令、恢复/回放、反制、终局、异常与预算，以及亡语/复生/回响/重复施法/抽到时施放/满手/来源变形回手和嵌套选择。全量回归结果在 [项目状态](project-status.md)。
