## 公共效果

[sacrifice.py](../hs_sim/engine/sacrifice.py)提供不依赖卡牌 ID 的两个入口：

```python
victim = MinionReference.capture(target)
recipient = MinionReference.capture(source)
DestroyForBuff(victim, recipient, attack=2, health=2, source_id=source.id)
SacrificeAdjacent(recipient, attack=2, health=2, side='right', source_id=source.id)
```

`DestroyForBuff` 支持指定非相邻、敌方或友方场上随从。牺牲与受益双方必须在开始时仍是捕获的活动、存活、未标记死亡随从；否则不消灭也不增益。已死亡目标不能让重复请求再次领奖。自我消灭可以成功，但不向墓地实体授予增益。

`SacrificeAdjacent` 在效果执行时读取当前场位，取左侧或右侧紧邻一位。没有该位置、位置是地标、休眠、待建造星舰或已濒死随从时不消灭，也不跳到更远的随从。此前回合末触发的召唤/死亡/回手会改变后续实际目标，不使用回合末事件最初捕获的位置列表。

## 状态身份与结算

`MinionReference` 保存实体 ID、控制者、卡牌 ID、区域修订号和入场顺序；既不能把新实体误认成原随从，也不能因原实体回到相同位置/同一职业而恢复旧引用。

- 消灭通过原有 Destroy 处理器和统一死亡检查，不生成第二套死亡/尸体/亡语流程。
- 普通结算按已有调度：消灭标记与事件、死亡检查、捕获触发/亡语/复生，再处理条件增益。
- 内部 `CompleteDestructionBuff` 保存本次消灭前的死亡记录边界，只接受此后相应目标的死亡，不能用较早死亡历史冒领增益。
- 增益前再次核对受益随从。死亡、转控（包括转出再转回）、变形（包括原样变形）、回手后重入都使原奖励失效；复生的新实体不会继承旧奖励。
- 普通受伤/其他增益不改变身份。牺牲已经开始后的沉默不会追溯取消已捕获的效果数值，但下一次事件不再捕获被移除的触发。
- 临时休眠的受益随从不能接受奖励。终局遵循现有规则，清空剩余结算，不再增益。

场上 Transform 现在也推进 `zone_epoch`，即使变回同一张牌仍可区分前后身份；原手牌/牌库升级已有对应修订机制。此变更随规则/schema 版本发布。

**R-073：消灭与奖励的精确窗口待国服校准。** 本批使用现有公共死亡检查时点，不宣称已证实官方在所有卡牌上的亡语/复生/奖励顺序。在星舰发射明确延迟随从死亡时，已接受的消灭标记也视为满足条件，奖励沿发射序列继续；不额外插入死亡检查。挂起选择保存这一边界，发射结束再处理死亡。

**R-074：待结算来源的身份与位置待国服校准。** 回合末已捕获效果要求来源保持同一场上身份；执行时动态选相邻目标，奖励时再次校验。沉默后已开始效果、临时失活及原样变形的具体官方例外继续保留为校准场景。
