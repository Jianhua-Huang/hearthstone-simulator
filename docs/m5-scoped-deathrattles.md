# M5-13d-02k-05：自身与获得亡语的范围

2026-10-03。内核 `prototype-v96` / `core-effects-v96`，快照 schema93，代表包56；观察51、命令7和外层 replay1保持。**R-140是明确的原型政策，尚未国服校准。** 本批补齐逐项亡语次数和自身／能力来源筛选，不宣布混合重复类别或完整卡族完成。

## 声明与逐项计划

`DeathrattleRepeatSpec`在次数和载体类型之外增加 `scope` 与 `origins`。`scope='friendly'`作用于接受玩家的匹配载体，`scope='self'`只作用于装有该政策的实体；`origins`是非空、唯一、不可变的 `printed` / `granted` 元组。默认仍为友方、两种来源，保留男爵和雪落墓地的既有范围。玩家长期效果没有自身载体，声明自身范围时明确拒绝。

每个有效亡语能力分别计算匹配来源，多个次数设值取最大值，无来源时一次。`DeathrattlePayloadPlan(ability, plan)`绑定原附件与其计划；`DeathrattleBatch.payloads`保存有序、非空、能力ID唯一的载荷。不能用整组单一次数表达“印刷一次、获得两次”。`batch.abilities`仍可查询原顺序；`batch.plan`只在所有载荷计划完全相同的情况下可用，混合计划明确报错，可信宿主应逐项查询。

一轮长度为各载荷次数之和，总长度为主动轮数乘一轮长度。排列继续是主动轮次、能力顺序、该能力的来源重复。例如印刷A一次、授予B两次、主动两轮：A1/B1/B2，再A1/B1/B2。每次捕获保留独立身份和原附件，位置函数、预算与恢复共同使用这套排列。

## 接受窗口与自身死亡

主动入口从当前有效能力中捕获每项计划；自然入口在同批死亡移出后读取外部场上及玩家来源，保持R-137/R-138窗口。明确自身范围的政策另外从该载体的不可变 `DeathRecord.abilities`捕获，避免载体死亡移出场面后丢掉自身效果。这个保留只适用于自身政策，不让已死亡的友方次数光环继续贡献。

计划接受后冻结载体、控制者、能力顺序、逐项来源与次数；后续沉默、变形、离场、转控和来源到期不重算已接受批次。第一轮每项能力的首次回调保留原接受局面，额外重复和后续轮次读取先前结算后的新局面。新入口重新捕获。原控制工作、死亡／光环检查点、终局截断与事务保持，不新增解释器或玩法事件。

## 能力来源与生命周期

筛选使用能力实例的 `origin`，不根据行为ID、标签、授予者或卡面名称猜测。直接授予和磁力继承是 `granted`；磁力仍保留原卡面声明身份。当前实体复制保留印刷／授予分类，并将自身政策绑定到新载体；其来源证据仍保存原身份。星舰基础及组件声明沿用已有 `printed`分类，直接附加的亡语是 `granted`。这些分类是本原型已有来源语义，精确官方行为仍列R-140。

沉默移除政策和授予能力；沉默后再次授予仅按当时有效来源计算。变形、回手后重打、复生沿用公共生命周期重建／重置规则。临时政策和亡语分别到期；转控后的新接受使用当前控制者，自身政策不作用于邻居或原载体。动态自身政策可复用 `GrantDeathrattleRepeatAura`，不需专门卡牌分支。

## 保存、恢复与信息边界

schema93序列化逐项能力和计划、声明范围与来源，明确拒绝schema1～92，无默认迁移。恢复校验载荷顺序与覆盖、每项来源范围、冻结自身死亡证据、完整位置和挂起队列；主动捕获局面也核对完整有效能力集合。修改来源、重复／遗漏载荷或位置、改变次数与伪造控制者均拒绝。它验证结构与语义一致性，不提供快照来源认证。

原工程预算在分配历史前检查完整总长度，每个工作继续计入累计预算；错误回滚，工程耗尽不冒充玩法结局。普通回溯撤销原计划，保留结果式回溯建立新接受批次。玩家观察与命令版本保持，内部计划、死亡记录和全知快照只供可信宿主，不能直接提供给玩家。
