# M5-13d-03d-02b 沙德沃克与混合历史重演

本批只把一个必要代表接到已有公共机制：`GIL_820`使用`RepeatPlayedBattlecrySequence`，没有新的解释器、全局递归计数器或存档字段。引擎仍为prototype-v84/core-effects-v84、snapshot81；代表包升级为representative-m5-v46，282条冻结内容、283个定义（另含test.hero），十四个choice-only描述保持。38项专项、4347项全量及69示例通过。

**这是R-126实验适配，不是当前国服沙德沃克的完整规则认证。** 数据版本已固定；上限、嵌套窗口及来源政策的证据缺口见[前置审计](m5-shudderwock-policy-audit.md)。集中校准仍属于M6。

## 明确采用的实验政策

| 项目 | 本批契约 | 未证明的官方边界 |
| --- | --- | --- |
| 数量 | 每个序列最多30次直接主体尝试，无目标也占一次，不补抽 | 30是实验候选值；已有官方历史20次公告不能证明当前30次或国服部署 |
| 候选 | 已完成的本玩家出牌声明，包含反制声明；随从/武器/英雄共用 | 反制、组合主体、特殊提交的正式资格仍待校准 |
| 自身排除 | 排除`m5.shudderwock`声明行为，不排除整张复合载体的其他主体 | 身份别名和动态混合声明需随对应机制再次验证 |
| 抽样 | 从过滤后的候选无放回随机选至上限，再随机排序，接受时冻结 | 服务端具体抽样步骤与随机数消费尚未校准 |
| 来源 | 每个直接主体前要求同一活跃形态；死亡/回手/变形/休眠阻止后续；沉默不取消已接受序列 | 同名变形、醒来检查点、铜须第二遍和特殊离区待国服校准 |

| 目标/选择 | 原目标域实时筛选，再排除当前载体；副本仍可选；主体内选择随机 | 排除只作用于直接请求，不擅自传播到所有后代的自有政策 |

## 历史窗口与嵌套

使用已有`battlecry_play_window`，与实验鹦鹉保持同一原执行窗口政策：手牌主体以本次play_id为排他上界；借用出牌声明以原history_play_id为上界；复制实际激活追溯其原来源；直接触发场上实体则使用该激活开始时的历史边界。

因此“实际历史复制原沙德沃克”暂时只看到原来那次之前的历史；“现在直接触发场上沙德沃克”可以读到后来完成的出牌。这两种行为分别测试，不能由名称“再来一次”混同。**这个差异是待校准假设**：如果正式规则要求借用时读取当前全部历史，必须一起核对间接自身排除或共享后代限额，不能只移除上界导致循环。

专项序列`普通护甲战吼 → 沙德沃克 → 鹦鹉 → 沙德沃克`共4次出牌、11次实际激活，最终获得10点护甲。第二个沙德沃克直接选取普通战吼和鹦鹉；鹦鹉借用第一个沙德沃克，而该层只有更早的普通战吼。每条本组合的出牌历史边都向更小的原提交ID前进，以声明的窗口正常结束。它证明的是本实验策略有限、恢复一致，不证明官方采用同一算法。

每层仍有独立直接限额。30不是整棵后代树的总限额，任意其他行为若主动制造循环仍会受到工程预算保护。直接自身目标排除、来源停止和控制者政策也不自动覆盖其他来源自己的嵌套效果。这些边界有意公开，后续不能用38项通过宣称所有历史重演来源已闭环。

## 组合、存档与信息

复用原主体而不重新付款、不产生新出牌事件，也不复制原卡的全部附件。铜须使手牌来源开启两份独立序列；伯尔纳使用原首次出牌政策，间接激活不再次触发“打出卡牌”。原始发现可人工选择，历史重演采用自动选择。条件重新读取执行时局面，复制自身的主体使用现载体。

测试在battlecry_started监听中暂停，以及在沙德沃克→鹦鹉→沙德沃克内层暂停，验证多层结束标记、冻结随机、玩家接口、保存恢复和完整回放。中途转控按history_player_id/player_id分别验证。普通回溯撤销旧结果；保留结果的回溯运行各自有限序列。失败后的历史、付款和RNG一起回滚，终局中断余下工作。

玩家观察不输出历史上界、原play_id、行为ID、来源epoch或内部续接计划。全知记录仅供可信宿主调试。

[38项专项](../tests/test_m5_shudderwock.py)与[真实组合示例](../examples/shudderwock_history.py)覆盖上述契约。示例用宝石甲虫、沙德沃克、鹦鹉、沙德沃克，经玩家接口跨回合执行，首次发现中途恢复，然后自动完成后续发现并验证全回放。全量结果见[项目状态](project-status.md)。
