当前 `spell_repeats.py.execution_count` 只扫描己方有效场上随从的 `spell_repeat` 附件，`SpellRepeatSpec` 只有总次数和职业关系，未保存玩家预算/到期或消费收据。已有独立法术施放历史、法术批次、玩家战吼/连击政策可作设计参照；不可直接复用连击的声明、激活或消费记录。

下一增量先覆盖BOT_411/EDR_464需要的公共政策，最终是否接代表取决于完整依赖是否满足。必须明确：

1. 玩家与来源分离、匹配范围、有限次数、本回合到期及重叠政策的次数合并。
2. 支付/提交、反制、目标转移、实际主体接受与自动施法分别在何处捕获/消费；拒绝用函数名推断规则。
3. 一个手牌出牌只扣一次预算；多个重复遍、回溯重试与保留结果怎样携带原计划。
4. 法术死亡延后、发现独立选择、抉择缓存与现有批次兼容；暂停、终局、回滚及严格恢复。
5. 只公开玩家规则事实，不把来源/附件/消费收据泄露给玩家。

先前待办中的条件/种族重复、动态战吼主体和混合来源继续保留。此次原始候选检索未证明所有这些条件都有已确认构筑来源；不要为填清单先造任意开关。额外/跳过回合、其他关键词族、完整正式池与国服校准仍属于整体目标。

## 现有执行路径与实施切口

以下来自当前内核87的源码阅读，是下一增量的设计输入，尚未新增玩家法术政策，也不是官方规则结论。

| 边界 | 当前入口 | 下一增量需要维护的约束 |
| --- | --- | --- |
| 手牌提交 | `resolver.play_from_hand` 在付款并加入PlayRecord后开启法术窗口 | 若采用提交消费，收据应在提交反应前冻结；非法操作及付款失败不能消耗。不能等到主体开始才处理反制牌的用途 |
| 主体接受 | `interrupts.resolve_spell` 在目标/反制窗口结束后调用 `spell_repeats.execution_count` | 场上光环仍按这个现有窗口读取；玩家提交收据与此时场上次数合并，不能因新增政策提前冻结既有光环 |
| 物理重复 | `spell_repeats.begin/start_iteration` 以play_id维护批次及死亡延后 | 一个手牌出牌只捕获一次预算。重复施放的各个cast和选择不得再次扣除；计数1的提交及反制也可能需要收据，不能让收据仅依附于存在的重复批次 |
| 自动施法 | `spell_casts.automatic` 及生成/存储/抽到/历史入口另建cast，无新手牌提交 | 首个实现明确仅匹配手牌使用；自动施法不消费也不继承这种预算。若未来来源要求自动施放，须另立来源策略并验证，不把入口顺带扩大 |
| 普通回溯 | `rewind.retry` 恢复提交前GameState并重新执行动作 | 玩家预算和收据随检查点恢复，最终接受的分支仅消耗一次；RNG和身份计数保持既有回溯政策 |
| 保留回溯结果 | `rewind_outcomes.payload` 包住每次物理施法的主体 | 已捕获的手牌预算不在各个保留结果中重捕获；结算期间新授予的预算保留给之后匹配的出牌 |
| 到期与信息 | 现有玩家战吼/连击政策提供到期和受控公开投影示例 | 玩家法术政策独立建模；一次原子移除到期项目，再处理反应。只投影规则事实，来源实体ID和内部收据留在全知状态 |

建议实施顺序：先确定有限用途、全局回合截止和非乘法叠加的暂定契约；再增加独立玩家状态/提交收据及严格序列化与验证；接入提交与次数合并；补到期和公开投影；最后接必要来源。保存结构及观察结构变更必须更新各自版本，不能沿用84/48伪装兼容。

专项需要覆盖：反制仍按所选提交契约消费；移除/授予发生于提交反应时不追溯已捕获计划；场上光环在主体接受前改变仍按现有窗口生效；多次政策各减一次而非次数相乘；三次预算跨回合、本回合预算到期；自动施法不消费；独立发现、抉择、死亡延后、普通回溯与保留结果；错误回滚、终局、待选恢复与篡改收据拒绝。真实来源是否可直接接入仍以完整依赖核对为前提。
