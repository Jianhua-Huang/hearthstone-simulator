# M5-13d-02h：玩家法术次数、用途与期限

2026-09-25。运行内核 `prototype-v88` / `core-effects-v88`，snapshot schema85、玩家观察49、代表包49；动作7、外层replay1保持。旧schema1～84及旧观察版本明确拒绝。**R-131为内部原型契约，未获国服校准。** 本批不认证完整卡池或全部施法来源。

## 公共表达与归属

`AddSpellRepeatModifier(player_id, spec=SpellRepeatSpec(class_mode='any'), source_id=None, uses=None, expires_turn=None)` 为玩家添加独立次数政策。`casts`为总施放次数，至少2；`uses`为剩余匹配的手牌出牌数，None表示不限；`expires_turn`是全局回合结束的绝对截止值，None表示不自动到期。`RemoveSpellRepeatModifier`按玩家和内部政策ID移除，移除已不存在项目无效果。

政策使用独立 `SpellRepeatModifier`，不占场位、奥秘、任务或长期效果容量。来源身份只供全知诊断；来源沉默、死亡、转控、回手或变形不会撤销已经授予的玩家效果。不能把持续光环的载体生命周期套到此处。

所有适用来源取总次数最大值，不相加或连乘。所有匹配的有限政策各消费一次；较低次数政策也消费。重复两次和三次效果重合时，总共三次，不变成六次。当前规则仍需实际国服证据确认。

## 两个捕获窗口

1. `play_from_hand` 完成付款并追加手牌PlayRecord后，先捕获玩家政策，再发出提交事件及进入目标/反制窗口。不合法的动作和付款失败不消费。这里仅匹配法术手牌出牌；随从、武器、英雄技能等不匹配。
2. 每次匹配生成独立 `SpellPolicyReceipt`，记录play_id、匹配时的英雄职业，以及消费前的政策快照。有限用途一次减一，耗尽移出活跃列表；无限政策保留并记录适用收据，不产生“使用一次”的扣数事件。消费后才执行提交反应。
3. 法术被反制也保留提交收据与消费，但不启动重复主体。提交反应导致终局时同样保留消费，未开始的重复阶段不凭空创建。
4. 玩家政策冻结后，结算期间新授予或移除的政策不改变这一次的计划。新授予项目留给下次匹配手牌出牌。
5. **场上法术重复光环仍在目标/反制窗口关闭后读取。** `spell_repeats.execution_count`将已捕获玩家次数与此时仍有效的场上次数取最大值。不能为了复用收据而将既有光环提前到提交窗口。
6. 重复主体、目标、死亡延后、抉择缓存及独立发现沿用[法术重复契约](m5-spell-repeats.md)。物理施放各有cast记录，但只有一次手牌出牌和一次预算消费。空效果法术也消费并记录实际施放。

玩家政策的职业筛选复用 `SpellRepeatSpec`：any不限；other使用提交时英雄职业和法术印刷职业，中立或包含本职业的多职业牌不匹配，缺失资料明确失败。收据保存提交时英雄职业，之后换英雄不把过去的资格重解释。场上光环使用自身较晚窗口的当前英雄职业；两个窗口有意分别保持。

## 自动施法、回溯与期限

本批政策仅作用于手牌使用。生成自动施法、抽到时施放、历史重施及手牌法术内部嵌套的自动施法，不消费这种预算，也不继承它的重复次数。这是明确的来源边界，不代表所有写着“下一个法术”的正式牌都已完成来源校准。

普通回溯恢复提交前GameState，连同玩家预算和收据回到检查点，再为新分支提交一次；最终接受的分支只扣一次。保留全部回溯结果时，多个结果共享原手牌收据，不重捕获或重复扣数；同一法术的两次物理施放与各自多个保留结果仍保持独立历史。

回合结束时先原子移除双方所有截止政策，再发出到期事件。到期反应中新授予且截止为当前回合的项目进入既有稳定清理循环。此处是全局回合期限，不是“再等受益方一个回合”。额外/跳过回合仍是其他待补机制。

## 保存、验证与玩家信息

玩家活跃政策、历史提交收据、挂起的添加/移除指令和政策规范均支持类型化JSON保存，不依赖可变闭包。恢复检查字段集合、非布尔整数、唯一身份、归属、创建/到期时间、原始卡身份、资格、收据顺序、连续剩余用途及其与重复批次的关系。收据不能复用仍在其他类型附件中使用的身份。已消费或主动移除的项目不需要仍在活跃列表。

暂停可能发生在提交反应中、主体开始前，也可能发生于某一遍发现内；恢复时不会再扣一次。未挂起动作失败回滚整个出牌；选择失败回到先前待选状态，保留此前已经成功提交的一次消费。终局中断不退还已消费用途。工程结算上限报错，沿用事务回滚，不转为规则判负。

`spell_modifiers`及四类政策事件只公开casts、class_mode、uses_remaining、expires_turn。来源实体、附件ID、收据、行为和帧都不进入玩家观察。公开日志恢复同样严格检查字段及数值。
