# M5-10a：招募、死亡历史复活与入场身材

本批建立区域召唤选择、死亡历史筛选、基础复活和入场前属性设值。只增加公共能力和合成验证，真实卡包保持不变。入口 [summon_sources.py](../hs_sim/engine/summon_sources.py)，[62 项专项测试](../tests/test_m5_summon_sources.py)；完整结果见 [项目状态](project-status.md)。

## 物理招募与死亡历史复活

v79扩展：区域招募的 `PoolQuery.ability` 读取真实卡牌能力；`DeathQuery.cards.ability` 的current基准读取死亡时冻结附件，printed基准读取死亡卡面。复活仍重建基础实体，不复制死亡附件。详见[能力筛选](m5-ability-filters.md)。

| 操作 | 身份变化 | 主要契约 |
| --- | --- | --- |
| `SummonFromZone` | 原手牌/牌库实体移到战场 | 保留已有实例状态；跨玩家来源保留 owner，controller 改为接收者；不抽牌、不触发疲劳、不支付该随从费用、不执行战吼 |
| `ResurrectMinion` | 根据指定死亡记录创建新实体 | 原死亡记录和墓地实体保留；新 owner/controller 为接收者，来源指向死亡实体；重建基础能力，不恢复伤害、沉默、已消费能力或额外附件 |
| `Resurrect` | 从冻结的死亡候选批量重建 | 每次重建及其反应结算后继续；同次调用不重复使用已选记录或卡牌身份，其他调用仍可使用原死亡记录 |

所有路径接入既有随从入场，支持巨型附肢、休眠和召唤触发。复活不算重新打出，也不执行战吼、回响或微缩；复生是重新安装的印刷能力，不因曾经消费而永久丢失。星舰保留死亡时的组件构成，重建活跃主体，不重新执行发射；兆示基础形态按新入场时接收者的计数强化。特殊保留附件或可变身份恢复仍须另行声明，不能静默假定完整支持。

```python
# 招募：从自己的牌库随机召唤费用不超过 4 的随从。
SummonFromZone(player_id, query=PoolQuery(max_cost=4))

# 原手牌实体移入场；owner_id 可指定从哪名玩家的区域选择。
SummonFromZone(player_id, zone=Zone.HAND, count=2, selection='first')

# 从死亡时属于己方的记录中选择三条，各自复活基础形态。
Resurrect(player_id, count=3, distinct='death')

# 不同卡牌身份：同名多次死亡只占一组候选。
Resurrect(player_id, count=3, distinct='card')

# 复活两个死亡时具有亡语的随从，入场前设为 1/1。
Resurrect(player_id, count=2, query=DeathQuery(has_deathrattle=True),
          stats=SummonStats(attack=1, health=1))
```

`SummonFromZone` 每次实际召唤后重新查询区域，因此召唤反应改变的牌库会影响下一次选择。满场、无候选或零次请求不会消耗随机数；满场不移除或揭示隐藏来源。`selection='first'` 使用当前区域顺序，`random` 按物理候选均匀选择。区域引用带修订号，不能误命中已移动又返回的旧状态。

指定 `position` 时，批量操作使用递增数值插入位置；不指定则使用普通右端插入。巨型附肢和中途反应共享场位，因此数量是最大尝试次数，不保证全部成功。这个位置策略不是针对任意卡牌文本的自动推断。

## 死亡候选查询

`death_candidates(state, registry, player_id, DeathQuery(...), source_id)` 是只读规则查询，返回不可变死亡记录；不能把全知查询结果直接交给玩家。需要玩家选择时，用已有 `RequestChoice` 明确构造选项和 `ResurrectMinion` 后续效果。

`DeathQuery` 支持：

- 死亡时的 friendly / enemy / both；按 controller 判定，不按原 owner 或墓地实体的当前状态判定。
- 复用 `PoolQuery` 的印刷费用、职业、种族、稀有度、排除身份及关键词过滤。全种族 `all` 候选可匹配具体种族，公共候选过滤同步修正。
- 关键词可显式选择印刷定义或死亡时的有效关键词；亡语条件读取死亡记录的有效能力。
- 全局回合区间，以及排除特定来源实体 ID。排除一个实体与排除其整种卡牌身份是不同条件。

只有战场随从的真实死亡可成为候选，武器/地标销毁、弃牌、烧牌和普通移动不算。未知的必需元数据明确报错，不能通过过滤掉未知候选伪造正确概率。

批量复活在开始时冻结死亡 ID，不吸收本批复活引起的新死亡。`distinct='death'` 按每次死亡等权抽取且本批不放回；多次同名死亡仍可得到多个同名实体。`distinct='card'` 先按卡牌 ID 分组，对身份组等权，再选择组内死亡记录；同一身份的不同星舰构成也因此需要显式选择具体记录。确定性选择按历史顺序。候选记录从不被全局消费，后续复活仍可再次使用。

## 入场前身材与状态恢复

`SummonStats` 供 `Summon`、`SummonStoredCard`、`SummonFromZone`、`ResurrectMinion` 和 `Resurrect` 共用。攻击力可为 0，生命须大于 0；至少指定一项。它在主体创建/移入后、召唤事件与巨型展开之前添加属性设值附件，再应用连续光环。设置生命同时清除已有伤害；只设置攻击不修改生命状态。

设值不是改写卡牌基础定义。后续沉默按普通附件语义去掉它，当前复制保留、基础复制不继承。入场触发和其冻结上下文已看到设值及光环后的属性，避免先触发再补 Buff 导致行为错误。

每次成功复活写入独立 `ResurrectionRecord`，保存死亡记录 ID、新实体、接收者、回合/操作、施效来源及可选入场身材。M5-12b-02a 又加入原始入场顺序和区域修订，支持成功主体的受保护续接。满场失败不写成功记录。严格恢复校验新实体唯一性、来源、owner、死亡类型和时间顺序；之后实体变形/转控不改写成功历史。该校验不声称能够认证任意人为构造的自洽历史。

M5-12b-02a 增加 `DeathQuery.cost_extreme` / `cost_basis`，以及 `Resurrect` / `ResurrectMinion.on_summon`。费用极值与后续实体增益的完整约定见 [死亡费用筛选与复活续接](m5-resurrection-followups.md)；该增量有独立 51 项专项，不将原 62 项测试数当作新增总数。

snapshot schema 74 拒绝旧 1～71；`player-view-v44` 新增公开 `minion_resurrected` 事件，仅投影既有可见身份，不发内部死亡/复活记录 ID。外层 replay schema 1、player-actions-v7 保持。全部选择帧、随机状态、失败回滚和重算回放沿用统一流程。
