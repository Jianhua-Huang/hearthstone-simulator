# 声明式目标筛选

本接口供普通主动操作和独立战吼/连击主体共用。它补充目标域中的条件筛选，不改变付款、主体接受窗、死亡检查或结算顺序。实际执行结果与下一项只在[项目状态](project-status.md)和[机制清单](mechanism-backlog.md)维护。

## 公共接口

`TargetPredicateSpec` 位于 `hs_sim/engine/target_predicates.py`，使用 `Registry.register_target_predicate(spec)` 注册。当前可以交集组合以下条件：

| 条件 | 依据 |
| --- | --- |
| `attack_min` / `attack_max` | 候选实体当前有效攻击力，包含属性修改、光环和“攻击力等于当前生命”等派生关系，包含端点 |
| `health_min` / `health_max` | 候选实体当前剩余生命，包含端点 |
| `max_health_min` / `max_health_max` | 候选实体当前最大生命，独立于剩余生命，包含端点 |
| `damage_min` / `damage_max` | 候选实体当前损伤值，非负，包含端点 |
| `damaged` | 当前损伤大于0为受伤；`False`要求未受伤，`None`不限制 |
| `durability_min` / `durability_max` | 候选实体当前耐久，包含端点 |
| `printed_tribes_any` | 候选当前卡面对应静态定义的印刷种族，非动态种族；`all`匹配任一要求种族；元数据未知明确报错，已知空集合正常排除 |
| `current_tribes_any` | 候选当前种族，按有序种族附魔修改印刷集合，尊重全集的指定排除；未知完整集合报错，见[动态种族契约](m5-dynamic-tribes.md) |
| `printed_rarities` | 当前卡面定义的已知印刷稀有度；Rarity.NONE为已证无标签，未知仍报错，见[条件法术](m3-conditional-health-spells.md) |
| `keywords_all` / `keywords_none` | 候选实体当前有效关键词，分别全部具备/全部不具备 |

目标域、友敌关系、是否排除来源、必选/可选/有目标时必选，以及潜行、免疫和魔免的可选中保护继续由公共 `TargetSpec` / `targeting.py` 检查。筛选条件不替代这些限制。

```python
from hs_sim.engine import Registry, TargetPredicateSpec, Keyword

registry = Registry("my-target-rules-v1")
registry.register_target_predicate(TargetPredicateSpec(
    "small_beast", health_max=4, printed_tribes_any=("beast",),
    keywords_none=(Keyword.DIVINE_SHIELD,),
))
# 卡牌或独立主体声明通过 target_rule="small_beast" 引用；
# 再用 TargetSpec 声明区域、实体类型与友敌关系。
```

注册值必须是准确类型的不可变声明；整数拒绝bool，区间不得反向，关键词要求/排除不得重叠，过滤项不得重复。未知规则、任意用户回调冒充内置规则、冻结后的注册继续拒绝。

`damage`范围不得为负；`damaged=False`不能同时要求正损伤，`damaged=True`不能把损伤上限设为0。攻击力、最大生命、剩余生命和损伤分别读取对应属性，不用一种属性冒充另一种属性。

## 接受、后续执行与恢复

普通根及每个物理Battlecry/Combo主体各自查询完整有序候选，沿用自己的激活/目标条件和原支付前接受窗。公共授予层只判断是否存在完整的已注册主体授权，不执行筛选、报价、主体行为或随机选择。

付款前候选证明保留原实体当前攻击力、最大生命、损伤、剩余生命、耐久、关键词和卡面事实；本接口只读这些字段及已绑定注册表的静态元数据。事实要求“剩余生命＝最大生命－损伤”，攻击力及损伤非负，保留死亡实体可能出现的负生命。当前攻击力保存实际属性值，不从印刷攻击力或当前目标的后续状态推算。恢复时从原事实重算原候选；目标随后受伤、治疗、获得增益或变形，不能据当前目标重写原选择。实际主体执行仍以现有 `skip_unavailable` 政策检查当前目标是否合格。

普通支付、零主体收据、磁力普通根和回溯重试共用该事实格式；回溯新尝试在自己的原窗口重新捕获，不借用第一尝试的攻击力或损伤。完整原来源Entity继续与来源的标量事实逐项核对，缺失新字段不会默认填0。

所有筛选参数进入注册表指纹。同名规则但阈值或过滤条件不同，不能加载原接受记录。未使用此接口的注册表不新增谓词指纹字段。原事实保存种族附件及可选原玩家观察后开发快照为schema137、规则为prototype-v140/core-effects-v140；旧schema1～136需使用原引擎，明确拒绝自动补缺恢复。玩家公开/自身属性增加有效种族，观察升级58；命令9和replay1保持，没有改写已有回调语义或扩大旧内置规则。

## 玩家边界

引擎拥有实现函数，用户只提供声明，不提供可读取全局状态的回调。玩家候选查询在执行谓词前检查声明和目标域；对方手牌的结构过滤明确返回 `unsupported_target_domain`，不会通过候选数量揭露暗牌生命、关键词或种族。公开区域及自己的手牌可使用此规则，牌库/墓地等区域仍需既有独立揭示/选择契约。

完整原事实及注册表指纹仅供可信宿主和恢复校验；玩家JSON继续只得到当前可见句柄与目标列表，不导出原目标证明或内部授权标识。证明检查只说明内部一致性，不提供未签名存档的外部来源认证。

## 保留的缺口

动态种族已由公共附魔修改层表达，原事实保存其完整有序修改并按原卡面重建；具体来源若要求持续光环、长期种族规则或其他当前依据接受窗，仍需明确并验证其政策。依赖玩家可见资源、费用和计数的条件已由[显式玩家条件原输入](m5-player-target-inputs.md)表达；本结构接口不调用任意回调。未公开内部历史或全知状态的自定义条件仍需独立输入与授权契约，不能把玩家观察当作完整内部历史。[间接战吼](m5-indirect-body-targets.md)已连接自己的原授权和逐次条件/目标/RNG窗；其他生成、历史间接来源继续按独立契约补齐。所有精确国服时序与正式卡牌支持范围维持原校准门槛。
