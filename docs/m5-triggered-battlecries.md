## 组合契约

伯尔纳自身只有`card_played`监听，没有战吼主体。其适配器使用RuleContext内冻结的完成出牌记录：玩家相同、类型为随从、有提交时捕获的战吼声明，并且completed且未interrupted，才进入历史查询。

监听条件和历史条件分别表达。历史查询为同玩家、同回合、截至这次完成出牌的首个战吼出牌；武器和英雄牌可作为历史依据，即使它们不触发这个随从出牌监听。首个依据可以在伯尔纳入场之前形成。适配器从捕获上下文选出play_id，再交给RepeatPlayedBattlecry执行该出牌中的全部捕获主体，不从旧实体当前卡面重建能力。

原出牌完成只产生一次card_played；铜须和有限次政策可以使原战吼执行多遍，伯尔纳仍对这次完成出牌触发一次。多个伯尔纳各自捕获，按现有来源顺序执行。历史子执行没有新的支付/出牌事件，不再消费或应用手牌战吼次数政策，也不因此重新触发伯尔纳。

## 来源生命周期与R-122

以下为**原型明确政策，尚未经过国服规则校准**。内部测试证明代码遵守这些政策，不证明其与官方所有边界一致。

| 边界 | 当前行为 | 校准关注点 |
| --- | --- | --- |
| 原战吼内来源死亡/沉默/变形/回手 | 完成出牌时不再拥有有效监听，不触发 | 精确监听捕获窗口 |
| 原战吼内来源转控 | 按完成时监听控制者检查出牌归属 | 控制变化和原出牌玩家 |
| 原战吼内新来源入场 | 参与随后完成事件的捕获 | 新来源入场窗口 |
| 完成事件已捕获，较早监听使来源离场/沉默/转控 | 已冻结的普通监听仍执行，使用捕获玩家和首个依据 | 官方捕获后来源存续资格 |
| 已捕获来源变形 | 回调仍是捕获的伯尔纳回调；间接执行载体卡面取开始时当前实体 | 回调身份与载体身份区分 |
| 被反制的完成提交 | 同时允许触发、允许成为首个历史依据 | 两层资格分别校准，当前均include |
| 满场入场失败或合成磁力混合声明 | 有完成提交和捕获声明时允许重演 | 不声称正式来源行为已确认 |
| 首个战吼为武器/英雄牌 | 允许成为历史依据 | 文案范围与正式执行是否一致 |
| 目标与选择 | 当前场面重新随机，使用共用RNG | 不沿用旧目标/旧发现选项 |
| 铜须与多监听/回溯 | 每次完成事件每来源一次；不对间接子主体再乘次数 | 官方重复规则和窗口 |

这些假设统一登记R-122；金刚鹦鹉自身的原历史窗口仍归R-121。卡文的本地冻结记录见[来源](../outputs/m5-13d-03c-bolner-source.json)，其canonical SHA256为`395f19a5b63418c58253c3781135718ef1a1cb494b8fe23667a9e5d0844dc185`。卡文不足以关闭上述问题。

## 验收范围

31项专项覆盖第一/后来/跨回合、来源进场前的历史、双方玩家、武器/英雄历史来源、普通召唤反例、来源两个时间窗口、多个监听、铜须/有限次政策、反制、满场/磁力、物理间接激活、目标消失、自动发现、回溯两种结果政策、终局、动作/选择回滚、玩家信息隔离、挂起恢复与篡改拒绝。

真实组合使用铜须、两名伯尔纳、宝石甲虫和金刚鹦鹉；甲虫第一次发现时保存，恢复后用玩家接口完成两次人工发现，后续六次发现自动选择。两次出牌、十次实际战吼，生成八张牌，只支付两次费用。另有两个SC_405组件的组合星舰：原出牌捕获两份独立战吼，伯尔纳保持各自声明来源和顺序重演。运行`python -m examples.bolner_history`可导出快照、回放和玩家观察。

普通监听被捕获后的行为仍由公共调度器负责；间接战吼恢复、历史依据和玩家身份仍走既有校验。内容包版本变化使旧代表包快照不能冒充新版；schema不变不表示不同内容包的回放可以混用。
