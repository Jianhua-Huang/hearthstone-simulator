# 13d-03c 前置检查：触发式首次战吼重演

本页记录v81后的组合验收依赖，尚未接入伯尔纳。SW_115伯尔纳·锤喙的中英记录来自[固定候选来源](../outputs/m5-13d-03-source-candidates.json)，canonical SHA256为`395f19a5b63418c58253c3781135718ef1a1cb494b8fe23667a9e5d0844dc185`。其文本是在使用战吼随从牌后重复本回合第一个战吼；自身为场上触发能力，引用战吼关键词并不使它自身拥有战吼主体。

源码核对：`resolver.finish_play`先将PlayRecord标为completed，再发出带play_id的card_played事件；RuleContext从此事件获得完成记录。普通场上触发已捕获独立行为上下文，`PlayRecord.battlecries`可判断该次提交时的有效声明；v81查询支持回合、类型、排除和反制政策。RepeatPlayedBattlecry已经允许非战吼载体执行别人的捕获主体，不要求载体安装该能力。

因此先组合现有机制验证，不预设还需要另一套触发或历史引擎。必须分开两层筛选：监听的是本玩家完成提交的战吼**随从**，历史候选“本回合第一个战吼”不应因触发类型限制就未经证据排除武器/英雄牌。精确官方资格仍需登记校准；尤其反制、入场失败/磁力和控制者变化。

验收至少覆盖：

- 本回合第一张战吼、后来另一张战吼，以及普通非战吼牌；原牌出牌数与重复激活数不混计。
- 第一战吼为武器/英雄牌、后来以战吼随从触发；与单纯“第一张随从”区分。
- 首次依据来自伯尔纳入场之前；下一回合重新计算，玩家归属和回合窗口独立。
- 源在出牌主体中死亡/沉默/转控，或监听捕获之后离场；使用公共监听与执行窗口，并保留待校准记录。
- 铜须让原主体执行多遍仍只有一次完成出牌事件；多个监听载体按既有排序分别触发，间接重演不再次制造card_played。
- 反制记录的监听资格与历史资格分开明确；没有实际激活的提交不能从当前实体重建旧声明。
- 有限次玩家重复政策、回溯、金刚鹦鹉原历史窗口、组合星舰、随机目标和发现的实际交互。
- 开始/完成反应中的暂停、快照恢复/篡改拒绝、玩家接口、完整回放、错误回滚和终局中断。

能以既有原语正确表达时，只增加必要代表与组合验收；发现共用缺口才扩展。沙德沃克的整局集合及复杂循环、02系列动态授予/条件重复、M0完整池与M6正式校准均未因本页关闭。
