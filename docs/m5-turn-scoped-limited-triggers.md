# M5：每个实际回合的有限触发预算

现有 `LimitedTriggerSpec.uses` 表达一个能力实例在生命周期内的总次数。实验室奴隶主的真实卡文要求“每回合一次”，因此增加 `reset='turn'`，复用原捕获、身份守卫、条件、消耗和主体执行；没有另建触发器。必要完整原行见[固定材料](../data/support/turn-scoped-limited-trigger-basics.json)。

```python
LimitedTriggerSpec(
    'armor_gained', 'native.lab_patron',
    condition_id='native.owner_gained_positive_armor',
    uses=1, reset='turn',
)
```

默认 `reset='instance'` 保持旧语义。法术迸发、暴怒始终使用实例内一次，不能改为回合刷新。当前 `turn` 范围只覆盖普通事件；带 `EndTurnSpec` 的分类结束主体明确拒绝，相关组合不在本阶段展开。

每个能力保存当前实际 `trigger_turn` 和剩余次数，在 `state.turn` 真正递增时刷新双方所有物理载体。刷新早于新回合的来源接受和开始事件；对手回合和同一玩家连续的实际回合同样属于新预算窗口。被跳过的时段不伪造新回合。能力 ID 保持，预算属于实体附件，不在同卡名或同玩家之间共享。

捕获的 `CheckLimitedTrigger` 保存必要 `budget_turn`。执行仍检查原实体、控制者、入场身份和能力实例；旧回合守卫不能消费新回合已经刷新的预算。条件成功后先扣次数，再执行主体，阻止同一实例借递归再次使用当前预算。新建印刷实体按当前回合获得自己的独立预算；旧实例的复制状态继续遵循既有附件复制政策，没有扩展特殊复制或授予规则。

生命周期、沉默、印刷重置、死亡、等待、回放和异常回滚沿已有管线。当前实体预算时钟必须等于实际回合；时钟与范围均严格验证。默认实例预算省略新增声明字段后保持旧注册表指纹；新声明参与指纹。`prototype-v267` / `core-effects-v261`、schema234拒绝旧1～233。内部预算时钟不进入玩家 DTO，旧剩余次数展示保持。

本地七类关键词复核确认已有超杀/荣誉消灭/过量治疗判定、法术迸发/暴怒有限触发和腐蚀/注能进度。关键词标签与卡文引用必须分开：有缺标签的真实关键词卡，也有普通引用和“腐蚀对战”的不同含义，不能把标签计数作为完整分母。暴雪[通灵学园说明](https://hearthstone.blizzard.com/en-us/news/23486106)确认法术迸发的一次触发概念；它没有独立证明所有自动施法来源的具体时序，因此本项不改其来源窗口。其他来源、特殊授予、正式池与国服校准继续保留。

实验室奴隶主仅作为一张必要实验代表，召唤主体使用原印刷新建。每个实际回合刷新、控制/复制边界和精确窗口是明确本地政策，仍待国服校准。实际运行结果、差异和下一项只在[项目状态](project-status.md)与[机制清单](mechanism-backlog.md)维护。
