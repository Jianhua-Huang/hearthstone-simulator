# 本地 HTML 对战界面

这是当前支持范围的实验模拟器界面。它不是最新炉石完整实现，也没有正式卡池或国服一致性认证。卡牌数据存在、可执行代表定义和正式支持是不同口径；页面提供已接入实验定义的选牌测试入口，不是完整官方收藏或组牌器。

## 启动

在项目根目录执行（只需已有 Python 环境，无新增依赖）：

```powershell
python -B -X utf8 -m web_ui.server
```

打开 http://127.0.0.1:8765/ 。改端口用 `--port 8766`，停止用 Ctrl+C。必须使用 `127.0.0.1`，服务器验证 Host 和 Origin，只监听 IPv4 回环地址。服务进程需保持运行。

## 使用

1. 默认「测试场 · 即刻出牌」，也可选「构筑开局 · 含换牌」，点击「创建 / 重置对局」。构筑开局复用 `examples/matches/constructed.json` 的法师/战士代表卡组、固定种子和实验构筑策略，含双方换牌与硬币。测试场是明确的跨职业实验场景，10法力、已有场上随从和暗影视界，方便验证出牌、攻击和真正结算内发现，不声称正式卡组合法。
2. 换牌勾选要替换的手牌；不勾选即保留。电脑托管时，对手自动完成自己的换牌；双人手动时，等待另一位玩家选择后点击「交接座位」，把设备交给下一位玩家，由其点击接手。
3. 点击手牌、英雄、技能或场上实体，再点击高亮目标执行；随从入场点击「+」位置。只有一条完整合法用法且不需要目标或入场位置的操作（包括普通无目标英雄技能、武器和法术）点击即提交；有目标的技能仍需点击高亮目标。完整合法操作、类型/来源下拉框、事件日志和玩家DTO均收进默认关闭的「调试详情」，普通对战不显示协议字段。
4. 发现与其他挂起选择使用选项勾选面板，按引擎 min/max 数量提交。预览仅使用引擎已投影给当前座位的数据。抉择等出牌前分支由当前合法动作驱动，点击卡牌后在居中面板显示玩家DTO提供的中文效果标签；只显示本次合法分支。无目标分支点选即提交，需要目标或位置的分支继续高亮对应位置；取消或Esc不提交、不扣费。
5. 页面默认选择「电脑托管」，对手会自动完成换牌、待选和普通回合。自己的换牌/发现仍须亲自确认。点击「暂停托管」或选择「双人手动」后可交接座位；托管时不显示对手手牌。暂停立即阻止下一步，已发出的单条操作可完成，再切换为手动。自己的普通操作仍受行动权限制；认输仍按内核独立契约处理。
6. 重置或认输需要页面内第二次点击，避免误触。刷新保留当前座位凭证；服务重启会丢失内存对局，需要重新创建。如果丢失原标签页的 sessionStorage 凭证，直接创建独立新局即可；旧凭证不会恢复原对局。本版不提供联网加入。
7. 「测试设置」可输入0–10整数，点击应用；也可直接「设为 10 费」。同时设置当前可用法力与最大水晶，不重开场面，之后正常支付费用。只调整当前回合的绑定座位；换牌、结算待选、交接、终局，以及过载/临时法力存在时禁用并说明原因。不会通过补费重置英雄技能或攻击次数。
8. 当前回合的完整合法列表只剩「结束回合 / 认输」时，「结束回合」变绿；仍可出牌、攻击、使用技能或其他能力时保持金色。待选、对手回合、枚举失败和操作处理中不显示绿色提示。
9. 点击「选牌测试」，按名称、卡牌ID或效果文字搜索，也可筛选类型。目录来自当前已注册的实验定义，默认只显示能直接加入手牌的项；取消筛选可查看英雄技能、选择专用定义和需专用场景生成的模板及禁用原因。「加入手牌」只给当前绑定座位添加一张，回到战场后按正常规则出牌；可配合「设为10费」测试。它不自动满足额外资源、目标、种族或其他条件，不表示全目录已逐张通过官方验证。

两个初始牌组均是固定演示配置。测试场初始牌库每方12张（4种各3张），起手、场上和随机种子固定；构筑开局使用固定30张牌组与固定种子。棋盘显示的是牌库剩余张数。「选牌测试」提供额外手牌，不修改这些初始牌组，也不从数据仓库中把尚未接入的卡片当成可执行牌。

攻击呈现按当前玩家已公开的 `attack_finished` 事件播放：攻击者蓄力、冲撞实际目标、命中闪光与目标后仰、回到原位。电脑使用同一公开事件，无需暴露其动作或手牌；取消/拒绝的攻击不会播放成功碰撞。本步新生成且旧画面没有位置的实体省略移动轨迹，结果仍按最新玩家投影显示。攻击伤害飘字不占用操作锁，下一次操作会清理上次剩余特效；命令提交与必要移动仍串行，系统减少动画偏好继续生效。

已安装的八种已知灌注技能在图标和悬停预览上显示“灌注 N 阶”，按该技能 `controller` 对应的公开 `player.imbue.level` 取值，累计尝试数 `count` 仅作提示，不替代实际阶数。小精灵的祝福（EDR_851p）的两处印刷占位符按既有R-100契约显示灌注基础数值 `max(1, level)`；0阶不伪装成已灌注一次，费用仍取实体的真实费用。该呈现不计算结算、不改变技能使用次数；其他技能文本与静态选牌目录不做通用占位符猜测，缺少有效公开进度时不编造阶数。

## 实现与信任边界

- `web_ui/server.py` 是 Python 标准库 HTTP 薄宿主，`web_ui/static/` 是无构建步骤的 HTML/CSS/JavaScript。没有另造战斗、费用或目标规则，没有修改 hs_sim 内核运行源。
- 一个进程维护最多32个独立内存对局，新的浏览器会话创建新对局，不接管既有座位；超出上限淘汰最早创建的会话。RLock 串行化观察、命令、重置和交接。Game、全知状态、快照、历史和回放留在宿主；仅使用绑定座位的 `for_player(seat).legal_actions/submit/events` 构建玩家响应。浏览器不接收 snapshot、原始 ActionResult、牌库顺序或敌方暗牌身份。
- 创建后产生随机 Bearer 凭证，对局和座位保存在宿主；重置有效会话只重置自己的对局，缺失/失效凭证只创建独立新局。客户端不能通过 viewer/player_id 参数改变座位。只有显式 handoff 能切换到另一座位，切换旋转凭证并使旧凭证立即失效；ready 前仅响应遮罩信息且拒绝操作。前端清空旧手牌、动作、选项、来源菜单、日志和 DTO；只保存凭证，不保存玩家 DTO。
- 此权限模型适用于自愿交接的本机热座对战，不是两个互不信任远程玩家的身份认证。共用设备的操作者可以主动切换座位；历史浏览器开发工具/此前已见信息无法撤销。不要对公网或局域网开放端口。
- 名称映射仅为当前玩家 DTO 或过滤日志中已经披露的 card_id 查询注册表名称，不下发全部卡表。对手已公开过的牌保留记忆属于引擎信息契约，不能误当成泄漏。
- `/api/create` 只接受 preset 和可选的 opponent；`view/handoff/ready` 只接受空对象；`action` 原样交给 Port，revision/action 之外的字段由引擎拒绝。错误仅显示固定代码与中文说明，异常、随机状态和全知摘要不下发。
- `/api/test/mana` 是本地测试宿主入口，只接受当前 revision 与严格整数 mana（0–10且不超mana_cap），不是普通玩家动作协议。当前座位和阶段校验后，在clone上使用既有 ChangeManaCrystals/RefreshMana 资源结算、信息同步和稳定检查；完整快照恢复成功才提交。异常丢弃副本，旧场面保持。旧动作的build_replay留在宿主test_segments，调整后快照成为下一回放段起点，避免把手工测试调整伪称原对局的合法动作。各段与全知起点均不下发；只返回玩家投影、费用控件状态与简单调整回执。
- `/api/catalog` 只返回注册卡牌的静态名称、类型、印刷费用/文本、实验范围与是否可直接加手，不包含对局实体、对方手牌、牌库顺序或生成候选。静态目录与当前玩家的 `names`/`card_texts` 分离，后两者只覆盖已披露身份。加牌入口 `/api/test/hand` 严格接受当前 `revision` 与 `card_id`，每次一张，只在本人正常行动窗且手牌有空位时执行；未知卡、选择专用、基础英雄/技能及需要组件的星舰模板明确拒绝。测试调整与原动作回放分段保留，不作为普通合法动作发送；全知段落仅留宿主。新建测试场配置既有实验生成上下文，生成池仍受原注册实验范围限制。
- Host/Origin 校验、JSON Content-Type、64KiB输入上限、静态路径白名单、无CORS、no-store 与 CSP 减少其他网页访问本机服务的风险。凭证不放 URL，服务不打印请求日志。

## 对手托管契约

页面新局默认 `opponent: "ai"`；`/api/create` 的该字段可省略，兼容旧消费者时省略仍为双人手动。新局的人工玩家是座位1，也可在双人模式交接后启用托管，电脑绑定另一座位。托管开启时禁止交接，需先切回手动。

`listing.opponent` 仅包含模式、托管座位、是否可推进、固定错误码和一次性控制票据。`POST /api/opponent` 接收 `{revision,ticket,mode}`，`POST /api/opponent/step` 接收 `{revision,ticket}`。revision取当前人工座位，ticket校验宿主控制版本，避免对手私有选择未改变人工观察修订时重复推进。每个成功玩家动作、测试改费、托管步进、模式切换和交接刷新票据；旧请求不改变状态。view本身不执行动作。

每次step只执行一条动作。行动者以挂起选择的player_id优先，否则为active_player；自己的换牌/发现仍由人工完成。策略只接收电脑自身的玩家JSON和独立Random，不访问Game、注册表、牌库顺序或内核随机源。普通时从完整合法动作中随机选取，排除认输，优先操作再结束回合；普通动作达到24次后尝试合法结束，挂起选择优先处理但连续选择最多64次。待选枚举超限时按已披露完整选项与min/max构造有效选择，其他错误或预算耗尽暂停并提示，不伪造合法动作。

宿主始终返回人工座位listing，不回传电脑的手牌、选择内容、动作句柄或提交结果日志。电脑动作经过原PlayerPort提交，自然进入命令历史和回放；动画只比较人工可见局面。页面每步间隔约450ms，单请求与动画串行，没有空闲轮询。暂停立即取消后续定时器，已发出的单步完成后配置为手动；交接、重置和失效同样取消旧调度。

## 范围与限制

显示英雄生命/护甲、法力/过载/已投影职业资源、双方场上实体、己方手牌、敌方牌背与双方牌库数量；公开武器、全部已安装技能、奥秘、任务和地标可见状态沿 DTO 展示。公开长期效果/进度与更多细节可展开查看。常用动作和少见动作共享合法动作面板，未枚举支持的声明明确显示错误；enumeration_limit 下仍可手动提交当前待选选项，非选择阶段有明确的结束回合尝试入口。

已有仅用于呈现的出牌、攻击、施法、数值变化和回合反馈动画，以及简单随机合法动作托管；没有账号、联网匹配、自定义组牌、文件存档导入/下载或正式全卡池。托管不评估胜率或战术，可能作出不利选择。部分关键词/事件名及协议详情仍保留英文原名；高组合数动作面板可能较长，可按来源/类型筛选。本次没有改变观察84/命令12协议，没有把代表库或本地提取数据数量宣传为支持率。

## 2026-10-14 直接点击与本地客户端美术

常用操作改为点击手牌/己方随从/英雄/技能→选择操作或分支→点击高亮目标；随从入场点击战场「+」位置。当前版本唯一且无目标/位置的操作立即提交，具体条件见末节。只从当前座位的完整合法动作中逐步筛选，最后提交原动作；不猜测目标、位置、费用或攻击资格。不同主动动作/分支先分组，独立复杂主体目标继续用通用面板。取消按钮或Esc可清除选择；刷新、提交、失效和交接清除已选内容。完整合法列表默认折叠。

对战桌采用对手在上、己方在下的布局，英雄与技能居中、随从椭圆牌面、己方手牌横排、敌方牌背、法力水晶及生命/攻击/护甲数值，结束回合位于桌面右侧。只是浏览器静态呈现与已有Python结算对接，不运行官方客户端或其代码，不声称像素级复刻完整客户端。

## 战场呈现与直接操作契约

战场使用本地客户端真实中央底板 `VarianLL_Playspace.webp`，配合木质外缘、英雄位置、两排随从、底部扇形手牌、独立牌库、武器与英雄技能槽。`tools/extract_ui_board_art.py` 只读三个已知纹理包，选取14个候选纹理供视觉检查，来源与输出哈希在 `assets/board-art-manifest.json`；只有适合完整使用或明确定位区域的纹理进入布局。完整官方棋盘还包含三维网格和交互装饰，本Demo不是官方场景程序。所有卡牌插图均受 `.card-art` 与对应组件尺寸约束；武器攻击/耐久分别读玩家DTO中的attack/durability，不使用health占位。手牌印刷文本取同一已钉住代表记录，只在已披露卡面上显示，不据文本生成效果或推断动态数值。

直接操作仍投影原合法动作。若只有一条精确动作，且无目标、位置、磁力目标或复杂主体路线，普通无目标技能/卡牌立即提交；目标技能、随从位置、分支、特殊参数仍显式选择。装备武器可点击选择当前具有合法攻击动作的英雄，英雄才是实际攻击者。Esc、取消按钮或战场右键可取消当前选择。悬停预览、箭头和反馈动画均只读取当前座位投影和页面位置；交接、失效和重新渲染清空旧预览与选择，失效还清除隐藏DOM里的旧提示。

动画在内核确认接受动作后播放，期间保持请求锁，不能通过连点重复支付/施放。攻击冲刺、法术轨迹、数值变化、入场/离场和回合提示不会驱动规则；失败操作不演成成功。`prefers-reduced-motion` 下略过动作动画。`render_game_to_text` 仍只给当前座位可见状态，`advanceTime` 仅完成呈现动画，不能推进引擎回合。

扇形手牌的外层命中区域保持原角度，悬停时只移动内部卡面，避免露出的牌边随动画离开鼠标。满手按张数增加重叠，保留资源栏空间；棋盘使用不可滚动裁切，防止装饰外溢引起焦点滚动。浏览器回归入口为 `node tools/test_web_ui_browser.mjs --output outputs/新的目录`，可通过 `--playwright` 指定已安装的Playwright模块路径。

本轮实际验证、发现的问题和下一项只登记在项目状态及机制台账。


## 逐卡测试工作台

从普通页面顶部的「逐卡测试工作台」在独立标签页打开 `/lab`。目录使用当前 `hs_sim.cards.constructed.build_registry()` 的完整已接入定义，不再局限于普通对局默认的代表注册表。目录会随服务重启后的内容包变化重新生成；每个定义保留一条工作项，不能直接成为物理牌的选择项或星舰模板明确要求来源生成，不悄悄删除。此目录不是正式标准合法池认证。

选卡后点击「创建测试局面」，再直接在嵌入的真实战场点击卡牌和目标；也可以「自动执行并核对」或在手动操作后「核对当前局面」。支持按职业选择默认英雄、设置0～40法力、尸体、随机种子、双方场面、牌库以及己方预先受伤量。普通页面原「设为10费」入口仍为0～10，不改变正常费用规则。高费用牌的独立场景可以显式提升法力上限。伤害准备由既有健康执行器处理，随从至少留1血；准备本身不冒充玩家操作。

已配置的专用场景包括伤害/冻结、发现复制、滋养分支、亡语、主动和被动技能、机械狗探底、奥卡尼选择、鹦鹉重放、治疗、武器强化、受伤目标、亡灵剧毒，以及原始牌库相关卡。后者先走真正 `Game.from_decks` 和双方保留起手的换牌流程，再通过宿主既有资源/区域效果准备测试牌；完整快照成为可信测试段起点，保留原生开局事实，不给 Scenario 伪造原始牌库信用。复杂效果的覆盖范围以结果中实际列出的断言为准。

结果分别显示：尚未运行、列出的效果断言通过、效果断言失败、执行失败、待核对效果、待完成选择、需要前置条件、仅显示场景、需要来源生成。普通随从/武器仅在没有额外可执行声明时，才用固定印刷记录生成入场属性断言；这不等于验证关键词触发。其他卡成功执行也只记为待核对效果。修改默认条件会停用该默认用例的效果断言；生命周期所需的真实开局及准备仍保留。

「检查当前筛选」逐项创建临时独立场景、执行真实玩家命令，最多自动确认四个己方待选，再将座位1玩家投影送入同一个战场渲染器；自动巡检画面只读。界面结构检查比对公开实体名称、费用、攻击、生命/耐久和嘲讽标记；图片缺失明确记为占位卡面，不等于图片已经通过验证。停止按钮完成已发出的本张检查后停止，不取消内核中正在执行的单次操作。可以筛选失败/待准备项，并导出JSON；手动截图检查与结构断言互为补充，不宣称每张卡的全部视觉状态都已验收。

`web_ui/card_lab.py` 与 `lab_cases.json` 是测试宿主/用例，不修改卡牌实现或内核。`/api/lab/catalog` 返回静态目录；`create` 创建自己的新测试会话；`probe` 使用不注册到会话表的临时局面，既不改变普通对局也不消耗其会话额度。测试会话满额时只淘汰旧测试会话，无法腾出时拒绝创建，避免淘汰普通对局。`run/check` 要求原测试座位1且不处于交接遮罩，不能从座位2请求座位1手牌的实际断言值。原始状态、存档、随机源和证明材料都留在宿主。

工作台通过同源 iframe 复用普通战场；`frame-ancestors` 限为 self，消息同时校验 origin 与 parent/source。正常操作继续走原 PlayerPort；巡检预览无凭证且禁用交互。公开卡面按已披露ID获取本地图像；未识别的图像仍使用带名称和数值的占位卡面。已知八种灌注技能的 `@` 仅按原R-100共用的 `max(1, level)` 显示，阶数仍取公开 `imbue.level`，不改实际效果或技能使用次数。

巡检结果只在内容注册表与用例指纹同时匹配时从 `lab_baseline.json` 载入；卡池继续补齐或断言变化时，不把旧结果自动继承为当前通过。浏览器只保存静态检查结果，不保存当前对局DTO或全知快照。服务重启后才能读取新注册的Python内容；当前已打开的冻结验证服务对应其原内容版本。实际运行范围、失败、证据与下一项仅在原项目状态和机制台账维护。
